共通レイヤーの3つのファイルは --rules、--phases、--risk で、レイヤーを探す場所は --projects と
--project-home で変更します。この5つはいずれも同じ制限が適用され、診断専用で、
それ以外の実行では無視されます。

--root と --cwd は、この実行がどこで行われているかを指定します。.ccnavi/scripts/
のラッパースクリプトがこれらを判定して渡すため、各1回のみ指定できます。2回目の指定は、
上書きとしては扱われず拒否されます。

設定の値を上書きするフラグもあります。--mode、--ticket-control、--restore-if-deny、
--guard-core-files、--guard-ticket-approval は環境変数と同じ値を取ります。--log、--state、
--approved、--tickets は記録と置き場の場所を動かし、上の5つと同じく診断専用です。

.ccnavi/scripts/ のスクリプトが付けるフラグは次のとおりです。

    --record-writes <file> [--record-tree <dir>]
        （この実行で書いた・消したパスを、logs/state/write-and-push/ の下の <file> に1行1つで
         書き出します。--record-tree を渡すと一覧はそのツリーからの相対になり、
         置き場の外に書いたらエラーになります。write-and-push と ccnavi-user-agree.sh が使います）
    --record-commit <message> [--record-merge <sha>]
        （write-and-push 専用。--record-writes と --record-tree と一緒に渡します。書く前に元の先頭を読み、
         --record-merge なら子の先頭を合流してから書き、書いたパスを <message> でコミットします。
         失敗したら合流ごと戻します。答えは <file>.answer に1行1つで書き出します）
    --placed-out <file>
        （--agree 専用。実際に書けた承認済みチケットのパスなどを JSON で書き出します）
    --choose-out <file>
        （decide の前半。選択とダイジェストを書くだけです）
    --accept-plan <file>
        （decide の --yes と --close-early 用。受け入れる指摘と、スレッドに残す返信の
         本文を書くだけです。スクリプトが返信と解決を済ませてから、
         置く呼び出しを打ちます）
    --accept-check <file>
        （--close-early 用。--accept-plan で書いた計画のあとで、未解決の指摘が変わっていないかを
         確かめるだけです）
    --accept-done <file>
        （decide の --yes と --close-early 用。--accept-plan で書いた計画を読み、返信と解決が済んだ
         結果を確かめて置きます。--close-early は y/N を聞き直しません）
    --no-issue
        （--close-early 用。受け入れた指摘への返信に、issue に回すと書かないようにします）
    --via terminal|board
        （decide が書くレビュー済みの印と、user handoff --yes の経路。handoff は board だけ）

    ccnavi review prepare   --cwd <dir> --phase N --body-file <path>
    ccnavi review requested --cwd <dir> --phase N --result <json>
    ccnavi review confirm   --cwd <dir> --phase N --result <json> [--actor <account>]
        （手で done/ に動かして共有済みの子は、移動の前の未解決の指摘を受け入れ台帳 accepted.json に
         版つきで足して確定します。移動の後に付いた指摘が残れば確定しません）
    ccnavi review ready     --cwd <dir> --result <json>
        （標準出力: コメントの下書き、"tree <dir>"、続いて "wip-from <sha>" と、
         wip/ から削除した追跡済みファイルごとに "wip <path>" を1行ずつ出力します）
    ccnavi worktree drop <name> [--cwd <dir>]
        （ビルド成果物を削除し、.claude/worktrees/<name> に対して --force なしで
         `git worktree remove` を実行します。ブランチは残します。--cwd がその中にある場合、
         または未コミットの変更がある場合は何もせず、その旨を表示します）
    ccnavi worktree clean <name> [--preview]
        （ビルド成果物だけを削除します。ワークツリーは削除しません。cwd は見ません。
         未コミットの変更がある場合は何も削除しません。git の登録が残っていない
         ディレクトリは、未コミットの変更を確かめずに掃除します。--preview は削除する
         ものを表示するだけです）
    ccnavi worktree tidy <parent> [--phase N] [--cwd <dir>]
        （クローズ済み（完了または取り消し）の子のワークツリーを削除します。--phase N を
         指定した場合はそのフェーズのみが対象です。doing/ にある子のワークツリーだけは残ります。
         子のidは、チケットから読み取った親を指すものとして扱われます）
    ccnavi worktree remaining <parent> [--cwd <dir>]
        （そのファミリーのワークツリーのうち、まだ残っているものを一覧表示します。削除はしません。
         対象は、チケットを保持する親と異なる名前のワークツリーと、クローズ済みの子のワークツリーで
         未保存の下書きがあるものです。該当がなければ何も表示しません）
    ccnavi worktree retire --abandon <parent>
        （放棄した親（MR をマージせずに閉じた親）の片付けの記録 state/retire/<parent>.json を
         消します。親のワークツリーが残っている間は断ります。ユーザがターミナルで打ちます。
         エージェントからは打てません）
    ccnavi worktree retire <parent> [--cwd <dir>]
        （ready が Draft を外した後に、親を閉じる片付けを行います。閉じた子のワークツリーと、
         子の手元のブランチ（合流した子: 先頭が merged_sha と同じで、それが push 済みの親に含まれる
         場合のみ）、親のワークツリーを削除します。取り消した子のブランチは一覧表示のみで、
         ユーザが確認した後に、ユーザが ! を付けて
         ccnavi-user-clean-branch.sh <name> --confirmed を打って削除します。
         ccnavi-review.sh ready が中で呼びます。エージェントからは打てません。
         未コミットの変更があるワークツリーは理由を出して残します。git が無視しているファイルは scratchpad/worktrees/<名前>/ へ退避します）
    ccnavi worktree branch <name> [confirmed]
        （retire が記録した子のブランチだけを、条件を確かめ直して削除します。記録の子が
         チケットの parent: でもその親の子であることを確かめます。取り消した子は confirmed が
         要ります。ユーザが ! を付けて打つコマンドで、エージェントからは打てません）
    ccnavi sync tidy <parent> <repo> <branch> <sha>
        （親の MR がマージ済みと分かった後に、親のワークツリーと
         手元のブランチを、<branch> が親のブランチで、手元の先頭が push 済みの先頭
         （origin/<branch>）と <sha>（MR の先頭）の両方に含まれるときだけ削除します。
         エージェントからは打てません。
         1 行ずつ報告し、最後に
         "record yes|no"（片付けが済んだか）を出力します。済んだときは retire/<parent>.json も
         消します。ネットワークには出ません）
    ccnavi sync plan|integ|fetched|family|pull|merged|recheck|end <scripts> <args>...
        （.ccnavi/scripts/ccnavi-sync.sh 用。sh が ls-remote・fetch・ccnavi-review.sh merged を
         打つ間の判定と、早送り・merge（失敗したら取りやめ）・origin/HEAD の向け直し・片付けを行います。
         "sync 1" の行に続いて、表示する "out <行>"、止めたことを表す "failed"、取り込みが書きかけと
         重なって止まったことを表す "overlap"、渡された親のワークツリーに親チケットも提案も無いことを表す
         "noticket"、次の一手の
         "next <語>"（fetch・ask・skip・go）を出力します。end は、それまでの答えを並べたファイルから
         sync の終了コードを決め、"exit <コード>" を出力します。merged は片付けでブランチを消すので、
         エージェントからは打てません。ネットワークには出ません）
    ccnavi sync check <parent> [<repo>]
        （<parent> を取り込んだ後の検査です（ccnavi-sync.sh は sync recheck で同じ判定をします）。ファミリーの承認済みチケットと
         その権限を再判定します。"check 1" の行に続いて、"error <detail>" か "warn <detail>" を
         1行ずつ出力します（warn には、手元のレイヤーが取得済みの origin/<統合先> のレイヤーと
         違うことを含みます。git show でローカルの参照を読むだけで、ネットワークには出ません）。
         error がある場合は終了コード1になります）
    ccnavi fetch plan|forward|track|retarget|base|advance|auth <args>...
        （.ccnavi/scripts/ccnavi-fetch.sh 用。sh が fetch・ls-remote を打つ間の判定と、早送り・
         update-ref・origin/HEAD の向け直し、認証に失敗して取ってこられなかったときの案内を行います。"fetch 1" の行に続いて、表示する "out <行>" と
         次の一手の "next <語>"（fetch・lock）を出力します。ネットワークには出ません）
    ccnavi sync retired
        （ボード用。"retired 1" の行に続いて、親を閉じた後の片付けの列挙元
         （state/retire/<parent>.json）を "retired <parent> <self|project> <mr|-> <branch|->" の
         形で1行ずつ出力します。読めない記録や mr の無い記録は "incomplete <parent> <理由>"
         です。ネットワークにも git にも触れません）
    ccnavi tree parent <tree> <name> [<branch>]
        （スクリプト用。"tree 1" の行に続いて、"parent yes|no|unreadable"（そのツリーが
         親のチケットまたは提案 <name> を保持しているか）、"approved yes|no|unreadable"
         （承認済みの親チケットがあるか。提案は数えません）、"requested yes|no"
         （.requested のマーカーがあるか）、"archived yes|no"（手元の退避に親があるか）、
         "started yes|no"（着手済みか）、"mr <番号>|-"（親チケットの mr:）を出力します。
         <branch> を渡すと、続けて "trace yes|no"（親のブランチを一度は送った形跡があるか）を
         出力します。スクリプト自身はチケットのYAMLを読み込みません）
    ccnavi tree gate <tree> <branch> <id> <seconds>
        （push のゲート用。"tree 1" の行に続いて、次の一手 "gate pass|stop|ls-remote" を出力します。
         stop には "why <理由>"、ls-remote にはリモートに無いときの "missing <理由>" と、
         確かめられないときの "unreachable <理由>" が続きます。ls-remote は呼ぶ側が打ちます）
    ccnavi text <id> [name=value]... [@field=case]...
        （スクリプト用。文面ファイル（.ccnavi/messages/）の識別子 <id> の文を
         組み立てて出力します。
         name=value は文面の {name} に入る値、@field=case は欄の場合分けの選択です。
         引けないとき（識別子が無い・値の不足・文面ファイルの不備）は何も出力せず、
         理由を標準エラーに出して終了コード1になります）
    ccnavi worktree direct plan -- <ccnavi-worktree.sh の引数>...
        （ccnavi-worktree.sh 用。引数と、切る前に決まる検査（C1〜C3・同じ識別子・既にあるワークツリーとブランチ・
         親のワークツリー・取り込みの途中の記録）を行い、引き取り（--adopt）と --dry-run はここで終えます。切る道に
         進むなら "fetch <取り込み先>" と "top <ツリー>" を出力します。答えは 1 行 1 項目で、誤りは
         "fail <識別子> <終了コード>" と "msg <文>"）
    ccnavi worktree direct cut fetch=ok|failed fetch-out=<file> heads=<file> heads-err=<file> -- <ccnavi-worktree.sh の引数>...
        （ccnavi-worktree.sh 用。sh が取った fetch の出力と ls-remote --heads の応答（heads が空なら取れなかった）から、
         origin とのずれ・書きかけ・確認コードを決め、確認が要れば報告して終了コード 3 を返す答えを出し、要らなければ
         記録（ccnavi-direct/<名前>）を書いてワークツリーを切ります）
    ccnavi worktree issue-id <number> <prefix> [<project>] --title <title>
        （ccnavi-start.sh 用。issue から新しい親のブランチ名（= 識別子）を作り、"id <名前>" を
         出力します。Chrome 拡張の「始める」と同じ作り方です。タイトルが長くて slug を
         語の区切りで切ったときは、続けて "long yes" を出力します）
    ccnavi write-and-push family <id>
        （write-and-push 用。"write-and-push 1" の行に続いて、
        親子のチケット・リポジトリ・write-and-push の対象か
         （target yes|no|stop）・親のワークツリーとブランチなどを1行ずつ出力します。読み取り専用）
    ccnavi write-and-push sort <parent> [<rev>]
        （write-and-push 用。
        置き場の変更をコミットしてよいものと止めるものに分けて1行ずつ出力します）
    ccnavi write-and-push merge <child>
        （write-and-push 用。finish が子を親のブランチへ合流する前の検査）
    ccnavi accept plan <plan>
        （ccnavi-user-lib-review.sh 用。受け入れの計画の操作 ID とスレッドの数を "op"・"count" の行で出力します。読み取り専用）
    ccnavi accept threads <plan> <result> <github|gitlab> <dir>
        （ccnavi-user-lib-review.sh 用。返信と解決をホストに書く前の確かめをして、"mr" と
         スレッドごとの "thread <番号> <id> <キー>" を出力し、返信の本文を <dir>/<番号>.reply に書きます。
         止めるときは "stop <文>"）
    ccnavi accept decided <answer> <issue-url> <warning>
        （ccnavi-user-decide.sh 用。置いた答えの JSON に issue_url と warning を足した 1 行の JSON を出力します）
    ccnavi write-and-push busy <tree>
        （write-and-push 用。親のワークツリーに途中の操作があれば "busy <名前>" を出力します。読み取り専用）
    ccnavi write-and-push commit <tree> <list> <message>
        （write-and-push 用。<list> のパスだけをコミットし、"commit <sha>|none" を出力します）
    ccnavi write-and-push undo <answer>
        （write-and-push 用。--record-commit の答えの自分のコミットを、比較つきで元の先頭に戻します）
    ccnavi write-and-push landed <answer>
        （write-and-push 用。取り込み直した先頭に自分のコミットが入っていれば "landed yes <sha>" を出力します）
    ccnavi write-and-push unsent <tree> <branch>
        （ccnavi-user-push-approved.sh 用。まだ送れていないパスを "unsent <パス>" で1行ずつ出力します。読み取り専用）
    ccnavi ops get <op-id>
        （レビューの sh 用。操作記録の段階と applied を "stage <id>"・"<id>.state" などの1行1つで出力します。読み取り専用）
    ccnavi ops replied <op-id> <thread-id> <result> [<account>]
        （ccnavi-user-lib-review.sh 用。スレッドへの返信をホストが既に持っているかを "replied yes|no" で出力します。判定にアカウントが要るときは "replied account"）
    ccnavi ops resume <op-id>
    ccnavi ops resume-plan <op-id> <file>
        （ccnavi-user-decide.sh の --resume 用。resume は再開の表示に使う項目を1行1つで出力し、resume-plan は再開の計画を <file> に書きます）
    ccnavi branches issue|mr <number> [checked github|gitlab <host> <owner/repo> <project-id>|-] [--result <file>] [--json]
    ccnavi branches issue|mr <number> unchecked <reason> [--json]
    ccnavi branches issue|mr <number> failed <call> --result <file> [--json]
        （ccnavi-branches.sh 用。issue・MR に紐づくブランチの候補を出力します。checked の --result はホストの応答のまま
         （MR は 1 本、issue は GitHub なら開いた PR の一覧、GitLab なら related_merge_requests）、failed の --result は
         ホストの返事。読み取り専用）
    ccnavi path under <base> <path>
        （ccnavi-review.sh 用。"path 1" に続けて、path が base の下なら "under yes"、違えば "under no" を
         出力します。大文字小文字は区別しません。読み取り専用）
    ccnavi stage -- [--commands] <path>...
        （ccnavi-stage.sh の本体。保護対象のファイルを下書きの置き場（wip/handoff/）へコピーするか、--commands で
         編集済みの下書きの取り込みの手順を出します。出力はそのまま標準出力・標準エラーに書きます）
    ccnavi dirs
        （ccnavi-dirs.sh の本体。projects/ に clone 済みのリポジトリを、最新コミットが新しい順に最大 10 件出力します）
    ccnavi ticket-sh id -- <ccnavi-ticket.sh の引数>...
        （ccnavi-ticket.sh 用。識別子を "id <識別子>" で出力します。使えなければ "bad yes" と "msg <文>"）
    ccnavi ticket-sh child <child> <parent-tree> <parent-branch> <parent>
        （ccnavi-ticket.sh 用。子の start で、子のワークツリーが無ければ親のブランチの先頭から作ります。
         手元の子のブランチに親に無いコミットがあれば作らずに "fail <識別子> 1" を出力します）
    ccnavi ticket-sh unsent <op> <parent-branch> <mr|->
        （ccnavi-ticket.sh 用。一度も送っていない親で止めたときの次の手を "err <行>" で出力します）
    ccnavi ticket-sh result-begin | result-end <file> <rc> <started> -- <ccnavi-ticket.sh の引数>...
        （ccnavi-ticket.sh 用。approval-request の結果ファイルの名前を決め（"file <パス>"・"started <時刻>"）、
         終わったあとに中身を書きます）
    ccnavi git check <self> <sync> <start> <self_q> <worktree_q>
        （ccnavi-git.sh 用。標準入力に NUL 区切りで受けた git の引数を、git の状態とあわせて通すかを、
         allow・pass か "deny <識別子>" と拒否の文で出力します。読み取り専用）
    ccnavi git integration <tree>
        （スクリプト用。そのツリーが属するリポジトリの統合先（origin/HEAD、無ければ origin/main・
         origin/master）が決まれば "integration <名前>"、決まらなければ "hint <案内>" を出力します）
    ccnavi git refusal <file>
        （スクリプト用。git の標準エラーを書いた <file> から、git が断った理由を "refusal <文>" で
         出力します）
    ccnavi git integrate <self> <self_q> <worktree_q> <ticket_q> <lines> -- integrate|integrate-done <args>...
        （ccnavi-git.sh 用。integrate・integrate --abort・integrate-done を行い、結果をそのまま出力します。
         0 は済んだ、1 は止めた、2 は拒否。ロックは呼ぶ側が取ります）
    ccnavi start args -- <ccnavi-start.sh の引数>...
        （ccnavi-start.sh 用。引数を確かめ、依頼のリポジトリ（--repo）と origin を比べ、値を 1 行 1 項目で
         出力します。今いる場所のプロジェクトは "project <名前>"。誤りは "fail <識別子> <終了コード>" と "msg <文>"。読み取り専用）
    ccnavi start api-failed what=<何の問い合わせか> status=<HTTP の番号> body=<file> why=<file>
        （ccnavi-start.sh 用。ホストの API が失敗した理由を "reason <文>" で出力します。ホストに届いて断られた
         （401・403・404・410）ときだけ "refused <文>" も出力します）
    ccnavi start branch-ok <branch> strict|lenient [heads=<file>] [err=…] [hint=…] [exit=<n>]
        （ccnavi-start.sh 用。識別子が親に使えるかと、同じ識別子になる別のブランチが無いかを確かめます）
    ccnavi start merged github|gitlab <branch> <file>
        （ccnavi-start.sh 用。同じブランチ名のマージ済み MR があれば止めます）
    ccnavi start resolve <file>|- [issue=…] [issue-n=…] [issue-r=…] own=<owner/repo> [mr=…] [orig=…]
        （ccnavi-start.sh 用。MR が閉じる issue の一覧から、frontmatter に書く issue を決めます）
    ccnavi start issue-state state=open|closed|… number=<n> [real=…] [reopened=…]
        （ccnavi-start.sh 用。closed の issue なら止めて、どうするかの次の手を出力します）
    ccnavi start prepare <branch> [from=<起点>] [ff=yes] [initial=yes] integration=<branch> number=<n> [real=…]
        （ccnavi-start.sh 用。ワークツリーを出し、早送りと空の初期コミットを済ませます。初期コミットを積めなければ、
         この回で作ったワークツリーとブランチを片付けて止めます。from を渡すと、origin/<統合先> が手元に無ければ止めます。
         push を飛ばすか（先頭が origin/<branch> と同じ）を "push needed|skip" で出力します）
    ccnavi start fetched <branch> <終了コード> <fetch の出力のファイル>
        （ccnavi-start.sh 用。続けるブランチの fetch の結果を "remote checked|gone|unchecked" で出力します。
         取れず、origin に無いとも言えず、手元にも無ければ止めます）
    ccnavi start stop <名前> [<名前>=<値>]...
        （ccnavi-start.sh 用。止めるときの文と終了コードを、"fail <識別子> <終了コード>" と "msg <文>"、
         または出力の行と "exit <終了コード>" で出力します）
    ccnavi start check-report <事前確認の答えのファイル> repo=<リポジトリ> top=<トップ>
        （ccnavi-start.sh --check 用。対象リポジトリ・項目ごとの行・結論・次の一手を出力します）
    ccnavi preflight plan|check|next <名前>=<値>...
    ccnavi preflight access github|gitlab <プロジェクトの応答> [<member の応答>]
    ccnavi preflight uid <user の応答>
        （ccnavi-common-host.sh 用。チケット作業の事前確認について、手元の項目・項目ごとの結果・勧める対処・行と次の一手を出し、
         書き込みの権限を判定します。ネットワークには出ません）
    ccnavi host fail <file>
    ccnavi host probe ok|failed <file>
    ccnavi host mr-state github|gitlab <scheme> <host> <path> <number> ok|failed <file>
    ccnavi host find-mr|merged|copy|marked|posted|found|account|undraft <args> <file>...
    ccnavi host sent comment|issue <url>
    ccnavi host requested github|gitlab <number> <url> <posted-url> <created-at> <author>
        （ccnavi-common-host.sh・ccnavi-common-review.sh・ccnavi-review.sh 用。スクリプトが取ったホストの応答のファイル
         （失敗したときはホストの返事）を読み、1行1項目で出力します。copy と requested は --result に渡す JSON を出力します。
         読めない応答は終了コード 1。読み取り専用）
    ccnavi host mask <url>
        （ccnavi-common.sh の ccnavi_mask_url 用。URL に埋まった資格情報を伏せた "masked <URL>" を出力します。読み取り専用）
    ccnavi start report <名前>=<値>...
    ccnavi start dry new-issue|mcp|create|existing <名前>=<値>...
        （ccnavi-start.sh 用。開始の結果と、--dry-run の作る予定を出力します）
    ccnavi start issue|linked-page|linked-body|linked-gitlab|similar|list-open|pick <args> <file>...
        （ccnavi-start.sh 用。スクリプトが取得したホストの応答のファイルを読み、1行1項目で
         出力します。読めない応答は終了コード 1。読み取り専用）
    ccnavi start route <candidates.json> what=issue|mr number=<n> [issue=…] [mr=…] [branch=…] [mcp=…] integration=<branch>
        （ccnavi-start.sh 用。ccnavi-branches.sh の候補と引数とこのリポジトリの git から、
         進む道（route の行）と、採用できない理由（problem の行）を出力します。読み取り専用）

        （ccnavi-start.sh 用。ホストに届かないときの案内（GitHub は MCP で代行する手順、GitLab は
         認証を頼んで打ち直す次の一手）を出力します。読み取り専用）

ccnavi自身は、リモートに接続しません。スクリプトがマージリクエストとそのスレッド、
レビューを取得し、--result <json> として渡します。

未解決のレビュースレッドは、人が親のワークツリーのターミナルから、次のコマンドで受け入れます
（VS Code のボードの「決める」も、同じ判定を通ります）。

    sh <workspace root>/.ccnavi/scripts/ccnavi-user-decide.sh N

（スクリプトはワークスペースにのみ存在するため、プロジェクトから作成したワークツリーからは、
相対パスで到達できません）

このコマンドはスレッドを取得し、次を実行します。

    ccnavi --entry sh user reviewed N --accept-unresolved --result <json> --cwd <parent worktree>
        [--actor=<account> --via=terminal|board]
        （スクリプトは、読み取れる場合はトークンの所有者を渡します。レビュー済みの印には、
         アカウントと実行方法が記録されます。渡さなかった場合、印はこれまでどおりです）

実行ファイルは user reviewed を内部で --reviewed に読み替えます。--reviewed を user の外で
渡すと断ります。見るだけの --reviewed N --accept-unresolved --preview は
ccnavi-review.sh decide N --preview が呼び、エージェントも実行できます。

人が親を早期にクローズする（「今のところ十分」とする）には、次を実行します。

    sh <workspace root>/.ccnavi/scripts/ccnavi-user-close-early.sh --parent <parent> --reason <why>

`ccnavi --entry sh user close-early --reason <why> --result <json>` を実行した後、
マージリクエストのDraftを解除し、残った項目を新しいissueとして登録します。
