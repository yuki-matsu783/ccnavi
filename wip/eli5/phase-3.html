フェーズ 3: 設計の記録（ADR-0093）を、いまの Chrome 拡張に合わせる

親チケット i0065 のフェーズ 3、子 i0065-03-01 です。直したのは文書 1 つだけ（+12 −7 行）で、動きは何も変えていません。

1. なぜやるのか

フェーズ 2 で、Chrome 拡張は棚（チケットの置き場）の場所を env からも統合先の設定からも読まなくなりました。 ところが設計の記録 ADR-0093 には「棚の場所は統合先の .claude/settings.json から読む」と書いたままでした。 読んだ人が、もう無い動きを本当だと思わないように直します。

2. 直した 6 か所

場所前後
3.1 の 12棚を絶対パスに向けたワークスペースは C1 と Chrome の対象外対象外は C1 だけ。Chrome は env を読まず既定の棚を使う（断らない）
3.3 の 6層と棚の場所の設定を統合先から読む層は統合先から読む。棚は既定に固定で、統合先の設定からは読まない
11.2 の表統合先から読むものに「棚のパス（env）」棚のパスを外し、「既定に固定」と書く
段階 3 の D書く先は統合先の設定から引いた棚の下書く先は既定の棚の下
段階 5 の決定 6プロジェクトも棚の場所をワークスペースの統合先から読む棚は既定に固定。判定に要る設定はワークスペースの統合先から読む
レビュー指摘 8全部の操作を「ワークスペースも登録したもの」に限るワークスペースの登録まで見るのは「始める」だけ。書く操作はプロジェクト自身の登録を見る

昔の形は消さず、「（追記: 前は…だった。棚を既定に固定したので…）」と経緯として残しました。この ADR に前からある追記の書き方に合わせています。

3. 決めたことが文書に残る

レビュー指摘 8 の約束が狭くなったことを、文書の上でも確定させました。 書く操作でワークスペースの登録を見ていたのは、棚を読むためにワークスペースを探す処理のついででした。 フェーズ 2 のレビューで、これを戻さないと決めたので、約束のほうを実際に合わせました。

4. 直していないところ

  • 手元の sh・C1・lint の棚の記述（ADR-0093 の 199・238・1230・1443・1520 行あたり）。i0064 の文書のフェーズが直すので、ここで触るとぶつかります。
  • ほかの ADR・設計書・README。拡張の README と設定画面の文はフェーズ 2 で直しました。

5. 気にしてほしいこと

  • 書きぶり。守りの約束を狭めた書き方（指摘 8）で、誤解が生まれないかを見てください。
  • i0064 との境目。3.1 の 12 は C1（i0064 の範囲）と Chrome（i0065）の両方に掛かる項目です。Chrome の分だけを書き分けました。i0064 が C1 の分を直すときに、同じ項目でぶつかることがあります。
