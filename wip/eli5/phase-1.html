履歴ファイルの名前をそろえる

なにをしたの？

ccnavi は、作業の「いつ・なにがあったか」を 1 行ずつ書き足していく記録ファイルをいくつか持っています。 そのうち「チケットの状態の履歴」だけ、名前の終わりが .ndjson でした。ほかの記録は .jsonl です。 中身の形は同じなのに名前が 2 種類あって、読む人が迷っていました。

そこで、履歴ファイルの名前も .jsonl にそろえました。

どこが変わるの？

変わるのは名前だけです。中身の書き方や、チケットの進み方は変わりません。

名前を決める場所は 1 か所（history.py）にまとまっていて、ほかのプログラムはそこを見ます。 文書、テスト、ボードと Chrome 拡張も、新しい名前に直しました。

気をつけること

むかしは .jsonl という名前のファイルを git が見ない設定にしているリポジトリが多いので、 あえて .ndjson にしていました。.jsonl に変えたあと、そういう設定のリポジトリでは、 新しい履歴ファイルを git に入れられず、承認や着手が止まることがあります。

この心配は、ユーザの判断で手当てをしないことにしました。ccnavi のこのリポジトリでは、 .gitignore から *.jsonl を外したので起きません。ADR-0086 にもそう書きました。

いままで .ndjson で書いた履歴は、新しい名前では読みません（移行はしません）。

どれくらい危ない？

リスクは低い（15 点）です。ファイルの数が多い（32 ファイル）だけで、中身は名前の置き換えが中心です。 Python のテストは全部通りました。ボードと Chrome 拡張のテストは、環境が整っておらず回せていません。
