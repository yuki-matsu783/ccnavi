下書きの「控え」をやめる

保護されたファイルを直すときの、下書きの控え（.orig）を、なくす変更です。

1. 何があったか

AI は、保護されたファイルを直接直せません。そこで、まず下書きを作り、人が取り込みます。このとき、下書きを作った瞬間の元を、もう 1 枚コピーして残していました。それが控え（.orig）です。

2. 困っていたこと

控えは、wip/handoff/ に残ります。残った控えは、Git が追跡していないファイルなので、取り込み（integrate）と後片付けを止めました。今回の作業でも、3 回止まりました。

しかも、控えの役目は「助言」でした。本当の歯止めは、別の確認（--expect。取り込み先の今のハッシュを含む）です。

3. 変えたこと

実行ファイル、下書きを作る sh、VS Code 拡張の画面（「衝突」の表示）、設計書、テストから、控えと「衝突」の判定を全部取り除きました。

4. 弱くなるところ（レビューで見てほしい点）

取り込める種類（文書・設定・メッセージ・テンプレート）は、--expect が守ります。

守れないのは、defense（hook や sh など、人が mv で差し替えるもの）です。mv は、元々 --expect を通りません。控えが、唯一の確認でした。

それでも進める理由: defense のファイルは Git で管理されていて、git diff と履歴で戻せます。起きるのは、同じファイルを下書き中に他の人が直した、まれな場合だけです。設計書に、mv の前に git diff で元を確かめる、と書きました。

5. 残る後始末

すでにある控えは、読まれなくなるだけで、自動では消えません。wip/handoff/ の下の .orig は、手で消してかまいません。
