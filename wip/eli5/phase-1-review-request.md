## 変更の概要

保護対象のファイルを直すときの下書きの控え（`<下書き>.orig`）をやめ、取り込み時の確認を `--expect` のハッシュだけにしました（#757）。

- `ccnavi-stage.sh`: `.orig` を作らない。`--commands` の「下書きを作ったあとに元が変わった」判定をなくした
- `handoff.py`・`cli_handoff.py`: `.orig` を読まない・消さない。取り込みの `conflict` 判定をなくした。`--expect` のハッシュから `.orig` の項を外した（5 項から 4 項）
- VS Code 拡張: 取り込みの状態から `conflict`（「衝突」の表示）を外した
- 設計書・`.ccnavi/docs/`・要件書・テスト: 上に合わせて直した

## 背景

`.orig` が `wip/handoff/` に残ると、追跡されないファイルとして `integrate` と後片付けを止める。控えの確認は助言で、歯止めは `--expect` が取り込み先の今のハッシュを含むこと。ユーザの判断で、他セッションの変更の退行は Git の履歴で戻せるとして、控えをやめた。

## 確かめたこと

- 変えた範囲のテスト: Python 130〜140 件、VS Code 拡張の handoff グループ 52 件が通った（全件は回していない）
- 横展開: `.orig`・`conflict`（取り込みの意味）の残りを、リポジトリ全体で grep した。ADR 0144 は履歴なので触っていない
- haiku による横展開漏れの調査、sonnet・haiku による敵対的レビュー、別の sonnet によるフラットな評価を済ませた

## レビューで見てほしい点

- **`defense` の `mv`**: 取り込めない種類（hook・sh・settings など）は、ユーザが `mv` で差し替える。`mv` は `--expect` を通らず、控えがなくなったため、下書きを作ったあとに他の人が元を直したことを検知できない。許容できるか。設計書に「`mv` の前に `git diff` で元を確かめる」と書いた
- 取り込める種類でも、見せる前に変わっていた分は止まらず、差分に出る（設計書に追記した）
- 実機の VS Code 画面は確認していない

## レビュー指摘の扱い
