# 設計: コマンド置換を読む

書くもの: `wip/design/shellread-subst.md`。

## 決めること

1. **中身の見つけ方。** shlex は引用の状態を返さないので、何らかの形で自前で引用を追う必要がある。
   次を比べて 1 つに決める。どちらも、中身は `read()` を再帰して読む
   - shlex に渡す前に原文を走査し、`$( )` とバッククォートの位置を拾う
   - shlex のトークンに引用の情報を足す形で、ひとつの走査にまとめる

   どちらを採っても、次を正しく扱う: 単一引用、`$'...'`、`\` によるエスケープ、二重引用の中の `'`、
   コメント、`$((` と `$[`、heredoc の本文（引用付きは文字、引用なしは展開）、入れ子、
   `$( )` の中で引用の状態が最初からに戻ること
2. **組み直す位置。** 切り出した中身を、ルールに当てる文字列のどこに `\x00` でつなぐか。
   `^` で始まる allow（prefer-read-grep、prefer-glob）と、`(^|\x00)` で始まる deny の両方で、
   外側のコマンドの判定が変わらないこと。引用の外の `$( )` の今の形
   （`echo $\x00git push origin main`）と揃えるかも決める
3. **縮退の条件。** 閉じない `$(` とバッククォート、shell で答えが割れる形（`$( )` の中の `case`）、
   中身の側の縮退をどう外側に伝えるか。理由の名前（`REASON_*`）を足すかも決める
4. **文面。** 引用の中から切り出したコマンドにルールが当たったときに添える文と、記録に残す印。
   回避策の綴り（`\$(`、`` \` ``、単一引用、`commit -F`、`--body-file`、git の値は出して読んでから書く）を名指しする

## 洗い出すこと

- rules.yml の Bash のルールと、`ccnavi/phase.py` などの組み込みのルールを 1 本ずつ見て、
  切り出した中身に当たるようになったとき判定が変わる見本を挙げる。変わらないなら根拠を書く
- 見本（`.ccnavi/common/rule-samples.yml`）と tests/test_shellread.py のうち、判定か出力の形が変わるもの
- 親チケットの「shell の実測」を Git Bash（bash 5 系）でも取り直し、食い違いがあれば書く

## 受入テストに渡すこと

2 番目（受入テスト作成）がそのままテストに書ける形で、次の 2 つを設計文書の末尾に置く。

- 「この入力がこの文字列になる（または縮退する）」の対応表
- 「この見本がこの判定になる」の一覧。回避策の綴りが止まらないことを含める
