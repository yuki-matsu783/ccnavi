## いま何がそうなっているか

`.claude/settings.json` の `PostToolUse` に載っているのは 2 本。

| matcher | 何をするか | モデルへ返す経路 |
|---|---|---|
| （全部） | `ccnavi-launcher.sh`。実行後の監視 | 本体の仕組み |
| `Write\|Edit\|NotebookEdit` | `lint-py.sh`。編集した `.py` が属するツリーを ruff にかける | `exit 2` |

`Stop` には `test-py.sh` が載っていて、そのターンで触ったツリーだけをテストする。
触ったツリーの控えは `logs/session/<session>.trees` に積んである。

つまり「そのセッションで何を触ったか」を hook が数える型は既にあり、置き場も掃除
（`find -mmin +60 -delete`）も `test-py.sh` が持っている。足りないのは、本数を見て
突き合わせを促す 1 本だけ。

見るのは ruff だけで、決まりとの突き合わせは誰もやっていない。決まりが溜まっている場所:

| 何の決まりか | 置き場 | 量 |
|---|---|---|
| 作業の進め方（ワークツリー、`ccnavi-git.sh`、`scratchpad/`、sh の綴り） | `CLAUDE.md` | 1 枚 |
| 判定に当てる決まり | `.ccnavi/common/rules.yml` | 1 枚 |
| 過去の決定と、その理由 | `docs/adr/` | 53 枚 |
| 用語 | `CONTEXT.md` | 1 枚 |
| 外から観測できる要求 | `requirements.md` | 1 枚 |

`requirements.md` に該当する要求は無い。ccnavi の実行ファイルの振る舞いではなく、
このワークスペースの hook の話。

## 何をするか

### 1. `.claude/hooks/review-nudge.sh` を足す（保護済み。`staging` で人が写す）

`PostToolUse` に 2 つの matcher で登録する。

```
matcher: Write|Edit|NotebookEdit
  → tool_input.file_path を logs/session/<session>.edits に追記
  → sort -u の行数が 5 未満なら exit 0（何も返さない）
  → 5 以上なら exit 0 + stdout に JSON:
      {"hookSpecificOutput": {
         "hookEventName": "PostToolUse",
         "additionalContext": "<レビュー観点を含む文面。下>"}}

matcher: Agent
  → logs/session/<session>.edits を消す（数え直し）
```

数え方の決まり:

- **ファイル単位。** 同じファイルを何度直しても 1 本。`sort -u` で重複を落とす
- **`scratchpad/` の直下 1 段は数えない。** 下書きで突き合わせを起こさない。
  綴りの判定は `CLAUDE.md` の決まりに合わせる。`*/scratchpad/*` で書くと
  `docs/scratchpad/` まで巻き込むので、ツリーのルートからの相対で先頭の区切りが
  `scratchpad` のときだけ外す
- Windows のパスは JSON の中でバックスラッシュが 2 個に増えている。`lint-py.sh` と
  同じく `tr '\\' '/' | tr -s '/'` で直してから積む

### 2. 勧告の文面（レビュー観点）

文面は hook が持つ。モデルに考えさせない。**「決まりに沿っているか」を最初の観点に置く。**

```
このセッションで <n> 本のファイルを編集しました。次の編集へ進む前に、
Agent ツールでレビューをバックグラウンドに出してください。対象: <ファイルの一覧>

見てほしい観点を、この順で:

1. 蓄積された決まりに沿っているか。読む先は CLAUDE.md（作業の進め方）、
   .ccnavi/common/rules.yml（判定の決まり）、docs/adr/（過去の決定）、
   CONTEXT.md（用語）。触った場所に関係する ADR を grep で絞ってから読む。
   沿っていない箇所は、どの決まりのどの行に反するかを名指しする
2. 過去の決定を、理由を知らずに覆していないか。ADR が「やらない」と書いたことを
   やり直していたら、その ADR 番号を挙げる
3. 決まりのほうが古くなっている可能性。反していると見えた箇所が正しく、
   決まりを直すべきなら、そう書く

指摘は「どのファイルのどの行が、どの決まりに、どう反するか」の形で返す。
決まりを名指しできない指摘は返さない。
```

3 番目を入れるのは、決まりとの突き合わせが「決まりが常に正しい」前提で走ると、
古い決まりに合わせて新しい判断を潰す方向にしか働かないため。

### 3. 受入テスト `tests/sh/test_review_nudge_sh.py` を書く

`tests/sh/test_clean_sh.py` と同じ型で、合成した payload をスクリプトに流して出力を見る。
`.claude/hooks/review-nudge.sh` は人が写すまで無いので、書いた時点では落ちる。

| 何を言うテストか |
|---|
| 4 本目までは標準出力が空 |
| 5 本目で `hookSpecificOutput.additionalContext` を含む JSON が出る |
| 同じファイルを 5 回直しても出ない（ファイル単位で数える） |
| `scratchpad/a.md` は数えない。`docs/scratchpad/a.md` と `scratchpadX/a.md` は数える |
| `tool_name` が `Agent` の payload でカウンタが消える |
| 文面に `CLAUDE.md`・`rules.yml`・`docs/adr/` の綴りが入っている |
| Windows 形式のパス（バックスラッシュ 2 個）でも数えられる |

### 4. `.claude/settings.json` を直す（保護済み。`staging` で人が写す）

`PostToolUse` の配列に 2 エントリ足す。既存の 2 本は触らない。

### 5. 文書

`README.md` の hook の一覧と、`CLAUDE.md` の「何がどこに置かれるか」に 1 行。

## フェーズの分け方

| 番号 | 種類 | 中身 |
|---|---|---|
| 1 | acceptance | `tests/sh/test_review_nudge_sh.py` を書く（この時点では落ちる） |
| 2 | staging | `review-nudge.sh` の全文と、直した `settings.json` の全文を `wip/design/` に置く |
| 3 | docs | `README.md`・`CLAUDE.md` |

移植性の検査（`tests/core/test_sh_portability.py`）は `ROOT` の下の `*.sh` を全部拾い、
`worktrees` だけを除くので、`.claude/hooks/` に写された時点で自動的に対象に入る。
足すテストは無い。

## やらないこと

- **`exit 2` での差し戻し。** 勧告に留める。編集の途中で毎回止めると、複数ファイルに
  またがる変更の流れを 5 本ごとに断ち切る。`test-py.sh` の冒頭コメントが
  「意味のない失敗の山」と書いているのと同じ理由
- **hook から `claude -p` を起こすこと。** 決定的に走る代わりに、同期なら tool の呼び出しが
  そのぶん固まり、非同期なら結果を誰も読まない
- **決まりを機械で照合すること。** ADR 53 枚を規則に落として静的に当てる道は取らない。
  書き下せる決まりは既に `rules.yml` にあり、残っているのは書き下せなかったぶん
- **専用のサブエージェント定義を足すこと。** 観点は hook の文面で渡す。
  `.claude/agents/` に 1 本足す案は代案に置く

## 得るもの

- 編集が積み上がった時点で、決まりとの突き合わせが入る契機ができる。人が言い出す必要がなくなる
- **ADR 53 枚を、書いた本人ではない読み手が見る。** 編集しているセッションは目の前の変更で
  文脈が埋まっていて、53 枚を思い出す余地が無い。別コンテキストならそこだけを読める
- 突き合わせが別コンテキストに出るので、本体の会話が診断の出力で埋まらない
- 差し戻しではないので、ccnavi 本体の `POST_VIOLATION` の差し戻しと画面上で混ざらない
- 走ったかどうかを `Agent` の `PostToolUse` で拾えるので、数え直しの契機が hook の中で閉じる。
  「勧告したのに走っていない」状態は次の編集でまた勧告が付いて自然に解ける

## 失うもの

- **強制力が無い。** `exit 2` と違い hook エラー通知が出ないので、モデルが無視しても
  画面には何も出ない。無視され続けても止まらない
- **サブエージェントは決まりを全部は読めない。** ADR 53 枚を毎回読ませればレビュー 1 回が
  重くなり、grep で絞れば絞り方を間違えたぶんが落ちる。**どちらにしても
  「見ていない決まり」が残る。通ったことを「決まりに沿っている」と読めない**
- **決まりの側が古いときに、古いほうへ引き戻す力が働く。** 観点の 3 番目で打ち消そうと
  しているが、打ち消しきれる保証は無い
- **届くのは次のモデル呼び出し。** 1 レスポンスに `Edit` を並べた場合、その束が終わるまで
  読まれない。5 本目で即座に、にはならない
- **レビュー対象と現状がズレる。** バックグラウンドの完了通知が返る頃には編集がさらに
  進んでいる。サブエージェントが見るのは呼ばれた時点の差分
- **全セッション・全ワークツリーに一律で効く。** 調査だけのセッションでも数えが進み、
  5 本読んだだけでは数えないが 5 本直せば勧告が出る
- トークンの消費が増える。編集 5 本ごとに、ADR を読むぶんを含めたレビュー 1 回ぶん
- `logs/session/` に持つ状態が 1 種類増える。掃除は `test-py.sh` の `find -mmin +60 -delete` に
  相乗りするが、**保持が 1 時間なので、編集 5 本に達する前に 1 時間空くと数えが消える**。
  実用上は問題ない想定だが、意図した挙動として書き残す

## やらない場合どうなるか

いまのまま。決まりとの突き合わせは人が言い出したときだけ入る。ADR は増え続け、
読まれない割合が上がる。実害が出ているわけではない。

## 代案

- **`Stop` で数える。** ターンの終わりに 5 本以上なら差し戻す。変更が揃った状態で 1 回だけ
  走るので対象と現状がズレない。`test-py.sh` の差し戻し上限（`MAX=3`）と掃除をそのまま
  流用できる。代わりに、編集の途中では気づけず、ターンが短いと毎ターン走る
- **`.claude/agents/rule-check.md` を足し、観点をそちらに持たせる。** hook の文面は
  「このエージェントに出せ」の 1 行で済み、観点の改版が hook の写し直しを伴わなくなる
  （`.claude/agents/` は保護の対象外なので、エージェントが直接直せる）。
  代わりに、決まりが 2 か所（hook の文面とエージェント定義）に散る
- **`matcher: Agent` のリセットを持たない。** 作りは単純になるが、勧告が走ったかを
  hook が知れないので、毎回の編集に勧告が付き続ける
- **しきい値を設定で持つ。** 環境変数で 5 を動かせるようにする。つまみが 1 つ増える
