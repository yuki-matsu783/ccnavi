## 方針

- A: ADR の番号は main で先に押さえる（i0064 の ADR を `docs/adr/0098-places-are-fixed-to-defaults.md` として入れる PR が別にある。番号は変わりうる）
- B: コード・sh・テストのコメントには ADR の番号を書かず「置き場は固定」とだけ書く。番号は文書の中だけで振り直す
- C（利用者の決定、main の取り込み直しのあと）: 保護済みの sh は main の版をそのまま採った。main の sh が読む置き場の env は、**この子の写す版でまとめて外す**。
  人が sh を写すのを 1 回で済ませるため

保護済みの sh は人が写すので、番号を書いておくと、番号が動くたびに人が写し直すことになる。
B で番号を外せば、この子の写しを最後にできる。

フェーズ 4 と同じく、写すのは人。`cp` と `git add`・`git commit` は `wip/design/scripts/README.md` の手順で打つ。
親が代わりに打つのは利用者が了解したときだけで、そのときも README の照らし（blob が表と同じこと）を先に済ませる。
写すのは**この子のレビューが済み、親のブランチに取り込んだあと**。子のワークツリーで写さない。
i0064-06（docs）は `.ccnavi/` に触らないので、写すのは 06 の作業と前後してよい。親を統合する前には写し終える。
06 の前に main を取り込むとき、`.ccnavi/scripts/` が main の側でも変わっていれば、写す前の照らし（土台の blob）が合わなくなる。
そのときは写さずに止まり、今の `.ccnavi/scripts/` から写す版を作り直す（README の照らしがそれを見つける）。
**写すまでの間、i0064-04・i0064-11 の A9 の受入テスト（`PlacesAreNotReadTest` など）は `.ccnavi/scripts/` に対して落ちる。** 写せば通る。

## 失うもの

- **コメントから ADR へ辿りにくくなる。** sh の `# 固定` の横から番号で ADR を引けなくなる。読む人は「置き場」「固定」で `docs/adr/README.md` を探す
- **A の PR が入るまで 06 に着手できない。** この子は番号に依らず進むが、設計書の冒頭のリンク（0098）は A と 06 のあとまで辿れない
- **sh を 2 回写すことになる。** フェーズ 4 で写したばかりの sh を、main の取り込みと番号のためにもう一度写す。
  人の手間が 1 回増え、写す前の照らし（blob）をまた要る。照らし忘れて古い版を写すと、main の診断ログと取り込み（sync・C1）を消す
- **写す差分が前の案より大きい。** 番号だけ（8 か所）から、env の読み取り（common 3 関数・git 3 か所・sync 4 行）が加わる。人が目で見る量が増える
- **main の sh と離れる。** 次に main を取り込むとき、main の側で `ccnavi-common.sh`・`ccnavi-git.sh`・`ccnavi-sync.sh` の同じ行が変わっていればぶつかる
- **終わったフェーズ 4 のレビューをもう一度受ける。** 承認でフェーズ 4 のマーカーが消える。06 の承認はそれが済むまで待つ

## 得るもの

- 保護済みの sh が置き場の env を読まなくなり、i0064 の方針（置き場は既定に固定）が main から入った取り込み・承認の sh にも効く。
  `CCNAVI_TICKETS_APPROVED=/x` のような代入で、git の置き場の守り（`store_hit`）や子のブランチを送らせない検査（`push-child-worktree`）、家族の見分け（`ccnavi_parent_tree`）が外れない
- `ccnavi-sync.sh` の予備が、実行ファイルの `sync paths` と同じ既定を使う。実行ファイルが無いときと有るときで置き場が食い違わない
- 保護済みの sh に番号が無くなるので、A の PR の番号がまた変わっても、sh を 3 回目に写すことは無い
- 保護済みの sh が、統合後に main の改名の ADR（0092）を指したまま残らない
- 種類 staging の範囲に収まり、承認した範囲がそのまま書ける。env と番号を 1 回の写しで済ませる
- 設計書の番号を直す場所が 2 行に減る

## やらない場合

- main の sh が置き場の env を読み続け、i0064 の受入テスト A9（`test_gitwrap.PlacesAreNotReadTest` ほか）が落ち続ける。
  i0064 を統合すると、文書は「置き場は固定」と言い、sh は env で動く
- 保護済みの sh の「ADR-0092」が、統合後に main の改名の ADR を指す。「置き場は固定（ADR-0092）」を辿ると別の決定に着く
- 設計書のリンクが切れたまま、本文の「ADR-0092」も main の改名を指したまま残る

## 代案

1. **env の読み取りを外す写しと、番号を外す写しを 2 つの子に分ける。** 1 つずつの差分は小さく、レビューが軽い。
   代わりに、人が sh を写す回が 1 回増える（フェーズ 4 から数えて 3 回）
2. **通らなくなる分岐（絶対パスの `case`、末尾 `/` を落とす行）も消す。** sh が固定の綴りだけの形になり、読む人が迷わない。
   代わりに、写す版の差分が増え、main の sh と離れる行も増える
3. **sh のコメントを 0098 に直す（08 の形を番号だけ変える）。** sh から番号で ADR を辿れる。代わりに、A の PR の番号が
   変われば sh をもう一度写す。0092・0093 と 2 度続けて起きている
4. **sh は直さず、統合の後に別に写す。** この子で人が写す回が無くなる。代わりに、統合から写すまでの間、
   保護済みの sh が env で置き場を動かせる形のまま統合先に入る。写し忘れれば残り続ける
5. **設計書の番号を全部外す（冒頭のリンクも）。** 番号が動いても設計書を直さなくてよい。代わりに、設計書から決定の記録へ辿れなくなる。
   設計書は文書なので、方針 B（番号はコードから外し、文書で振る）の外にある
