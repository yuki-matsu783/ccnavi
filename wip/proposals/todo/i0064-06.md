# 置き場の env 6 つを文書から消し、置き場の ADR を main の 0098 に揃える

## 方針（利用者の決定）

| 決定 | 中身 |
|---|---|
| A | **ADR の番号は main で先に押さえる。** i0064 の ADR を `docs/adr/0098-places-are-fixed-to-defaults.md` として main に入れる PR を別に出している（番号は変わりうる。変わったら親が知らせる）。i0064 は、その PR が main に入ったあと main を取り込み、自分の `0084-places-are-fixed-to-defaults.md` を消して main の 0098 に揃える |
| B | **コード・sh・テストのコメントから ADR の番号を外す。** 番号を振るのは文書の中だけ（i0064-09・i0064-10 がする） |

| 前の版から変えたこと | 理由 |
|---|---|
| 振り直し先を 0093 から **main の 0098** に。改名ではなく、自分の版を消して main の版に揃える | 0093 は main の #157（Chrome 拡張の承認）が採った。番号を i0064 の中で決めると、統合までに main が先に進むたびに取られる（0092・0093 と 2 度続いた）。A で main に先に置けば、統合のときに番号が動かない |
| コード・sh・テストの番号は「0093 に直す」から「番号を外す」に（09・10） | 方針 B。番号がまた変わっても、直すのは文書だけになる |
| **A の PR が main に入ってからでないと始めない** | 消す相手（main の 0098）が親のブランチに無いと、揃えられない |
| 分岐 1 の gitlink の扱いと「記録の改名」の 1 文は、A の PR の 0098 に書いてあるかを確かめるだけにする | A の PR で書いてあるはず（利用者）。無ければこの子が冒頭の追記で足す |
