# sh のコメントから置き場の ADR の番号を外す写す版を置き直し、設計書の番号を直す

親 i0064 のフェーズ 4（staging）に足す子。設計書 `wip/design/i0064-fixed-places.md` §7 に従う。
未承認の i0064-08（`wip/proposals/todo/i0064-08.md`、番号を 0093 に直す案）を置き換える。08 は消した。

## 方針（i0064-09 と同じ）

- A: ADR の番号は main で先に押さえる（i0064 の ADR を `docs/adr/0098-places-are-fixed-to-defaults.md` として入れる PR が別にある。番号は変わりうる）
- B: コード・sh・テストのコメントには ADR の番号を書かず「置き場は固定」とだけ書く。番号は文書の中だけで振り直す

保護済みの sh は人が写すので、番号を書いておくと、番号が動くたびに人が写し直すことになる。
B で番号を外せば、この子の写しを最後にできる。

| 子 | phase（種類） | 範囲 | 中身 |
|---|---|---|---|
| i0064-09 | 3（implement） | `ccnavi/*`・`scripts/*`・`vscode-extension/*`・`tests/*` | コード・テストから番号を外す、ADR の番号のテスト、env の例とコメント、拡張の README、拡張のテスト ID |
| **i0064-10（これ）** | 4（staging） | `wip/design/*` | `.ccnavi/scripts/` から番号を外した写す版、設計書の番号 |
| i0064-06 | 5（docs） | `README.md`・`ccnavi.md`・`docs/*` | main の 0098 に揃える、文書の env の除去 |

順序は **09 → 10 → 06**。この子は `predecessors: [i0064-09]` を持つ。フェーズ 4 はフェーズ 1〜3 を待つので、
09 を足して開き直したフェーズ 3 が閉じてレビュー済みになるまで、この子は承認されない。`predecessors` は、
09 より先にこの子だけが承認される形（今はフェーズ 3 が閉じているので、順序の検査だけでは通ってしまう）を止めるために置く。
終わったフェーズ 4 に子を足すと、承認でフェーズ 4 のマーカーが消え、この子が閉じたらフェーズ 4 のレビューをもう一度受ける。

振る舞いは変えない。写す版の差分はコメントの中の番号 10 か所だけ。
種類 staging の範囲には `tests/*` もあるが、この子はテストを書かない（テストのコメントは 09 が直す）。

## 失うもの

- **コメントから ADR へ辿りにくくなる。** sh の `# 固定` の横から番号で ADR を引けなくなる。読む人は「置き場」「固定」で `docs/adr/README.md` を探す
- **A の PR が入るまで 06 に着手できない。** この子は番号に依らず進むが、設計書の冒頭のリンク（0098）は A と 06 のあとまで辿れない
- **sh を 2 回写すことになる。** フェーズ 4 で写したばかりの 6 本を、コメントの番号のためにもう一度写す。
  人の手間が 1 回増え、写す前の照らし（blob）をまた要る。照らし忘れて古い版を写すと、main の診断ログを消す
- **終わったフェーズ 4 のレビューをもう一度受ける。** 承認でフェーズ 4 のマーカーが消える。06 の承認はそれが済むまで待つ

## 得るもの

- 保護済みの sh に番号が無くなるので、A の PR の番号がまた変わっても、sh を 3 回目に写すことは無い
- 保護済みの sh が、統合後に main の改名の ADR（0092）を指したまま残らない
- 種類 staging の範囲に収まり、承認した範囲がそのまま書ける。写す版の差分（コメント 10 か所だけ）を 1 回で見られる
- 設計書の番号を直す場所が 2 行に減る

## やらない場合

- 保護済みの sh の「ADR-0092」が、統合後に main の改名の ADR を指す。「置き場は固定（ADR-0092）」を辿ると別の決定に着く
- 設計書のリンクが切れたまま、本文の「ADR-0092」も main の改名を指したまま残る

## 代案

1. **sh のコメントを 0098 に直す（08 の形を番号だけ変える）。** sh から番号で ADR を辿れる。代わりに、A の PR の番号が
   変われば sh をもう一度写す。0092・0093 と 2 度続けて起きている
2. **sh のコメントは直さず、統合の後に別に写す。** この子で人が写す回が無くなる。代わりに、統合から写すまでの間、
   保護済みの sh が main の改名の ADR を指したまま統合先に入る。写し忘れれば残り続ける
3. **設計書の番号を全部外す（冒頭のリンクも）。** 番号が動いても設計書を直さなくてよい。代わりに、設計書から決定の記録へ辿れなくなる。
   設計書は文書なので、方針 B（番号はコードから外し、文書で振る）の外にある
