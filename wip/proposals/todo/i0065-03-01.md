# ADR-0093 の Chrome 拡張の置き場の記述を既定に固定する形に書き直す

親 i0065 のフェーズ 3（docs）。直すのは `docs/adr/0093-chrome-approval-parent-branch-authority.md` だけ。コードと試験には触らない。

## 直すもの

行番号は親のブランチ（i0065）の今の版のもの。

| 場所 | 今 | 直し方 |
|---|---|---|
| 3.1 の 12（161〜162 行） | 置き場のパスの設定が絶対パスのワークスペースは、C1 と Chrome の対象外にする | Chrome の側は、置き場の env を読まず既定の置き場を使う（絶対パスでも断らない）と書く。C1 の側は i0064 の範囲なので、Chrome の分だけを書き分ける |
| 3.3 の 6（226 行） | 共通層とワークスペース自身の層と置き場のパスの設定: ワークスペースの統合先から読む | 「置き場のパスの設定」を外す。置き場は既定に固定し、統合先の `settings.json` からは読まないと書く |
| 11.2 の表「判定の入力（D2）」（1250 行あたり） | 統合先から読むのは … 置き場のパス（`.claude/settings.json` の `env`）… | 置き場のパスを外し、既定に固定と書く |
| 段階 3 のレビューの対応 D（1714〜1716 行） | 書くパスは統合先の `.claude/settings.json` から自分で引いた置き場の下に限る | 書くパスは既定の置き場（提案・承認済み）の下に限る、と書く |
| 段階 5 の決定 6（1916〜1917 行） | 置き場のパスもワークスペースの統合先から読む | 置き場は既定に固定し、ワークスペースの統合先からも読まない、と書く。プロジェクトの `.claude/settings.json` を読まない点は残す |
| レビュー指摘 8 の対応（1959 行） | すべての操作を登録したリポジトリ（プロジェクトのワークスペースも登録したもの）に限る | 括弧の中を今の実際に合わせる。ワークスペースの登録を確かめるのは「始める」だけで、書く操作（`commit`）はプロジェクトのリポジトリの登録だけを見る。前は置き場を読む処理のついでに確かめていたが、置き場を既定に固定したので外れた、と経緯を書く |

ADR-0098（置き場は既定に固定）への参照を、書き直した箇所の近くに 1 回だけ置く。

## やらないこと

- `ccnavi-git.sh`・C1・lint・`settings.local.json` の検査など、手元の sh と実行ファイルの置き場の記述（1230 行・1443 行・1520 行あたり）は直さない。i0064 の文書のフェーズ（i0064-05-02）の範囲で、両方で触るとぶつかる
- ほかの ADR・設計書・README は直さない（拡張の README と設定画面の文はフェーズ 2 で直した）

## 終わりの条件

- 上の 6 か所が、Chrome 拡張は置き場の env と統合先の `settings.json` を置き場のために読まない、という今の実装と食い違わない
- `grep -n "settings.json" docs/adr/0093-chrome-approval-parent-branch-authority.md` で残る箇所が、置き場以外の用途（互換のマーカー・統合先の名前・判定に要る設定など）か、i0064 の範囲のものだけになっている
- `docs/` の外に差分が無い

## 得るもの

- ADR-0093 を読んだ人が、Chrome 拡張が置き場を env から読むと誤解しない
- レビュー指摘 8 の約束と実装の食い違いが消える

## 失うもの

- レビュー指摘 8 の対応の約束が狭くなる（書く操作でワークスペースの登録を見なくなった）。守りが 1 つ減ったことが文書の上でも確定する

## やらない場合

ADR-0093 が実装と食い違ったまま残る。特にレビュー指摘 8 は、守っていない約束を守っているように読める。
