## 目的

#743 の項目を、要件書（extensions/vscode/ccnavi-board/docs/requirements/）と実装でそろえる。

## 範囲

- ルール: B4a（保存後に warn の本文を帯へ出す。リスク・フェーズ画面も同じ作りなのでそろえる）、B6（期待確認の「ヒットしたルール」に組み込み保護の根拠を出す）、絞り込み 0 件の案内
- テンプレート: B4（編集中は外からの対象切り替えを受けず理由を知らせる）、B5（子のフロー編集の案内文から無い機能を外す）、B7（新規作成・下書きの名前で Windows の予約名と末尾ピリオドを断る）、計画の表の操作列の固定（CSS）
- フェーズ: 「既定」の表記、区切りの注意書き、絞り込みの全角英字（NFKC）
- 3 画面: 絞り込み中は並べ替えボタンを止める
- 規定の無いものは、直す前に要件書・設計書へ 1 文足す

## 対象外

- ルール B4b（重複 id で古い行も開く）。重複 id は warn で直す状態で、仕様どおり
- フェーズの区切りに全角読点を受けること
- 360px での計画の表の縦積み

## 完了の確かめ方

変えた画面のテストを `pnpm test:for <変えたファイル>` で回す（最低限）。名前の検査は該当の Python テストを回す。

## 計画の理由

設計判断はユーザと合意済みで、実装だけなので quick-work 1 本にする。
