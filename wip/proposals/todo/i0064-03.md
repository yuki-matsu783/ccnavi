# 置き場を既定に固定し、projects/ のぶつかりと載せ忘れを知らせる実装を入れる

親 i0064 のフェーズ 3（implement）。設計書 `wip/design/i0064-fixed-places.md` に従う。
`.ccnavi/scripts/`（フェーズ 4）と文書（フェーズ 5）には触らない。

## 直すもの

| 置き場 | 直すこと | 設計書 |
|---|---|---|
| `ccnavi/settings.py` | env 名の定数 6 つと overrides 表の 6 行を消す。上書き設定ファイルの同じキーも読まれなくなる。使い手の無くなった `_log_or_none` を消す | §2.1 |
| `ccnavi/lint.py` | `CCNAVI_TICKETS_APPROVED` が空の指摘を元ごと消す。`_projects` の早期リターンの前に索引の検査を足し、`git ls-files -s -z -- projects/` の mode で分ける: 通常のファイルがあれば**ぶつかり**（改名の案内。gitlink もあれば 1 文足す）、gitlink だけなら**載せ忘れ**（`git rm -r --cached projects` と `.gitignore` に `/projects/`）。どちらのときも「無視されていない」を出さない。拡張とテストが見る句をコメントで残す | §2.2・§4.1・§4.2 |
| `scripts/ccnavi-setup.sh` | `CCNAVI_LOG` と `--all` の 4 つを書かない。既存の `env` から 6 つを外し、既定と違う値を名指しする。`--check` は 6 つが残っていれば「揃っていない」に数える。入れ終わりと `--check` で、`--lint` と同じ条件・同じ文面でぶつかりか載せ忘れを知らせる（止めない、終了コードを変えない、索引を変えない） | §4.4・§5 |
| VS Code 拡張（`vscode-extension/ccnavi-board`） | 置き場の env を読まない。「置き場が無効（`CCNAVI_PROJECTS` が空）」の分岐・文面を消す。`(projects)` の苦情が先頭の句で始まるとき（ぶつかりでも載せ忘れでも）、`.gitignore` に追加のボタンと「無視されていない」の帯を出さない | §4.3・§4.5 分岐 1 の案 A |

## 書くもの（受入テスト）

| # | 確かめること | 置き場 |
|---|---|---|
| A5b | 載せ忘れ（gitlink だけ）: `(projects)` の warn が 1 件、先頭の句の直後が `（入れ子のリポジトリとして`、`git rm -r --cached projects` と `/projects/` があり `git mv` が無い。「無視されていない」を出さない。`.gitignore` に `/projects/` があっても、コミット前でも出す。2 本なら「ほか 1 件」 | `tests/ticket/test_lint_places.py` |
| A5c | 両方（通常のファイルと gitlink）: warn は 1 件で改名の文面、gitlink を `git rm --cached projects/<名前>` で名指し | 同上 |
| A8b | 導入スクリプトが載せ忘れを見つけたとき、先頭の句と `git rm -r --cached projects` を出し、`git mv` を出さない。終了コードを変えず、`--check` でも出し、索引を変えない | `tests/sh/test_setup.py` |
| A10 | 拡張: ぶつかりの苦情があるとき、帯を出し、`.gitignore` のボタンと「無視されていない」の帯を出さない | `vscode-extension/ccnavi-board/test/projects/` |
| A10b | 拡張: 載せ忘れの苦情でも A10 と同じ。`.gitignore` に既に `/projects/` があっても苦情の帯は出たまま | 同上 |

gitlink はテストの中で、入れ子のリポジトリを作ってワークスペースで `git add -A` する形で作る
（人が踏む経路と同じ。設計書 §6）。フェーズ 2 で置いた A1〜A8 のテストは、実装に合わせて
直さない。直したくなったら、そのテストが設計書と食い違っている理由を報告に書く。

## 終わりの条件

- A1〜A8、A5b・A5c・A8b が通る（`uv run python -m unittest discover -s tests -t .` の全件で、A9 以外に落ちたものが無い）
- A9 は落ちたままでよい。落ちる理由が「`.ccnavi/scripts/` の sh がまだ env を読む」ことだけだと報告に書く（フェーズ 4 で写す版を置き、人が写すと通る）
- `uv run --with ruff ruff format --check .` と `uv run --with ruff ruff check .` が通る
- 拡張: `pnpm test`（`vscode-extension/ccnavi-board`）が通り、A10・A10b がその中にある
- `.ccnavi/scripts/` に差分が無い（`git diff --stat <base_sha> -- .ccnavi/scripts/` が空）
- 設計書 §4.2 の 2 つの文面と、`--lint` と導入スクリプトの実際の文面が一致している（A8・A8b が 1 文目の一致を見る）

## 得るもの

- 置き場の決まり方が、実行ファイル・導入スクリプト・拡張で 1 通りになる。env を見る分岐が消える
- `.gitignore` に入れ忘れて `git add -A` しただけの人に、改名という重い誤った案内ではなく、
  2 手で済む正しい直し方（索引から外して無視に入れる）が出る
- ワークスペース自身が `projects/` を追跡しているときは、サブモジュールを黙って層として読むのではなく、原因と改名の案内が出る
- フェーズ 2 の受入テストが通り、残る落ちたものは A9（sh を写すまで）だけになる

## 失うもの

- **導入スクリプトが既存の `settings.json` から 6 つのキーを消す。** 人が手で書いた値も消える（既定と違えば名指しする）
- **配布先で値を変えている人は、実行ファイルと拡張では既定に戻る。** sh は写すまで env を読むので、フェーズ 4 で写すまでは読む側の間で食い違う（親ブランチの中だけの話で、統合先へは全フェーズの後に戻す）
- **載せ忘れの案内でも、拡張は `.gitignore` に追加のボタンを出さない。** 2 手とも人が端末で打つ（設計書 §4.5 分岐 1。案 B を採ればボタンで半分済むが、拡張が 2 つ目の句に頼り、押した後の表示を別に作ることになる）
- **`.gitmodules` で意図してサブモジュールを置いている人にも「外して無視に入れる」と言う**（設計書 §4.5 分岐 2 の案 A。今も「無視されていない」が出ているので苦情の数は増えない）
- 条件（mode で分ける）と文面 2 つを、`lint.py` と導入スクリプトの 2 か所に書く。ずれはテスト（A8・A8b）で捕まえるが、文面を変えるときは 2 か所を直す
- 拡張が `--lint` の文面の先頭の句に依存する箇所が 1 つ増える

## やらない場合

実装が入らず、フェーズ 2 の受入テストが落ちたまま残る。親のフェーズ 4（staging）と 5（docs）は
このフェーズを待つので、親全体が止まる。載せ忘れの分岐だけを外して入れると、`.gitignore` に
入れ忘れただけの人に `git mv projects apps` という誤った案内が出る。
