# main の sync paths とテストを置き場の固定に合わせ、sync・C1 の sh の受入テストを足す

親 i0064 のフェーズ 3（implement）に足す子。設計書 `wip/design/i0064-fixed-places.md` に従う（置き場は既定に固定、env では動かない）。

## 何が起きたか

親に main を取り込み直した（`eca9693`）。main の ADR-0093（Chrome 拡張からのチケット承認、権威を親のブランチに固定）の
機能は、i0064 で消した 6 つの env（`CCNAVI_PROJECTS`・`CCNAVI_PROJECT_HOME`・`CCNAVI_TICKETS_PROPOSAL`・
`CCNAVI_TICKETS_APPROVED`・`CCNAVI_LOG`・`CCNAVI_STATE`）で置き場が動く前提で書かれている。

- **実行ファイル（`ccnavi/`）は、もう env を読んでいない。** `ccnavi sync paths`（`ccnavi/cli.py` の `sync_paths`）は
  `settings.load` の `conf.approved`・`conf.tickets`・`conf.project_home` を返すだけで、`settings.load` は i0064 で置き場を既定に固定した。
  2026-10-03 に `grep -rnE 'CCNAVI_(PROJECTS|PROJECT_HOME|TICKETS_PROPOSAL|TICKETS_APPROVED|LOG|STATE)\b' ccnavi` を打ち、
  `os.environ` で 6 つを読む行が無いことを確かめた（残るのはコメントと `lint.py` の `_LOCAL_FORBIDDEN`）
- **落ちる・ずれるのはテストとコメント。** 下の表
- **保護済みの sh（`.ccnavi/scripts/`）は、まだ env を読む。** 利用者の決定で main の版をそのまま採り、env を外すのは
  i0064-10 の写す版でまとめてやる。この子は sh に触らない（範囲の外でもある）

## 判定を緩めないこと

- `test_sync_paths`: 前は「env の値を返す」、直したあとは「env を入れても既定を返す」。項目を 1 つずつではなく辞書全体の一致で見るので、
  見る範囲は前より広い
- `test_gitwrap`: 前は「env が指す綴りを止める」、直したあとは「env を入れても既定の置き場を止める」。止める対象は承認済みチケットの
  置き場そのもので、env で守りを外せないことを見る。i0064 の受入テスト A9 の向きと揃う
- 消すテストは無い。名前と期待を変える 2 本と、足す 3 本

## 失うもの

- **フェーズ 3 のレビューをもう一度受ける。** 09 と合わせて 2 本ぶん。10・06 の承認はそれが済むまで待つ
- **足した受入テストが、写す版が入るまで落ちる。** 全件を回したときの「範囲外の失敗」が、i0064-10 を写すまで増える
  （`test_sync_sh` の 2 本前後と `test_c1_sh` の 1 本）。i0064-04 のときと同じ形で、写したあとに消える
- **main のテストの意図を書き換える。** main の側で同じテストを直すと、次に main を取り込むときにぶつかる

## 得るもの

- 全件のテストで落ちていた `test_places_follow_the_environment` が通る
- 写す版（i0064-10）に入れる sh の変更を、sync と C1 の受入テストで確かめられる（今は `test_sync_sh`・`test_c1_sh` が `.ccnavi/scripts/` しか見ないので、写す前に確かめる手が無い）

## やらない場合

- `test_places_follow_the_environment` が落ち続ける。i0064-10 を写すと `test_a_moved_store_is_followed` も落ちる（写した sh は env を読まないので、env の綴りを止めない）
- i0064-10 の写す版で sync・C1 を壊しても、写すまで気づけない。写した先は全セッションの git と承認の運びを決める

## 代案

1. **main のテスト 2 本を消す。** 手間が一番少ない。代わりに、`sync paths` と git の置き場の守りが env で動かないことを見るテストが減る。判定を緩める側なので採らない
2. **`sync paths` に `projects` の項目を足し、`ccnavi-sync.sh` が実行ファイルから受け取る。** 実行ファイルと sh の綴りが 1 か所に揃う。
   代わりに、`sync paths` の約束（D33 の 1 行 1 項目）を i0064 の中で広げることになり、main の約束を変える。sh も読む側を足す必要がある。
   既定の綴りを sh に直に書く形（i0064-10）なら、`ccnavi-fetch.sh`・`ccnavi-push-approved.sh` の `projects=projects # 固定` と揃う
3. **受入テストを足さず、i0064-10 の終わりの条件で手で確かめる。** フェーズ 3 のレビューが軽くなる。代わりに、写す版の sync・C1 を確かめる手が人の目だけになり、
   写したあとに壊れても回帰で拾えない
