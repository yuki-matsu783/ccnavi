# 放置セッションの引き継ぎ促し 設計案

合意前の下書きです。コードは変えていません。

## 目的

キャッシュが失効したあとに大きな文脈で再開すると、文脈全体のキャッシュ書き込みの費用がかかります。失効の前（キャッシュが温かいうち）に、次セッションへの引き継ぎ文書を書かせておけば、新しいセッションを小さい文脈から始められます。引き継ぎを書くターンは読み取り単価で済みます。

キャッシュの失効自体は防ぎません。同じセッションで続ける場合の書き込み費用も避けられません。

## 振る舞い

### 設定

| 名前 | 意味 | 既定 |
|---|---|---|
| `CCNAVI_HANDOFF_SUGGEST_TOKENS` | 文脈が基準（下の「次に促す大きさ」）よりこの値以上に大きければ、次セッションへの引き継ぎを促す。0 で無効 | 400000（有効） |

### 文脈の大きさ

トランスクリプトの末尾から、`isSidechain` でない最新の `assistant` 行を探し、`usage` の `input_tokens + cache_read_input_tokens + cache_creation_input_tokens` を足します。大きさが分からないときは促しません。

### 次に促す大きさ

状態に「基準」を持たせます。最初は 0 です。文脈の大きさが `基準 + CCNAVI_HANDOFF_SUGGEST_TOKENS` 以上のとき、促しの対象になります。

- C が発火したとき、基準をそのときの文脈の大きさにします。同じセッションで続けると、次は `閾値 × 2` 付近（基準 + 閾値）に育つまで促しません。
- 文脈が基準より小さくなったとき（`/compact`・`/clear` のあと）は、基準を 0 に戻します。
- 基準はセッションごとです。新しいセッションは 0 から始まります。

この刻みのおかげで、閾値以上の文脈を同じセッションで使い続けても、放置のたびに引き継ぎが書かれることはありません。

### キャッシュの TTL

同じ `usage` の `cache_creation.ephemeral_5m_input_tokens` が 0 より大きければ 5 分、そうでなければ 1 時間とみなします。待ち時間は、1 時間なら 55 分、5 分なら 4 分です。

### 促しの 2 段

| 段 | 契機 | 動作 | 回数 |
|---|---|---|---|
| A | 促しの対象になったターンの Stop | ユーザに「次セッションへの引き継ぎを勧める」と案内する | 1 セッション 1 回 |
| C | 促しの対象になったターンの Stop から待ち時間が過ぎても、ユーザの入力が無い | Claude を起こし、`scratchpad/` に引き継ぎ文書を書かせる。基準を更新する | 基準の刻みごとに 1 回（発火後は次のユーザ入力まで、待機を始め直さない） |

A と C は独立です。A の促しの有無に関係なく、C は動きます。

### 発火しない場合

- headless（`CLAUDE_CODE_SESSION_ATTENDED` が `0`、または `CLAUDE_CODE_ENTRYPOINT` が `sdk` で始まる）
- サブエージェントのターン
- 文脈が促しの対象の大きさに届いていない、または大きさが分からない
- 無効（0）

### 引き継ぎ文書

置き場は `scratchpad/` です（追跡されない）。起こすときの指示は次の内容を含みます。

- 目的、済んでいて確かめたこと、進行中のこと、未決の判断、次の 1 手を書く
- 「このセッションで確かめた」と「前から持ち越し、再確認していない」を分ける
- 「待ち」の行には、いつ・どこで聞いたか、答えをどこで見るかを書く
- 新しい作業を始めない。コミットも push もしない
- 書く価値のあるものが無ければ 1 行で答えて止まる

指示の先頭に目印（`[idle-handoff]`）を付け、その指示では状態を戻さないようにします。

## 構成

| 部品 | 役割 |
|---|---|
| 実行ファイルのサブコマンド `ccnavi idle` | 文脈の大きさと TTL の判定、状態の更新、発火してよいかの判定。ネットワークには出ない |
| sh `.ccnavi/scripts/ccnavi-idle.sh` | 待機（`sleep`）。起きたら実行ファイルに発火してよいかを聞き、終了コード 2 で終わると指示が stderr から届く |
| 状態ファイル | セッションごと。状態は `waiting`（ランダムなトークン付き）・`fired`・`active`。ほかに基準を持つ |

判断は実行ファイル、待機は sh に置きます（`docs/claude/exe-boundary.md`）。

### 名前

既存は `ccnavi <名詞> <動詞>`（`tree parent`・`sync check`・`worktree retire`・`user handoff`）と、名詞ごとの sh（`ccnavi-sync.sh`・`ccnavi-review.sh`・`ccnavi-worktree.sh`）です。それに揃えます。

| 名前 | 呼ばれる場面 | 内容 |
|---|---|---|
| `ccnavi idle start` | Stop（`ccnavi-idle.sh start` 経由） | 促しの対象か判定し、A の案内を出し、待機の状態を書く。待ち時間（秒）を返す |
| `ccnavi idle check` | 待機のあと（`ccnavi-idle.sh` 経由） | 状態を読み直し、発火してよければ指示の文面を出して状態を `fired` にし、基準を更新する |
| `ccnavi idle reset` | UserPromptSubmit | 状態を `active` に戻す。目印付きの指示では戻さない |

`user handoff`（保護対象の下書きの取り込み）とは別の機能です。名前の取り違えを避けるため、名詞には `handoff` を使わず `idle` にします。

状態ファイルは、既存のセッションごとの記録（`logs/session/<セッション>.*`）に並べて `logs/session/<セッション>.idle` に置く案です。置き場の最終判断は実装時に既存の状態の置き場（`ccnavi-common-state.sh`）を見て決めます。

### hook の登録

既存のエントリは変えません。次を足します。

| イベント | 内容 |
|---|---|
| Stop | `sh ccnavi-idle.sh start`（`asyncRewake: true`、`timeout: 3600`）。A の案内は `idle start` が出す |
| UserPromptSubmit | `ccnavi idle reset`。目印付きの指示では状態を戻さない |

### 状態の遷移

1. Stop で、無効・headless・サブエージェント・促しの対象でないなら何もしない。状態が `fired` でも何もしない。
2. 対象なら、`waiting` とトークンを書き、待機する。A の案内がまだなら出す。
3. 待機のあとで状態を読み直し、`waiting` かつトークンが同じなら `fired` にして、基準を更新し、指示を stderr に出して終了コード 2 で終わる。違えば何もしない。
4. UserPromptSubmit で `active` に戻す。古い待機は、トークンが違うので何もせず終わる。
5. 文脈が基準より小さくなっていたら、基準を 0 に戻す。
6. 7 日より古い状態ファイルを消す。

## 配布

配布先にも配ります。

- `.ccnavi/scripts/ccnavi-idle.sh` を配る（既存の `.ccnavi/scripts/` と同じ経路）。
- 配布先の `settings.json` に、Stop と UserPromptSubmit のエントリを `ccnavi-setup.sh` が書く。既存のエントリは置き換えない。
- 使い方の文書（`.ccnavi/docs/` と `docs/guide/`）に、環境変数と動作を書く。
- 登録を足す判断は ADR に残す。

## 決まっていないこと

- 状態ファイルの置き場（上の案を実装時に確かめる）。
- `asyncRewake` の挙動（ユーザの入力との競合を含む）は、実機で確かめていない。

## 確かめること

- 待機を短くしたテスト用の上書きで、発火・待機を始め直さない・入力で取り消し・目印で戻さない、を確かめる。
- 実際のトランスクリプトで、文脈の大きさと TTL の判定が `/context` と合うかを確かめる。
- `claude -p` が数秒で終わる（待機に捕まらない）ことを確かめる。
