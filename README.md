# ccnavi

ccnavi は、Claude Code を使った開発を、ルール・チケット・必要時の情報参照・振り返りで支えるツールです。
Claude Code の hook でツール呼び出しを止め、止めた理由と代わりに取る手段を返す、というガードが出発点です。
いまは、止めるだけでなく、作業を合意からレビューまで進め、必要な資料を必要なときに引き、記録から次の作業の決まりを良くするところまでを受け持ちます。

## コア機能

| # | コア機能 | 何をするか | 主な入口 |
|---|---|---|---|
| 1 | ルールによる作業のガードとガイド | ツール実行とファイル操作をルールに照らして判定し、止める・人間に確認する・注意点や進め方を伝える。拒否には理由と代わりの手段を添える。ルールが関係する場面で、理由・注意点・手順を届ける | [ルール](docs/50_guide/rules.md)、[ツール実行後チェック](docs/50_guide/hooks.md) |
| 2 | チケットによる作業・レビュー管理 | 作業の目的・範囲・計画をチケットで管理し、人間の承認、フェーズの進行、先行との依存、子への分担、レビュー、指摘への対応を経て、合意した作業をレビューまで進める。ワークツリーとサブエージェントの連携、実績の差分に基づくリスク評価、計画テンプレートの利用を含む | [チケット](docs/50_guide/tickets.md)、[レビュー](docs/50_guide/review.md) |
| 3 | ドキュメント・スキルの検索と必要時の参照 | 文書とスキルの本文を最初から全部は渡さず、目録と索引で読む対象を絞り、本文はエージェントが必要になったときに読む。ccnavi 自身のヘルプに限らず、ワークスペースとプロジェクトの文書・作業手順を引く | [ドキュメントの索引](docs/50_guide/docs-search.md) |
| 4 | 記録と振り返りによるルール・作業手順の改善 | 判定の記録、作業・レビューの気づき、振り返りから、ルール・作業手順・スキル・文書・計画テンプレートの改善候補を見つけて提案し、人間が採ったものを次の作業に活かす | [記録と振り返り](docs/50_guide/records.md)、[設定の確かめ方](docs/50_guide/check.md) |

### 1 つ目と 3 つ目の違い

どちらも「必要な情報をモデルへ届ける」仕組みだが、届くきっかけが違う。

- ガードとガイド（1）: 操作や作業の状況がきっかけになる。判定は ccnavi の hook 処理が、モデルのコンテキストの外で行う。
  モデルがルールを読んで自発的に守ることには依存しない。関係する場面（拒否・確認・通すとき・ターンの終わりなど）で、
  その場に要る理由・注意点・手順が届く。「ルールを全部コンテキストに入れてから判定する」仕組みではない
- 検索と必要時の参照（3）: エージェントが情報を必要としたときに、自分で資料や手順を探して読む。
  ccnavi は何を読めばよいかを絞る目録と索引を用意する。

どちらも、不要な情報を最初から入れず、同じ説明を重ねて渡さないための設計である。
ただし、渡す量が減ることやルールが守られることは保証しない。

## 導入

どんなコマンドが打たれ、ルールが何にヒットするかは、動かしてみるまで分からない。まず `dry-run` で導入し、記録を読みながらルールを直し、記録が落ち着いてから `enable` に切り替える。手順は [導入と配布](docs/50_guide/install.md)、設定の値は [設定](docs/50_guide/settings.md)、ルールの書き方は [ルールの書き方](docs/50_guide/rules.md) にある。
