# 既存の失敗を確かめる

- 「既存の失敗」と書く前に、変更前の状態（統合先）で同じテストが落ちるかを確かめる。親のブランチに他の子の変更が入った後で見た失敗は、他の子が原因のことがあるため
- 報告やレビューで「既存」と扱うときは、どの ref で再現したかを添える
