# フラットな評価では、レビューの指摘が事実かを、コードの行で確かめさせる

- フラットな評価は、過剰な指摘を落とすために行う。ただし、評価役が指摘を読まずに推測で退けると、本物の指摘を落とす。評価役にも、確かめたことと推測を分けて答えさせる
- 評価を頼む依頼文に、次の 3 つを書く
  - 対象の差分と、指摘の一覧を渡す。評価役は読むだけで、ファイルを書かない。確かめられることは、ファイルを書かない範囲（読む・grep・出力だけの実行）で確かめさせる
  - 指摘ごとに、読んだ箇所（ファイル:行）を書き、事実と推測を分ける。不採用にする理由も、行で示す
  - 他のレビュアーの指摘と、自分の理解が食い違うときは、必ず該当の行を読む
- 確かめられなかった指摘は、不採用にせず「未確認」とし、理由と残る確認の手順を書かせる。推測だけを根拠に不採用にしない
- 採否を決める側も、不採用の理由が「確かめた事実」か「推測」かを見る。推測のものは、読み直させるか、自分で該当の行を 1 つ読む
- 例: 評価役が「`defense` を取り込みの経路に揃えるのは、表の変更が要る別件」と退けたが、実際は `defense` が取り込みの表にすでにあり、表の変更は要らなかった。評価役が表の定義を読んでいなかった
- 評価役に、メインの結論は渡さない（結論に引きずられるため）。差分の取り方は [diff-against-base.md](diff-against-base.md) に従う
