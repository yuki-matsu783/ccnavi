# 文面ファイルに文を足す・直す

エージェントとユーザが読む文は、コードや sh に書かず、文面ファイル（`.ccnavi/messages/*.yml`）に置く。
条件（いつ出すか）はコード・ルール・sh に残る。設計は[文面ファイルの設計](../../docs/21_design/messages.md)、一覧と移行の進み具合は[文面の移行の一覧](message-migration.md)にある。
止め方の選び方と拒否の文の型は[止め方の型と選び方](stop-patterns.md)、出力の `次:` の決まりは[スクリプトの出力に次の一手を書く](script-output.md)。

## 文を足す手順

1. 文面ファイルに 1 件足す。種類は識別子の頭で決まる（`DENY_*`・`RULE_*` は `deny`、`NUDGE_*` は `nudge`、`NEXT_*` は `next`、`CHOICES_*` は `choices`、`NOTE_*` は `note`、`NOTICE_*` は `notice`）。拒否と促しの識別子は、記録の `code` と同じ（組み込みルールの文 `RULE_<ルールの id>` は別。記録の `code` ではなく、ルールの id から決める）。同じコードで文が分かれるときだけ `__<区別>` を足す
2. 種類ごとの欄を書く。必須の欄と任意の欄は、設計書の文面ファイルの設計（`messages.md`）の「形式」の節の、種類ごとの欄の表に従う。文は `|-` のブロックで書くと、`{` や backtick を含んでも引用符で囲まずに済む
3. 差し込む値の名前を `values` に全部書く。文面に書いた `{名前}` と過不足なく一致させる
4. 呼ぶ側に識別子と値を渡す。Python は `texts.say(root, "ID", {"名前": 値})`（値の辞書は直接書く。テストが名前を数えるため）。sh は `ccnavi_text "$root" ID "名前=値"`。出力の `次:` と `案内:` の見出しは文面ファイルの側が付けるので、コードや sh に書かない
5. `tests/core/test_texts_catalog.py` が、引く識別子が文面ファイルにあること、値の名前が一致すること、どこからも引かれない識別子が無いことを見る。通るまで直す
6. 移した出力は、文面ファイルを引いた結果に対して、`次:` の行が 1 行で値が埋まっていることを確かめる
7. [文面の移行の一覧](message-migration.md)の行を「残り」から「移した」の表へ動かす

## 組み込みルールの文を足す

`builtin:` で始まる id の組み込みルール（`policy/builtin.py`・`policy/selfguard_shell.py`・`tickets/model/ticket_guard.py`・`tickets/model/phase_forms.py`）の文は、ルールの組み立てでは引かない。ルールは hook の呼び出しごとに組み立てるので、組み立てで引くと、拒否に当たらない呼び出しにも文面ファイルの冷たい読み（YAML の読み）が乗る。

1. 文面ファイルに `RULE_<ルールの id>` を足す。`what` だけが必須で、言うことが無い欄は省く
2. ルールの dict（または `Rule`）に `**texts.spec("RULE_…", git=…, wrapper=…, cased=(…))` を渡す。ラッパーの有無で分かれる欄は `cased` に、それ以外の場合の選びは `variants` に書く。`message` は書かない
3. 拒否に当たった回に、`texts.spoken(rule)` が識別子と値と場合から文を組む。文を使う側は `rule.spoken_message()` ではなく `texts.spoken(rule)` を呼ぶ
4. `tests/core/test_texts_catalog.py` が、組み込みのルールが持つ識別子が文面ファイルにあり、渡す値の名前が `values` と一致することを見る

`message_id` はルールファイルからは書けない（`from_file` が偽のルールだけが持つ）。

## 書き方の決まり

- 止めない通知（`NOTICE_*`）は、見出し（`[ccnavi] <コード> (…)`）と `subject:`・`path:` などの状態の行をコードに残し、本文だけを文面ファイルに置く。`案内: ` を付けて出したい 1 件の補足は `NOTE_*` にする
- 実行のときに場合を選ぶ文（結末、ラッパーの有無など）は、識別子を場合の数だけ分けるか、欄を場合分けにする。長さの上限（設計書の文面ファイルの設計の「点検」の節）を超えそうな、場合が多い文は識別子を分ける（`NOTICE_UNDECLARED__ASK` など）
- 差し込みの書き方（`{名前}`・`{名前:sh}`・`{名前:path}`・`{名前_q}`・`{script:<sh の名前>}`・`{{` `}}`）は、設計書の文面ファイルの設計の「識別子・差し込み・場合分け」の節に従う。使い分けは次のとおり
  - コマンドの一部になる値は、`:sh` か `:path` で引用する。sh から渡すときは引用せずにそのまま渡す。sh が引用を済ませた引数の並びは、名前を `_q` で終える
  - 相対の `.ccnavi/scripts/` の呼び出しは書かない（`{script:…}` を使う）
- `next` は `次:` で始めない。`what` `why` `next` `no_bypass` は 1 行、`note` は複数行でよい（1 行ごとに `案内: ` が付く）
- 値の制御文字・行の区切り・全角空白は空白になる。外から来る語（タイトル・本文）が行を足して案内を偽装することはできない
- ADR 番号を書かない（[実行環境とADRの扱い](environment.md)）
- 共有する部品の文（複数の出力が同じ定数を使い、テストもその定数を見ているもの）は、値として渡さず、呼ぶ側のコードに残している。[文面の移行の一覧](message-migration.md)の「残り」にある

sh の次の一手は、実行ファイルの `text` に引かせる。実行ファイルが無い・版が合わないときは、具体的なコマンドを出せず、短い既定の文（実行ファイルと文面ファイルを確かめてもらう）になる。止める・止めないの判定は変わらない。

## 引けないとき

`texts.say` は例外を投げない。文面ファイルが無い・壊れている・識別子や値が合わないときは、種類ごとの短い既定の文（`texts.fallback`）を返す。止める判定は呼ぶ側が決めたままで変わらない。`ccnavi_text` は同じ場面で sh の既定の文を出し、終了コードは 0（呼ぶ側の `set -e` を起こさない）。個々の文を既定として組み込みに残さない（直した文と食い違うため）。

## 上書きと保護

文だけを替える上書きの口は持たない。`.ccnavi/messages/` の外（`.ccnavi/config/project/messages/` や旧い置き場）に文面ファイルが置かれていても読まず、`--lint` も何も言わない。読まれるのは `.ccnavi/messages/` だけで、共通レイヤーのミラーにも入らない。

`.ccnavi/` の下は組み込みの保護が止めるので、エージェントは書けない。直す下書きは `wip/handoff/` に置き、ユーザが `ccnavi-user-handoff.sh` で取り込む（`.ccnavi/messages/<名前>.yml` の下書きだけが取り込める。取り込み前に検査（欄・差し込みの名前・`次:` の数・長さ・ADR 番号・相対の script）が走る）。文面ファイルは設定 3 本（コア）に加えていない。

## 配る

`scripts/ccnavi-setup.sh` が、配布元の `.ccnavi/messages/*.yml` を配布先の同じ場所へ配る。配布先に無いと、文は短い既定の文に落ちる。配布先に旧い置き場 `.ccnavi/config/common/messages/` が残っていても自動では消さず、不要と案内するだけ（古い実行ファイルが走っている間に消すと、文が既定の文に落ちる）。

## 使う側のテスト

使い捨てのワークスペースで文を見るテストは、同じプロセスで動く Python なら、文面ファイルが無い木でもこのリポジトリの文面ファイルの文を引く（`tests/__init__.py`）。別プロセスで起こす sh と実行ファイルを使うテストは、`tests.put_messages(root)` でコピーする。
