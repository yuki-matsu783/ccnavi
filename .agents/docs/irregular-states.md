# まれな異常状態の扱い方

壊れた記録、書きかけのファイル、手で動かされた状態、ネットワークの一時的な失敗など、まれな異常状態を扱うコードを書くとき・直すときの決まり。

## 決まり

まれな異常状態のために、推測・修復・やり直し・詳しい説明を作り込まない。状態と直し方を言って止め、ユーザに頼む。

作り込みに当たるのは次のような処理。

- 壊れた記録の中身を、更新時刻やファイル名から推して使う
- 失敗したら自動でもう 1 回やり直す
- 原因を探して詳しく説明する（どのコミット・どの子・何件か）
- 同じ処理を、道具が無い環境のためにもう一度書く
- 手で動かされた状態を細かく分けて受け入れる

## 残すもの

次のどれかに当たる処理は、まれに見えても残す。

| 残すもの | 例 |
|---|---|
| 普段の操作で通る | 計画の振り直しでの子の提案の付け替え、バックグラウンド実行の結果を後から結ぶ処理、並列に走る hook の順序の待ち |
| データの損失や二重の書き込みを防ぐ | push の到達確認、中断（Ctrl-C・時間切れ）時の巻き戻し、古いロックを奪うときの照合 |
| 保護の強さを保つ | バックアップが無いときに git から戻す処理、承認済みの古い欄の読み取り |
| 削ると、エージェントもユーザも抜け出せない | エージェントが消せない置き場の記録を、ユーザの手作業でしか消せなくする形 |

「まれ」かどうかは、普段の操作で起きるかで決める。Ctrl-C、時間切れ、hook の並列の実行、バックグラウンド実行、ワークツリーへの下書きの持ち出しは、普段の操作で起きる。

置き換えても同じだけの処理が要るなら、簡単にならないので変えない。

## 止めるときの文

- 何が起きたか（状態）と、直し方を言う。直し方はそのまま打てる形にし、値（パス・名前）を埋める
- エージェントが打てない操作（再帰の削除、保護された置き場の書き換えなど）は、ユーザに頼むと書く
- 確かめていないことは断定しない
- 次のユーザの発言や再実行で自然に解ける形があれば、そちらを選ぶ
- 文の型は[止め方の型と選び方](stop-patterns.md)、出力の案内は[スクリプトの出力に次の一手を書く](script-output.md)に従う

## 判断に迷ったら

削るか残すかに迷う処理は、削る前に「削ると何が起きるか」を具体的な状態と結果で書き出す。データ損失・保護の弱体化・袋小路のどれにも当たらず、普段の操作でも起きないなら削る。
