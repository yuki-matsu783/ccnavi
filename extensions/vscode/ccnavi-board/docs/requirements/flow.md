# フロー編集画面

同じ拡張に「フロー編集画面」がある。子チケットのフロー（担当のサブエージェントが作業中に読む手順書。設計 9.3.1）を図で書く。入口はボードの子のカードの「フロー」だけで、サイドパネルには並ばない。ファイルは YAML で、形（`nodes` / `connections` / `subAgentFlows`）は実行ファイルが読むもの。置き場と着手中かどうかは、実行ファイルの `--explain --json` の `tickets[].flow` をそのまま使う。着手中（`locked`）の子のフローは読むだけになる。フローが正しいか（読めるか・形）は、一時ファイルを実行ファイルの `--lint --json --flow` に渡して確かめ、画面は自分で判定しない（答えを実行ファイルの 1 か所に置く）。値の意味（`0755` や `yes` を何と読むか）も実行ファイルが読んだ中身と見比べ、食い違えば開かない・保存しない。置き場は承認済みの領域（`.ccnavi/approved/flows/<子>.yml`）で、ユーザが管理する。エージェントの Write / Edit は判定が止める。シェルから行き先を追えない形で書き換わったときは、着手のあとなら実行ファイルが知らせる。書くのはこの画面を使うユーザだけ。
エージェントは効力の無い下書き（`wip/proposals/flows/<子>.yml`。置き場は `tickets[].flow.draft`）を書ける。画面は下書きがいまのフローと違えば「提案あり」を出し、ユーザは、文の前後まで見せた差分を読んでから取り込む。着手の前の子には「エージェントにフローの作成を頼む」ボタンがあり、依頼の文を承認の文と同じ「コピー / 新しいセッションで開く」で渡す。

子チケット 1 枚のフロー（設計 9.3.1）を図で直す。ボードの子のカードの「フロー」から開き、タブは子ごとに 1 枚（同じ子をもう 1 度押せば前面に出す）。ボタンの言葉は、ファイルが無ければ「フロー: 作成」、在れば「フロー: 編集」、着手中なら「フロー: 閲覧（着手中）」。どれも `--explain --json` の `tickets[].flow`（`exists` と `locked`）をそのまま使い、拡張は `started_at` などから組み直さない。ボタンは親のカードには出ない。完了・取り消しの子でファイルが無いときも出ない（実行ファイルが `flow` を null で返す。古い実行ファイルの答えでも、拡張は閉じた列の子で `exists` が偽なら出さない）。

置き場は `flow.path`（承認済みの領域の `.ccnavi/approved/flows/<子>.yml`）。承認済みチケットと同じツリーのルートからの相対パスで、固定。拡張は置き場を組まず、実行ファイルの答えをそのまま使う。承認済みの領域へのエージェントの書き込みは判定が止めるので、フローを書くのはユーザだけ。書いたファイルは、承認済みチケットと同じくユーザがコミットして送る。

```sh
sh .ccnavi/scripts/ccnavi-push-approved.sh   # 承認済みの領域（flows/ も）に変更のあるツリーごとにコミットし、送る
```

保護されたブランチ（`main` など）の上なら、コミットだけして送らない。手で行うなら、親のワークツリーで `.ccnavi/approved/flows/<子>.yml` を `git add` してコミットする。

| 何 | どう出るか、何が起きるか |
|---|---|
| 図 | ノードが点、`connections` が矢印の線。見た目は cc-wf-studio に寄せてあるが、コードは使っていない（AGPL のため）。ノードの右の点から次のノードの左の点へ引くと線が繋がる。分岐（if / else・switch）とユーザに聞く（選択肢ごと）は出口が並び、線には条件か出口の名前が付く。開始へ入る線と終了から出る線は、引いている最中に受け付けない（放しても線はできない）。拡大・縮小・全体表示のボタンは左下 |
| 部品箱 | 開始・終了・プロンプト・サブエージェント・ユーザに聞く・分岐（if / else）・分岐（switch）・スキル。押すといちばん下のノードの下に足され、右の欄が開く |
| 右の欄 | 選んだノードの名前と中身（プロンプト、サブエージェントの説明・種類・プロンプト、問い・選択肢・複数選択、分岐の対象・出口の名前と条件、スキルの名前と説明）。線を選べば条件を書けて消せる。何も選ばなければフローの名前と説明。グループを選べば名前を直せて、解くか消せる |
| 元に戻す・やり直す | 上の「元に戻す」「やり直す」か、Ctrl+Z／Ctrl+Shift+Z（Ctrl+Y）。1 回の操作（足す・消す・繋ぐ・1 回のドラッグ・グループ化・貼り付け など）で 1 件、欄に打った字は同じ欄に続けて打った分（1 秒以内）を 1 件にまとめ、欄からフォーカスが外れたら区切る。欄の中の Ctrl+Z は欄に任せる。100 件まで。再読込・保存・外で変わった知らせで空になる。読むだけのときは使えない。戻して読み込んだ中身と同じになれば「未保存」が消える（未保存は読み込んだ中身との見比べで決める） |
| コピー・貼り付け・複製 | 図で選んだノード（無ければ右の欄のノード）を「コピー」（Ctrl+C）で画面の中に覚えておき、「貼り付け」（Ctrl+V）で足す。「複製」（Ctrl+D）はその場でコピーして貼り付ける。選んだノード同士の線も一緒にコピーされ、ノードと線の id は振り直す（分岐の出口 `branch-<番号>` と条件・中身はそのまま）。グループを選べば中のノードもコピーされ、新しい枠の中で同じ相対位置に置く。枠をコピーせずに中のノードだけコピーしたら、元の枠がまだあればその枠の中に、無ければ外に置く。貼り付けるたびに右下へ 40 ずつずらし、貼り付けたものを選ぶ。開始はコピーしない（開始が 2 つになると、案内が両方から辿るため）。終了はコピーできる。VS Code のクリップボードは使わない。既知の制限: コピーした内容は再読込・保存の後も残り（貼り付ければ今のフローに足す）、位置が数でないノードの置き場所は見積もりで決まる |
| ミニマップ | 図の右下。上の「ミニマップを隠す／出す」で切り替える（既定は出す。そのタブを開いている間は覚える）。見えている範囲を引くと図が動く |
| 保存前の確かめ | 「保存」を押すと、読み込んだ時点からの変更（フローの欄・足した・消した・変えたノードと線。変えたものは欄の名前も）を一覧で出し、「保存する」で保存に進む。「やめる」か Esc で閉じる（編集はそのまま）。中身は同じで順序だけ変わったときも一覧を出し、「順序だけが変わりました」と出す。設定 `ccnaviBoard.flowSaveReview` を外すか、一覧の「次から確かめずに保存する」にチェックを付けて保存すると、以後は一覧を出さない（この選択は、設定が有効になっている範囲に書く。フォルダかワークスペースの設定に値があればそこ、無ければユーザの設定） |
| 未保存のまま閉じる | VS Code の Webview には閉じるのを止める仕組みが無いので、閉じる前には聞けない。未保存の間はタブの題の頭に「●」を付ける。閉じた後に未保存だったら「開き直して戻す」「YAML で開く」「破棄する」を聞く。開き直すと閉じる前の編集が未保存のまま戻る。戻すのは、置き場・有無・更新時刻・中身のハッシュ（sha256）が閉じたときと全部同じときだけで、どれかが違えば戻さず、編集を名前の無い YAML のエディタで開く。同じ子の画面が既に開いていれば、その画面の編集は差し替えず、戻せなかったことを知らせて同じく YAML で開く。「YAML で開く」も同じエディタで開くだけで、ファイルには書かない |
| 消す | ノードの右上と線の真ん中の ×（載せた・選んだときだけ出る）か、右の欄のボタン。Delete キーでは消えない。ノードを消すと出入りする線も消える。読むだけのときは × を出さない |
| グループ | Shift を押しながらノードを押す（何も無いところを引いて囲む）といくつも選べ、2 つ以上選ぶと上の「グループ化」が押せる。グループは点線の枠（`type: group`、大きさは `style` の `width` / `height`）で、中のノードは `parentId` を持ち位置は枠からの位置で書く。手順には入らず、線も繋がない。ノードを枠の中へ引いて放すと入り、外へ放すと出る（ノードの真ん中で決める）。選ぶと縁を引いて大きさを変えられる。解く・消すと枠だけ消え、中のノードはその場に残る。実行ファイルの案内（`SubagentStart`）の手順には並ばない（中のノードはほかと同じに並ぶ） |
| 目印 | ユーザに聞くノードに「メインに戻る（ユーザに聞く）」、サブエージェント（とサブフロー）のノードに「入れ子（上限なら戻る）」。どちらもそのノードで止まってメインに返す（サブエージェントには AskUserQuestion が渡らず、入れ子の上限では Agent ツールも渡らないため）。目印は種類の性質を表すだけ |
| 注意 | 入れ子が子の下に 3 段以上重なる（既定の上限はメインの下 3 段、子は 1 段目なので子の下は 2 段まで）、サブフローが巡っている、開始が無い・2 つ以上ある、欄を持たない種類がある、サブフロー（`subAgentFlows`）がある、のときだけ上部に出る。実行ファイル（`--lint --json --flow`）の `(flow)` の warn（線が無いノードを指す・開始へ入る・終了から出る・開始や終了が無い・開始から届かないノード・出口に線が無い・サブエージェントの種類やスキルの名前が候補に無い など）も同じ一覧に出す（一時ファイルのパスはフローのファイルのパスに直す）。開始が無いことは実行ファイルも警告するので、答えがあるときは画面の注意を出さず 1 度だけにする。開始が 2 つ以上あることは実行ファイルが警告しないので画面が警告する。保存は止めない |
| 担当に渡る手順 | 右の列の欄の下に開閉できる区画で、`SubagentStart` で担当のサブエージェントに渡る手順の行（実行ファイルの答えの `flow.rendered`）をそのまま出す。開くときの答えを出し、直すと、手が止まってから（0.8 秒）実行ファイルに確かめ直させて（書きはしない）、その答えで出し直す。確かめている間は前の答えを出したまま「確かめ直している…」と出す。確かめられなければ理由を出す。並べられない（`null`）ときと、実行ファイルが古くて欄が無いときはそう表示する |
| 候補の名前 | サブエージェントの種類（`builtInType`）とスキルの名前は、実行ファイルの答えの `flow.candidates`（組み込み・ワークスペースの `.claude/` の下）から選べる。打って決めてもよく、欄の下に「組み込み」「プロジェクト（.claude/ の下）」「候補に無い（ユーザ・プラグインのものなら気にしなくてよい）」を添える。答えに候補が無ければふつうの欄 |
| 知らない欄・種類 | 落とさない。読んだ中身をそのまま持ち、触った欄だけを差し替えて書く（コメントと書き方は残らない）。欄を持たない種類（`mcp`・`subAgentFlow`・`codex` など）は名前と位置だけ直せ、`data` は YAML の形で読むだけで見せる。サブフローの中身は描かない（保存してもそのまま残る） |
| ファイルが無い | 雛形（開始 → 終了）を見せ、そのまま「保存」できる。保存でファイル（と `.ccnavi/approved/flows/`）が作られる |
| リンク | フローのファイルか、ツリーのルートからそこまでの途中がシンボリックリンク（`flow.linked`）なら、読まないし書かない。理由を出す |
| ふつうのファイルでない・ハードリンク・大きい | 名前付きパイプやデバイス、ハードリンク（名前が 2 つ以上）、256KB を超えるファイルは読まないし書かない（実行ファイルと同じ）。読むときは `O_NOFOLLOW` と `O_NONBLOCK` で開き、開いたものを確かめ直す |
| 読めないファイル | 開くときに読んだバイトをそのまま一時ファイル（OS の一時ディレクトリの `ccnavi-flow-*/flow-<番号>-<乱数>.yml`。呼ぶたびに別の名前で書き、確かめ終わると消す。画面を閉じるとディレクトリごと消す）に書き、`--lint --json --flow <一時ファイル>` に掛ける。実行ファイルが `(flow)` の error を出せば（UTF-8 として読めない・YAML として読めない・別名（`*名前`）がある・`nodes` が無い・ノードに `id` が無い・`id` が重なる など。読み手と検査は `SubagentStart` と同じ）、画面を開かずその理由を出す。エディタで直してから「再読込」。画面も、UTF-8 として不正なバイトを置き換え文字で埋めずに断る（BOM は実行ファイルと同じく 1 つ外す）。実行ファイルが通しても画面の YAML の読み手（`yaml`、YAML 1.2）で読めない・ノードのリストが取れないときは、描けないとして開かない。実行ファイルの `--version --json` の `flags` に `--flow` が無い・`--version` を知らない古い実行ファイルや、答えに読んだ中身（`flow`）が無いときは確かめられないので開かない |
| 読みが食い違うファイル | 画面の読み（YAML 1.2）で読んだ中身と、実行ファイルが読んだ中身（`flow.data`）を見比べ、食い違えば開かない。場所（ノードの `id` と欄のパス。`ノード "a" の data.v` など）と両者の値（`画面: 整数 755、実行ファイル: 整数 493`）を出すので、エディタで引用符を付けるなどして直す。裸の `0755` `yes` `on` `1:30` `0o17` `1e3` `1_000` `1.` 日付 `!!float 1` `!!binary`、大きすぎる整数、`.inf`、キーが文字列でない辞書、別名を使わないマージキー（`<<: {…}`。実行ファイルは取り込み、画面は取り込まない）などが当たる。整数と浮動小数は決め打ちで揃え、実行ファイルが浮動小数で読んだ `1.0` は画面が整数で持つので食い違いにする。値の意味は実行ファイルが決め、画面は自分で決めない |
| 着手中 | `flow.locked` が真なら、上部に赤で理由（着手中は書き換えられない。`finish` か `cancel` で外れる）を出し、部品箱・欄・保存を止める。図は動かせない。チケットの置き場が変わると錠を取り直し、開いたまま外れれば編集できるようになる |
| 保存 | 書き出す本文を一時ファイルに書いて `--lint --json --flow` に掛け、`(flow)` の error があるか、実行ファイルが読んだ中身（`flow.data`）が画面の書こうとした中身と違えば、書かずに理由（食い違いなら場所と両者の値）を出す（ほかの設定の苦情では止めない）。次に押した時点で `--explain --json` を打ち直し、`locked` が偽で、置き場が読んだときと同じで、読み込んでから外で変わっていない（無かったファイルはまだ無い）、ツリーのルートからファイルまでの途中にリンクが無いときだけ書く。どれかが満たされなければ書かずに理由を出す。書き込みは同じディレクトリの一時ファイルを `rename` で入れ替える（消せずに残った `.*.tmp` は `ccnavi-push-approved.sh` はコミットしない）。256KB を超えるフローは書かない。書く形は 2 字下げのブロック形式の YAML（複数行の文は `|`、別名は使わず、実行ファイルの YAML 1.1 が文字以外として読む表記 `yes` `0755` などは引用符で囲む。タブ・U+0085・U+2028・U+2029・U+FEFF・制御文字を含む文字列と、複数行で 1 行目の頭か行末が空白の文字列は、二重引用符とエスケープ（`\t` `\N` `\L` `\P` など）で書く）。画面は YAML 1.1 の読みを真似しない。手で裸の `yes` と書いたファイルは、開くときの見比べで食い違いとして開かない。指数で書かれる数（`1e-7` など）のように PyYAML が文字として読む書き出しも、保存の前の見比べで止まる。聞き直してから書くまでの短い間に子が着手されると、着手の直後に書き込みが入りうる（残る隙間） |
| 提案あり | エージェントの下書き（`tickets[].flow.draft.path`。既定 `<ツリー>/wip/proposals/flows/<子>.yml`、置くツリーはフローと同じ）が在り、中身がいまのフローと違えば（`sameFlow` が偽）、上部に「提案あり」の帯を出す。読めない下書き（リンク・ハードリンク・ふつうのファイルでない・大きい・YAML として読めない）も帯を出し、理由を添える。下書きの効力は無い（`SubagentStart` も着手のときのハッシュも読まない） |
| 提案を見る | 下書きを読んだバイトのまま `--lint --json --flow` に掛け、error なら取り込めないと理由だけを出す。画面の読みと実行ファイルの読みの見比べ（開くときと同じ）も通れば、いまのフローとの差分を、足す・消す・変えるノードと線ごとに、欄の名前と値の前後（文は改行も含めてそのまま。値には「文字列」「数」「真偽」「null」などの種類の表示を添え、`1` と `"1"` を見分けられる）まで出す。欄は名前の配列（キーと番号の配列）で照らし合わせ、`.` や `[` を含むキーは `["…"]` で囲んで書くので、欄の表記を真似たキーで本当の変更を隠せない。それでも欄ごとに分けられないときは、全体の JSON の前後を出して取り込ませない。フローの文は担当のサブエージェントへの案内になるので、外部の道具を使わせる指示などが紛れていないかをここで読む |
| 取り込む | 下書きの中身を編集中の内容に入れるだけで、書かない（元に戻すで戻せる）。保存はいつもの経路（保存前の確かめ・lint・押した時点の錠の聞き直し）。未保存の変更があれば、それを捨てることを文とボタンの言葉（「未保存の変更を捨てて取り込む」）で確かめる。着手中（錠）は押せない |
| 取り込んだ下書きを消す | 取り込んだ中身のまま（取り込んだあとに直したり、元に戻して別の編集をしたりしていない）保存が成功したときだけ、下書きの中身が取り込んだときのハッシュ（sha256）と同じなら消す。消す前に同じディレクトリの別の名前へ移して確かめ直し、違えば元の名前へ戻す（確かめてから消すまでに書き直された案を消さない）。違えば（取り込んだあとにエージェントが書き直した）消さずにそのことを知らせる。リンク・ハードリンク・ふつうのファイルでない・ツリーの外のものは消さない。取り込んだだけ・取り消した・保存に失敗した・錠で止まったときは消さない。消した下書きは保存のあとの知らせ（「ターミナルで送る」とそうでない親子のチケットへの案内）に名前を出し、追跡されていた下書きの削除は `ccnavi-push-approved.sh` がフローと一緒にコミットに入れる |
| エージェントに頼む | 着手の前（承認待ち・承認済みで未着手）で錠が無いときだけ、上のボタンを出す。フローが無ければ「エージェントにフローの作成を頼む」、在れば「エージェントにフローの直しを頼む」、下書きが既に在れば「エージェントにフローを頼み直す」。着手中・閉じた子・錠の確認中には出さない。押すと依頼の文（子の識別子・下書きを書く置き場・いまのフローの置き場・`ccnavi-launcher.sh --lint --flow <下書き>` で確かめてから渡すこと・`.ccnavi/approved/flows/` に書かないこと）を出し、「コピー」「新しいセッションで開く」で渡す（ボードの承認の文と同じ経路）。依頼は書き込みの許可条件ではない |
| 監視 | フローのファイル（外で変われば「外で変わった」の帯）と、下書き（動けば「提案あり」と依頼のボタンを出し直す。編集は捨てない）と、チケットの置き場（錠を取り直す） |
| 読み直しの見え方 | フェーズ管理と同じ `retainedHost`。中身が届くのは「再読込」と保存が通ったときだけで、外で変わっただけのときは帯が出る |
