# フェーズ管理画面

同じ拡張に「フェーズ管理画面」がある。フェーズ定義（自身のレイヤーとプロジェクトのレイヤーの `phases.yml`。共通レイヤーには置けない）を画面で直し、保存する前に `--lint` を通す。定義は親チケットの計画に並べる型で、子の範囲の上限とレビューの既定を持つ。子の範囲が上限に収まるか、レビューが要るかを判定するのは実行ファイルで、拡張が持つのは、定義を書く場所と、書いた定義が読めるかを確かめる入口だけ。チケット制御が `disable` なら、対象がどれでも開かない（定義は親チケットの計画と子の範囲にしか読まれない）。

対象は 2 種。ワークスペースの設定（既定 `.ccnavi/config/phases.yml`）と、プロジェクト 1 つの設定（既定 `projects/<名前>/.ccnavi/config/phases.yml`）。フェーズ定義は config にだけ置き、共通の設定には置けない（設計 11.2、11.4.1）。サイドパネルとコマンドが開く先はワークスペースの設定。プロジェクトの設定は、画面上部の「設定」の欄（ワークスペース・設定のあるプロジェクトの一覧）で切り替える。欄は対象が 2 つ以上あるときだけ出る。タブは 1 枚で、別の対象を選ぶと中身が入れ替わる。未保存の変更があれば、破棄してよいかを聞く。チケット制御が disable なら、入口は出ず、呼ばれても開かない。

ワークスペースとプロジェクトの設定ファイルの場所は `--explain --json` の `layers[].phases_file` から取るので、実行ファイルが見つからないとその画面はエラーの表示になる。フェーズ定義は足し算をしない。使われるのは、親チケットの `project:` が指す 1 本（空ならワークスペースの設定）だけで、共通の設定も、ほかの設定も足されない（設計 11.4.1）。

プロジェクトの設定は、親チケットの着手（`ticket start`）で上書きされない。着手が配るのは、共通の設定のミラー（そのプロジェクトの `.ccnavi/common/`）だけで、プロジェクトの `.ccnavi/config/` には触れない（設計 11.12）。この画面で直したプロジェクトの `phases.yml` は残る。

共通の設定（`.ccnavi/common/phases.yml`）にファイルがあるときは、実行ファイルがそれを使わず空として扱い、`--lint` が error で言う（設計 11.4.1）。画面は開き、その error を上部の帯で出す。画面からそのファイルを直したり消したりはしない（エディタで消す）。

編集中の内容は一時ファイルに書いて、`--lint --project-phases-file <名前>=<パス>`（ワークスペースの設定は `self=<パス>`）で実行ファイルに渡す。確かめるのは、その 1 本の中だけ（同じ id、表示名の重なり、overlap / requires の指す先）で、共通の設定と合わせては確かめない。保存の往復の間は欄を止める。`--lint` は設定全体を見るので、`rules.yml` などに error がある間は定義も保存できない。先に rules を直す。YAML として読めないファイルは画面から直せない（エディタで直す）。

| 何 | どう出るか、何が起きるか |
|---|---|
| 定義 | `phases` を 1 件 1 行（id・title・kind のラベル・review・scope）で並べる。既定は全部畳んであり、行を押すとその下に欄が開く。開いた行は id で覚えておき、更新のあとも開いたまま。欄は id（マップのキー）・title・kind（work / feedback）・review（none / mr）・scope（inherit か glob のリスト）・deliverables と、「ほかの定義との関係・補足」の 1 行に畳んだ overlap・requires・after・agent・when（値がある定義だけ最初から開く）。overlap・requires・after は、このファイルのほかの定義の id を複数選択のセレクトボックスで選ぶ。押すたびに 1 件ずつ付け外しし、Ctrl は要らない。キーは矢印・Home・End でフォーカスを動かし、Space か Enter で付け外しする。素の矢印のように選択を 1 件に縮めない。自分の id は候補に出ない。一覧の上にファイルの頭の `order` の選択がある。`order` は全体計画の待ち方で、sequential / dag。sequential は既定で、元から欄が無ければ書かない。scope と deliverables は `,` 区切りの 1 欄。足す・消す・上下に動かす・改名する。足した行は開いて出て、図を見ていたら一覧へ移る。足した定義の既定は `scope: inherit` |
| 保存 | 一時ファイルへ書いて `--lint --project-phases-file` を通し、error があれば保存しない。識別子に使えない id、title の重なり、feedback で `review: none`、overlap / requires が指す先の無い定義、提案がワークツリーに在る親の計画が指す定義を消したとき。これらはここで止まる。ただし承認済みチケットの計画は照合せず、定義が読めなくなるときだけ止まる。チケット制御が disable なら照合は走らない。同じ id が 2 つあるときは画面が先に止める（実行ファイルは後ろの定義で知らせずに上書きするため） |
| 欄名 | 日本語で、`phases.yml` のキー名は欄名にマウスを重ねると出る。id = `id`、タイトル = `title`、区分 = `kind`、レビュー = `review`、範囲 = `scope`、成果物 = `deliverables`、並行できる定義 = `overlap`、一緒に必要な定義 = `requires`、先に済ませる定義 = `after`、案内するエージェント = `agent`、使う場面 = `when` |
| ファイルが無い | 「設定が無い」正常な状態で、不備の帯は出さない。組み込みの既定も雛形も無い（実行ファイルも持たない）。雛形は置かず、作るボタンも出ない。欄はそのまま触れ、定義を足して保存すると、`--lint` を通った最初の保存でファイルが作られる（先頭に説明のコメントが付く）。定義の無いファイル（`phases: {}`）は先に書き出さない |
| 設定が読めない | 実行ファイルがその設定のファイルを読めず（不正で）空として扱っているとき、上部にその理由が出る |
| 共通の設定に phases.yml がある | 上部に error の帯（「共通の設定には置けない。使われない」）を出す。画面は開き、対象はワークスペースとプロジェクトの設定のまま |
| チケット制御が disable | 画面が開かない（入口も出ない。対象がどれでも同じ）。開いたままのときは何もしない |
| 監視 | 定義のファイル（絶対パスでも）、`.claude/settings.json`、`.claude/settings.local.json`、チケットのフォルダ。外で変われば「ファイルの変更を検知しました」の帯を出し、チケットが動けば保存の可否を取り直す。更新で定義のパスが変わっていれば監視も張り直す |
| 読み直しの見え方 | 画面は React で、拡張ホストが渡すのは中身（`PhasesData`）だけ。リスク管理と同じで、入れ物（HTML）は開いたときに 1 度入るだけ（`retainedHost`）。中身が届くのは編集を捨ててよいときだけで、外で変わっただけのときは帯が出る。往復の間に欄を止めるのもリスク管理と同じ。リストの欄（scope・成果物）は打っている途中の文字を欄が持つので、`,` の直後もそのまま打てる。「ほかの定義との関係・補足」の開閉は行ごとに 1 度だけ値の有無で決め、あとはユーザが開け閉めしたとおりになる |

次のことを守っている。

- **判定は実行ファイルが出す。** 画面は定義を書くだけで、子の範囲が上限に収まるか、レビューが要るかは出さない。
  それは承認（`--agree`）と着手・閉じるときに実行ファイルが知らせる
- **作業中のチケットがある間は保存できない。** 定義は承認・着手・閉じるときに読まれるので、ワークスペースの設定はどのツリーの `doing` でも止める。
  プロジェクトの設定は、そのプロジェクトのチケットにしか使われないので、そのプロジェクトの `doing` だけで止める
- **外で変わったら上書きしない。** ルール管理画面と同じ。読み込んだときの更新時刻と保存時のそれが違えば止める
- **コメントを残す。** `phases.yml` のコメントは、変えていない場所ではそのまま。定義を並べ替えたり改名したりすれば、その定義の前の
  コメントも一緒に動く（`phases:` と先頭の定義の間のコメントは先頭の定義に付いて動き、その定義を消せば `phases:` の見出しのコメントとして残る）。
  定義の前の空行は「何番目か」に付いていたものとして揃え、先頭に来た定義には元の空行を持ち込まない。変えていない欄は引用符も含めて触らない。
  ただし `scope` を書いていない定義には保存で `scope: inherit` を補う。新しく足す glob は二重引用符で囲み、
  overlap / requires の id は裸で書く。`kind` と `review` を書いていない定義は既定（work / mr）で出し、変えなければ足さない。
  `version` が無いファイルは保存で先頭に `version: 1` を足す。`phases: {}` の 1 行書きはブロックに直す。中身がマップ（キーと値の組の集まり）でない定義は画面に出ず、保存で消える（苦情にそう書く）
- **実行ファイルが別の型に読む語は囲む。** 実行ファイルは PyYAML（YAML 1.1）で、`yes` `on` `1:30` `0755` のような id・title・when・
  overlap / requires を裸で書くと真偽値や数に変わる（lint は止めず、計画から指せない定義になる）。そうなる値だけ二重引用符で囲む
