# フェーズ管理画面

同じ拡張に「フェーズ管理画面」がある。フェーズ定義（自身のレイヤーとプロジェクトのレイヤーの `phases.yml`）を画面で直し、保存する前に `--lint` を通す。定義は親チケットの計画に並べる型で、子の範囲の上限とレビューの既定を持つ。子の範囲が上限に収まるか、レビューが要るかを判定するのは実行ファイルで、拡張が持つのは、定義を書く場所と、書いた定義が読めるかを確かめる入口だけ。順序（どのフェーズがどれを待つか）はフェーズ定義には書かず、親チケットの計画の項の `after` で決める。この画面は順序を扱わず、定義どうしの関係の図も持たない。チケット制御が `disable` なら、対象がどれでも開かない（定義は親チケットの計画と子の範囲にしか読まれない）。

対象は 3 種。共通の設定（`.ccnavi/config/common/phases.yml`。場所は固定）、ワークスペースの設定（既定 `.ccnavi/config/project/phases.yml`）、プロジェクト 1 つの設定（既定 `projects/<名前>/.ccnavi/config/project/phases.yml`）。判定に使われるのは共通の設定と親の `project:` が指す設定の和（設計 11.4.1）。サイドパネルとコマンドが開く先はワークスペースの設定。ほかの対象は、画面上部の「設定」の欄（共通の設定・ワークスペース・設定のあるプロジェクトの一覧）で切り替える。欄は対象が 2 つ以上あるときだけ出る。タブは 1 枚で、別の対象を選ぶと中身が入れ替わる。未保存の変更があれば、破棄してよいかを聞く。チケット制御が disable なら、入口は出ず、呼ばれても開かない。

ワークスペースとプロジェクトの設定ファイルの場所は `--explain --json` の `layers[].phases_file` から取るので、実行ファイルが見つからないとその画面はエラーの表示になる。判定に使われるのは、共通の設定の定義と、親チケットの `project:` が指す設定（空ならワークスペースの設定）の定義の和（設計 11.4.1）。ほかの設定は足されない。画面は、開いている設定の定義の一覧の下に「共通の設定の定義」の欄を読み取り専用で出し、定義の出どころが共通か開いている設定かを見分けられるようにする。欄の中身は `--explain --json` の `sums[].phases.types` のうち `source` が `common` のもので、拡張は足し直さない。共通の設定に定義が無ければ欄を出さない。

プロジェクトの設定は、親チケットの着手後のユーザの発言で上書きされない。そのとき配るのは、共通の設定のミラー（そのプロジェクトの `.ccnavi/config/common/`）だけで、プロジェクトの `.ccnavi/config/project/` には触れない（設計 11.12）。この画面で直したプロジェクトの `phases.yml` は残る。

共通の設定と同じ id で中身が違う定義か、共通の設定の定義と表示名（title）が重なる定義があると、実行ファイルはその設定のその定義だけを使わず（同じ id なら共通の設定の定義を使い、その設定のほかの定義は使う）、`--lint` が error で言う（設計 11.4.1）。画面は、共通の設定の定義と表示名が重なる定義を id の重なりと同じく止め（保存を押せない、下部に error の文）、同じ id の定義には一文を添える（中身が同じかは画面では比べず、保存の `--lint` に任せる）。共通の設定の `phases.yml` を実行ファイルが読めないときは、上部に error の帯を出す。画面は開き、そのファイルを画面から直したり消したりはしない（エディタで直す）。

編集中の内容は一時ファイルに書いて、`--lint --project-phases-file <名前>=<パス>`（ワークスペースの設定は `self=<パス>`）、共通の設定は `--phases <パス>` で実行ファイルに渡す。実行ファイルは、共通の設定と足した形で確かめる（同じ id、同じ id で中身が違う、表示名の重なり、定義の形）。保存の往復の間は欄を止める。`--lint` は設定全体を見るので、`rules.yml` などに error がある間は定義も保存できない。先に rules を直す。YAML として読めないファイルは画面から直せない（エディタで直す）。

| 何 | どう出るか、何が起きるか |
|---|---|
| 定義 | `phases` を 1 件 1 行（id・title・kind のラベル・review・scope）で並べる。既定は全部畳んであり、行を押すとその下に欄が開く。開いた行は id で覚えておき、更新のあとも開いたまま。欄は id（マップのキー）・title・kind（work / feedback）・review（none / mr）・scope（inherit か glob のリスト）・deliverables と、「補足」の 1 行に畳んだ agent・when（値がある定義だけ最初から開く）。scope と deliverables は `,` 区切りの 1 欄。足す・消す・上下に動かす・改名する。足した行は開いて出る。足した定義の既定は `scope: inherit`。図・「一覧／図」の切り替え・全体計画の待ち方（`order`）の選択・ほかの定義との関係の欄（`overlap`・`requires`・`after`）は無い |
| 保存 | 一時ファイルへ書いて `--lint --project-phases-file` を通し、error があれば保存しない。識別子に使えない id、title の重なり、feedback で `review: none`、提案がワークツリーに在る親の計画が指す定義を消したとき。これらはここで止まる。ただし承認済みチケットの計画は照合せず、定義が読めなくなるときだけ止まる。チケット制御が disable なら照合は走らない。同じ id が 2 つあるときは画面が先に止める（実行ファイルは後ろの定義で知らせずに上書きするため） |
| 欄名 | 日本語で、`phases.yml` のキー名は欄名にマウスを重ねると出る。id = `id`、タイトル = `title`、区分 = `kind`、レビュー = `review`、編集可能な範囲 = `scope`、必須成果物 = `deliverables`、案内するエージェント = `agent`、使う場面 = `when` |
| ファイルが無い | 「設定が無い」正常な状態で、不備の帯は出さない。組み込みの既定も雛形も無い（実行ファイルも持たない）。雛形は置かず、作るボタンも出ない。欄はそのまま触れ、定義を足して保存すると、`--lint` を通った最初の保存でファイルが作られる（先頭に説明のコメントが付く）。定義の無いファイル（`phases: {}`）は先に書き出さない |
| 設定が読めない | 実行ファイルがその設定のファイルを読めず（不正で）空として扱っているとき、上部にその理由が出る |
| 共通の設定に phases.yml がある | ワークスペースかプロジェクトを開いているときは、一覧の下に「共通の設定の定義」の欄を読み取り専用で出す。共通の設定を開いているときは、その欄は出ず一覧が編集できる。読めなければ上部に error の帯を出す。画面は開く |
| 共通の設定の定義と重なる | 表示名が重なる定義は保存を止め、下部に error の文を出す。同じ id の定義には、中身が違えば保存の検証が error にすることを添える |
| 取り込み待ちへ進む | 見出しの「取り込み待ちを開く」を押すと、取り込み待ち画面が開く（プロジェクトの設定を見ているときは、そのプロジェクトのツリー。それ以外はワークスペースのツリー）。実行ファイルが `handoff` の機能を持たなければ押せず、理由が横に出る。案内の間は押せない |
| チケット制御が disable | 画面が開かない（入口も出ない。対象がどれでも同じ）。開いたままのときは何もしない |
| 監視 | 定義のファイル（絶対パスでも）、`.claude/settings.json`、`.claude/settings.local.json`、チケットのフォルダ。外で変われば「ファイルの変更を検知しました」の帯を出し、チケットが動けば保存の可否を取り直す。更新で定義のパスが変わっていれば監視も張り直す |
| 読み直しの見え方 | 画面は React で、拡張ホストが渡すのは中身（`PhasesData`）だけ。リスク管理と同じで、入れ物（HTML）は開いたときに 1 度入るだけ（`retainedHost`）。中身が届くのは編集を捨ててよいときだけで、外で変わっただけのときは帯が出る。往復の間に欄を止めるのもリスク管理と同じ。リストの欄（編集可能な範囲・必須成果物）は打っている途中の文字を欄が持つので、`,` の直後もそのまま打てる。「補足」の開閉は行ごとに 1 度だけ値の有無で決め、あとはユーザが開け閉めしたとおりになる |

次のことを守っている。

- **判定は実行ファイルが出す。** 画面は定義を書くだけで、子の範囲が上限に収まるか、レビューが要るかは出さない。
  それは承認（`ccnavi user agree`）と着手・閉じるときに実行ファイルが知らせる
- **作業中のチケットがある間は保存できない。** 定義は承認・着手・閉じるときに読まれるので、ワークスペースの設定はどのツリーの `doing` でも止める。
- **ターン中は保存の前に確認する。** エージェントがターンの途中（`--explain --json` の `turns` が空でない）に保存すると、次のツール呼び出しで元に戻されることがある。保存は止めず、押した時点でセッションを示して「それでも保存する」を選ばせる。選ばなければ保存せず、画面に取りやめた旨を出す。この欄を出さない古い実行ファイルでは確認を出さない
  プロジェクトの設定は、そのプロジェクトのチケットにしか使われないので、そのプロジェクトの `doing` だけで止める
- **外で変わったら上書きしない。** ルール管理画面と同じ。読み込んだときの更新時刻と保存時のそれが違えば止める
- **コメントを残す。** `phases.yml` のコメントは、変えていない場所ではそのまま。定義を並べ替えたり改名したりすれば、その定義の前の
  コメントも一緒に動く（`phases:` と先頭の定義の間のコメントは先頭の定義に付いて動き、その定義を消せば `phases:` の見出しのコメントとして残る）。
  定義の前の空行は「何番目か」に付いていたものとして揃え、先頭に来た定義には元の空行を持ち込まない。変えていない欄は引用符も含めて触らない。
  ただし `scope` を書いていない定義には保存で `scope: inherit` を補う。新しく足す glob は二重引用符で囲む。
  `kind` と `review` を書いていない定義は既定（work / mr）で出し、変えなければ足さない。
  `version` が無いファイルは保存で先頭に `version: 1` を足す。`phases: {}` の 1 行書きはブロックに直す。中身がマップ（キーと値の組の集まり）でない定義は画面に出ず、保存で消える（苦情にそう書く）
- **実行ファイルが別の型に読む語は囲む。** 実行ファイルは PyYAML（YAML 1.1）で、`yes` `on` `1:30` `0755` のような id・title・when を
  裸で書くと真偽値や数に変わる（lint は止めず、計画から指せない定義になる）。そうなる値だけ二重引用符で囲む
