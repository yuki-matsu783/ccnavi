# 入口とコマンド

拡張を入れると、VS Code の左端（アクティビティバー）に ccnavi のアイコンが出る。押すとサイドパネルに「プロジェクト管理」「ルール管理」「リスク管理」「フェーズ管理」「テンプレート管理」「チケット管理」の入口が名前だけで並ぶ。取り込み待ちは並べず、ルール管理・リスク管理・フェーズ管理・テンプレート管理の各画面の「取り込み待ちを開く」から開く。何ができるかはマウスを重ねると出る。並ぶのは押すと画面が開くものだけで、見た目はパネルのタイトルバーの配色のアイコンから変える。

「チケット管理」「リスク管理」「フェーズ管理」「テンプレート管理」が出るのは、ワークスペースがチケット制御を使っているときだけ。配点も定義もテンプレートもチケットにしか読まれないので、`disable` の間はどれも何も動かさない。`.claude/settings.json`（`settings.local.json` が優先）の `env.CCNAVI_TICKET_CONTROL` が `disable` なら、入口も、コマンドパレットの「チケット管理を開く」「チケット管理を更新」「リスク管理を開く」「フェーズ管理を開く」「テンプレート管理を開く」「チケット管理の基本の案内を見る」も出ない。書いていなければ enable。設定ファイルが変われば、その場で読み直す。ボードを開いたとき、ccnavi の出力（`--explain --json` の `settings.ticket_control`）と食い違えば通知で知らせる。

| ID | 区分 | 要件 |
|---|---|---|
| REQ-VSC-04 | 状態 | 実行ファイルの `--explain --json` が `settings.ticket_control` を `disable` と答えている間、VS Code 拡張は、「チケット管理」「リスク管理」「フェーズ管理」「テンプレート管理」の入口（サイドパネルとコマンドパレット）を出さず、「プロジェクト管理」「ルール管理」の入口だけを出すこと。値は起動したときと `.claude/settings.json`・`.claude/settings.local.json` が変わったとき、ボードを読み直したときに実行ファイルに聞き、設定ファイルの env を自分では読まないこと。実行ファイルから答えが取れないときは入口を出すこと（REQ-DIA-07） |
| REQ-VSC-39 | 事象 | 拡張の版が、左パネルの案内を最後に開いたときの版と違うまま起こされ、ワークスペースが開かれているとき、VS Code 拡張は左パネルの案内（ウォークスルー）を開く。同じ版では 2 度目以降に開かない。サイドパネルのタイトルバーの「?」を押したときは、版に関わらず開く |

## できること

| コマンド（コマンドパレット） | 動き |
|---|---|
| `ccnavi ボード: チケット管理を開く` | チケット管理画面を開く。既に開いていれば増やさず前面に出す |
| `ccnavi ボード: チケット管理を更新` | `ccnavi --explain --json` を走らせ直して内容を差し替える |
| `ccnavi ボード: ルール管理を開く` | 共通の設定のルール管理画面を開く。既に開いていれば前面に出す（別の設定を見ていれば、そのタブの中身を共通の設定のルールに入れ替える） |
| `ccnavi ボード: プロジェクト管理を開く` | プロジェクト管理画面を開く。既に開いていれば前面に出して読み直す |
| `ccnavi ボード: リスク管理を開く` | 共通の設定のリスク管理画面を開く。既に開いていれば前面に出す（別の設定を見ていれば、そのタブの中身を共通の設定の配点に入れ替える）。チケット制御が `disable` なら一覧に出ず、呼ばれても開かずに理由を知らせる |
| `ccnavi ボード: フェーズ管理を開く` | ワークスペースの設定のフェーズ管理画面を開く（「設定」の欄で共通の設定を選ぶと、共通の定義を編集する。ワークスペースかプロジェクトを開いたときは、共通の定義を画面の中に読み取り専用で並べる）。既に開いていれば前面に出す（別の設定を見ていれば、そのタブの中身をワークスペースの設定に入れ替える）。チケット制御が `disable` なら一覧に出ず、呼ばれても開かずに理由を知らせる |
| `ccnavi ボード: テンプレート管理を開く`（`ccnaviBoard.openTemplates`） | テンプレート管理画面を開く（共通の設定・ワークスペース・プロジェクト 1 つの 3 種を、「設定」の欄で切り替える。詳細は [templates.md](templates.md)）。既に開いていれば前面に出す（別の対象を見ていれば、そのタブの中身をワークスペースの設定に入れ替える）。チケット制御が `disable` なら一覧に出ず、呼ばれても開かずに理由を知らせる |
| `ccnavi ボード: 取り込み待ちを開く`（`ccnaviBoard.openHandoff`） | 取り込み待ち画面を開く（ワークスペースのツリー。ほかのツリーは画面上部の「ツリー」の欄で切り替える。詳細は [handoff.md](handoff.md)）。既に開いていれば前面に出す。チケット制御が `disable` でも開く |
| `ccnavi ボード: 計画編集を開く`（`ccnaviBoard.openWorkflow`） | 引数に渡した親の識別子の計画編集タブを開く（[workflow.md](workflow.md)）。開く親を選ぶ段が無いので、コマンドパレットには出さない（キーバインドの `args` などから呼ぶ）。引数が識別子の形でなければ開かずに知らせる |
| `ccnavi ボード: 左パネルの案内を見る`（`ccnaviBoard.tour`） | 左パネルの案内（VS Code のウォークスルー）を開く。サイドパネルのタイトルバーの「?」からも開く |
| `ccnavi ボード: 基本の案内を続けて見る（…）`（`ccnaviBoard.tourBasics`） | プロジェクト管理を開いて基本の案内を動かし、閉じたらチケット管理を開いて基本の案内を動かす。チケット制御が `disable` ならプロジェクト管理だけ。見たあとでも出す |
| `ccnavi ボード: プロジェクト管理の基本の案内を見る`（`ccnaviBoard.tourProjects`） | プロジェクト管理画面を開き、基本の案内を動かす（見たあとでも出す。既に開いていれば、そのタブに出す） |
| `ccnavi ボード: チケット管理の基本の案内を見る`（`ccnaviBoard.tourBoard`） | チケット管理画面で同じことをする。チケット制御が `disable` ならコマンドパレットに出さない |
| `ccnavi ボード: 見た目を切り替える` | 7 つの画面の配色を選ぶ。「VS Code のテーマに従う」（既定）／「Claude ライト」／「Claude ダーク」。設定 `ccnaviBoard.appearance` に書き、開いている画面にはその場で反映する（再描画しないので編集中の内容は消えない） |

タブは画面の種類ごとに 1 枚で、7 種類は同時に開ける。どの画面も、押したらまずタブを出して「<読むもの>を読み込み中…」（「チケットを読み込み中…」「web のルールを読み込み中…」など）を見せ、中身を読み終えたら差し替える。中身を入れた後も、画面のスクリプトが組み上がるまでは同じ一言が出ている。実行ファイルへの問い合わせを待つ間に押し直しても、タブは増えない。読めなかったときもタブは閉じず、中に理由を出す。

ルール管理とリスク管理は、編集する 1 本（共通の設定・ワークスペースの設定・プロジェクトの設定）を切り替えて使い、それとは別に読み取りの統合結果の表示を持つ。フェーズ管理も、編集する 1 本（共通の設定・ワークスペースの設定・プロジェクトの設定）を切り替えて使う。共通の設定を開いていないときは、共通の設定から足される定義を読み取り専用の欄で見せる。別の対象を開くとそのタブの中身が入れ替わる。未保存の変更があれば「未保存の変更があります。破棄して「…」に切り替えますか？」と聞き、やめれば前の対象と編集がそのまま残る。

サイドパネル（左端の ccnavi アイコン）の「プロジェクト管理」「ルール管理」「リスク管理」「フェーズ管理」「テンプレート管理」「チケット管理」は、それぞれ `プロジェクト管理を開く`、`ルール管理を開く`、`リスク管理を開く`、`フェーズ管理を開く`、`テンプレート管理を開く`、`チケット管理を開く` と同じ。`取り込み待ちを開く` はコマンドパレットと各画面のボタンから呼ぶ。チケット制御が `disable` なら、この 6 つのうち「リスク管理」「フェーズ管理」「テンプレート管理」「チケット管理」は並ばない。`見た目を切り替える` は行として並べず、パネルのタイトルバーの配色のアイコンから呼ぶ。今の値（VS Code のテーマに従う / Claude ライト / Claude ダーク）は、行の代わりに見出し「画面」の横に薄く出る。タイトルバーの「?」は `左パネルの案内を見る` を呼ぶ。

## 左パネルの案内

左パネルは VS Code 標準のツリー表示で、画面のような吹き出しを出せない。左パネルの案内は VS Code のウォークスルー（「ccnavi の左パネルの案内」）に置く。段は「左パネルを開く」「プロジェクト管理」「チケット管理」「基本の案内を続けて見る」「ほかの画面と見た目」の 5 つで、チケット制御が `disable` なら「チケット管理」の段は出ない。各段のリンクが、上の `tourProjects`・`tourBoard`・`tourBasics` などを呼ぶ。

拡張の版が、左パネルの案内を最後に開いたときの版（`globalState` の `tour.sidebarVersion`）と違えば、拡張を起こした最初のときに自動で開く（新しく入れたときも開く）。開く前に版を書くので、1 度だけ出る。ワークスペースが開かれていない間は開かず、次にワークスペースを開いて起こしたときに開く。

基本の案内は、プロジェクト管理 → チケット管理の順に続けて動かせる。前の案内を閉じる（最後まで見ても、途中でやめても）と次の画面を開く。頼んだ画面は、見たことがあっても案内を出す。

## 見た目

既定は VS Code のテーマ変数（`--vscode-*`）に従う。`ccnaviBoard.appearance` を `claude-light` / `claude-dark` にすると、7 つの画面の地・枠・文字・入力欄を Claude の配色（橙 `#D97757`、生成りの地 `#FAF9F5`、暖色の濃い地 `#262624`）に置き換える。意味の色（error の赤、warning の黄、成功の緑）も地に合わせた色に置き換える。青系の強調（承認待ち・進行中・焦点）は橙に寄せる。文字の色は地に対して 4.5:1 以上にしてあり、テストがコントラスト比を計算する。

ハイコントラストのテーマ（HC ダーク／ライト）では、VS Code の作法どおり `contrastBorder` と `contrastActiveBorder` の変数で次のものを見せる。開いている行の左の縁（他のテーマでは `focusBorder` の細い縁）、行・カード・ボタンのホバーの点線、メニューの項目の枠（押せない項目は点線）、無効なボタンの点線の枠。これらの変数は HC でしか定義されないので、他のテーマでは何も変わらない。
