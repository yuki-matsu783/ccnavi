# 入口とコマンド

拡張を入れると、VS Codeの左端（アクティビティバー）にccnaviのアイコンが出る。押すとサイドパネルに、見出し「ユーザ待ち」「進行中の親」「画面」のツリーが出る（下の「サイドパネル」）。「画面」には「チケット管理」「プロジェクト管理」「ルール管理」「リスク管理」「フェーズ管理」「テンプレート管理」「取り込み待ち」の入口が名前だけで並ぶ。何ができるかはマウスを重ねると出る。並ぶのは押すと画面が開くものだけで、見た目はパネルのタイトルバーの配色のアイコンから変え、バグ報告はその横の虫のアイコンから始める。

「チケット管理」「リスク管理」「フェーズ管理」「テンプレート管理」が出るのは、ワークスペースがチケット制御を使っているときだけ。配点も定義もテンプレートもチケットにしか読まれないので、`disable`の間はどれも何も動かさない。`.claude/settings.json`（`settings.local.json`が優先）の`env.CCNAVI_TICKET_CONTROL`が`disable`なら、入口も、コマンドパレットの「チケット管理を開く」「チケット管理を更新」「リスク管理を開く」「フェーズ管理を開く」「テンプレート管理を開く」「チケット管理の基本の案内を見る」も出ない。書いていなければenable。設定ファイルが変われば、その場で読み直す。チケット管理画面を開いたとき、ccnaviの出力（`--explain --json`の`settings.ticket_control`）と食い違えば通知で知らせる。

## できること

| コマンド（コマンドパレット） | 動き |
|---|---|
| `ccnaviボード: チケット管理を開く` | チケット管理画面を開く。既に開いていれば増やさず前面に出す |
| `ccnaviボード: チケット管理を更新` | `ccnavi --explain --json`を走らせ直して内容を差し替える |
| `ccnaviボード: ルール管理を開く` | 共通設定のルール管理画面を開く。既に開いていれば前面に出す（別の設定を見ていれば、そのタブの中身を共通設定のルールに入れ替える） |
| `ccnaviボード: プロジェクト管理を開く` | プロジェクト管理画面を開く。既に開いていれば前面に出して読み直す |
| `ccnaviボード: リスク管理を開く` | 共通設定のリスク管理画面を開く。既に開いていれば前面に出す（別の設定を見ていれば、そのタブの中身を共通設定の配点に入れ替える）。チケット制御が`disable`なら一覧に出ず、呼ばれても開かずに理由を知らせる |
| `ccnaviボード: フェーズ管理を開く` | ワークスペースの設定のフェーズ管理画面を開く（「設定」の欄で共通設定を選ぶと、共通の定義を編集する。ワークスペースかプロジェクトを開いたときは、共通の定義を画面の中に読み取り専用で並べる）。既に開いていれば前面に出す（別の設定を見ていれば、そのタブの中身をワークスペースの設定に入れ替える）。チケット制御が`disable`なら一覧に出ず、呼ばれても開かずに理由を知らせる |
| `ccnaviボード: テンプレート管理を開く`（`ccnaviBoard.openTemplates`） | テンプレート管理画面を開く（共通設定・ワークスペース・プロジェクト1つの3種を、「設定」の欄で切り替える。詳細は [templates.md](templates.md)）。既に開いていれば前面に出す（別の対象を見ていれば、そのタブの中身をワークスペースの設定に入れ替える）。チケット制御が`disable`なら一覧に出ず、呼ばれても開かずに理由を知らせる |
| `ccnaviボード: 取り込み待ちを開く`（`ccnaviBoard.openHandoff`） | 取り込み待ち画面を開く（ワークスペースのツリー。ほかのツリーは画面上部の「ツリー」の欄で切り替える。詳細は [handoff.md](handoff.md)）。既に開いていれば前面に出す。チケット制御が`disable`でも開く |
| `ccnaviボード: 計画編集を開く`（`ccnaviBoard.openWorkflow`） | 引数に渡した親の識別子の計画編集タブを開く（[workflow.md](workflow.md)）。開く親を選ぶ段階が無いので、コマンドパレットには出さない（キーバインドの`args`などから呼ぶ）。引数が識別子の形でなければ開かずに知らせる |
| `ccnaviボード: 左パネルの案内を見る`（`ccnaviBoard.tour`） | 左パネルの案内（VS Codeのウォークスルー）を開く。サイドパネルのタイトルバーの「?」からも開く |
| `ccnaviボード: 基本の案内を続けて見る`（`ccnaviBoard.tourBasics`） | プロジェクト管理を開いて基本の案内を動かし、閉じたらチケット管理を開いて基本の案内を動かす。チケット制御が`disable`ならプロジェクト管理だけ。見たあとでも案内を出す |
| `ccnaviボード: プロジェクト管理の基本の案内を見る`（`ccnaviBoard.tourProjects`） | プロジェクト管理画面を開き、基本の案内を動かす（見たあとでも案内を出す。既に開いていれば、そのタブで出す） |
| `ccnaviボード: チケット管理の基本の案内を見る`（`ccnaviBoard.tourBoard`） | チケット管理画面で同じことをする。チケット制御が`disable`ならコマンドパレットに出さない |
| `ccnaviボード: バグ報告を始める`（`ccnaviBoard.bugReport`） | バグ報告を始める（下の「バグ報告」）。サイドパネルのタイトルバーの虫のアイコンと同じ。報告の間に呼ぶと、再現を促す通知を出し直す |
| `ccnaviボード: バグ報告のスクリーンショットを撮る`（`ccnaviBoard.bugReportScreenshot`） | 画面全体をpngで撮る。報告の間だけコマンドパレットに出る |
| `ccnaviボード: バグ報告を終えてzipにまとめる`（`ccnaviBoard.bugReportFinish`） | 報告を終えてzipにまとめる。報告の間だけコマンドパレットに出る |
| `ccnaviボード: 見た目を切り替える` | 9つの画面の配色を選ぶ。「VS Codeのテーマに従う」（既定）／「Claudeライト」／「Claudeダーク」。設定`ccnaviBoard.appearance`に書き、開いている画面にはその場で反映する（再描画しないので編集中の内容は消えない） |

タブは画面の種類ごとに1枚で、7種類は同時に開ける。どの画面も、押したらまずタブを出して「<読むもの>を読み込み中…」（「チケットを読み込み中…」「webのルールを読み込み中…」など）を見せ、中身を読み終えたら差し替える。中身を入れた後も、画面のスクリプトが組み上がるまでは同じ一言が出ている。実行ファイルへの問い合わせを待つ間に押し直しても、タブは増えない。読めなかったときもタブは閉じず、中に理由を出す。

ルール管理とリスク管理は、編集する1本（共通設定・ワークスペースの設定・プロジェクトの設定）を切り替えて使い、それとは別に読み取りの統合結果の表示を持つ。フェーズ管理も、編集する1本（共通設定・ワークスペースの設定・プロジェクトの設定）を切り替えて使う。共通設定を開いていないときは、共通設定から足される定義を読み取り専用の欄で見せる。「設定」の欄で別の対象を選ぶとそのタブの中身が入れ替わる。未保存の変更があれば「未保存の変更があります。破棄して「…」に切り替えますか？」と聞き、やめれば前の対象と編集がそのまま残る。

### 設定の4画面で開く設定

ルール管理・リスク管理・フェーズ管理・テンプレート管理の4画面は、開くときの設定（共通設定・ワークスペースの設定・プロジェクト1つの設定）を共有する。拡張は、4画面のどれかの「設定」の欄でユーザが最後に選び、切り替わった設定を覚える（ワークスペースごとに`workspaceState`へ。未保存の確認でやめたときは覚えない）。画面を開くとき、覚えた設定がいまの`--explain --json`の答えの選択肢にあれば、その設定で開く。無ければ画面の既定（ルール管理とリスク管理は共通設定、フェーズ管理とテンプレート管理はワークスペースの設定）で開き、「プロジェクトapiにはこの設定が無いため、ワークスペースを開きました」のように1行の通知を出す。覚えた設定は書き換えない。答えをまだ1度も読めていないときは選択肢を確かめられないので、覚えた設定で開く（読めなければ画面に理由が出て、「設定」の欄で選び直せる）。覚えたものが無ければ画面の既定で開き、通知は出さない。

すでに開いている画面は、サイドパネルやコマンドから開き直しても前面に出すだけで、設定を切り替えない（未保存の変更があってもなくても同じ）。ほかの画面で設定を選んでも、開いている画面には伝えない。

## サイドパネル

サイドパネル（左端のccnaviアイコン）のツリーは、見出し「ユーザ待ち」「進行中の親」「画面」の3つ。中身はチケット管理画面と同じ1回の`--explain --json`の答えで、チケット管理画面を閉じていても、拡張が動いている間は監視が変化を見つけたら読み直す（REQ-VSC-45）。監視する場所は、チケット管理画面の場所（提案・承認済みチケット・ワークツリーの登録・退避）に、全ツリーの`wip/handoff/`と取り込み先（`.ccnavi/config/`・`.ccnavi/docs/`・`.ccnavi/CCNAVI.md`・`.claude/skills/`）と`.claude/settings.json`・`.claude/settings.local.json`を足したもの。フローの下書き（`wip/proposals/flows/`）は提案の置き場に入る。

| 見出し | 並ぶもの | 押したとき |
|---|---|---|
| ユーザ待ち | `inbox`の種類ごとの行に件数を添え、その下に識別子の行を並べる。承認待ち（親か子かを添える）・レビュー待ち（親とフェーズ）・注意（1つめの不備を添え、全文はマウスを重ねると出る）・取り込み待ち（ツリーごとの件数）・フローの下書き。0件の種類は行を出さない。最後に「片付け」（数えない）。件数の合計は見出しの横とビューのバッジに出す。答えがまだ無いときは「読み込み中…」、読めないときは「読み込めません」（理由はマウスを重ねると出る） | 承認待ち → チケット管理画面でその1件の承認のオーバーレイ。レビュー待ち → そのフェーズのレビュー完了（カードの「レビュー完了」と同じく、ここで初めてMRの残った指摘を取りに行く）。注意 → チケット管理画面でそのカードを選ぶ。取り込み待ち → そのツリーの取り込み待ち画面。フローの下書き → その子のフロー編集。片付け → チケット管理画面の「MRの状況を確認」（ここで初めてリモートのMRを見に行く。結果はチケット管理画面に出る） |
| 進行中の親 | チケット管理画面の「進行中」の列の親を、識別子とタイトル、局面の文（`parents[].stage`）で並べる。無ければ「ありません」 | チケット管理画面でそのカードを選ぶ |
| 画面 | 画面の入口7つ。最初は畳んで出す | それぞれの画面を開く |

「カードを選ぶ」は、チケット管理を開いてそのカードを選び（カードを押したときと同じく右のパネルに出す）、そのカードまで送って焦点を当てること。チケット管理画面を開く前や画面の作り直し中に頼まれたら、拡張が覚えておき、画面ができたときに渡す。そのカードを隠している絞り込み（プロジェクト・親・ユーザ待ちのみ）、畳んだ列、アーカイブの表示を外し、ほかの絞り込みは残す。行けるか（承認待ちに在るか、レビュー待ちのフェーズか）は、チケット管理画面のボタンを押したときと同じく、いまの答えで確かめる。

「画面」の「チケット管理」「プロジェクト管理」「ルール管理」「リスク管理」「フェーズ管理」「テンプレート管理」「取り込み待ち」は、それぞれ`チケット管理を開く`、`プロジェクト管理を開く`、`ルール管理を開く`、`リスク管理を開く`、`フェーズ管理を開く`、`テンプレート管理を開く`、`取り込み待ちを開く`と同じ。取り込み待ちは、ルール管理・リスク管理・フェーズ管理・テンプレート管理の各画面の「取り込み待ちを開く」からも開ける。チケット制御が`disable`なら、「リスク管理」「フェーズ管理」「テンプレート管理」「チケット管理」と、チケットに関わる行（承認待ち・レビュー待ち・注意・フローの下書き・片付け・進行中の親）は並ばない（REQ-VSC-04）。取り込み待ちは残る。`見た目を切り替える`は行として並べず、パネルのタイトルバーの配色のアイコンから呼ぶ。今の値（VS Codeのテーマに従う / Claudeライト / Claudeダーク）は、行の代わりにビューの名前「一覧」の横に薄く出る。タイトルバーの「?」は`左パネルの案内を見る`を呼ぶ。

## 左パネルの案内

左パネルはVS Code標準のツリー表示で、画面のような吹き出しを出せない。左パネルの案内はVS Codeのウォークスルー（「ccnaviの左パネルの案内」）に置く。ステップは「左パネルを開く」「プロジェクト管理」「チケット管理」「基本の案内を続けて見る」「ほかの画面と見た目」の5つで、チケット制御が`disable`なら「チケット管理」のステップは出ない。各ステップのリンクは、上の`tourProjects`・`tourBoard`・`tourBasics`などを呼ぶ。

拡張の版が、左パネルの案内を最後に開いたときの版（`globalState`の`tour.sidebarVersion`）と違えば、拡張が起動した最初のときに自動で開く（新しく入れたときも開く）。開く前に版を記録するので、1度だけ開く。ワークスペースが開かれていない間は開かず、次にワークスペースを開いて起こしたときに開く。

基本の案内は、プロジェクト管理 → チケット管理の順に続けて動かせる。前の案内を閉じる（最後まで見ても、途中でやめても）と次の画面を開く。頼まれた画面は、見たことがあっても案内を出す。

## バグ報告

サイドパネルのタイトルバーの虫のアイコン（配色のアイコンの横）は、画面を開かず、不具合を再現する間の様子を1つのzipにまとめる。チケット制御が`disable`でも出る。

1. 押すと「バグ発生時の挙動を再現してください」の通知が出る。ステータスバーの左に「再現中: 終了」と「スクリーンショット」のボタンが出て、報告の間は、そこから撮ることも終えることもできる（通知は時間が経つと隠れるため）。チケット管理画面のビューのタイトルにも、報告の間だけカメラのボタンが出る（撮れないOSでは、ステータスバーにもタイトルにも出さない）
2. ffmpegが見つかれば、画面全体の録画を始める。WindowsはPATHの`ffmpeg`、WSLはWindows側の`ffmpeg.exe`（相互運用で起動する）、macOSはPATHの`ffmpeg`と`/opt/homebrew/bin`・`/usr/local/bin`を探す。設定`ccnaviBoard.ffmpegPath`があればそれだけを使う。見つからない・始められない（macOSで「画面収録」の許可が無いなど）ときは、その旨を通知して録画だけをやめる。録画は10分で止まる（終了を忘れたときや、拡張ホストが落ちて止められなくなったときに録り続けないため）。macOSの録画は1枚目の画面だけを録る
3. 「スクリーンショット」のボタン（ビューのタイトルのカメラのボタン、通知の「スクリーンショット」も同じ）を押すたびに、画面全体をpngで撮る。ffmpegは使わない（macOSは`screencapture`、WindowsとWSLはPowerShell）。続けて押しても1枚ずつ別の名前で残る
4. 「終了」を押すと、録画を止めてgif（8fps、幅1280pxまで）にし、始めてから`logs/diag/*.log`に足された行、スクリーンショット、説明の`report.txt`（版・OS・録画の結果・起きたエラー）を`logs/bug-report/bug-report-<始めた時刻>.zip`にまとめる。まとめたら場所を通知し、「フォルダで表示」で開ける。録画を始める途中で押したときは、始め終わるのを待ってから止める。zipを書けなかったときは理由をエラーで知らせる

Windows・macOS・WSL以外（WSLでないLinuxなど）では録画もスクリーンショットもせず（通知にも「スクリーンショット」のボタンを出さない）、ログと説明だけをまとめる。ワークスペースを開いていないときは、ログを入れずに一時フォルダへ書く。録画とスクリーンショットは画面に映ったものを、ログはその間の操作の記録をそのまま入れるので、渡す前に中身を確かめるよう、終えたときの通知で促す。`logs/`はgitの管理外なので、zipはコミットされない。

## 見た目

既定はVS Codeのテーマ変数（`--vscode-*`）に従う。`ccnaviBoard.appearance`を`claude-light` / `claude-dark`にすると、9つの画面の地・枠・文字・入力欄をClaudeの配色（橙`#D97757`、生成りの地`#FAF9F5`、暖色の濃い地`#262624`）に置き換える。意味の色（errorの赤、warningの黄、成功の緑）も地に合わせた色に置き換える。青系の強調（承認待ち・進行中・焦点）は橙に寄せる。文字の色は地に対して4.5:1以上にしてあり、テストがコントラスト比を計算する。

文字が細かいときは、`ccnaviBoard.zoom`（0.8〜2、既定1）で9つの画面全体を拡大できる。文字だけでなくボタンや余白も同じ倍率で変わる。VS Code全体の拡大（`window.zoomLevel`）とは別に、ccnaviの画面だけが変わる。範囲の外の値は端に丸め、数でない値は等倍にする。切り替えと同じく、開いている画面にもその場で反映する。コマンドは無く、設定だけで変える。

ハイコントラストのテーマ（HCダーク／ライト）では、VS Codeの作法どおり`contrastBorder`と`contrastActiveBorder`の変数で次のものを見せる。開いている行の左の縁（他のテーマでは`focusBorder`の細い縁）、行・カード・ボタンのホバーの点線、メニューの項目の枠（押せない項目は点線）、無効なボタンの点線の枠。これらの変数はHCでしか定義されないので、他のテーマでは何も変わらない。
