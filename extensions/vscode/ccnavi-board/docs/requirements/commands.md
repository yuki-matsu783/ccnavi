# 入口とコマンド

拡張を入れると、VS Code の左端（アクティビティバー）に ccnavi のアイコンが出る。押すとサイドパネルに「プロジェクト管理」「ルール管理」「リスク管理」「フェーズ管理」「チケット管理」の入口が名前だけで並ぶ（何ができるかはマウスを重ねると出る）。並ぶのは押すと画面が開くものだけで、見た目の切り替えはパネルのタイトルバーの配色のアイコンに置く。

「チケット管理」「リスク管理」「フェーズ管理」が出るのは、ワークスペースがチケット制御を使っているときだけ。配点も定義もチケットにしか読まれないので、`disable` の間はどれも何も動かさない。`.claude/settings.json`（`settings.local.json` が優先）の `env.CCNAVI_TICKET_CONTROL` が `disable` なら、入口も、コマンドパレットの「チケット管理を開く」「チケット管理を更新」「リスク管理を開く」「フェーズ管理を開く」も出ない。書いていなければ enable。設定ファイルが変われば、その場で読み直す。ボードを開いたとき、ccnavi の出力（`--explain --json` の `settings.ticket_control`）と食い違えば通知で知らせる。

| ID | 区分 | 要件 |
|---|---|---|
| REQ-VSC-04 | 状態 | `.claude/settings.json`（`settings.local.json` が優先）の env `CCNAVI_TICKET_CONTROL` が `disable` の間、VS Code 拡張は、「チケット管理」「リスク管理」「フェーズ管理」の入口（サイドパネルとコマンドパレット）を出さず、「プロジェクト管理」「ルール管理」の入口だけを出すこと。書いていない値と読めない値は `enable` として扱うこと。ボードを開いたとき、実行ファイルの `settings.ticket_control` と食い違えば通知で知らせること（REQ-DIA-07） |

## できること

| コマンド（コマンドパレット） | 動き |
|---|---|
| `ccnavi ボード: チケット管理を開く` | チケット管理画面を開く。既に開いていれば増やさず前面に出す |
| `ccnavi ボード: チケット管理を更新` | `ccnavi --explain --json` を走らせ直して内容を差し替える |
| `ccnavi ボード: ルール管理を開く` | 共通の設定のルール管理画面を開く。既に開いていれば前面に出す（別の設定を見ていれば、そのタブの中身を共通の設定のルールに入れ替える） |
| `ccnavi ボード: プロジェクト管理を開く` | プロジェクト管理画面を開く。既に開いていれば前面に出して読み直す |
| `ccnavi ボード: リスク管理を開く` | 共通の設定のリスク管理画面を開く。既に開いていれば前面に出す（別の設定を見ていれば、そのタブの中身を共通の設定の配点に入れ替える）。チケット制御が `disable` なら一覧に出ず、呼ばれても開かずに理由を知らせる |
| `ccnavi ボード: フェーズ管理を開く` | ワークスペースの設定のフェーズ管理画面を開く（フェーズ定義は config にだけ置くので、共通の設定は開かない）。既に開いていれば前面に出す（別の設定を見ていれば、そのタブの中身をワークスペースの設定に入れ替える）。チケット制御が `disable` なら一覧に出ず、呼ばれても開かずに理由を知らせる |
| `ccnavi ボード: 見た目を切り替える` | 5 つの画面の配色を選ぶ。「VS Code のテーマに従う」（既定）／「Claude ライト」／「Claude ダーク」。設定 `ccnaviBoard.appearance` に書き、開いている画面にはその場で反映する（再描画しないので編集中の内容は消えない） |

タブは画面の種類ごとに 1 枚で、5 種類は同時に開ける。どの画面も、押したらまずタブを出して「<読むもの>を読み込み中…」（「チケットを読み込み中…」「web のルールを読み込み中…」など）を見せ、中身を読み終えたら差し替える。中身を入れた後も、画面のスクリプトが組み上がるまでは同じ一言が出ている。実行ファイルへの問い合わせを待つ間に押し直しても、タブは増えない。読めなかったときもタブは閉じず、中に理由を出す。

ルール管理とリスク管理は、編集する 1 本（共通の設定・ワークスペースの設定・プロジェクトの設定）を切り替えて使い、それとは別に読み取りの足し算の表示を持つ。フェーズ管理は、対象（ワークスペースの設定・プロジェクトの設定）を切り替えて使い、足し算の表示は無い（フェーズ定義は足し算をしない）。別の対象を開くとそのタブの中身が入れ替わる。未保存の変更があれば「未保存の変更があります。破棄して「…」に切り替えますか？」と聞き、やめれば前の対象と編集がそのまま残る。

サイドパネル（左端の ccnavi アイコン）の「プロジェクト管理」「ルール管理」「リスク管理」「フェーズ管理」「チケット管理」は、それぞれ `プロジェクト管理を開く`、`ルール管理を開く`、`リスク管理を開く`、`フェーズ管理を開く`、`チケット管理を開く` と同じ。チケット制御が `disable` なら、この 5 つのうち「リスク管理」「フェーズ管理」「チケット管理」は並ばない。`見た目を切り替える` は行として並べず、パネルのタイトルバーの配色のアイコンから呼ぶ。今の値（VS Code のテーマに従う / Claude ライト / Claude ダーク）は、行の代わりに見出し「画面」の横に薄く出る。

## 見た目

既定は VS Code のテーマ変数（`--vscode-*`）に従う。`ccnaviBoard.appearance` を `claude-light` / `claude-dark` にすると、5 つの画面の地・枠・文字・入力欄を Claude の配色（橙 `#D97757`、生成りの地 `#FAF9F5`、暖色の濃い地 `#262624`）に置き換える。意味の色（error の赤、warning の黄、成功の緑）も地に合わせた色に置き換える。青系の強調（承認待ち・進行中・焦点）は橙に寄せる。文字の色は地に対して 4.5:1 以上にしてあり、テストがコントラスト比を計算する。

ハイコントラストのテーマ（HC ダーク／ライト）では、VS Code の作法どおり `contrastBorder` と `contrastActiveBorder` の変数で次のものを見せる。開いている行の左の縁（他のテーマでは `focusBorder` の細い縁）、行・カード・ボタンのホバーの点線、メニューの項目の枠（押せない項目は点線）、無効なボタンの点線の枠。これらの変数は HC でしか定義されないので、他のテーマでは何も変わらない。
