# 取り込み待ち画面

同じ拡張に「取り込み待ち画面」がある。保護対象（`rules.yml`・`phases.yml`・`risks.yml`・テンプレート・`.ccnavi/docs/` の docs・hook やラッパースクリプトなど）を直すとき、エージェントは元のファイルを `wip/handoff/<ツリーからの相対パス>` にコピーして下書きを編集する。この画面は、その下書きの差分を読み、選んだ対象を同じツリーの元のパス（下書きの置き場で読み替えた `.claude` の階層は戻す）へ取り込む。
種類・状態・検査・差分・ハッシュ・取り込めるかを決めて書くのは実行ファイル（`ccnavi user handoff`）で、拡張はその答えを並べ、選んだ対象を実行ファイルに取り込ませるだけにする。拡張は取り込み先のファイルを書かない。
チケット制御が `disable` のワークスペースでも開く（作業中の錠は、チケットが無ければ掛からない）。

## 入口とタブ

| 項目 | 約束 |
|---|---|
| 入口 | ルール管理・リスク管理・フェーズ管理・テンプレート管理の各画面の「取り込み待ちを開く」（サイドパネルには並べない。プロジェクトの設定を見ているときは、そのプロジェクトのツリーを開く）と、コマンドパレットの「ccnavi ボード: 取り込み待ちを開く」（`ccnaviBoard.openHandoff`。開く先はワークスペースのツリー）。ボードのカードの「テンプレートの下書きを作る」の通知からも開ける |
| タブのタイトル | 「ccnavi 取り込み待ち」（ツリーによらず同じ） |
| 枚数 | タブは 1 枚。開いたまま押すと増やさず前面に出す。別のツリーで開かれたときは、そのタブの中身を入れ替える |
| 裏に回したとき | 中身を保持する。裏で選んだ対象・開いた行は、表に戻したときもそのまま |
| 読み込み | 押したらまずタブを出し、「…を読み込み中…」を見せてから中身を入れる。読めなかったときもタブは閉じず、理由を中に出す |

## 見るツリー

実行ファイルは `--root` で指したツリー 1 本の `wip/handoff/` だけを見る。画面上部の「ツリー」の欄で、ワークスペース・プロジェクト・ワークツリーを切り替える（ボードの `trees` から作る）。ほかのツリーの下書きは、そのツリーに切り替えて見る。

## 一覧

見るだけの呼び出し（`user handoff --json`。何も書かない）の答えを、対象ごとに 1 行で出す。

- パス（ツリーからの相対）、種類（`template`・`messages`・`layer-config`・`docs`・`defense`。`messages` は `board` が偽で、ターミナルで取り込む）、状態（`new`・`changed`・`unchanged`・`rejected`）のバッジ
- errors と warnings の件数。見出しを押して開くと、errors・warnings の本文と差分を出す。差分は実行ファイルの文のまま出し（改行コード・BOM・制御文字・ゼロ幅の文字は見える形に直して返る）、拡張は整形しない
- 要約の行に、対象の件数・取り込める件数・選択の件数・対象外（許可リストにヒットしない・リンクのディレクトリ）の件数。実行ファイルが `ignored_paths` を返すときは、要約の外の折りたたみに名前と理由（種類の表に無い・リンクのディレクトリ）を出す。無い・形が違うときは件数だけ

## 取り込めるか

取り込める対象は、`board` が真で、`state` が `new` か `changed` で、errors が無いもの。取り込めない対象は、選べず、理由を行の下に出す。

| ヒットするもの | 出す理由 |
|---|---|
| `board` が偽（`defense`） | ボードからは取り込めない。ターミナルで取り込む |
| `rejected` | 取り込み先として受け付けない対象。errors を直す |
| `unchanged` | 取り込み先と同じ内容で、取り込むものが無い |
| errors がある | 検査で error がある。直してから取り込む |
| 知らない状態 | 知らない状態。実行ファイルを更新する |

warnings だけの対象は取り込める（warnings は行に出す）。

## 取り込み

1. 取り込める対象にチェックを付ける。「取り込める対象をすべて選ぶ」「選択を外す」もある
2. 「選んだ対象を取り込む…」を押すと確認の帯が出る。取り込むパスの一覧を読んで、「この内容で取り込む」を押す（「やめる」で閉じる）
3. 拡張ホストは次の順で進める。どこかではじかれたら取り込みを呼ばず、理由を出す
   - 選んだ対象が見せた一覧にあり、取り込めること
   - 作業中のチケットの錠を、押した時点で取り直して確かめること（次の節）
   - 取り込みたいパスだけを指して見るだけの呼び出しをもう一度行い、返った `expect` を使うこと。拡張はハッシュを自分で組み直さない。見せたあとに対象の `entry_sha` が変わっていれば取り込まない
   - `user handoff <パス…> --yes --expect <ハッシュ> --via board --json` を呼ぶ
4. 画面からの取り込みはターミナルの確認を出さない。代わりに、見せた内容との一致（`--expect`）と、エージェントが Bash から打てない形であること（hook の止め）で守る

## 作業中の錠

作業中のチケットがある間は取り込めない。この制限は拡張の画面だけが持つ。実行ファイルには足さない（ルールの不具合で作業が止まっているときに、ルールを直せなくなるため）。

- 掛けるのは、種類が `template` と `layer-config` の対象。hook は次の呼び出しから設定とテンプレートを読み直すので、着手済みのチケットがある間に書くと判定が途中で変わるため
- テンプレート管理画面の編集の保存も、同じ決まりで止める（[templates.md](templates.md) の REQ-VSC-34）
- `docs` には掛けない。`defense` はボードから取り込めない（ターミナルのみ）ので、掛けない
- 見るツリーがプロジェクトなら、そのプロジェクトの作業中のチケットだけで止める。ワークスペースは、どのツリーの作業中のチケットでも止める。作業中かを答えない実行ファイル、またはボードを読めないときは、止める側に倒す
- 止まっている間は、その種類の対象を選べず、理由を行の下と帯に出す。選んでいた対象は外れる。`docs` の対象は選べる

## `defense` の対象

`board` が偽の対象（hook・ラッパースクリプト・`settings.json` など）は、一覧には出すが、ボードから取り込まない（`--via board` は実行ファイルが断る）。開くと「ターミナルで取り込む」案内を出す。`defense` の開いた案内には、防御がエージェントを止める仕組み（hook など）であることと、ボードから取り込むと防御を外せてしまうためユーザのターミナルで打つことの説明を添える。

- 「ターミナルのコマンドを出す」を押すと、そのパスだけを指して見るだけの呼び出しをもう一度行い、返った `expect` で `ccnavi-user-handoff.sh <パス> --yes --expect <ハッシュ>` を出す。ユーザがターミナルで打つ
- 「コピー」でクリップボードへコピーできる
- 取り込めない状態（`rejected`・`unchanged`）や errors のある対象には、コマンドを出さず、理由を出す

## 取り込みの結果

取り込みが終わったら、一覧を読み直したあとに結果を出す。

- 取り込めた対象（`applied`: パスと種類）
- 消した下書き（`removed_drafts`）
- 残した下書きと理由（`kept_drafts`。取り込みのあとに下書きが編集されていた場合など）
- 取り込めなかったときは理由。見せたあとに対象が変わった、錠が掛かった、`expect` が合わなかった、など

## 読み直しと監視

- 下書きの置き場（`wip/handoff/`）と、取り込み先になる場所（`.ccnavi/config/`・`.ccnavi/docs/`・`.ccnavi/CCNAVI.md`・`.claude/skills/`・`.claude/settings*.json`）を監視し、変わったら自動で読み直す。取り込みの最中とその直後の反応は、取り込みの側が読み直すので破棄する
- 読み直しのとき、選んでいた対象は、同じパスで `entry_sha` が変わらず、いまも取り込める対象だけ残る。ターミナルのコマンドの案内は破棄する
- 作業中のチケットが動いたときは、中身は読み直さず、錠だけを取り直す
- 「更新」はいつでも押せる

## 実行ファイルが古いとき

`ccnavi --version --json` の `features` に `handoff` が無い実行ファイルでは、画面を無効にして「実行ファイルが古い版です。組み立て直してください」の理由を出し、一覧を読まない。「更新」で確かめ直せる。

## 適用範囲外

- 取り込み先のファイルの書き込み。書くのは実行ファイル
- `defense` のボードからの取り込み。ターミナルだけ
- ルール管理・リスク管理・フェーズ管理の画面の保存。これらは今までどおり拡張が直接書く（取り込み待ちには寄せていない）
- 下書きの編集。下書きはエージェントやユーザがエディタで直す。この画面は読んで取り込むだけ
