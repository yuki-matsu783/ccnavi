# リスク管理画面

同じ拡張に「リスク管理画面」がある。実績で測るリスクの配点（`risks.yml`）の境目の点と項目を画面で直し、保存する前に `--lint --risk` を通す。点を数えるのは実行ファイルで、拡張が持つのは、配点を書く場所と、書いた配点が読めるかを確かめる入口だけ。チケット制御が `disable` なら開かない（配点は子チケットを閉じるときにしか読まれない）。

編集する対象は 3 種。共通の設定の配点（`.ccnavi/common/risks.yml`。場所は固定）、ワークスペースの設定の配点（`.ccnavi/config/risks.yml`）、プロジェクトの設定の配点（`projects/<名前>/.ccnavi/config/risks.yml`）。画面上部の「設定」の欄（共通の設定・ワークスペース・設定のあるプロジェクトの一覧）で、編集する 1 本を切り替える。欄は対象が 2 つ以上あるときだけ出る。別の対象を選ぶと中身が入れ替わり、未保存の変更があれば、破棄してよいかを聞く。

判定は共通の設定と、親の `project:` が指す設定の和で行う（設計 11.4.2）。編集する 1 本とは別に、読み取りの足し算の表示を持つ。ワークスペースの足し算は「共通の設定 + ワークスペースの設定」、プロジェクトの足し算は「共通の設定 + そのプロジェクトの設定」を出す。パスを持たない判定の全プロジェクト込みの和ではない（その旨を画面に注記する。配点の合成はそもそも親の `project:` が指す 1 つのレイヤーだけを足す）。足し算の結果は実行ファイルが出し（`--explain --json` が持つ合成結果を使う）、拡張は自分では合成しない。足し算の表示は読み取り専用。

プロジェクトの設定の `risks.yml` は、親チケットの着手（`ticket start`）で上書きされない。着手が配るのは、共通の設定のミラー（そのプロジェクトの `.ccnavi/common/`。配点の `script:` の指す先も同じ `.ccnavi/common/scripts/`）だけで、プロジェクトの `.ccnavi/config/` には触れない（設計 11.12）。この画面でプロジェクトの配点を直して保存した内容は残る。共通の設定の配点を直せば、次の着手でミラーに届く。ミラーは誰も編集しないファイルで、この画面は開かない。

共通の設定とプロジェクトの設定のファイルが無いのは「設定が無い」正常な状態。どちらも無ければ組み込みの配点が効く。

編集中の内容は一時ファイルに書いて、`--lint --risk <パス>` で実行ファイルに渡す。保存の往復の間は欄を止める。`--lint` は設定全体を見るので、`rules.yml` などに error がある間は配点も保存できない。先に rules を直す。YAML として読めないファイルは画面から直せない（エディタで直す）。

| 何 | どう出るか、何が起きるか |
|---|---|
| リスクレベルの基準点 | `levels` の medium / high / critical の 3 欄を 1 行に。空ならそのリスクレベルは組み込みの値（20 / 40 / 70）で、保存しても欄を書かない。説明は見出しの下の「説明」を開くと出る |
| 項目 | `factors` を 1 件 1 行（id、points、加点条件と値をつないだ「〜たら加点」の文と message）で並べる。絞り込みは画面に出ている語（加点条件のラベル・要約の文）でもキーの名前でも当たる。既定は全部畳んであり、行を押すとその下に欄が開く。開いた行は id で覚えておき、更新のあとも開いたまま。欄は id・points・加点条件（lines_over / files_over / deleted_over / glob / script / judge から 1 つ）・その値・max（glob だけ）・message。足す（足した行は開いて出る）・消す・上下に動かす。加点条件を変えると前の加点条件の欄は消え、値は持ち越さない |
| 保存 | 一時ファイルへ書いて `--lint --risk` を通し、error があれば保存しない。整数でない points や逆順の境目の点はここで止まる |
| ファイルが無い | 不備として出さない。共通の設定にもワークスペースの設定にも無いときは組み込みの配点を読み取り専用で見せ、「組み込みの配点でファイルを作る」で同じ値のファイルを書き出す。値が同じなので数え方は変わらない。既にあれば上書きしない |
| チケット制御が disable | 画面が開かない（入口も出ない）。開いたままのときは何もしない |
| 欄名 | 日本語で、`risks.yml` のキー名は欄名にマウスを重ねると出る。id = `id`、点 = `points`、加点条件 = `lines_over` / `files_over` / `deleted_over` / `glob` / `script` / `judge`、基準・glob・スクリプト・yes/no の質問 = 加点条件の値、上限 = `max`、理由 = `message`、MEDIUM / HIGH / CRITICAL = `levels` の各リスクレベル |
| 監視 | 配点のファイル（絶対パスでも）、`.claude/settings.json`、`.claude/settings.local.json`、チケットのフォルダ。外で変われば「ファイルの変更を検知しました」の帯を出し、チケットが動けば保存の可否を取り直す。更新で配点のパスが変わっていれば監視も張り直す |
| 読み直しの見え方 | 画面は React で、拡張ホストが渡すのは中身（`RiskData`）だけ。入れ物（HTML）は開いたときに 1 度入るだけ（`retainedHost`）。中身が届くのは編集を捨ててよいときだけで、ユーザが「更新」を押したときと、保存・作成が通ったとき。外で変わっただけのときは帯が出るだけで、打ちかけの欄も開いた行も残る。絞り込みは読み直しのあとも残る |
| 往復の間 | 「保存」「作る」「更新」を押した時点で欄と 3 つのボタンを止める（帯の中の「更新」も同じ）。ユーザが「破棄して更新しますか？」をやめたときは、拡張ホストがそう伝えて欄が戻る。往復の間に読み直されていたら、遅れて通った保存は捨てる |

次のことを守っている。

- **点は実行ファイルが出す。** 画面は配点を書くだけで、差分を数えて何点になるかは出さない。試算が要るなら
  子を閉じたときの出力と `phases/<親>/<子>.risk.json` を見る
- **作業中のチケットがある間は保存できない。** 配点は子を閉じるときに読まれるので、共通の設定とワークスペースの設定はどのツリーの `doing` でも止める。プロジェクトの設定はそのプロジェクトの `doing` があるときだけ止める
- **外で変わったら上書きしない。** ルール管理画面と同じ。読み込んだときの更新時刻と保存時のそれが違えば止める
- **コメントを残す。** `risks.yml` のコメントは、変えていない場所ではそのまま。項目を並べ替えれば、その項目の前の
  コメントも一緒に動く（`factors:` と先頭の項目の間のコメントは先頭の項目に付いて動き、その項目を消せば `factors:` の見出しのコメントとして残る）。
  項目の前の空行は「何番目か」に付いていたものとして揃え、先頭に来た項目には元の空行を持ち込まない。新しく足す glob は二重引用符で囲む。
  `version` が無いファイルは保存で先頭に `version: 1` を足す。マップ（キーと値の組の集まり）でない項目は画面に出ず、保存で消える（苦情にそう書く）
- **実行ファイルが別の型に読む語は囲む。** 実行ファイルは PyYAML（YAML 1.1）で、`yes` `on` `1:30` `0755` `1_000` のような
  id・message・script・judge を裸で書くと真偽値や数に変わる（lint は止めない）。そうなる値だけ二重引用符で囲む
- **glob 以外の加点条件に `max` は残さない。** 画面に出ない欄が保存で残らないように、加点条件が glob でなければ `max` を消す
