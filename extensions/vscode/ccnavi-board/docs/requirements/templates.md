# テンプレート管理画面

同じ拡張に「テンプレート管理画面」がある。作業・レビュー計画のテンプレート（完了した親の計画と子のフローを 1 ファイルにまとめたもの）と、エージェントが書いた下書きを扱う。一覧・検索・表示に加えて、開いている対象の層のテンプレートは直して保存できる。計画の項と先行の線は図で、子のフローはフロー編集と同じ図で直す（「編集」の節）。下書きは読むだけで、取り込みと編集は「取り込み待ち」の画面（[handoff.md](handoff.md)）で行う。
テンプレートの有効か・捨てた理由・編集中の中身が読めるか・計画の順序・フローの形を決めるのは実行ファイルで、拡張はその答えを並べるだけにする。拡張がテンプレートのファイルを書くのは、ユーザが「編集」の欄で保存を押したときだけ。
チケット制御が `disable` のワークスペースでは開かない。

対象は 3 種。共通の設定（`.ccnavi/config/common/templates/`）、ワークスペースの設定（`.ccnavi/config/project/templates/`）、プロジェクト 1 つの設定（`projects/<名前>/.ccnavi/config/project/templates/`）。
画面上部の「設定」の欄で切り替える。欄は対象が 1 つでも出る。画面の中身は、対象の層（上の一覧）と、その対象に見える統合結果（下の読み取り専用の枠）で決まる。ルール管理・リスク管理と同じ並び（帯 → ツールバー → 本体 → 統合結果の枠）にする。

## 入口とタブ

| 項目 | 約束 |
|---|---|
| 入口 | サイドパネルの「テンプレート管理」と、コマンドパレットの「ccnavi ボード: テンプレート管理を開く」（`ccnaviBoard.openTemplates`）。どちらも開く先はワークスペースの設定 |
| タブの題 | 「ccnavi テンプレート管理」（対象によらず同じ） |
| 枚数 | タブは 1 枚。開いたまま押すと増やさず前面に出す |
| 対象の切り替え | 別の対象を選ぶと、そのタブの中身が入れ替わる |
| 非表示にしたとき | 中身を保持する。非表示の間に開いていた行と本文は、再表示したときもそのまま |
| 読み込み | 押したらまずタブを出し、「…を読み込み中…」を見せてから中身を入れる。読めなかったときもタブは閉じず、理由を中に出す |
| 制御が `disable` | 開かず、呼ばれても開かずに理由を知らせる。サイドパネルとコマンドパレットの入口も出ない |

## 一覧

一覧は、開いている対象の層のテンプレートだけを出す（共通の設定は共通の層、ワークスペースは self、プロジェクトはその層）。層の置き場のパスは、ツールバーの対象の欄の横に出す。

その下に、読み取り専用の枠「統合結果」を出す（既定は閉じている）。統合結果を選ぶ欄で、統合結果（共通 + ワークスペース）とプロジェクトごとの統合結果（共通の設定 + そのプロジェクトの設定）を切り替える。表には、名前・由来の層・使われるか・捨てた理由を、実行ファイルが出した索引のまま出す。1 件の中身は、見たい層に対象を切り替えて上の一覧で開く。

各テンプレートには次を出す。

- 名前・層・説明・いつ使うか（`when`）
- 使える、使えない（使われない）、捨てた理由（統合結果で捨てられたときの理由。統合結果の枠の表にも出す。読めない・同じ中身の重なり・同名の衝突など、実行ファイルの答えのまま）、読み取り専用
- 検査の結果。error・warn・info を、色だけでなく文字のラベルでも出す

拡張はこれらを判定しない。同名の衝突でどちらが効くか、どこで捨てたかは、実行ファイルの答えを読むだけにする。

## 1 件を開く

テンプレートの見出しを押すと、次が見える。

- 計画の項の表（番号・種類・レビュー・待つ項）。全体計画（`plan`）とフィードバック計画（`feedback`）を分けて出す
- フローの要約（子ごとの名前・ノード数・つながり数・種類ごとの数）
- 本文。「本文を見る」で読む。制御文字と書式文字は、読める形の `\uXXXX` に置き換えて出す（実際のファイルの中身は変えない）
- 検査の指摘

本文は読むだけ。直すときは「編集」を押す（次の節）。

## 編集

開いている対象の層（共通の設定なら共通の層、ワークスペースなら self、プロジェクトならその層）のテンプレートは、行を開いて「編集」を押すと、一覧の代わりに編集欄が開く。その層の置き場が読み取り専用（実行ファイルが `writable` を偽と答えた）か、読めない（`valid` が偽）テンプレートには「編集」を出さない（読めないものはファイルを直接直す）。統合結果の枠にあるほかの層のテンプレートは編集できない。一覧の上の「新しいテンプレートの名前」と「作る」で、この層に新しいテンプレートを作れる（保存するまでファイルは作らない。共通の層かこの層に、大文字小文字だけが違う同じ名前があるとき・名前に使えない文字があるときは押せない）。

編集欄の中身は次のとおり。

| 部分 | 何ができるか |
|---|---|
| 説明・使う場面 | `description`（一覧に出す説明）と `when` を直す。名前は変えられない |
| 計画の図 | 全体計画とフィードバック計画ごとに、項と先行の線を図で見せる。項から項へ線を引くと、引かれた項が引いた元の項を待つ（`after`）。線の真ん中の × で消す。引けない線（自分へ・計画をまたぐ・循環）は引けない。先行が自分より小さい添字になるよう、項の番号は画面が付け直す。図の中身（番号・始まる項・終端に当たらない項・順序の error）は実行ファイルの答えのまま描く。答えが戻るまでは線を引けない |
| 計画の表 | 項の種類（この層で使える `phases.yml` の定義から選ぶ。全体計画は `work`、フィードバック計画は `feedback`。定義に無い型は「（定義なし）」と出す）、レビュー（定義のまま / `mr` / `defer`）、前後への並べ替え（先行か後続を越える動きは不可）、削除（全体計画の最後の 1 項は不可。消した項を待っていた項は、消した項の先行を引き継いで待つ）、末尾への追加（前の末尾の項を待つ）。フィードバック計画は空にでき、「フィードバック計画を作る」で作れる。番号はフィードバック計画が全体計画の続き |
| 子のフロー | 全体計画の項ごとに、フローを足す（雛形）・編集する・外す。編集はフロー編集画面の図と右の欄をそのまま使う。部品箱からノードを足せるが、グループ化とコピーはない |
| 検査の指摘 | 直すたびに少し待って実行ファイルに読ませ（`--templates --check-file`）、返った error・warn・info をそのまま出す |
| 元に戻す・やり直す | 編集欄の全体の履歴 |

保存は、次をすべて満たしたときだけ書く。どれかが欠けたら何も書かず、理由を編集欄に出して編集を続けられる。

1. 書き出す本文を実行ファイルに読ませて、error が無い
2. 実行ファイルが読み返した中身が、画面が書こうとした中身と同じ（YAML の読み方の違いで食い違えば書かない）
3. 開いたときからファイルが外で変わっていない（開いたときの内容のハッシュと同じ。新規はまだ無い）
4. 作業中のチケットが無い（次）
5. リンクを辿らず、一時ファイルの入れ替えで書く

**作業中の錠。** 作業中のチケットがある間は、編集はできるが保存できない（取り込み待ち画面がテンプレートの取り込みを止めるのと同じ決まり。[handoff.md](handoff.md) の「作業中の錠」）。共通の設定とワークスペースはどのツリーの作業中でも、プロジェクトはそのプロジェクトの作業中だけで止める。確かめられないときは止める。錠は編集を始めたとき、チケットが動いたとき、保存を押した時点で取り直す。実行ファイルには錠を足さない。

編集の間は、対象の切り替えと「更新」を押せない。外でテンプレートが変わっても編集中の中身は替えない（保存のときに 3 で断る）。未保存のまま閉じるときは、捨ててよいかを聞く。保存したあとの一覧は自動で読み直す。

## 下書き

一覧の下に、エージェントが書いた下書き（`wip/handoff/` に置かれた、種類が `template` のもの。実行ファイルの `--templates --json` の `drafts[]`）を出す。下書きには効力が無く、取り込むまでテンプレートとして使われない。
この画面で下書きは読むだけにする。取り込み・保存・改名・移動・削除の操作は持たない（編集の対象はテンプレートだけで、下書きは編集できない）。取り込みは「取り込み待ち」の画面（[handoff.md](handoff.md)）で行う。
下書きの節に「取り込み待ちを開く」を置く。押すと取り込み待ち画面が開く（プロジェクトの設定を見ているときはそのプロジェクトのツリー、それ以外はワークスペースのツリー）。
1 件ごとに次を出す。

- 名前と置かれたツリー（ワークスペースのルートは空）
- 検査の指摘に error があるとき、その印。読み込めない下書きの印
- 本文や説明に `TODO` が残っているときは、その印

開いた下書きには、パス・説明・使う場面・指摘・計画（全体計画とフィードバック計画）・フローを、テンプレートと同じ形で出す。下書きの本文と取り込み先との差分は、取り込み待ち画面で見る。

## 改名・移動・削除

テンプレートの改名・移動・削除は、この画面にも実行ファイルにも無い。ファイルを直接操作する（その間は衝突の検査と作業中の錠を通らない）。

## 案内

ヘッダ右上の「?」から、基本の案内と使い方ごとの案内（統合結果を読むとき・下書きを読むとき）を選べる。ほかの設定の画面と同じく、案内の間は見本（`tours/templates.yml` の `sample:`）を描き、実際のテンプレートには触れず、拡張ホストへ操作を送らない。初回は拡張ホストが案内を頼み、閉じたら見たことを残す。

## 読み直しと監視

- テンプレートの置き場、下書きの置き場（`wip/handoff/`。ワークスペースのルート・プロジェクト・ワークツリー）、設定ファイル（`.claude/settings.json`・`.claude/settings.local.json`）を監視する
- 画面が書くのは保存のときだけなので、これらが変わったら自動で読み直す（開いた行と本文は、読み直しで閉じる。編集欄は開いたまま、中身を替えない）。自分の保存でも読み直す
- 「更新」はいつでも押せる

## 実行ファイルが古いとき

`ccnavi --version --json` の `flags` に、テンプレート管理画面が使う引数（`--templates`・`--show`）が揃っていなければ、一覧を読まずに理由を画面の中に出す。
理由には、足りない引数の名前と、ワークスペースの ccnavi を更新すれば直ることを書く。編集が使う引数（`--check-file`）だけが無い実行ファイルでは、一覧は読めて、「編集」「作る」を押したときに同じ理由を一覧の上に出す（編集を始めない）。
`features` に `handoff` が無い実行ファイル（取り込み待ち画面を使えない古い版）では、一覧は読めるが、「取り込み待ちを開く」を無効にして「実行ファイルが古い版です。組み立て直してください」の理由を出す。

## 適用範囲外

- ボードのカードから**テンプレート管理画面を開く**入口は無い。カードの「テンプレートの下書きを作る」で下書きを作ったあとに開くのは、取り込み待ち画面である
- テンプレートの改名・移動・削除・複製、下書きの編集。取り込みは取り込み待ち画面、改名・移動・削除はユーザがファイルを直接操作する
- 読めない（`valid` が偽の）テンプレートと、統合結果にあるほかの層のテンプレートの編集
