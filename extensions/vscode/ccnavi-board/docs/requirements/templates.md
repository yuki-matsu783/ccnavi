# テンプレート管理画面

同じ拡張に「テンプレート管理画面」がある。作業・レビュー計画のテンプレート（完了した親の計画と子のフローを1ファイルにまとめたもの）と、エージェントが書いた下書きを扱う。一覧・検索・表示に加えて、開いている対象の設定のテンプレートは直して保存できる。計画のステップと先行の線は図で、子のフローはフロー編集と同じ図で直す（「編集」の節）。下書きは読むだけで、取り込みと編集は「取り込み待ち」の画面（[handoff.md](handoff.md)）で行う。
テンプレートの有効か・破棄した理由・編集中の中身と一覧の図の中身が読めるか・計画の順序・フローの形を決めるのは実行ファイルで、拡張はその答えを並べるだけにする。拡張がテンプレートのファイルを書くのは、ユーザが編集欄で保存を押したときだけ。
チケット制御が`disable`のワークスペースでは開かない。

対象は3種。共通設定（`.ccnavi/config/common/templates/`）、ワークスペースの設定（`.ccnavi/config/project/templates/`）、プロジェクト1つの設定（`projects/<名前>/.ccnavi/config/project/templates/`）。
画面上部の「設定」の欄で切り替える。欄は対象が1つでも出る。画面の中身は、対象の設定（上の一覧）と、その対象に見える統合結果（下の読み取り専用の枠）で決まる。ルール管理・リスク管理と同じ並び（帯 → ツールバー → 本体 → 統合結果の枠）にする。

## 入口とタブ

| 項目 | 約束 |
|---|---|
| 入口 | サイドパネルの「テンプレート管理」と、コマンドパレットの「ccnaviボード: テンプレート管理を開く」（`ccnaviBoard.openTemplates`）。どちらも開く先はワークスペースの設定 |
| タブのタイトル | 「ccnaviテンプレート管理」（対象によらず同じ） |
| 枚数 | タブは1枚。開いたまま押すと増やさず前面に出す |
| 対象の切り替え | 別の対象を選ぶと、そのタブの中身が入れ替わる |
| 非表示にしたとき | 中身を保持する。非表示の間に開いていた行と本文は、再表示したときもそのまま |
| 読み込み | 押したらまずタブを出し、「…を読み込み中…」を見せてから中身を入れる。読めなかったときもタブは閉じず、理由を中に出す |
| 制御が`disable` | 開かず、呼ばれても開かずに理由を知らせる。サイドパネルとコマンドパレットの入口も出ない |

## 一覧

一覧は、開いている対象の設定のテンプレートだけを出す（共通設定ならcommon、ワークスペースならself、プロジェクトならその名前の設定）。設定の置き場のパスは、ツールバーの対象の欄の横に出す。

その下に、読み取り専用の枠「統合結果」を出す（既定は閉じている）。統合結果を選ぶ欄で、統合結果（共通 + ワークスペース）とプロジェクトごとの統合結果（共通 + プロジェクト（名前））を切り替える。表には、名前・由来の設定・使われるか・破棄した理由を、実行ファイルが出した索引のまま出す。1件の中身は、見たい設定に対象を切り替えて上の一覧で開く。

各テンプレートには次を出す。

- 名前・設定の名前・説明・いつ使うか（`when`）
- 有効、無効、使われない、破棄の理由（統合結果で破棄されたときは「使われない」を出さず、理由だけを「破棄: …」と出す。読めない行は「無効」も並べる。共通と全欄が同じで破棄した行（`duplicate`）は、共通の1本が使われていて直すことが無いので、「無効」も「破棄: …」も出さず「共通の側を使用」とだけ出す。破棄の理由の本文は、行の苦情の一覧に1度だけ出し、見出しの下には繰り返さない。統合結果の枠の表にも出す。読めない・同じ中身の重なり・同名の衝突など、実行ファイルの答えのまま）、読み取り専用
- 検査の結果。error・warn・infoを、色だけでなく文字のラベルでも出す

拡張はこれらを判定しない。同名の衝突でどちらが効くか、どこで破棄したかは、実行ファイルの答えを読むだけにする。

## 1件を開く

テンプレートの行は畳んで出し、見出しを押すと開く。件数が増えても一覧を見渡せるようにするためである。一覧の上の絞り込みでは、名前・説明・使う場面の語で絞れるほか、苦情の深刻度でも絞れる（「errorあり」「warnあり」「infoあり」を押すと、その深刻度の苦情を持つテンプレートだけが残る。もう1度押すと外れる）。開いた行には次が見える。

- 計画の図（読むだけ）。全体計画（`plan`）とフィードバック計画（`feedback`）を分けて出す。中身は、行を開いたときにそのファイルを実行ファイルに読ませた答え（`--templates --check-file`）のまま描く
- 子のフローの図（読むだけ）
- 図を読めなかったときは、その理由。読み終えるまでは、計画のステップの表（番号・種類・レビュー・先行ステップ）とフローの要約を出す
- 本文。「本文を見る」で読む。制御文字と書式文字は、読める形の`\uXXXX`に置き換えて出す（実際のファイルの中身は変えない）
- 検査の指摘

本文は読むだけ。直すときは「編集」を押す（次の節）。

## 編集

開いている対象の設定（共通設定ならcommon、ワークスペースならself、プロジェクトならその名前の設定）のテンプレートは、行の「編集」を押すと、一覧の代わりに編集欄が開く。その設定の置き場が読み取り専用（実行ファイルが`writable`を偽と答えた）か、読めない（`valid`が偽）テンプレートには「編集」を出さない（読めないものはファイルを直接直す）。統合結果の枠にあるほかの設定のテンプレートは編集できない。一覧の上の「新しいテンプレート名」と「追加」で、この設定に新しいテンプレートを作れる（保存するまでファイルは作らない。共通設定かこの設定に、大文字小文字だけが違う同じ名前があるとき・名前に使えない文字があるときは押せない。同じ名前があるとき・名前の決まりに合わないときは、その理由を「追加」の横に文字で出す）。新しい名前は、英数字で始め、英数字と`.` `_` `-`だけを使い、64字までとする。末尾の`.`とWindowsの予約名は断る。Windowsの予約名は`con` `prn` `aux` `nul` `com1`〜`com9` `lpt1`〜`lpt9`で、`con.x`のように拡張子が付いても同じに扱う。Windowsでファイル名にできないためである。ccnaviの下書きの作成（`--templates --draft`の`--name`）も同じ決まりに従う。すでに置いてあるファイルの読み込みには、この決まりを使わない。

フェーズ管理・ルール管理・リスク管理は一覧の行を直接編集する。テンプレートは一覧とは別の編集欄で編集する。テンプレートは計画の図と子のフローの図を持ち、編集のたびに実行ファイルに読ませて図と苦情を描き直す。そのため1件ずつ開いて編集する形にしている。一覧のまま全件を編集できる形にすると、全件の図と検査を同時に持つことになるからである。

編集欄の中身は次のとおり。

| 部分 | 何ができるか |
|---|---|
| 説明・使う場面 | `description`（一覧に出す説明）と`when`を直す。名前は変えられない |
| 計画の図 | 全体計画とフィードバック計画ごとに、ステップと先行の線を図で見せる。ステップからステップへ線を引くと、引かれたステップに引いた元のステップが先行する（`after`）。線の真ん中の × で消す。引けない線（自分へ・startとendに触れる・循環・すでにある線）は引けない。線を引いている間は、引けないステップを薄くし、載せたときの説明でも言う。引けない所で放したら、図の下に理由を一言出す（次に図を触るか、少し経つと消える）。先行が自分より小さい添字になるよう、ステップの番号は画面が付け直す。図の中身（番号・始まるステップ・終端に届かないステップ・順序のerror）は実行ファイルの答えのまま描く。答えが戻るまでは直す前の図のまま「読んでいます」と出すが、その間も線を引け、× で消せる。画面は、番号とは別に編集の間だけ変わらない印でステップを覚え、図の番号を今のステップへ引き直す。番号が振り直っても別のステップを指さない。番号が振り直っても点は置いた場所から動かず、表示する番号だけが変わる。新しいステップは空いた場所に置く。「並べ直す」で今の線から置き直す |
| ステップを選ぶ・詳細の欄 | 図のステップか、表の行の番号を押すと、そのステップを選ぶ。選んだステップは図の点と表の行の両方で目立たせ、図の空いた所を押すと選ぶのをやめる。選んだステップは番号ではなくステップに付く（番号が振り直っても同じステップを選んだまま）。図の右に詳細の欄を出す（計画編集タブと同じ部品で、畳める。畳んだかは画面が覚える）。欄には、選んだステップの番号・タイトル・先行と後続・すぐ始まるか・終端に届かないかを実行ファイルの答えのまま読むだけで出し（答えが戻る前に追加したステップは、読み終えると出る）。その上に、種類とレビューの指定（表と同じ選択肢）・削除（表の削除と同じ決まり）・ステップを追加する操作（次の行）を置く。全体計画のステップには「子のフローを追加」か「子のフローへ移る」も置き、移ると子のフローの節のそのステップの図を開いて画面をそこまで送る |
| 図からステップを追加する | 選んだステップに対して、詳細の欄の「追加するステップの種類」で選んだ型のステップを追加する。「この後に挟む」は、新しいステップに選んだステップを先行させ、選んだステップを先行にしていたステップは代わりに新しいステップを先行にする（直列の途中に入る）。「これと並べて追加」は、新しいステップに選んだステップと同じ先行を付け、選んだステップを先行にしていたステップは新しいステップも先行にする（並行に走って同じ所で合流する。選んだステップが最後なら合流先が無く、終端に届かないステップになる。そう出すのは実行ファイルの答え）。追加したあとは先行が自分より小さい添字になるよう番号を振り直し、ほかの点は動かさず、追加したステップを選ぶ |
| 計画の表 | ステップの種類（この設定で指定できる`phases.yml`の定義から選ぶ。全体計画は`work`、フィードバック計画は`feedback`。定義に無い型は「（定義なし）」と出す）、レビューの指定（定義のまま / `review: true` / `review: false` / `deferred: true`）、前後への並べ替え（先行か後続を越える動きは不可）、削除（全体計画の最後の1ステップは不可。消したステップが先行だったステップは、消したステップの先行を引き継ぐ。子のフローを持つステップは、フローも一緒に消えることを削除ボタンで先に言い、消したあとは「元に戻す」で戻せると編集欄に出す）、末尾への追加（前の末尾のステップが先行する）、先行ステップの選び（自分より前のステップの番号をチェックで選ぶ。図に線を引くのと同じ結果になり、図を使わずキーボードでも直せる）。並べ替えは表でだけ行う（図の上の位置と番号は別のもの）。フィードバック計画は空にでき、「フィードバック計画を追加」で作れる。番号はフィードバック計画が全体計画の続き |
| 子のフロー | 全体計画のステップごとに、フローを追加する（雛形）・図を開いたまま直す・外す。行の見出しは「1:設計 のフロー」の形（番号と、その型の定義のタイトル）。図は最初から開いていて、「畳む」「図を開く」で開閉する。直すときはフロー編集画面の図と右の欄をそのまま使う。部品箱からノードを足せるが、グループ化とコピーはない。右の欄の案内文は、共通の部品を使うが、グループ化・Ctrl+C / V / D・Ctrl+Zの案内は出さない。元に戻すときは、編集欄の「元に戻す」かCtrl+Zを使う（編集欄の全体の履歴で戻る） |
| 検査の指摘 | 直すたびに少し待って実行ファイルに読ませ（`--templates --check-file`）、返ったerror・warn・infoをそのまま出す。ただし作った直後でまだ何も入力していない間は、errorを出さない（warn・infoは出す）。触ったあと・保存を押したあとは全部出す |
| 元に戻す・やり直す | 編集欄の全体の履歴。ボタンのほか、Ctrl+Z（元に戻す）とCtrl+Y・Ctrl+Shift+Z（やり直す）でも動く（macOSはCmd）。文字の欄の中では、そのキーは欄の文字の取り消しに任せる |

保存はCtrl+Sでもでき、押せない理由はボタンのツールチップに出る（[設定を直す画面に共通の操作](../requirements.md#設定を直す画面に共通の操作)）。保存は、次をすべて満たしたときだけ書く。どれかが欠けたら何も書かず、理由を編集欄に出して編集を続けられる。

1. 書き出す本文を実行ファイルに読ませて、errorが無い
2. 実行ファイルが読み返した中身が、画面が書こうとした中身と同じ（YAMLの読み方の違いで食い違えば書かない）
3. 開いたときからファイルが外で変わっていない（開いたときの内容のハッシュと同じ。新規はまだ無い）
4. 作業中のチケットが無い（次）
5. リンクを辿らず、一時ファイルの入れ替えで書く

**作業中の錠。** 作業中のチケットがある間は、編集はできるが保存できない（取り込み待ち画面がテンプレートの取り込みを止めるのと同じ決まり。[handoff.md](handoff.md)の「作業中の錠」）。共通設定とワークスペースはどのツリーの作業中でも、プロジェクトはそのプロジェクトの作業中だけで止める。確かめられないときは止める。錠は編集を始めたとき、チケットが動いたとき、保存を押した時点で取り直す。実行ファイルには錠を足さない。

**応答中の確認。** エージェントが応答の途中（`--explain --json`の`turns`が空でない）に保存を押したときは、保存の前に「それでも保存する」を選ばせる。選ばなければ保存しない。

編集の間は、対象の切り替えと「更新」を押せない。コマンドなど外から別の対象で開かれても切り替えない。切り替えると古い対象の編集欄が残るためである。そのときは「編集中のため切り替えません。保存か破棄してから切り替えてください」と知らせる。計画の表の操作の列は、狭い幅で表を横にスクロールしても右端に残す。外でテンプレートが変わっても編集中の中身は替えない（保存のときに3で断る）。編集欄の「閉じる」で未保存のまま閉じるときは、破棄してよいかを聞く。タブを閉じるのはVS CodeのWebviewでは止められない。そのため、未保存の間はタブのタイトルの頭に「●」を付け、未保存のままタブを閉じたら、閉じた後に「YAMLで開く」「破棄する」を聞く。「YAMLで開く」は閉じる前の編集を名前の無いYAMLのエディタで開くだけで、ファイルには書かない。保存したあとの一覧は自動で読み直す。

## 下書き

一覧の下に、エージェントが書いた下書き（`wip/handoff/`に置かれた、種類が`template`のもの。実行ファイルの`--templates --json`の`drafts[]`）を出す。下書きには効力が無く、取り込むまでテンプレートとして使われない。
この画面で下書きは読むだけにする。取り込み・保存・改名・移動・削除の操作は持たない（編集の対象はテンプレートだけで、下書きは編集できない）。取り込みは「取り込み待ち」の画面（[handoff.md](handoff.md)）で行う。
下書きの節に「取り込み待ちを開く」を置く。押すと取り込み待ち画面が開く（プロジェクトの設定を見ているときはそのプロジェクトのツリー、それ以外はワークスペースのツリー）。
1件ごとに次を出す。

- 名前と置かれたツリー（ワークスペースのルートは空）
- 検査の指摘にerrorがあるとき、その印。読み込めない下書きの印
- 本文や説明に`TODO`が残っているときは、その印

開いた下書きには、パス・説明・使う場面・指摘・計画（全体計画とフィードバック計画）・フローを、テンプレートと同じ形で出す。下書きの本文と取り込み先との差分は、取り込み待ち画面で見る。

## 改名・移動・削除

テンプレートの改名・移動・削除は、この画面にも実行ファイルにも無い。ファイルを直接操作する（その間は衝突の検査と作業中の錠を通らない）。

## 案内

ヘッダ右上の「?」から、基本の案内と使い方ごとの案内（統合結果を読むとき・下書きを読むとき）を選べる。ほかの設定の画面と同じく、案内の間は見本（`tours/templates.yml`の`sample:`）を描き、実際のテンプレートには触れず、拡張ホストへ操作を送らない（図の取り出しも頼まない。見本の行は表で見せる）。初回は拡張ホストが案内を頼み、閉じたら見たことを残す。

「完了した作業からテンプレートを溜めたいとき」と「テンプレートで次の親の提案を始めたいとき」の2本は、時系列の図で示す。親を閉じるときの案内から下書きを作り、取り込み待ち画面で取り込むまで、取り込んだテンプレートで次の親の提案を始める流れ（フィードバック計画の有無で結果が変わること）。本文の下に出る時系列の図は、登場者を左から並べ、矢印を上から下へ時間順に並べる。矢印には、実際に入れる値や出る答えを等幅で添える。手順ごとに、いま説明している矢印だけを光らせ、ほかは薄く出す。

## 読み直しと監視

- テンプレートの置き場、下書きの置き場（`wip/handoff/`。ワークスペースのルート・プロジェクト・ワークツリー）、設定ファイル（`.claude/settings.json`・`.claude/settings.local.json`）を監視する
- 画面が書くのは保存のときだけなので、これらが変わったら自動で読み直す（開いた行と本文は、読み直しで閉じる。編集欄は開いたまま、中身を替えない）。自分の保存でも読み直す
- 「更新」はいつでも押せる

## 適用範囲外

- チケット管理画面のカードから**テンプレート管理画面を開く**入口は無い。カードの「テンプレートの下書きを作る」で下書きを作ったあとに開くのは、取り込み待ち画面である
- テンプレートの改名・移動・削除・複製、下書きの編集。取り込みは取り込み待ち画面、改名・移動・削除はユーザがファイルを直接操作する
- 読めない（`valid`が偽の）テンプレートと、統合結果にあるほかの設定のテンプレートの編集

## 要件
