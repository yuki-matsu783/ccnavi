# チケット管理画面（ボード）

列は 未着手 / 作業中（承認済み・レビュー待ちを含む）/ 完了 / 取り消し。保存先のフォルダとの対応は、未着手 = `wip/proposals/todo/`、作業中 = `.ccnavi/approved/doing/` と `wip/proposals/review/`（レビュー待ちはカードの属性「レビュー待ち」で分かる）、完了 = `.ccnavi/approved/done/`、取り消し = 同じ `done/` で `cancelled_at` を持つもの。

カードに枠付きのバッジが付くのは、ユーザが動く必要がある状態だけ（未承認・レビュー準備中／レビュー待ち・書き込み停止中・先行待ち・ワークツリーなし・実績のリスクが HIGH 以上・複数の場所にある）。

「先行待ち（<識別子>）」は、子が挙げる先行（`predecessors`）のどれかが `done/` に無いか取り消し済みのため、承認と着手（`start`）が止まっていることを表す。tooltip では、承認待ちのカードなら承認も着手も止まり、承認済みで未着手なら着手が止まる、と書き分ける。着手済み・レビュー待ちのカードでは「先行が未完了（<識別子>）」になり、作業と `finish` は止まらないことを示す。書き込みはどちらでも止まらない。どの先行が何の状態かはバッジの tooltip に出る。数えるのは実行ファイル（`predecessors_unmet`）で、ボードはその結果を表示するだけ。

「複数の場所にある」は、同じ ID のチケットが別々の保存先のフォルダ（`doing/` と `done/` など）に残っていて、どれを本物とするか決まらないときに付く。こうなるのは、移動が途中で止まったときか、先に進んだワークツリーがまだ合流していないとき。子のワークツリーに承認済みチケットがあるだけなら、本物とする側が決まるので付かない。本物とするのは親のツリー（親自身なら自分のツリー）にある側で、そこに無ければ元ツリー（ワークスペースルート。プロジェクトのチケットならそのプロジェクト）にある側。ただし親のツリーが無く、元ツリーより先のフォルダに合流していない承認済みチケットがあるときは、どれを本物とするか決めずに付く。別のリポジトリにある同じ ID は同じチケットと見なさず、1 件にまとめずに数える。`todo/` が並んでいれば、ほかのフォルダが違っていても付かない（同じフォルダの重複があるときだけ付く）。

レビューが済むまで止まっている間は、その段の名前のバッジを 1 枚だけ出す。依頼を出すまでが「レビュー準備中」で、次に動くのはエージェント。出してからレビュー済みまでが「レビュー待ち」で、次に動くのはユーザ（判定はこれを JSON の `review_waiting` で示す）。レビューが済んだカードには出ない。親カードのフェーズ行の要約にも同じ名前が出る。依頼のマーカー自体は残り、経緯としてフェーズ行の全文（広げたときとツールチップ）と `ccnavi --explain` の文には出る。

承認済み／レビュー待ち／クローズ、人間レビューの要否、ワークツリーの名前、レビュー済み／省略、MEDIUM 以下のリスク、base は、枠の無い薄い文字で 1 行に並ぶ。列やバッジと同じことは重ねない。完了・取り消しの列にいるカードには、クローズと人間レビューの要否を出さない（レビュー済み／省略とリスクの点は残る）。提案が残っていて未着手・作業中の列にいる閉じたカードには、食い違いの手がかりとしてクローズを出す。終了のマーカーは、止まっている間はバッジの「レビュー準備中」で分かるのでカードに出さない。済んだ後も含めて、フェーズ行の全文には残る。

親カードにはフェーズの一覧が 1 フェーズ 1 行で付く。左の丸がフェーズ（終了は緑の塗り、進行中は青の輪）、右が状態。カードの内寸が 480px 未満（1920px の画面で 4 列のときも含む）では、状態をバッジと同じ項目の要約に絞る（レビュー準備中／レビュー待ち、HIGH 以上のリスク。順調なフェーズは空）。他の列を畳むかドラッグで広げて 480px 以上になると、フェーズの状態、マーカー、レビューの要否、リスクの点と理由まで出る全文に替わる。狭いときも読み上げには全文を渡す。全文は行にマウスを載せるとツールチップにも出る。止まっているフェーズは名前も状態も赤になる。

上部の見出しには、承認待ちと不備の件数を 1 件以上のときだけ出し、残りと全体は薄く添える。

カードに状態の履歴があれば、畳んだ「履歴（N 件）」が付く。開くと新しい順に、時刻（UTC）・何が動いたか（「承認（承認待ち → 作業中）」「フェーズ 1: レビュー依頼済み」など）・経路（sh（ccnavi-ticket.sh など）/ ターミナル / ボード / hook）が並ぶ。sh の経路は、打ったのがエージェントかユーザかを区別できないので断定しない。並ぶのは、実行ファイルが渡す履歴のうち新しい側の 20 件まで。列・バッジ・要対応は状態の履歴から決めない（状態の正は置き場）。履歴の上を押しても提案は開かない。

上部の「要対応のみ」を入れると、ユーザが対応する必要があるカード（承認待ち、バッジが付くもの、不備、レビュー準備中やレビュー待ちのフェーズを持つ親）だけが残る。

その隣の「アーカイブ済みチケットを表示」を入れると、5 つめの列「アーカイブ」が出て、Draft を外したとき（`ccnavi-review.sh ready`）に手元の `logs/archive/` へ退避した閉じたチケットが並ぶ。既定は外してあり、列ごと出ない。アーカイブのカードは表示だけで、操作もバッジも持たず、上部の件数（残り・全・不備）にも数えない。押すと退避したファイルを開く。

依頼のマーカーが持つマージリクエストは「MR #N」のリンクで出て、既定のブラウザで開く。親カードのリンクはマージリクエスト自体を、フェーズ行のリンクは依頼の投稿を指す。ボードはリモートを見に行かないので、リンクの先が閉じられていても気づかない。

列は画面の幅に合わせて伸び縮みし、1 列が 220px より狭くなるとき（エディタを分割したときや、サイドパネルが広いとき）だけ横スクロールになる。列の見出しを押すと、その列を見出し 1 行ぶんの幅に畳める。列の右端をドラッグすると幅を固定でき、ダブルクリックで元の伸び縮みに戻る。幅を固定した列も、畳めば見出し 1 行ぶんに縮み、広げると固定した幅に戻る。畳んだ列・列の幅・絞り込みは更新しても残る。

ユーザの承認はボードのオーバーレイで行う。「承認」を押すと、拡張が `ccnavi --agree --preview --json` を子プロセスで打ち、承認待ちの一覧（いま承認待ちのもの全部）の本文・対象外の提案・読めない提案をボードの上に出す。「この N 件を承認する」を押すと `ccnavi --agree --yes <識別子,…> --json` を打つ。実行ファイルは「見せた一覧と今の一覧が同じ」ことを確かめてから承認済みチケットを置き、違えば何も置かない。そのときボードは一覧を読み直して出し直す。この経路ではターミナルからの起動（stdin が tty）を求めない。エージェントが Bash で同じ形のコマンドを打っても、実行ファイルの組み込みの deny が止める。

承認できたら、同じオーバーレイが「N 件を承認しました」に替わる。Claude Code に渡す文（承認された識別子と後工程の進め方）は、「コピー」「新しいセッションで開く」の 2 ボタンで渡す。「コピー」なら文をコピーし、「新しいセッションで開く」なら `vscode://anthropic.claude-code/open?prompt=…` で新しいセッションの入力欄に入れる。送信はユーザが Enter で行う。hook は承認をモデルに知らせない。進行中のセッションで続けるときは、この文を貼るか、エージェントに `ccnavi-ticket.sh status` で承認済みチケットの状態を確かめさせる。

レビューの未解決の指摘には、フェーズ行の「対応方針を決める」で対応方針を選ぶ。承認と同じオーバーレイが開いて指摘が 1 件ずつ並び、それぞれに対応方針（対応しない・このフェーズで直す・issue に回す）を選ぶ。拡張は `ccnavi-review.sh decide <N> --preview` で指摘と digest（指摘一覧の照合用の値）を読み、ボタンが押されたら `decide <N> --choices … --digest …` を子プロセスで打つ（ホストを読むのは sh）。全部の指摘に選ぶまでボタンは押せず、置いている最中はオーバーレイを閉じない。置けたら、決めた結果を Claude Code に渡す文を出す。親を早めに閉じる `close-early` はボードに出さないので、ターミナルで `ccnavi-review.sh close-early` を打つ。

レビューを終えたことをエージェントに伝えるのは、フェーズ行の「レビュー済み連絡」。承認と同じオーバーレイに文を出し、「コピー」「新しいセッションで開く」で Claude Code に渡す。文は「[ccnavi] ユーザが親 X のフェーズ N のレビューを終えた。」で始まり、親が自分のワークツリーで `confirm --phase N` を単体で打つよう求める。拡張はマーカーを置かず、実行ファイルも sh も起動しない。`confirm` を打ってマーカーを置くのは、文を受けた親（メインエージェント）。未解決の指摘が残っていれば、`confirm` がその一覧と次の方法を返す。文が「連結せず単体で」と求めるのは、レビューで止まった親のワークツリーでは `sh …ccnavi-review.sh …` の形だけが通り、`cd … && sh …` は止まるため（設計 9.8）。

ボードの中で。

| 操作 | 何が起きるか |
|---|---|
| カードをクリック / Enter | そのチケットの提案（無ければ承認済みチケット）を Markdown プレビューで開く。組み込みの Markdown 拡張が無効ならエディタで開く |
| 上部の「承認待ち N 件を承認」 | `--agree --preview --json` を打ち、承認のオーバーレイを出す。承認待ちのチケットの表（ID・タイトル・場所）、承認画面の本文、承認の対象にしない提案とその理由、読めない提案が並ぶ。絞り込み中は、見えている承認待ちの識別子を並べて渡し（`--agree --preview --json i0002 i0002-01-01`）、その分だけが承認の対象になる。絞り込みが無ければ承認待ち全部。親や親の改版を対象から外した子は実行ファイルが落とし、何も承認しない |
| 未承認カードの「この 1 件を承認」 | そのカードの識別子だけを渡し（`--agree --preview --json i0002-01-03`）、その 1 件だけでオーバーレイを出す。同じ親の承認待ちが他にあっても巻き込まない。親や親の改版が承認待ちのまま子だけを押したときは、実行ファイルが断った理由をオーバーレイに出し、何も承認しない |
| オーバーレイの「この N 件を承認する」 | 見せた識別子をそのまま `--agree --yes <識別子,…> --json` に渡す。一覧が変わっていれば何も置かれず、読み直して「表示した一覧と今の一覧が違います」と出る。読み直しは、見せたときと同じ絞り（カードの 1 件、絞り込みで見えていた分）で行い、その絞りが通らない（識別子がもう承認待ちに無い、親の改版が承認待ちに入った）ときだけ承認待ち全部に戻す。承認できたらオーバーレイが「N 件を承認しました」に替わり、Claude Code に渡す文と「コピー」「新しいセッションで開く」「閉じる」が出る。同じところでボードを読み直す（監視だけに頼らない）ので、オーバーレイを閉じるころには列が動いている。1 件も置かれなかったときは読み直さない |
| オーバーレイの「やめる」「閉じる」/ Esc | 何もせず閉じる。承認している最中は閉じない |
| 承認後の「コピー」 | Claude Code に渡す文（`--yes` の `prompt`）をコピーし、オーバーレイを閉じる。進行中のセッションに貼って送る |
| 承認後の「新しいセッションで開く」 | `vscode://anthropic.claude-code/open?prompt=…` を開き、オーバーレイを閉じる。Claude Code の新しいタブに文が入る。送信はユーザが Enter |
| フェーズ行の「対応方針を決める」 | 依頼済みで止まったまま（レビュー待ち）のフェーズに出る。未解決の指摘のオーバーレイを開く。sh（`<ワークスペースルート>/.ccnavi/scripts/ccnavi-review.sh`）を親のワークツリーを cwd にして子プロセスで走らせる（プロジェクトのワークツリーには `.ccnavi/scripts/` が無いので、ルートからのパスで呼ぶ）。Windows は統合ターミナルと同じ Git Bash で走らせる |
| フェーズ行の「レビュー済み連絡」 | 「受け入れ」と同じ条件で出る。何も起こさず、Claude Code に渡す文（親の識別子・フェーズ・依頼のマーカーのマージリクエストの URL・親のワークツリーで `ccnavi-review.sh confirm --phase <N>` を打つこと）を組んでオーバーレイに出す。「コピー」「新しいセッションで開く」「閉じる」は承認の後と同じ。親のワークツリーが無い、そのフェーズがユーザのレビュー待ちでない（ボードが古い）ときは通知で断る。承認のオーバーレイ（読み込み中・一覧・承認中・承認した文）の上には被せない。承認した文は取り返せないので、渡し終えるか閉じるまで残す。文の sh のパスは実行ファイルの案内と同じく realpath で解いたワークスペースルートから書く |
| フェーズ行・親カードの「MR #N」 | 依頼のマーカー（`marks.requested` の `mr` / `url`）をそのまま表示する。フェーズ行は依頼の投稿、親カードは `#` から後ろを落としたマージリクエスト自体。http(s) 以外の URL はリンクにせず文字で出す。リンクの上ではカードを開かない |
| 「要対応のみ」 | ユーザが対応する必要があるカードだけを出す。条件は、承認待ち（`pending_approval`）、レビュー準備中／レビュー待ち、書き込み停止中（`blocked`）、未着手・作業中なのにワークツリーが無い、HIGH 以上のリスク、複数の場所にある（同じ ID が別々の保存先のフォルダに残り、どれを本物とするか決まらない）、不備、親ならフェーズ行の要約（レビュー準備中／レビュー待ち・HIGH 以上）に出るもの。承認待ちは新規の未承認と親の改版で、バッジの「未承認」とは違い、改版を含む。書き込み停止中は不備としても出る。組み立て（`board.ts`）が付けた目印を画面が読むだけ。プロジェクト・親の絞り込みと重ねて適用され、列の件数と「承認待ち N 件を承認」もその分になる。選択は Webview の状態として覚える |
| 「アーカイブ済みチケットを表示」 | 手元の退避（`logs/archive/`。実行ファイルの JSON の `archived[]`）にある閉じたチケットを「アーカイブ」の列に出す。既定は外していて、外している間は列もカードも出ない。入れると、右端に足されたアーカイブの列まで横へスクロールする。プロジェクト・親・要対応の絞り込みと重ねて適用される（アーカイブのカードは要対応に入らない）。`logs/archive/` の変化も監視するので、`ready` の後に自動で読み直る。選択は Webview の状態として覚える |
| プロジェクトの絞り込み | `projects/` があるときだけ出る。選択は Webview の状態として覚える |
| 親の絞り込み | 親チケットが 1 つでもあれば出る。選んだ親とその子だけを出す。プロジェクトの絞り込みと重ねて使える。選択は Webview の状態として覚える |
| 絞り込みと件数 | 列の見出しの件数と「承認待ち N 件を承認」の N は、絞り込みで見えている分の数になる。上部の「残り／全／不備／承認待ち」はボード全体の数のまま |
| 動いた表示 | 前の読み直しから列が変わったカード（承認された、レビュー不要で閉じた、レビューが済んだ、取り消された）と、新しく現れたカードに緑の輪と帯が出る。帯は「未着手 → 作業中」「新規起票」のように書く。新しく現れたカードは行き先を言わない。もう置かれた列で読める。着手（`ticket start`）は列を動かさないので動いた表示は出ない。時間では消さず、次に何かが動くまで残す。開いた直後は出ない。列が動いていないボードが渡し直されても（オーバーレイの出し入れ、何も変わらなかった「更新」）作り直さない。読み直せなかった画面を挟んでも、最後に読めたボードと比べる。色だけに頼らず帯の文で伝え、`prefers-reduced-motion` では光らない。覚えるのは拡張ホストで、画面が作り直されても表示は残る。パネルを閉じると消える（`core/board-moved.ts`） |
| 「更新」 | ボードを読み直す。押すとすぐに非活性になり、回り記号と「更新中…」に替わる。読み直しが終わると HTML が作り直され、新しい画面のボタンは活性で出る。失敗したときは更新ボタンごとエラー画面に差し替わるので、やり直しはコマンドパレットの「チケット管理を更新」から。実行ファイルが 60 秒で返らないときは打ち切って失敗として見せる。監視による自動の読み直しと、コマンドパレットの「チケット管理を更新」では、ボタンの見た目は変わらない |

- 提案（`wip/**/proposals/`、全ワークツリーの同じ場所）・承認済みチケットとマーカー（`.ccnavi/approved/`）・
  ワークツリーの登録（`.git/worktrees/`、`projects/*/.git/worktrees/`）を監視し、変化が 120 ミリ秒
  止まったら自動で読み直す。オーバーレイの状態は拡張側が持つので、読み直しで HTML が作り直されても消えない
- 承認の後も、承認済みチケットが `.ccnavi/approved/doing/` に置かれたことで読み直す
- それとは別に、承認の側からも読み直す（`approval-machine.ts` の `refresh`）。承認済みチケットの置き場は
  固定で、`core/watch.ts` の監視するパスとずれない。この読み直しは `files.watcherExclude` で置き場を外したときも動く。
  重なった読み直しは 1 回にまとめられる（`board-panel.ts` の `again`）
- 対象はワークスペースの最初のフォルダだけ。`projects/` 配下のプロジェクト向けチケットも
  同じボードに出る（`project` バッジ）
- レビューのスレッドの現状は取りに行かない。ボードが見せるのはマーカーまで
- 実行ファイルが無い、JSON が読めない、版が違うときはボードを開かず通知で伝える。
  開いている間に読めなくなったら、前の表示を消して理由を出す
