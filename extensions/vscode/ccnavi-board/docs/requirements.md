# ccnaviボードの要件

VS Code拡張「ccnaviボード」が外から見てどうふるまうかを書く。入口はサイドパネルとコマンドパレットで、チケット管理（ボード）・ルール管理・リスク管理・フェーズ管理・テンプレート管理・取り込み待ち・プロジェクト管理の7画面と、ボードの子のカードから開くフロー編集画面がある。取り込み待ちはサイドパネルに並べず、ルール管理・リスク管理・フェーズ管理・テンプレート管理から開く。使い方と組み立ては [README](../README.md)、作りは [design.md](design.md)にある。

拡張とccnavi本体の間の取り決め（拡張が呼ぶコマンド、読むJSONの形、互換の版）は本体側に書く。本体の [要件2.13拡張との取り決め](../../../../docs/11_requirements/extension-if.md)（REQ-EXT）と [設計](../../../../docs/20_design.md)を見る。拡張自身の要件のうち、本体の要件から切り出したものにはREQ-VSCのIDを振ってある。

## 設定を直す画面に共通の操作

ルール管理・リスク管理・フェーズ管理・フロー編集・テンプレートの編集・計画編集は、保存と削除を同じ作法で扱う。

| 何 | どう出るか、何が起きるか |
|---|---|
| 保存できない理由 | ［保存］（計画編集は［この順序に決める］）を押せないときは、理由をボタンのツールチップに出す。理由は1つだけ出し、次の順に見て最初に当たったものを使う。処理中、読み取り専用、書き込み停止中（作業中のチケットがある、保存できるか確かめられていない）、中身が保存できない形（フェーズのidの重なりなど）、変更が無い。押せるときのツールチップは「保存します（Ctrl+S）」 |
| Ctrl+S | Ctrl+S（macOSはCmd+S）で、押したときの［保存］と同じことをする。欄に入力中でも効く。押せないときは保存せず、ボタンと同じ理由を一言の行に表示する（次に編集すると消える）。処理中は何もせず、出ている「保存中…」などを残す。案内の間と、確認の面（フロー編集の提案・依頼文・保存前の確認、テンプレートの編集の閉じる確認、計画編集の確認）が出ている間は反応しない。ルールの選択肢やフェーズのヘルプが開いていても効く。計画編集は確認の面を開く |
| 削除の取り消し | ルール管理・リスク管理で行を［削除］すると、確認なしで消え、上部に「〜を削除しました（まだ保存していません）」の帯と［元に戻す］が出る。［元に戻す］で、直前に削除した1行を元の位置へ戻す（その後に行が減っていれば末尾）。取り消せるのは直前の1行だけで、次に削除すると取り消せる行が入れ替わる。［閉じる］か、中身の読み直し（更新・保存・対象の切り替え）で帯は消える。フェーズ管理・フロー編集・テンプレートの編集は、元に戻す（履歴）で戻せるので帯を出さない |
| 操作の結果 | 直前の操作の一言（保存中・保存できない理由・検証のerror・断られた理由など）は、画面の上に貼り付くツールバーの最後の行に出す（`webview/shared/StatusLine.tsx`）。押したボタンのすぐ下に出て、一覧をスクロールしても見えたままになる。errorは赤で出す。一言が無いときは行ごと消す。検証の報告が長いときは、行の高さを画面の3割までに抑え、中でスクロールする |
| エディタで開く | ファイルがまだ無いときは押せず、ツールチップに「ファイルがまだないため、開けません」と出す |
