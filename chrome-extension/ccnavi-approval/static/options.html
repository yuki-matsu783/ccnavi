リポジトリ

    直近の日数と指定のブランチは、承認待ちを見つけるのに使うだけです。判定には統合先・親のブランチ・先行の閉包だけを入れます（ADR-0093 の D2）。

    プロジェクトのリポジトリ（手元で projects/<名前> に clone するもの）は、プロジェクト名と、先に登録したワークスペースのリポジトリを選びます。共通層・置き場の綴り・互換の印はワークスペースの統合先から読みます（ADR-0093 の 3.3 の 7）。GitLab の入れ子のグループは owner に group/sub と書きます。

    PAT

      承認・取り下げ・レビュー済みを親のブランチへ書き、「始める」で issue から親のブランチを作ります（段階 5）。GitHub は fine-grained token でリポジトリを限り、Contents: Read and write（ブランチを作るのにも使う）・Metadata: Read-only・Pull requests: Read-only・Issues: Read-only を選びます。GitLab は api スコープ（Commits API は write_repository では書けない）で、project access token が使えればプロジェクトを限れます（使えなければ個人の PAT になり、プロジェクトを限れません）。期限は 90 日を選びます。エージェント用のトークンとは別にします。PAT はこのブラウザのプロファイルに平文で置かれます（ADR-0093 の 5.5）。期限はホストの応答から読みます。読めないときは上の欄の日付を使い、切れる 7 日前からボードとアイコンで知らせます。
