リポジトリ

    直近の日数と指定のブランチは、承認待ちを見つけるのに使うだけです。判定には、統合先と親のブランチ、先行をたどって行き着く親のブランチだけを入れます（ADR-0093 の D2）。

    プロジェクトのリポジトリ（手元で projects/<名前> に clone するもの）を登録するときは、プロジェクト名を入れ、先に登録したワークスペースのリポジトリを選びます。共通層・置き場のパス・互換のマーカーはワークスペースの統合先から読みます（ADR-0093 の 3.3 の 7）。GitLab の入れ子のグループは owner に group/sub と書きます。

    PAT

      PAT は、承認・取り下げ・レビュー済みを親のブランチへ書くのと、「始める」で issue から親のブランチを作るのに使います（段階 5）。GitHub では fine-grained token を作り、対象のリポジトリを絞って、Contents: Read and write（ブランチを作るのにも使う）・Metadata: Read-only・Pull requests: Read-only・Issues: Read-only を選びます。GitLab では api スコープを選びます（Commits API は write_repository では書けないため）。project access token が使えればプロジェクトを絞れます。使えなければ個人の PAT になり、プロジェクトは絞れません。期限は 90 日を選びます。エージェント用のトークンとは別に作ります。PAT はこのブラウザのプロファイルに平文で置かれます（ADR-0093 の 5.5）。期限はホストの応答から読みます。読めないときは上の欄の日付を使い、切れる 7 日前からボードとアイコンで知らせます。
