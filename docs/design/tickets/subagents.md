### 9.12 サブエージェント

| イベント | すること |
|---|---|
| `SubagentStart` | cwd のワークツリーが承認済みチケットに結び付くときだけ、開いている子の一覧（識別子・ワークツリーの有無・範囲・未完了の先行・フェーズ定義・`agent` の案内）を `additionalContext` で渡す。親のツリーならその親の子、子のツリーならその子自身。止められないイベントなので案内だけを渡す。子がフロー（9.3.1）を持てば、下の「フローの案内」も足す。着手中の子のフローが着手のときのハッシュから変わっていれば、`systemMessage` にも載せて知らせる。チケット制御が有効で state の置き場があり、payload に `agent_id` があれば、実行中の印（下の「実行中の印」）も置く。チケット制御が有効で state の置き場があり、`agent_id` があるときは、同じ作業ツリーで実行中の別の編集するサブエージェントがいれば、その旨の案内も渡す（下の「同じ作業ツリーの案内」。ワークスペースルートからの起動にも渡す）。どの起動にも、cwd がプロジェクトの中ならそのスキルの目録（11.13）と、「気づいたスキル候補は最後の報告に節を足して返す」の 1 行（`subagent.CANDIDATE_NOTE`）を渡す。この 1 行を渡すのは、サブエージェントには `Stop` の振り返りが届かないため（6.6） |
| `SubagentStop` | 実行中の印を外す（差し戻して続けさせる回は外さない。判定の途中で例外が出ても外す）。対象の子の仕事の始まり（親の先頭との共通の祖先）から先頭までのコミット済みの差分と未コミットの変更の両方から範囲外を探し、残っていれば `enable` で 1 回だけ終了コード 2 で差し戻す。担当の子が決まるのは cwd が子のワークツリーのときだけで、親のツリーから起動された体は全部の子を検査するが差し戻さず、`unattributed` として親に知らせる。終わり方は 5 つに分けて `state/subagent-<セッション>-<id>.outcome`（JSON）に残す（下の「終了結果の記録」）。差し戻しの記録は `state/subagent-<セッション>-<id>.bounced`。`agent_id` が来ない payload では `<id>` がワークツリーの名前になり、同じワークツリーから `agent_id` 無しで来る 2 体目は通る。名前で書いた記録はセッションが終わるまで残る。2 回目は通して文だけ渡す。未コミットが残っていること自体は差し戻さない。対象の子のフローが着手のときのハッシュから変わっていれば、それも知らせる（9.3.1）。対象の子のワークツリーを読めず範囲を確かめられなかったら、差し戻さずに通す（読めない原因は子の作業とは限らず、差し戻しても子には直せないことがある）。範囲外が他に見つからなければ記録を `skip` / `worktree-unreadable` にして許可と分け、どちらの場合も `detail` に確かめなかった子を残す。この出力は親に届かないので、`state/subagent-<セッション>-<id>.unchecked` に 1 行目のセッションの識別子（そのまま）と子の識別子を書き、親に 1 行言う（下の 2 行）。処理が ccnavi の内部エラーで終わった回も、通して、`systemMessage` でユーザに知らせ、同じ印を置く。どの子を見るはずだったかは分からないので中身は空にし、親には内部エラーで確かめていないと言う |
| `PostToolUse`（`Agent`） | サブエージェントが差し戻しを無視して終わったこと、`SubagentStop` で子の範囲を確かめられなかったこと（`worktree-unreadable`。印は読んだら消す）を親に言う（`SubagentStop` の出力は親に届かない）。起動したのがサブエージェント（payload に `agent_id` がある入れ子）なら、同じ文を `systemMessage` にも載せる。同じ呼び出しで実行後チェックが `enable` の差し戻し（終了コード 2）をするときは載らない |
| `PostToolUse`（親のどのツールでも）・`UserPromptSubmit` | payload に `agent_id` の無い親の呼び出しなら、このセッションに残った `.unchecked` の印をぜんぶ読んで言い、消す。どのセッションの印かは、名前ではなく中身の 1 行目と完全一致で比べる（名前の前置きは別のセッションのものとも重なりうる）。バックグラウンドで動かしたサブエージェントは、親の `Agent` の `PostToolUse` が `SubagentStop` より先に来るので、そこだけで読むと知らせが落ちて印が残る。親が次のツールを使えばその `PostToolUse` で、ツールを使わずにターンを終えたなら次の依頼の `UserPromptSubmit`（`additionalContext`）で届く。`Stop` では読まない（`Stop` から親に言うには、終わろうとするのを止めて続けさせることになる）。サブエージェントの中の呼び出しでは読まない（その子の親でない印を消すと、親に届かなくなる）。`.outcome` が `unattributed` のものも、この 2 つの経路で 1 度だけ言う（出力に書き終えてから `notified` の印を付けるので、書く前に止まれば次の機会に出し直す） |

判定は行き先で決まるので、`SubagentStart` の一覧は案内でしかない。

**範囲外の変更の検査と、確かめられなかった印。** 子チケットには編集してよい範囲が決まっている。書き込み先が呼び出しに
現れるツール（`Write`・`Edit` など）は `PreToolUse` が事前に止める。一方、スクリプトやシェルが中で別のファイルを
書き換える場合、その行き先は呼び出しからは分からず、事前には止められない。`SubagentStop` の検査は、この取りこぼしを
「結果として何が変わったか」から見つけるための二段目の守りになる。

- 例（検査できた回）: 子の範囲が `src/foo/**` で、サブエージェントが `sh gen.sh` を実行した。`gen.sh` は
  `src/foo/a.py` のほかに `docs/b.md` も書き換えた。`PreToolUse` は `sh gen.sh` の中身までは追えず通す。
  サブエージェントの終了時に差分を読むと `docs/b.md` が範囲外なので、1 回だけ差し戻して「`docs/b.md` は範囲外」と伝える。
- 例（検査できなかった回）: 子のワークツリーが消えている、または git が失敗して差分を読めない。範囲外の変更が
  あったのかどうかも分からない。差し戻しても子には直せないので止めない。ただし何も言わないと、親には「問題なし」と
  区別がつかない。そこで確かめられなかった子を印（`.unchecked`）に残し、親に「子 X のワークツリーを読めず、範囲外の
  変更を確かめていない。合流の前に確かめて」と伝える。
- 例（親に届くまで）: 親が次にツールを使えば、その `PostToolUse` で伝わる。ツールを使わずにターンを終えたなら、
  ユーザの次の依頼の `UserPromptSubmit` で、上の文が `additionalContext` として渡る。伝えたら印は消す。

**親のワークツリーへの書き込み（`DENY_SUBAGENT_PARENT_TREE`）。** サブエージェントは子のワークツリーで手元にコミットするだけで、親のワークツリーへの merge・commit・書き込みは hook が止める。子のワークツリーでのコミットと、衝突を解くための親のブランチの merge は通る。動かすスクリプトと push は `DENY_SUBAGENT_TICKET_OP` が止め、子チケットのワークツリーからの push は git のラッパースクリプトが拒む。子の合流と push は、メインエージェントが打つ子の `finish` が行う。親を閉じる（レビューの依頼・`ready`）のもメインエージェントである。

- 親のワークツリーかは、そのワークツリー自身のチケットで決める。`parent:` の無い同名のチケットが 1 つでもあれば親とする。
- 居場所は `cd` と `env -C`・`sudo -D` の行き先で追う。`GIT_DIR`・`GIT_WORK_TREE` などの git の置き場の変数を置いてラッパーを呼ぶ形は止める（ラッパーも先頭で外す）。
- 書き込みは Write / Edit のほか、Bash のリダイレクト・`tee`・`sed -i`・`cp` / `mv` の行き先も見る。
- `python -c`・`node -e`・`perl -e` のコードは読み切れないので、親のワークツリーのパスと書き込みを疑う語が並べば止める。
- スクリプトのファイルを実行する形と、変数で組み立てた行き先は見ない（限界）。

**親の局面。** 子の一覧を渡すときは、その子の親ごとに「親 X の局面: <局面>」を 1 行足す（`subagent._stage_lines`）。
局面の文字列は `phase.stage` が返すまま（局面の名前は 9.7 の「局面の名前」）。開いた子が居ないときは一覧ごと渡さないので、
子が居ない親は何も出ない。計画の無い親（局面が空）や、局面を組めなかったとき（置き場を読めないなど）は、その行だけ出さず、
`SubagentStart` は失敗させない。局面は案内であって判定ではない。

**終了結果の記録。** `SubagentStop` は、終わり方を 5 つに分けて `state/subagent-<セッション>-<agent_id>.outcome`（JSON）に残す（`hook/subagent_outcome.py`）。差し戻しの記録（`.bounced`）が残すのは「差し戻したか」で、こちらは「終わったときにどうだったか」を残す。

| 結果 | 意味 | 親への知らせ | Stop の促し |
|---|---|---|---|
| `ok` | 範囲外の変更が無い | 言わない | しない |
| `fixed` | 差し戻した後に直った | 言わない（警告しない） | しない |
| `outside` | 範囲外の変更が残ったまま終わった | 従来の経路（差し戻しを無視した知らせ） | する |
| `unchecked` | 読めない・内部エラーで検査できなかった | 従来の経路（`.unchecked`） | する |
| `unattributed` | 担当の子が分からない（親のツリーから起動された） | `PostToolUse`・`UserPromptSubmit` で 1 度 | しない |

- 担当の子が決まるのは、cwd が子のワークツリーのときだけ。親のツリーから起動された体は、全部の子を検査するが差し戻さない（別の子の変更を、関係ない体に直させないため）。範囲外が見つかれば `unattributed` にして親へ知らせる。最終的には `finish` の範囲検査が止める
- 差し戻して続けさせる回は `final: false` で書き、結果を確定しない。次の `SubagentStop` で直っていれば `fixed`（親に警告しない）、差し戻しを残したまま終われば `outside` に確定する。`dry-run` は差し戻さないので、`outside` を差し戻し 0 回で残し、親への文は「差し戻していない」と言う
- 親への知らせは、確定した結果を 1 度だけ。出力に書き終えてから `notified` の印を付ける
- `Stop` が促すのは `outside` と `unchecked` だけ（理由コード `NUDGE_SUBAGENT_OUTCOME`）。同じ結果では 1 回で（`nudged` の印）、別の経路で同じ内容を親に言った結果は促し済みにする。`stop_hook_active` が真のとき、サブエージェントの中、実行中のサブエージェントが居る間、state の置き場が無いときは促さない。順序は `finish` → 依頼までの道 → サブエージェント結果 → `integrate` → ルール（6.6）
- `.outcome` は prune が 14 日で掃除する
- 未了: 担当の子が分からない場合に `SubagentStop` の cwd が実機でどうなるかは、まだ確かめていない。孫の起動などで `unattributed` がどれだけ起きるかは分かっていない

**実行中の印。** メインの `Stop` が、委任して待つ回を「レビュー依頼までの道」の促し（`NUDGE_TICKET_REQUEST`。6.6・9.6）で止めないための記録。

- `SubagentStart` が `state/subagent-<セッション>-<agent_id>.running` を置き、`SubagentStop` が外す。サブエージェントごとに 1 ファイルなので、並行して始まる・終わるサブエージェントが同じファイルを取り合わない。中身は 1 行目に `session <セッション>`（`.unchecked` と同じ。別のセッションの名前と前置きが重なりうるので、セッションは中身で決める）、2 行目に開始時刻（エポック秒）。編集するサブエージェントだけが、3 行目以降に `tree <種類> <名前>` と `type <agent_type>` を足す（「同じ作業ツリーの案内」）
- メインの `Stop` は、そのセッションの印が 1 つでも「実行中」なら促しを見送り、「1 回だけ」の記録（`nudged-<セッション>.json`）も進めない。入れ子の体（孫）も自分の `agent_id` の印を持ち、全部が外れるまで見送る。順序は `Agent` の `PostToolUse` が `SubagentStop` より先に来ても関係しない（始まりと終わりの印だけを見る）。`Stop` が `SubagentStop` より先に来れば印が残っていて見送る。逆に `SubagentStop` が `Stop` より少し遅れる終わりぎわの回も見送るだけで、害は無い
- 印を読めない（置き場を一覧できない、壊れて開始時刻を読めない）ときも見送る。壊れた印はファイルの更新時刻で期限を見る。促しは保護ではないので、迷ったら止めない側に倒す
- `SubagentStop` が来ないまま残った印（中断・クラッシュ・内部エラー）は、開始から `RUNNING_MAX_SECONDS`（4 時間）を過ぎたら実行中と数えない。値の根拠は、背景の体が現実に走る長さ（数分から 1 時間ほど）に余裕を足したこと。長すぎる分の害は、取りこぼした印が促しを止める時間が伸びるだけ。加えて、セッションの起動と再開（`SessionStart` の `source=startup` と `resume`）で、そのセッションの印を全部捨てる。どちらも新しいプロセスで、前のプロセスのサブエージェントは生きていないため。compact と clear では捨てない（同じプロセスで、実行中の体が残りうる）。古いセッションの印は後始末（prune）が、ほかの `subagent-` の記録と同じに消す（`.outcome` も同じ 14 日）
- `agent_id` が payload に無い始まり・終わりは、鍵が決まらないので印を置かず外しもしない。その体は実行中と数えられない（制限）
- 数えるのはサブエージェントだけ。チームメイトと背景のシェルは待ちに数えない

**同じ作業ツリーの案内。** 同じ作業ツリーで編集するサブエージェントを並行させると、途中の変更でテストが落ちる、同じ文書を同時に編集する、未コミットの変更が常に残る、といった問題が出る。並行するときは別のワークツリーを割り当てる決まり（`.ccnavi/docs/decisions.md`）を、起動の時点で気づけるようにする。これは案内である。要件（外から観測できる約束）ではなく、実装の案内である。子チケットの一覧を渡す条件（REQ-TKT-22）とは別に、ワークスペースルートからの起動にも渡す。mode によらず、dry-run でも同じ文を渡す（`subagent._shared_note`）。

- 実行中の印（上）に、編集するサブエージェントだけが 3 行目以降を足す。`tree <種類> <名前>`（起動時の `cwd` のツリー。ワークスペースルートの名前は空）と `type <agent_type>`。読み取り専用のサブエージェントと、ワークスペースの外からの起動は書かない。3 行目の無い印（古い版が置いたものを含む）は、案内の相手に数えない。印は書きかけを見せない書き方（`fsio.write_text_atomic`）で置く。ファイルを作った時点で中身が空になる書き方だと、同時に起動した相手が中身の空の印を読み飛ばして、案内を逃す
- 起動したサブエージェントが編集するものなら、自分の印を先に置いてから、同じセッションの印を探す。自分の鍵ではなく、開始から `RUNNING_MAX_SECONDS` を過ぎておらず、ツリーが同じ（種類が同じで、名前は大文字小文字を区別せず比べる）ものが相手。同時に起動した 2 つのうち、後から探すほうは先に置かれた印を必ず見つけるので、相手を見つけ損ねる窓は無い
- 「編集する」の見分け（`agentkind.kind_of`）は広めに倒す。読み取り専用と確かめられたものだけを読み取りとする。読み取りになるのは、ツールの一覧（payload の `tools`、なければ定義の `tools`）が空でなく、全部が読み取り系（`Read`・`Grep`・`Glob`・`LS`・`WebFetch`・`WebSearch`・`NotebookRead`・`TodoWrite`・`Agent`・`Task`。`agentkind.READ_TOOLS`）のときと、定義が無い組み込みの `Explore`・`Plan`・`claude-code-guide`。定義は `<ツリー>/.claude/agents` か `<ルート>/.claude/agents` から探し（`name` は大文字小文字を区別せず比べる）、組み込みと同名なら定義を優先する。これ以外は編集するものとして数える。`tools` に制限の無い定義、`*`、`Edit(src/**)` のような括弧付き、`Bash`、MCP のツール、空の一覧、定義が無い・読めない、`agent_type` が空、プラグインやユーザ階層の定義がこれに当たる。`disallowedTools` は読み取りの根拠にしない（外していない `Bash` や MCP が残るため）。`Bash` だけで書き込むものも編集するものに数える（コードから書く経路は読み切れない）
- 同じ相手への案内は 1 回に抑えるため、案内した相手の鍵を `state/once-<セッション>-peers-<agent_id>.json` に残す。同じセッションの中で `SubagentStart` がまた走っても（サブエージェントの再開）、同じ相手は重ねて案内しない。新しい相手には案内する。記録は `deliver` の数えと同じく `SessionStart` のたびに捨てるので（`ctxfile.forget`）、起動・再開・compact・clear のあとは、同じ相手にもう一度案内しうる。`deliver` が読み書きする `once-<セッション>-<agent_id>.json` とは別のファイルにする（書き戻すときに相手の鍵を落とすため）。記録を読めない・置き場が無いときは、案内する側に倒す
- 案内は子チケットの一覧に至る前に組み、スキルの目録と同じ文にまとめる。チケットの無いツリーやワークスペースルートからの起動にも届く
- 案内の文は「起動時の作業ディレクトリが同じ」と言う。サブエージェントの `cwd` はメインの `cwd` になりうる（付録 C）ので、親が別のワークツリーを割り当てて隔離している場合も同じに見える。文には、別のワークツリーで作業している場合と、親から委任された子の場合は対応が要らないことを添える
- 既知の制限。(1) 入れ子の子は、待っている親と同じツリーで動く。hook の入力に親の `agent_id` は無いため、親子を見分けられない。そのため、委任のたびに案内が出る。(2) 案内が出るのは、起動した側だけである。先に動いていたサブエージェントは、後から来たサブエージェントについて知らされない。(3) 中断などで `SubagentStop` が来なかった印は、最大 4 時間残る。その間は誤って案内が出る。案内済みの相手の記録（上記）により、誤った相手への案内も、起動したサブエージェントごとに 1 回で止まる。(4) 印は、チケット制御の有無によらず置く。直接作業の促しが、チケット制御に依らないためである

**フローの案内。** 一覧の子がフローを持てば（ファイルが在れば）、その子の行の下に次を足す（`flow.briefing`）。

- 手順を並べるのは、起動の cwd が**その子のワークツリー**で子が 1 本に決まるときだけ。親のツリーからの起動
  （入れ子の孫も cwd は親のツリー）では、各子のフローのパスを 1 行ずつと「自分の担当の子チケットのフローだけを
  読んで従う。他の子のフローには従わない」だけを渡す。以下は子のワークツリーからの起動のとき
- フローのファイルの絶対パスと、それが合意済みの手順でエージェントは編集しないこと、作業の前に読んでその順に
  進めること、の 1 行（compact で案内が消えても辿り直せるようファイルを名指しする。付録 C）。ロックと、着手のあとの
  書き換えの知らせは、サブエージェントには言わない。ロックは書き込みを止めるときの理由で、書き換えの知らせは
  ユーザとメインに向く
- 手順を 1 ノード 1 行で並べ、合意済みのフローの本文（データ）として囲ったもの。`start` から繋がりを辿った順に
  `<番号>. [<種類>] <名前>: <中身> → <次の番号>（<分岐の名前>）`。40 ノードか文の上限（9.3.1）を超えたら
  そこで切り、続きはファイルを読ませる。リンクや読めないフローは 1 行で言う
- `askUserQuestion` のノードがあれば、その扱い。サブエージェントには AskUserQuestion が渡らないので、そのノードで
  手を止め、問いと選択肢を添えてメインに返す。メインがユーザに聞き、答えを持って同じサブエージェントを再開させる
- `loop` のノードがあれば、その扱い。条件が成り立つあいだ「繰り返す」側へ進み、成り立たなくなるか繰り返した回数が最大に
  達したら「抜ける」側へ進む。回数は自分で数え、最大に達しても条件が成り立つままなら最後の報告に書く
- `subAgent` / `subAgentFlow` のノードがあれば、その扱い。Agent ツールがあれば入れ子のサブエージェントとして起動し、
  そのプロンプトに担当の子チケット・ワークツリー・範囲を必ず書き、他の子のワークツリーに触れないことを書く。
  **Agent ツールが無ければ**（入れ子の上限。`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`、クラウドの環境は 1）、
  そのノードで手を止め、起動してほしいエージェントの種類・プロンプト・担当の子のワークツリーと範囲を添えて
  メインに返す。メインがそのとおり起動し、結果を持って同じサブエージェントを再開させる（`askUserQuestion` と同じ流れ）

既知の制限: 孫の hook の `cwd` はメインの `cwd` になるので、孫の起動では `SubagentStart` が親の全部の子を
並べる（フローはパスだけ）。`SubagentStop` は全部の子を検査するが差し戻さず、`unattributed` として親へ知らせる。
孫は範囲の中なら兄弟のワークツリーにも書ける。入れ子のプロンプトに担当を必ず書かせるのはこのため。フローのファイルが無いときは何も足さない。

compact の前後の hook でフローを入れ直すことはしない。どちらの hook も `additionalContext` を受け付けるとは文書に書かれておらず、`systemMessage` は捨てられるため（付録 C）。
