### 9.5 ファイルの行き先で選んだチケットによる判定

`Write` / `Edit` / `NotebookEdit` の対象を解いた先が `.claude/worktrees/<名前>/` の中なら、その名前と
同じ識別子の開いた承認済みチケットで判定する。呼び出し元の `cwd` も、サブエージェントかどうかも見ない
（REQ-TKT-01）。範囲の前置はそのワークツリーのルートから解く。

ワークツリーの特定は、パスの前置だけでなく `.git` ファイルの `gitdir:` と元リポジトリの
`.git/worktrees/<名前>/gitdir` の相互参照でも確かめる。候補が複数あるときは最長一致を採る。

ルールの判定とチケットの判定を両方出し、強い側を採る。強さは `deny` > `ask` > `allow` > 何も言わない。
チケットの範囲の外と、チケットが `deny` と書いた項は `deny`。同じ強さならルールを採る（ルールの文面のほうが具体的なため）。
ルールが `deny` ならチケットは見ない。

| ルール | チケット | 結果 |
|---|---|---|
| `deny` に当たる | どれでも | 止まる（ルールの文面） |
| `ask` / `allow` に当たる | 範囲の外、または `deny` の項 | 止まる（`DENY_TICKET_SCOPE`） |
| `ask` に当たる | 範囲の中（`ask` / `allow`）、またはチケットが無い | ユーザに確認が出る（`RULE_ASK`） |
| `allow` に当たる | 範囲の中（`ask`） | ユーザに確認が出る（`TICKET_ASK`） |
| `allow` に当たる | 範囲の中（`allow`）、またはチケットが無い | 通る |
| 何も言わない | 範囲の中（`allow`） | 通る |
| 何も言わない | 範囲の中（`ask`） | ユーザに確認が出る（`TICKET_ASK`） |
| 何も言わない | 範囲の外、または `deny` の項 | 止まる（`DENY_TICKET_SCOPE`） |
| 何も言わない | ワークツリーにチケットが無い | 権限モードに従う（`UNDECLARED`） |

「範囲の外」には、子の範囲の中だが親の範囲かフェーズの種類の上限の外を含む（下の切り詰め）。

**理由コードは増やさない。** 範囲の外も、チケットの `deny` の項も、ルールを狭めた回も `DENY_TICKET_SCOPE`。
区別は文面と記録で持つ。チケットがルールより強かった回は、文面の頭に `rule:` 行を足し、記録の `rules` を
`(ticket-scope)` とルールの id のリストにし、`source` を空にする。チケット（子か親）の `deny` の項に当たったときは
`ticket entry:` 行も足す。

```
rule: <id> (<allow|ask>) lets this through, but the ticket for this worktree narrows it
ticket entry: deny <書かれた表記>
```

ルールの `additionalContext` は、どちらが判定を決めても載せる。承認済みチケットの走査は 1 回の判定で 1 度だけで、
プロジェクトの食い違いの点検と同じ一覧を使う。承認画面の親の見出し「このチケットで編集可能な範囲」の下と、
`--explain` のチケットの節の頭に、範囲がルールの `allow` / `ask` より強いことを 1 行で書く。

**子の範囲は親と種類でも切り詰める。** 子 → 親 → 種類の `scope` の順に当て、厳しい側を採る。
種類の上限は `allow` か外かしか言わないので、子が `ask` と書いた場所が種類の中なら `ask` のまま。
regex で書いた子の範囲は、実際のパスで親と種類に当てる。実行前チェック、実行後チェック（`POST_TICKET_SCOPE`）、
SubagentStop の差し戻しが同じ合成を使う。理由コードは増やさず、どの上限で外に出たかを文面の `limit:` 行で
名指しする（子自身の範囲の外なら `scope:` 行で足りるので足さない）。

```
limit: phase type 設計 (design): wip/design/*, docs/*
limit: parent i0001: src/*, tests/*
```

**種類が読めないときは、種類では切り詰めない。** どの層にも phases.yml が無いか、種類の `scope` が
`inherit` なら、親までで切り詰めて何も言わない。phases.yml が実在するのにその番号の種類を引けない
（壊れた、種類を消した）ときは、親では切り詰め、種類では切り詰めず、実行前チェックに注記
「種類 `<id>` が読めないので、種類の上限では切り詰めていない」を出す。phases.yml の読み込みで
上がる `ValueError` 系（`UnicodeDecodeError` を含む）も「壊れている」と扱い、例外を外へ出さない。
deny にはしない（phases.yml はコアファイルでエージェントが壊せず、親の切り詰めは残る）。壊れている間は
種類の上限が適用されないことを、注記と `--lint` の error で知らせる。

チケットは閉じる向きにしか働かない。ルールの `deny` と `ask` を緩めることは無く、ルールの `allow` は狭める。
未承認のチケットは判定に何も反映せず、結び付いたワークツリーが無いチケットも適用されない（承認は残るので、同じ名前で
作り直せばまた適用される）。

チケットの置き場（提案の置き場 `wip/proposals/` と承認済みチケットの置き場 `.ccnavi/approved/` の下）は、
範囲の外として扱わない（次のチケットを提案する手段を残すため。提案は承認されるまで判定に何も反映されない）。状態の置き場と
承認済みチケットは組み込みの `deny`（9.2、8.2）が先に止めるが、組み込みが入るのは実行前のルール集合だけ。
外し方は、実行前チェック・サブエージェント終了時チェック・ターンの終わりのコミット済みのぶんは置き場ごと
（`ticket.is_ticket_place`）、呼び出しごとの実行後チェックは内容で選ぶ（`post._script_writes`、7.2）。
ワークツリーのルートからの相対パスを `/` の境で見て大文字小文字を区別しない。

下書きの置き場（ワークツリーのルートの直下の `scratchpad/`）も、**実行前チェックだけ**範囲の外として扱わない
（`ticket.is_unscoped`）。根拠は「そのツリーの git が `scratchpad/` を追跡しないこと」で、保証ではない
（`.gitignore` は各リポジトリが持つ）。実行後チェックとサブエージェント終了時チェックは `scratchpad/` を外さない。
入力が `git status`（`--ignored` なし）と追跡ファイルの差分なので、正しく設定されたリポジトリでは現れず、
追跡されているときだけ報告する。`--lint` は、`scratchpad/` に追跡されているファイルがあるリポジトリと、
`scratchpad/` を無視していないリポジトリを警告で名指しする（ワークスペースと各プロジェクト）。

この除外だけは大文字小文字を**区別する**（`.gitignore` の照合が Linux で区別するのに合わせ、除外を
追跡から外れる範囲より狭く保つ）。ルートの直下 1 段のディレクトリだけを見る（`docs/scratchpad/` や同じ名前の
ファイルは外さない）。置き場の名前は設定で動かさない。

ELI5 の HTML の置き場（ワークツリーのルートからの相対で `wip/eli5/` の下）も、範囲の外として扱わない（`ticket.is_eli5_place`）。レビューの依頼に必ず添える材料で（9.10）、親の範囲に毎回書かせると書き忘れた親が依頼の手前で止まるため。
`scratchpad/` と違って追跡される置き場なので、実行前チェック（`ticket.is_unscoped`）に加えて、実行後チェック
（`post.ScopeGuard.finding`）とサブエージェント終了時チェック（`phase.scope_findings`）でも外す。親のツリーでも子のツリーでも同じ。
外すのは `wip/eli5/` の下だけで、`wip/` のほかの場所・`wip/eli5x/`・`docs/wip/eli5/`・同じ名前のファイルは外さない。
大文字小文字は区別し、`\` は `/` に直さずに見る（`wip\eli5\x.py` という名前の 1 ファイルは置き場ではない）。
`tree.relative` が `os.sep` を `/` に直すので、Windows の区切りはこれで足りる。チケットの置き場（`ticket._under`）と
下書きの置き場（`ticket.is_scratch_place`）も、同じく `\` を直さずに見る。名前は設定で動かさない。
`wip/` は `ready` の前に丸ごと消すので、ここに置いたものは squash した成果物に残らない。`ready` の前提は大文字小文字を区別せず、
名前が `wip\` で始まる 1 ファイルも `wip/` の残りとして止める（区別しない FS で `WIP/eli5/` を先に作った形を拾う）。
**この除外は、チケットの `deny` と、チケットが信頼できないときの全面停止（`LIMIT_BLOCKED`）より先に適用される**（`is_unscoped` が
範囲の判定より前にある。順を変えるとチケットの置き場と `scratchpad/` の扱いにも及ぶので、この弱さは受け入れている）。

`Read` `Grep` `Glob` は範囲を見ない。Bash の実行前チェックにもチケットの範囲は当てない。コマンド
文字列からパスを追えないため。シェルが書いたものは実行後チェックが `POST_TICKET_SCOPE` で言い
（7.2）、子のワークツリーについてはサブエージェントの終了時に基準点からの差分を見る（9.12）。

行き先のツリーが属するプロジェクトと、そのツリーに結び付く承認済みチケットの `project:` が違えば
`DENY_TICKET_PROJECT_MISMATCH` で止める（11 章）。

サブエージェント（`agent_id` 付き）からの `ccnavi-ticket.sh` / `ccnavi-review.sh` の操作と
`ccnavi-git.sh push` は、ルールより先に `DENY_SUBAGENT_TICKET_OP` で止める。シェルから実行ファイルを
`--agree` / `--reviewed` / `--close-early` 付き、または状態とレビューを動かす副命令（`ticket start|finish|cancel|record-risk`、
`review prepare|requested|confirm|ready`）付きで直接打つ形は、素性によらず
`DENY_TICKET_APPROVAL_CLI` で止める。`ccnavi-agree.sh` と `ccnavi-push-approved.sh` を
`sh` / `bash` で打つ形も同じ理由コードで止める。大文字小文字によらない。
`comment` / `fetch` / `origin` は sh だけの仕事なので当てていない。
**hook のほかに保護が無い形**は、実行ファイルの表記によらず、同じ理由コードで止める（`phase.human_path_form`）。

- ボードの経路。`--agree` / `--reviewed` と `--yes` の組、sh の `--choices` と `--digest` の組。`--yes` の経路は
  端末を求めないので、ここが唯一の保護になる。`decide <N>` と `--preview` は止めない（前者は
  実行ファイルが端末を求め、後者は何も置かない）
- 端末要求を切る形。実行ファイルは `CCNAVI_GUARD_TICKET_APPROVAL` と `--guard-ticket-approval` で端末要求を
  外す（テストと CI のため）。変数は、読むだけの形（`$X`・`${X}`・`$env:X`）以外で名前が現れたら止める。フラグは、
  `enable` 以外の値を渡したら止める。切れなければ、端末を持たないエージェントは実行ファイルの側で止まる

実行ファイルを呼ぶ書き方（`uv run -m ccnavi`、名前を変えたコピー、`awk` の `system()` など）は追い切れないので、
コマンドの位置は見ず、**コマンド行の生の文字列の全体**から引用符と `\` を落として表記を探す（`--y""es`・
`"--yes"` を同じに読む）。外すのは、並んだコマンドが全部、表示・検索・閲覧の道具（`echo`・`grep`・`cat` など。
名前の完全一致）のときだけ（`sed`・`awk`・`git`・`printf` は外さない）。この表記をシェルで探す・書くコマンドも
止まる（Grep ツールと Edit ツールで済む）。コミットの文面（`git commit` / `ccnavi-git.sh commit` の `-m` の値）は
外す。ただし値の中にコマンド置換があれば外さない。

**これで止められないもの。** 表記を組み立てて隠す形（base64、文字の連結）、ファイルに書いたスクリプトを別の
呼び出しで走らせる形、擬似端末（`script`・`pty`）で端末要求を満たす形。hook は最終防衛線ではない（12.4）。

どちらも実行役のコマンド越し（`env`・`sudo`・`sh -c`・`source`・`find -exec`）に打った形を、中で実行される
コマンドで止める（6.3.1）。実行ファイルのパスには `selfguard.binary_clause`（8.2）が入るので、
`sh .ccnavi/bin/<os>-<arch>/ccnavi --agree …` も同じルールで止まる。
