### 9.15 作業・レビュー計画のテンプレート

完了した作業の計画とフローを次の作業で使い回すための設計。ここにあるのは、読む側（読み込み・2 層の足し算・検査・
`ccnavi --templates` の答え・`--lint` への出方）と、溜める側（下書きの作成、ユーザの取り込み、取り込んで消えた下書きのコミット）まで。
テンプレートから親を起こす操作、導入 sh への配布はまだ無い。用語は CONTEXT.md の「作業・レビュー計画」に従う。

**何か。** 1 つの親の作業・レビュー計画（全体計画 `plan:` とフィードバック計画 `feedback:` の項と `after`）と、
各子のフローの本文を 1 ファイル `<名前>.yml` にまとめたもの。欄は `name`・`description`・`when`・`plan`・`feedback`・`flows`。
`after` は**その計画の中の添字**（1 始まり）で、フィードバック計画の `after` もフィードバック計画の中の添字にする。
提案ではフィードバック計画の番号が全体計画の続きになるので、そのまま写すと番号がずれる。相対で持てば、使う側が付け直せる。
`flows` は全体計画の項の添字をキーにする。子の識別子は使うたびに変わるので、位置で指す。

**置き場と足し算。** 共通は `.ccnavi/config/common/templates/`、プロジェクトは `.ccnavi/config/project/templates/`
（`settings.common_templates_dir` / `settings.layer_templates_dir`）。ルール・フェーズ定義・配点の 3 本を回す
`settings.LAYER_KINDS` には入れない（ファイル 1 本ではなくディレクトリで、3 本の処理に影響するため）。使うのは共通と 1 つのレイヤー
（自身のレイヤーか、プロジェクト）の和で、レイヤーどうしは足さない。

| 場合 | 扱い |
|---|---|
| 同名で全欄が同じ | レイヤーの側を捨てて info。共通の 1 本を使う |
| 同名で中身が違う | レイヤーの側を使わず error。違う欄を名指しする。共通を使う |
| 共通のテンプレートが読めない | 共通のそのテンプレートを無いものとして扱い、レイヤーの側は使う |
| 置き場が無い | 正常（無い = 空） |

フェーズ定義の足し算（`phasetypes.merge`）と同じ形で、どちらが効くかを黙って決めない。1 本の衝突で、ほかのテンプレートは止めない。

**読み方。** `plan_templates.parse_template` が 1 ファイルを読む。フローと同じ部品を使う。ファイルは `flow.read_bytes`
（シンボリックリンク・ハードリンク・ふつうのファイルでないものは読まず、`flow.FILE_LIMIT` が上限）、YAML は `flow.parse_yaml`
（別名は拒み、UTF-8 で BOM は 1 つ外す）。例外は外に出さず、読めなければ理由つきの苦情を返す。置き場がシンボリックリンクなら読まない。
`.yml` でないファイルは warn、`.` で始まるファイルは読まない。ファイル名が名前で、`name` が違えば error。未知の欄は warn で、
`extra` に持って書き戻しでも落とさない。`flows` の本文は `flow.parse` と同じ形の検査を通す。

**往復。** `Template.as_data` と `plan_templates.dump` は、読んだ中身をそのまま書き戻せる形にする。読んだものを書いて読み直すと
同じ `Template` になり、`dump` の結果も変わらない（`- design` と `- {type: design}` のような書き方の違い、コメント、キーの順は
保たない）。後の段階の保存・取り込み・削除が同じモデルを書き戻す。

**検査。** `plan_templates.check`。計画は、合成した frontmatter を `ticket.parse` に渡して `Ticket` を得て、承認の検査と同じ関数を当てる。

| 検査 | 深刻度 |
|---|---|
| `after` の範囲（1 以上、自分より小さい）、終端が 1 つ、最後の項は延期できない、延期の引き受け手が在る（`workflow.problems`） | error |
| `review` は `mr` か `defer`（弱める向きは書けない） | error |
| 計画が 99 項（子の識別子のフェーズ番号の上限）を超える | error |
| `flows` の添字が全体計画に在る、フローの形が読める（`flow.parse`） | error |
| 型が使うフェーズ定義（共通 + レイヤーの `phases.yml`）に無い | warn |
| 定義の `kind` が置き場と合わない、延期の引き受け手の定義にレビューが無い（`agree_candidates.plan_problems`） | warn |
| フローの線の構造・名前の表記（`flow_shape.structure_problems` / `name_problems`。`--lint --flow` と同じ） | warn |

定義に左右される食い違いを warn にとどめるのは、定義が後から変わるため。承認のあとは親の写しを読み、`phases.yml` を直しても進行中の
親を止めない決まりに合わせた。使うときの承認の検査が改めて error にする。型が `phases.yml` に無いときは仮の定義を置いて順序の検査を
通し、定義が無いことは別に warn で言う。定義が 1 本も無いときは、型ごとではなく 1 件の warn にまとめる。共通のテンプレートは共通の定義だけで、
レイヤーのテンプレートは共通 + レイヤーの定義で検査する（`--templates` の一覧は、選んだレイヤーの足し算の結果の定義で検査し直す）。

**`--templates`。** `cli_templates` が引数を受ける。一覧・`--keyword`（`name`・`description`・`when` の部分一致。語を重ねるとどれか）・
`--show <名前>`・`--layer`・`--json`。読むだけなのでエージェントが打ってよい。`--docs` の絞り込みのうち `--keyword` だけを共有し、
ほかは `--docs` でだけ使えるまま断る。`--docs` や、判定・チケットの経路のフラグとは並べられない。答えの形は README の
「作業・レビュー計画のテンプレート」と `tests/fixtures/templates-json.json`。画面は判定を自分で出さず、この答えをそのまま描く。

答えには、各テンプレートの名前・層・置き場の相対パス・中身のハッシュ（保存の `--expect` に使う。`--plan-order` の `source_sha` と同じ流儀）・
説明・いつ使うか・計画の項（計画の中の添字と、提案に写したときの番号つき）・フローの要約・足し算で使われるか（`effective`）と
捨てた理由（`dropped`）・書き込めるか（`writable`）・検査の結果（`severity` と `detail`）を入れる。層ごとの生の中身（`layers`）、
選んだレイヤーの足し算の結果（`templates`）、全レイヤーの足し算の索引（`sums`）の 3 つを返し、足し算の結果だけでなく、
どの層に何が書いてあって、どれが効いているかが分かる。

**書き込めるか。** ワークスペースルートの共通は書ける。親の着手がプロジェクトの `.ccnavi/config/common/` へ写したミラー（承認済みの
親のワークツリーの中）は共通レイヤーの写しで誰も編集しないので、`writable` は `false`。レイヤーの置き場は常に `true`。
ミラーへの配布（`configsync`）はまだ無い。ミラーに写す対象にテンプレートが入っていないので、単体 clone の共通には届かず、
ミラー先に置いたテンプレートは共通レイヤーに無いファイルとして次の着手で消される。配布を足すときに、写す対象と読み込みを合わせる。

**`--lint`。** `lint_templates` が `plan_templates.scan` の苦情を `(templates)`（共通）・`(templates/<レイヤー>)` の場所で出す。
置き場の無いワークスペースでは何も言わない。読むのは設定の置き場だけで、承認済みチケットの置き場は読まないので、走査に写し（`copies`）を
渡す必要は無く、置き場の読み直しの回数も増えない。`--lint --json` の形は欄を足していないので、版は上げない。

#### 溜める側

完了した親から下書きを作り、ユーザが差分を読んで取り込む。下書きにも取り込みにも判定の変更は無い（判定・組み込みの保護・
`rules.yml` はそのまま）。下書きの置き場は提案の置き場の下で範囲外なので、エージェントは今のまま書ける。取り込み先は
`.ccnavi/config/` の下で、組み込みの保護が既にエージェントの書き込みを止める。

**下書きの置き場。** `<提案の置き場>/templates/<名前>.yml`（既定は `wip/proposals/templates/`。プロジェクトのツリーならそのプロジェクトの
`wip/proposals/templates/`）。`plan_templates.draft_dir_rel` / `draft_rel` / `draft_dir` / `draft_file` が、子のフローの下書き
（`flow.draft_rel` / `draft_file`）と同じ形で置き場を返す。下書きに効力は無い。`plan_templates.scan` も `--templates` の足し算も読まない。
下書きを読む口は `template_drafts.scan` で、全ツリー（ワークスペース・プロジェクト・ワークツリー）の置き場を読み、そのツリーのレイヤー
（`self` かプロジェクト名）のフェーズ定義で検査する。同じ中身の下書きが複数のツリーに在れば（親のブランチに乗った下書きは子のワークツリーにも
checkout される）1 本にまとめ、ほかのツリーを `also_in` に持つ。

**`--templates --draft <親> [--name <名前>]`。** エージェントが打ってよい（効力が無いので `_CLI_FORMS` には足さない）。

| 段 | 内容 |
|---|---|
| 親を探す | `approval.scan(closed=True)` で `done/` の親を探す。作業中（`doing/`）・取り消した・計画が無い・複数のツリーに在って決まらない、は断る。`ready` で閉じて退避済み（`logs/archive/`）は「退避した親は読まない」と言って終了コード 1。退避から読む実装は無い |
| `after` の正規化 | 親の計画の `after` は全体計画の続きの絶対番号。全体計画はそのまま、フィードバック計画は全体計画の項数を引いて計画の中の添字にする。承認が順序を確かめた計画の引き算だけなので、並べ替え（`plan_order.renumber`）は使わない。計画の中の項を指さない `after`（引いて 1 未満）は落として知らせる。検査が合成する提案（`_composed`）は逆の足し算をするので、往復で絶対番号に戻る |
| フロー | 全体計画の n 番目の項の子（`phase` が n で `done/` に在る）のうち、フローを持つ最初の 1 本（識別子順）を `flows[n]` に写す。読めないフローは写さずに知らせる。ほかの子にもフローがあれば知らせる。フィードバック計画の子のフローは写さない（`flows` は全体計画の添字で指すため） |
| 固有名 | 機械では一般化しない。`description` を `TODO 一般化する: <親の題>`、`when` を `「<親の題>」と同じ形の作業をするとき` にする。`description` か `when` に `TODO` が残っていると、検査（`plan_templates.check`）が warn で言う。エージェントが直す |
| 書く | `fsio.write_new_durable`（一時ファイル → fsync → 差し替え。在れば書かない）。同名の下書きは上書きせず error。置き場の途中にリンクがあれば書かない。名前の既定は親の識別子で、`NAME_RE` に合わなければ `--name` を求める |

**`--templates --import <下書きの名前かパス> --to common|project [--layer <名前>] [--replace] [--yes --expect <ハッシュ>]`。** ユーザ専用で、
`phase_forms._CLI_FORMS` に `--import` を足してエージェントが打てないようにした（下見も含めて止める。`--yes` は既に入っていた）。
値なしの `--yes` は `--import` だけが読み（`cli_templates.BARE_YES`）、ほかの経路は今までどおり識別子を求める。
隠した引数の検査（`hidden_user_entry`）も `--import` と `--yes` の組を承認の組と同じに扱う。

| 段 | 内容 |
|---|---|
| 下書きを探す | 名前なら全ツリーの置き場から探し、中身の違う同名が複数あればパスで指させる。パスは下書きの置き場の下の `.yml` だけ受ける |
| 下見（`template_drafts.prepare`） | 何も書かない。下書きを取り込み先の定義（共通は共通だけ、`project` は共通 + レイヤー）で検査し直す。error があれば取り込めない。warn は見せるだけ。同名が取り込み先に在れば `--replace` が要る。共通とレイヤーに同名で中身が違うものが並ぶ取り込みは、足し算がレイヤーの側を使わない error にするので断る（全欄が同じなら info） |
| 差分 | 同名があれば取り込み先のいまの文面と下書きの `difflib.unified_diff`（前後 3 行つき）。同名が無ければ本文を全部見せる。フローの文は案内文になるので、ユーザが読むことが歯止め。続けて打つ形（ハッシュ入り）を出す |
| 書く（`commit`） | `--yes` と `--expect` が揃い、`--expect` が下書きの今の中身（検査したバイト列）のハッシュと同じときだけ。中身は書き換えずそのまま書く。新規は `write_new_durable`、置き換えは `write_bytes_atomic`（どちらも一時ファイル → fsync → 差し替え）。取り込み先がリンク・ハードリンク・ふつうのファイルでない、または置き場の途中にリンクがあれば書かない。書いたあとに読み直してハッシュを確かめる |
| 下書きを消す | 書けたあと、下書きを読み直して取り込んだときの中身（ハッシュ）と同じときだけ消す。違えば消さずにそう言う。読めない（リンク・ハードリンクなど）も消さない |
| `--json` | 下見と結果。`ok`・`errors[]`・`infos[]`・`problems[]`・`diff[]`・`written`・`removed`・`kept`・`draft`・`target` |

端末を求めることはしない。ボードの画面（将来のテンプレート管理画面）が `--yes` つきで呼べるようにするため、保護は `_CLI_FORMS` と
`--expect`（下書きのハッシュ）の 2 つにしている。

**`--templates` の一覧。** 下書きがあれば最後に `下書き: N 件（wip/proposals/templates/）` を 1 行出す。`--json` は `drafts[]` を足す
（`templates[]` にも `layers[]` にも `sums[]` にも入れない）。1 件は `name`・`tree`・`path`・`sha`・`valid`・`importable`・`layer`・
`exists_in`（同名のテンプレートが在るレイヤー）・`also_in`・`description`・`when`・`plan`・`feedback`・`flows`・`problems`。`errors` / `warns` /
`infos` には数えない。`LINT_VERSION` は上げない。

**`--lint`。** 下書きの苦情は `(template-drafts)` の場所で、error を warn に下げて出す（効力が無い）。深刻度は warn と info だけ。

**取り込んで消えた下書きのコミット。** `ccnavi-push-approved.sh` は `ls-files --deleted` で追跡されていて消えた `todo/` の提案と `flows/` の下書きを
コミットする。`templates/` も同じ形で足した（C1 の手順の `carry_paths` と、そうでないツリーのコミットの 2 か所）。保護済みの sh なので、
完成品を `wip/design/scripts/ccnavi-push-approved.sh` に置いた（ユーザがコピーする）。既存の挙動は変わらない。承認済みチケットの置き場に
変更が無いツリーは見ないままなので、下書きの削除だけではコミットされず、次に置き場に変更があったときに一緒に入る（フローの下書きと同じ）。
