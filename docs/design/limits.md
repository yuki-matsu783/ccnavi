## 12. 限界と保証しないこと

### 12.1 保証しないこと

2.1 で対象外に置いた主体（実行環境を掌握した攻撃者）と、そこへ向けた防御は、そのまま保証の外。
加えて次を保証しない。

| 保証しないこと | なぜ |
|---|---|
| 敵対的な回避への防御 | 意図的な文字列の分割、変数展開、alias 経由の実行は対象にしない。完全なシェルの解析を書いても守れる範囲は広がらない |
| `cd` の行き先を読み切れない形 | 変数・置換・グロブを含む `cd`、`cd -`、`pushd` の先は追わない（6.3.2）。そのあとは継ぎ足さないので、書かれた表記で当たるものだけが当たる。`case` の枝の中、`$( )` の中身から見た外側の行き先、一覧に無い実行役のコマンドが移す先も同じ |
| 一覧に無い実行役のコマンドの中 | `ssh host <cmd>`・`watch`・`python -c` など、組み込みの一覧（6.3.1）に無い実行役のコマンドは外さない。先頭に固定したルールはその中に当たらず、未宣言なら 6.5 の扱いになる |
| ccnavi の外側で打ち切られた場合 | プロセスごと終了させられると応答が捨てられ、呼び出しはそのまま通る。自分の期限で先回りするだけ |
| 巨大なコマンドを期限の中で読み切ること | 読みは置換 1 つごとに `shlex` を組み直すので、置換を数万個並べると読みだけで期限（3 秒）に達する（8 万個・949KB で 3.6 秒）。読み終えたあと期限切れとして止める側になる（`deadline-exceeded`）が、hook の実行時間はそのぶん延びる |
| git の管理下にないファイルへの事後検知 | 追跡されていない変更・`.gitignore` の中・リポジトリ外への出力は検知しない |
| 情報流出を防ぎ切ること | 外へ送れる形のコマンドはルールで拒否と誘導の対象にできるが、一覧は網羅ではない。スクリプトの中で送る形や Bash 以外の送信経路には判定が届かない。egress を閉じられる sandbox やネットワークポリシーが上位 |
| ルールが列挙していない領域の保護 | 未宣言の領域は判定を持たず、扱いは委ねる先が決める。列挙漏れは防げない |
| hook の登録そのものを消された場合 | 登録が消えれば呼ばれない。`PreToolUse` の登録ごと消されれば一切動かない |
| チケットの生成 | チケットはエージェントが書き、ユーザが承認する。ccnavi は検証と提示だけ |
| ブランチの親子とマージ先の検証 | 判定で確かめるのはワークツリーの名前と識別子の一致だけ。例外はレビュー依頼の前提 |
| チケット同士の範囲の重なり | 同じ場所を 2 本が宣言しても止めない。衝突はマージで解く |
| プロジェクトをまたぐ親どうしの順番と依存 | 親は 1 つのプロジェクトに閉じる（11.5）。どの親を先に進めるかは、ユーザが承認と合流の順で決める |
| レビューの中身の評価 | 見るのは未解決のスレッドの有無だけ |
| チャットでの許可の検出 | ユーザの判断は端末からの直接起動で受け取る |
| リモートの読み書きそのもの | JSON が実物と一致していることは sh と道具の側の責任 |
| Claude Code 以外のエージェントや IDE | ツール名と入出力の書式が異なる |

### 12.2 許容する誤検知

失敗の向きが見逃し（実行を止めずに通す）のものは止め続け、誤検知（実行でないものを止める）のものは
理由が返るので書き直せる。判断が付かないときは常に誤検知の側を採る。

| 誤検知 | 回避 |
|---|---|
| `grep -n "<<" f` がヒアドキュメントに見えて止まる（6.3） | 対象をファイルへ移す |
| 二重引用の中の `$( )` が、文字のつもりでも実行として読まれる。シェルは実際に実行する | `\$(` で書く、単一引用、`--body-file <ファイル>` |
| バッククォートは、文字のつもりでも中身に依らず止まる（`--body "…"` に書いた Markdown の ``` `git push` ```、閉じないバッククォート。6.3） | 単一引用で包む、`` \` `` で書く、`--body-file <ファイル>` |
| `commit -m "$(cat <<'EOF' … EOF)"` や `gh pr create --body "$(cat <<'EOF' …)"` に heredoc のルールが当たる | 本文を Write で置いて `commit -F <ファイル>` / `--body-file <ファイル>`。改行を含む `-m "…"` |
| `cd "$(git rev-parse --show-toplevel)"` が raw-git に当たる | ラッパースクリプトで値を出して読み、次のコマンドに値を書く |
| `grep -rn foo "$(pwd)"` や、grep を改行で 2 行つないだものが allow から外れて確認になる | 値をそのまま書く。1 行ずつ打つ |
| `$( )` の中の、コマンドの先頭ではない `case` の語でも止まる（`"$(echo just in case)"`） | 語を変える。case は if/elif で書く |
| `$( )` の中の縮退（`xargs`、`sh -c`、シェルによって読みが分かれる形）が、外側のコマンドにも広がる | スクリプトを Write で置いて `sh <ファイル>` |
| 1 語のパターンが引用の中でも当たる（`echo ".env"`） | ルールのパターンを絞る |
| 縮退した複合コマンドの、読めた側の区間も生の文字列で判定される | 別のコマンドに分ける |
| `PARSE_UNCERTAIN` でユーザに確認が出る | `Write` でスクリプトを置いてから渡す |
| 引用の外のブレース展開が、読める形でも止まる（`grep -rn foo --exclude-dir={a,b} .`、`cp f{,.bak}`。6.3） | 語を並べて書く（`--exclude-dir=a --exclude-dir=b`、`cp f f.bak`） |
| シェルが広げない位置のブレースも止まる（代入の右辺 `x={a,b}`、case のパターン `case $x in {a,b})`、`[[ $f == *.{jpg,png} ]]`、bash 3.2 だけで動かす `{1..5..2}`） | 単一引用で包む（`x='{a,b}'`）。パターンは `a\|b)` や `[[ $f == *.jpg \|\| $f == *.png ]]` と書く（`[[ ]]` の中のブレースはどちらのシェルでも一致しない） |
| 変数や置換をコマンド名に置く普通の書き方が止まる（`G=…; $G add`、`sh $SCRIPT`、`"$PYTHON" -m x`。6.3） | コマンド名とスクリプトのパスをそのまま書く |
| シェルが展開しない表記のコマンド名も止まる（単一引用した `'$c'`、エスケープした `\$c`、引用したグロブ文字 `"gi?"`） | 表記を変える |
| `coproc`・`select` がコマンドの位置で止まる（`for` と `case` の直後の語は止まらない） | `&` でバックグラウンドに回す。`for` で回す |

### 12.3 未実装

要件書にあって手が付いていないもの。確認の記憶（REQ-PRE-07）とその事後無効化（REQ-PST-04）、
セッション開始時の実効権限の提示（REQ-SES）、記憶の消去（REQ-DIA-05）。一覧と次の一手は
GitHub の issue。

### 12.4 最終防衛線

ccnavi はアプリケーション層の柵で、それ自体を最終防衛線にしない。実行環境の認証情報に本番
リソースへの権限を与えない、開発用の DB 接続に破壊の権限を与えない、外部通信を許可の一覧で
絞る、コンテナや VM の中で動かす。ccnavi がすべて突破されても、実行環境の認証情報が本番を
破壊できなければ、最悪の被害は起きない。
