## 12. 限界と保証しないこと

### 12.1 保証しないこと

2.1 で対象外に置いた主体（実行環境を掌握した攻撃者）と、その主体へ向けた防御は、そのまま保証の外にある。
加えて次を保証しない。

| 保証しないこと | なぜ |
|---|---|
| 敵対的な回避への防御 | 意図的な文字列の分割、変数展開、alias 経由の実行は対象にしない。完全なシェルの解析を書いても守れる範囲は広がらない |
| `cd` の行き先を読み切れない形 | 変数・置換・グロブを含む `cd`、`cd -`、`pushd` の先は追わない（6.3.2）。そのあとは追わないので、書かれた表記でヒットするものだけがヒットする。`case` の枝の中、`$( )` の中身から見た外側の行き先、一覧に無い実行役のコマンドが移す先も同じ |
| 一覧に無い実行役のコマンドの中 | `ssh host <cmd>`・`watch`・`python -c` など、組み込みの一覧（6.3.1）に無い実行役のコマンドは外さない。先頭に固定したルールはその中にヒットせず、未宣言なら 6.5 の扱いになる |
| git が引数の文字列を実行する形の中 | `git rebase --exec "git push"`（`-x`）のように、git がオプションの値をシェルで実行する形は、引用の中を読まない。中の `git push` は組み込みの止めにヒットせず、未宣言なら 6.5 の扱いになる |
| ラッパー（`ccnavi-git.sh`）の居場所を `CDPATH` で読み違える形 | `CDPATH=.ccnavi cd approved && sh …ccnavi-git.sh rm …` を、hook は cwd からの相対と読む。環境の `CDPATH` は hook から見えない。2 重目の sh は実際の居場所で見て自己防衛の対象を止めるが、承認済みチケットの置き場の `rm` は通す |
| 別の言語の中で組み立てたラッパーとユーザの入口の呼び出し | `python3 -c 'os.system("sh …ccnavi-git.sh rm …")'`・`perl -e`・`awk` の `system()` の中は読まない。言語ごとの読み方が要り、見合わない。ラッパーは 2 重目の sh が展開後の引数で自己防衛の対象を止める |
| `xargs` に読み込む値の中身と、オプションを変数で書いたラッパーの呼び出し | `xargs` はラッパーの名前の直後のサブコマンドだけを見る。`restore $O HEAD~1 <対象>` のようにオプションの位置に置いた展開は追わない。2 重目の sh が展開後の引数で、自己防衛の対象と承認済みチケットの置き場を止める |
| レビュー待ちの置き場の、ディスクに無く索引にだけ残るファイル | 置き場の親（`wip/`・`wip/proposals/`）を消す形は、hook が見たときに置き場に何かがあるときだけ止める。hook は git を起こさないので、索引にだけ残るファイルは数えない。シェルの `rm` と Write は置き場で止まるので、エージェントがこの形を作るのは難しい |
| ccnavi の外側で打ち切られた場合 | プロセスごと終了させられると応答が破棄され、呼び出しはそのまま通る。自分の期限で先回りするだけ |
| エージェントが案内に必ず従うこと | ナビ（案内・`次:`・フロー）は通常の手順を支えるだけで、従うかどうかはエージェント次第。止めるのは関門（hook とスクリプトの拒否）だけ |
| 事前確認（`ccnavi-start.sh --check` など）で後の操作の成功が保証されること | 確かめられるのはその時点の状態だけ。通ったあとも、取り込みや push の関門で止まることはある |
| 時間制限で全体の時間や子孫プロセスの終了が保証されること | 時間制限は待ち続けないためのもの。全体の所要時間を厳密に切ることも、子孫のプロセスを残らず終わらせることもしない |
| 異常停止や複数 PC の同時操作で、厳密に 1 回だけ実行すること | 同じ PC のロックと、送る前の照合で重複を減らすだけ。結果が分からないときは自動で送り直さず、確かめを求めて止まる |
| 巨大なコマンドを期限の中で読み切ること | 読みは置換 1 つごとに `shlex` を組み直すので、置換を数万個並べると読みだけで期限（3 秒）に達する（8 万個・949KB で 3.6 秒）。読み終えたあとは期限切れとして止める側になる（`deadline-exceeded`）が、hook の実行時間はそのぶん延びる |
| ルール 1 件の照合を期限の中で止めること | 期限の確認はルール 1 件の照合が終わるたびにしか見ないので、1 件の照合の途中は切れない。実ルールの `*ccnavi-git.sh*` のような `*x*` 形の glob は、照合の時間が入力の長さの 2 乗で伸びる（開始位置ごとに末尾まで走査する）。`tests/core/bench_deadline.py` で、このリポジトリの実ルール（`enable`）を使って測ると、期限（3 秒）を超えるのは、Bash の約 2 万字、置換 5,000 個、Write の `file_path` 1 万字から。時間は次のとおり。Bash の `echo` に `a` を並べると 1 万字で 2.16 秒、2 万字で 8.70 秒。`$(:)` の置換は 2,000 個で 2.73 秒、5,000 個（25KB）で 5.65 秒。Write の `file_path` は 1 万字で 3.23 秒。超えた回は次のルールの確認で `deadline-exceeded` になる（終了コード 2）が、止まるまでの時間はそのぶん延びる。Bash の 40 万字は 17.5 秒。値は macOS での 1 回の測定で、機械によって変わる。修正は issue #241 で扱う |
| git の管理下にないファイルへの事後検知 | 追跡されていない変更・`.gitignore` の中・リポジトリ外への出力は検知しない |
| 情報流出を防ぎ切ること | 外へ送れる形のコマンドはルールで拒否と誘導の対象にできるが、一覧は網羅ではない。スクリプトの中で送る形や Bash 以外の送信経路には判定が届かない。egress を閉じられる sandbox やネットワークポリシーが上位 |
| ルールが列挙していない領域の保護 | 未宣言の領域は判定を持たず、扱いは委ねる先が決める。列挙漏れは防げない |
| hook の登録そのものを消された場合 | 登録が消えれば呼ばれない。`PreToolUse` の登録ごと消されれば一切動かない |
| チケットの生成 | チケットはエージェントが書き、ユーザが承認する。ccnavi は検証と提示だけ |
| ブランチの親子とマージ先の検証 | 判定で確かめるのはワークツリーの名前と識別子の一致だけ。例外はレビュー依頼の前提 |
| チケット同士の範囲の重なり | 同じ場所を 2 本が宣言しても止めない。衝突はマージで解く |
| プロジェクトをまたぐ親どうしの順番と依存 | 親は 1 つのプロジェクトに閉じる（11.5）。どの親を先に進めるかは、ユーザが承認と合流の順で決める |
| レビューの中身の評価 | 見るのは未解決のスレッドの有無だけ |
| チャットでの許可の検出 | ユーザの判断は、ユーザが直接操作する場所（ターミナル・ボード・Chrome 拡張）で受け取る |
| リモートの読み書きそのもの | JSON が実物と一致していることは sh と道具の側の責任 |
| Claude Code 以外のエージェントや IDE | ツール名と入出力の書式が異なる |
| Stop の AI 判定の正しさ | 判定役が返した指摘が正しいことは保証しない。検証するのは出力の構造だけ。判定役が落ちた・拒まれた・返り値に従わなかったときは、未検査で閉じるか「記録外の停止の疑い」として数えるだけで、防げない。材料には上限があり、切れたときは未検査にする。伏せ字は秘密の形をした部分だけで、すべての機密を消すものではない（[stop-review.md](stop-review.md)） |

### 12.2 許容する誤検知

失敗の向きが見逃し（実行を止めずに通す）になるものは、止め続ける。誤検知（実行でないものを止める）になるものは、
理由が返るので書き直せる。判断が付かないときは常に誤検知の側を採る。

| 誤検知 | 回避 |
|---|---|
| `grep -n "<<" f` がヒアドキュメントに見えて止まる（6.3） | 対象をファイルへ移す |
| 二重引用の中の `$( )` が、文字のつもりでも実行として読まれる。シェルは実際に実行する | `\$(` で書く、単一引用、`--description-file <ファイル>`（gh なら `--body-file`） |
| バッククォートは、文字のつもりでも中身に依らず止まる（`--description "…"`（gh なら `--body`）に書いた Markdown の ``` `git push` ```、閉じないバッククォート。6.3） | 単一引用で包む、`` \` `` で書く、`--description-file <ファイル>`（gh なら `--body-file`） |
| `commit -m "$(cat <<'EOF' … EOF)"` や `glab mr create --description "$(cat <<'EOF' …)"`（gh なら `gh pr create --body …`）に heredoc のルールがヒットする | 本文を Write で置いて `commit -F <ファイル>` / `--description-file <ファイル>`（gh なら `--body-file <ファイル>`）。改行を含む `-m "…"` |
| `cd "$(git rev-parse --show-toplevel)"` が builtin:guard-raw-git にヒットする | ラッパースクリプトで値を出して読み、次のコマンドに値を書く |
| `grep -rn foo "$(pwd)"` や、grep を改行で 2 行つないだものが allow から外れて確認になる | 値をそのまま書く。1 行ずつ打つ |
| `$( )` の中の、コマンドの先頭ではない `case` の語でも止まる（`"$(echo just in case)"`） | 語を変える。case は if/elif で書く |
| `$( )` の中の縮退（後ろが許可リストにない `xargs`、`sh -c`、シェルによって読みが分かれる形）が、外側のコマンドにも広がる | スクリプトを Write で置いて `sh <ファイル>` |
| 1 語のパターンが引用の中でもヒットする（`echo ".env"`） | ルールのパターンを絞る |
| 縮退した複合コマンドの、読めた側の区間も生の文字列で判定される | 別のコマンドに分ける |
| `PARSE_UNCERTAIN` でユーザに確認が出る | `Write` でスクリプトを置いてから渡す |
| 引用の外のブレース展開が、読める形でも止まる（`grep -rn foo --exclude-dir={a,b} .`、`cp f{,.bak}`。6.3） | 語を並べて書く（`--exclude-dir=a --exclude-dir=b`、`cp f f.bak`） |
| シェルが広げない位置のブレースも止まる（代入の右辺 `x={a,b}`、case のパターン `case $x in {a,b})`、`[[ $f == *.{jpg,png} ]]`、bash 3.2 だけで動かす `{1..5..2}`） | 単一引用で包む（`x='{a,b}'`）。パターンは `a\|b)` や `[[ $f == *.jpg \|\| $f == *.png ]]` と書く（`[[ ]]` の中のブレースはどちらのシェルでも一致しない） |
| 変数や置換をコマンド名に置く普通の書き方が止まる（`G=…; $G add`、`sh $SCRIPT`、`"$PYTHON" -m x`。6.3） | コマンド名とスクリプトのパスをそのまま書く |
| シェルが展開しない表記のコマンド名も止まる（単一引用した `'$c'`、エスケープした `\$c`、引用したグロブ文字 `"gi?"`） | 表記を変える |
| `coproc`・`select` がコマンドの位置で止まる（`for` と `case` の直後の語は止まらない） | `&` でバックグラウンドに回す。`for` で回す |

### 12.3 未実装

要件書にあって手が付いていないもの。セッション開始時の実効権限の提示（REQ-SES）。学びの蓄積（REQ-LRN。9.16）のうち、今ある wiki の移行（`target`・`sources` の無い既存のパターン）。学びの蓄積が記録の中身の質を見ないこと（空でないことだけを見る）と、記録・wiki・採否の記録の偽装を機械的には止めないこと（防御の方針）は、保証しないこと。一覧と次の一手は
GitHub の issue にある。

### 12.4 最終防衛線

ccnavi はアプリケーション層の柵であり、それ自体を最終防衛線にはしない。実行環境の認証情報に本番
リソースへの権限を与えない、開発用の DB 接続に破壊の権限を与えない、外部通信を許可の一覧で
絞る、コンテナや VM の中で動かす。ccnavi がすべて突破されても、実行環境の認証情報が本番を
破壊できなければ、最悪の被害は起きない。

### 12.5 文書化されていない外部の前提

ccnavi が Claude Code から読む、または頼っている挙動のうち、Claude Code の文書に無いもの。版が変わると変わりうる。

| 前提 | 使う場所 |
|---|---|
| 環境変数 `CLAUDE_CODE_SESSION_ATTENDED` が `0` なら付き添いなし | セッション開始の作業の決まりの条件 `non_interactive`（REQ-SES-07・REQ-SES-08） |
| 非対話（`claude -p`）は、バックグラウンドの Bash とバックグラウンドのサブエージェントの完了を、待ち上限（既定は連続 10 分の idle。`CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS` で変えられ、0 で上限なし）の範囲で待つ。`CLAUDE_CODE_BG_TASKS_REPORT_RUNNING=0` の環境では、バックグラウンドのサブエージェントはターン終了で消える | 非対話のとき、サブエージェントをフォアグラウンドで起動して完了を待つ案内（消える環境でも安全な形）|

- 判定は、`0` と確かめられたときだけ非対話とする。未設定・`1`・読めない値は対話として扱う
- 人が付き添う入口（IDE の拡張など、SDK 系の起動）で `0` になるかは確かめていない。`0` になるなら、人がいても非対話の案内が渡る
- この変数の意味が変わったら、非対話の案内が出なくなるか、対話のセッションに出る。コードで見るのは 1 か所（`non_interactive` の判定）で、変数名は定数にまとめてある
- 確かめた値・版・試行回数、確かめていないこと、再現の方法は[付録 C の「非対話の起動」](appendix.md)にある
