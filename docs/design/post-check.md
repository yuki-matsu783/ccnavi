## 7. 実行後チェック

### 7.1 何を見るか

引数に現れない書き込み（ビルドの出力、許可されたスクリプトが内部で開くファイル、読み切れないシェル構文で書いたもの）は、
実行したあとの作業ツリーを git で読んで拾う。

`PostToolUse` で、`Read` `Grep` `Glob` `WebFetch` `WebSearch` 以外の全ツールの後に走る。
読み取り専用のツールの直後は `tool-cannot-write` として見に行かない（同じ変更は次の書き込みうるツールの直後に見える）。

見るツリーは、ワークスペースルートと、この呼び出しが触ったツリー（パスを持つツールは行き先、
Bash は cwd）。ツリーごとに `git status --porcelain -z --untracked-files=all --no-renames` を
期限 2 秒で起動する。読めなければ `worktree-unreadable` として何も言わない。

### 7.2 保護領域と違反

保護領域は別に宣言しない。そのツリーのルールのうち、`match` に `Write` `Edit` `NotebookEdit` の
どれかを含む `deny` / `ask` が、そのまま「この場所に書かせない」の宣言になる。
変更の実パスがそれに当たれば違反（`POST_VIOLATION`）。そうでなく、ワークツリーに結び付くチケットの
範囲の外（チケットの `deny` の項を含む）なら、ルールの `allow` に当たっていても `POST_TICKET_SCOPE`（9.5）。
記録と state の置き場（`logs/decisions.jsonl`、`logs/state/` の下）は除く。ローテートした記録は除かない。

チケットの置き場（`wip/proposals/`、`.ccnavi/approved/`）に現れた変更は、ccnavi の副命令
（`ticket start` / `finish` / `cancel` と `review request` / `confirm` / `ready`）が書いたと内容から読めるぶんだけ除く。
見るのはコミット済みの版との差で、除くのは次の 3 つ。

| 何 | 外す条件 |
|---|---|
| frontmatter を持たないファイル | どちらの版も持たない。マーカー・`.risk.json`・`.judge.json`・`accepted.json`・閉じの記録のほか、チケットでないファイルはすべてここに入る |
| チケットへの書き足し | `ticket.SCRIPT_FIELDS` のうちコミット済みの版がまだ持っていない欄以外が 1 文字も変わっていない（`ticket.script_shape`） |
| `finish` / `cancel` の移動 | 正規化した内容が同じチケットが `doing/` か `review/` から消え、`review/` か `done/` に現れた組。両側とも 1 件ずつのときだけ |

範囲・親・フェーズ・本文が変わったチケット、既に値のあるスクリプトの欄（`base_sha` など）の書き換え、新しく現れた
承認済みチケット、消えただけのチケットは報告する。コミット済みの版を読めなかったものは外さない。

見分けるのは未コミットの側だけ。ターンの終わりにコミット済みのぶんを数えるところ（`_committed_findings`）は、置き場ごと外す。

違反の報告には 1 件ずつ、変更されたファイル・種類・該当するルール・原因となった直前の実行・戻す手順（対象ごとに 1 つ）を添える。

| 変更の種類 | 戻し方 |
|---|---|
| 中身が変わった・消えた | `git restore --staged --worktree -- <path>` |
| 追跡されていないものが現れた | `git clean -f -- <path>` |
| 索引に足された状態で現れた | `git rm -f -- <path>` |

このイベントにツール呼び出しを取り消す手段は無い。`enable` では終了コード 2 と標準エラーで
差し戻し、`dry-run` では `additionalContext` で報告だけする。報告は 12 件、記録は 500 件が上限。

### 7.3 前から在った変更と記録

初めて見た変更は、その場でセッションごとの記録（`state/<セッション>.json`）に取る。そのうえで `POST_PREEXISTING`
として 1 度だけ伝え、戻すなと明示し、自動復元の対象からも外す。以降に新しく現れたものだけを
原因付きで差し戻す。既知の変更は繰り返さない。同じ場所でも「中身が変わった」の次に「消えた」が
来れば、別の出来事としてもう一度言う。

### 7.4 ターンの基準とユーザへの報告

`UserPromptSubmit` で、そのとき保護領域にある変更と、ツリーごとの HEAD を
`state/<セッション>.turn.json` に記録する。`Stop` で、その基準に無い違反だけを `systemMessage` で
ユーザへ報告し、戻す手順を 1 件ずつ添える。記録した HEAD からの差分も見るので、保護領域を汚してからコミットしたぶんも出る。
数えるのはそのツリーが積んだコミットだけ（`--first-parent --no-merges`）で、`merge <統合先>` が
持ち込んだぶんは数えない。基準を持たないツリー（ターンの途中で切ったもの）は数えず、数えていないことを 1 行で言う。
コミットに入ったぶんは戻す手順を持たない（履歴は書き換えない）。チケットの置き場は外す。
戻さない。`enable` と `dry-run` で同じように報告する（`disable` はイベントそのものが走らず、
記録に `mode-disabled` が残る）。基準が無ければ何も報告せず、記録に `no-turn-baseline` を残す（REQ-PST-06、REQ-PST-07）。

呼び出しごとの報告はモデルへ、ターンの終わりの報告はユーザへ届く。

同じ報告に、このセッションで同じ理由の拒否が N 回に達した呼び出し（6.4）を並べる。拒否の文面はモデルにしか
届かないので、言い換えて打ち直しを繰り返しているかもしれないことをユーザにも言う。言った回数を記録に残し、増えるまで繰り返さない。

### 7.5 自動復元

`CCNAVI_RESTORE_IF_DENY` が `enable`（既定）のとき、新しく現れた違反のうち、ルールが `deny` と
宣言した場所のものだけを戻す。`ask` と承認済みチケットの範囲外は、報告はするが戻さない
（報告する範囲 `post._guarding` より戻す範囲 `post._restorable` が狭い）。中身が変わった・
消えたものは `git restore --staged --worktree`、現れたものは消さずに
`state/aside/<日時>/<path>` へ退避し、退避先を報告に載せる（索引にあれば先に `git rm --cached`）。
`dry-run` は戻さず、報告に `would-restore` の行を足す。`disable` は戻さず、その行も出さない。
戻す先はコミット済みの内容なので、保護領域を汚した未コミットの変更は失われる。戻せたものは記録に入れない。
戻さなかったもの（`ask` と範囲外）は記録に入るので、呼び出しごとの報告はセッションで 1 度きりになり、その後は
ターンの終わりの報告でユーザに見せる。

### 7.6 見えないもの

| 見えない | なぜ |
|---|---|
| `.gitignore` に入っているファイル | `git status` に出ない |
| git の作業ツリーの外 | 実行後チェックはリポジトリの中だけを見る |
| この呼び出しが触っていない別のツリー（プロジェクト・ワークツリー） | 見るのはワークスペースルートと触ったツリー。子のワークツリーはサブエージェントの終了時に基準点からの差分を見る（9.12） |
| 失敗したツール呼び出しの副作用 | `PostToolUse` は成功した呼び出しの後にしか走らない |
