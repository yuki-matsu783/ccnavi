## 7. 実行後チェック

### 7.1 何を見るか

引数に現れない書き込み（ビルドの出力、許可されたスクリプトが内部で開くファイル、読み切れないシェル構文で書いたもの）は、
実行したあとの作業ツリーを git で読んで拾う。

`PostToolUse` で、`Read` `Grep` `Glob` `WebFetch` `WebSearch` 以外の全ツールの後に走る。
読み取り専用のツールの直後は `tool-cannot-write` として見に行かない（同じ変更は次の書き込みうるツールの直後に見える）。

見るツリーは、ワークスペースルートと、この呼び出しが触ったツリー（パスを持つツールは行き先、
Bash は cwd）。ツリーごとに `git status --porcelain -z --untracked-files=all --no-renames` を
期限 2 秒で起動する。読めなければ `worktree-unreadable` として何も言わない。

### 7.2 保護領域と違反

そのツリーのルールのうち、`match` に `Write` `Edit` `NotebookEdit` の
どれかを含む `deny` / `ask` が、そのまま「この場所に書かせない」の宣言になる。
変更の実パスがそれに当たれば違反（`POST_VIOLATION`）。そうでなく、ワークツリーに結び付くチケットの
範囲の外（チケットの `deny` の項を含む）なら、ルールの `allow` に当たっていても `POST_TICKET_SCOPE`（9.5）。
記録と state の置き場（`logs/decisions.jsonl`、`logs/state/` の下）は除く。

チケットの置き場（`wip/proposals/`、`.ccnavi/approved/`）に現れた変更は、ccnavi のサブコマンド
（`ticket start` / `finish` / `cancel` と `review request` / `confirm` / `ready`）が書いたと内容から読めるぶんだけ除く。
見るのはコミット済みの版との差で、除くのは次の 3 つ。

| 何 | 外す条件 |
|---|---|
| frontmatter を持たないファイル | どちらの版も持たない。マーカー・`.risk.json`・`.judge.json`・以前の版が置いた `accepted.json`・閉じの記録のほか、チケットでないファイルはすべてここに入る |
| チケットへの書き足し | `ticket_model.SCRIPT_FIELDS` のうちコミット済みの版がまだ持っていない欄以外が 1 文字も変わっていない（`ticket_fields.script_shape`） |
| `mr:` の書き足し（例外 1 つ） | コミット済みの版に frontmatter があって `mr:` が空（欄なし・値なし・続きの行なし）、いまの版の `mr:` が `mr: 12` の 1 行だけの正の整数で、`mr:` の行を除いたほかが 1 文字も変わっていない（`post_findings._mr_filled`）。`review request` が親ブランチの MR を確かめた後に親の承認済みチケットへ書き足すぶん。整数から別の整数・整数から空・`"12"` や注釈つきの書き方・ほかの欄や本文の変更は、今までどおり報告する。`mr` は `SCRIPT_FIELDS` には入れない（提案者が書ける欄で、`script_fields_set` の対象でもない）。除く条件は最初の比べだけで、`finish`・`cancel` の移動の組には使わない |
| `finish` / `cancel` の移動 | 正規化した内容が同じチケットが `doing/` か `review/` から消え、`review/` か `done/` に現れた組。両側とも 1 件ずつのときだけ |

範囲・親・フェーズ・本文が変わったチケット、既に値のあるスクリプトの欄（`base_sha` など）の書き換え、新しく現れた
承認済みチケット、消えただけのチケットは報告する。コミット済みの版を読めなかったものも報告に残す。

見分けるのは未コミットの側だけ。ターンの終わりにコミット済みのぶんを数えるところ（`_committed_findings`）は、置き場ごと外す。

違反の報告には 1 件ずつ、変更されたファイル・種類・該当するルール・原因となった直前の実行・戻す手順（対象ごとに 1 つ）を添える。

| 変更の種類 | 戻し方 |
|---|---|
| 中身が変わった・消えた | `<git> restore --staged --worktree -- <path>` |
| 追跡されていないものが現れた | `rm -- <path>` |
| 索引に足された状態で現れた | `<git> restore --staged -- <path> && rm -- <path>` |

`<git>` は、ワークスペースルートに git のラッパー（`.ccnavi/scripts/ccnavi-git.sh`）があればその実パス（`sh <ルート>/.ccnavi/scripts/ccnavi-git.sh`）、
無ければ、ユーザに頼む文にする（生の git は組み込みでいつも止まるため）。ラッパーは `rm -f` と
`clean` を通さないので、現れたものは索引から外してシェルの `rm` で消す形にする。

このイベントにツール呼び出しを取り消す手段は無い。`enable` では終了コード 2 と標準エラーで
差し戻し、`dry-run` では `additionalContext` で報告だけする。報告は 12 件が上限で、超えた分は「ほか N 件」と書く。
報告済みの記録は件数で切らない。切った先の汚れが新しい変更として戻されるため。

### 7.3 前から在った変更と記録

セッションの開始（SessionStart の startup）で、全ツリーの変更を基準として記録する（`state/<セッション>.reported.json`）。基準が取れなかったときは、初回の実行後チェックが同じ記録を取る。そのうえで `POST_PREEXISTING`
として 1 度だけ伝え、戻すなと明示し、自動復元の対象からも外す。以降に新しく現れたものだけを
原因付きで差し戻す。同じ場所でも「中身が変わった」の次に「消えた」が
来れば、別の出来事としてもう一度言う。

記録の `code` は文面の先頭の行と同じ材料から書く。差し戻した回は件の code のうち強いほう（`POST_VIOLATION` が
`POST_TICKET_SCOPE` より先）で、混ざった回は内訳を `detail` に足す。前から在った変更だけを知らせた回は、`decision` が
`allow` のまま `code` を `POST_PREEXISTING` にする（付録 A）。

### 7.4 ターンの基準とユーザへの報告

`UserPromptSubmit` で、そのとき保護領域にある変更と、ツリーごとの HEAD を
`state/<セッション>.turn.json` に記録する。`Stop` で、その基準に無い違反だけを `systemMessage` で
ユーザへ報告し、戻す手順を 1 件ずつ添える。記録した HEAD からの差分も見るので、保護領域を汚してからコミットしたぶんも出る。
数えるのはそのツリーが積んだコミットだけ（`--first-parent --no-merges`）。基準を持たないツリー（ターンの途中で切ったもの）は、記録済みの他のツリーの HEAD との分岐点（merge-base）から数える。分岐点も取れないものは数えず、数えていないことを 1 行で言う。
チケットの置き場は外す。直接作業の記録（`side_by_side yes`）が有効なメインのチェックアウトの変更は、「出所不明の変更（ユーザか別のセッションの可能性）」として報告し、判定の記録の `detail` に件数（`side-by-side N`）を残す。
戻さない。`enable` と `dry-run` で同じように報告する（`disable` はイベントそのものが走らず、
記録に `mode-disabled` が残る）。基準が無ければ何も報告せず、記録に `no-turn-baseline` を残す（REQ-PST-06、REQ-PST-07）。

ユーザの発言で始まるターンでは、その時点の変更を、呼び出しごとのチェックが使う報告済みの記録にも足す。起動時の基準
（7.2）は 1 度しか取らないので、足さないと、セッションの途中でユーザが `deny` の場所を直したぶんが次のツール呼び出しの
変更に見えて、コミット済みの内容へ戻される。起動時の基準が取れているセッションにだけ足す。バックグラウンド作業の完了通知
（`prompt` に `<task-notification>` が含まれる）も `UserPromptSubmit` を起こすが、その間に動いたプロセスの変更は
ユーザの変更と区別できない。前のターンの終わりに動かしている作業が残っていたとき（8.3）も同じ。どちらも足さない。
ターンの基準（`turn.json`）は、足す・足さないに関わらず取り直す。

報告済みの記録の鍵は種類とパスだけなので、足した変更のうえにエージェントが同じファイルを書き換えても、
鍵では見分けられない。足すときに中身の指紋（sha256）を `state/<セッション>.accepted.json` に鍵ごとに持ち、
指紋が違えば新しい変更として扱う。ただし戻さない。戻す先のコミット済みの内容は、ユーザが足させた編集より
古く、戻すとその編集まで消える。報告には `not-restored` の理由として書く。言ったあとは今の指紋を足し直し、
同じ変更を呼び出しのたびに言わない。

呼び出しごとの報告はモデルへ、ターンの終わりの報告はユーザへ届く。

ターンの終わりの記録も、報告した回は `decision` を `deny`、`code` を件の code（上と同じ選び方）にする。`detail` は
上書きせずに足す（読めなかったルールファイル、`uncounted`、混ざった code の内訳）。同じ Stop で `finish` の促しか
`match: Stop` のルールが止めた回は、止めた促しが記録の `decision`・`code`・`rules` を持ち、報告の `code` と `rules` は
`detail` に `report <code> <id,…>` で残る（付録 B）。

同じ報告に、このセッションで同じ理由の拒否が N 回に達した呼び出し（6.4）を並べる。拒否の文面はモデルにしか
届かないので、言い換えて打ち直しを繰り返しているかもしれないことをユーザにも言う。言った回数を記録に残し、増えるまで繰り返さない。

### 7.5 自動復元

`CCNAVI_RESTORE_IF_DENY` が `enable`（既定）のとき、新しく現れた違反のうち、ルールが `deny` と
宣言した場所のものだけを戻す。`ask` と承認済みチケットの範囲外は、報告はするが戻さない
（報告する範囲 `post_findings._guarding` より戻す範囲 `post._restorable` が狭い）。中身が変わった・
消えたものは `git restore --staged --worktree`、現れたものは消さずに
`state/aside/<日時>/<path>` へ退避し、退避先を報告に載せる（索引にあれば先に `git rm --cached`）。
ただし、直接作業の記録が `side_by_side yes` で有効なメインのチェックアウト（作業ワークツリーが在り、同じ名前のブランチを開いている間）の変更は、`enable` でも戻さず報告だけにする。横で作業する指定が無い別のプロジェクトと作業ワークツリーの変更、自己防衛の対象は、今までどおり戻す。ワークスペース自身は、ワークスペース自身のリポジトリが横で作業する指定を持つときだけ戻さない。
`dry-run` は戻す代わりに、報告に `would-restore` の行を足す。`disable` は戻さず、その行も出さない。
戻す先はコミット済みの内容なので、保護領域を汚した未コミットの変更は失われる。
戻さなかったもの（`ask` と範囲外）は記録に入るので、呼び出しごとの報告はセッションで 1 度きりになり、その後は
ターンの終わりの報告でユーザに見せる。

### 7.6 見えないもの

| 見えない | なぜ |
|---|---|
| `.gitignore` に入っているファイル | `git status` に出ない |
| git の作業ツリーの外 | 実行後チェックはリポジトリの中だけを見る |
| この呼び出しが触っていない別のツリー（プロジェクト・ワークツリー） | 見るのはワークスペースルートと触ったツリー。子のワークツリーはサブエージェントの終了時に基準点からの差分を見る（9.12） |
| 失敗したツール呼び出しの副作用 | `PostToolUse` は成功した呼び出しの後にしか走らない |
| `Read` `Grep` `Glob` `WebFetch` `WebSearch` の直後 | 次の書きうるツールの直後に確かめる（遅れであって見落としではない。7.1） |

呼び出しごとに見るのはワークスペースルートと、この呼び出しの行き先（Bash は cwd）が属するツリーだけ。ターンの区切り（`UserPromptSubmit` と `Stop`）では全部のツリーを見る。
