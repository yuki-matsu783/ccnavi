# モジュール構成

`src/ccnavi/` のサブパッケージと、その中のモジュールの役割のまとまりを書く。
ファイル 1 本ごとの役割は、そのファイルの先頭の説明（docstring）が持つ。ここには写さない。ファイルを足す・名前を変える・役割が動くたびに、この表を直さなくて済ませるため。
サブパッケージの層（読む向き）は、下の表の上から下で、`tests/core/test_module_layers.py` が import の向きを見る。
リポジトリのトップレベルの置き場は [development.md](../development.md) にある。

## サブパッケージ

| 場所 | 役割 | 読むもの |
|---|---|---|
| `src/ccnavi/__main__.py` | 入口。標準入出力を整えて `entry/cli.py` の `run` を呼ぶだけ | `entry` |
| `src/ccnavi/infra/` | 土台。ファイル・git・パス照合・hook の入出力・設定・シェルの読み・ワークツリー | どれも読まない |
| `src/ccnavi/records/` | 記録。伏せ字・判定の記録・診断ログ・後始末・拒否や失敗の数え・学びの蓄積 | `infra` |
| `src/ccnavi/policy/` | ルール。読み込み・照合・組み込み・レイヤーの合成・自己防衛・文脈ファイル | `infra`、`records` |
| `src/ccnavi/tickets/` | チケット。置き場、合意の手続き、承認・レビュー済みの判定、フェーズ、リスク、操作 | `infra`、`records`、`policy` |
| `src/ccnavi/hook/` | hook の判定。実行前チェック・文面・実行後チェック・イベント・サブエージェント・文書の検索 | `infra`、`records`、`policy`、`tickets` |
| `src/ccnavi/entry/` | 入口。CLI・診断・lint・提案・版 | 下の全部。どこからも読まれない |

同じサブパッケージの中の読む順（段）は、サブパッケージだけでは言えないので、テストの段の表が持つ。モジュールを足したら、その表に段を足す。

## infra

土台。どのサブパッケージも読まない。

| まとまり | 役割 |
|---|---|
| hook の入出力・設定・モード | stdin の payload の解釈と応答の組み立て、環境と設定ファイルからの設定解決、enable / dry-run / disable の 3 値と終了コード |
| パスと名前の比較 | 大文字小文字だけが違う名前を同じものとして扱う鍵（`pathcase`）、glob から正規表現への翻訳。パスと名前を比べるときは、必ず `pathcase` を通す。`os.path.normcase` は単独で使わない。返すのは比べる文字列で、ファイルを開く表記には使わない |
| シェルの読み（`shellread*`） | コマンド文字列のうち実際に実行される部分の切り出し。走査、語の見分け、`cd` で移った先の追跡に分けてある |
| ファイルと YAML | 読み書きの型（`fsio`。state の記録・マーカー・承認済みチケット・下書きは全部これを通る）、safe な YAML の読み手（`yamlread`。libyaml があれば C で読み、結果が分かれうる文書と深い入れ子は純 Python に回す） |
| git とワークツリー | git を 1 回起動する（`gitcmd`。期限つきの起動は期限を過ぎてから起動しない）、作業ツリーの変更を git から読む、ワークツリーの特定、直接作業の記録を読む（書かない） |
| 機械の語 | `<os>-<arch>`（`platformtag`）。組み立ての目印と、振り分けの sh が起動する実体の探し方 |

## records

| まとまり | 役割 |
|---|---|
| 記録 | 1 行 1 件の追記記録、診断ログ（`logs/diag/<出どころ>.log`）、記録に残す文字列から秘密の形をした部分を伏せる処理 |
| 後始末 | 記録と state のローテート、古い記録と終わったセッションの記録の削除 |
| 数え | ターンの終わりに残っていた作業、ツール呼び出しの失敗や拒否の連続、同じルールの繰り返し。判定は変えない |
| Stop の AI 判定（`stop*`） | 判定計画・試行・結果の検証と最終分類、評価の集計、propose の操作実績 |
| 学びの蓄積の wiki（`wiki*`） | パターン・採否の記録の読み取り。作業ツリーか git のオブジェクトから読む |

## policy

| まとまり | 役割 |
|---|---|
| ルールの読み込みと照合 | ルールファイルの読み込みと検証、文の差し込み、検査（`--lint`・保護対象の下書きの取り込み・提案の候補の検査が呼ぶ）、ツールの呼び出しからルールを当てる文字列を選ぶ、この呼び出しに当てるルール集合を決める（ワークスペース・プロジェクト・その和） |
| 組み込みの既定 | ルールファイルを読めないときの組み込み既定 |
| モデルへ渡す文 | 当たったルールがモデルへ渡す文（additionalContext）。ファイルの本文と once の記録 |
| 自己防衛（`selfguard*`） | ccnavi 自身の設定ファイルと実行ファイルのバックアップと復元、守る対象の一覧、守る対象へのシェルからの書き込みを止める組み込みのルール |

## tickets

| まとまり | 役割 |
|---|---|
| チケットの形と読み込み（`ticket*`） | 書式の定数・状態の名前・範囲の項・計画の項、識別子とブランチ名の規則、範囲を当てない置き場、同じ識別子のまとめ方、状態の置き場を守る組み込みのルール、スクリプトが書く欄の書き換え |
| 承認済みチケットの置き場と操作（`approval*`・`oplog`・`manual_settle`・`standing`） | 読み込み・走査・提案の集め方、承認・欄の書き換え・閉じる・レビューへ送る、フェーズとマーカー、構造の検査、親子の立ち位置（正とする側を親のブランチに固定する）、ホストへの送信の段階の記録 |
| 合意（`agree*`） | 承認の対象を集めて `--preview` / `--verify` に答え、書き込みを並べて置き場へ動かす。候補と検査、画面の文面、承認の対象の指紋 |
| 判定のコア（`core*`） | 承認・レビュー済みの判定。入口の `core.py` は名前を束ね直すだけで、`entry/cli.py` と Chrome 拡張（Pyodide）はここを引く。共通部分、手元の承認、レビュー済みの判定に分けてある |
| フェーズ・計画・リスク | フェーズの終わりと HITL ポイント、フェーズ定義（`phases.yml`）の読み込み、範囲の当て方、計画の番号の振り直し、計画の待ち方、親の提案の雛形と形式検査、実績で測るリスク |
| テンプレートとフロー | 作業・レビュー計画のテンプレートの読み込み・下書き・使う側、子チケットのフロー（置き場・形の検査・文面の整え方・描き方） |
| レビュー（`review*`） | 依頼と確認、sh との契約の JSON の形、残った指摘の行き先の決定、親を閉じる |
| 状態を動かす操作（`ops*`） | `ticket start / finish / cancel / record-risk`、動かしてよいかの検査、Stop で打ち忘れや道の途中を見つけて促す判定 |
| 着手の前と片付け | 共通レイヤー・工程スキルのミラー、閉じた親子の退避、ワークツリーとブランチの片付け、終わっていない integrate の記録、直接作業の取り込み先 |
| write-and-push | sh が聞くこと。親子のチケットが対象か、置き場の変更の分け方、合流の前に聞くこと |
| 学び（`learning*`・`consolidate`） | 気づきの記録・受信箱・判定記録の要約、処理すべきものの判定、SessionStart の通知、統合の子を作る |
| そのほか | ユーザだけが打つ操作の表（`user_only`。hook の止めと端末要求が引く正本）、誰がどの経路で動かしたか（`via`）、保護対象の下書きの取り込み、ブランチの探索、セッション開始で示す一覧と却下された要求 |

## hook

| まとまり | 役割 |
|---|---|
| 判定の中核 | イベントごとの手順（`events`。1 回の起動で何が起きるかはここを上から読む）、実行前チェック（`judge`）、判定に添える文面と理由コード、判定に達せなかったときに通してよい呼び出しか（`failsafe`。設定もルールも読まずに答える） |
| 実行後チェック（`post*`） | 作業ツリーの読み取り、前からあった変更の記録、復元、変わったファイルを守る場所とチケットの範囲に当てる、差し戻しの文 |
| 実行前に止める形 | サブエージェントが Bash から親のワークツリーへ書き込む形、Bash からワークスペースルート直下へ書く形（Write / Edit と同じ決まりに当てる。`rootwrite`）、保護済みの sh を呼ぶ形のうち止めるもの |
| サブエージェント | SubagentStart / SubagentStop、終了結果の記録、編集するものか読み取り専用かの見分け、起動ツールの PreToolUse での担当の決定、子 1 本の担当の案内 |
| セッション開始 | 作業の決まり（`.ccnavi/CCNAVI.md`）の条件と差し込み、プロジェクトのスキルの目録、文書の索引（`docsearch*`。索引を組む、問いに答える） |
| そのほか | 親の提案を手書きしたときの書式の案内、Stop の AI 判定の判定役の呼び出しの見分け |

## entry

| まとまり | 役割 |
|---|---|
| CLI（`cli*`） | 1 回の起動の入口。標準入出力とコマンドラインを判定や各コマンドへ振り分け、ワークスペースルートを見つける。`--help` の本文、引数の読み分け、サブコマンドごとの入口 |
| lint（`lint*`） | 設定とルールの検証。置き場・レイヤー・テンプレート・チケット・ブランチ・直接作業・wiki ごとに分けてある |
| 診断（`diagnose*`） | 判定を実行せずに試す `--test` と `--explain`。名前を引き受ける入口と、試す・説明する・ボードの中身・共有する部品に分けてある |
| そのほか | sh がチケットについて聞くこと（読むだけ）、チケットの状態の表示、`--suggest`、`--version` |
