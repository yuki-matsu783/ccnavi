### 11.8 保護済みスクリプトと案内

sh はワークスペースにしかなく、プロジェクトの中に `cwd` があると `sh .ccnavi/scripts/ccnavi-git.sh` は見つからない。
Bash ツールの環境に `CLAUDE_PROJECT_DIR` は来ない（付録 C）。だから拒否の文面が案内するパスは、ルールファイルの `message` に `{root}` で書く。
`{root}` はモデルへ渡すときにワークスペースルートの絶対パスへ置き換わる（書いた表記は `--explain` に残る。4）。
自身の層とプロジェクトの層のルールでも、置き換わる先はワークスペースルート。重複の判定（11.4）も置き換えた後の欄で比べるので、
共通層とプロジェクトの層に同じ `{root}/...` を書いた定義は重複として一致する。

フェーズの種類と配点の読み込みは `{root}` を置き換えない（書いてもそのまま残る）。`script:` は 11.4.2 の解決先で決まる。

git のラッパースクリプトの記録はワークスペースの `logs/<プロジェクト>/` に書く。ラッパースクリプトは `cwd` の git で動くので、
プロジェクトの作業はプロジェクトに入ってから始める（CLAUDE.md の運用）。判定はそれに依存しないが、レビューの依頼と確認は `origin` を `cwd` から引く。
