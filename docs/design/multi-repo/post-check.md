### 11.7 実行後チェック

`git status` をツリーごとに起動する。見るのはワークスペースルートと、そのターンで書き込みのあったプロジェクトとワークツリー。
触ったツリーはセッションの記録（`session/<id>.trees`）が既に持っているので、それを使う。基準（ターンの始まり）と
「もう伝えた」の記録はツリーごとに分ける。差し戻しはそのツリーの git で行う。報告にはツリーの名前を頭に付ける。

元リポジトリで見た変更に当てるのは共通レイヤー（ワークスペースルートの 1 本。プロジェクトの `.ccnavi/common/` のミラーは、単体 clone でない限り読まない）+ そのツリーのレイヤーのルールの和、ワークツリーならそのツリーに結び付くチケットの範囲と、
共通レイヤー + 元リポジトリのレイヤー。Bash の和は使わない（行き先が分かっているため）。

承認済みの親のワークツリーの中で、ミラーを配る書き込み（11.12）だけは差し戻さず、報告もしない。中身がワークスペースルートの共通レイヤーと同じものに限る。
