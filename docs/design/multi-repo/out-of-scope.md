### 11.11 見ないもの、入れないもの

- VS Code 拡張の画面のレイヤーへの追従は、拡張の要件（`extensions/vscode/ccnavi-board/docs/requirements/`）が決める。
  ルール管理とリスク管理は、編集する 1 本（共通・ワークスペース・プロジェクト）を切り替え、足し算の表示は実行ファイルの出力を使う。
  フェーズ管理は足し算をしないので、ワークスペースの config とプロジェクトの config だけを開く。
  フェーズ定義は `--project-phases-file` で、その 1 本として検証してから保存する
- `CCNAVI_TICKET_CONTROL` のプロジェクト単位化。この変数はワークスペース単位のつまみで、README の語をその意味に直すだけ
- 統合先ブランチの git オブジェクトから設定を読む形。読むのは checkout されている版だけ
- プロジェクトの `.claude/` を認める形
- `.ccnavi/scripts/` をコアファイルにする形（11.6）。中身のハッシュを突き合わせる形も入れない
- レイヤーが無いことを `--lint` が言う形。このため、レイヤーを消す・レイヤーが入る前のコミットへ `checkout` する、のどちらでも
  そのプロジェクトの deny が痕跡なく消える（「壊す」と error、「消す」と何も言わない、の非対称。未解決）
- プロジェクト A に居るときだけ適用される Bash のルール、`cwd` と `cd` の追跡、引数の語の走査
- 2 段以上の深さに置いたプロジェクト、ワークスペースの外に置いたプロジェクト
- ワークツリーの中に checkout された設定ファイルとスクリプト

受け入れる代償。

- プロジェクトは共通レイヤーの `ask` を `allow` に緩められない（`ask` は `allow` より先に当たる）
- 共通レイヤーの `allow` が全プロジェクトに適用される
- パスを持つツールに他プロジェクトのルールは足さないので「A のルールを B にも」は書けない。要るなら共通レイヤーへ上げる
- ワークツリーで足した `.ccnavi/` の変更は、元リポジトリに入るまで使われない
- `glob` も `regex` もどの機械でも大文字小文字を区別せずに当てるので、`allow` も表記違いに広がる
- レイヤーの数だけ読み込みが増える。1 本 200 行の YAML で数 ms なので期限の中に収まるが、`ms` の欄で見る（11.10）
