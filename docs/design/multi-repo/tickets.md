### 11.5 チケット

チケットのプロジェクトは、提案を置いた場所で決まる（9.2、9.3）。

- 置き場で決まる。プロジェクトの `wip/proposals/` ならその名前、ワークツリーの中ならその元リポジトリ、ワークスペースの `wip/proposals/` なら空。
  走査がそれを入れ、承認済みチケットに残す。frontmatter の `project:` は照合のためで、書かなくてよく、置き場と違えば
  承認しない。承認画面がプロジェクトと提案のパスを出す。ワークスペースの `wip/<名前>/proposals/` は走査されず、
  画面にもボードにも出ない（`--lint` が名指しし、名前が `projects/` に在るなら正しい置き場を案内する）
- 判定は申告を見ない。書き込みは行き先のツリーで判定され、そのツリーに結び付く承認済みチケットの `project:` と
  ツリーの `project` が違えば止める（`DENY_TICKET_PROJECT_MISMATCH`）
- ワークツリーはプロジェクトから切る。親がプロジェクトの中で git のラッパースクリプトの `worktree add` を打ち（ラッパースクリプトは `cwd` の git を使う）、
  `.claude/worktrees/<識別子>` に作る。`ticket start` は、その元リポジトリが承認済みチケットの `project:` と合うことを確かめてから動かす
- 複数のプロジェクトにまたがる依頼は、プロジェクトごとの親に分ける。親どうしの順番と依存は ccnavi が見ず、ユーザが承認と合流の順で決める（12.1）
