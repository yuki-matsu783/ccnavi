### 11.4 ルール

パスを持つツール（Read / Grep / Glob / Write / Edit / NotebookEdit）は共通レイヤー + 行き先のレイヤーの和。行き先は解いた先のパスで、
Grep と Glob が探す場所を省いたときは `cwd`。行き先がプロジェクトに属するならその git プロジェクトルートの `.ccnavi/config/rules.yml`、
ワークスペースのツリー（ワークスペースルートと、そこから切ったワークツリー）なら `<ワークスペースルート>/.ccnavi/config/rules.yml` を足す。
ルールは解いた先の絶対パスに当てるので、プロジェクトのルールに `*/schema/*` と書けば、元リポジトリでもそこから切ったワークツリーでも当たる。
ワークツリーの中に checkout されているレイヤーのファイルは読まない（ユーザが見ていないルールは適用しない）。

パスを持たないツール（Bash / PowerShell / WebFetch / Skill / Agent）は全部の和。共通レイヤー、自身のレイヤー、全プロジェクトのレイヤーをタイプごとに
連結して当てる。`deny` `ask` `allow` の順は変わらない。Bash は `cd` で `cwd` の外に移れ、WebFetch・Skill・Agent は行き先のパスを持たないので、
どのプロジェクトの呼び出しかは決めず、どこに `cwd` があっても同じ判定になる（REQ-MLT-05）。

順は共通レイヤー → 自身のレイヤー → プロジェクトのレイヤー（名前順）。先に当たったルールが文面に載るだけで、判定は同じ。

識別子にはレイヤーの名前を添える。共通レイヤーは裸の `id`、自身のレイヤーは `self:id`、プロジェクトは `<名前>:id`（REQ-MLT-07）。記録の `rules` と
文面の `source` はこの形で出す。

裸の `id` にコロンは書けない。3 本とも、書いた `id`（`phases` の鍵、配点の項目名を含む）にコロンがあれば error にして読み込みから落とす。
接頭辞はレイヤーを足す側だけが付ける。

レイヤーの名前に `common` と `self` を予約する。この名前のプロジェクト（`casefold` で比べ、`projects/Self/` も同じ）はレイヤーとして数えず、
`--lint` が error で名指しし、`--agree` はその `project:` を承認しない。
予約名のプロジェクトへの書き込みは共通レイヤーだけで判定し、ワークスペース自身のレイヤーでは判定しない（そうすると、ワークスペースのレイヤーの広い `allow` で通る）。
予約の判断は 1 か所に置き、レイヤーを数える側と行き先のレイヤーを引く側が同じ答えを引く。

重複は後ろを捨てる。裸の `id` が同じで、`{root}` を置き換えたあとの全欄（`match` / `glob` / `regex` / `message` /
`additionalContext*` / `additionalContext*File` / タイプ）が一致する定義は、後ろのレイヤーのものを捨てる。`--lint` が
info で言い、`--explain` は残った 1 本だけ出す。全部の和でも同じ。

同 `id` で中身が違うとき、ルールは両方適用され、`--lint` が warn で言う。`allow` はパスを持つツールでは行き先の 1 レイヤーにしか足さないので
そのツリーの中だけで済むが、パスを持たないツールでは他のプロジェクトの作業にも適用される。配点の項目も両方を数える（11.4.2）。
フェーズ定義は扱いが違う（11.4.1）。

`glob` も `regex` も、どの機械でも大文字小文字を区別しない。チケットの範囲、フェーズ定義とリスクの配点の `scope`、
組み込みの保護（8.2）のパス、コマンドの名前も同じ規則で当てる。区別が要る `regex` は、区別したい部分だけ `(?-i:...)` で囲む。
否定の文字クラス（`[^c]` など）を持つルールは、区別しないと除外の側が広がるのでそこを囲む。

Grep と Glob は、探し始める場所でレイヤーを選び、ルールもその場所のパスに当てる。探す範囲の中身は見ない。`*/secrets*` のようなルールは
探し始める場所のパスに `secrets` が無ければ当たらない。レイヤーの選び方で差が出るのは、パスによらず当たる広いルール（`match: Grep`・`glob: "*"` など）だけ。

読めないレイヤーは空として扱う。そのツリーを行き先にするパスを持つツールは共通レイヤーだけで判定し、全部の和からもそのレイヤーを外す。
記録の `fallback` にレイヤーの名前を残し、`--lint` が error で言う。組み込みの既定には戻さない（11.2）。

代償は 11.11 の「受け入れる代償」。

#### 11.4.1 フェーズ定義の合成

どのレイヤーを足すかは親の承認済みチケットの `project:` で決まる。値は提案を置いた場所が決め（11.5）、子も親と同じ値を持つ。
空ならワークスペース自身のレイヤー。ワークツリーの元リポジトリが `project:` と合うことは着手時に確かめてある（REQ-MLT-13）。

`id` ごとに合成する。共通レイヤーのフェーズ定義と、そのレイヤーのフェーズ定義を 1 つの集合に並べる。同 `id` で中身が違えば error。表示名（`title`）の重なりも
レイヤーをまたいで error。同 `id` で全欄が一致するものは重複として後ろを捨て、info で言う。

`overlap` / `requires` が指す先は合成後の集合で確かめる。レイヤー 1 本を読むときは参照を確かめず、合成したあとで、そのレイヤーが新しく足したフェーズ定義の
参照だけを当てる（レイヤーから共通レイヤーのフェーズ定義を指すのは正しい形）。

衝突したレイヤーは空として扱う。error があるとき、判定はそのレイヤーを空として扱い（共通レイヤーのフェーズ定義だけで進む）、`--lint` が error で言う。
親の `plan:` がそのレイヤーのフェーズ定義を指していれば「フェーズ定義が無い」で承認が止まる。記録の `fallback` にレイヤーの名前を残すのは配点の側だけ（11.4.2）。

`id` は裸のまま鍵にする。`plan:` と `feedback:` とマーカーは裸の `id` でフェーズ定義を指し、レイヤーの名前は `--explain` と記録のレイヤーの欄に出す。
接頭辞を付けないのは、`id` が合成の鍵で、同じ名前で違う中身を error にするため。

`scope` はワークツリーのルートからの相対。`inherit` も同じ。`{root}` はここでは使わない。

#### 11.4.2 リスクの配点の合成

どのレイヤーを足すかはフェーズ定義と同じ。子を閉じるときに、親の承認済みチケットの `project:` のレイヤーを共通レイヤーに足す。

項目は連結し、境目の点はキーごとに小さいほうを採る。共通レイヤーの項目の後ろにレイヤーの項目を並べる。全欄一致なら重複として後ろを捨てる（info）。
`levels` は `medium` / `high` / `critical` のそれぞれで、書かれた鍵だけが参加し、そのうち小さいほうを採る。どのレイヤーも書いていない鍵は既定（20 / 40 / 70）。
合成後に `medium <= high <= critical` でなければ error。

同じ項目かは全欄で比べ、`script:` は書いたパスでなく置き場からの相対と中身で比べる（着手でコピーした配点（11.12）を 2 重に数えないため）。

同 `id` で中身が違う項目は両方を数え、`--lint` は warn。後ろのレイヤーの項目は `<レイヤー>:<id>`（例 `lib:big-diff`）と表記し、記録の `hits`、
`<子>.judge.json`、`record-risk` の項目名、問いの見出しはその名前で出す。レイヤーを空にすると点が下がるので空にしない。

`levels` の順が崩れたレイヤーは空として扱う。`fallback` にレイヤーの名前を残し、閉じるときの出力が言い、`--lint` は error。共通レイヤーだけで測るので、点は小さくなりうる。

`script:` の解決先はレイヤーごとに違い、たがいに指せない。

| レイヤー | `script:` に書けるパス | 解決の基準 |
|---|---|---|
| 共通レイヤー | `.ccnavi/common/scripts/...` | ワークスペースルート |
| 自身のレイヤー | `.ccnavi/scripts/...` | ワークスペースルート |
| プロジェクトのレイヤー | `.ccnavi/scripts/...`（同上） | そのプロジェクトの git プロジェクトルート |

共通レイヤーから `.ccnavi/scripts/` を、レイヤーから `.ccnavi/common/scripts/` を指す定義は読み込みで error。指す先が git プロジェクトルートに無ければ
`--lint` が error（走らせるときは「測れなかった」でその項目の点を加える）。ワークツリーの中のスクリプトは読まない。`cwd` は
子のワークツリーで、環境変数（`CCNAVI_BASE_SHA` 等）も同じ。プロジェクトの `.ccnavi/` はそのプロジェクトだけで閉じる。
