### 11.6 守るもの

コアファイル（8。ルールファイルの外で、組み込みで、バックアップと復元まで持つ対象）は次のとおり。

| 対象 | 場所 |
|---|---|
| hook の登録 | `.claude/settings.json`、`.claude/settings.local.json` |
| 共通レイヤーのファイル | `<root>/.ccnavi/common/{rules,phases,risks}.yml`（`phases.yml` は置けない（11.4.1）が、置かれても守る） |
| 共通レイヤーのミラー | `projects/<名前>/.ccnavi/common/{rules,phases,risks}.yml`（11.12。単体 clone では共通レイヤーとして読まれる） |
| 自身のレイヤーの 3 本 | `<ワークスペースルート>/.ccnavi/config/{rules,phases,risks}.yml` |
| プロジェクトのレイヤーの 3 本 | `projects/<名前>/.ccnavi/config/{rules,phases,risks}.yml` |
| 実行ファイル | `CCNAVI_BIN_PATH`（振り分けの sh）と、sh が起動する実体（8.2） |
| ワークツリー側の設定 | 上の各ファイルのうち追跡されているものについて、**その元リポジトリから切った**ワークツリーが持つ同じファイル |

ファイル単位で、無いものは対象から外れる（REQ-SLF-03）。Write / Edit の拒否、シェルからの書き込みの拒否、バックアップと復元の 3 つとも、
`rules.yml` と同じものを掛ける。3 本とも判定の中身そのもので、書けるとエージェントが自分の判定を緩められる。

予約名のプロジェクトの 3 本も守る。判定のレイヤーとしては数えない（11.4）が、ファイルはバックアップして戻す。バックアップの名前はレイヤーの種別で決め、レイヤーの名前の表記では決めない
（レイヤーの名前で比べると `projects/common/` の 3 本が共通レイヤーと同じ名前になり、バックアップと復元の対象から外れる）。

共通レイヤーのファイルは、フェーズ定義と配点もコアに入れる。シェルからの書き込みは組み込みで止め、書けても戻す。名指しのツールから共通レイヤーのファイルを守るぶんも組み込み
（`builtin-guard-common-layer`）で持つ（ルールの 1 行に任せると、書き換えたルールファイルのもとで通る）。組み込みで名指しのツールを止めるのは、
実行ファイル・ccnavi ディレクトリ・共通レイヤーの 3 つ。hook の登録（`.claude/settings*.json`）はルールの `deny` に任せる。

プロジェクトから切ったワークツリー側の設定も足す。ワークツリーは元リポジトリを添えて列挙し、ワークツリー側の設定の相対を元リポジトリから
組む（REQ-MLT-08）。

ミラーを配る書き込み（11.12）だけは、実行後チェックとバックアップと復元が戻さない。外す条件は 11.12 のとおり（承認済みの親のワークツリーの中で、パスの途中にシンボリックリンクが無く、
中身がワークスペースルートの共通レイヤーと同じ）。配る前の書き込みの記録は持たない。

`.ccnavi/scripts/` はコアに入れない。スクリプトは配点の `script:` で参照されて初めて使われ、配点がコアで守られていれば新しい参照は足せない。
既に参照されているスクリプトの書き換えは、次の組み込み deny と `CCNAVI_RESTORE_IF_DENY` で止めて戻す。
コアにすると数の定まらないファイルを呼び出しのたびに比べることになり、実行前チェックの期限を圧迫する。

ccnavi ディレクトリの全体に組み込みの deny を掛ける。`match: Write|Edit|NotebookEdit`、`glob: */.ccnavi/*` の 1 本を `deny` の先頭に足す
（`builtin-guard-project-home`。パスは固定の `.ccnavi` で組む）。シェルからの書き込みも同じ 1 本
（`builtin-guard-setting-files`）で止める。3 本に絞らないのは、配点が呼ぶスクリプトも含めるため。

シェルの側のパスは「区切りが続くか、そこで終わる」形 `\.ccnavi(?:[\\/ \x00\x01]|$)` で書き、`rm -rf .ccnavi` と
`mv .ccnavi .ccnavi.bak` も止める。語の中の目印 `\x01` も終わりに数えるので、`rm ".ccnavi x"` も止まる（別名を指すので誤検知）。
`.claude` の側も同じ形に揃えるが、`.claude` の下は名前を絞ってあるので（`worktrees/` は守る対象ではない）、そこで終わる形は空白・コマンドの切れ目・
語の中の目印だけで閉じる（区切りを含めるとワークツリーの片付けまで止まる）。場所のパスもコマンドの名前（`rm` / `cp`）も、大文字小文字を区別せずに当てる。

元と行き先がある `cp` `ln` `install` は、行き先の側だけで当てる。行き先は GNU の読み方で決める。`-t <dir>` /
`--target-directory=<dir>`（まとめた短いオプション `-vt`、値を続けた `-t.ccnavi`、頭だけの `--target`、空白で値を渡す形も同じ）があればその値、
無ければ選択肢でない最後の引数。最後の引数のあとに回した選択肢（`cp /tmp/x .ccnavi/common/rules.yml -f`・`-S .bak`・`--`）は飛ばし、
文字列の終わり・コマンドの切れ目・後ろのリダイレクトまでを引数のリストとして読む。値を取る選択肢の値に出た `-t`（`-S -t`・`-Svt`）と
`--` のあとの `-t` は行き先を名指ししないので、そのときも最後の引数を見る。
`cp .ccnavi/common/rules.yml /tmp/backup.yml` や `cp -t /tmp/out .ccnavi/common/rules.yml` のように守る場所が元の側に出ただけの形は
読むだけなので組み込みの保護では止めず、通すかどうかはルールに任せる。`cp /tmp/x .ccnavi && echo` や `cp /tmp/x .ccnavi > /dev/null` のように
後ろに何か続けた形、`sudo` / `env` の後ろ（shellread が実行役のコマンドを外した層）、`cd` で移った先から見た表記も止める。
動かした ccnavi ディレクトリ・共通レイヤーの 3 本・実行ファイルの表記は、書き込み用・最後の引数用・`-t` の値用に分けて足す
（`selfguard_shell.shell_write_regex`）。共通レイヤーの 3 本はファイルなので、ディレクトリを取る `-t` の値には足さない。
当て方は組み込みのルールの regex 1 本のまま（`rules._build` を通る）で、語の割り方が 1 通りに決まる形に書いてある。

行き先を、守るものが入っているディレクトリにした形（`cp /tmp/decisions.jsonl logs/`・`mv /tmp/decisions.jsonl logs/`・
`cp -t logs /tmp/decisions.jsonl`）は、行き先の表記に守る名前が出ないので、元の名前で見る（`selfguard_shell.holder_regex`。`mv` も含める）。
止めるのは、元の側に守る名前の語（後ろの区切りは問わない）か、名前の決まらない語（グロブ・`$`・逆引用・ブレース、
`.` と `..` で終わる元）があるか、`-T` / `--no-target-directory` があるときだけ。`cp /tmp/notes.txt logs/` のように別の名前を
置くだけの形は止めない（`logs/` の下の git のラッパースクリプトの記録は守らない）。組を作る先は、`logs/` の中の記録と state の置き場、
実行ファイルの末尾 2 要素（振り分けの sh なら組み立ての置き場の `bin/` とその親も）、動かした ccnavi ディレクトリと
ワークスペースルートの下に置いた共通レイヤーの 3 本（ルートからの相対の各段）、ルートの外に置いた共通レイヤーの 3 本（すぐ上のディレクトリ）、
そしてワークスペースルート（`.` とルートの絶対パスを行き先に、`.ccnavi` `.claude` `logs` と上で足したいちばん上の名前）。
`.claude/` `.ccnavi/` `logs/state/` そのものを行き先にした形は、名前を問わずに上の場所の表記で止まる。
元の語はリストのどこにあってもよいので、最初に見つかった元の語で決め打ちし（後戻りしない括り `(?>...)`）、
当たらない長いリストでも照合の手数が語の数に比例する範囲に収める。
`mv` `rm` `tee` `dd` `truncate` `patch` `shred` `sed -i` とリダイレクトは名指ししたところを書くので、元と行き先を分けずに当てる。

deny なので、実行後チェックが保護領域に数え、`CCNAVI_RESTORE_IF_DENY` が git の変更一覧に出た差分を戻す。`.ccnavi/scripts/` の
追跡済みファイルへの書き換えは、Write / Edit とシェルの両方で止まり、止められずに書かれても戻す。

ワークツリーの中の `.ccnavi/` の新規ファイルは拾わない。元リポジトリの配点から参照されていないので、統合されて元リポジトリに checkout されるまで使われない。
`--lint` が「ワークツリーの `.ccnavi/` に元リポジトリに無いファイルがある」を warn で言う。
承認済みの領域（承認済みチケット・マーカー・子の記録・フロー）の下は数えない（親のワークツリーの版が判定とフローの案内に読まれるため）。

前提として、ユーザはプロジェクトに checkout されている版を信頼している。ccnavi が守るのは
「checkout されている版が、セッションの中で書き換えられない」ことまでで、そこへ入る前の経路（ブランチ、マージリクエスト、レビュー）は人の運用に置く。
