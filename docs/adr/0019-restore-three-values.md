# ADR-0019: 戻す働きは 3 値にし、新しく現れたファイルは消さず退避する

状態: 採用

## 状況

当初の設計では、自動復元の設定は `off` / `warn` / `auto` の 3 値で、`warn` は「通知して復元は
AI にさせる」、`auto` は新規ファイルを削除する、だった。実装の初期には `CCNAVI_RESTORE` を
`off` / `auto` の 2 値にしていた。その後 `CCNAVI_RESTORE_IF_DENY` を 3 値にしたが、
`post.py` は `enable` しか見ておらず、`dry-run` と `disable` が同じ挙動になっていた。
コアファイル側は `would-restore` を出していたので、片方だけ抜けていた。

## 決定

`CCNAVI_RESTORE_IF_DENY` と `CCNAVI_GUARD_CORE_FILES` は `enable` / `dry-run` / `disable` の 3 値。
`dry-run` は戻さず、報告に `would-restore` の行を足して、本番なら何をしていたかを言う。
`disable` は戻さず、その行も出さない。`CCNAVI_MODE=dry-run` のときは、こちらが `enable` でも
`dry-run` として振る舞う。

現れたファイルは消さずに `.claude/ccnavi/state/aside/<日時>/` へ退避し、退避先を報告に載せる。

## 理由

設計の `warn` は「戻す手順を示す」ことと同じで、それは REQ-PST-03 で必須なので、`off` でも
同じことをする。同じ挙動に 2 つ名前を付けない。

2 値（真偽）に落とす案も出たが、モードと掛けた表（requirements.md §2.2）の「ブロック × 予行」が
書けなくなる。判定は本番のまま戻しだけを試す状態で、対象がプロジェクトの宣言次第で動く
ルール由来の保護では、そこがいちばん要る。宣言の書き損じがそのまま「頼んでいないファイル操作」に
なるので、何が戻るのかを戻される前に見せる段が要る。無効と予行を見分けられることも同じ理由で
要る。何も出さない側と「戻すはずだった」と言う側が同じ文面になるなら、3 値は 2 値でしかない。

消さないのは、消すと「保護領域を汚した実行」と「出力先を間違えただけで中身は要るもの」を、
戻す側が見分けられないまま片方に決めることになるから。取り返しの付かない操作を止めるための
道具が、自分だけは取り返しの付かない操作をするのはおかしい。

## 得たもの・失ったもの

- 得たもの: 宣言を書いた直後に、何が戻るのかを戻される前に確かめられる
- 失ったもの: 戻す先はコミット済みの内容になる。宣言した保護領域を汚した未コミットの変更は、
  戻すと失われる。守りたいなら `disable` にするか、宣言を狭める
- 失ったもの: 退避先が溜まる。掃除は人

## 採らなかった案

- 2 値。上のとおり
- 新規ファイルを削除する。上のとおり
