# ADR-0165: ターン中かどうかを、セッションごとの印のファイルで残す

状態: 採用

## 状況

ユーザの変更を受け入れるのは次の発言だけで（自己防衛の戻す側）、ターンの間に設定ファイルや `deny` の場所を直すと、次のツール呼び出しの実行後チェックに戻されることがある。
VS Code 拡張は、ルール・フェーズ・配点・テンプレートの保存を、作業中のチケットがあるときだけ止めていた。チケットに結び付かない直接作業の最中は、保存しても戻されうるのに、拡張には知る手立てが無かった。
ターン中かを示す記録は無く、一番近い `busy` は、ターンの終わりに動かしている作業が残っていたかだけを持つ。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| セッションごとに `state/turn-<セッション>.json` を置く。ユーザの発言とバックグラウンド作業の完了通知で置き、メインエージェントの `Stop`・ユーザの中断・起動・再開で消す | 並行するセッションが互いの印を書き換えも消しもしないため。1 本の共有ファイルに全セッションを入れると、読み書きの競合を直すロックが要る | 1 本のファイルにセッションの一覧を持つ（競合） |
| ツール呼び出しでは更新時刻だけを動かし、無い印は作らない | `Stop` の直後に並行して走ったサブエージェントの呼び出しが、消した印を作り直さないため。中身を書き換えないので、書き込みの途中を読まれることもない | 呼び出しのたびに中身を書き直す（印の復活、書き込み回数の増加） |
| 読む側は、更新が 30 分以上無い印と、読めない・形の違う印を数えない。読む側は消さない | 中断や落ちたプロセスは `Stop` を送らない。印が残り続けると、拡張が毎回警告する。30 分は、1 回のツール呼び出し（ビルドなど）より長く取る。短いと、長い呼び出しの最中に警告が消え、一番危ない時間に黙る | `Stop` が来るまで有効（残った印が永遠に警告する）。プロセスの PID を持つ（hook は短命な別プロセスで、Claude Code の PID を payload から取れない） |
| `PostToolUseFailure` の中断（メインエージェントのみ）でも消す | 中断では `Stop` が来ないことがあり、印が 30 分残るため。サブエージェントの中断はターンを終わらせない | 中断を見ない（30 分の誤警告が増える） |
| 拡張は `--explain --json` の `turns` を読み、保存の前に確認を出す。保存は止めない | 保存できても戻されることがある、という事実を保存の前に知らせれば足りるため。ターンが終わるまで保存できなくすると、編集中の内容を使えない | 作業中のチケットと同じに保存を止める（直接作業を邪魔する）。画面に常時出す（各画面の変更が大きい） |
| `busy`（動かしている作業が残るか）とは別のファイルにする | 寿命が違う。`busy` はターンの終わりに書き、次の発言の受け入れの可否に使う。印はターンの間だけ | `busy` に相乗り（意味が混ざる） |

## 得たもの・失ったもの

- ターンの途中のユーザの編集が戻されうることを、拡張が保存の前に伝えられる
- 印の読み書きに失敗すると印が無い側に倒れ、警告が出ないだけになる。保護の動きは変わらない
- 中断で `Stop` も `is_interrupt` も来ない場合（モデルが考えている最中の中断など）は、最大 30 分、ターン中と誤って出る。出し過ぎは確認が 1 回増えるだけで、保存は妨げない
- ツール呼び出しのたびに更新時刻を動かすので、`utime` が 1 回増える
- バックグラウンド作業だけが動いていて、ターンが終わっている間（`busy` が残る間）は、ターン中には数えない。同じように戻されうるが、この印の範囲外で、別途扱う
