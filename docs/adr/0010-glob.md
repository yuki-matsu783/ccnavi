# ADR-0010: ルールの記法は `fnmatch` の glob にする

状態: 採用

## 状況

ルールは「どのツールの、何に当たったら」を文字列の形で書く。`\bgit\s+push\b` のような正規表現は
書きにくいので、書く人が正規表現を書かずに済む記法が要る。

一方で、記法が書いたものに手を加えて当てる（語の切れ目を自動で挟む、部分一致にする）と、
書いたものと当たるものの間に見えない層ができる。語の切れ目をワイルドカードの両隣にも挟むと、
`foo*bar` は `\bfoo\b.*\bbar\b` になり、`foo-bar` には当たるのに `fooXbar` にも `foobar` にも
当たらない。足したつもりで何も止めていないルールは、記法がいちばん防がなければならないもの。

## 決定

探すものは欄 `glob` に書き、意味は標準ライブラリの `fnmatch` そのままにする
（書式の版 1）。文字列全体に当たる。残したのは区切り文字の正規化 1 つだけで、`/` と書けば
`\` にも当たる。書けないものは `regex` に正規表現を書き、両方書いたルールは受け付けない。
先読み・後読み・後方参照は読み込み時に弾く。

## 理由

「書いたものがそのまま当たる」を崩さないため。区切り文字の正規化だけを残すのは、
落とすとルール 1 本の意味が走らせる機械で変わるから。実装は `fnmatch.translate` の出した式の
`/` を置き換えるだけで、文字クラスの中に `/` を書いた `[a/b]` のような形は組み立てに失敗して
読み込み時に落ちる。黙って別の意味になるより落ちるほうがよい。

先読み・後読み・後方参照を弾くのは、書ける範囲を狭く保てばルールがエンジンをまたいでも
同じ意味になるためで、これらが組み合わせ爆発を起こす書き方の入口でもあるため
（ADR-0001）。

## 得たもの・失ったもの

- 得たもの: 書いたものと当たるものの間に見えない層が無い。翻訳後の正規表現を `--test` がそのまま見せる
- 失ったもの: 部分一致は自動で付かない。前後に `*` を自分で書く。`git push *` は
  `cd /repo && git push` に当たらず、`*git push*` なら当たる
- 失ったもの: 語の切れ目も入らない。右側だけなら空白を書いて `*sed *` とすれば `sedate` を
  外せるが、左側は glob では書けない。`*git push*` は `legit push` にも当たり、`* git push*` と
  書くと行頭の `git push` が外れる。左の切れ目が要るルールは `regex` を使う
- 残った誤検知: 空白を含まない 1 語のパターンは、引用の中にあっても当たる。`echo ".env"` は
  `.env` のルールに当たる。塞ぐならルール側に「コマンド位置だけ」「引数だけ」の区別を足すことに
  なり、書式の版が上がる
- 残った取りこぼし: `git -C /repo push` は `*git push*` に当たらない。語の並びをそのまま探すため

## 採らなかった案

- 自前の記法を直して残す。見えない層は残る
- 正規表現だけにする。日常の操作を止めるルールを正規表現を知らずに書けること（REQ-RUL-06）に反する
