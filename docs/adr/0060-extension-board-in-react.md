# ボードの画面を React にし、拡張ホストは中身だけを渡す

状態: 採用

## 状況

VS Code 拡張の 5 つの画面（ボード・ルール設定・リスク管理・フェーズ管理・プロジェクト管理）は、
どれも拡張ホストが HTML を 1 枚の文字列に組み立てて Webview に渡していた。画面の中で動く部分
（絞り込み、列の畳み、承認のオーバーレイの操作）は、テンプレート文字列に埋めた素の JavaScript で、
5 画面あわせて 1,200 行ほどある。ここには型検査が効かない。無い id への参照も、イベントの付け忘れも、
happy-dom で動かすテスト（`*.dom.test.ts`）を書いたところだけで見つかる。

更新のしかたも粗い。監視がファイルの変化を拾うたびに HTML を丸ごと作り直して `webview.html` に
入れ直す。画面はそこで捨てられて作り直されるので、スクロール位置も、開いていた `details` も、
入力中の値も飛ぶ。飛ばないように、絞り込みと畳んだ列は Webview の state に、承認のオーバーレイは
拡張ホストの `PanelState` に、それぞれ逃がしてある。

## 決定

ボードの画面を React にする。拡張ホストが渡すのは「いま何を見せるか」（`core/board-view.ts` の
`BoardData`）だけにして、列とカードの DOM は画面が作る。画面が返すのは人が押した操作
（`BoardMessage`）だけで、判定も実行ファイルの呼び出しもしない（ADR-0035 のまま）。

| 決めたこと | なぜ |
|---|---|
| まずボードだけ。残り 4 画面は今までどおり拡張ホストが HTML を組む | 一度に全部を置き換えると、描画 2,950 行とテスト 4,193 行が同時に動く差分になる。形が良ければ順に移す |
| 画面は束ねて（esbuild）`<script nonce>` に文字列で流し込む | 「外部資源に依存しない 1 枚の HTML」を保てる。`localResourceRoots` は空のままでよく、CSP も nonce だけで済む |
| 2 枚目からは `postMessage` で中身だけ渡す。HTML を入れ直すのは 1 枚目と、裏に回っている間だけ | 監視の更新で画面を捨てない。裏では `retainContextWhenHidden` が偽で画面が捨てられているので、入れ直しておけば表に戻った瞬間に新しい中身が出る |
| 表に戻って作り直された画面は `ready` を送り、いまの中身をもらい直す | 入れてある HTML は少し古いことがある。取りこぼしを画面の側から塞ぐ |
| 画面が組み上がる（`ready`）までは `postMessage` を送らない。開いた直後の絞り込みは、届く経路で渡すまで消費しない | React の受け口は最初の描画の後（`useEffect`）に付く。作り直している最中に送ったものは誰にも届かず、1 度きりの指示（「このプロジェクトで絞って開く」）は消えたきりになる。埋め込みのスクリプトは同期で受け口を付けていたので、この窓は無かった |
| 型は 2 本の tsconfig に分ける（拡張ホストは DOM 無し、画面は Node 無し） | 片方の型がもう片方に混ざると、境界が文書だけのものになる |
| テストは happy-dom のまま。束ねた画面を読み込んで、同じ選択子と同じ `postMessage` を見る | 確かめている中身（CB-T・CB-D の項目）を変えずに移せる。配るものと同じ画面を動かせる |

## 理由

型が効かない 1,200 行のうち、ボードのぶん（196 行）が TypeScript になる。画面の状態（絞り込み・
畳んだ列・承認のオーバーレイ）を「拡張ホストが持って描くたびに渡す」から「画面が持つ」に寄せられ、
更新のたびに画面を捨てなくてよくなる。

## 得たもの・失ったもの

得たもの。

- 画面の中身に型検査と補完が効く。無い id への参照とイベントの付け忘れが、動かす前に分かる
- 監視の更新でスクロール位置も入力中の値も飛ばない（差分で描き直す）
- 「拡張ホストは中身、画面は見せ方」の線が `board-view.ts` の 1 本になり、両側から読める

失ったもの。

- 依存が 2 つ増える（react / react-dom。開発時のみ）。束ねた画面は 239KB で、HTML に流し込む分だけ
  1 枚が重くなる。開くのは 1 度きりなので体感には出ないが、軽くはない
- 画面の作りが 2 通りになる。ボードは React、残り 4 画面は文字列。移し終えるまでは、どちらの作法かを
  ファイルごとに見分ける必要がある
- テストの土台が変わった。React は押した直後に描き直さないので、操作のあとに `await page.settle()` を
  挟む。挟み忘れると「変わっていない」と見える。`settle` 自身も、happy-dom が追わない待ち
  （React のスケジューラが落ちる `setImmediate` / `setTimeout`）を空にするまで回す必要がある
- 拡張ホストと画面のやり取りに、組み上がりの合図（`ready`）という段が 1 つ増えた。1 度きりの指示を
  渡すときは「届いたか」を気にしなければならない

## その後

| いつ | 何 |
|---|---|
| 2 画面目 | プロジェクト管理を移した（issue #85）。`retainContextWhenHidden` が偽でボードと同じ前提なので、`core/screen-host.ts` はそのまま当たった。あわせて束ねを画面の一覧から回す形にし（issue #83）、使い回すぶん（`embedJson`・`webview/initial.ts`・`webview/appearance.ts`）を 1 か所に寄せた。画面に渡す形（`ProjectsPage`）は契約の側（`core/projects-view.ts`）へ移した。判定のファイルに置いたままだと、Webview がそこから `node:path` を読むファイルを辿って型検査が落ちるため |

| 3 画面目 | リスク管理を移した（issue #86 の前半）。`retainContextWhenHidden` が真の画面なので、先に保持する画面の段取りを決めた（ADR-0062、issue #82）。配点の形（`KINDS`・`FactorForm` など）は読み書き（`risk-doc.ts`）から契約（`core/risk-view.ts`）へ移した。画面がそこから `yaml` を辿ると、束ねたものに YAML の解析器が丸ごと入るため |

| 4 画面目 | フェーズ管理を移した（issue #86 の後半）。リスク管理と作りが同じなので、型を当て直す作業になった。違いは 3 つ: 層（自身の層・プロジェクト）はファイルが無くても編集できる（`editable`）、id の重なりだけは画面が保存を止める、並びの欄（`scope` など）は `,` 区切りの文字を欄が持つ（並びに直したものを欄へ戻すと、区切りの直後が打てない） |

残る 1 画面（ルール設定）も `retainContextWhenHidden` が真で、同じ `retainedHost` で移せる（issue #84）。

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| 5 画面を一度に React にする | 描画 2,950 行とテスト 4,193 行が同時に動く。レビューできる大きさにならない |
| React を入れず、埋め込みのスクリプトを別ファイルの TypeScript にして束ねるだけ | 型は効くようになるが、DOM の組み立ては手書きのまま。更新のたびに画面を捨てる形も変わらない |
| 拡張ホストで React を文字列に描き（`react-dom/server`）、画面で hydrate する | テストの書き換えは小さく済むが、更新のたびに HTML を入れ直す形が残るので、React にする利点がほぼ消える |
| 束ねた画面をファイルとして読ませる（`asWebviewUri`） | `localResourceRoots` を開け、CSP に資源の出どころを足すことになる。1 枚に収める今の形のほうが守りが狭い |
