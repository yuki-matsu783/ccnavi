# ADR-0131: 生の git は組み込みでいつも止め、共通レイヤーの見本を外す

状態: 採用

## 状況

ADR-0114 は、生の git の組み込みの止めを「チケット制御が有効で、ワークスペースルートにラッパーがあるとき」に限り、
共通レイヤーの見本 `raw-git` も残した。理由は 2 つだった。

1. ラッパーが無いときに止めると、git を打つ道が 1 つも残らない
2. 文面が「ラッパーを使え」と案内するので、誘導先が無い

しかし、ラッパーが無いときに `git` を案内する文は、組み込みで止まる形を勧めることになる。そこで条件を分けた。
共通レイヤーの見本は、ラッパーの無い配布先で git を止めるための唯一の手段だったが、組み込みで止めれば不要になる。
ccnavi 自身の約束（チケット制御の可否）を守るのは組み込みの役目で、設定に依らない。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 生の git（`builtin-guard-raw-git`）を、チケット制御の有無・ラッパーの有無・共通レイヤーの有無によらず組み込みで止める | ラッパーの可否と設定の状態に依らず、ccnavi の約束が外れないようにする | ラッパーがあるときだけ止める（ADR-0114）。ラッパーが無い配布先で git の止めが消える |
| ラッパーが無いときは文面をユーザに頼む形にし、`git` の形を案内しない | 案内した `git` の形も組み込みで止まるため。`ccnavi-git.sh` も無いので名指ししない | `git` を案内する。止まる形を勧めることになる |
| 共通レイヤーの見本 `raw-git` を削除する | 組み込みと重複し、消しても二重に効く。見本が残ると、設定しだいで組み込みの文面と食い違う | 残す（ADR-0114）。重複を抱えたまま |
| セッション開始の作業の決まりの git の行は、条件 `git_wrapper` でラッパーの有無だけで文を分け、行自体は常に出す | 組み込みが常に止めるので、判定と文が揃う。ラッパーが無いときの文は頼む形になる | 行を出さない。止めるのに決まりを言わない |
| 組み込みの土台の id のうち、ccnavi 自身を守るもの（`builtin-guard-*`、`builtin-ticket-*`、`builtin-script-env`、`builtin-child-push`）以外は `builtin-deny-` で始める | 利用者が見て「ccnavi の保護」と「一般的な危険の止め」を区別できる | 全部を `builtin-guard-` に寄せる（予約の意味が広がりすぎる）。`builtin-` のまま（役割が見えない） |
| 生の git の id を `builtin-guard-raw-git` にする（予約の接頭辞の内側） | ccnavi のラッパーの約束を守る。ルールファイルから同じ id で置き換えられない | `builtin-deny-raw-git`（自身を守るものが deny の名前に紛れる） |

`builtin-read-anything` は allow なので、`builtin-deny-` の対象にしない。

## 得たもの・失ったもの

- 得たもの: ラッパーの無い配布先、共通レイヤーを置かないワークスペースでも、生の git が止まる
- 得たもの: 組み込みの id を見れば、ccnavi の保護か一般的な危険の止めかが分かる
- 失ったもの: **ラッパーが無いワークスペースでは、エージェントは git を一切打てない。** 読み取りの `git status` も止まる。
  ユーザがターミナルで打つ分には影響しない。共通の見本を入れていたワークスペースでは、これまでも同じだった
- 失ったもの: 古い ID（`builtin-recursive-delete` など）で書いた記録・集計は、新しい ID と突き合わせられない

## 採らなかった案

- **共通レイヤーの見本を残す。** 組み込みと重複する。消しても二重に効かないので、残す理由が無い
- **ラッパーが無いときは git を止めない。** 止めない間は、ワークスペースの設定しだいで ccnavi の約束が外れる。ADR-0114 の懸念の本体はこちらだった
