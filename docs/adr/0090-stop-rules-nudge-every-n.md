# ADR-0090: `match: Stop` のルールで、ターンの終わり N 回に 1 度止めて文を渡せるようにする

状態: 採用

## 状況

「作業を何度か区切るごとに振り返らせ、スキルの改善を承認付きで提案させたい」という要望が出た
（2026-09-27。Hermes Agent の、N ターンごとに裏でスキルを見直す仕組みを、人の承認を挟む形で取り入れる）。

`every: N`（ADR-0057）で「N 回に 1 度」は書けるが、ルールが当たるのは `PreToolUse` のツール呼び出しだけで、
数えもツール呼び出しの回数になる。ツール呼び出しは作業の区切りと比例せず、書きかけの途中で届く。

最初は `UserPromptSubmit`（利用者の発言）で数える形で作ったが、利用者と相談して `Stop` に替えた。
発言の時点では何も起きておらず、振り返る材料はターンが終わったところで揃うため。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| ルールの `match` に `Stop` を書ける。メインエージェントのターンの終わりに当たる。当てる文字列は無いので固定の `(stop)` に当て、`glob: "*"` と書く | 作業の区切りを数える単位にする | `UserPromptSubmit` で数える（最初の形）。振り返る材料が揃う前に届き、文脈を先に積む |
| 渡す回（`every` の刻み）にだけ `decision: block` で止め、`reason` を `NUDGE_STOP_RULE: <ルールの文>` にする | `Stop` でモデルに文を届ける経路は、止めてターンを続けさせることしか無い | `systemMessage` に載せる。人にしか届かず、モデルは振り返らない |
| 見るのは `allow` のルールだけ。`deny` / `ask` に書いたもの、`(stop)` に当たらない表記、`every` の無いものは `--lint` が warn | 判定ではなく促し。`every` が無いとターンの終わりのたびに止まる | `deny` に書かせる。止めることが目的ではない |
| 同じ Stop で `finish` の促し（ADR-0087）が止めるなら、そちらだけを出し、ルールは数えもしない | 1 回の Stop で止める理由は 1 つにする。数えだけ進めると、届かない回が生まれる | 両方を 1 つの `reason` に並べる。何をすればよいかがぼやける |
| `stop_hook_active` が真の回は止めず、数えも進めない | 連鎖の 2 回目で止めると、ターンが終わらない | 数えだけ進める。止めた回の直後に N が進むことになる |
| サブエージェント（`agent_id`、`SubagentStop`）は見ない。代わりに `SubagentStart` で「気づいたスキル候補は最後の報告に節を足して返す」の 1 行を渡す | 子が止まると親の待ちが伸びる。候補はメインが報告から集める（`docs/claude/skill-review.md`） | サブエージェントにも数える。何も渡さない（子の気づきが失われる） |
| 状態ディレクトリが無い・読めない・書けないときは止めない（`ctxfile.for_rules` の `unsure_speaks=False`） | 覚えられないまま止めると、ターンの終わりのたびに止まる。ADR-0087 と同じく止めない側を採る | `additionalContext` と同じ「覚えられないなら言う」。Stop では止め続けになる |
| `dry-run` は止めず、止めたはずの文を `systemMessage` に載せる | ADR-0087 と同じ。止めないことがモードの約束 | `dry-run` でも止める |
| 文面・しきい値は今までの `additionalContext*` と `every` をそのまま使う | 実行ファイルに持つのは当てて数えるところだけ（ADR-0057） | 実行ファイルに「10 回に 1 度」を組み込む |
| ルールは共通層とワークスペース自身の層からだけ引き、同じ id は 1 本に数える。本文のファイルはワークスペースルートの版だけを読む | **最初は全部の層の和から引き、レビューで 2 つの穴が見つかった**（2026-09-27）。プロジェクトの層（外のリポジトリ）の 1 行が cwd に依らずメインのターンを止め、止めた文をそのまま渡す。共通層を配ったコピー（ADR-0084）が古くなって `every` が違うと、同じルールが別々の刻みで両方止める。ワークツリーやプロジェクトにあるコピーはエージェントが書き換えられる | 全部の層の和（パスを持たないツールと同じ）。上の 2 つの穴 |
| `every` が 2 より小さいルールは実行時にも使わない | ターンの終わりのたびに止まる。`--lint` の warn だけでは、置いた設定で止め続ける | lint だけで言う |
| 止めた文の頭に、実行ファイルが決まった前置き（`STOP_PREFACE`）を付ける: タスクの続きではない・振り返りだけ・利用者への問いで終わったならその問いを最後に書き直す・何も無ければ「振り返り: 無し」 | 止めるとモデルはターンを続けるので、放っておくと作業の続きを始める。問いで終わったターンを止めると問いが画面から流れる（`-p` や SDK では最後の文が置き換わる）。ルールの文やファイルが差し替わっても守られるよう、実行ファイルに持つ | 前置きを文書（`skill-review.md`）にだけ書く。ファイルを差し替えれば消える |
| 数えは `state/stop-<セッション>.json` に置き、compact・再開・clear では捨てない。捨てるのは起動（`source=startup`）と古いセッションの後始末だけ | `once-*` と同じ状態ファイルに置くと、compact が N 回より先に来る長いセッションで一度も届かない（レビューで再現） | `once-*` の状態ファイルを共用する（ADR-0057 の代償をそのまま引き受ける） |
| 記録の `rules` には実際に渡したルールだけを残す | 当たっただけのルールを並べると、どれで止めたかが記録から読めない | 当たったルールを全部並べる |

## 得たもの・失ったもの

- 得たもの: 「ターンの終わり N 回に 1 度、手順を渡して振り返らせる」を設定だけで書ける。ルールを書かなければ今までと同じで、止めない
- 失ったもの: **`Stop` が止める理由が 1 つ増えた。** 渡す回はエージェントがもう 1 手動き、ターンが伸びる。何も無ければ「無し」で終えてよいと文書（渡す文）に書く必要がある
- 失ったもの: ターンの終わりのたびにルールファイルを読む
- 失ったもの: 数えの状態ファイルが 1 種類増えた（`stop-*.json`）。prune がセッションごとに消す
- 失ったもの: プロジェクトの層に `match: Stop` を書いても適用されない。プロジェクトごとの振り返りは共通層のルールと文書の側で分ける
- 失ったもの: 前置きは振り返りの用途を前提にした言い方で、`match: Stop` を別の用途に使うと合わない
- 失ったもの: 前置きに従うかはモデル次第。問いの書き直しを ccnavi は確かめられない
- 失ったもの: `finish` の促しが出た回は数えないので、促しが続くと振り返りは遅れる
- 失ったもの: `match` に書ける名前にツールでないものが 1 つ混じった。`Bash|Stop` と並べると、数えは両方で 1 本になる。`--test` と見本は `tool: Stop` を別の読み方（使われるルールを並べる）で扱う
- 失ったもの: このワークスペースのように `CCNAVI_MODE=dry-run` のところでは止まらず、人への報告に出るだけになる

## 採らなかった案

- **`UserPromptSubmit` で数える。** 一度作った。発言のたびにルールを当て、`additionalContext` で渡す。止めずに済むのが利点だったが、
  振り返る材料が揃う前（ターンの頭）に届き、何も起きていない時点で文脈を積む。利用者と相談して `Stop` に替えた
- **設定だけで近づける（`PreToolUse` の全ツールに `every: 50`）。** 実行ファイルに触らずに済むが、数えるのがツール呼び出しで、
  書きかけの途中に届く
- **`ccnavi-ticket.sh finish` の Bash に当てる `allow` のルール。** 閉じる直前に届くが、`allow` に置くと dontAsk / bypassPermissions で
  `finish` が「言及なし＝止める」から「通す」に変わる（判定が緩む）ので入れなかった
- **専用の hook スクリプト。** `.claude/hooks/` は保護済みで人が写す必要があり、数えの状態ファイルも別に持つことになる
