# ADR-0090: `match: Stop` のルールで、ターンの終わり N 回に 1 度止めて文を渡せるようにする

状態: 採用

## 状況

「作業を何度か区切るごとに振り返らせ、スキルの改善を承認付きで提案させたい」という要望が出た
（2026-09-27。Hermes Agent の、N ターンごとに裏でスキルを見直す仕組みを、人の承認を挟む形で取り入れる）。

`every: N`（ADR-0057）で「N 回に 1 度」は書けるが、ルールが当たるのは `PreToolUse` のツール呼び出しだけで、
数えもツール呼び出しの回数になる。ツール呼び出しは作業の区切りと比例せず、書きかけの途中で届く。

最初は `UserPromptSubmit`（利用者の発言）で数える形で作ったが、利用者と相談して `Stop` に替えた。
発言の時点では何も起きておらず、振り返る材料はターンが終わったところで揃うため。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| ルールの `match` に `Stop` を書ける。メインエージェントのターンの終わりに当たる。当てる文字列は無いので固定の `(stop)` に当て、`glob: "*"` と書く | 作業の区切りを数える単位にする | `UserPromptSubmit` で数える（最初の形）。振り返る材料が揃う前に届き、文脈を先に積む |
| 渡す回（`every` の刻み）にだけ `decision: block` で止め、`reason` を `NUDGE_STOP_RULE: <ルールの文>` にする | `Stop` でモデルに文を届ける経路は、止めてターンを続けさせることしか無い | `systemMessage` に載せる。人にしか届かず、モデルは振り返らない |
| 見るのは `allow` のルールだけ。`deny` / `ask` に書いたもの、`(stop)` に当たらない綴り、`every` の無いものは `--lint` が warn | 判定ではなく促し。`every` が無いとターンの終わりのたびに止まる | `deny` に書かせる。止めることが目的ではない |
| 同じ Stop で `finish` の促し（ADR-0087）が止めるなら、そちらだけを出し、ルールは数えもしない | 1 回の Stop で止める理由は 1 つにする。数えだけ進めると、届かない回が生まれる | 両方を 1 つの `reason` に並べる。何をすればよいかがぼやける |
| `stop_hook_active` が真の回は止めず、数えも進めない | 連鎖の 2 回目で止めると、ターンが終わらない | 数えだけ進める。止めた回の直後に N が進むことになる |
| サブエージェント（`agent_id`、`SubagentStop`）は見ない | 振り返りの候補は報告に添えてメインに返す決まり（`docs/claude/skill-review.md`）。子が止まると親の待ちが伸びる | サブエージェントにも数える |
| 控えの置き場が無い・読めない・書けないときは止めない（`ctxfile.for_rules` の `unsure_speaks=False`） | 覚えられないまま止めると、ターンの終わりのたびに止まる。ADR-0087 と同じく黙る側を採る | `additionalContext` と同じ「覚えられないなら言う」。Stop では止め続けになる |
| `dry-run` は止めず、止めたはずの文を `systemMessage` に載せる | ADR-0087 と同じ。止めないことがモードの約束 | `dry-run` でも止める |
| 文面・しきい値・数えは今までの `additionalContext*` と `every` をそのまま使い、ルールは全部の層の和から引く | 実行ファイルに持つのは当てて数えるところだけ（ADR-0057）。cwd に依らない | 実行ファイルに「10 回に 1 度」を焼き込む |

## 得たもの・失ったもの

- 得たもの: 「ターンの終わり N 回に 1 度、手順を渡して振り返らせる」を設定だけで書ける。ルールを書かなければ今までと同じで、止めない
- 失ったもの: **`Stop` が止める理由が 1 つ増えた。** 渡す回はエージェントがもう 1 手動き、ターンが伸びる。何も無ければ「無し」で終えてよいと文書（渡す文）に書く必要がある
- 失ったもの: ターンの終わりのたびにルールファイルを読む
- 失ったもの: 数えは `SessionStart`（compact の後を含む）で 0 に戻る（ADR-0057 と同じ代償）。長いセッションでは正確に N 回ごとにはならない
- 失ったもの: `finish` の促しが出た回は数えないので、促しが続くと振り返りは遅れる
- 失ったもの: `match` に書ける名前にツールでないものが 1 つ混じった。`Bash|Stop` と並べると、数えは両方で 1 本になる
- 失ったもの: このワークスペースのように `CCNAVI_MODE=dry-run` のところでは止まらず、人への報告に出るだけになる

## 採らなかった案

- **`UserPromptSubmit` で数える。** 一度作った。発言のたびにルールを当て、`additionalContext` で渡す。止めずに済むのが利点だったが、
  振り返る材料が揃う前（ターンの頭）に届き、何も起きていない時点で文脈を積む。利用者と相談して `Stop` に替えた
- **設定だけで近づける（`PreToolUse` の全ツールに `every: 50`）。** 実行ファイルに触らずに済むが、数えるのがツール呼び出しで、
  書きかけの途中に届く
- **`ccnavi-ticket.sh finish` の Bash に当てる `allow` のルール。** 閉じる直前に届くが、`allow` に置くと dontAsk / bypassPermissions で
  `finish` が「言及なし＝止める」から「通す」に変わる（判定が緩む）ので入れなかった
- **専用の hook スクリプト。** `.claude/hooks/` は保護済みで人が写す必要があり、数えの控えも別に持つことになる
