# ADR-0079: 副命令の名前は動きを言い、ユーザの判断はフラグで受ける

状態: 採用

## 状況

2026-09-23、`ccnavi-ticket.sh` と `ccnavi-review.sh` の副命令の名前を見直した。名前から動きが
読めないものが 7 つあった。

| 名前 | 動き | 読み違え |
|---|---|---|
| `done` | 子を `review/` か `done/` へ動かす | 置き場の `done/` と同じ表記で、行き先が `review/` のこともある |
| `judge` | サブエージェントの判定を記録する | 自分で判定するように読める。実行前チェック（`judge.py`）とも紛れる |
| `check` | レビューが通ったかを確かめ、マーカーを置く | 見るだけに読めるが、状態を動かす |
| `note` | マージリクエストにコメントを 1 件投稿する | GitLab の用語で、GitHub では通じない。手元のメモとも読める |
| `accept` | 残った指摘の扱いを選ぶ（受け入れるか、続きの子を起こすか） | 受け入れ専用に見える |
| `handoff` | 残った指摘から issue を作る | 誰に何を渡すかが読めず、ホストに書き込むことが見えない |
| `wrapup` | 指摘が残ったままユーザが早めに閉じる | 何を閉じるかが読めない |

ユーザしか打てない操作の形も揃っていなかった。`--approve` と `--reviewed` は実行ファイルのフラグで、
早めに閉じる操作だけが `review wrapup` という副命令だった。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `finish` / `record-risk` / `confirm` / `comment` / `decide` / `to-issue` / `close-early` にする。`start` / `cancel` / `request` / `ready` / `fetch` / `origin` は変えない | 名前だけで動きが分かる。`ready` は `gh pr ready` と同じ意味で通じる | 1 語に揃える（`assess` / `spinoff` / `conclude`）。短いが、名前から動きが読めない |
| 実行ファイルの 1 語目（`ticket` / `review`）は残し、sh の名前と 1 対 1 にする | hook の `builtin-guard-ticket-approval` は `ccnavi … (ticket\|review) <動詞>` の 2 語の並びで状態の操作を見分ける。動詞だけで当てると、`ccnavi --test Bash "npm start"` のような引数に当たる | 1 語目を外す。判定の正規表現を書き直して止め漏れと誤検知を測り直すことになり、得るものが無い |
| sh は `ccnavi-ticket.sh`（手元の置き場だけを動かす）と `ccnavi-review.sh`（ホストを読み書きする）の 2 本のまま | `review` の側に早めに閉じる操作や issue 作成も入るが、「マージリクエストまわり」と読めば外れない | `ccnavi-host.sh` に改名する、1 本にまとめる |
| 早めに閉じる操作は実行ファイルのフラグ `--close-early` で受ける。ユーザの判断は全部フラグ（`--approve` / `--reviewed` / `--close-early`）、エージェントが sh 経由で打つものは副命令 | ユーザが打つものとエージェントが打つものが形で分かれる | 3 つとも副命令にする。`--approve` は拡張と導入スクリプトが使っていて、動かす量に得が見合わない |
| マーカーのファイル（`close-early.json`）、マージリクエストに残す目印（`<!-- ccnavi:comment -->` など）、state の置き場の下書きの名前、ボードの JSON の欄（`close_early`）も新しい名前に揃える | 副命令とそれが残したものが同じ語で引ける | 残したものの名前だけ据え置く |
| 実行ファイルはフラグの前方一致を受けない（`allow_abbrev=False`） | 組み込みの deny は全部書いた形しか見ない。前方一致を受けると `--close` や `--review` が `--close-early` / `--reviewed` として実行され、deny を抜ける。`review wrapup` は位置引数だったので前方一致の対象にならず、フラグにしたことで抜け道が増えていた | deny の正規表現に略形を並べる。どこまで略せるかは他のフラグの表記で変わり、足すたびに見直すことになる |
| 旧名は受けない。別名も、旧名で打たれたときの案内も置かない | 判定が見る表記が 1 組で済む。別名を持つと止める対象が倍になり、書き漏れがそのまま抜け道になる | 1 リリースだけ別名で受ける |

## 失うもの

- 旧名で書いた手順書と、旧名を覚えたエージェントは 1 度止まる。止まったときの文面は使える名前を並べるので、
  そこから打ち直せる
- 旧名のまま残ったマーカー（`wrapup.json`）とマージリクエストの目印は読まない。目印は `<!-- ccnavi:` の
  前置で除くので、未解決の数には影響しない。`wrapup.json` を持つ親は、早めに閉じた扱いにならない
