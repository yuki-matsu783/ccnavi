# ADR-0101: 子チケットの識別子にフェーズ番号を入れ、連番はフェーズごとに振る

状態: 採用（2026-10-04。ユーザと方針を合意して実装した。sh の写し・承認済みの置き場の移行・Chrome 拡張の入れ直しはユーザが行う）

## 状況

2026-10-04。子の識別子は `<親>-<2 桁の連番>` で、連番は親ごとに 1 本だった（`i0012-01`、`i0012-02`、…）。
フェーズ番号は子の frontmatter の `phase:` にだけあり、識別子からは読めなかった。

連番が親ごとに 1 本なので、後から前のフェーズに子が足されると番号の順と作業の順が食い違う。
フェーズ 5 で `-06` を取った後に、レビューで残った指摘を直す続きの子（ユーザが `decide` で起こす）が
フェーズ 2 に `-07`・`-08` で入る。一覧を番号で並べると、フェーズ 2 の直しがフェーズ 5 の後ろに来る。
識別子だけを見ても、どのフェーズの子かが分からない。

識別子だけから親を割り出す箇所は 4 つあった。`ticket.py` の `_CHILD`（`child_pattern()`。Chrome 拡張の
`family_of` もこれを使う）、hook の C1 の `family_of`、`ccnavi-common.sh` の `ccnavi_c1_family`（`%-[0-9][0-9]` で
末尾を剥がす）、lint の「親なのに子の形」の検査。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 子の識別子は `<親>-<2 桁のフェーズ番号>-<2 桁のフェーズ内の連番>`。親 i0012 のフェーズ 5 の 1 枚目は `i0012-05-01`。計画の無い親の子はフェーズ 0 なので `-00-01` | 番号の順がフェーズの順と一致し、後から前のフェーズに足した子もそのフェーズの中に並ぶ。識別子だけでフェーズが読める。0 埋めの 2 桁なので、文字列の順のまま数の順になる | 連番だけを残し、並べるときに `phase:` を読む（識別子を見ただけでは分からないまま）。フェーズ番号を 0 埋めしない（文字列の順と数の順が食い違う） |
| 識別子の中のフェーズ番号と `phase:` が食い違えば error で読まない | 2 か所に同じ値を書くので、食い違いを許すとどちらが正か決まらない | 識別子の側を正として `phase:` を読まない（`phase:` を読む既存の箇所が多い） |
| 旧形式（`<親>-<2 桁>`）は新しい形へ移し、読むのは新しい形だけにする。旧形式の子は error | 読み手を 2 通り持つと、親の割り出し・採番・lint のどれもが 2 通りを扱うことになる。既存の子は閉じたもの 14 件だけで、移せる | 旧形式も読み続ける（割り出しが 2 通りになり、`foo-01` が旧形式の子か新形式の親の途中か決まらない） |
| ccnavi が採番する続きの子（`next_child_id`）は、親とフェーズごとに最大の連番 + 1 | フェーズ内の連番の定義どおり | 親ごとの最大 + 1 をそのフェーズに付ける（フェーズ内の連番が飛ぶ） |
| 識別子だけから親を割り出すときは、右から 2 段（`-\d{2}-\d{2}$`）を剥がす。Python・hook・sh で同じ規則にする | 親が `-` や数字を含んでも（`web-i0012-05-01` の親は `web-i0012`）割り出し方が 1 通りに決まる | 左から最初の `-` で切る（`web-i0012` のようにプロジェクト名を持つ親で誤る） |
| lint は、親の識別子の末尾が `-\d{2}` なら今までどおり warn。`-\d{2}-\d{2}` で終われば子の形そのもので、どの親の子として扱われるかを言う。`-\d{2}` だけなら別の親の子の識別子の途中（`<親>-<フェーズ番号>`）と紛れると言う | 割り出しは右から 2 段なので `-\d{2}` だけで終わる親は誤って割り出されないが、人が読むと紛れる。前の規則（`-\d{2}$` を避ける）を緩めずに済む | `-\d{2}-\d{2}` だけを warn にする（規則が緩み、旧形式と同じ綴りの親が通る） |

## 移行

**範囲は閉じた子（`done/`）だけ。** この時点の旧形式の子は、承認済みの置き場（`.ccnavi/approved/done/`）の 14 件
（`i0055-01`〜`05`、`i0060-01`〜`02`、`i0061-01`〜`06`、`i0062-01`）で、どれも閉じている。作業中の子はワークツリーと
ブランチと一緒に動かす必要があり、移行の対象にしない。

**移すのはユーザ。** 承認済みの置き場はユーザの置き場なので、エージェントは Python のスクリプト
（`wip/design/scripts/migrate_child_ids.py`）を用意し、ユーザが打つ。スクリプトの決めごとは次のとおり。

- 旧形式か新しい形かは、形ではなく `parent:` で決める（親 `a-05` の旧形式の子 `a-05-03` を、新しい形と取り違えない）。
  `phase:` は ccnavi と同じ読み方で読み、読めない子があれば止まる
- フェーズ番号はそれぞれの `phase:`。同じ親・同じフェーズの子は旧い連番の順に並べ、そのフェーズに既にある新しい形の子の
  続きから振る（`i0055-02` → `i0055-02-01`、`i0055-03` → `i0055-02-02`）
- ファイル名、`ticket:`・`predecessors:`、`phases/<親>/<子>.risk.json`・`.judge.json`、`events/<子>.ndjson`、
  本文中の言及を一緒に変える。承認したときに提案が在った場所の記録（`ccnavi_approved.source_path`）は過去の事実なので
  変えない。大文字小文字だけが違う綴りは人が書いた文の一部として変えず、一覧に出す
- チケットの無い記録 `phases/i0054/i0054-01.risk.json`・`i0054-02.risk.json` は、フェーズが分からず新しい名前を決められない
  ので、ユーザの決定で消す。チケット本体は消さない
- 書く前に全部を調べ、移す先が既にある、作業中の旧形式の子がある、提案の置き場に旧形式の提案がある、旧形式の子と同じ
  名前のワークツリーかブランチがある、中身の指紋に結び付いた記録（`flows/<子>.yml`、`<子>.flow.json`）がある、の
  どれかなら何も書かずに止まる

**互換の版を 3 から 4 に上げた。** 子の識別子の形は、実行ファイルと sh（親の割り出し）と Chrome 拡張（同梱の ccnavi）の
契約に当たる。古い sh や拡張が新しい形の識別子を旧い規則で割り出すと、別の親子のチケットとして扱う。版を上げたので、
食い違えば sh と拡張の版の検査が名指しする。Chrome 拡張は同梱の ccnavi の版を組み立てのときに埋め込むので、
**作り直して入れ直す**（入れ直すまでは、統合先の `CCNAVI_COMPAT` と版が合わないので「始める」を断る）。

**保護された sh はユーザが写す。** `.ccnavi/scripts/` はエージェントが書けないので、直した写し
（`ccnavi-common.sh` の親の割り出しと `CCNAVI_COMPAT=4`、`ccnavi-agree.sh` の使い方の例）を `wip/design/scripts/` に置き、
ユーザが写す。

ADR の本文に残る旧形式の識別子（`i0055-04` など）は、書いた時点の記録なので書き換えない。
現行の手順書・README・設計書の書式例は新しい形にした。ADR-0093 の「親の識別子に `-\d{2}$` を使わせない」と
`_CHILD = ^<親>-<2 桁>$` の記述には追記で、この ADR で子の形と割り出し方が変わったことを書いた。

## 得たもの・失ったもの

- 得たもの: 番号の順と作業の順が一致する。識別子だけでフェーズが読める。続きの子がどのフェーズのものかが名前で分かる
- 失ったもの: 識別子が 3 文字長くなる。既存の子の名前が変わり、旧い名前で書かれたコミットのメッセージ・issue・
  マージリクエストの本文とは綴りが合わなくなる（書き換えられない）。フェーズが 100 以上の子は読まず（error）、
  1 つのフェーズの連番が 99 を超える続きの子は起こさない（2 桁で足りない）。続きの子は、同じ名前のファイルがどこかの
  置き場に在れば（読めないものも）上書きせずに止まる。保護された sh の写し・承認済みの置き場の移行・Chrome 拡張の
  入れ直しに、ユーザの手が 1 回ずつ要る

## 採らなかった案

- **旧形式を読み続ける。** 親の割り出しが「右から 2 段、無ければ 1 段」の 2 通りになり、`foo-01` が新しい形の
  親 `foo-01` なのか旧形式の `foo` の子なのか決まらない。lint・採番・C1・Chrome の 4 か所で扱いが要る
- **フェーズ番号を `phase:` だけに置き、表示で並べ替える。** 識別子を見る場所（ブランチ名・ワークツリーの名前・コミットの
  メッセージ）では順が直らない
