# ADR-0061: 拡張のテストもターンの終わりに回し、回すのは触ったファイルが関わるグループだけ

状態: 採用

## 状況

拡張（`vscode-extension/ccnavi-board`）のテスト 203 本は、人が `pnpm test` を打ったときにしか
回らなかった。このリポジトリに CI は無く、`.claude/hooks/` の登録対象でもないので、ターンの
終わりに走る Python のテスト（ADR-0036）にも乗っていない。ボードを React にしたとき、テストの
土台（`test/helpers/dom.ts` の `settle`）が「描き直しを待ち切れない」形になっていて、混んでいる
機械では落ちることがあると分かった。この種のものは 1 回打って通ったかどうかでは分からない
（issue #89）。

`package.json` にはグループごとの行（`test:board`・`test:rules` など）が並んでいたが、どの行も
`clean-out` → `tsc -p tsconfig.test.json` → 束ね → `node --test` を自分で並べていた。`tsc` は
`src/` と `test/` を全部見るので約 6 秒かかり、テストの実行は全部で約 5 秒。つまり 2 グループを
続けて回すと、コンパイルが 2 回走って全部回すより遅い。

## 決定

| 決めたこと | なぜ |
|---|---|
| ターンの終わり（`Stop`）に `.claude/hooks/test-ext.sh` で回す。編集ごとには回さない | ADR-0036 と同じ。1 ファイル直すたびに全件を走らせると、複数ファイルにまたがる変更では途中の状態が必ず落ちる |
| 拡張のファイルを触っていないターンは何もしない | 文書だけのターンや Python だけのターンを待たせない。触ったかどうかは `PostToolUse` の `.claude/hooks/mark-ext.sh` が `logs/session/<セッション>.ext-files` に書き残す |
| 回すのは、触ったファイルが関わるグループだけ。決めるのは `vscode-extension/ccnavi-board/scripts/test-groups.js` | 余計なテストを回さない。`src/core/risk-doc.ts` を直したターンで board の 63 本は何も確かめない |
| どのグループがどのファイルを読むかは表で持たず、テストの `import` を辿って数える | 表はファイルを増やしたときに黙って古くなる。`test/<グループ>/` を増やしても直すところは無い |
| コンパイルは、いくつグループを選んでも 1 回 | `tsc` は `src/` と `test/` を全部見るので、グループを絞っても安くならない。安くなるのは実行のほうだけ |
| `package.json` のテストの行は全部この 1 本に寄せる | 9 か所に同じ工程が並んでいると、工程を直すときに 9 か所直すことになる |
| 差し戻しは 3 回まで。回数のファイルは `test-py.sh` と分ける | 上限の理由は ADR-0036 と同じ。別々に数えるのは、片方の失敗で他方の残り回数が減らないため |
| このリポジトリの `.claude/settings.json` には登録しない | `test-py.sh` と同じ扱い。登録するかは利用者が `settings.local.json` で決める |

`import` では辿れないものは 3 つあり、それぞれ綴りで決める。固定データ（`test/fixtures/`）は
実行時に名前で開くので全グループ、画面（`src/webview/`）は esbuild が束ねてテストは束ねた
ものを読むので「束ねたものを読むグループ」、組み立ての土台（`package.json`・`tsconfig*.json`・
`scripts/`・`pnpm-lock.yaml`）は全グループ。読み物（`*.md`）と絵（`media/`）は何も回さない。
テストが 1 つも読まないファイル（`src/extension.ts` などの拡張ホストの入口）は、テストは回さず
`tsc` だけ通す。型の誤りはそこにも出るため。

## 理由

グループを絞る値は、実行の約 5 秒のうち関わらないぶんだけで、コンパイルの約 6 秒は残る。
それでも絞るのは、ターンの終わりに毎回 11 秒待つのと 6 秒で済むのとでは、1 日の回数ぶんの差が
出るため。絞る仕掛けそのものは、人が `pnpm test:rules` を打つときにも同じだけ効く。

`import` を辿るのは、表を置くと「新しいテストがどのグループに要るか」を人が覚えていなければ
ならなくなるため。辿るなら、ファイルを足した時点で正しい答えが出る。

回すグループを 1 行で出す（`--plan`）のは、sh と JS の契約をその 1 行に閉じるため。sh は
`groups=... compile=... webview=...` を読むだけで、どのファイルがどのグループに属するかを
知らない。テストは sh の代わりにこの 1 行を読む。

## 得たもの・失ったもの

- 得たもの: 拡張を触ったターンで、`pnpm test` を打たなくても落ちたことが分かる
- 得たもの: 2 グループ以上を回すときコンパイルが 1 回で済む（`pnpm test:rules && pnpm test:risk`
  の 10 秒が `node scripts/test-groups.js rules risk` の 6 秒になる）
- 失ったもの: 拡張を触ったターンが 3〜8 秒伸びる（全部回すと 11 秒）
- 失ったもの: `import` を辿るのは静的な綴りだけ。動的な `import()` や、名前を組み立てて開く
  ファイルは辿れない。辿れないものは上の 3 つとして綴りで決めてあり、増えたらそこに足す
- 失ったもの: hook が 1 本増えた（`mark-ext.sh`）。拡張には整形も静的検査も無いので、
  `lint-py.sh` のように「もう走っている hook に相乗り」ができなかった
- 失ったもの: 記録のファイルが 1 セッションに 2 つ増える（`.ext-files`・`.ext-retries`）。
  掃除は `test-py.sh` と同じ 1 時間

## 採らなかった案

- **GitHub Actions を足す**（issue #89 の道 1）。落ちたことが必ず分かるが、このリポジトリに
  CI という層が増える。いまは意図して持っていないので、足すかどうかは人の判断。hook は
  手元で気づけるだけで、push したものが通ることは保証しない。両方持つこともできる
- **何もしない**（道 3）。統合先へ戻す前と MR に出す前に人が打つ、という運用を続ける。
  運用で保っているものが運用のままになる
- **`Stop` で `pnpm test` を丸ごと回す。** 11 秒。グループを絞る仕掛けが要らない代わりに、
  `src/core/risk-doc.ts` を直したターンでも board の 63 本を待つ
- **触ったファイルを `git status` から数える。** hook を 1 本増やさずに済むが、前のターンで
  直してすでにテストした変更も、他セッションの書きかけも混ざる。回すものが増える側に外れる
- **グループの表を `scripts/` に置く。** 辿るより速いが、ファイルを増やしたときに黙って古くなる
- **`tsc` もグループごとに絞る。** `tsconfig.test.json` は `src/` と `test/` を全部見るので、
  絞るには入口の一覧を組み立てることになる。型の検査が「テストが読むぶんだけ」に狭まり、
  拡張ホスト側の型の誤りが落ちなくなる
