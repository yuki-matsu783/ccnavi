# ADR-0047: 書き直せる読みにくい形は、読み分けずに止めて案内する

状態: 採用

## 状況

ADR-0046 で、引用の外のブレース展開を展開して読まずに止め、書き直し方を案内するようにした。同じ見方で `shellread` を
見直すと、2 種類の形が残っていた。

**1 つめは、実行するときに決まるコマンド名。** どのプログラムが走るかが綴りに無いので、どのルールも当たらない。
2026-09-15 に `--test` で確かめた。

| コマンド | 判定 | bash が実行するもの |
|---|---|---|
| `c=git; $c push origin main` | ask（UNDECLARED） | `git push origin main` |
| `$(echo git) push origin main` | ask（UNDECLARED） | 同上 |
| `/usr/bin/gi? push origin main` | ask（UNDECLARED） | 同上 |
| `git${IFS}push origin main` | ask（UNDECLARED） | 同上 |
| `/bin/r? -rf /tmp/x` | ask（UNDECLARED） | `rm -rf /tmp/x` |

UNDECLARED なので、権限モードが `auto` なら確認なしに実行されうる（ADR-0009）。ADR-0046 と同じ穴で、「変数には届かない」は
既知の限界として文書に書かれていた。

**2 つめは、読み分けの規則を持っているが、作業ではほとんど書かれない形。** バッククォートは、中で `\` が外れる文字が
二重引用の中かどうかで変わり、入れ子は外したあとの中身を読み直さないと分からない。`$( )` の中の `case`、`$((cmd) | x)`、
16 段を超える入れ子は bash と zsh で読みが割れるので縮退して確認に落としていた。`coproc NAME { … }` は NAME を切り分ける
読みを持っていたが、敵対的レビューで漏れが見つかって足したもの（shellread-subst-04）。

このワークスペースの記録（Bash のコマンド 2,841 種類）での頻度は次のとおり。

| 形 | 頻度 |
|---|---|
| コマンド名の位置の変数・置換・グロブ | 約 3.5%。`G=…; $G add` と `sh $G` の形が大半（`[` を数え込んだ近似） |
| 二重引用の中のバッククォート | 1.2%。`gh … --body "…"` の Markdown が大半 |
| 引用の外のバッククォート | 0.1% |
| `case`・`coproc`・`select` | 0.2% 未満（綴りの数え込みを含む） |

## 決定

**書き直しを求める形を 4 つにまとめ、読み（`shellread.Reading.rewrites`）に（形, 綴り）で並べる。** 判定はルールより先に止め、
形ごとの理由コードと書き直し方を 1 回で返す。記録の `rules` には `(形)` が残る。

| 形 | 理由コード | 並べるもの | 書き直し方 |
|---|---|---|---|
| `brace-expansion` | `DENY_BRACE_EXPANSION` | 引用の外のブレース展開（ADR-0046） | 語を並べる、単一引用 |
| `command-name-expansion` | `DENY_COMMAND_NAME_EXPANSION` | コマンドの位置の語に、変数か置換の `$`、`*` `?`、閉じた `[…]` | コマンド名とスクリプトのパスをそのまま書く |
| `backquote` | `DENY_BACKQUOTE` | 単一引用・`$'…'`・`` \` ``・引用付きヒアドキュメントの本文・コメントの外のバッククォート | `$( )`、単一引用、`--body-file` |
| `ambiguous-form` | `DENY_AMBIGUOUS_FORM` | `$( )` の中の `case`、`$((cmd) \| x)`、16 段を超える入れ子、コマンドの位置の `coproc`・`select` | if/elif、空白を入れる、分けて打つ、`&`、`for` |

- コマンドの位置の語は、前に置いた代入（`a[1]=x`・`x+=1` を含む）とリダイレクト（`>/dev/null`・`2>&1`）を飛ばした最初の語。
  `case` `for` `select` の直後の 1 本は、調べる値と変数名なので見ない
- コマンド名は、読んだコマンド（置換の中身を含む）と、実行役のコマンドを外した層（ADR-0045）の両方で見る。`env $c`・
  `sudo -u me $c`・`sh $SCRIPT`・`. $venv/bin/activate`・`sh -c "$c"`・`eval "$(…)"` も止まる
- 実行役のコマンドを外すとき、前に置いたリダイレクトも外す。外さないと `>/dev/null env $c` の `env` が先頭に立たない
- バッククォートは見つけたところで読むのをやめる（縮退の理由 `backquote`）。中のエスケープの外し方と入れ子の読み直しは持たない
- `coproc NAME { … }` の NAME を切り分ける読みは持たない
- `ambiguous-substitution` の縮退は残るが、必ず書き直しを求める形として並ぶので、縮退の断りは出なくなる

## 理由

**止めるのは、書き直した結果がその場で読める形に収まるものに限る。** どの形も、案内どおりに書き直すと、コマンド名を
そのまま書く、`$( )`、if/elif のように、ccnavi が読める形に収まる。書き直した後も、コマンドは ccnavi の目の前にある。

**`sh -c`・`eval`・`xargs`・`find -exec` は止めない。** 書き直し先が「スクリプトをファイルに置いて `sh <ファイル>`」になり、
中身が ccnavi から見えなくなる。今は層（ADR-0045）で、中身に止める側のルールを当てられる。`xargs` と `find -exec` は
代わりの書き方も不便。

**コマンド名は、穴だから止める。** 5 形とも UNDECLARED で、読み分けを足しても変数の値には届かない。

**バッククォートと読みの割れる形は、規則を減らすために止める。** 規則を持つほど、読み違いが素通りに倒れる余地が増える。
作業ではほとんど書かれず、書き直せる。二重引用の中のバッククォートは、書いた側が文字のつもりでもシェルは実行するので、
中身がルールに当たらなくても止まるほうが安全。

## 得たもの・失ったもの

- 得たもの: 変数・置換・グロブをコマンド名に置いた形が、ルールをすり抜けなくなる。`env`・`sudo`・`sh` 越しも同じ
- 得たもの: バッククォートの中身の読み分けと、`coproc NAME` の切り分けが消える
- 得たもの: 二重引用の中のバッククォートを文字のつもりで書いた本文が、実行される前に止まる
- 失ったもの: 変数をコマンド名にする普通の書き方（`G=…; $G add`、`sh $SCRIPT`、`"$PYTHON" -m x`、`$EDITOR f`）が止まる。
  記録では最大 3.5% 程度。コマンド名やパスをそのまま書けば通る
- 失ったもの: シェルが展開しない綴りのコマンド名も止まる。単一引用した `'$c'`、引用したグロブ文字 `"gi?"`（許容する誤検知、
  ccnavi.md §12.2）
- 失ったもの: 二重引用の中のバッククォートを使う本文（issue・PR の Markdown）が、中身に依らず止まる。単一引用か `--body-file` で書く
- 失ったもの: 今まで縮退して確認（ask）に落ちていた、読みの割れる形とバッククォートの形が拒否になる
- 失ったもの: 層の深さ（4）と語数（2000）を越えた先の実行役のコマンドの中のコマンド名は並ばない。その形は元から縮退していて、確認に落ちる
- 失ったもの: 理由コードが 3 つ増える

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| 同じコマンドの中の代入を追いかけて、変数の値をコマンド名として読む | 環境変数や前のコマンドで決めた値には届かない。規則が増える |
| `sh -c`・`eval`・`xargs`・`find -exec` も一律に止める | 書き直し先がファイルになり、中身が見えなくなる。`xargs`・`find -exec` は代わりの書き方が不便 |
| ヒアドキュメントも組み込みで止める | 共通層の `rules.yml` ですでに止めている。組み込みにすると配布先の設定より強くなるので、別に決める |
| バッククォートを今までどおり読む | 読み分けの規則が残る。二重引用の中で実行される形を、中身がルールに当たらない限り通す |
