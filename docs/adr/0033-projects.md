# ADR-0033: 複数のリポジトリ：道具はワークスペース、設定はプロジェクト、Bash は和

状態: 採用

## 状況

道具（hook の登録、実行ファイル、保護済みスクリプト、スキル、CLAUDE.md）は public に出したくない
ワークスペースで、private のリポジトリに置く。直したいプロジェクトは別々のリポジトリで、
ワークスペースの下に clone して Claude Code に作業させる。ルールはプロジェクトごとに違い、
プロジェクトの git で育てる。

それまでの作りでは、ルートが 1 つ（相対パスの解決、実行後の監視、作業ツリーの列挙がすべて
ワークスペースルート 1 か所を向く）、ルールファイルが 1 本、プロジェクトに `.claude/` を置く形は
採れない（Claude Code がそこのスキルを読み込む）、の 3 つが成り立たなかった。

## 決定

骨は 3 つ。道具はワークスペース、設定はプロジェクト、git はツリーごと。Write / Edit は行き先の
プロジェクトのルール、Bash は全プロジェクトの和。プロジェクトを決めるのは人の承認で、判定は
その値を見ない。

- プロジェクトの置き場は `projects/` 直下の 1 段に固定する。名前がそのままツリーの名前になる
- プロジェクトのリポジトリに書くのはルール（`config/rules.yml`）だけ。提案はワークスペースルートの
  `wip/<プロジェクト>/tickets/` に置く。git ラッパの記録も同じ向きで `logs/<プロジェクト>/` へ
  寄せるが、こちらは未実施で、いまは `logs/` に平坦に出る（HANDOVER.md の「次にやること」）
- 作業ツリーの中に checkout されたルールファイルは読まない。読むのは git プロジェクトルートの版
- 読めないプロジェクトのルールは組み込みに落とし、Bash の和からそのプロジェクトを外す
- チケットの `project:` は親が書き、子は承認で継ぐ。行き先のツリーが属するプロジェクトと、
  そのツリーに結び付く写しの `project:` が違えば止める。**この行の前半は ADR-0038 が改めた。**
  プロジェクトは提案を置いた場所が決め、`project:` は照合に使う
- プロジェクトのルールファイルは中核ファイル（ADR-0021）に加える
- フェーズの種類とリスクの配点はワークスペースに 1 本
- 拒否の文面が案内する sh の綴りは `{root}/.claude/scripts/...` で書く。Bash ツールの環境に
  `CLAUDE_PROJECT_DIR` は来ない（実測済み）

## 理由

Bash を和にするのは、Bash の呼び出しがどのプロジェクトのものかを当てる仕掛け（`cwd`、`cd` の
追跡、引数の語の走査）が「どのルールファイルを引くか」の 1 点にしか効かず、コマンドの副作用は
結局実行後の監視が拾うため。仕掛けの量と得るものが釣り合わない。当てずに和を取れば、`deny` と
`ask` は増える側に倒れ、緩むのは `allow` の共有だけになる。

置き場を 1 段に固定するのは、列挙が速いことと、何がプロジェクトかで迷わないため。
プロジェクトの中に提案と記録を書かないのは、プロジェクトが public のリポジトリで、提案と記録は
ワークスペースの運用の痕跡だから。作業ツリーのルールを読まないのは、ブランチで変えたルールが
そのブランチの判定に効く形が、人が見ていないルールが効く形になるため。申告を見ないのは、
「プロジェクトは B」と言った値でルールを選ぶと、A に書きながら B を名乗る形が通るため。

## 得たもの・失ったもの

- 得たもの: 1 つのセッションが複数のプロジェクトを横断できる。`projects/` が無ければ前と同じに動く
- 失ったもの: allow の共有。プロジェクト A だけが許したい `npm test` はプロジェクト B に居ても通る。
  「プロジェクト A に居るときだけ止める」は書けない
- 失ったもの: ルールの読み込みがプロジェクトの数だけ増える。1 本 200 行の YAML で数 ms
- 残っているもの: git ラッパの記録を `logs/<プロジェクト>/` へ寄せる（sh は人が直す）

## 採らなかった案

- `cwd` と `cd` の追跡、引数の語の走査でプロジェクトを当てる。上のとおり
- 2 段以上の深さやワークスペースの外にプロジェクトを置く。列挙と判定の材料が増える
- プロジェクトごとのフェーズの種類とリスクの配点。今回は入れない
