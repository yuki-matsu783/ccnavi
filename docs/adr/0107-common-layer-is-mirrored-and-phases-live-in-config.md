# ADR-0107: 共通レイヤーはプロジェクトの common へミラーし、フェーズ定義は config だけに置く

状態: 採用（実装済み。2026-10-05 にユーザが決めた）

## 状況

ADR-0084 は、親の着手でプロジェクトの `.ccnavi/config/` の同名ファイルを共通レイヤーで上書きし、上書きを最初のレビューで知らせると決めた。
運用すると次の問題が出た。

- プロジェクトの `config/` に、共通レイヤーにあるファイルと同じ名前でプロジェクトだけの設定を持てない（着手のたびに上書きされる）
- 上書きの安全装置が重い。消える識別子の名指し、未コミットの変更での停止、`config-sync.json`、レビューでの知らせ、知らせるまで親を閉じさせない処理
- フェーズ定義は、`id` の衝突、`title` の重なり、`dag` が全レイヤーで揃わないと効かない規則が絡み、足し算が難しい

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 配り先をプロジェクトの `.ccnavi/common/` にし、ワークスペースルートの `common/` のミラーにする。プロジェクトの `config/` には触れない | ミラーは誰も編集しないので、上書きや消去で失うものが無い。プロジェクトだけの設定は `config/` に自由に置ける | `config/` への上書き（ADR-0084） |
| ミラーでは、共通レイヤーから無くなったファイルも消す | ミラーは共通レイヤーの写し | 上書きと追加だけ |
| 名指し、未コミットでの停止、`config-sync.json`、最初のレビューでの知らせ、閉じるのを止める処理、`script:` の書き換えは外す | ミラーなので失うものが無く、配り先のパスも共通と同じ `.ccnavi/common/scripts/` になる | 全部残す |
| ワークスペースの中では、ワークスペースルートの `common/` だけを共通レイヤーとして読む。ミラーは、そのプロジェクトを単体で clone したときだけ共通レイヤーとして読み、そのとき `config/` は自身のレイヤーになる | 単体 clone でも、ワークスペースの中と同じ「共通 + 1 レイヤー」の和で判定される | ミラーも二重に読む |
| `phases.yml` は `config/` だけに置く。親の `project:` が指す 1 本で決まり、足し算はしない。共通レイヤーに `phases.yml` があれば error で、判定に使わず空として扱う | 衝突の規則がいらなくなる | 共通と config の和 |
| `common/` と `config/` は、どちらが無くても動く。ファイルが無いのは「設定が無い」正常で、`fallback` にも診断にも出さない。壊れているときだけ `fallback` を残す | 無いことと壊れていることを分ける | 共通が無ければ組み込みの既定に戻して `fallback` を残す（従来） |
| 組み込みの deny は、`common/` と `config/` の有無・状態によらず常に有効。両方が無いとき、または共通のルールが壊れているときの判定は、組み込みの既定だけになる | 共通が無い・config だけのときも、取り返しの付かない操作の止めが消えない | 共通が無いときは deny も無い |
| 常時有効にするのは土台の deny（`rm -rf`・`git push`・`git reset --hard`・認証情報。認証情報の regex は先頭境界つき）だけ。`builtin-guard-*`（設定の保護）は、組み込みの既定を使っている間（共通のルールが壊れている間）は外す | 土台は誤検知を避けて狭く保ち、壊れた設定を直す道（Write / Edit）は残すため | `builtin-guard-*` も常時有効、広い regex の土台 |
| 共通が無く config だけあるときの配点は、共通を空として config の項目だけを数える。組み込みの 4 項目は両方無いときだけ | 「無い = 空」に揃えるため | 共通が無ければ組み込みの 4 項目を足す |
| 共通の `.ccnavi/common/` が無いか空なら、配らず、ミラーを消さない（着手は止めない） | 共通の消し忘れ・取り違えでミラーを全部失わないため | 空の共通でミラーを全消去 |
| 拡張は、ルールとリスクで「共通 + 1 レイヤー」の和を読み取りで見せ、フェーズ管理はワークスペースかプロジェクトの `config/` の 1 本を選んで編集する | 判定は実行ファイルが出す。拡張は見せるだけ | 拡張が和を自分で作る |

## 理由

単体 clone のユーザに共通のルールを見せる、という ADR-0084 の目的は残す。残したうえで、配り先を config から common に変えると、
上書きで失うものがなくなり、周辺の安全装置が要らなくなる。

## 得たもの・失ったもの

- 得たもの: プロジェクトの `config/` に、プロジェクトだけのルール・配点・フェーズ定義を置ける
- 得たもの: 配布の実装と、ユーザが負う手順（レビューでの知らせ、端末での確認）が小さくなる
- 得たもの: フェーズ定義の合成規則が要らなくなる
- 失ったもの: 2 重管理は残る。ミラーは次の親の着手まで共通レイヤーとずれ、その間は古いミラーの項目が残る
- 失ったもの: 共通レイヤーのルールの中身がプロジェクトの git に入る。public のリポジトリなら外に出る（ADR-0084 と同じ）
- 失ったもの: 他のワークスペースに共通の `phases.yml` があると、error になる。`config/` へ移す手順が要る
- 失ったもの: 共通が無いことを `fallback` で気づけなくなる。組み込みの deny は残るが、組み込みの既定のほかの判定は共通に頼れない

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| 配布をやめる | 単体 clone のユーザに共通のルールが見えなくなる。ユーザが「見せる必要あり」と決めた |
| 共通レイヤーの `id` にも `common:` の接頭辞を付ける | 他のレイヤーはすでに接頭辞付きで、重複排除には裸の `id` が要る。記録と参照の形が変わる割に得るものが小さい |
