# ADR-0022: チケットは絞る向きにしか使わず、未承認は何も効かせない

状態: 採用

## 状況

当初の設計のチケット層は、プロジェクト設定の `target_directories` の上に乗り、上位の deny を
覆せない・明示の ask を allow にできない、という「できないこと」の一覧を持っていた。
実装にはその土台が無い（ADR-0008）。

## 決定

チケットが担うのは「宣言した範囲の外は止め、中は聞かない」の 2 つで、ルールが何も言わなかった
ときだけ見る。ルールのほうが強いので、チケットが上位の宣言を覆すことはない。

未承認のチケットは 1 ミリも効かない。判定はチケット由来の判定を一切出さず、ルールの 3 タイプ
だけが残る。チケットのファイル自身（提案）は範囲の外でも書ける。

## 理由

広げる経路そのものが無いので、設計の「できないこと」の側は自動的に満たされる。

未承認を「全部拒否」に倒さなかったのは、倒すとチケットを直す手も承認済みチケットを直す手も同時に止まるから。
ルールファイルが読めないときに組み込みの既定へ落ちる（ADR-0012）のと同じ形で、倒れた先に
回復の道を残した。設計は「全 allow を ask に降格」だったが、チケットが何も言わなければルールの
3 タイプだけが残り、そこも言及していない場所は権限モードに従うので、降格の処理を別に書かずに
同じ着地点へ行く。

提案を範囲の外でも書けるのは、塞ぐと、いちど承認した範囲から出る道が無くなるため。
次のチケットを提案する経路は開けておく。提案が効くのは承認されてからなので、開けても
範囲は広がらない。

## 得たもの・失ったもの

- 得たもの: 層の合成を書かずに、上位の宣言が下位から緩まないことが成り立つ
- 失ったもの: チケットで「ルールが止めている場所を今回だけ開ける」ことはできない。
  要るならルールの側を直す

## 採らなかった案

- 未承認は全部拒否。上のとおり
- 未承認は allow を ask に降格。同じ着地点に、別の処理を書くことになる
