# ADR-0115: 公開前なので、移行のための読み取りと掃除をすべて外す

状態: 採用（ADR-0104 の「既存の承認済みチケットに残る欄は消さない。移行はしない」「古い形も読む」、ADR-0109 の「前の版が書いた待ち方のファイルは読まない（`--lint` が warn で言う）」を改める）

## 状況

ccnavi はまだ外部に公開しておらず、過去のデータを持つのは開発中のワークスペースだけ。
それでもコードは、過去の版が書いたデータを読むための分岐を持ち続けていた。

- 承認の記録 `ccnavi_approved`（`approved_at`・`source_tree`・`source_path`）を持つ古い承認済みチケットの読み取り。
  取り下げの分岐、承認の時刻の出どころ、取り込み済みの親子の「閉じた」の照合（Python と `ccnavi-sync.sh`）、
  退避との照合、`--lint` の warn
- 前の版が書いた待ち方のファイル `phases/<親>/workflow.yml` が残っていることの warn、
  `load_copy` が互換のためだけに受けていた `approved_dir`、`waits_of` の読まない `types`
- 前の形の識別子 `i<番号>`・`<名前>-i<番号>`（通し番号の数えと lint の文面）
- 古い索引名 `index.jsonl` を新しい名前に移るときに消す処理
- フェーズ定義の古い欄 `order`・`after`・`overlap`・`requires` の警告と、VS Code 拡張のフェーズ画面の「読まない欄」の帯
- hook が承認を伝えていた頃の記録 `approved-<セッション>-<エージェント>.json` の掃除

## 決定

上をすべて消す。新しい形だけを読み、書く。

- 承認済みチケットの `ccnavi_approved` は読まない。取り下げは中身の一致（ADR-0104）と、続きの子の目印
  （`followup_of`）だけで決める。承認の時刻は状態の履歴 → git のコミット → 未コミットの順
- 取り込み済みの親子が「閉じた」かは、`base_sha` → `started_at` → `cancelled_at` の順だけで比べる。
  どの欄でも照合できなければ閉じていない側に倒す
- 提案の `ccnavi_approved` は拒まなくなる（読まない欄になるため）。`followup_of` と `workflow:` は今までどおり拒む
- 互換の版（COMPAT）を上げる。承認済みチケットの読み方が変わるため

## 理由

- 公開前なので、過去のデータを持つのは開発中のワークスペースだけ。読む分岐を残す理由は、手で移す手間だけ
- 分岐が残ると、読み手は「いまの形」と「古い形」のどちらの話かを毎回確かめることになる
- 古い形を装える弱点（ADR-0104 の「残る弱点」）が、読む分岐ごと消える

## 得たもの・失ったもの

- 得たもの: 古い形の分岐、定数、テスト、sh の `approved_at_of`（約 55 行）が消える。「古い形は装える」弱点が無くなる
- 失ったもの: 古い承認済みチケット（`ccnavi_approved` を持つ）は、取り下げの条件と照合で新しい形と同じに扱われる。
  取り込み済みの親子に古い形が残っていると、欄が無いため「閉じていない」と読まれて止まる。ユーザが `done/` の
  チケットを確かめる
- 失ったもの: 古い `index.jsonl`、古い `approved-*.json`、`phases/<親>/workflow.yml` は自動では消えなくなる。残っていれば
  ユーザが消す。読まれないので害は無い
- 失ったもの: 互換の版を上げるので、組み直す前の実行ファイルと配り直す前の Chrome 拡張は食い違いを知らせる

## 採らなかった案

- 残す。公開前に消す機会を逃すと、公開後は本当の移行として残り続ける
- 自動で移す。承認済みの置き場を動かすのはユーザ（ADR-0058）で、移す相手のデータが開発中のものしか無い
