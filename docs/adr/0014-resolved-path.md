# ADR-0014: ファイルのパスは行き着く先で見る

状態: 採用

## 状況

`file_path` を来たまま当てていたので、`docs/../.env` のような綴りでルールを外せた。

## 決定

`Read` `Write` `Edit` `NotebookEdit` のルールは、payload の `file_path` そのものではなく、
`cwd` から絶対パスに直し、`..` を正規化し、シンボリックリンクを解いた結果に当てる。
まだ存在しないファイルへの書き込みは解けないので、絶対パスにして `..` を正規化するところまでで止める。

## 理由

守る対象は名前ではなく場所なので、同じ場所を指す別の綴りでルールを外せてはいけない。

## 得たもの・失ったもの

- 得たもの: `.env` `./.env` `docs/../.env` `/abs/path/to/.env` が同じ判定に行き着く
- 失ったもの: Bash のコマンドに現れるパスは対象外で、そちらはコマンド文字列としてしか見ていない。
  `cat docs/../.env` は `.env` の綴りが残るので当たるが、`cat $(dirname x)/.env` のような形は追えない
- 失ったもの: ルールは絶対パスに当たるので、`glob` は `*/secrets/*` のように前を `*` で受ける形になる

## 採らなかった案

- 綴りのまま当てる。上のとおり
- Bash の引数のパスも解く。コマンド文字列からパスを確定できる形が限られ、確定できない形が
  「解いたつもり」で通る
