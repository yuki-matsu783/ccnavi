# ADR-0120: 2 段目の無いユーザの入口は、引数を読み切れなければ止める

状態: 採用

## 状況

2026-10-11 の再確認で、ユーザが端末で打つ入口のうち次の 3 つが、引数を組み立てるだけで hook を抜けていた
（判定は ask（UNDECLARED か PARSE_UNCERTAIN）で、権限モードが auto / bypass なら実行される）。

| 入口 | 抜けた形の例 | 2 段目 |
|---|---|---|
| `ccnavi-review.sh decide --choices` | `--cho${X}ices`・`${C}ices`・`--cho*`・`--ch[o]ices`・`sh -c` の中の `${X}`・`xargs -a` | 無い。ボードの経路で、端末を求めない |
| `ccnavi-sync.sh --forget` | `--for${X}get`・`--f*`・`bash -c` の中の `${X}`・`xargs`・`sh < /dev/null …`・`busybox sh …` | 無い。実行ファイルを起動せず、sh が取り込み状態を消す |
| 実行ファイルの `--agree --yes` / `--reviewed … --yes` | `--agr${X}ee --y${X}es`・`--agr*ee --y*`・`busybox sh` / `sh < /dev/null` 越しの launcher・`xargs -a` | 無い。`--yes` は端末を求めない |

止めていたのは、文字として並んだ表記を見る 2 つ（`human_path_form` の文字列の組と、組み込みの script 節の
コマンドの位置の正規表現）だけだった。ADR-0093 は「deny の表記の抜け」（変数の展開・`cat … | sh -s`）を、
ADR-0080 は「表記を組み立てて隠す形」を受け入れていたが、どちらも実行ファイルの端末要求という 2 段目が
あることが前提だった。上の 3 つにはそれが無い。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 3 つの入口に、`$`・バッククォート・glob 文字（`*` `?` `[`）・`find -exec` の `{}` を含む引数があれば、`DENY_TICKET_APPROVAL_CLI` で止める（`phase_forms.hidden_user_entry`） | 実行の時点まで値が決まらない引数は、hook には読めない。読めなければ拒否する（設計 1.3） | 展開を含む表記を個別に並べる。分け方はいくらでも作れる |
| 実行ファイルは、展開を含む語があり、承認の旗（`--agree` / `--approve` / `--reviewed`）と `--yes` が文字か展開でどちらもそろいうるときに止める。`--guard-ticket-approval` になりうる語も止める | 実行ファイルはほかの副命令が多く、全部を止めると `--docs` も打てなくなる。端末を求めない枝は `--yes` だけ | 実行ファイルへの展開を全部止める |
| 入口を引数を外から流し込む実行役（`xargs`）で起動する形、標準入力から読むシェル（`sh -s`・`cat … \| sh`）で名前が出る形、入口を `<` で読ませる形は、名前が出た時点で止める | 何が渡るかがコマンド行に無い | 流し込む中身を追う |
| 入口はコマンドの位置で探す。前に置けるのはシェル・`busybox`・`.`・シェルの選択肢・リダイレクト・代入だけ。実行役のコマンド（`env`・`sh -c`・`xargs`）は shellread が外した層で見る | `sh -x`・`sh < /dev/null`・`busybox sh` を挟んでも外れず、`git log --grep ccnavi-sync.sh` のように文字列として出るだけの形には当たらない | 生の文字列の全体で探す（`human_path_form` の方式）。名前を引数に書いただけの形まで止まる |
| 走査が止まる形（バッククォート）は、生の文字列の語で探し、位置を見ない | 読めなければ止める側に倒す | 通す |
| 止めた文は「値を変数や glob で組み立てず、そのまま書く。承認・受け入れはユーザが端末で打つ」を案内する | 正当に値を変数で渡した場合（`ccnavi-sync.sh "$P"`）も止まるので、次の一手を示す（P8） | 文面を分けない |

文字として並んだ `--forget` を `busybox sh` や `sh < x` の後ろに置く形も、同じ関数で止める。script 節が当たる形は
script 節に任せ、文面を 1 つにする。

## 得たもの・失ったもの

- 得たもの: 2 段目の無い 3 つの入口では、表記を分けても値を組み立てても、ユーザの判断をエージェントが出せない
- 失ったもの: **値を変数で渡す正当な書き方も止まる。** `sh ccnavi-sync.sh "$P"`、`ccnavi-review.sh decide "$N" --preview`、
  `ccnavi-launcher.sh --docs "$T"` は止まり、値をそのまま書き直すことになる（1 手増える）
- 失ったもの: ccnavi の名前を持たない呼び出しは見ない。名前を変えたコピー（`/tmp/cc --agr${X}ee --yes`）と、
  入口の名前そのものを組み立てる形（`ccnavi-rev${X}iew.sh` は `DENY_COMMAND_NAME_EXPANSION` が止める）、コマンド行全体を
  変数に入れて `sh -c "$CMD"` で走らせる形は、ADR-0093・ADR-0080 の受け入れのまま
- 失ったもの: 擬似端末（`script -qc`）で端末要求を満たす形は、この決定の外にある

## 採らなかった案

- **`decide` を `--preview` 以外まるごと止める。** `decide` の語が残る限り止まるが、`--forget` と実行ファイルの `--yes` は救えない
- **`--forget` を実行ファイルへ移し、端末要求を付ける。** 2 段目ができ、sh が状態を消す判断を持つ形（P13）も解けるが、
  擬似端末の穴が残るうえ、sh と実行ファイルの契約と配布物が変わる
