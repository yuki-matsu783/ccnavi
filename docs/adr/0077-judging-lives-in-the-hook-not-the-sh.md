# ADR-0077: 止める・通すの判定は hook が持ち、sh の検査は 2 重目にする

状態: 採用

## 状況

2026-09-23、実行ファイル・sh・拡張の分担を見直した。決まっていたのは「実行ファイルはネットワークに
出ない」（P11、ADR-0028）と「拡張は判定を自分で出さない」（ADR-0035）の 2 本で、sh が持ってよいものは
書かれていなかった。

子チケットのワークツリーからの push は、2 か所が別々の材料で止めていた。

| | hook（`phase.py`） | `ccnavi-git.sh` |
|---|---|---|
| 誰に効くか | サブエージェントだけ | 誰にでも |
| 何で見分けるか | 素性 | cwd のツリーの名前と、その名前の承認済みチケットの `parent:` |

親エージェントが子のツリーで打つ push を止めていたのは sh だけで、その sh の検査には穴が 3 つあった。

1. **環境変数で外れる。** sh はワークスペースルート・承認済みチケットの置き場・実行ファイルを環境変数から
   読む。`CCNAVI_TICKETS_APPROVED=/x sh …ccnavi-git.sh push` を hook は allow で通し、sh は存在しない
   置き場を見て通した。`env X=…`、同じ行の `export X=…`、`unset X` も同じ
2. **写しがずれると黙って外れる。** sh は承認済みチケットを探すツリーを `approval.trees` と同じ形に
   書き直して持つ。#120 ではこれがずれて、親のワークツリーに置いた子を見落としていた
3. **symlink をまたぐと外れる。** ワークスペースを論理の `pwd` から、ツリーを git の実際のパスから
   作るので、ワークスペースを symlink 越しに開くと（macOS の `/tmp` → `/private/tmp` など）比較が外れた

最初の案は「sh が実行ファイルに問い合わせる（`ccnavi tree --json`）」形だった。Sonnet と Opus の
敵対的レビューで、次の理由から捨てた。sh は実行ファイルを `CCNAVI_BIN_PATH` の環境変数から探すので、
エージェントが置いた偽物を指せば検査が開く（ADR-0028 が潰した `--review-fixture` と同じ形）。
加えて Python の読み方（`approval.scan`）は sh より狭く、寄せると止まっていたものが通るようになる。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 子のワークツリーからの `ccnavi-git.sh push` を、hook の組み込みで誰が打っても止める（`DENY_CHILD_PUSH`） | hook は `settings.json` の env で起動するので、コマンドの前の代入の影響を受けない。居場所は payload の cwd と `cd` の追跡（6.3.2）で決まる | sh から実行ファイルに問う。上のとおり |
| 止める広さは sh に合わせる。登録されていない `.claude/worktrees/<名前>`、閉じた子（`done/`）、レビュー待ちの子（`review/`）、YAML として読めないチケットも、`parent:` の行があれば子と見る | `approval.scan` に寄せると、この 4 つが通るようになる | Python の読み方に合わせる |
| `cd` の行き先が読めない形で push を打つと止める | どのツリーから送るかが決まらない。書き直す道は必ずある（行き先をそのまま書く） | 読めないときは見送る。sh の検査だけが残る |
| 保護済みの sh（`ccnavi-*.sh`）を呼ぶコマンド行で、`CCNAVI_*` と `CLAUDE_PROJECT_DIR` を置く・外す形を、組み込みで止める（`DENY_SCRIPT_ENV_OVERRIDE`） | 拒否されたエージェントが言い換えて再試行する形そのもので、2.1 の「逸れていく LLM」の範囲 | sh の側で環境変数を無視する。テストと人の設定（`CCNAVI_PROJECTS` を変えた配布先）が使えなくなる |
| 関数の定義の本体（`f() { …; }`）も、走るものとして見る。`env -i` も止める | 敵対的レビューで、関数で包むだけで 2 つの判定が両方とも素通りすると分かった（読みは縮退しないので、確認にもならない）。`env -i` は settings.json の env が書き出した置き場を消し、sh を既定の置き場へ向ける | 関数の定義を読み切れない形として確認にする。人に同じ確認が増える |
| 置いてよい変数は並べる（`CCNAVI_GIT_MAX_LINES`・`CCNAVI_GIT_FAIL_LINES`・`CCNAVI_GIT_KEEP_LOGS`・`CCNAVI_FETCH_TIMEOUT`）。残りは止める | sh があとから読むようになった変数は、止まる側になる | 止める変数を並べる。足し忘れると素通り |
| 2 つとも組み込みに置く | ルールは空にできるので、守りの根拠が守られる対象の中に入る（ADR-0021 と同じ理由）。P4 の「ガード自身を守るもの」に数える | rules.yml に書く |
| sh の検査は残し、symlink の穴だけ直す | hook の登録が壊れた・hook が効かない環境でも、sh が止める | sh の検査を外して 1 か所にする。hook が効かないと何も止めない |
| hook と sh に同じ見本（`tests/guard/test_wrapguard.py` の `CHILD_CASES`）を渡す | 同じことを 2 つの実装で持つので、ずれは見本で捕まえる | — |
| 原則 P13 を置く：止める・通すの判定は hook と実行ファイルが持ち、sh の検査は 2 重目 | sh に何を書いてよいかの線が無いまま、sh が状態を読んで止める形が増えていた | — |

P13 は「運ぶ対象を決めるためにツリーを数える」ことを判定に数えない。`ccnavi-push-approved.sh` と
`ccnavi-fetch.sh` は実行ファイルを起動しない（承認の直後、実行ファイルが入れ替え中でも運べるように）ので、
ツリーを自分で数える。これは止める・通すではない。

## 得たもの・失ったもの

- 得たもの: 環境変数を前に置いて子の push の検査を外す道が閉じる。親エージェントが子のツリーから push する形を、
  プロセスの環境に左右されない場所で止める。sh の検査がずれても hook が先に止める
- 得たもの: symlink をまたぐ環境で sh の検査が黙って外れる穴がなくなる（写す版を人が写したあと）
- 失ったもの: **子の push の検査が 2 か所に残る。** 見本に無い形のずれは捕まらない
- 失ったもの: 環境変数を前に置いて保護済みの sh を呼ぶ普通の使い方も、エージェントからは止まる。
  人が端末で打つ分には効かない
- 失ったもの: 読み切れる形しか止まらない。前の Bash 呼び出しで `export` した変数と、スクリプトに書いて
  `sh <ファイル>` で走らせる形は見えない（12.1）。`sh -c "…"` は縮退して確認に回る
- 失ったもの: `cd "$X" && sh …ccnavi-git.sh push` のように、行き先が読めない push は親のツリーからでも止まる

## 採らなかった案

- **sh から実行ファイルに問う（`ccnavi tree --json`）。** 実行ファイルを差し替えれば開く。止める範囲が
  狭まる。sh だけが新しく実行ファイルが古いと、副命令を知らずに全部の push が止まる
- **hook に移して sh の検査を外す。** hook が効かない環境では何も止めない。緩む向き
- **`PATH` と `GIT_*` も止める。** `ccnavi-git.sh` は `GIT_CONFIG_*` などを自分で消している。`PATH` の
  差し替えで道具をすり替える形は 12.1 の「敵対的な回避」に入り、止めても `sh <ファイル>` で回れる
