# ADR-0048: ルールのレイヤーは、パスを持つツールは行き先で、持たないツールは全部の和で選ぶ

状態: 採用

## 状況

ルールは 3 つのレイヤー（共通レイヤー、自身のレイヤー、プロジェクトのレイヤー）から来る（設計 11.4）。1 回の判定にどのレイヤーを足すかは、
ツールごとに決める必要がある。

レイヤーを選ぶ側（`ruleload.rules_for`）が決めていたのは、Read・Write・Edit・NotebookEdit（行き先のレイヤー）と Bash・PowerShell（全部の和）
だけで、それ以外のツールは共通レイヤーだけで判定していた。そのため次の 2 つが起きていた。

- 自身のレイヤーやプロジェクトのレイヤーに `match: WebFetch` / `Skill` / `Agent` / `Grep` / `Glob` のルールを書いても一度も当たらず、
  `--lint` も知らせない。書いたユーザは適用されていると思い込む
- 判定側（`judge.PATH_TOOLS`）は Grep・Glob をパスを持つツールとして扱う（探す場所を省けば `cwd`）のに、レイヤーを選ぶ側の一覧には
  入っていない。`lib` のレイヤーで `*/secrets*` を deny にすると、Read は止まり、同じ場所を Grep・Glob で探すと止まらない

## 決定

**ツールを、行き先のパスを持つかどうかで 2 つに分ける。**

| ツール | 足すレイヤー |
|---|---|
| パスを持つ: Read / Grep / Glob / Write / Edit / NotebookEdit | 共通レイヤー + 行き先のツリーのレイヤー（プロジェクトならそのレイヤー、ワークスペースのツリーなら自身のレイヤー） |
| パスを持たない: Bash / PowerShell / WebFetch / Skill / Agent | 共通レイヤー + 自身のレイヤー + 全プロジェクトのレイヤー（和） |

- 行き先は `judge.subject_of` が解いたパス。Grep・Glob が探す場所を省いたときは `cwd`
- パスを持つツールの一覧は `ruleload.PATH_TOOLS` の 1 か所に置き、判定側（`judge.PATH_TOOLS`）はそれを使う
- 一覧に無いツールは、ルールを当てる対象を持つ限り和で判定する

## 理由

**パスを持つツールは、どのプロジェクトの呼び出しかが行き先で 1 つに決まる。** 決まるなら、そのプロジェクトのルールだけを当てる。
Read と Grep・Glob は同じ場所を読むので、同じレイヤーで判定しないと、読み方を変えるだけで保護が外れる。

**パスを持たないツールは、どのプロジェクトの呼び出しかを決める材料を持たない。** Bash は `cd` を挟めば `cwd` の外に届き、
WebFetch・Skill・Agent は行き先のパスそのものを持たない。当てずに和を取れば、`deny` と `ask` は増えるほうになる（ADR-0033 と同じ理屈）。

**共通レイヤーだけで判定すると、レイヤーに書いたルールが知らされないまま適用されない。** 適用されないルールを書ける形は、足したつもりで何も止めていない 1 行を生む。

## 得たもの・失ったもの

- 得たもの: 自身のレイヤーとプロジェクトのレイヤーに書いた WebFetch・Skill・Agent・Grep・Glob のルールが適用される
- 得たもの: Read・Grep・Glob で、同じ場所の保護が揃う
- 失ったもの: パスを持たないツールで `allow` を共有する。プロジェクト A のレイヤーで WebFetch や Skill を `allow` にすると、プロジェクト B の作業にも適用される。
  共通レイヤーの `ask` はレイヤーの `allow` より先に当たるので緩まない
- 失ったもの: Grep・Glob でも、行き先のプロジェクトの `allow` が適用されるようになり、許す範囲がそのツリーの中で広がる
- 失ったもの: Grep・Glob はディレクトリを再帰的に探すが、レイヤーは探し始める場所の 1 つで選ぶ。ワークスペースルートから探すと、中のプロジェクトのレイヤーは足さない。
  ルールも探し始める場所のパスに当てるので、`*/secrets*` のようなルールは、`secrets` を含まない場所から探すとレイヤーをどう選んでも当たらない。
  レイヤーの選び方で差が出るのは、パスによらず当たる広いルール（`match: Grep`・`glob: "*"` など）だけ
- 失ったもの: 実行後チェックが見るツリーは、Grep・Glob では探し始める場所になる。Grep・Glob は書き込まないので、差し戻す変更は増えない
- 失ったもの: パスを持たないツール（WebFetch・Skill・Agent を含む）は、呼び出しのたびにプロジェクトの数だけレイヤーのファイルを読む。1 本 7ms ほど

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| 今のまま、パスを持たないツールは共通レイヤーだけにし、レイヤーに書いたルールを `--lint` が warn で知らせる | レイヤーで WebFetch などを制御する手段が無いまま残る |
| パスを持たないツールは全レイヤーの `deny`・`ask` だけを足し、`allow` は共通レイヤーだけにする | 緩む方向にならないが、Bash と扱いが違い、「allow だけ適用されない」という規則が 1 つ増える |
| Grep・Glob は共通レイヤーだけのまま | Read と保護が食い違ったまま残る |
| Grep・Glob は、探し始める場所がプロジェクトを含む（ワークスペースルートや `projects/`）なら全部の和にする | 当たるようになるのはパスによらず当たる広いルールだけで、`*/secrets*` のようなルールは和にしても当たらない。代わりにその場合はレイヤーの `allow` も適用され、判定の規則が 1 つ増える |
