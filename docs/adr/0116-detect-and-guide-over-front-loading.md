# ADR-0116: 決まりを先に詰め込まず、危険と失敗を起きた時点で検知して案内する

状態: 採用

## 状況

エージェントへの案内は、はじめは決まりを先に渡す形だった（起動時や文書に「こうしない」を並べる）。
運用で見つかった失敗には、この形が効かなかったものがあった。

- 古い統合先からワークツリーを切る
- ワークツリー名の食い違い
- 番号の誤検知

決まりを先に積んでも、作業の最中には読み返されず、同じ失敗が起きた（たとえば、ワークツリーを切る前に fetch する手順は
文書にあったが、読まれずに古い統合先から切った）。
そこで、起きた時点で hook と `--lint` が検知し「何が起きたか・代わりに何をするか」を返す形に改めた。効果は、これから運用で確かめる。
先に積むほど起動時の文脈が膨らみ、肝心の判断が薄まる問題もあった。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 起動時に渡すのは最小の案内だけにし、決まりを全部は入れない | 先に積んだ決まりは作業中に効かず、文脈も薄まる | 決まりを起動時の案内や CLAUDE.md に足し続ける |
| 危険な作業とよくある失敗は、hook と `--lint` が起きた時点で検知し、その場で「何が起きたか・代わりに何をするか」を返す | 失敗の直後は、案内が作業に直接つながって効く | 事前の注意書きだけに頼る |
| 判定は変えず、案内を足す形を基本にする | 止める・通すの境界を動かさず、副作用なく直せる | 失敗のたびに deny を増やす |
| 新しい失敗が見つかったときも、まず検知して案内する道で直す | 直し方を 1 つに揃え、積み増しに戻らないため | 新しい失敗ごとに決まりの文を足す |

## 得たもの・失ったもの

得たもの: 起動時の文脈が軽く保たれ、失敗は起きた場で解消される。失敗の種類が増えても案内の置き場が検知の側に決まる。

失ったもの: 失敗が 1 度は起きる。検知の条件を誤ると（番号の誤検知のように）案内が空振りするので、検知の側のテストと見直しが要る。

## 採らなかった案

- 決まりをすべて先に渡す: 作業中に効かず、起動時の文脈を汚す
- 検知なしで事前の注意書きだけにする: 失敗が起きたことに気づけない
