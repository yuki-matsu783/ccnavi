# ADR-0080: 残った指摘は 1 件ずつ行き先を決め、ボードで選べるようにする

状態: 採用

## 状況

2026-09-23、レビューで残った指摘の扱いを見直した。前の形は端末の `decide` だけで、選べるのは
残った指摘の**全部をまとめて**「受け入れて進む（`a`）」か「続きの子を起こす（`f`）」かの 2 つだった。

- 実際の判断は指摘ごとに違う（この指摘は直す、あれは対応しない）。まとめてしか選べないと、人は
  全部を直すか全部を見送るかに寄せることになる
- 3 つ目の行き先（別の issue に回す）は `to-issue` という別の命令で、エージェントが題と本文を書いて
  issue を作り、そのあと人が `decide` で受け入れる、の 2 手だった
- 承認はボードで完結する（ADR-0040）のに、この判断だけ端末へ行く必要があった。ADR-0040 は
  「拡張に移すにはその結果を JSON で返す契約が別に要る」と書いて残していた

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 行き先は指摘ごとに、対応しない（`keep`）・このフェーズで直す（`fix`）・issue に回す（`issue`）の 3 つから選ぶ | 判断の単位は指摘。選んだ行き先がそのまま記録（`accepted.json`・続きの子の本文・issue）に残る | 一括の二択を残す。画面に移しても「a / f が変」の根は残る |
| `to-issue` をやめて `decide` の行き先に畳む。issue は人が選んだ分から sh が作る | 切り出すかどうかは人の判断で、2 手に分かれている理由が無い。題と本文は指摘から組める | `to-issue` を残す。人の判断の前に、エージェントがホストへ書き込む道が残る |
| issue に回せるのはフィードバック計画が承認されたあとだけ | それまでは同じフェーズに子を足して応える道がある（前の `to-issue` と同じ線） | いつでも回せる。計画の途中で指摘が外へ逃げる |
| 1 件でも直すなら続きの子を起こしてフェーズを開き直し、直さない分は受け入れる | 一部だけ直す、が実際の判断。直す分は受け入れないので、次の `confirm` がまた数える | 直す分があるときは他も受け入れない。人が見送ると決めた指摘を、何度も数え直すことになる |
| ボードは承認と同じオーバーレイで、`decide <N> --preview`（一覧と指紋）と `decide <N> --choices <JSON> --digest <指紋>` を子プロセスで打つ。打つのは sh（ホストを読むため） | 実行ファイルはネットワークに出ない（ADR-0028）。見せたあとに指摘が変われば、指紋が合わず何も置かない | 拡張がホストを読む。判定と外を見に行く道が拡張にもできる |
| ボードの経路は端末を求めない。代わりに、`--approve` / `--reviewed` と `--yes` の組、sh の `--choices` と `--digest` の組を、組み込みの deny（`DENY_TICKET_APPROVAL_CLI`）がコマンド行の生の文字列の全体から探して止める。外すのは、並んだコマンドが全部表示・検索・閲覧の道具のときだけ | 承認の `--yes` と同じ守り（ADR-0040）。`--yes` は端末を求めないので、ここが唯一の守り。敵対的レビューで、実行ファイルの綴りやコマンドの位置で見分ける形は、名前を変えた写し・`awk` の `system()`・`python -c` の引数のリスト・引用の分け書きで抜けた | 端末の壁を残す。拡張の子プロセスは端末を持たず、壁ごと切ることになる。コマンドの位置で見る。上のとおり抜ける |
| 端末の `decide <N>` も 1 件ずつ聞く（`k` / `f` / `i`）。知らない文字でやめ、何も置かない | ボードと端末で選べるものを揃える | 端末は一括のまま残す |

## 失うもの

- `--reviewed` の経路に端末の壁が無くなった。人が押したことの証拠は「見せた指紋の一致」と「組み込みの
  deny」の 2 つで、指紋は秘密ではない（エージェントも `--preview` で読める）。守りは実質 hook だけで、hook が
  見えない形（綴りを組み立てて隠す、ファイルに書いたスクリプトを別の呼び出しで走らせる）は通る。承認の
  `--yes`（ADR-0040）と同じ構造。塞ぐなら、拡張だけが持つ秘密で選択に署名し、実行ファイルがそれを確かめる
  形が要る（今は入れない）
- この綴りをシェルで探す・書くコマンドも止まる（`sed` での置換など）。Grep ツールと Edit ツールで済む。
  コミットの `-m` の文面は実行されないので外す（コマンド置換を含むときは外さない）
- 指摘が多いと、ボードで 1 件ずつ選ぶ手間が増える。まとめて選ぶ操作は今は持たない
