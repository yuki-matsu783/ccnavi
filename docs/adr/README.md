# 設計判断の記録（ADR）

設計書 [docs/design.md](../design.md) は「いまの実装がどう作られているか」だけを書く。
「なぜそう決めたか」「以前はどうだったか」「何を採らなかったか」は、判断 1 つにつき 1 枚、ここに置く。
一度やめた道へ戻らないための記録で、設計書を読んで「なぜ」が気になったときに引く。

書式は 1 枚ごとに同じ。

| 見出し | 書くこと |
|---|---|
| 題 | `# ADR-<番号>: <題>`。番号はファイル名の先頭 4 桁と合わせる |
| 状態 | `採用`、`提案`（決めたが、段階を分けて入れるので有効になっていない部分があるもの。括弧で入れた範囲を書く）、または `置き換え（ADR-NNNN）`。題の次の行に置く |
| 状況 | 何が問題だったか。以前の形があればそれも。日付は書かない（git の履歴が持つ）。要件書・設計書を指すときは行数や節番号でなく、文書名と見出し・項目の言葉で書く（[書き分け](../claude/docs-writing.md)） |
| 決定 | 何にしたか。1 段落、または「決めたこと / なぜ」の表 |
| 理由 | なぜその側を採ったか。決定が表なら、表の「なぜ」の列がこれを兼ねる |
| 得たもの・失ったもの | 決定の代償。無いなら「無い」と書く。**唯一の必須** |
| 採らなかった案 | 比べた案と、落とした理由。決定が表なら、表の「採らなかった側」の列がこれを兼ねる |

決定が十数個の判断をまとめた表になる枚（0024、0029、0030）では、理由と採らなかった案を表の列が
兼ねる。そのぶん、**行単位で後から覆されたときに「置き換え」が使えない**ので、覆した側の ADR 番号を
その行に書き添える（0024 の `ccnavi-review.sh` の行がその例）。

状態は「採用」「提案」か「置き換え（ADR-NNNN）」。決定をまるごと覆したときは新しい 1 枚を足し、古い側の
状態を「置き換え」にする。古い 1 枚は消さない。

番号は 1 枚につき 1 つで、**重複させない**。足すときは、`origin/main` を取ってきたうえで
最後尾の次を採る（重複は並行して伸びた枝が合流したときに起きる）。

重複させてしまったら、引かれている数が少ないほうを空き番号へ動かし、下の「動かした N 枚」の表に
古い番号を残す。数がほぼ同じときは、保護された場所（`.ccnavi/scripts/`・`.ccnavi/config/common/`）から
引かれている側を残す。そちらを動かすと、書き換えにユーザの手が要る。「後から置いたほう」を動かす
（テストの ID で採った決め方、issue #88）のと逆にしたのは、後から置いた側が本文と実装から
何十か所も引かれていることがあるため。数え方は「追跡されているファイルのうち、その枚自身を
除いて `ADR-00NN` と書かれている行」。

**動かすと失うものがある。** (1) 番号が置いた順でなくなる（0064 は 0062 より先に決めたのに
番号は後ろ）。(2) git の履歴と、GitHub の issue・PR の本文は書き換えられない。そこに書かれた
古い番号は、いまは別の決定を指したままになる。(3) 古いファイル名へのリンクは切れる。動かすのは、
「`ADR-00NN` と書かれた参照がどの決定を指すか読めない」ほうが重いと判断したときだけ。

`tests/core/test_adr_numbers.py` が、番号の重複と、題が `# ADR-<番号>:` で始まることと、「一覧」に
置いてある ADR が 1 回ずつ載って番号が合っていることを確かめる。**ただしこのテストは、ADR を足した
だけのコミットでは回らない**（コミットの検査は「ドキュメントだけなら回さない」ため）。
重複が合流するまで気づけないのは変わっていない。気づく時点が「誰かが `core` を回したとき」に
早まっただけ。

動かした 18 枚。最後の 1 枚は、main に先に入った 0146 と後から合流した Stop の AI 判定の ADR が同じ番号を採ったもので、後者を 0153 へ動かした。数は動かした時点のもので、後から増えても直さない。判断の根拠として残してある。最初の 3 枚は issue #98（main の `e927ede`）。4 枚目は #101 と #104 が別々に 0066 を採ったまま合流したもので（main の `a5a0a61`）、5 枚目はその直し（#106）と #105 が同じ 0067 を採ったもの（main の `bdaa289`）。6 枚目は 5 枚目で残した 0067 と #102 の 0067 が合流したもの（main の `5548a45`）。7・8 枚目は #115 と #116 が別々に 0073 を採って main で合流し、そこへ 3 本目の 0073 が合流したもの（3 枚が同じ番号になったので 2 枚動いた）。9 枚目は #286 と plan-order-core（#275）が別々に 0109 を採ったまま合流したもの。空いていた 0110 は同じ時期に main へ入った別の ADR が採っていたので、0111 にした。10 枚目は #304 と #302 が別々に 0115 を採ったまま main で合流したもの。11・12 枚目は、main の #296 と #302 が採った 0114・0115 と、生の git の組み込みの止めの枝（claude/sweet-bell-duunub）が採った 0114・0115 が合流したもの。いったん空いていた 0116 と、0117 の次の 0118 にしたが、0116 は同じ時期に main で 10 枚目が採ったので、もう一度 0119 へ動かした。13 枚目は、main の #324 が採った 0120 と、親は計画を必ず持つ決まりの枝が採った 0120 が合流したもので、あとから合流した枝の側を 0121 へ動かした。その 0121 は、git のラッパーで自己防衛の対象を消す形を止める枝（claude/practical-einstein-qkxtal）が採った 0121 とまた合流したので、もう一度動かした。0122 はその枝がもう採っていたので、0123 にした。16 枚目は、main の #396 と #398 が別々に 0133 を採ったまま合流したもので、引かれている数が少ない #396 の側を 0134 へ動かした。17 枚目は、テンプレート管理画面の直接保存の ADR と、ワークスペース内 clone と単体 clone の ADR が別々に 0145 を採ったまま main で合流したもので、引かれている数が少ない前者を 0149 へ動かした。
