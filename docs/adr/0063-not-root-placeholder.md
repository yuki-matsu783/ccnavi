# ADR-0063: ワークスペースの外は、先読みではなく展開で書く

状態: 採用

旧番号: 0058（番号が 2 つの決定に付いていたので動かした。issue #98）

## 状況

ルールファイルで「ワークスペースの外」を指す手が無かった。書けるのは
「外の置き場を名指しする」形までで、`outside-temp` が一時ディレクトリを 4 環境ぶん
列挙している。列挙に無い場所は素通りする。

書けない理由が 2 つ重なっていた。2026-09-17。

- **先読みが禁じられている。** `(?!...)` は契約で弾く（§5.3）。書ける範囲を狭く保つと
  ルールがエンジンをまたいでも同じ意味になること、そして先読みと後方参照が
  組み合わせ爆発を起こす書き方の入口であることによる。Python の `re` に時間制限は無く、
  判定が固まった hook は期限に達して素通りになる
- **`{root}` は 1 塊で埋まる。** 読み込み時にエスケープ済みの実パスへ置き換わるので
  （ADR-0032）、ルールを書く側が 1 文字ずつに割って否定を組み立てられない。
  ルートの綴りは機械ごとに違うので、直書きもできない

## 決定

**`{!root}` という合言葉を足し、読み込み時に「ワークスペースルートで始まらない」を
意味する式へ展開する。展開結果に先読みも繰り返しも含めない。**

ルートを 1 文字ずつ「ここで終わる（ルートより上）／ここが違う／ここは同じ」の入れ子に
分解する。

```
^(?:\Z|[^c]|c(?:\Z|[^:]|:(?:\Z|[^\\/]|[\\/](?:…))))
      └┘ └──┘ └──────────────┘
   ルートより上  綴りが違う      同じなら次の文字へ
```

最内はルートを全部なぞり切った位置で、そこに区切りでない 1 文字が続けば
`…/ccnavi-fork/x` のような別のディレクトリなので「外」と数える。**最内に `\Z` は置かない。**
そこで文字列が終わるなら対象はルートそのもので、中と数えるのが正しい。

| 決まり | |
|---|---|
| 書ける場所 | `regex` だけ。`glob` は fnmatch に翻訳されるので入れ子を埋める場所が無い |
| 置ける位置 | `^` の直後に 1 回だけ |
| 直後の量化子 | error。`^{!root}?` は展開結果ごと省略でき、どの対象にも当たる式になる |
| 後ろに続く式 | 書ける。`.*` のように任意の位置まで進む形で受けていなければ warn |
| ルートの正規化 | `realpath` したうえで末尾の区切りを落とす |
| 展開先 | どの層のルールでもワークスペースルートで固定（`{root}` と同じ） |

ルートが 256 字以上なら展開しない。組み立てられなかったルールは**強い側に倒す**。
`deny` と `ask` は `match` の全部に当たる式を持たせて止め、`allow` はどれにも当てない。

## 理由

- **展開なら契約を崩さない。** 出来上がる式は既存の語彙（捕獲しないグループ、否定文字クラス、
  錨）だけでできている。`_unsupported` が禁じるものを 1 つも含まない
- **繰り返しを含まないので爆発しない。** 各段の選択肢は最初の 1 文字でほぼ排他で、
  戻る余地がほとんど無い。判定は 12 マイクロ秒で、PreToolUse の期限 3 秒の 0.0004%
- **失敗を緩む側に落とさない。** 組み立てられなかった `deny` を捨てると、
  守られなくなる範囲が「外の全部」に広がる。報告だけでは足りないので、
  止める側に倒す（REQ-RUL-10）

## 得たもの・失ったもの

- 得たもの: 「中でなければ外」が書け、名指しの列挙が漏れる問題が消えた
- 得たもの: 判定の費用が実測済みで、期限に対して 5 桁の余裕がある（`tests/core/bench_not_root.py`）
- 失ったもの: **語彙が 1 つ増えた。** しかも `{root}` と性質が違う（`glob` に書けない、
  前に置けない、直後に量化子を置けない）。error と warn で補うが、覚えることは増える
- 失ったもの: **組み立てが毎回 +3 ms。** hook は呼び出しごとに別プロセスなので毎回走る。
  `{!root}` を使うルールの本数だけ積まれる
- 失ったもの: ルートが 256 字以上の機械では、利用者が手でルールを外すまで
  そのルールが見るツールが全部止まる。`rules.yml` は守られているのでエージェントには外せない
- 失ったもの: **`_build` の戻り値を広げた。** 全部のルールが通る経路で、
  「苦情を出しつつルールも採る」形が増えた

## 採らなかった案

- **前置きを 1 文字ずつ伸ばして並べる（列挙型）。** 式の長さがルートの長さの 2 乗で伸びる。
  436 字のルートで 141,365 字・組み立て 481 ms になり、判定の期限に達する
- **判定側に「ルートの中か」の関数を持ち、正規表現に展開しない。** いちばん速く、
  再帰の上限も無い。ただしルールファイルから条件を書けなくなり、組み込みルールになる。
  「ルールは人が持つ」という構造から外れる
- **`(?!...)` の禁止を `{!root}` の展開時だけ免除する。** 実装は数行で済むが、
  「エンジンをまたいでも同じ意味」の契約が崩れる
- **ルールに `outside: root` の欄を足す。** `glob` とも組めて、断片として合成できない
  問題も起きない。欄が増える代わりに `glob` / `regex` との組み合わせを lint が見る必要がある

## 補足

しきい値 256 は、この形の入れ子で `re.compile` が `RecursionError` になる 493 字の半分以下。
Windows の `MAX_PATH` が 260 なので、256 字のルートはその時点で実用にならない。
**組み立てが落ちる長さは展開の形で変わる。** 1 文字あたりの入れ子の段数を変えたら
`tests/core/bench_not_root.py` を回して測り直すこと。

大文字小文字を区別せずに当てるので（ADR-0051）、大文字小文字だけが違うパスは「中」と数える。
ファイルシステムでも同じ場所なのでこれが正しい。ただし `re.IGNORECASE` は
トルコ語の `İ`（U+0130）と `ı`（U+0131）を ASCII の `I`/`i` と同一視するため、
本当は別の場所でも「中」になる。既知の例外として受け入れる。
