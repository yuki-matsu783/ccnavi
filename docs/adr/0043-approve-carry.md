# ADR-0043: 承認済みチケットは sh がコミットして push し、範囲の超過は判定で止め、ボードの承認はダイジェストで照合する

状態: 採用

## 状況

- ボードの承認はコミットと push をしなかった。 承認済みチケットのコミットと push は
  `ccnavi-approve.sh` の後半にしか無く、VS Code 拡張のボードで承認すると、承認済みチケットは
  置き場に置かれても、コミットと push はされなかった
- 子の範囲の超過は承認で必ず弾かれた。 子の範囲が親の範囲かフェーズの種類の scope を超えると
  承認で error になり、判定を dry-run にしていても、提案を書き直すまで承認できなかった。
  種類の scope が使われるのは承認のときだけで、判定は親の範囲でしか切り詰めていなかった
- ボードの `--yes` は識別子しか比べなかった。 見せてから押すまでに提案の中身が書き換わると、
  見ていない中身が承認された

## 決定

| 何 | 前 | 後 |
|---|---|---|
| 承認済みチケットのコミットと push | `ccnavi-approve.sh` の後半 | `ccnavi-push-approved.sh` に切り出す。端末の承認は `ccnavi-approve.sh` から、ボードの承認では利用者の端末にコマンドを送って呼ぶ |
| エージェントがコミットと push を行う sh（`ccnavi-push-approved.sh`）を打つ | ― | 組み込みの deny（`DENY_TICKET_APPROVAL_CLI`）で止める。表記の大文字小文字は区別しない。sh の側で標準入力が端末かは確かめない |
| 子の範囲が親・種類の scope を超える | 承認で error | 承認で warn（承認画面で示す）。判定で親と種類の scope の両方で切り詰める |
| ボードの承認 | 識別子の一覧を比べる | `--approve --preview --json` が返す `digest` を `--digest` で渡し、承認のときに読み直した中身のダイジェストと比べる。違うか、渡されなければ何も置かない |
| phases.yml の読み込みの例外 | 判定の外へ出る | 壊れているとして扱う。種類では切り詰めず notice を出し、親の範囲では切り詰める |

ダイジェストを取る対象は、承認画面の本文と、一括承認のチケットごとに承認のとき書き出す中身（新規は提案の
frontmatter と本文、改版は計画を差し替えた承認済みチケット。`ccnavi_approved` は除く）。
ダイジェストは、部分ごとの SHA-256 を件数と並べたものから取った全体の SHA-256 で、区切り文字ではつながない。

## 理由

- push は外へ送り出す操作で、いつ送るかを決めるのは人。コミットと push だけを sh に分ければ、端末でもボードでも
  同じ手順で送れ、エージェントからの実行は組み込みの deny 1 か所で止められる
- 書き込みを止めるのは判定。判定が親と種類の scope で切り詰めれば、超えた部分を承認しても書けない。
  承認で止めるのをやめれば、dry-run の間も提案を書き直さずに進められ、判定の記録で「enable なら止めた」と示せる
- 判定が例外で終わると終了コード 1 になる。Claude Code は終了コード 1 を止める合図として扱わないので、止めるはずの
  書き込みが通る。例外を deny として扱うと、人が phases.yml を編集している間、全部の子の書き込みが止まる。
  phases.yml は保護されたコアファイルなのでエージェントには壊せない。また、親の範囲での切り詰めは残る
- 画面の本文だけからダイジェストを取ると、画面に出ない内容（`issue` キーの値、Markdown の本文、知らないキーの値）を
  画面で見せたあとに書き換えても承認が通る。書き出す中身までダイジェストの対象にすれば、見せたものと置くものが一致する

## 得たもの

- ボードで承認しても、承認済みチケットがコミットされて push される
- 超過のある子を dry-run で承認でき、何が止まるはずだったかを判定の記録で見られる
- 種類の scope が、承認のときだけでなく書き込みのたびに適用される
- 見せてから押すまでに書き換わった中身は承認されない
- phases.yml が壊れても、判定が例外で落ちない

## 失ったもの

- 承認のたびに端末でコマンドが実行される。 ボードで押すと、利用者の端末にコミットと push が送られる
- 承認できても、超えた部分は書けない。 承認画面の warn を見落とすと、作業の途中で判定に止められて気づく
- 本文を直しただけでも押し直しになる。 見せたあとの書き換えは、中身によらず `mismatch` になる
- 超過があっても `--lint` の CI は失敗しない。 超過は承認の error ではなくなり、warn で通る
- phases.yml が壊れている間は種類の上限が適用されない。 notice と `--lint` の error で気づかせる

## 採らなかった案

- コミットと push を行う sh に、標準入力が端末かどうかの検査を入れる。 push はそこまで守らなくてよいと決めた（2026-09-14）。
  止めるのは組み込みの deny だけにする
- エージェントにコミットと push をさせる。 push の時機を決めるのが人でなくなる（2026-09-13 の決定）
- 承認の処理がモードを読み、dry-run のときだけ超過を緩める。 承認済みチケットの意味が、承認した
  ときのモードで変わる。enable に戻したあとも緩めて承認したものが残る。判定で止めれば、モードによる違いを
  判定の中だけで扱える
- 画面の本文だけからダイジェストを取る。 画面に出ないキーの値を画面で見せたあとに書き換えても、承認が通る
- 超過の一覧だけを照合する。 超過以外の中身の書き換えを見逃す

## ADR-0023 との関係

ADR-0023 は、承認済みチケットと提案の照合をやめた。この ADR のダイジェストは、承認したあとの一致ではなく、
見せてから押すまでの一致を確かめるもので、目的が違う。ADR-0023 の決定は変えない。

敵対的レビューで決めた経緯はマージリクエスト #29 の記録にある。
