# ADR-0093: 診断ログは sh・Python・拡張の 3 つの logger が同じ形で `logs/diag/` に書き、判定の記録とは分ける

状態: 採用

## 状況

あとから「何が起きたか」を追う手段が、言語ごと・スクリプトごとにばらばらだった。sh は標準エラーの文面と
`logs/git-*.log`（`ccnavi-git.sh` の全量）のほかに残すものが無く、拡張は `console.error` へ出して開発者ツールを
開いていないと読めなかった。判定の記録（`logs/decisions.jsonl`）は 1 回の判定の証跡で、判定の外で起きたこと
（承認のコミットが push で落ちた、fetch が認証で落ちた、hook が差し戻した）は入らない。逆に、判定の記録へ診断を
混ぜると、「記録が無ければ動かなかった」と読む元（ADR-0089）が濁る（2026-09-27）。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 置き場はワークスペースルートの `logs/diag/<出どころ>.log`。出どころは固定の短い語（`ccnavi`・`ccnavi-git`・`ccnavi-board`）で、`[A-Za-z0-9_-]` 以外の字を含む名前では書かずに捨てる | 判定の記録（`logs/decisions.jsonl`）や git のラッパースクリプトの記録（`logs/git-*.log`）と名前で紛れない（ADR-0092）。名前にパスや利用者の入力が入ると置き場の外を指せる。置き換えると別の出どころとぶつかる | 判定の記録に `diag` の欄を足す。ADR-0089 の読み方が濁る |
| 行の形は `<時刻> <レベル 5 字> <出どころ>[<pid>] <本文> key=value…` の 1 事象 1 行。時刻は現地時刻と時差で秒まで。値は logfmt で、空白・タブ・`"`・`=`・改行を含むときだけ囲み、改行は `\n` の 2 字に畳む。sh・Python・TS の 3 つが 1 字まで同じ行を出す（`tests/sh/test_diaglog_sh.py`） | どの言語が書いた行も同じ道具（`grep`・`awk`）で読める。BSD の date はミリ秒を出せないので 3 つとも秒 | 言語ごとの標準の logger（`logging`・`console`）の形。行の形が 3 つに割れる |
| 書く下限は `CCNAVI_LOG_LEVEL`（`DEBUG` / `INFO` / `WARN` / `ERROR`、大文字小文字を問わない）。既定と読めない値は `INFO`。受け付けた操作・判定の結果・拒否の理由・最終の結果（終了コード）が `INFO`、判定の材料が `DEBUG` | 既定で 1 回の起動につき数行に収め、材料は要るときだけ出す | 既定を `DEBUG`。hook の呼び出しの数だけ行が増える |
| ツール呼び出しのたびに走る hook（実行ファイルの判定、開発用の `mark-ext.sh`・`lint-py.sh` の通した側）は、判定の結果も `DEBUG` に置く | 既定の `INFO` で hook の呼び出しの数だけ行を増やさない | 判定の結果はいつも `INFO` |
| 実行ファイルの副命令（hook 以外）は入口の `cli` が `cmd=<固定の名前>` で受け付けと終了コードを書く。状態を変える副命令は `INFO`、読むだけの副命令（`--lint`・`--test`・`--explain`・`--suggest`・`*-preview` など）は `DEBUG` | 拡張はファイルの変化のたびに読むだけの副命令を打つので、`INFO` だと hook と同じく行が積もる。状態を変える操作は低頻度で、誰が何をしたかを既定で残したい | 副命令はすべて `INFO` |
| **fail-open。** 書けない（置き場が作れない・権限・容量・リンク）ときは黙って捨て、何があっても本体の出力と終了コードを変えない。sh の `log_*` は `set -eu` の下でも 0 を返す | 診断ログは補助。ログの成否で判定や操作が変わると、診断のための仕組みが事故の元になる | 書けなければ止める |
| **標準出力にも標準エラーにも出さない。** hook の標準エラーと exit 2、hook の JSON、`reject` / `fail` の文面、`ok  git …` の結果行、`ccnavi-fetch.sh` の標準出力は契約のまま変えない | 標準出力はモデルの文脈に入り、標準エラーは利用者とモデルへの文面。どちらもテストが文面を固定している | 標準エラーへ重ねて出す。文面が変わり、モデルの文脈も埋まる |
| **リンクを辿らない。** `logs`・`logs/diag`・書き先のどれかがシンボリックリンクなら書かない（sh は `[ -L ]`、Python は lstat と `O_NOFOLLOW`、TS は `lstatSync`）。片付けも辿らず報告に出す | リンクの先へ追記すると、置き場の外（`logs/decisions.jsonl` など）を書き換えられる | リンクを辿る。上の穴 |
| 新しいファイルは 0600 で作る。既にあるファイルの権限は変えない | 行にはパスや識別子が入る。同じ機械の他の利用者に読ませない | umask に任せる |
| 本文と値に同じ伏せ字を当てる（URL の authority の `user:tok@`、scp 形の `user:tok@host:`）。Python はさらに `ccnavi/redact.py` を通す。伏せ字は最後の網で、一次の守りは秘密の値を渡さないこと | 利用者の引数に資格情報が混ざる。3 つで綴りを揃え、同じ入力が同じ行になる | 伏せ字だけに頼る |
| 拒否は文面ではなく、種類を表す kebab-case の識別子（`reason=unapproved-push`）だけを書く。sh の `reject` / `fail` は 1 つ目の引数に識別子を取る | 文面には利用者の引数（URL・パス）が入る。識別子なら数えて並べられ、秘密も入らない | 文面を写す |
| `logs/diag/` は自己防衛（selfguard）で守らない | 判定が読まない補助で、書き換えられても止める・通すの判定は変わらない。守る値打ちより hook のたびに控えを取る手間の方が大きい。リンクで置き場の外を書かせる道は、logger がリンクを辿らないことで塞ぐ | 判定の記録と同じく守る |
| 片付けは `ccnavi/prune.py` の `_prune_diag`。判定の記録と同じしきい値（`CCNAVI_LOG_ROTATE_MB`・`CCNAVI_LOG_KEEP_DAYS`）で、上限を超えた 1 本を `<出どころ>.<日時>.log` へ名前を変え（同じ秒にぶつかれば `-2` から）、保持日数のあいだ書かれていない `*.log` を消す。走るのはセッション開始と `ccnavi --prune` | しきい値を分けると、利用者が覚える変数が増える。後始末の仕組み（`O_EXCL` で押さえてから名前を変える）は ADR-0089 のものを使う | 診断ログ専用のしきい値 |
| 拡張の実行ファイル呼び出しは `ccnavi.ts` の `run` / `runScript` がまとめて 1 行書く。失敗・打ち切り・起動できないは `ERROR`、成功は `DEBUG` と所要時間。標準出力と標準エラーは中身を書かず長さだけ。拡張の `src/core/` は logger を持たない | 呼び手ごとに書くと漏れと重複が出る。子の出力には資格情報が混ざりうる。core は純粋な層に保ち、パースの失敗は呼び手が種類と長さで書く | 呼び手ごとに書く |

### logger を使わないもの

| もの | なぜ |
|---|---|
| `ccnavi-launcher.sh` | hook ごとに実行ファイルへ `exec` するだけのホットパス。共通部を読む重さを足さない。実行ファイルの側が書く |
| `scripts/ccnavi-setup.sh`・`scripts/ccnavi-build-install.sh`・拡張の `scripts/package.sh` と `scripts/*.js`・`.ccnavi/scripts/ccnavi-clean.js`・`build.py`・`tools/run_tests.py` | 配布前か手元の道具で、出力そのものが利用者向けの報告。`ccnavi-clean.js` は呼ぶ側の `ccnavi-clean.sh` が受け付けと結果を書く |
| `logs/session/` の状態ファイル（`<セッション>.trees` など） | ログではなく、開発用の hook のあいだで受け渡す状態 |
| 拡張の webview | Node の `fs` が無い。要るなら親のパネルへ送り、拡張ホストの側で書く |
| `tools/gitlab/probe_gitlab.py` の `steps.log` | 調査道具の成果物で、利用者が読むために残す報告 |

## 得たもの・失ったもの

- 得たもの: 承認の push、fetch の失敗、hook の差し戻し、拡張からの実行ファイル呼び出しの失敗を、あとから 1 か所で追える。
  3 つの言語の行が同じ形なので、同じ道具で読める
- 失ったもの: `logs/diag/` はエージェントが消したり書き換えたりできる。診断ログは証跡にならない（証跡は判定の記録）
- 失ったもの: `logs` を別の場所へのリンクにしている環境では、診断ログは残らない
- 失ったもの: 開発用の hook（`.claude/hooks/`）は、ワークスペースの共通部（`.ccnavi/scripts/ccnavi-common.sh`）を読めるときだけ書く。
  読めない環境では何も残らない（hook の振る舞いは変えない）
- 失ったもの: `ccnavi-ticket.sh` と `ccnavi-clean.sh` は最終の終了コードを書くために実行ファイル・node を `exec` せず子として走らせる。
  プロセスが 1 つ増える（出力と終了コードは同じ）
- 失ったもの: sh と TS は Python の `redact` を持たず、URL と scp 形の資格情報だけを伏せる

## 採らなかった案

- **標準エラーに `[debug]` の行を足す。** 文面を固定しているテストと、モデルの文脈を汚す
- **syslog や OS のイベントログ。** Windows・macOS・Linux で綴りも読み方も揃わず、ワークスペースの外に出る
- **言語ごとの logger をそのまま使う。** 行の形・置き場・伏せ字が 3 つに割れ、同じ事象を横に並べて読めない
