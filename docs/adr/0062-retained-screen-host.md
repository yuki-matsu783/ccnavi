# ADR-0062: 保持する画面は、入れ物を入れ直さない段取りで React にする

状態: 採用

## 状況

ボード（ADR-0060）とプロジェクト管理を React にしたとき、拡張ホストが画面に中身を渡す段取りを
`core/screen-host.ts` に抜いた。この段取りは `retainContextWhenHidden` が**偽**の画面を前提にしている。
裏に回ると画面は捨てられ、表に戻ると入れてある HTML から作り直される、という VS Code の振る舞いに
乗って、裏にいる間は**入れ物ごと入れ直す**（`rebuilt`）。

残る 3 画面（ルール設定・リスク管理・フェーズ管理）は `retainContextWhenHidden` が**真**。
編集の途中を持つので、裏に回っても捨てられないようにしてある。ここへ同じ段取りをそのまま当てると
2 つ壊れる。**裏にいる間の入れ直しで、人が打ちかけていた内容が消える。** また `post()` は表に
出ていないと偽を返すので、いま裏でも送っている `{type:"lock"}` `{type:"changed"}` が届かなくなる。

決めないまま移行を始めると、下の案 1 と案 2 のどちらかを移行の途中で選ぶことになり、やり直しが出る。
2026-09-19、issue #82（#84・#86 の前提）。

## 決定

- **`core/screen-host.ts` に、保持する画面のための `retainedHost()` を足す。** 返る形
  （`ScreenHost<D>`）は `screenHost()` と同じで、パネルは作るところの 1 行だけが違う
- **入れ物（HTML）は 1 度しか入れない。** 2 枚目からは必ず `postMessage`。入れ直すと画面が
  作り直され、打ちかけの内容が消える
- **表裏（`surface.visible`）を見ない。`hidden()` は何もしない。** 保持する画面は裏でも生きていて、
  `postMessage` も届く。見て倒すと、裏にいる間の `lock` と `changed` の知らせが落ちる
- **`deferred` は 1 枚目だけ残す。** 入れ物を入れてから画面が組み上がる（`ready`）までの間は
  受け口が無い。ここは保持するかどうかに関わらず同じ
- **中身（`data`）を渡すのは、画面の編集を捨ててよいときだけ。** 人が「再読込」を押したときと、
  保存・作成が通って中身が入れ替わったとき。監視がファイルの変化に気づいても勝手に渡さず、
  帯（`changed`）を出して人に決めさせる。これは移行前の振る舞いと同じ
- **どちらを使うかはパネルが選ぶ。** `retainContextWhenHidden` と対で書き、取り違えを目で見つけられる
  ようにする。取り違えるとどちらの向きでも壊れる（保持する画面に `screenHost` = 編集が消える、
  保持しない画面に `retainedHost` = 捨てられた画面へ送り続けて中身が止まる）

## 理由

**編集の途中を Webview の state に写す案（案 2）より、段取りを 1 つ足す案のほうが失敗の代償が小さい。**
案 2 は段取りが 1 系統のまま済むが、写す仕事が画面ごとに要り、**写し漏れがそのまま「打った内容が
消える」事故になる**。ルール設定の欄数（ルール 1 件あたり 10 欄以上）で、漏れを型で縛る手段が無い。

**保持をやめると、判定の往復の間に画面が捨てられる道ができる。** 3 画面はどれも保存の前に実行ファイルへ
往復する（`--lint` / `--test`）。その間にタブを裏へ回されると、案 2 では画面が捨てられ、戻ってきた
答えの届け先が無くなる。保持したままなら往復は成立する。

**2 系統になる代償は、選ぶ場所が 1 か所に収まるので受け入れられる。** 選ぶのはパネルが
`createWebviewPanel` の隣で 1 行書くところだけで、以降の呼び方（`send` / `post` / `ready` / `hidden`）は
同じ。画面（React 側）は違いを知らない。

**案 3（3 画面は React にしない）は、作り方が 2 通り残る代償が続く。** 5 画面共通の部品を足すたびに
React 側と文字列側の両方に書くことになり、埋め込みの JS 約 1,200 行に型検査が効かないままになる。

## 代償

- 段取りが 2 系統になる。画面を足す人は、自分のパネルがどちらかを知っていなければならない。
  取り違えても型では止まらない（返る形が同じなので）。README とこのファイルが対で言う
- `retainedHost` は表裏を見ないので、**画面が生きていることを VS Code の設定（`retainContextWhenHidden: true`）に
  頼っている**。パネル側でその設定を落とすと、送り先が消えたことに気づけない
- 保持する画面は VS Code がメモリを抱えたままになる。これは移行前からの性質で、この決定では変えない
