# ADR-0062: 保持する画面は、入れ物を入れ直さない段取りで React にする

状態: 採用

## 状況

ボード（ADR-0064）とプロジェクト管理を React にしたとき、拡張ホストが画面に中身を渡す段取りを
`core/screen-host.ts` に抜いた。この段取りは `retainContextWhenHidden` が**偽**の画面を前提にしている。
裏に回ると画面は捨てられ、表に戻ると入れてある HTML から作り直される、という VS Code の振る舞いに
乗って、裏にいる間は**入れ物ごと入れ直す**（`rebuilt`）。

残る 3 画面（ルール設定・リスク管理・フェーズ管理）は `retainContextWhenHidden` が**真**。
編集の途中を持つので、裏に回っても捨てられないようにしてある。ここへ同じ段取りをそのまま当てると
2 つ壊れる。**裏にいる間の入れ直しで、人が打ちかけていた内容が消える。** また `post()` は表に
出ていないと偽を返すので、いま裏でも送っている `{type:"lock"}` `{type:"changed"}` が届かなくなる。

決めないまま移行を始めると、下の案 1 と案 2 のどちらかを移行の途中で選ぶことになり、やり直しが出る。
2026-09-19、issue #82（#84・#86 の前提）。

## 決定

- **`core/screen-host.ts` に、保持する画面のための `retainedHost()` を足す。** 返る形
  （`ScreenHost<D>`）は `screenHost()` と同じで、パネルは作るところの 1 行だけが違う
- **入れ物（HTML）は 1 度しか入れない。** 2 枚目からは必ず `postMessage`。入れ直すと画面が
  作り直され、打ちかけの内容が消える
- **表裏（`surface.visible`）を見ない。`hidden()` は何もしない。** 保持する画面は裏でも生きていて、
  `postMessage` も届く。見て倒すと、裏にいる間の `lock` と `changed` の知らせが落ちる
- **`deferred` は 1 枚目だけ残す。** 入れ物を入れてから画面が組み上がる（`ready`）までの間は
  受け口が無い。ここは保持するかどうかに関わらず同じ
- **中身（`data`）を渡すのは、画面の編集を捨ててよいときだけ。** 人が「再読込」を押したときと、
  保存・作成が通って中身が入れ替わったとき。監視がファイルの変化に気づいても勝手に渡さず、
  帯（`changed`）を出して人に決めさせる。これは移行前の振る舞いと同じ
- **どちらを使うかはパネルが選ぶ。** `retainContextWhenHidden` と対で書く。取り違えるとどちらの
  向きでも壊れる（保持する画面に `screenHost` = 編集が消える、保持しない画面に `retainedHost` =
  捨てられた画面へ送り続けて中身が止まる）ので、**渡す口の側で見て言う**。`retainedHost` が受ける口は
  表裏（`visible`）を持たず（読まないものを実装させない）、パネルは口を作るところで
  `panel.options.retainContextWhenHidden` を確かめて、偽なら記録に出す
- **表に戻ったら、いま出すべき知らせ（`lock`・`changed`）を送り直す。** VS Code の型定義は同じ
  ファイルの中で食い違っている。`postMessage` の側は「live な画面には届く。保持する画面は裏でも live」、
  `retainContextWhenHidden` の側は「裏に回った画面にはメッセージを送れない」。**どちらが正しくても
  壊れない形にする。** 送り直すのは知らせだけで、中身（`data`）は送らない（裏で打っていた編集が消える）

**追記（issue #87）。** 見た目（`{type:"appearance"}`）だけが、この段取りを通らずに
`panel.webview.postMessage` を直に叩いていた。送る先の生死を自分で見ず（表に出た瞬間はまだ
受け口が付いていないので落ちる）、表に戻ったときの送り直しも別に持っていた。**5 画面とも段取りを
通す形に揃えた。** 上の 2 行がそのまま当てはまる。保持しない画面は入れ物から作り直され `ready` で
渡し直され、保持する画面は表に戻ったところで `lock`・`changed` と一緒に送り直す。落ちたぶんを
持ち越す必要は無く、`sendAppearance` は届いたかどうかを返すだけにしてある。

## 理由

**画面を捨てて作り直す案（案 2）では、写せないものがある。** Webview の state に写せるのは値だけで、
**焦点の位置・選択範囲・スクロール・IME で変換している途中・入力欄の undo の履歴は写せない**。
設定 3 画面はどれも「長く開いて少しずつ直す」画面なので、タブを行き来するたびにこれらが飛ぶ。
保持したままなら VS Code が全部そのまま持つ。

**写す仕事は画面ごとに要り、漏れは事故になる。** React にした画面は編集の状態が 1 か所
（`Editing` と `dirty`）に集まっているので写すこと自体は数行だが、まだ文字列で組んでいる
ルール設定（1 件あたり 10 欄以上）は集まっていない。**写し漏れはそのまま「打った内容が消える」**で、
漏れを型で縛る手段が無い。

**保存をやめると、判定の往復の間に画面が捨てられる道ができる。** 3 画面はどれも保存の前に実行ファイルへ
往復する（`--lint` / `--test`）。案 2 でも、答えの届け先はホストが持ち直せる（`ready` で渡し直す
仕組みが既にある）が、**往復の間だけ立てている状態（欄を止めている `busy`）は、作り直しで消える**。
戻ってきた画面は「止めていたこと」を忘れ、人は二重に押せる。

**2 系統になる代償は、選ぶ場所が 1 か所に収まるので受け入れられる。** 選ぶのはパネルが
`createWebviewPanel` の隣で 1 行書くところだけで、以降の呼び方（`send` / `post` / `ready` / `hidden`）は
同じ。画面（React 側）は違いを知らない。

**案 3（3 画面は React にしない）は、作り方が 2 通り残る代償が続く。** 5 画面共通の部品を足すたびに
React 側と文字列側の両方に書くことになり、埋め込みの JS 約 1,200 行に型検査が効かないままになる。

## 代償

- 段取りが 2 系統になる。画面を足す人は、自分のパネルがどちらかを知っていなければならない。
  取り違えても型では止まらない（返る形が同じなので）。パネルが口を作るところの検査と、
  README とこのファイルが対で言う
- `retainedHost` は表裏を見ないので、**画面が生きていることを VS Code の設定（`retainContextWhenHidden: true`）に
  頼っている**。VS Code の文書がその点で食い違っているので、表に戻ったときの送り直しで支えている。
  送り直しは知らせ（`lock`・`changed`）だけで、`failed` のような 1 度きりの一言は裏で落ちれば落ちたまま
- **実機で確かめるのは人の仕事として残る。** 裏に回している間に届くかどうかは単体テストでは出ない。
  拡張の README の手動確認に 38b（リスク管理）と 42c（フェーズ管理）を置いた
- 保持する画面は VS Code がメモリを抱えたままになる。これは移行前からの性質で、この決定では変えない

## その後

3 画面とも移し終えた（リスク管理とフェーズ管理は issue #86、ルール設定は issue #84）。
ここで前提にしていた「ルール設定はまだ文字列で組んでいる」は、もう当てはまらない。段取り
（`retainedHost`・表に戻ったときの送り直し・中身を渡すのは編集を捨ててよいときだけ）は
3 画面とも同じ形で当たり、変えたところは無い。手動確認は拡張の README の 38b（リスク管理）と
42c（フェーズ管理）に加えて、ルール設定のぶんも同じ形で確かめる。
