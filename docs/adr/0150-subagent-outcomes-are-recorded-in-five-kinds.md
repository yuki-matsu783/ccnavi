# ADR-0150: サブエージェントの終了結果は 5 つに分けて記録し、担当の子が分からない体は差し戻さず親へ知らせる

状態: 採用

## 状況

`SubagentStop` は、子の範囲外の変更が残っていれば 1 回だけ差し戻していた。この判定には次の弱点があった。

- 親のツリーから起動された体（孫を含む）は、hook の `cwd` がメインの `cwd` になるので、担当の子が分からない。それでも親の全部の子を検査し、兄弟の子の変更で関係ない体を差し戻していた
- 差し戻して直ったのか、差し戻しを残したまま終わったのかが、親にもユーザにも残らなかった。差し戻しを無視した知らせと、範囲を確かめられなかった知らせは別々の印で、結果としてまとまった記録が無かった
- 親が結果を知る手段が `PostToolUse` の 1 回の知らせだけで、取りこぼしても `Stop` が気づかせる経路が無かった

## 決定

`SubagentStop` が終わり方を 5 つに分け、`logs/state/subagent-<セッション>-<agent_id>.outcome`（JSON）に残す。

| 結果 | 意味 |
|---|---|
| `ok` | 範囲外の変更が無い |
| `fixed` | 差し戻した後に直った |
| `outside` | 範囲外の変更を残したまま終わった |
| `unchecked` | 読めない・内部エラーで検査できなかった |
| `unattributed` | 担当の子が分からない（親のツリーから起動された） |

- 担当の子が決まるのは、cwd が子のワークツリーのときだけ。親のツリーから起動された体は、全部の子を検査するが差し戻さず、`unattributed` として親へ知らせる。最終的な止めは `finish` の範囲検査に任せる
- 差し戻して続けさせる回は確定させず（`final: false`）、次の `SubagentStop` で `fixed` か `outside` に決める。直ったものは親に警告しない。`dry-run` は差し戻さないので、差し戻し 0 回の `outside` を残し、親への文は「差し戻していない」と言う
- `unattributed` は `PostToolUse` と `UserPromptSubmit` で親へ 1 度だけ知らせる。出力に書き終えてから `notified` の印を付けるので、書く前に止まれば次の機会に出し直す。`outside` と `unchecked` は従来の経路で親に届く
- `Stop` が促すのは `outside` と `unchecked` だけ（理由コード `NUDGE_SUBAGENT_OUTCOME`）。同じ結果では 1 回（`nudged` の印）。順序は `finish` → 依頼までの道 → サブエージェントの結果 → `integrate` → ルール。実行中のサブエージェントが居る間、サブエージェントの中、`stop_hook_active` が真のときは促さない
- `.outcome` は、ほかの `subagent-` の記録と同じく、prune が 14 日で消す

## 得たもの・失ったもの

得たもの: 関係ない体を差し戻さない。結果が残るので、親は何が起きたかを後から確かめられる。範囲外が残ったものや確かめられなかったものは、親が取りこぼしても `Stop` が 1 回拾う。

失ったものは次のとおり。

- 親のツリーから起動された体の範囲外の変更は、その場では止まらない。`finish` の範囲検査が止めるまで、親が知らせを受けて確かめる前提になる
- 担当の子が分からない場合に `SubagentStop` の `cwd` が実機でどうなるかは、まだ確かめていない。`unattributed` がどれだけ起きるかは分かっていない
- 記録を書けないとき、結果は残らない（hook は止めない）。促しの印を付けられない結果は促さない

## 採らなかった案

- 親のツリーから起動された体も、検査した子の全部で差し戻す（従来）: 兄弟の子の変更のせいで、関係ない体に直させてしまう
- 担当の子をプロンプトの文面から推し量る: 書かれたとおりかを hook が確かめられない
- `unattributed` も `Stop` で促す: 担当が分からず、促しても確かめる先を示せない。親への 1 度の知らせで足りる
- 結果を記録せず、知らせの印だけで済ませる: 直ったか残ったかを見分けられず、`Stop` の促しも出せない
