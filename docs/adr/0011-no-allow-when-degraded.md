# ADR-0011: 読み切れないコマンドに `allow` を当てない

状態: 採用

## 状況

Bash のルールは、コマンド文字列そのものではなく、シェルが実際に実行する部分に当てる。
静的に読めないコマンド（文字列をコードとして実行する `bash -c` `eval` `xargs` `find -exec`、
閉じていない引用やヒアドキュメント）は、生の文字列との一致に縮退する。縮退した先で
`allow` を当てるかどうかを決める必要があった。

## 決定

縮退した呼び出しに `allow` は当てない。`deny` と `ask` は当てたままにする。どこにも当たらなければ
`PARSE_UNCERTAIN` で人に確認が出る。ここだけは権限モードに委ねない（ADR-0009 の例外）。
文面は「禁止された操作を行った」ではなく「読めなかったので文字列に当てた」と伝える（REQ-HNT-04）。

## 理由

当てる先が実行される部分ではなく生の文字列なので、そこで許可を出すのは「読めなかった文字列に
そう書いてあった」を根拠に通すことになる。`deny` と `ask` は厳しい側へ外れるだけで、
そのことは文面が断る。権限モードに委ねないのは、読めなかったという事実が判定の結果に現れず、
委ねた先には伝わらないから。それを言えるのがここしかない。

コメントだけの行のように、実行される部分が何も残らないコマンドは判定に入らない。
何も走らないものについて人に聞く意味が無い。記録には `nothing-to-run` が残る。

## 得たもの・失ったもの

- 得たもの: 縮退が緩む側に倒れない。縮退の割合を記録の `degraded` で数えられる
- 失ったもの: 複合コマンドは 1 つの区間が読めなければ全体が縮退する。`a && bash -c "..."` は
  `a` の側も生の文字列で判定される。縮退の向きが安全側なのでそのままにしてある
- 失ったもの: `grep -n "<<" README.md` は、引用された `<<` と素の `<<` を `shlex` が区別しないため
  ヒアドキュメントの始まりに見え、閉じない本文として縮退する。これは直す対象ではなく、
  許容する誤検知として設計書に書いてある。塞ぐにはトークンが引用されていたかを `shlex` から
  取り出す必要があり、公開された手段が無い
- perl や python は縮退の対象に入れていない。`perl -pi -e 's/git push/.../' README.md` のような
  1 行編集は禁止語に触れる文書を直すときの普通の書き方で、ここを諦めると直したい誤検知が
  そのまま残る

## 採らなかった案

- 縮退した呼び出しにも `allow` を当てる。上のとおり
- 縮退した呼び出しを一律 deny にする。直せる書き方（対象をファイルへ逃がす）があるのに
  ターンを止める
