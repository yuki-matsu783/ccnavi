# ADR-0006: `disable` は起動側の環境からしか効かせない

状態: 採用

## 状況

設定は `.claude/settings.json` の `env` に置く（ADR-0005）。そのファイルは作業ツリーの中にあり、
エージェントが書き換えられ、変更は次のツール呼び出しから効く。監視される側が監視を止められる
経路になる。

## 決定

停止の指定は、ccnavi を起動した側の環境からしか効かせない。守り方は 2 段にする。

**モードを解決する段。** 設定ファイルが求めた `disable` は無視して理由を出す。見分けられるのは
`ccnavi.settings.local.json`（ccnavi 自身のソースツリーでだけ読む上書き設定）が求めた `disable` まで。
`.claude/settings.json` の `env` に書かれた `disable` は Claude Code がプロセス環境として渡すので、
ここでは「人が起動時に渡した `disable`」と区別が付かない。

**書く経路を閉じる段。** 区別できないぶんは、そこへ書けないことで担保する。`.claude/settings.json` は
中核ファイル（ADR-0021）で、`Write` / `Edit` はルールの `deny`（`guard-settings`）が止め、シェルからの
書き込みは組み込みが止め、すり抜けても実行後に控えから戻る。加えて `env` は再読み込みされないので、
書けたとしても同じセッションでは効かず、効かせるにはセッションを開き直す必要がある。それは人が起こす。
書かれていること自体は `--lint` が error で名指しし、導入スクリプトは `--mode disable` を断る。

## 理由

要件 REQ-CMN-04（停止はプロジェクト内のファイルに書いても効かない）をそのまま形にした。
一時的に外したいときは、セッションを起動する側の環境から渡す。

## 得たもの・失ったもの

- 得たもの: エージェントが設定ファイルを書いてガードを止める道が閉じる
- 失ったもの: 「このプロジェクトでは使わない」を settings.json では書けない。導入スクリプトも
  `--mode disable` を断る
- 失ったもの: モードの解決だけを見ると REQ-CMN-04 を満たしていないように読める。担保が
  中核ファイルの保護（ADR-0021）側にあるので、そこを `disable` にすると `env` に書いた
  `disable` が次のセッションから通る。守りの 2 段が別の設定で切れる形は残っている
- `ccnavi.settings.local.json` は開発の便宜で、境界ではない。`mode` の `disable` だけは塞ぐが、
  戻す働きやチケット制御はここから緩められる。だから ccnavi 自身のソースツリーでしか読まない

## 採らなかった案

- settings.json の `disable` も効かせる。止められる側が止め方を持つ形になる
