# ADR-0164: 共通レイヤーのミラーの同期は、ユーザ専用の入口で、見せた差分と照合してから作業ツリーに書く

状態: 採用

## 状況

プロジェクトの `.ccnavi/config/common/`（ミラー）は、親チケットの `ticket start` のときにだけ、ワークスペースの共通レイヤーに揃う。間が空くと、ミラーを共通レイヤーとして読む使い方（clone 済みのディレクトリで起動する形）では、判定が古い共通レイヤーのまま働く。

直接作業の開始時には、ミラーを意識しない。共通レイヤーのうち、直接作業にも効くのはルール（`rules.yml`）だけで、フェーズ定義・リスクの配点・テンプレートはチケット用である。ミラーが無くても、組み込みの deny は常に有効で、動作は止まらない。

ずれに気づく入口と、揃える入口が無かった。ユーザだけが実行する操作の一覧（ユーザ専用の入口）に、この操作を追加する。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 調べる入口と揃える入口を `ccnavi user mirror` として追加する。調べる形は何も書かない | プロジェクト管理画面が、決まった間隔で読み取りだけを呼べる | 画面が自分で比べる |
| `user` の入口に置き、見るだけの形もユーザ専用にする。hook は `user handoff` と同じ扱いで止める | プロジェクトのメインのチェックアウトに書く操作を、エージェントが実行できないようにする | 誰でも実行できる入口にする |
| 揃えるときは、見せた差分から求めた照合の値（`--expect`）が今の差分と一致したときだけ書く。一致しなければ何も書かず、内容が更新されたと返す | ユーザが見ていない内容を書かない。共通レイヤーやミラーが、見せたあとに変わった場合も同じ | 照合せずに書く |
| 書くのはプロジェクトの作業ツリーのミラーだけにする。コミットしない。プロジェクトの `config/project/` に触れない | コミットして運ぶかどうかはユーザが決める。メインのチェックアウトの履歴を勝手に動かさない | 専用のワークツリーを切ってコミットする |
| 書くときは端末を求める。拡張の子プロセスは `--via board` で端末を求めない経路を使い、`--expect` と `--json` を付けて呼ぶ | 取り込み（`user handoff`）と同じ作り | 経路を分けない |
| 共通レイヤーに写すものが無いときは、ずれとせず、ミラーを消さない | 共通を消し忘れたときに、ミラーを全部失わない（着手のミラーと同じ） | 空の共通でミラーを消す |
| 調べられないプロジェクトは `error` にして、まとめて揃える対象から外す | 1 つの不備で、ほかのプロジェクトの同期を止めない | 全体を止める |
| 直接作業の開始時には、共通設定を同期しない | 上の状況のとおり。直接作業は、ミラーが無くても止まらない。開始時に同期すると、ユーザの作業ツリーを開始のたびに書き換える | 開始時に毎回同期する |
| 同期のための hook（`UserPromptSubmit` など）は追加しない（親のワークツリーへの同期は ADR-0166 が覆した。メインのチェックアウトは、この行のまま） | ミラーの元は、単体 clone の側から見えない。ワークスペースの側では、ミラーは読まれない。hook がユーザの作業ツリーを書き換えると、直接作業の取り込みの前提も崩れる | 発言のたびに同期する |

## 理由

ミラーがずれても、動作は止まらず、共通レイヤーより古いルールで判定されるだけである。だから、自動で書き換えるより、ずれを見せてユーザが押す形が釣り合う。照合の値は、ユーザが読んだ差分と書く内容を一致させるための歯止めで、取り込みと同じ考え方である。

## 得たもの・失ったもの

- 得たもの: ミラーのずれを、親チケットの着手を待たずに見つけて、揃えられる
- 得たもの: 書く内容は、見せた差分と一致したものだけ
- 失ったもの: エージェントのターンの最中に書くと、実行後チェックがミラーの変更を戻しうる。メインのチェックアウトのミラーは、着手が配ったミラーの書き込みのように、内容で外す対象に入らないため。ユーザが書いた内容は次の発言で基準に取り直される
- 失ったもの: 揃えたミラーは、ユーザがコミットするまで作業ツリーにだけある。単体 clone の人に届くのは、コミットして push したあと
- 失ったもの: 端末と画面に出るのは、変更するファイルの一覧と種類（追加・更新・削除）で、中身の差ではない。照合の値には中身が入っているので、一覧を見たあとで中身が変わっていれば書かない。中身の差を見る方法は、端末の出力に案内する（`diff -ru`）
- 失ったもの: ミラーをユーザが手で直していた場合（単体 clone で編集できる）、揃えると上書きされ、共通レイヤーに無いファイルは削除になる。差分は事前に見せる

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| 揃えるときに、専用のワークツリーを切ってコミットまで行う | 手数が多く、MR に出すかどうかの判断までユーザから取ってしまう |
| ミラーの元を単体 clone から引けるようにする（ワークスペースの場所を記録する） | 単体 clone にワークスペースへの参照を持たせると、別の機械で壊れる |
