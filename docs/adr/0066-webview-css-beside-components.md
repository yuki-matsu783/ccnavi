# ADR-0066: 画面の CSS を部品と同じ置き場に移し、束ねたものを拡張ホストが流し込む

状態: 採用

## 状況

VS Code 拡張の 5 つの画面は React で組んであり、部品は `src/webview/<名前>/*.tsx` にある
（ADR-0064、ADR-0062）。ところが**その CSS だけは拡張ホスト側**（`src/core/<名前>-style.ts`。
5 画面共通のぶんは `src/core/styles.ts`）にあり、テンプレート文字列で持っていた。

部品を 1 つ足すたびに、別のモジュールの文字列を編集しに行くことになる。結び付いているのは
クラス名だけで、対応を保証するものは無い。各 `*-style.ts` の頭には「部品を足したらここに足す」と
書いてあり、**対応は人が保っていた**（issue #91）。

拡張ホスト側に置いてあった理由は CSP にある。Webview の `style-src` は `'nonce-...'` で、nonce を
持つ `<style>` しか通さない。nonce は入れ物の HTML を組む側（拡張ホスト）が呼ぶたびに作るので、
画面（React）が後から `<style>` を挿すには nonce を画面へ渡すことになる。

issue #91 が挙げていた道は 3 つ。(1) nonce を埋め込みの JSON に載せて画面へ渡す、(2) 画面が
`document.querySelector("style")?.nonce` で拾う、(3) いまのまま。

## 決定

**4 つめの道を採る。CSS は画面の側（`src/webview/`）に実体のある `.css` として置き、esbuild が
画面ごとに 1 本へ束ね、拡張ホストはその出来上がり（`out/webview/<名前>.css`）を読んで
`<style nonce>` に流し込む。** 画面のスクリプト（`out/webview/<名前>.js`）と同じ扱いになる。

| 決めたこと | なぜ |
|---|---|
| 置き場は画面と同じ `src/webview/<名前>/` で、**部品と同じ名前の CSS**（`Card.tsx` なら `Card.css`） | 部品を足すとき、隣に CSS を置く。別のモジュールを開きに行かない。**1 対 1 ではない**: 自前の見た目を持たない部品には CSS を置かず（`Hooks.tsx`）、画面の中で分け合う見た目（ルール設定の表は判定と hook の両方が使う）は `App.css` に置く |
| 画面ごとの入口は `src/webview/<名前>/style.css` 1 本で、中身は `@import` を並べるだけ | 束ねの入口の綴りを 1 つに決める（`main.tsx` と同じ約束）。部品が増えても直すのは 1 行 |
| 5 画面共通のぶんは `src/webview/styles/`（`page.css`・`button.css`・`appearance.css`・`list.css`） | 骨組みの定義は 1 か所のまま。画面は `@import` で持つ |
| 束ねは JS と別に回し、**CSS は小さくしない** | esbuild の `minify` は JS と CSS の両方に掛かる。CSS は 13〜18KB で、小さくすると board で 2.9KB 減る（スクリプトは 1 本 200KB 強なので、減るぶんは 1%）。その 2.9KB より、開発者ツールで読める得のほうが大きい。esbuild が付ける `/* src/webview/board/Card.css */` の行で、どの部品の CSS かがその場で分かる |
| CSS は画面のスクリプトから `import` しない（別の入口にする） | 画面が CSS を持ち回ると、挿すのも画面の仕事になり、nonce が要る。挿すのは入れ物を組む側のまま |
| 拡張ホストが読むところは `src/webview-asset.ts`（旧 `webview-script.ts`）に `webviewStyle` を足す | スクリプトと同じ読み方（名前で引く・1 度読んで覚える）。画面が増えても直すところは無い |
| 置いた CSS が束ねから漏れていないことをテストで見る（CB-T166・CB-T168） | 新しい失敗のしかたは 2 つ。「`@import` の書き忘れ」（見た目だけが黙って抜ける）と、「部品を消したのに CSS が残る」。前者は `@import` を辿って、どの画面の束ねにも入らない CSS が無いことと束ねた 1 本にその中身が入っていることを見る。後者は `Card.css` に `Card.tsx` があることを見る |

## 理由

issue #91 の 3 つの道は、どれも「nonce を画面へ渡すかどうか」で迷っていた。**渡さなくてよい。**
CSS の置き場（どこに書くか）と、CSS を挿す場所（誰が `<style>` を作るか）は別の話で、前者だけを
動かせば issue の詰まりは解ける。束ねが両者の間に入り、拡張ホストが受け取るのは「出来上がった 1 本」
という文字列 1 つになる。CSP は 1 文字も変わらず、nonce はどこにも増えない。

実体のある `.css` になる副産物もある。編集機が CSS として扱えるようになり（色の見本・補完・
書式の検査）、esbuild が読めない綴りを**警告として出す**。テンプレート文字列のときは、黙っていた。
**落ちるところまではいかない**: `@import` の行き先が無いときだけビルドが止まり、閉じ忘れと
プロパティ名の綴り違いは警告 1 行、値の綴り違い（`display: flexx`）は何も言わずに通る（esbuild 0.25 で確かめた）。

## 得たもの・失ったもの

得たもの。

- 部品を足すときに触るのが同じディレクトリだけになる（`Card.tsx` と `Card.css`）
- 置いた CSS の取りこぼし（`@import` の書き忘れ、部品を消したのに残った CSS）を、人の注意ではなく
  テスト（CB-T166・CB-T168）が止める
- CSS が CSS として扱われる（編集機・esbuild の検査）。どの部品の CSS かが、配ったものの中でも分かる
- `src/core/` から CSS の 6 ファイル（495 行）が消え、拡張ホストは「束ねを読んで流し込む」だけになる
- テストの回り方が細かくなる。`scripts/test-groups.js` が `@import` も辿るので、`Card.css` を触れば
  board のぶんだけ、共通の `styles/page.css` を触れば全部、と分かれる（辿れないと全部に倒れる）

失ったもの。

- **CSS の中のコメントが、配るものから消える。** esbuild は CSS のコメントを落とす。書いた説明は
  ソースには残るが、開発者ツールで読んでいた注記（「HC では効かない書き方」など）は画面に出ない
- **束ねる工程が 1 つ増える。** `pnpm run compile` を通す前の `out/` では、CSS が無いので画面が
  素のまま出る。拡張は開く前に見て、無ければ「ビルドが揃っていない」と言って開かない
- **規則を文字列で見るテストが、esbuild の並べ方に触れる。** 束ねたものは 1 宣言 1 行に並べ直される
  ので、`.card { a: 1; b: 2; }` の形で見ていたテストがそのままでは当たらない。1 行に潰してから
  見る道（`test/helpers/bundle.ts` の `flatStyle`）を 1 本用意して、全部そこを通した。
  esbuild の並べ方が変わっても、当てるものと宣言が同じなら通る
- **並びが変わる。** `@import` は CSS の決まりで先頭に集まるので、共通のぶん（ボタン・配色・一覧）が
  必ず画面ごとの CSS より前に来る。**移すときに 1 か所、見た目が変わっていた**: 設定 3 画面の
  `button.action.small { margin-left: auto }`（見出しの「＋ 追加」向け）と、一覧の
  `.row-body .buttons button { margin-left: 0 }` が同じ詳細度で、前後が入れ替わって行末のボタンが
  散らばっていた。**詳細度で勝たせる形**（`.row-body .buttons button.action`）に直して、並びに依らないようにした。
  残りの組（画面ごとに 4〜36 組）は、同じ要素に両方が当たる組み合わせが実在しないことを
  機械で数えて確かめた（`src/webview/**/*.tsx` の `className` の組み合わせと突き合わせた）。
  **ただしこれは移すときに 1 度確かめたもので、以降は人が保つ。** 並びを見るテストは無い
- **配るものの大きさは減る**（コメントが落ちるぶん、移す前より 0.4〜1.6KB 小さい）が、**小さくすれば
  もっと減る**（board で 17.6KB → 14.7KB）。読める形のまま配る選択の代償

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| nonce を埋め込みの JSON に載せ、画面が `<style nonce>` を作って挿す（issue #91 の 1） | CSP の nonce を置く場所が増える。CSS の置き場を直したいだけなのに、守りの側に手が伸びる |
| 画面が `document.querySelector("style")?.nonce` で拾う（issue #91 の 2） | ブラウザの実装に寄りかかる。実機で確かめるまで分からず、確かめても VS Code の Chromium が変われば分からない |
| いまのまま（issue #91 の 3） | 5 画面とも React になり、CSS は 6 ファイル 495 行になった。部品を足す回数はこれから増える |
| CSS を `main.tsx` から `import "./style.css"` する（esbuild が JS の隣に CSS を出す） | 束ねが 1 回で済むが、`minify` が JS と CSS の両方に掛かる。読める CSS を配るには、どのみち別に回すことになる |
| CSS をファイルとして Webview に読ませる（`localResourceRoots` を開ける） | 「外部資源に依存しない 1 枚の HTML」をやめることになる（ADR-0064 で決めた形） |
