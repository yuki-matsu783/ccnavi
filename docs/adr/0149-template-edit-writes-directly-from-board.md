# ADR-0149: テンプレート管理画面は、ユーザが図で直したテンプレートを拡張が直接保存する

状態: 採用（ユーザが「テンプレート管理で plan と flow を GUI で編集できるように」と求め、保存方式は画面から直接保存、範囲は計画とフローの両方を既存の図の再利用で、と決めた）

## 状況

保護対象の変更は handoff に一本化している（ADR-0144）。その前に、画面からテンプレートを書く案では「書き込みは実行ファイルに任せ、拡張は YAML を書かない」としていた（ADR-0134。のちに ADR-0144 で専用の書き込みオプションごと無くした）。
そのため、取り込み済みのテンプレートの計画とフローを直すには、下書きを作り、エディタで YAML を直し、取り込み待ちで差分を読んで取り込む手順しかなかった。計画の項と線、フローのノードと線は、図で直すほうが誤りが少ない。

制約。

- エージェントは `.ccnavi/` の下を書けない。画面を操作するのはユーザだけ（ADR-0100）
- 拡張は判定を自分で出さず、実行ファイルの答えを読む（ADR-0035）
- PyYAML（YAML 1.1）と拡張の `yaml`（1.2）は読み方が食い違う。拡張が書いた本文を実行ファイルが同じ中身に読むとは限らない
- フロー編集画面は、同じ理由で、拡張が直接書き、保存の前に実行ファイルに読ませて見比べる

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 開いている対象の層の、読めるテンプレートは、画面の編集欄で直して保存できる。書くのは拡張で、フロー編集画面と同じ書き方（リンクを辿らず、一時ファイルの入れ替え）を使う | ユーザが図で直す価値は、下書きと取り込みの手順を挟むと薄れる。ルール管理・フロー編集と同じ作りに揃う | 下書きに直して取り込む（ADR-0144 の手順のまま。図で直せない） |
| 実行ファイルに足すのは読むだけの `--templates --check-file <パス> --layer <名前> --json` だけ。本文の検査・読み返した中身（`data`）・計画の図の中身（`plans`）・選べる型（`types`）を返す。書き込みのオプションは足さない | 判定は実行ファイルに置く（ADR-0035）。書き込みのオプションを足すと、エージェントに打たせない止めがまた要る | 書き込みも実行ファイルが行う（ADR-0134 の案。専用の止めが増える） |
| 保存は、(1) 読ませて error が無い、(2) 読み返した中身が書こうとした中身と同じ、(3) 開いたときのハッシュと同じ（新規はまだ無い）、(4) 作業中のチケットが無い、を満たしたときだけ書く | 1.1 と 1.2 の食い違いで別の中身が書かれるのを止める。外での変更を上書きしない | 検査せず書く |
| 作業中の錠は、取り込み待ち画面がテンプレートの取り込みを止めるのと同じ決まり。拡張の画面だけが持ち、実行ファイルには足さない。編集はできて、保存だけ止める | hook は次の呼び出しから設定とテンプレートを読み直すため | 錠を掛けない |
| 改名・移動・削除、下書きの編集、読めないテンプレートの編集は持たない | 範囲を、図で直す価値のあるものに絞る。ファイルの直接操作で足りる | 画面にも足す |
| 取り込み待ちの手順（下書き → `user handoff`）は残す。親が閉じるときの下書きは今までどおり | エージェントが溜める経路は変えない | 下書きの経路をやめる |

## 得たもの・失ったもの

- 得たもの: テンプレートの計画とフローを、図で直してすぐ保存できる。保存の前に実行ファイルが読み、食い違いは書かない
- 失ったもの: 「保護対象の変更は handoff に一本化」の例外が 1 つ増える（ユーザが画面で押したときだけ。エージェントは通れない）。取り込み待ちのような、差分を読む段は無い（編集欄で直した内容が見えている）
- ADR-0144 の「テンプレート専用の取り込み・編集をやめる」は、実行ファイルのオプションについては今も正しい。拡張がファイルを直接書く点だけを、この ADR で改める

## まだ決めていないこと

- 編集欄の案内（ツアー）
- 保存前の差分の表示
