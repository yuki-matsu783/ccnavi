# ADR-0138: 親を閉じるときの片付けを ccnavi が行い、消すのは成果が失われないと確かめられたものだけにする

状態: 採用（2026-10-14 に実装。ADR-0136 の閉じた判定（MR のマージ済み）と、ADR-0137 の `merged_sha` を前提にする。追記: 片付ける「取り込み記録」と、ワークツリーを片付けた後の列挙元は、ADR-0142 が `ready` の書く `retire/<親>.json`（`mr` を含む）に改めた。`tidy` はブランチの確認の後にワークツリーを消す）

## 状況

親を閉じる流れは、`ready` が Draft を外し、ユーザが MR をマージする、の 2 段に分かれる。それまでは、片付けの対象と条件が次のようにばらついていた。

- 閉じた子のワークツリーは消えるが、レビュー待ちだった子のワークツリーと、子の手元のブランチは `ready` のあとも残った
- 親の手元のブランチと取り込み記録は、手で消すまで残った。squash でマージされると `branch -d` が通らない
- 閉じたかは手元の退避（`logs/archive/`）からの推定だった。退避の無い PC では、マージされた親が閉じたと分からず、不要なものが残り続けた

PC をまたいで続けると（ADR-0136）、親のワークツリー、子のブランチ、取り込み記録が PC ごとに溜まる。消しすぎると成果が失われるので、消してよい条件を決める必要がある。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 方針は、親を閉じたら、その PC の不要物（ワークツリー・ブランチ・取り込み記録・ロック）を ccnavi が片付ける。消すのは、成果が失われないと確かめられたものだけ。確かめられなければ消さずに、理由と手で消すコマンドを出す | 手での片付け忘れを無くす。確かめられないものを消さない | — |
| 片付け 1（`ready` が Draft を外した後）。子はすべて閉じているので、子のワークツリーをレビュー待ちだったものも含めてすべて消す。合流済みの子のブランチを条件つきで消す。親のワークツリーを消す。実行は `ccnavi worktree retire <親>` | 閉じた子の続きは、新しいチケットで新しいワークツリーを切る。親を閉じるときが、子のワークツリーを残す理由が無くなる時点 | — |
| `ready` は閉じた子のチケットを退避へ移すので、先に子の一覧（識別子・合流したか取り消したか・合流した先頭の sha）を状態の置き場の `retire/<親>.json` に書き、片付けはそれを読む | 退避に移したあとでも、どの子をどう片付けるかが分かる | — |
| 合流した子のブランチは、先頭が `merged_sha` と同じで、その sha が push 済みの親の先頭（`origin/<親のブランチ>`）の祖先であるときだけ消す。どちらかが違えば消さない | 成果が親に入っていると、push 済みの親で確かめられるものだけを消す | — |
| 取り消した子のブランチは、親に無いコミットの数を添えた一覧をユーザに見せ、ユーザが先頭に `!` を付けて `ccnavi-clean.sh --branch <名前> --confirmed`（中身は `worktree branch <名前> confirmed`）を打ったときだけ消す。エージェント（メインもサブエージェントも）が直に打つ形は hook が止める。確認なしでは消えない。`--confirmed` は、ccnavi が片付ける子として記録したブランチで、チケットの `parent:`（承認済みの置き場か退避）でも記録の親の子と確かめられたものにしか使えない | 取り消した子は合流していないので、コミットが親に無い。破棄するかはユーザが決める。`--confirmed` が単なる語だと、エージェントが添えるだけで確認を飛ばせる。ユーザ自身が打つことで確認を担保する。記録は state のファイルなので、書き換えて対象を広げられないよう確かめ直す | 確認なしで消す。エージェントが確認を取ったと言えば打てる |
| 消さないもの。未コミットの変更や、git が無視しているファイル（`.env` など）があるワークツリーは、理由を言って残す。cwd が消す対象の中にあるときも消さない | `worktree remove` は無視されたファイルごと消し、履歴から戻せない | — |
| 片付け 2（MR がマージされたと分かった後）。`ccnavi-sync.sh`（ボードの同期・`ccnavi-start.sh` の最後・エージェントの `sync`）が、ホストに聞いて、マージ済みの MR の番号と先頭の sha を渡す。聞くのは、親のブランチがリモートに残っている親（ホストはマージ後もブランチを残すことがある）も、ワークツリーを片付けた後に取り込み記録だけが残る親（記録の状態によらない）も同じ。MR の番号は取り込み記録から引き、無ければブランチから MR を探す推定はせず 1 行言う。消すブランチの名前は親のワークツリーの HEAD か MR の元ブランチから取る（取り込み記録の branch はキャッシュ）。実行は `ccnavi sync tidy`。親のワークツリーが残っていれば消し、親の手元のブランチを消す（渡されたブランチが親の識別子のブランチで、手元の先頭が push 済みの先頭（手元の `refs/remotes/origin/<ブランチ>`）と MR の先頭の両方に含まれるとき）。残っていた子のブランチは、MR の先頭を基準に片付け 1 と同じ条件で消す。すべて片付いたら、sh がその親の取り込み記録とロックを消す | squash でマージされると `branch -d` が通らない。MR の先頭は sh が渡す値で、ブランチ自身の先頭を渡せば必ず含まれるので、それだけでは信じない。push 済みの先頭に含まれれば未 push のコミットは無い。どちらかが手元に無ければ確かめられないので消さない | MR の先頭に含まれるかだけで決める |
| 閉じたかの確認は MR がマージ済みかで決める（ADR-0136）。ホストに聞けなければ推定せず止まる | ホストが答えを 1 つ持つ | 手元の退避から閉じたと推定する |
| 片付けた内容は 1 行ずつ報告する。消さなかったものは、理由と手で消すコマンド（`git -C <リポジトリ> branch -D <ブランチ>`）を出す。何かが残ると取り込み記録も残り、直してから `ccnavi-sync.sh` を打ち直せば片付く | 何が残ったかをユーザが見分けられる | — |
| `branch -D` はエージェントに開放しない。ラッパースクリプトも `-D` を通さない。条件の確認も削除も、ccnavi の実行ファイルとスクリプトの中で行う。片付けの入口（`sync tidy`・`worktree retire`・`worktree branch`・`ccnavi-clean.sh --branch`）も、エージェントは直に打てない。呼ぶのは sh（`ccnavi-review.sh ready`・`ccnavi-sync.sh`）の中か、ユーザが `!` を付けて打つときだけ。残ったブランチを消し直す入口は `worktree branch`、ネットワークには出ない | 条件を満たさないブランチをエージェントが強制で消せないようにする。入口に渡す値（sha・ブランチ名・`confirmed`）を呼び手が選べると、条件の確認が意味を失う | `branch -D` を許可して、エージェントに消させる |
| 退避（`logs/archive/`）はバックアップ専用。閉じた判定にも、識別子の再利用の確認にも使わず、消さない | 退避は PC ごとのもので、別の PC には無い | ローカルの退避で閉じた判定をする |
| `ready` の途中再開は、MR の Draft 状態と親のブランチで判断する | 退避の有無に頼らない | — |

## 得たもの・失ったもの

- 得たもの: 親を閉じれば、PC ごとの不要物が ccnavi の手で片付く。退避の無い PC でも、MR がマージされたと分かれば親のブランチと取り込み記録が片付く。消す条件が `merged_sha`・push 済みの親・MR の先頭に結び付き、成果が失われない
- 失ったもの: 条件を確かめられなかったものは残り、ユーザが理由を見て手で消す。取り消した子のブランチは、一覧を確認する手間が要る。`ready` と `sync` が、ホストに聞いて MR の状態を確かめられないときは止まる。片付けの実行ファイルとスクリプトの部分が増える
