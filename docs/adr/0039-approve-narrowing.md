# ADR-0039: 承認の対象は識別子で狭められる（狭めるだけ）

状態: 採用

## 状況

`ccnavi --approve` は承認待ちの全部をまとめて見せ、y/N を取る（ADR-0024）。VS Code 拡張の
ボードはプロジェクトや親で絞り込めるのに、承認のボタンは絞り込みを無視して全部を渡していた。
見えているものと承認するものが違う。

## 決定

`ccnavi --approve <識別子>...` で承認の対象を狭められる。絞りは狭めるだけで、絞らないときに落ちるものは
通さない。次のときは何も承認しない。

- 承認待ちに無い識別子が混じっている
- 親の改版が承認待ちなのに、その子だけを承認の対象に入れた

対象から外した親を持つ子は「親が承認されていない」で落ちる。落ちた親は、子が自分の親を引く池（承認済みチケットと、今回の承認で通ったもの）に入れない。

## 理由

絞りで新たに通るものを作らないため。狭める操作が緩める操作に変わると、絞り込みが権限を配る
道具になる。親の改版を外した子を拒むのは、外すと承認済みチケットに残っている旧い計画で検証してしまい、
人が見た計画と違うものを承認することになるから。

落ちた親を池に残さないのは、レビューで見つけた穴。残すと、親の承認を通らずに子の承認済みチケットができた。

## 得たもの・失ったもの

- 得たもの: ボードで見えているものと承認するものが揃う
- 失ったもの: 1 件だけを承認する手段ができたので、「まとめて見せてまとめて決める」が少し緩む。ただし
  狭めるだけなので、全部を見たときに落ちるものは絞っても落ちる
- 失ったもの: 識別子を打ち間違えると何も承認されない。断りなく一部だけ通すより、止まるほうを採った

## 採らなかった案

- 絞った中だけで検証する。外した親を見ないので、旧い計画で子を通す抜け道ができる
- 絞りを拡張だけの機能にして端末では受けない。承認は端末を通る（ADR-0029）ので、渡す手段が要る
