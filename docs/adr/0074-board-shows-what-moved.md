# ADR-0074: ボードは「動いた」を印で見せ、その印を時間では消さない

状態: 採用

## 状況

チケットの置き場が変わると（人が承認する、エージェントが `ticket done` を打つ）、ボードは監視で
読み直り、カードは別の列に現れる。**データとしては前から自動で動いていた。** それでも人には
動いて見えない、という指摘が出た（2026-09-22）。

理由は 2 つあった。

1. **承認の直後はボードが見えない。** 承認できるとオーバーレイが「N 件を承認した」に替わり、
   Claude Code に渡す文を見せる。閉じたときには移動は済んでいて、動く瞬間を人が見ない
2. **読み直しは列の中身を丸ごと差し替えるだけで、痕跡が無い。** エージェントが動かしたときも
   同じで、カードが黙って別の列に現れる

承認の後の読み直しも、監視だけに頼っていた（`approval-machine.ts` の `answered` は成功しても
`refresh` を返さなかった）。承認は承認済みチケットを `.ccnavi/approved/doing/` に書いてから提案を
消すので、**ふつうはその置き場の監視が拾う**（`core/watch.ts` の `.ccnavi/approved/**`）。拾えない
のは、その置き場が監視の綴りと違うとき（`CCNAVI_TICKETS_APPROVED` が既定と違う。監視の綴りは
固定してあり、この env を読まない）、`files.watcherExclude` でそこを外したとき、監視の効かない
ファイルシステムのとき。そこでは承認したのに画面が変わらないままになる。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 承認できたら、承認の側からもボードを読み直す（`refresh`） | 監視が拾えない置き方でも、承認は必ず画面に出る | 監視だけに頼る。拾えない置き方で黙って古いままになる |
| 読み直したボードを前のものと比べ、列が変わったカードと新規起票のカードに印を出す | 実行ファイルが返した事実だけを見せる。エージェントが動かしたときにも同じ印が効く | 承認のオーバーレイに「N 件が動いた」と書くだけ。オーバーレイの外の動きには効かない |
| **印は時間では消さない。** 次に何かが動くまで残す | 承認の直後はオーバーレイが覆っていて、秒で消すと人は印を一度も見ない | 数秒で消す。承認という一番見せたい場面で見逃す |
| 列が動いていないボードが渡り直ったときは、印を作り直さない | 承認の文を閉じると同じボードが渡り直る。そこで作り直すと、**閉じた瞬間に印が消える** | 届いたボードを毎回比べる。閉じた拍子に消える |
| **覚えるのは拡張ホスト**（`board-panel.ts`）で、画面ではない | 画面は裏に回ると捨てられ、表に戻ると作り直される（`retainContextWhenHidden` は偽）。画面に持たせると、承認の文を「新しいセッションで開く」で渡してボードに戻った瞬間に印が消える — **一番見せたい場面で消える**。承認のオーバーレイを画面の中に持たないのと同じ理由 | 画面が `useRef` で覚える。タブを移って戻るだけで消える |
| カードが動いたことは色だけでなく帯の文（「未着手 → 作業中」）でも言う | 色を見分けられなくても読める。`prefers-reduced-motion` では光らせないので、そのときも文が残る | 輪の色だけ。動きと色に頼る |
| どれが動いたかを決めるのは `core/board-moved.ts`（VS Code にも DOM にも触れない） | 「いまの状態 ＋ 入力 → 次の状態」の形（`movedStep`）にして、画面を動かさずに単体で試せる。承認の遷移と同じ切り分け（ADR-0068） | 拡張ホストの中で直に比べる。`board-panel.ts` は VS Code に触れるので単体で試せない |

## 得たもの・失ったもの

得たもの。承認しても画面が変わらない、が無くなる。何が動いたかが、オーバーレイを閉じた後も、
別のタブへ移って戻った後も残る。エージェントが動かしたときにも同じ印が出る。

失ったもの。

- 拡張ホストが持つものが 1 つ増えた（`MovedState`）。オーバーレイと同じ扱いで、パネルを閉じれば消える
- 承認のたびに実行ファイルを 1 回余分に走らせることがある（監視の読み直しと重なるとき）。
  重なった分は呼ぶ側が 1 回に畳む（`board-panel.ts` の `again`）ので画面はちらつかないが、
  プロセスは増える
- 印が次の動きまで残るので、**しばらく何も動かないワークスペースでは古い印が出たまま**になる。
  「いま動いた」ではなく「前の読み直しから動いた」と読む必要がある
- **輪の脈動（2 回で 2.2 秒）は、承認のときはオーバーレイの下で終わる。** 幕越しにうっすら見える
  だけで、人が文を読んで閉じたころには静かな輪と帯だけが残る。動いて「見える」ぶんの半分は、
  タブを移って戻ったとき（画面が作り直されて印が付き直るとき）にしか出ない。閉じたときに
  光らせ直すには、閉じたことを画面へ別に伝える仕掛けが要る。そこまではやっていない
- **絞り込みで隠れたカードの印は見えない。** 「要対応のみ」や親の絞り込みの外へ動いたカードは
  `display: none` の中にあり、人が見ないまま次の動きで印が消える
- 帯は静かな文で、`aria-live` を持たない。読み上げには「いま動いた」は届かず、そのカードまで
  移動すれば読める、に留まる

## 採らなかった案

**カードが列から列へ滑る（FLIP）。** 一番「動いて見える」が、カードは列ごとの配列で描くので
DOM をまたぐ移動になり、列の折りたたみ・絞り込み・幅のドラッグと干渉する。しかも実行ファイルの
往復と 120 ミリ秒のデバウンスの後に動くので、押した瞬間ではなく遅れて滑る。割に合わない。

**承認の失敗（`error`）でも読み直す。** 途中で止まった承認は、そこまでに置かれた分がある
（README の手動確認 4g）ので読み直す値はある。採らなかったのは、返らない実行ファイルを指した
ときに（手動確認 4e・4f）読み直しも打ち切られ、エラーの画面が画面ごと覆うのが確実になるから。
置かれた分は監視が拾う。
