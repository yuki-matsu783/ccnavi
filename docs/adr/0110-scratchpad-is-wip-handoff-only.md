# ADR-0110: 下書きの置き場は wip/handoff/ に一本化し、integrate が取り込むときに外す

状態: 採用（2026-10-11 にユーザが決めた。「置き場をひとつにする」はADR-0129が改めた。`wip/handoff/` の扱いはこの ADR のまま）

改訂（2026-10-20）: `integrate` がsquashでstagedにして止まる部分は、ADR-0154 が改める。`integrate` は一時ワークツリーに取り込み結果を展開し、`integrate-done` が 1 コミットにしてfast-forwardで載せる。ブランチが持ち込んだ `wip/handoff/` の下書きを取り込まない点は変わらない。

## 状況

下書きの置き場が 2 つあった。ワークツリー直下の `scratchpad/`（`.gitignore` で追跡から外し、ワークツリーごと消える）と、
ワークスペースルート直下の `wip/handoff/`（追跡して push する）。前者はチケットの範囲を実行前チェックだけ外し、
追跡されているときは実行後チェックとサブエージェント終了時チェックが範囲外として報告した。`--lint` の警告もこの前提のためにあった。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 下書きはワークツリーの中でも `wip/handoff/` に置き、ワークツリー直下の `scratchpad/` は廃止する | 置き場がひとつになる。履歴に残り、レビューで見せられる。`.gitignore` の有無に依存しない | `scratchpad/` を残して使い分けを文言で説明する。2 つの置き場と、片方だけの警告が残る |
| `ccnavi-git.sh integrate` は squash のあと、ブランチが持ち込んだ `wip/handoff/` の下を index と作業ツリーから外し、残りを staged にして止まる。`wip/` のそれ以外には触れない。統合先が元から持つ下書きのうち、ブランチが触らなかったものも消さない | 下書きが統合先に乗らないようにする。ルートで他セッションが push した下書き（保護対象のファイルを直すための写しなど）を巻き込まない | `wip/handoff/` の追跡済みファイルを全部消す。他セッションの下書きまで消える |
| 記録する index のツリーは外したあとのもの。`integrate-done` の「ブランチの中身が入りきったか」の検査と、実行後チェックの「index が squash の結果と同じか」の検査は、`wip/handoff/` の下の差だけを数えない | 外した分を差し引かないと、検査が常に失敗する。数えない範囲は `wip/handoff/` だけで、`wip/proposals/` などの欠けは今までどおり止める | 検査を緩める範囲を `wip/` 全体にする |
| `wip/handoff/` はチケットの範囲を、実行前・実行後・サブエージェント終了時のどれでも当てない | 追跡される置き場なので、実行前だけ外すと、通った書き込みがコミットのあとで範囲外として報告される。`wip/` の下なので `ready` が消す | 実行前だけ外す。下書きのたびに報告される |
| `--lint` の「`scratchpad/` を無視していない」警告と、ワークツリーの片付けでの `scratchpad/` の特別扱いをやめる | 置き場が追跡されるものになり、どちらも前提が無くなった | 警告を残す |
| レビュー依頼の本文とマージリクエストの下書きに、「`wip/handoff/` 配下はユーザに渡す写しで、レビューの対象外」と書く | 差分に下書きが載っても、レビュアーが読む対象に数えない | 文言で伝えない |

## 得たもの・失ったもの

- 得たもの: 置き場がひとつになる。`scratchpad/` が追跡されたリポジトリでの警告が要らなくなる
- 失ったもの: コミットしたくないもの（機密、巨大な出力）の置き場が、セッションのスクラッチパッドだけになる
- 失ったもの: ワークツリーの下書きはブランチの履歴に残る。統合先には乗らないが、ブランチをそのまま push すれば届く
- 失ったもの: `integrate` に消す操作が増える。`wip/handoff/` 以外を巻き込まないことをテストで固定する
- 失ったもの: プロジェクト（`projects/<名前>/`）には `wip/` の規約が無い。この変更はワークスペース側だけを対象にする

## 置き換え関係

下書きの置き場の扱いについて、ADR-0042 などの本文に書かれた `scratchpad/` の記述は、当時の事実として残す。
