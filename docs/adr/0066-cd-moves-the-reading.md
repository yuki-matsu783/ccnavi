# ADR-0066: `cd` で移った先から見た綴りを、当てる先として足す

状態: 採用

## 状況

実行前の守りとルールは、コマンドの**綴り**に当てる。`cd` で守られたディレクトリへ入ってから書くと、
行き先の綴りからディレクトリの名前が消えるので当たらない（issue #61。2026-09-16 に実測）。

| 結果 | コマンド |
|---|---|
| 止まる | `echo x > .ccnavi/common/rules.yml` |
| **通る** | `cd .ccnavi/common && echo x > rules.yml` |
| **通る** | `cd .ccnavi && echo x > common/rules.yml` |
| **通る** | `cd .claude && echo x > settings.json` |
| **通る** | `cd .claude/hooks && echo x > lint-py.sh` |
| 止まる | `cd .claude/worktrees/w && echo x > ../../scripts/ccnavi-git.sh` |

最後の 1 行が止まるのは、`cd` しても行き先の綴りに `scripts/ccnavi-git.sh` が残るため。
`shellread` はコマンドのうち実行される部分を切り出すが、`cd` を追って居る場所を持たない。

及ぶ先は `.ccnavi/` の下（層の設定・承認済みチケット・マーカー）だけではない。**コアファイルの
`.claude/settings.json` と `.claude/hooks/` にも及ぶ。** hook の登録そのものなので、ここが書けると
判定の仕組み自体を入れ替えられる。素通りではなく、実行後の監視（`PostToolUse`）は git の差分から
拾って戻すが、実行前に止める前提で書かれている文面（「変更が要る理由を伝えて利用者に依頼して
ください」）はこの経路では出ない。

## 決定

**`cd` の行き先を読んで、移った先から見たコマンドを組み、当てる先として足す。**
書かれた綴り（`Reading.text`）は動かさない。

- 読むのは `cd <リテラル 1 語>` だけ。行き先は `.` と `..` を畳んで継ぎ足す。サブシェル `( )` は
  行き先を出入りで戻す
- 移った先から見た綴りは `Reading.moved` に置き、判定は**中で実行されるコマンドの層と同じに
  扱う**（ADR-0045）。つまり `deny` と `ask` とサブエージェントの禁止にだけ当て、`allow` と
  「止めている間でも通す形」には当てない
- 継ぎ足すのは**引数だけ**で、コマンドの位置の語には足さない。実行役のコマンド
  （`env` `sudo` `timeout` など）と、文字列をコードとして実行するコマンドには、1 本まるごと
  継ぎ足さない
- 行き先が綴りから決まらない `cd`（引数なし、`cd -`、`~`、変数・置換・グロブを含む綴り、
  一覧に無いオプション、`pushd` `popd`）のあとでコマンドが実行されるなら、読み切れなかった
  ものとして縮退する（`unreadable-chdir`）。縮退した呼び出しに `allow` は当たらない（ADR-0011）

## 理由

**書かれた綴りを動かさないのは、いま当たっているものを外さないため。** ルールは綴りに固定して
書かれている。`_FORBIDDEN_COMMAND` は `sh …ccnavi-ticket.sh start` の `start` が直後に来る形に
当て、組み込みの守りは `(^|\x00)(mv|rm|tee|…)` と名前をコマンドの頭に固定して当てる。
`text` の語に行き先を継ぎ足すと、`start` が `projects/x/start` に、`rm` が `.ccnavi/rm` になって、
**いま止まっているものが止まらなくなる**。当てる先を別に足せば、倒れる向きは片側だけになる。
`cd` を読み違えても、当たるはずのものが当たらなくなることはない。

**当て先を足す形が既にある。** 実行役のコマンドの層（ADR-0045）が同じ性質を持つ。止める側の
ルールにだけ当て、元の形の判定を消さない。文面も「`env` が実行する `rm x` に当たりました」の
形を持っている。`cd` の層はここに乗せられるので、判定の側に足す規則が要らない。

**コマンドの位置の語に継ぎ足さないのは、上と同じ理由。** 実行役のコマンドを 1 本まるごと
外すのも同じで、中で実行されるコマンドの名前がどの語に立つかはオプションの読み方で決まる
（`timeout 5 rm x` の `rm`）。取り違えて名前に継ぎ足すと、そこだけ守りが消える。
足さなければ、今までと同じ当たり方が残るだけで済む。

**読めない `cd` で縮退するのは、そこから先の相対パスがどこに落ちるか決まらないため。**
`cd -` の後ろの `rm x` は、綴りだけを見ると無害なファイルを消す形に見える。読み切れない
コマンドに `allow` を当てない作法（ADR-0011）と同じ扱いにする。

## 得たもの・失ったもの

- 得たもの: `.claude/settings.json`・`.claude/hooks/`・ccnavi ディレクトリの下への `cd` 経由の書き込みが、
  実行前に止まる。`cd` した先の `rm -rf <名前>` や `cp` も同じ
- 得たもの: 組み込みの守りだけでなく、パスを綴ったプロジェクトのルールと、サブエージェントの
  禁止（`phase.forbidden`）にも同じ当て先が足される
- 得たもの: 文面が、どこへ書こうとしているかを綴りで示す（「`cd` で移った先から見ると
  `echo .claude/x > .claude/settings.json` で、そこに当たりました」）
- 失ったもの: 行き先の読めない `cd` のあとでコマンドを実行する形（`cd -`・`cd "$(…)"`・`pushd`）が
  確認に回る。`allow` が当たらなくなるので、通っていた形が 1 回聞かれる
- 失ったもの: パスではない引数にも継ぎ足すので、`cd .ccnavi && sed -i 's/a/b/' ../notes.md` の
  ような形が拒否に倒れることがある（`s/a/b/` が `.ccnavi/s/a/b/` になる）。守りの綴りが
  引数の中に現れる誤検知はもともと在るもの（`sed -i 's/.ccnavi/x/' notes.md`）と同じ筋で、
  倒れる向きは deny 側
- 失ったもの: `$( )` の中身は別の読みとして読むので、そこには行き先が届かない
  （`cd .claude && echo "$(rm settings.json)"`）。実行役のコマンドを通した形
  （`cd .claude && env rm settings.json`）と、`{ cd a; … }` の中も同じ。どれも今までと同じ当たり方が
  残るだけで、守りが減るわけではない
- 失ったもの: `case` の `)` をサブシェルの閉じ括弧と区別しないので、`case` の枝の中で `cd` した
  行き先が、枝を出たところで戻る。取りこぼす側に倒れる
- 失ったもの: 読みの規則が 1 つ増える。`cd` の行き先の読み方と、パスの畳み方

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| 書かれた綴り（`text`）の語に行き先を継ぎ足す | いま当たっているものが外れる。`sh …ccnavi-ticket.sh start` のサブエージェントの禁止と、名前をコマンドの頭に固定した組み込みの守りが、継ぎ足した綴りで当たらなくなる |
| `cd` を含むコマンドを一律に縮退させる | 穴は塞がらない。生の文字列にも守られた名前が残らないので `deny` は当たらず、確認に落ちるだけ。そのうえ `cd projects/<名前> && sh …ccnavi-git.sh …`（CLAUDE.md が指示している形）が毎回確認に回る |
| 実行前では拾わないと決め、実行後の監視に寄せる | 止める段が 1 つ減ったままになる。`.claude/settings.json` は hook の登録そのもので、実行後に気づいても書かれた後 |
| hook の payload の `cwd` も読んで、セッションが移っている場所から解く | 綴りの読みと、外から渡る状態が混ざる。`cwd` は 1 つ前の呼び出しの `cd` の結果で、そこを判定に入れると、同じコマンドが呼び出しの順で違う判定になる。別に決める |
