# ADR-0106: ccnavi が前提にしている作業の決まりは、セッション開始で要点だけを渡し、詳しいことは今ある入口に聞かせる

状態: 採用（2026-10-05 に実装。ユーザと方針を決めた）

## 状況

2026-10-05。このワークスペースの `CLAUDE.md` の「常に守ること」には、ccnavi の動作に依存する決まりが並んでいた。
ワークツリー（`.claude/worktrees/<名前>`）を切ってから編集する、git は `ccnavi-git.sh` を通す、下書きは `scratchpad/` に置く、
`projects/<名前>/` へ `cd` してから作業する、実装・調査・テストはサブエージェントに任せる、合意の要る変更の範囲、
承認済みチケットの状態は `ccnavi-ticket.sh status` で確かめる。

どれも ccnavi の判定・置き場・入口が前提で、ccnavi を入れたワークスペースなら同じことを書くことになる。ワークスペースごとに
書き写すと、ccnavi の動作が変わったときに食い違い、新しく入れたワークスペースでは書かれないまま始まる。

セッション開始の hook は、チケット制御が有効なときの作業の進め方（直接作業とチケット作業の使い分け）を既にモデルへ渡している。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 決まりは `SessionStart` の `additionalContext`（チケットの進め方と同じ経路）で渡す。文は実行ファイルが持つ | 置き場（`.claude/worktrees/`、`scratchpad/`）と入口の sh のパスは実行ファイルの定数と同じものを使えるので、動作と文がずれない | 別の設定ファイルに書いて読ませる（設定が 1 つ増え、文と動作が別々に変わる）。ADR-0057 のように設定の `additionalContext` に置く（そちらはワークスペースが足す勧告のためで、ccnavi 自身の動作の説明ではない） |
| 項目ごとに 1 行の要点だけを渡し、詳しいことは今ある入口に聞かせる。git の通る形とワークツリーの切り方は `ccnavi-git.sh --help`、止めた理由と代わりの手段は拒否の文面、承認済みチケットの状態は `ccnavi-ticket.sh status`、それ以外は `--docs` | 起動・再開・compact・clear のたびに常駐の文脈へ入るので、長いとそのぶん毎回重い。入口はどれも既にあり、要る場面で引ける | 詳しい手順まで全部渡す（常駐の文脈が膨らむ）。決まりを引く新しいコマンドを作る（今ある入口で足りる） |
| ワークツリーの行は id `main-tree`、git の行は id `raw-git` の deny が、共通レイヤーか自身のレイヤーにあるときだけ出す。有無はターンの終わりのルール（`match: Stop`）と同じ読み方（`ruleload`）で見て、新しい判定は作らない。共通レイヤーが読めずに組み込みの既定に戻ったときは出さない | 決まりを支えるのはそのルールで、ルールを外したワークスペースに出すと文と判定が食い違う | いつも出す（ルールが無いと文だけが残る）。ルールの中身（glob・regex）を見て判定する（新しい判定の仕組みになる）。id でなく文面で見る（言い回しで変わる） |
| `--docs` で引く行は、md の索引の案内を出す回だけ足す。`projects/` の行はプロジェクトがあるときだけ、`status` の行はチケット制御が有効なときだけ | 引いても何も当たらない入口、無い置き場、使わない操作を案内しない | いつも全行を出す |
| チケット制御の有無によらず出す。サブエージェントには出さない | ワークツリー・git の入口・下書きの置き場はチケットを使わなくても効く。サブエージェントの頭には `SubagentStart` が別の文を渡す | チケット制御が有効なときだけ出す（`disable` のワークスペースでも残る決まりが届かない） |
| チケットの進め方より前に置く | dry-run の注記を、進め方の最後の行のまま残す | 進め方の後ろに置く |
| 文はユーザに見せる文面と同じ書き方にする（簡潔な日本語、冗長な敬語を使わない） | エージェントの応答の書き方に合わせる | — |

## 得たもの・失ったもの

**得たもの**

- ccnavi を入れたワークスペースなら、`CLAUDE.md` に書かなくても同じ決まりが届く。置き場と入口のパスは実行ファイルの
  定数から組むので、動作が変わっても文が追従する
- 決まりは `CLAUDE.md` と二重に持たずに済む

**失ったもの**

- **毎回の常駐の文脈が 7〜9 行増える。** 1 行の要点に絞り、テストで行数と字数の上限を固定した
- **文を変えるには実行ファイルを作り直す。** ワークスペースごとに言い回しを変えることはできない
- **チケット制御を `disable` にしたワークスペースにも文が届く。** 以前は何も渡していなかった（ユーザの決定）
- **ワークツリーと git の行は id で見る。** 同じ働きのルールを別の id で書いたワークスペースには、その行が出ない。
  逆に、id だけ同じで中身の違うルールでも行は出る
- **セッションの開始でルールを 1 度多く読む。** 判定のたびではなく、1 セッションに 1 回
- **詳しいことを `--docs` で引けるかは、ワークスペースの文書次第。** ccnavi の側には決まりの詳しい文書を持たない
