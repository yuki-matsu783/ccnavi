# ADR-0082: フェーズの図を区分の枠で分け、図の下は凡例と当てはまるときだけの注意にし、細かい案内は初回の吹き出しとヘルプに寄せる

状態: 採用（ADR-0070 の「描いていないものを図の下に常に出す」「置き場所は id だけで決まる」と、
ADR-0078 の「図の下に常に出す」の 2 行を改める）

## 状況

2026-09-23。拡張の雛形（`phases-doc.ts` の `TEMPLATE_PHASES_TEXT`）でフェーズ管理画面の図を開くと、
調査 → 設計／受入テスト作成 → 実装とテスト → 実装フィードバック対応、という流れが読めなかった。

- 雛形は `order: sequential` で `after` が 1 本も無く、順序がファイルのどこにも無かった
- 点は id の辞書順に並び、`acceptance` と `implement` の線が間の `design` を突き抜けていた
- feedback の種類は `after` を持てない（ADR-0078）ので、種類どうしの線では「レビューのあと」を描けない
- 図の下には 6 文の注意書きが常に出ていて、要る注意がほかの文に埋もれていた。利用者は「何を言っているのか、
  そもそも要るのか」と問い、初回だけ案内を出し、それ以降はヘルプを押さない限り細かい案内は出さない形を求めた

実装のあと、Sonnet と Opus の敵対的レビューにかけ、下の「レビューで直したこと」を入れた。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| **雛形を `order: dag` にし、流れを `after` で書く**（research ← design, acceptance ← implement）。受入テストは実装より先（`overlap` を外す） | 図に出る流れと、判定が実際に待つ順序を一致させる。利用者が選んだ（案 1、受入テストは実装より先） | sequential のまま `after` だけ書く（判定に効かない飾りの矢印になる）。ファイルの並びを矢印で描く（計画の順ではないものを描く） |
| **work と feedback を枠で分け、枠の間に「レビュー後」の矢印を描く。** feedback の種類は work の右の列に置く | feedback は `plan:` ではなく、レビューのあとに `feedback:` へ並べる対応。区分の順は仕組みどおりで、種類どうしの関係ではないので、種類の線とは別の見た目にする | feedback の種類にも `after` を許す（ADR-0078 が退けた） |
| **線は点と点の間の隙間を通る折れ線**（`phases-route.ts`）。同じ組の線は関係ごとに少しずらす | 点の置き場所を変えずに（ADR-0070 の「関係を直しても点が動かない」を守る）、線が点を横切らないようにする。格子のどの 2 点を結んでも横切らないことを単体テストで確かめる | ベジェ曲線（別の行で 2 列以上離れた組が間の点を突き抜ける）。繋がった種類を寄せる並べ方（線を 1 本足すと点が動く） |
| **図の下は線の見本付きの凡例 1 行と、当てはまるときだけの注意**（sequential なのに after がある、層の画面で dag を選んでいる、このファイルに無い種類を指す関係がある、id が空の種類がある） | 常に出す文は、読まれなくなって要る注意を隠す。注意は、その画面で本当に起きていることだけを言う | ADR-0070・0078 のとおり常に出す |
| 「人が見る」の意味は札のツールチップとヘルプへ、判定が使う待ち方が承認のときに決まることはヘルプと案内へ移す | 図の読み方ではなく、仕組みの説明。見たい人がヘルプから開く | 図の下に常に出す |
| **初回だけ吹き出しの案内を出す。** 見たかどうかは拡張の `globalState` に画面ごと（`tour.<画面>`）に持つ。閉じたら（最後まで見ても、途中でやめても）印を残す。ヘルプの「案内をもう一度見る」でいつでも出せる | 画面の `setState` はタブを閉じると消えるので「初回」を決められない。画面ごとにするのは、ほかの画面に案内を足したときに、1 つ見ただけで全部が消えないように（利用者が選んだ） | 拡張全体で 1 回。1 枚の案内パネル（利用者は吹き出しを選んだ） |
| 案内は画面の様子（一覧と図、絞り込み、開いた行）を動かすが、**閉じたら元に戻し、途中の切り替えは控えに書かない** | 案内が利用者の画面を黙って書き換えたまま残らないように。途中でタブを閉じても、次に開く表示が変わらないように | 案内が動かしたまま残す |

## 変えないこと

- 図は判定をしない（ADR-0035、ADR-0070）。線が落ちた理由（綴り違いか、ほかの層の種類か）は言わない。
  層の画面では「ほかの層の種類を指しているならそのままでよい」とだけ添える
- 点の置き場所は、id・`after`（dag のとき）・区分（work か feedback か）だけで決まる。関係（`requires` / `overlap`）を
  直しても点は動かない

## 失うもの

- 雛形から作ったファイルは dag になる。辺を書き忘れた種類は並行して進む（sequential の「前を全部待つ」ではない）。
  雛形の頭のコメントと画面の案内がそれを言う
- 細かい説明はヘルプを押さないと見えない。ツールチップはキーボードやタッチでは見つけにくいので、同じことをヘルプにも書く
- 状態が 1 つ増える（`globalState` の印）。消す操作は用意していない（案内はヘルプから出せるので、消す必要が無い）
- 案内は画面の部品を選択子で指すので、画面の並びを変えるたびに追従が要る。指す先が無いときは吹き出しを画面の中ほどに出して文だけを見せる

## レビューで直したこと

- 吹き出しの高さを決め打ちしていて、長い一覧を指すと画面の外に出て「次へ」が押せなくなった。実寸で置き、画面の外に出さない（`tour-place.ts`）
- Tab で裏の画面へ焦点が逃げた。吹き出しのボタンの中だけを巡らせ、焦点は「次へ」から始め、閉じたら元の場所へ戻す
- 案内が絞り込みを消し、見本の行を開いたまま残し、途中の切り替えを控えに書いていた。閉じたら戻し、控えには書かない
- 線にならなかった参照を生の件数で数えていた。同じ種類・同じ関係・同じ id は 1 件にする
- sequential の注意が、ほかの層を指す after だけのときに出なかった。書いた after で判定する。層の画面で dag を選んだときの注意を足した
- 最後の段に同じ働きのボタンが 2 つ並んでいた。「完了」1 つにする
- 「レビュー後」の矢印が overlap の破線と見分けにくかった。点線にし、凡例に見本を足す
- 案内の最中に裏の画面をクリックできる、という指摘は、全面の覆い（`.tour`）がクリックを受けることを Chromium で確かめ、当たらなかった
