# ADR-0020: 前から在った変更は差し戻さない

状態: 採用

## 状況

最初は `git status` に出たものを全部「直前の実行が汚した」として返していた。このリポジトリで
動かすと、他セッションの書きかけを毎回「戻せ」と言うことになった。

## 決定

初めて見たときにその場で控え（`state/<セッション>.json`）を取り、以降に新しく現れたものだけを
原因付きで差し戻す。控えの側も 1 度は伝えるが、`POST_PREEXISTING` と名乗り、戻すなと明示し、
自動復元の対象からも外す。控えは違反が無いときにも必ず書く。同じ場所でも「中身が変わった」の
次に「消えた」が来れば、別の出来事としてもう一度言う。

ターンの終わり（Stop）の報告も同じ形で、`UserPromptSubmit` で控えた基準に無い変更だけを人へ
示す。基準が無ければ黙る。

## 理由

差し戻す相手を間違えると、エージェントは他人の作業を戻しにいく。控えを初回に必ず書くのは、
違反が無いときに書き落としていて、綺麗な作業ツリーで始まったセッションが永久に「初回」の
ままになり、その後の汚れが全部「前から在ったもの」に化けていたため。テストで見つけた。

Stop で基準が無いときに黙るのは、利用者自身の書きかけも、他のセッションが置いたものも、
前のターンで片付けなかったものも、すべてこのターンの成果として並ぶから。同じものを何度も
見せられた人は、次から読まなくなる。見えていない期間を見えたことにしない（REQ-PST-07）。

## 得たもの・失ったもの

- 得たもの: 並行するセッションの書きかけを戻さない
- 失ったもの: 控えはセッションごとの一時的な状態で、消えても次の起動で取り直せるが、
  取り直した回は前から在ったものが再び 1 度伝わる

## 採らなかった案

- `git status` の全部を差し戻す。上のとおり
