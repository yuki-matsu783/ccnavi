# ADR-0098: 置き場を既定に固定し、置き場を動かす環境変数を廃止する

状態: 採用

> この ADR は番号を先に確保するために置いた。実装はチケット i0064 で行う。それまでは main の実装は
> 環境変数で置き場を動かせるままである。

## 状況

2026-09-24。ADR-0052 で共通層の 3 本を固定したあとも、置き場を動かす環境変数が 6 つ残っていた。

| 変数 | 既定 | 起点 | 空文字 |
|---|---|---|---|
| `CCNAVI_PROJECTS` | `projects` | ワークスペースルート | プロジェクトを数えない |
| `CCNAVI_PROJECT_HOME` | `.ccnavi` | 各 git プロジェクトルート | 既定のまま |
| `CCNAVI_TICKETS_PROPOSAL` | `wip/proposals` | 各ツリーのルート | 既定のまま |
| `CCNAVI_TICKETS_APPROVED` | `.ccnavi/approved` | 各ツリーのルート | 既定のまま（`--lint` が指摘する） |
| `CCNAVI_LOG` | `logs/log.jsonl` | ワークスペースルート | 記録しない |
| `CCNAVI_STATE` | `logs/state` | ワークスペースルート | 状態を保存しない |

**既定から変えている配布先は見当たらなかった。** 導入スクリプト（`scripts/ccnavi-setup.sh`）が
配る `settings.json` に書くのは既定と同じ値だけで、`CCNAVI_LOG` は常に、残りの 4 つ
（`CCNAVI_STATE`・`CCNAVI_TICKETS_PROPOSAL`・`CCNAVI_TICKETS_APPROVED`・`CCNAVI_PROJECT_HOME`）は
`--all` のときだけ書く。`CCNAVI_PROJECTS` は書かない。このリポジトリで既定と違う値を入れているのはテストだけだった。

それでも、値を読む側である実行ファイル
（`settings.py` の overrides 表）、`.ccnavi/scripts/` の sh（`ccnavi-common.sh`・`ccnavi-git.sh`・
`ccnavi-fetch.sh`・`ccnavi-push-approved.sh`・`ccnavi-review.sh`）、VS Code 拡張は、それぞれが「env を見て、無ければ既定」の分岐を持っていた。しかも、読む側ごとに
扱いが揃っていなかった。

| 食い違い | 起きること |
|---|---|
| `CCNAVI_PROJECTS` の絶対パスを、実行ファイルと `ccnavi-git.sh push` は受けるが、`ccnavi-common.sh` の `ccnavi_project` は相対パスとしてしか照合しない | ラッパーの記録が `logs/<プロジェクト>/` に分かれない |
| `CCNAVI_STATE` の絶対パスを、実行ファイルは受けるが、`ccnavi-review.sh` は `$root/` の後ろにつなげる | `ccnavi-review.sh` だけが存在しない状態ディレクトリを見る |
| VS Code 拡張は `CCNAVI_TICKETS_PROPOSAL` を読まず、既定のパスを監視する | 既定から動かすと、提案の増減でボードが自動で更新されない（README に注記していた） |
| `ccnavi-push-approved.sh` は、末尾の `/` を落として空になるパスと `.` を既定に戻す | sh が、置き場が変わることを前提にした正規化とテストを抱えている |

加えて、ADR-0077 の `DENY_SCRIPT_ENV_OVERRIDE` は、保護済みの sh を呼ぶコマンド行で `CCNAVI_*` を
設定する形を止めている。環境変数が在る限り、その sh が読む値を差し替えられる経路も在る。

`requirements.md` に、置き場を変えられることを約束する要求は無い。

## 決定

**置き場は既定だけにする。変えたい要望が出たら、そのとき設定項目を足す。**

上の 6 つの環境変数を廃止する。

- `settings.py` から 6 つの定数と overrides 表の 6 行を削る。**この表は
  `ccnavi.settings.local.json`（ccnavi 自身を開発するときだけ読む上書き設定）と共有しているので、
  そちらの同じキーも読まなくなる**（ADR-0052 と同じ）
- **空文字を受ける設定項目も消す。** 「記録しない」「状態を保存しない」「プロジェクトを数えない」は指定できなくなる。
  プロジェクトを数えたくなければ `projects/` を作らなければよい
- 環境に値が残っていても**無視する。止めない。** 残った値のために判定を止めると、既定と同じ値を
  書いていた導入済みの環境がすべて止まる
- `Settings` の項目（`conf.projects` など）は既定の値を持って残す。値を渡している先の 20 か所ほどは変えない
- sh には既定のパスを直接書く。`ccnavi-push-approved.sh` のパスの正規化は消す
- VS Code 拡張は置き場の env を読まない。プロジェクト画面の「置き場が無効（`CCNAVI_PROJECTS` が空）」の
  分岐・文面・ボタンの抑止を消す

### 残すものとの区別

「置き場を動かす設定項目」とは、**ccnavi が自分で決められる置き場を、人が別の場所へ向けるための設定**を指す。
次の 3 つはこれに当たらないので残す。

| 残すもの | 当たらない理由 |
|---|---|
| `CCNAVI_BIN_PATH` | hook が起動する実行ファイルの指定。実行ファイルの置き場はプロジェクトごとに違い、誤った既定は無関係のファイルを守ることになるので、**既定を持たない**設計になっている（`settings.py` の `BIN_ENV`）。固定する既定がそもそも無い。守る対象を決める鍵でもある |
| `CCNAVI_WORKSPACE` | sh が cwd から上へ辿ってもワークスペースを見つけられないときの逃げ道。置き場を動かすのではなく、どこがワークスペースかを教えるもの |
| 診断のフラグ（`--log` `--state` `--approved` `--tickets` `--projects` `--project-home`） | 人が書く設定ではなく、hook からは渡されない。テスト 20 本以上がこれで一時的な置き場を指しているので、廃止は別に扱う |

ただし最後の行は、設定項目に当たらないから残すのではなく、廃止を**後回しにしたもの**。フラグが残る間、「置き場は動かない」が成り立つのは hook と sh
だけで、診断では置き場を動かせる。

### 導入済みの環境

導入スクリプトは 6 つを書かない（`--all` の一覧からも外す）。**既に入っている `settings.json` の
`env` からは、この 6 つを外す。** `env` は導入スクリプトが管理するキーなので、もう読まれない変数を残さない
（ADR-0052 の「設定として嘘をつかない」と同じ理由）。外した値が既定と違っていたら、名前と値を
1 行ずつ出す。導入は止めず、終了コードも変えない。

### `projects/` の名前がぶつかったとき

**見つける条件:** ワークスペースの git の索引に、`projects/` の下の通常のファイル（gitlink 以外）が
1 本でも載っている（`git ls-files -s -- projects/` の mode が `160000` 以外）。gitlink だけのときは
ぶつかりではなく載せ忘れとして別に扱う（下の「索引に gitlink しか無いとき」）。これはワークスペース自身のソースに `projects/` があるということで、
置き場を固定したあとは名前の衝突を避ける手段が無い。ぶつかると次のことが起きる。

- `.gitignore` に `/projects/` を足せない（足すとソースが追跡から外れる）ので、
  「無視されていない」の警告が消えない
- `projects/` の下で `.git` を持つもの（サブモジュールなど）がプロジェクトとして数えられ、
  その中の `.ccnavi/config/` が層として読まれる

**知らせる場所は 3 つ。**

| 場所 | 形 |
|---|---|
| `ccnavi --lint` | `(projects)` の warn。これが出るときは既存の「無視されていない」を出さない |
| VS Code 拡張のプロジェクト画面 | 上の warn をバナーで出す。「`.gitignore` に足す」ボタンを出さない |
| 導入スクリプト | 入れ終わったところで同じ条件を見て、同じ案内を出す。止めない |

**文面では、何が起きるかと直し方まで伝える。**

> `projects/` はワークスペースの git が追跡している（例: `projects/foo/main.py`）。
> ccnavi はワークスペース直下の `projects/` をプロジェクトの置き場として使い、名前は変えられない。
> このままだと `projects/` の下で `.git` を持つディレクトリ（サブモジュールを含む）が
> プロジェクトとして数えられ、その中の設定が判定に使われる。
> 直すには、ワークスペースの `projects/` を別の名前に移す（例: `git mv projects apps`）。
> ccnavi でプロジェクトを置かないなら、このままでも動く。そのときは `projects/` の下に
> `.git` を持つものを置かない

- **warn にとどめ、error にしない。** プロジェクトを置かない運用なら、判定は正しく動く
- **既存の「無視されていない」を出さない。** 原因が同じで、その文面の「`.gitignore` に入れる」が
  この場合は誤った案内になる。2 つ並ぶと、誤ったほうの案内が先に実行されるおそれがある
- **導入スクリプトでも知らせる。** 導入したときがいちばん気付きやすい。`--lint` を打たない人は、
  拡張を開くまで気付かない。条件と文面を sh にもう 1 度書くことになるが、止める判定ではなく
  知らせるだけなので、P13（判定は hook と実行ファイルが持つ）には反しない

**他の置き場のぶつかりは扱わない。** `.ccnavi/` と `wip/proposals/` は ccnavi のためにワークスペースの
git が追跡する場所で、既存の中身とぶつかっても並ぶだけ。`logs/` は今も既定のまま動いていて、
固定にしても振る舞いは変わらない。

### 索引に gitlink しか無いとき（載せ忘れ）

`.gitignore` に `/projects/` を入れ忘れたまま `git add -A` すると、索引には `projects/<名前>` が
gitlink（入れ子のリポジトリを 1 つの版として載せたもの）として載る。ワークスペース自身のソースに
`projects/` があるわけではないので、改名は要らない。**索引の `projects/` の下が gitlink だけなら、
ぶつかりではなく載せ忘れとして、索引から外して `.gitignore` に `/projects/` を入れる案内を出す**
（コミット済みなら `git rm -r --cached projects`、コミット前なら `git reset -- projects`）。
**通常のファイルが 1 本でもあれば、gitlink の有無に関わらずぶつかりとして改名を案内する。**
そのときは `.gitignore` に入れるとソースが追跡から外れるので、載っている gitlink は文面で
1 本ずつ名指しするだけにする。

載せ忘れも warn にとどめ、知らせる場所はぶつかりと同じ 3 つ。既存の「無視されていない」は出さない
（載せ忘れの文面は `.gitignore` に入れるところまで案内している。索引に gitlink が残る間は `.gitignore` に
足しても無視されないので、2 つを並べると誤った順で直されるおそれがある）。`.gitmodules` に登録した意図的な
サブモジュールも、mode だけを見るので区別しない。拡張は git の索引に触らないので、どちらの場合も
「`.gitignore` に足す」ボタンは出さない。

## 理由

置き場を読む側がどこを見るかを、コードの分岐を追わずに答えられるようになる。読む側ごとの食い違いは、
個別に直すのではなく、分岐と一緒に無くなる。

使われていない設定項目は、先に用意しておいても得るものが無い。設定項目がある限り、置き場を読むコードを
新しく書くたびに「env を見て、無ければ既定」を足すことになり、足し忘れや扱いの違いが次の
食い違いになる。上の表の 4 行はどれもそうやってできた。要望が出てから、その要望に合う形で
足すほうが、使われない一般形を保守するより安い。

## 得たもの・失ったもの

得たもの:

- 置き場の決まり方が 1 通りになる。実行ファイル・sh・拡張から分岐が消える
- 状況の表の食い違いが 4 つとも消える
- `ccnavi-push-approved.sh` のパスの正規化とそのテストが要らなくなる
- ADR-0077 が止める `CCNAVI_*` のうち、sh の置き場を差し替えられた 6 つが意味を失う
- README の環境変数の表が 6 行減る
- `projects/` がぶつかったとき、サブモジュールを知らないうちに層として読むのではなく、原因と直し方が出る

失ったもの:

- **「記録しない」「状態を保存しない」「プロジェクトを数えない」を env で指定できなくなる。**
  状態を保存しないと実行後の監視が働かないので、保存を止める意味はもともと薄い。記録を止めたい人は
  止められない
- **名前がぶつかったワークスペースは、自分のソースの `projects/` を改名するしかない。**
  そのリポジトリの参照（ビルド設定、CI、import）を直す仕事になる
- **配布先で値を変えている人がいれば、既定に戻る。** こちらから確かめる手段が無い。導入スクリプトを
  打ち直した人には名指しの 1 行が出るが、打ち直さない人は気付かない（ADR-0052 の代償と同じ形）
- **導入スクリプトが既存の `settings.json` から 6 つのキーを消す。** 人が手で書いた値も消える
  （既定と違えば名指しする）
- **テストの書き方が変わる。** env で置き場を指していたテストと、「数えない」を
  `CCNAVI_PROJECTS=""` で指定していたテストを直す。ADR-0067 が「人が `settings.json` に書く経路に
  近い」として選んだ形を捨てる
- 導入スクリプトと `--lint` が同じ条件と文面を 2 か所で持つ

## 採らなかった案

- **`CCNAVI_PROJECTS` だけ消す。** 変更は小さいが、同じ理由で要らない設定項目が 5 つ残り、
  同じ議論をあと 5 回することになる
- **置き場は固定し、`CCNAVI_LOG` / `CCNAVI_STATE` の空文字（止める設定）だけ残す。** 記録を止めたい人の
  逃げ道は残るが、「場所は変えられないが止めることはできる」という半端な設定項目になる。要望は出ていない
- **診断のフラグも同時に消す。** 1 回で片付くが、テストで一時的な置き場を作る部分を 20 本以上直すことになり、
  レビューが重くなる。別に扱う
- **消したうえで、環境に値が残っていたら `--lint` で知らせる。** 黙って既定に戻る人に気付かせられるが、
  消した変数を読むコードが残る。導入スクリプトの 1 行で足りるとみた（ADR-0052 は同じ問いを
  「決めていない」で残していた。ここで「入れない」に決める）
- **`projects/` がぶつかったら error にする。** 見落とされにくいが、プロジェクトを置かない運用で
  正しく動いているワークスペースに error を出し続けることになる

## 関連

- ADR-0052（共通層の置き場を固定する）。同じ形の判断で、この ADR はそれを残りの置き場へ広げる
- ADR-0067（層のフラグを診断に限る）。「`projects/` を数えない」を `CCNAVI_PROJECTS=""` で
  指定する形にテストをそろえた回。その形はこの ADR で無くなる
- ADR-0077（判定は hook が持つ）。`DENY_SCRIPT_ENV_OVERRIDE` の「採らなかった側」に
  「`CCNAVI_PROJECTS` を変えた配布先が使えなくなる」とある。その配布先は想定しなくなった
- ADR-0042（設定と記録の置き場）・ADR-0054・ADR-0055（提案と承認済みチケットの置き場）。
  それぞれ「env で決められる」と書いているが、この ADR で env で決める方法を無くす
- ADR-0074（ボードが動いたものを示す）。`CCNAVI_TICKETS_APPROVED` が既定と違うときの扱いに
  触れている。既定と違うことは起きなくなった
