# ADR-0068: `cd` で移った先から見た綴りを、当てる先として足す

状態: 採用

## 状況

実行前の守りとルールは、コマンドの**綴り**に当てる。`cd` で守られたディレクトリへ入ってから書くと、
行き先の綴りからディレクトリの名前が消えるので当たらない（issue #61。2026-09-16 に実測）。

| 結果 | コマンド |
|---|---|
| 止まる | `echo x > .ccnavi/common/rules.yml` |
| **通る** | `cd .ccnavi/common && echo x > rules.yml` |
| **通る** | `cd .ccnavi && echo x > common/rules.yml` |
| **通る** | `cd .claude && echo x > settings.json` |
| **通る** | `cd .claude/hooks && echo x > lint-py.sh` |
| 止まる | `cd .claude/worktrees/w && echo x > ../../scripts/ccnavi-git.sh` |

最後の 1 行が止まるのは、`cd` しても行き先の綴りに `scripts/ccnavi-git.sh` が残るため。
`shellread` はコマンドのうち実行される部分を切り出すが、`cd` を追って居る場所を持たない。

及ぶ先は `.ccnavi/` の下（層の設定・承認済みチケット・マーカー）だけではない。**コアファイルの
`.claude/settings.json` と `.claude/hooks/` にも及ぶ。** hook の登録そのものなので、ここが書けると
判定の仕組み自体を入れ替えられる。素通りではなく、実行後の監視（`PostToolUse`）は git の差分から
拾って戻すが、実行前に止める前提で書かれている文面（「変更が要る理由を伝えて利用者に依頼して
ください」）はこの経路では出ない。

## 決定

**`cd` の行き先を読んで、移った先から見たコマンドを組み、当てる先として足す。**
書かれた綴り（`Reading.text`）は動かさない。

- 読むのは `cd <リテラル 1 語>`（`builtin cd`・`command cd` を含む）と、`env -C <パス>`・
  `sudo --chdir=<パス>`。行き先は `.` と `..` を畳んで継ぎ足す。サブシェル `( )` は行き先を出入りで戻し、
  `|` `|&` `&` の左はサブシェルなので右と後ろには効かない
- 移った先から見た綴りは `Reading.moved` に置き、そこから 1 枚ずつ外した層（ADR-0045）も並べる。判定は
  **中で実行されるコマンドの層と同じに扱う**。つまり `deny` と `ask` とサブエージェントの禁止にだけ当て、
  `allow` と「止めている間でも通す形」には当てない
- 継ぎ足すのは、リダイレクトの行き先（コマンドの位置の前に書いたものと、コマンドが無いものも）と、
  中で実行されるコマンドの名前より後ろの語。**コマンドの位置の語には継ぎ足さない**
- 行き先が綴りから決まらないとき（引数なし、`cd -`、`~`、変数・置換・グロブ、一覧に無いオプション、
  `pushd` `popd`、`case` の枝）は、**そこから先を継ぎ足さないだけ**にする。縮退させない
- 居場所の綴りは 256 字、1 回の読みで継ぎ足す語数は 2000 語まで。越えたら継ぎ足さない

## 理由

**書かれた綴りを動かさないのは、いま当たっているものを外さないため。** ルールは綴りに固定して
書かれている。`_FORBIDDEN_COMMAND` は `sh …ccnavi-ticket.sh start` の `start` が直後に来る形に
当て、組み込みの守りは `(^|\x00)(mv|rm|tee|…)` と名前をコマンドの頭に固定して当てる。
`text` の語に行き先を継ぎ足すと、`start` が `projects/x/start` に、`rm` が `.ccnavi/rm` になって、
**いま止まっているものが止まらなくなる**。当てる先を別に足せば、倒れる向きは片側だけになる。
`cd` を読み違えても、当たるはずのものが当たらなくなることはない。

**同じ理由で、行き先が読めないときに縮退させない。** 縮退は当てる先を生の文字列に落とすので
（ADR-0011）、コマンドの頭に固定した守りがそこでも当たらなくなる。`cd - && rm -f .ccnavi/common/rules.yml` は
書かれた綴りでは止まるのに、縮退させると止まらなくなる（敵対的レビューで実測）。読めないのは
居場所であって、コマンドではない。読めない居場所のぶんは、当てる先を足さないことで足りる。

**当て先を足す形が既にある。** 実行役のコマンドの層（ADR-0045）が同じ性質を持つ。止める側の
ルールにだけ当て、元の形の判定を消さない。文面も「`env` が実行する `rm x` に当たりました」の
形を持っている。`cd` の層はここに乗せられるので、判定の側に足す規則が要らない。層まで並べるのは、
`cd .claude && sudo rm settings.json` の移った先が `sudo rm .claude/settings.json` で、
`(^|\x00)rm` がそこに当たらないため。書かれた綴りと同じように外して、はじめて当たる。

**コマンドの位置の語に継ぎ足さないのは、上と同じ理由。** 移った先の層で名前に継ぎ足しても
守りが消えることはないが（元の層は残る）、名前に付いた層はどのルールにも当たらないので、
当てる先が増えるだけで何も止められない。実行役のコマンドを通した形では、中で実行される
コマンドの名前の位置を `_peel` と同じ読み方で出し、その後ろに継ぎ足す。

**上限を持つのは、読みの時間が判定の期限の外にあるため。** 判定は 3 秒で切るが、それを見るのは
読み終えたあと。`cd a` を数千回並べると居場所の綴りが伸び、畳み直す値段が長さに比例するので、
上限が無いと全体が二乗になる（敵対的レビューで 150 秒を実測）。`$( )` の入れ子に深さの上限を
置いてあるのと同じ向きで、新しく伸びる経路にも上限を置く。

## 得たもの・失ったもの

- 得たもの: `.claude/settings.json`・`.claude/hooks/`・ccnavi ディレクトリの下への `cd` 経由の書き込みが、
  実行前に止まる。`cd` した先の `rm -rf <名前>`・`cp`・`dd of=`・`> <名前>` も同じ
- 得たもの: 実行役のコマンドを通した形（`cd .claude && sudo rm settings.json`）と、
  `env -C <パス>`・`sudo --chdir=<パス>` で移る形も止まる。どちらも `cd` と同じ穴だった
- 得たもの: 組み込みの守りだけでなく、パスを綴ったプロジェクトのルールにも同じ当て先が足される
- 得たもの: 文面が、どこへ書こうとしているかを綴りで示す（「`cd` で移った先から見ると
  `echo .claude/x > .claude/settings.json` で、そこに当たりました」）
- 失ったもの: パスではない引数にも継ぎ足すので、`cd .ccnavi && sed -i 's/a/b/' ../notes.md` の
  ような形が拒否に倒れることがある（`s/a/b/` が `.ccnavi/s/a/b/` になる）。守りの綴りが
  引数の中に現れる誤検知はもともと在るもの（`sed -i 's/.ccnavi/x/' notes.md`）と同じ筋で、
  倒れる向きは deny 側
- 失ったもの: `$( )` の中身には外側の行き先が届かない（`cd .claude && echo "$(rm settings.json)"`）。
  中身の中で移った先は届く。`case` の枝の中、一覧に無い実行役のコマンド（`ssh host <cmd>`）が移す先も
  届かない。どれも今までと同じ当たり方が残るだけで、守りが減るわけではない
- 失ったもの: 記録の `unwrapped` が、実行役のコマンドの層と `cd` で移った先の両方を運ぶ欄になる。
  欄の上では区別が付かないので、「実行役のコマンド越しに止めた件数」の集計には `cd` の分が混ざる
- 失ったもの: 読みの規則が増える。`cd` の行き先の読み方、パスの畳み方、区切りごとの居場所の続き方、
  中で実行されるコマンドの位置の出し方

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| 書かれた綴り（`text`）の語に行き先を継ぎ足す | いま当たっているものが外れる。`sh …ccnavi-ticket.sh start` のサブエージェントの禁止と、名前をコマンドの頭に固定した組み込みの守りが、継ぎ足した綴りで当たらなくなる |
| 行き先が読めない `cd` のあとを縮退させる（当初の実装） | 縮退は生の文字列に当てるので、`cd - && rm -f .ccnavi/common/rules.yml` のように**今は止まっている形**が止まらなくなる。読めないのは居場所であって、コマンドではない |
| 読めない居場所のときだけ `allow` を抑える印を別に持つ | 「読めたが居場所が決まらない」という 3 つめの状態が増え、文面・記録・判定の全部に回る。守られるのは「`allow` に書いた形を、居場所が違う場所で通す」という場合だけで、いまの `allow`（読み取りの誘導とラッパースクリプト）ではそこに実害が無い |
| `cd` を含むコマンドを一律に縮退させる | 穴は塞がらない。生の文字列にも守られた名前が残らないので `deny` は当たらず、確認に落ちるだけ。そのうえ `cd projects/<名前> && sh …ccnavi-git.sh …`（CLAUDE.md が指示している形）が毎回確認に回る |
| 実行前では拾わないと決め、実行後の監視に寄せる | 止める段が 1 つ減ったままになる。`.claude/settings.json` は hook の登録そのもので、実行後に気づいても書かれた後 |
| hook の payload の `cwd` も読んで、セッションが移っている場所から解く | 綴りの読みと、外から渡る状態が混ざる。`cwd` は 1 つ前の呼び出しの `cd` の結果で、そこを判定に入れると、同じコマンドが呼び出しの順で違う判定になる。別に決める |
