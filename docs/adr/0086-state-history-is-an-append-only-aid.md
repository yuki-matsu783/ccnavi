# ADR-0086: 状態が動いた跡を、チケットごとの追記専用のファイルに残す。正は置き場のまま

状態: 採用

## 状況

チケットの状態は置き場が表す（ADR-0055）。置き場は「いまどこに在るか」だけを言い、「いつ・どの経路で
ここへ来たか」は言わない。知る手段は、承認済みチケットの欄（`started_at` / `completed_at` /
`cancelled_at`、`ccnavi_approved.approved_at`）と、マーカーの `at` と、git の履歴だけだった。

- 欄は最後の 1 回ぶんしか持たない。承認と着手の時刻は分かるが、レビュー待ちへ動いた時刻、
  人がレビューを済ませて `done/` へ動いた時刻、どの経路（端末・ボード・エージェントの sh・hook）で
  動いたかは残らない
- マーカーは消える（同じ番号に子が足されると `clear_marks` が消す）。「一度レビュー済みになってから
  開き直った」は、消えたあとには読めない
- git の履歴はコミットの粒度で、承認済みチケットの移動とマーカーはまとめてコミットされる。
  `ccnavi-push-approved.sh` を通らずに残った分は、コミットされるまでどこにも無い

ボードのカードで「このチケットはどう動いてきたか」を見たい、という要望が出た（2026-09-26）。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 実行ファイルが状態を動かすたびに 1 行 1 JSON を追記する。欄は `at`（UTC の ISO 8601）・`ticket`・`kind`・`from`・`to`（置き場の名前。動かないマーカーは `null`）・`via`（`cli` / `terminal` / `board` / `hook`）と、種類ごとの添え（`phase`・`mark`・`reason`・`base_sha` など） | 置き場は「いま」だけを言う。「いつ・どの経路で」は、動かした瞬間にしか分からない | 置き場の移動を git の履歴から組み直す。コミットの粒度に縛られ、コミットされる前の移動は見えない |
| 書く場所は、動かす操作の最下段（`approval.admit` / `revise_copy` / `followup` / `settle_review` / `write_mark` / `clear_marks` / `write_parent_mark`、`ops.start` / `_move`） | 置き場を動かす経路が増えても、最下段を通る限り漏れない。承認・レビュー・締めの経路は同じ関数を通る | 入口（副命令ごと）で書く。副命令の中で複数のチケットが動く（`confirm` が子を `done/` へ動かしてマーカーを置く）ので、入口では何が動いたかを取り直すことになる |
| 置き場はチケットごと。承認済みの領域の `events/<識別子>.ndjson` | 1 本のファイルに全チケットを書くと、並行する枝が同じファイルに追記し、合流のたびに衝突する。チケットごとなら、同じチケットを 2 つの枝で動かしたときだけ衝突する | 親ごと（`phases/<親>/`）。親の枝の上では同じ衝突が起きる |
| マーカーの跡は親の跡に残す（`phase-mark` / `phase-reopened` / `parent-mark`） | マーカーは親のもの（`phases/<親>/`）で、置き場のどのチケットにも属さない | 子のそれぞれに書く。同じ事実が子の数だけ並ぶ |
| git で運ぶ。マーカーと同じく親のブランチに乗る（`ccnavi-push-approved.sh` が置き場ごと運ぶ） | 別の機械で続きをするときに、跡だけが途切れない（設計 9.2） | 記録と同じくワークスペース側（`logs/`）に置く。機械をまたぐと消える |
| 拡張子は `.ndjson`。`.jsonl` にしない | `*.jsonl` を無視するリポジトリは多く（このリポジトリも判定の記録のために無視している）、無視されると `git add -- <置き場>` が黙って落とす。運べない | `.jsonl` にして `.gitignore` に例外を足す。プロジェクトのリポジトリの `.gitignore` は ccnavi が持たない |
| 追記だけ。書き換え・消すコードは作らない。1 行を 1 回の write で追記で開いたハンドルに出す（記録の 1 行と同じ） | 跡は後から読むためのもので、書き直せると跡にならない。同時に書いても行は混ざらない | 1 本の JSON を読み直して書き戻す。途中で落ちると全部失い、同時に書くと片方が消える |
| 書く中身は落とさない。不正な UTF-8 から来たサロゲート（`--reason` に混ざる）は `\udcff` の形の JSON のエスケープで書く。JSON にできない値は綴りにする。書き込みの例外（`OSError`・`ValueError`）は「書けない」として扱う | 状態を動かしたあとで跡の書き込みが例外で落ちると、状態は動いたのに命令が失敗を返し、一括の承認なら残りが置かれない（2026-09-26 のレビューで再現） | 文字を置き換えて書く（`errors="replace"`）。元の理由が跡から読めなくなる |
| 識別子の形（`ticket.is_valid_id`）でなければ、跡のファイルに使わない。書かずに警告し、読みは空 | 呼び手は検査済みの識別子を渡すが、ファイル名を組む側でも同じ検査を当てる（多重の守り）。区切り文字や先頭の `.` で置き場の外を指させない | 呼び手の検査だけに頼る |
| 行が混ざらないのは POSIX の `O_APPEND` に頼る。Windows の追記はその保証が弱く、同時に書けば混ざりうる。読む側は読めない行を飛ばして数え、`problems[]` で言う。`O_BINARY` で改行の書き換えを止める | 同時に同じチケットを動かすのはまれで、混ざっても跡だけが欠け、状態は置き場が持つ | 読み書きをロックで直列化する。Windows と POSIX で別の実装が要る |
| 末尾だけ読む窓の切れ目が行の頭にちょうど当たったら、その行は完全なので捨てない（1 バイト手前から読んで、直前が改行かで見分ける） | 切れ目で必ず 1 行捨てると、窓にちょうど収まる件数のときに完全な行が 1 本消える | 窓の頭を常に捨てる |
| **正は置き場。跡は補助。** 判定も状態の操作も跡を読まない。食い違ったら置き場を信じる | 置き場はエージェントが書けない守りの中にあり（ADR-0058）、跡はそれを写しただけのもの。跡を読んで判定すると、跡だけが壊れたときに状態が変わる | 跡から状態を組み直す（イベントソーシング）。人が hook の外で置き場を動かす運び（ADR-0058）では跡が残らないので、組み直すと状態が食い違う |
| 書けなくても状態の操作は止めない。書けなかった理由は `ccnavi: 警告: …` の 1 行で標準エラーに出す | 補助のために本体を止めると、置き場が正しく動けるのに跡のせいで進めなくなる。黙って捨てると、跡が欠けたことに誰も気づかない | 書けなければ止める。跡の置き場が塞がっているだけで承認も着手もできなくなる |
| 警告は、動かす関数の中ではなく入口（`cli.run`）で出す。関数は理由を溜め、入口が抜けるときに出す | 最下段の関数の多くは標準エラーを持たない（`settle_review`・`write_mark`）。持たせるには呼び手を全部書き換えることになる | 関数ごとに標準エラーを渡す。漏れた経路で黙る |
| 経路は起動ごとに入口が決める。既定は `cli`（sh の副命令。打ったのがエージェントか人かは言えないので、ボードは「sh（ccnavi-ticket.sh など）」と見せ、誰が打ったかを断定しない）。人の判断の枝は `terminal` か `board`、hook は `hook` | 同じ関数が端末の承認からもボードの承認からも呼ばれる。呼ばれた側では区別できない | 関数の引数で経路を渡す。上と同じく呼び手を全部書き換える |
| ボードの JSON（`--explain --json`）のチケットに `history`（新しい側 20 件、古い順）を足す。版は上げない | README の方針どおり、欄を足すだけでは版を上げない（拡張は知らない欄を読み飛ばす）。古い拡張は履歴を出さないだけで、読み違えはしない | 版を上げる。古い拡張がボードごと読めなくなる |
| ボードのカードに畳める「履歴（N 件）」を置き、開くと新しい順に並べる。列・バッジ・要対応は跡から決めない | 跡は補助。カードの状態は今までどおり置き場の欄から決める（ADR-0035） | 跡の最新の 1 行をカードの見出しに出す。置き場と跡が食い違ったとき、どちらが本当か画面から読めなくなる |

## 得たもの・失ったもの

- 得たもの: いつ・どの経路で・どこからどこへ動いたかが、チケットごとに残る。マーカーが消えたあとも
  「一度済んでから開き直った」が読める
- 得たもの: 跡は git で運ばれるので、別の機械で続きをしても途切れない
- 失ったもの: **人が hook の外で置き場を動かした分（手での承認・再開・マーカーの手での削除）は残らない。**
  跡だけを読むと、それらが無かったように見える。正は置き場で、跡は補助として読む
- 失ったもの: 承認済みの領域にファイルが増える。コミットのたびに跡の行も乗る
- 失ったもの: 同じチケットを 2 つの枝で動かすと、合流で跡のファイルが衝突する。どちらの行も
  残せば足りる（追記だけなので、両方の行を並べれば壊れない）が、手で解くことになる
- 失ったもの: 跡を書く分だけ、状態の操作 1 回につきファイルの追記が 1 回増える
- 失ったもの: 経路は起動ごとの推定で、`cli` は「エージェントが sh から打った」とは限らない
  （人が同じ sh を端末で打っても `cli`）。人の判断の経路（端末の壁・ボードの指紋）を通ったものだけが
  `terminal` / `board` と確かに言える
- 失ったもの: 読むのは権威のツリー（承認済みチケットと同じツリー）の跡だけ。権威のツリーが途中で
  変わると（親のワークツリーを後から作った）、前のツリーに残った行はそのツリーのコミットが
  合流するまで読めない

## 採らなかった案

- 判定の記録（`logs/log.jsonl`）に状態の移動も書く。記録はワークスペース側で git に入らず、機械を
  またぐと消える。絶対パスとコマンド全文が入るので運べない
- 置き場の移動を `git log --follow` で組み直してボードに出す。コミットされる前の移動が見えず、
  拡張が git を読んで状態を組むことになる（ADR-0035）
- 1 本の `events.ndjson` にワークスペースの全チケットを書く。並行する枝の合流で必ず衝突する
