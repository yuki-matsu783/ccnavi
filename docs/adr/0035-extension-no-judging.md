# ADR-0035: VS Code 拡張は判定を自分で出さない

状態: 採用（2026-09-30、ADR-0093 の段階 3 で改訂。下の「改訂」。テンプレートの取り込みは ADR-0144 が改める。判定し直しが食い違うと取り込み状態を `blocked` にする点は、ADR-0142 が取り込み状態をやめたので改まった。食い違いは `ccnavi sync check` の error の表示と終了コード 1 で知らせる）

## 状況

チケットがどのワークツリーでどこまで進んでいるかを見る VS Code 拡張（ボード）を作った。
続けてルール設定画面、プロジェクト管理画面、リスク管理画面、フェーズ管理画面を足した。

## 決定

拡張は実行ファイルが出した JSON（`--explain --json`、`--test --json`、`--test-samples --json`、
`--lint --json`（`--flow` を含む））を並べるだけで、提案やマーカーを自分で解釈せず、glob も regex も自分で適用せず、
リスクの点も数えない。

ユーザの判断（`--approve`、`accept`）は拡張からもターミナルを通す。ボタンは統合ターミナルにコマンドを
送るだけで、y/N はユーザが押す。`wrapup` はボードにボタンを置かず、ターミナルで打つ。

テンプレートの取り込み（`--templates --import … --to … --yes --expect <ハッシュ> --via board`）も、拡張が子プロセスで打つ。承認と同じく、書くのは実行ファイルだけで、拡張はファイルを書かない。取り込みはターミナルの確認を免除する経路で、代わりに見せた下書きのハッシュ（`--expect`）が一致したときだけ書き、エージェントが Bash から打てない形（hook の止め）を通ったものに限る。取り込みの前後の差分と指摘は、実行ファイルの答えを画面が並べるだけにする。

編集中の内容は一時ファイルに書いて `--rules`（レイヤーなら
`--project-rules-file <名前>=<パス>`）/ `--risk` / `--phases`（レイヤーなら `--project-phases-file <名前>=<パス>`）で渡し、保存の前に `--lint` を通す。差し替えを使うのは診断の
ときだけで、hook からの判定では無視する。作業中のチケット（`doing`）がある間は保存しない。
配点と種類も同じ形で `--lint --risk` / `--lint --phases` に掛ける。子チケットのフロー（ADR-0085）も同じ形で、
開くときと保存の前に本文を一時ファイルに書いて `--lint --json --flow <パス>` に掛け、場所 `(flow)` の error が
あれば開かない・保存しない。読めるか・形が正しいかの答えは、`SubagentStart` と同じ読み手・同じ検査を持つ
実行ファイルが出し、画面は描けないときだけ断る（2026-09-26）。書式の側から来る制約が 1 つあり、
実行ファイルは PyYAML（YAML 1.1）で読むのに拡張の `yaml` は 1.2 なので、`yes` `1:30` `0755` のような語は
裸で書くと型が変わる。画面はその表記を引用符で囲んで書く。値の意味（PyYAML で何と読むか）の答えも実行ファイルが持つ。
`--lint --json --flow` は読めた中身を `flow.data` に載せ、画面は開くときに自分の読みと、保存の前に書こうとした中身と
見比べ、食い違えば開かない・保存しない（2026-09-26）。

拡張が自分で見るのは、origin（ローカルの git を読み取り専用で起こす）、ルールファイルの有無、
`.gitignore` の本文、ワークスペース直下を深さ 2 まで歩いて見つける
「プロジェクトになっていない `.git`」だけ。`git clone` / `fetch` / `pull` はターミナルへ送る。
プロジェクトを外す操作は入れない。

自分で適用しない glob と regex は、ccnavi のルールのもの。例外が 1 つあり、ルール管理画面が `.claude/settings.json` と
`.claude/settings.local.json` の hook の登録を見せるときは、Claude Code の matcher（空か `*` なら全部、それ以外は
ツール名に適用する正規表現）を拡張が自分で適用し、そのツール名で走る hook を並べる。これは Claude Code がどの hook を
起こすかを見せる表示で、ccnavi の判定を出し直すものではない。実行ファイルは Claude Code の matcher を読まないので、
答えを聞く先が無い。表示が Claude Code の解釈とずれても、止めるか通すかの答えは変わらない（2026-10-11 追記）。

## 理由

判定の答え（HITL ポイントで止めているか、承認待ち、ルールのヒットの仕方、何点か）を拡張が自前で出し直すと
2 か所で違う答えになる。ボードが「止めていない」と表示しているのに判定が止める、という形になる。

ターミナルを求める保護（ADR-0029）の外側に拡張の子プロセスを置かない。取り込みだけは、ターミナルの確認を免除する経路として、この保護の外に出る。内容の一致（`--expect`）と hook の止めで代えるのは、承認の経路と同じ考え方による（2026-10-12）。

保存を止めるのは、hook が呼び出しのたびにルールを読み直すので、走っているセッションの途中で
判定が変わる形を作らないため。プロジェクトのルールは、そのプロジェクトの `doing` だけで止める。
他のプロジェクトで進んでいるセッションの書き込みの判定は変えないため（Bash の和は変わる。
そこは受け入れる）。配点はワークスペースに 1 本なので、どのツリーの `doing` でも止める。フェーズの種類は、
共通レイヤーと自身のレイヤーならどのツリーの `doing` でも、プロジェクトのレイヤーならそのプロジェクトの `doing` で止める（フェーズの種類はそのレイヤーの
`project:` を持つチケットにしか足されない）。

`clone` は `ccnavi-git.sh` が「ユーザに依頼する」として通さないので、その依頼を受けたユーザが
この画面から打つ形になる。プロジェクトを外す操作を入れないのは、ワークツリーと承認済みチケットが残ったまま
ディレクトリだけ消してしまう事故につながるため。

## 得たもの・失ったもの

- 得たもの: 答えは 1 か所。拡張はネットワークに出ず、レビューのスレッドの現状も載せない
- 失ったもの: 実行ファイルが無い環境では拡張は何も出せない
- 失ったもの: 取り込みはターミナルの確認を通らない。見せた下書きとの一致と hook の止めで代えるので、迂回の穴は承認と同じ程度に残る
- 失ったもの: ボードが見せるのはマーカーまで。レビューの実物は見に行かない
- 失ったもの: 判定を出すたびに実行ファイルを起こすので、画面の反応は子プロセスの起動に縛られる

## 改訂（ADR-0093 の段階 3、2026-09-30）

Chrome 拡張（`chrome-extension/ccnavi-approval`）は、実行ファイルを起こせない承認者のブラウザで、同梱した
ccnavi の Python を Pyodide で動かして判定を出す。「実行ファイルの答え」を「同じコードの答え」と読み替える。
拡張の TS は判定を出さず、Python が返した承認待ち・書くもの（Changes）・書けるかを並べて、親のブランチへの
1 コミットにするだけ。

- 版ずれ（ADR-0093 の 7.3）: 同梱の ccnavi の互換の版が統合先の `CCNAVI_COMPAT` と違えば、承認と取り下げを
  書かずに表示だけにする。互換が同じなのに手元の判定し直しと答えが違えば、手元はその親子のチケットの取り込み状態を
  `blocked` にして止め、理由に Chrome の拡張の版と手元の版を書く
- ユーザの合意の証拠は、ターミナル（ADR-0029）ではなく、見せた一覧とダイジェストの一致と、書く先の先頭の一致（ADR-0093 の 8.3「承認の流れと競合」）

## 採らなかった案

- 拡張が glob と regex を自分で適用する。同じ問いに 2 か所が別の答えを出す
- 承認を拡張の子プロセスで実行する。ユーザの合意を出せる場所がターミナルの外に増える
- ボードに `wrapup` のボタンを置く。早めに閉じるのはユーザの判断で、残りを見せて y/N を取る場が要る
