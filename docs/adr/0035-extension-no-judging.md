# ADR-0035: VS Code 拡張は判定を自分で出さない

状態: 採用

## 状況

チケットがどの作業ツリーでどこまで進んでいるかを見る VS Code 拡張（ボード）を作った。
続けてルール設定画面、プロジェクト管理画面、リスク管理画面を足した。

## 決定

拡張は実行ファイルが出した JSON（`--explain --json`、`--test --json`、`--test-samples --json`、
`--lint --json`）を並べるだけで、提案や印を自分で解釈せず、glob も regex も自分で当てず、
リスクの点も数えない。

人の判断（`--approve`、`accept`）は拡張からも端末を通す。ボタンは統合ターミナルにコマンドを
送るだけで、y/N は人が押す。`wrapup` はボードにボタンを置かず、端末で打つ。

編集中のルールは一時ファイルに書いて `--rules`（プロジェクトなら
`--project-rules-file <名前>=<パス>`）で渡し、保存の前に `--lint` を通す。差し替えは診断で
だけ効き、hook からの判定では無視する。作業中のチケット（`doing`）がある間は保存しない。
編集中の配点は `--lint --risk` で検証する。

拡張が自分で見るのは、origin（ローカルの git を読み取り専用で起こす）、ルールファイルと
`.claude/` の有無、`.gitignore` の本文、ワークスペース直下を深さ 2 まで歩いて見つける
「プロジェクトになっていない `.git`」だけ。`git clone` / `fetch` / `pull` はターミナルへ送る。
プロジェクトを外す操作は入れない。

## 理由

判定の答え（ゲートの開閉、承認待ち、ルールの当たり方、何点か）を拡張が自前で出し直すと
2 か所で違う答えになる。ボードが「開いている」と言うゲートで判定が止まる、という形になる。

端末を求める壁（ADR-0029）の外側に拡張の子プロセスを置かない。

保存を止めるのは、hook が呼び出しのたびにルールを読み直すので、走っているセッションの途中で
判定が変わる形を作らないため。プロジェクトのルールは、そのプロジェクトの `doing` だけで止める。
他のプロジェクトで進んでいるセッションの書き込みの判定は変えないため（Bash の和は変わる。
そこは受け入れる）。配点はワークスペースに 1 本なので、どのツリーの `doing` でも止める。

`clone` は `ccnavi-git.sh` が「利用者に依頼する」として通さないので、その依頼を受けた利用者が
この画面から打つ形になる。プロジェクトを外す操作を入れないのは、作業ツリーと写しが残ったまま
ディレクトリだけ消してしまう事故につながるため。

## 得たもの・失ったもの

- 得たもの: 答えは 1 か所。拡張はネットワークに出ず、レビューのスレッドの現状も載せない
- 失ったもの: 実行ファイルが無い環境では拡張は何も出せない
- 失ったもの: ボードが見せるのは印まで。レビューの実物は見に行かない
- 失ったもの: 判定を出すたびに実行ファイルを起こすので、画面の反応は子プロセスの起動に縛られる

## 採らなかった案

- 拡張が glob と regex を自分で当てる。同じ問いに 2 か所が別の答えを出す
- 承認を拡張の子プロセスで実行する。人の合意を出せる場所が端末の外に増える
- ボードに `wrapup` のボタンを置く。締めるのは人の判断で、残りを見せて y/N を取る場が要る
