# ADR-0025: 参考にした運用から採ったもの、採らなかったもの

状態: 採用

## 状況

並行するチケット（ADR-0024）の設計を、参照専用の資料 `参考/issue-mr-ticket-workflow` の運用層と
突き合わせた。参考の設計書は ccnavi.md の元になった同じ文書で、新しい要素は無い。価値があったのは
`ticket.sh` / `worktree.sh` / `boundary.sh` とそれを縛る hook 群の側。

## 決定

丸写しではなく、ccnavi の「判定は写しだけを読む」「絞る向きは承認不要」に噛み合わせて採る。

| 採ったもの | 改めた点 |
|---|---|
| 状態はディレクトリで表し、提供コマンドだけが動かす | 判定の権威は写しのまま。置き場は閉じる向きにだけ効く |
| `start` が `base_sha` を記録し、事後検査は基準点からの差分 | 基準点は写しにも写し、検査は写しの値を使う |
| 人間レビュー要否をチケットごとに持ち、要のある切れ目だけレビュー | 既定は要。省略は印に残す |
| `request` / `complete` / `note` と前提検査、変更要求は受け入れでも通さない | 依頼の前提に子ブランチの合流を足した |
| 進行状態は共有ルート 1 か所、判定記録はツリーごと | 写しと印はワークスペースルート、記録は各ツリー |
| 判定の材料は cwd のツリーの作業中チケット | **行き先のツリー**のチケットで判定する。参考が並列を保留にした穴を、ここで越える |
| 既定は作業ツリーを切らない、本流で 1 枚ずつ | 常に 1 チケット = 1 作業ツリー。参考の既定は上の穴からの妥協で、目標ではない |
| 採番を本流に 1 本化 | 親が main に居ない。親の識別子を名前空間にして `<親>-<連番>` で衝突を防ぐ |

| 採らなかったもの | なぜ |
|---|---|
| `executor`（実行者のモデル）の照合 | 起動前に止められないと参考でも分かっていて報告止まり。write の範囲だけの今回は入れない |
| `allow.ops`（実行してよい操作の分類）、敵対的レビュー、md + HTML の対、draft 解除の手順 | ワークフローの側の話で、ガードの範囲外 |
| 15 種のタスクとフェーズ列のテンプレート | ccnavi は権限の道具で、作業の種類を知らなくてよい |
| 振り分けの宣言（entry skill）の強制 | ccnavi のルールと権限モードの委譲で足りる |

状態の移動（`start` / `done`）はスクリプトが置き場を動かすだけで、コミットは親がする。
参考の `ticket.sh` は自分でコミットしていたが、こちらは git ラッパが別にあるので分けた。

## 理由

参考は並列実施を「隔離はされるが統制が効かない」で発効保留にしていて、その穴は判定の材料を
作業ディレクトリのツリーの作業中チケットから採ることにある。ccnavi の「行き先で結ぶ」（ADR-0024）が
そこを越えるので、運用層の形はそのまま使えて、判定の鍵だけ差し替えれば済んだ。丸写しにしないのは、
参考の判定の権威が提案の側にあり、ccnavi は写しの側だから。

## 得たもの・失ったもの

- 得たもの: 動いている運用の形を土台にできた。並列実施を保留にした穴の場所が分かっていたので、
  そこだけを越える設計にできた
- 失ったもの: 参考が持っていた作業の型（15 種のタスクとフェーズ列のテンプレート、`allow.ops`、
  `executor` の照合）は入らないので、作業の進め方は CLAUDE.md とスキルの側に残る。ccnavi は
  権限の道具で、作業の種類を知らない

参考の `.claude/` を持つディレクトリをリポジトリの中に置くのは、参考自身が「攻撃面」と
警告している形で、実際に Claude Code がそこのスキル 28 本を読み込んでいた。`.gitignore` に
入れてあるが、読み終えたら外へ出すこと。
