# ADR-0088: 先行（`predecessors`）は承認と着手で求める。満たすのは `done/` に在って取り消しでないものだけ

状態: 採用

## 状況

子チケットは `predecessors: [<識別子>...]` で「先に閉じているべき子」を書ける（設計 9.3）。これまでは
案内にだけ使っていて、判定も承認も着手もこの値を見ていなかった。`SubagentStart` の一覧と `--explain` が「先行が未完了」と
添え、`--lint` が「先行が閉じていないのに着手している」を warn で言うだけで、承認も `ticket start` も
そのまま通った。「済んだ」の数え方も、閉じた（`done/`）かレビュー待ち（`review/`）に在る識別子の集合で見ていたので、
取り消した先行も済んだものとして数えていた。

先行を書いた子が、先行の作業を待たずに承認され、着手される形が起きた（2026-09-26）。人は承認の画面で
「依存している他チケット」を見るが、承認も着手も止まらないので、先行の成果が無いまま次の子の作業が始まる。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 承認と `ticket start` の両方で、子の `predecessors` の各チケットが `.ccnavi/approved/done/` に在って取り消しでない（`cancelled_at` が無い）ことを求める。満たさなければ、その子の承認と着手（`start`）を止める。**書き込みは止めない。** 書き込みの範囲を決めるのは承認済みチケットの置き場で（ADR-0058）、判定は `started_at` も先行も見ない。承認済みの子のワークツリーを作れば、`start` を打たずに範囲の中へ書ける。`finish` も止めない | 先行の成果が揃うのは、人のレビューまで済んで `done/` に入ったとき。承認だけで見ると、承認のあとに先行が戻された（人が `done/` から `doing/` へ動かした）子と、置き場を手で動かして承認した子（ADR-0058）が通る | 承認だけで見る。上の 2 つが抜ける |
| レビュー待ち（`review/`）は満たさない | 作業は終わっているが、人のレビューで指摘が付けば同じフェーズに続きの子が起き、先行の成果は変わる。済んだと言えるのは `done/` だけ | 今までどおり `review/` も済んだと数える。レビューで差し戻された成果の上で次の子が進む |
| 先行が取り消し済み・どこにも無い・複数の場所にある（どれを優先するか決まらない）ときも止める。自分自身・自分の親・辿ると自分に戻る（輪）先行も止める。満たしたとはみなさない | 取り消した先行は二度と `done/`（取り消しでない側）に入らない。無い先行は綴りの誤りか消えたもの。決まらない先行は、どちらを見ても答えが分かれる。自分自身や輪になった先行は、どれもほかが閉じるのを待ち続ける。親は子が全部閉じてから閉じる。どれも形の上で満たせない | 取り消し・無いものは満たしたとみなす。先行を書いた意味が気づかれないまま消える |
| 先行を探す範囲は、状態の操作（`ops._places`）と同じ集め方で決める。作業中・レビュー待ち・閉じた承認済みチケットを優先するツリーの側で数え、`todo/` の提案は承認済みが無いときだけ数える | 着手が「複数の場所にある」で止まる条件と、先行を「複数の場所にある」とみなす条件を揃える | 閉じた承認済みチケットの識別子だけを見る。`doing/` と `done/` に同じ識別子が残った形を `done/` と読む |
| 承認の止め方はフェーズの順序（`phase.order_problems`）に揃える。先行が閉じれば同じ提案が通るもの（承認待ち・作業中・レビュー待ち）は `rules.KIND_NOT_YET` の error、待っても通らないもの（取り消し・無い・複数の場所・自分自身・自分の親・輪）はふつうの error で、原因を名指しする。輪は辿った経路（`a → b → a`）を出す。閉じた（`done/`）先行の先は辿らない | 承認ではどちらも落とし、`--lint` は前者を warn、後者を error で言う。前者は書いた側に直すものが無く、後者は直すもの（`predecessors` から外す、綴りを直す）がある | 全部を同じ重さにする。前者で `--lint` が常に落ち、設定の保存と CI が止まる（`lint._approval_problems` と同じ理由） |
| 文面は、どの先行が何の状態か（`承認待ち（todo/）` / `作業中（doing/）` / `レビュー待ち（review/）` / `取り消し済み` / `どの置き場にも無い` / `複数の場所にある: <在り処>`）と、次の一手（先行を閉じる／`predecessors` から外して出し直す／1 つに決める）を言う。着手の文面は `finish` と `cancel` の sh の綴りを出す | 止められた側が、文面を読んでそのまま次に動ける | 「先行が閉じていない」だけを言う。何を待てばよいか、待っても無駄なのかが読めない |
| ボードは判定しない。`--explain --json` のチケットに `predecessors_unmet`（`{ticket, state, label}` の並び。閉じたチケットは空）を載せ、カードは「先行待ち（<識別子>）」のバッジを出す。承認のプレビュー（`--approve --preview --json`）は、落ちた子を今までどおり `rejected[]` に理由の文で載せる | 答えを出すのは 1 か所（ADR-0035）。バッジの tooltip は実行ファイルが付けた `label` をそのまま出す | 拡張が `predecessors` と各チケットの置き場を照らし合わせる。承認と答えが分かれる |
| `SubagentStart` の一覧・`--explain`・`--lint` の「先行が未完了／着手している」も同じ関数（`approval.unmet_predecessors`）で数える | 同じ事実を数える経路が 2 本あると、片方が気づかれないまま緩む。これまでの「`review/` に在れば済んだ」という数え方は、ここで揃えたことで無くなる | 表示だけ今までの数え方に残す。承認で止まるのに一覧は「済んだ」と言う |
| 続きの子（`decide` の「このフェーズで直す」、`--reviewed --chat` の指摘）は、見た子のうち取り消したものを `predecessors` に入れない。範囲の和には今までどおり入れる | 続きの子は人が `doing/` に直に起こす（人が選んだことで承認は済んでいる）。取り消した子を先行に入れると、その続きの子は二度と着手できない。見た子は、続きの子を起こす前に `done/` へ動いている（`_settle_children`） | 取り消した子も先行に残す。人の判断で起こした子が着手で詰まる |
| 先行の検査を迂回させないことは、今までの守りに頼る。承認済みチケットの置き場へのエージェントの書き込みは組み込みの守りとルールが止め（`Write` / `Edit` とシェルのリダイレクト。書き込み先を読めないシェルは権限モードに委ね、聞ける者が居なければ断る）、承認を自分で出す形（端末の外からの `--approve` / `--yes`）とサブエージェントの `ticket start` も止まる | 先行の検査は承認済みチケットの `predecessors` を読む。その値をエージェントが書き換えられなければ、検査は外せない | 先行の検査の結果をどこかに控える。控えを消す手段が増える |

## 得たもの・失ったもの

- 得たもの: 先行を書いた子が、先行の成果が `done/` に入るまで承認も着手（`start`）もされない。承認のあとに先行が
  戻されたときも、着手の手前で止まる
- 失ったもの: **止まるのは承認と `start` だけで、書き込みは止まらない。** 承認済みの子（置き場を手で動かした子を含む）の
  ワークツリーを作れば、`start` を打たずに範囲の中へ書ける（判定は `started_at` も先行も見ない。2026-09-26 のレビューで確認）。
  `start` を飛ばした子は基準点（`base_sha`）を持たないので、`finish` とリスクの計測には進めず、`--lint` が「先行を
  満たしていないのに着手している」とは言わない（着手していないので）。判定の側で締めるかは利用者と決める（保留）
- 得たもの: 先行の「済んだ」の数え方が、承認・着手・一覧・`--explain`・`--lint`・ボードで 1 つになる
- 失ったもの: **レビュー待ちの先行を持つ子は、人がレビューを済ませるまで承認できない。** これまでは
  レビューと並行して次の子を承認できた。並行させたいなら、`predecessors` から外して出し直す
- 失ったもの: 先行を 1 つでも取り消すと、それを先行に持つ子は `predecessors` を直して出し直すまで
  進めない。承認済みの子なら、人が承認済みチケットのキーの値を直すか、取り消して出し直す
- 失ったもの: 同じ承認で先行と後続を一緒に通すことはできない（先行はまだ `todo/` に在る）。先行が閉じて
  から後続を承認する
- 失ったもの: 承認と着手のたびに、先行を持つ子が居ればチケットの置き場を 1 回ずつ多く読む
- 失ったもの: `SubagentStart` の一覧で、これまで「済んだ」と数えていたレビュー待ちの先行が
  「先行が未完了（レビュー待ち（review/））」と出るようになる
- 失ったもの: 書き込み先を読めないシェル（`sed -i` など）で承認済みチケットを書き換える形は、組み込みの
  守りでは名指しで止まらず、聞ける者が居る権限モードでは Claude Code の確認に委ねる（今までと同じ）。
  人が確認で通せば書き換わる。そのときは実行後の監視が範囲・本文の書き換えとして言う（ADR-0075）

## 採らなかった案

- 判定（`blocking_problems`）でも先行を見て、満たさない子の書き込みを止める。上の「失ったもの」の穴は無くなるが、
  判定で止めると、承認のあとに先行が戻されたとき、作業中の子が突然どこにも書けなくなる（ADR-0058 の
  「失ったもの」と同じ形）
- 先行が `review/` に入った時点で後続の承認を許し、着手だけを `done/` まで待たせる。承認と着手で答えが
  分かれ、ボードの「先行待ち」が何を待っているのか読めなくなる
- 親の `predecessors` も見る。親は子のまとまりの入れ物で、親どうしの順序は計画（`plan`）と
  フェーズの順序が受け持つ。親に書いた `predecessors` は今までどおり warn で「読まない」と言う
