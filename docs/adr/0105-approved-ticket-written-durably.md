# ADR-0105: 承認済みチケットは一時ファイルに書き切って fsync してから差し替える

状態: 採用（2026-10-04 に実装。ADR-0056 が「マーカーと承認済みチケットは別に扱う」と残した件のうち、承認済みチケットの側を決める。マーカーはこの ADR の外）

## 状況

2026-10-04（issue #225）。承認は提案を `todo/` からバイト列のまま読み、同じバイト列を `doing/<識別子>.md` に
書いてから元を消す。書き込みは `fsio.write_bytes`（`open(path, "wb")`）だった。開いた時点で中身を捨てるので、
書き終える前に落ちる（プロセスが殺される、電源が落ちる、ディスクが一杯になる）と、空か書きかけの
承認済みチケットが残る。

承認済みチケットは判定が範囲を読む元で、承認は「提案とバイト単位で同じ」ことが条件（ADR-0104）。
壊れたものが残ると、

- 判定は読めないチケットとして扱い、そのチケットの範囲が効かない
- 提案は消える前なら `todo/` に残るが、`doing/` に壊れた同じ識別子が在るので「複数の場所にある」で止まる
- state の記録と違って、次の起動で取り直す手段が無い

同じ形の書き込みは、承認で一緒に書く親の待ち方（`phases/<親>/workflow.yml`）、落ちたときに待ち方を戻す処理、
Chrome 拡張の取り下げで提案を `todo/` へ戻す処理にもあった。

ADR-0056 は state の記録を `write_text_atomic`（差し替えるが `fsync` しない）にしたとき、
「マーカーと承認済みチケットは素の書き方のまま。ここは別に扱う」と残していた。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `fsio.write_bytes_atomic` を足す。同じディレクトリに一時ファイルを作って書き切り、flush と `fsync` をしてから `os.replace` で差し替え、最後に親ディレクトリを `fsync` する | 途中で落ちても前の中身か新しい中身のどちらかが残る。`fsync` までするので、電源断の直後に「差し替わっているが中身が空」も残さない | `write_text_atomic` をそのまま使う（電源断を守らない。テキストとして書くので改行が変わりうる） |
| 使うのは承認済みチケット（新規の承認）、親の待ち方、待ち方を前の中身へ戻す処理（`put_back`）、取り下げで提案を `todo/` へ戻す処理だけ | ユーザの決定（範囲は承認）。どれも承認と組で、壊れると取り返しが付かない | レビュー・フロー・自己防衛の書き込みまで広げる（範囲の外。影響を読み切れない） |
| 溜める段では新しい種類 `OP_BYTES_ATOMIC` として溜め、Writer(FS) が `write_bytes_atomic` で書く | `OP_BYTES` を書き換えると、`write_bytes` を使う他の書き込みまで書き方が変わる。種類を分ければ影響は承認の書き込みだけ | `OP_BYTES` の実行側を原子版に切り替える |
| 一時ファイルの名前は `.<元の名前>.<一意>.part` | 先頭の `.` と末尾の `.part` は `ccnavi-push-approved.sh` と C1 のコミットが除外する形。`.md` で終わらないので、`doing/` を読む側（`.md` だけを読む）が残骸をチケットとして読まない | `write_text_atomic` と同じ `<名前>.<一意>.part<拡張子>`（`doing/` の残骸が識別子とファイル名の違うチケットとして読まれ、除外にも当たらない） |
| macOS では `F_FULLFSYNC` を先に試し、使えなければ `os.fsync` | macOS の `fsync` はディスクの書き込みキャッシュまでは届かない | `os.fsync` だけ |
| 親ディレクトリの `fsync` は開けない・できないときは黙って飛ばす（Windows では開けない）。ファイルの `fsync` で落ちたら差し替えず、書けなかったとして返す | 差し替えの後なので、ディレクトリの `fsync` の失敗で「書けなかった」にすると、書けたものを戻す処理が走る。ファイルの `fsync` の失敗は中身が届いたか分からないので本番にしない | ディレクトリの `fsync` の失敗も書けなかったことにする |
| 権限は `write_text_atomic` と同じく、在ればその権限、無ければ素の `open` と同じ | `mkstemp` は 0600 で作るので、そのままだと承認済みチケットの権限が狭まる | — |

## 得たもの・失ったもの

**得たもの**

- 承認の途中で落ちても、承認済みチケットと待ち方は前の中身か新しい中身のどちらか。空や書きかけは残らない
- 中身はバイト列のまま書くので、承認がバイト単位で提案と同じことは変わらない

**失ったもの**

- **承認 1 件ごとに `fsync` の待ちが増える。** 承認はユーザの操作で、全ツール呼び出しの経路ではないので
  受け入れた。state の記録（ADR-0056）は今までどおり `fsync` しない
- **一時ファイルの名前が元より長い。** Windows の 260 文字の上限ぎりぎりの行き先では、以前は書けたものが
  書けないことがある
- **残骸の種類が 1 つ増えた。** 落ちて残った `.<名前>.<一意>.part` を掃除する仕組みは無い。コミットされず、
  チケットとしても読まれないが、置き場に残る
- **行き先がシンボリックリンクなら、リンクの先ではなくリンクそのものを差し替える。** 前の書き方はリンクを辿った
- **フローの移し（承認した子のフローを承認済みのツリーへ動かす `write_new`）は素の書き方のまま。**
  「在れば書かない」を保ったまま原子的にするには hard link などが要り、フローの読み手はハードリンクを拒むので、
  この ADR では扱わない。改版でチケットを書き直す処理（`write_text` を通る）も同じく外

## 採らなかった案

- **全部の書き込みを原子的にする。** 一度で揃う。採らなかったのは、ユーザが範囲を承認に絞ったため。
  レビュー・フロー・自己防衛の書き込みはそれぞれ読み手と残骸の掃除が違い、影響を読み切れない
- **`fsync` をしない（`write_text_atomic` と同じ値段）。** 速い。採らなかったのは、承認済みチケットは
  取り直せないので、電源断の直後に空が残る余地を残す理由が無いため
