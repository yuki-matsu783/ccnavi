# ADR-0094: レビューの依頼には ELI5 の HTML を必須で添え、ユーザは crit で見る

状態: 採用（置き場・crit の指摘の写し方・依頼文の末尾の 1 行・標準出力の案内は置き換え（ADR-0095））

## 状況

レビューの依頼（`ccnavi-review.sh request`）はマージリクエストに依頼文を投稿するだけで、ユーザは差分とコードから
変更を読み解いていた。変更の目的・何が変わるか・リスクを専門用語なしで先に掴めると、レビューが速く確かになる。
ユーザは手元の端末で外部の CLI `crit` を使い、HTML を開いて指摘を付けて見たい（2026-10-01、ユーザと合意）。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `request` に `--eli5 <HTML>` を足し、必須にする。無い・値が無い・拡張子が `.html` / `.htm` でないなら 2（引数の誤り）、ファイルが無い・空白だけなら 1（前提の未充足。依頼文が読めない・空のときと同じ） | 付け忘れを「あとで書く」で流さない。終了コードは既存の慣習（引数の誤りは 2、前提は 1）に合わせた | 任意にする。書かない依頼が普通になり、ユーザが見る材料が揃わない |
| 確かめるのは sh。ロックを取る前に済ませ、欠けていれば何も書かずに止める。`--eli5` は抜き取って実行ファイルには渡さない | 下の「hook に置けないか」を参照。実行ファイルのフラグを増やすと互換の版（`CCNAVI_COMPAT`）や `--version --json` の flags の扱いが要り、古い実行ファイルと組み合わせたときに引数の誤りで落ちる | 実行ファイルの `review prepare` で確かめる |
| 相対パスは `--body-file` と同じく、打った場所（実行ファイルに渡す `--cwd`）から解く。置き場は依頼文と同じ追跡しない場所（例 `wip/tmp/eli5.html`） | 依頼文と並べて置ける。親のワークツリーの中の未追跡は `request` の前提を落とさない（ADR-0029） | ワークスペースルートから解く。依頼文と規則が分かれる |
| sh は crit を起動しない。依頼とマーカーが済んだら、ユーザが打つ `crit <HTML の絶対パス>` を標準出力に出す。crit が PATH に無くても止めず、無いことを 1 行添える | crit は閉じるまで戻らないので、エージェントのツール呼び出しが止まる。crit はユーザの手元の道具で、エージェントの環境に無いことがある | sh から起動する。待ち続ける |
| 投稿する本文の末尾に「ELI5 の HTML（ファイル名）を添えた。依頼者の手元で crit で開ける」の 1 行を足す。HTML の中身とパスは載せない | マージリクエストだけを見るユーザにも、説明があることが分かる。中身は手元のファイルで足りる。目印は 1 行目なので、二重投稿の見分け（ADR-0093 の段階 2d の決定 D）は変わらない | 中身を貼る。長くなり、HTML は Markdown として正しく表示されない |
| crit でユーザが付けた指摘は、エージェントが読んで `comment --body-file` でマージリクエストに写す。止める・通すの判定は変えない（`confirm` の未解決のスレッドと変更要求、ユーザの `decide`） | 判定を新しく足さない。記録はマージリクエストに残る | crit の指摘を判定に数える。crit の出力の形に実行ファイルが縛られる |

**hook の側に置けないか（docs/claude/exe-boundary.md）。** 検討して置かなかった。hook が見るのはコマンド行の文字列で、
`--eli5` の表記は見られても、ファイルが在るか・空でないかは引数を解き、打った場所からパスを解かないと分からない。
これは sh が引数を読むのと同じ仕事の二重持ちになる。しかも ELI5 は状態（マーカー・チケット）を動かす判定ではなく、
依頼に添える材料の検査で、止めて困るのは依頼を打つ本人だけ。引数の検査として sh に置いた。

## 得たもの・失ったもの

- 得たもの: どの依頼にも、ユーザが先に読めるやさしい説明が付く。ユーザは crit で見て、指摘はマージリクエストに残る
- 失ったもの: 依頼のたびに HTML を 1 枚書く手間がかかる。小さな変更でも省けない
- 失ったもの: **中身の質は確かめない。** 在る・空でない・拡張子だけを見るので、中身の薄い HTML でも通る。外部の読み込みが無いことも確かめない
- 失ったもの: hook の案内（`phase.py`・`review.py` の文）に `--eli5` を足したので、版を混ぜると食い違う。
  古い sh と新しい実行ファイルでは、案内どおり `--eli5` を付けると sh がそのまま実行ファイルへ渡し、実行ファイルが引数の誤りで落とす。
  新しい sh と古い実行ファイルでは、案内に `--eli5` が無く、最初の 1 回は sh が止めて足りないものを言う。sh と実行ファイルは一緒に配る前提で、
  互換の版は上げていない
- 失ったもの: crit の指摘を写した投稿は機構の投稿なので、`confirm` を止めない。止めたい指摘はユーザがマージリクエストにスレッドを作る

## 採らなかった案

- **実行ファイル（`review prepare`）で確かめる。** 依頼文の検査と並ぶので見た目は揃うが、上の表のとおり互換の版の扱いが増える
- **hook で確かめる。** 上の「hook の側に置けないか」
- **sh が crit を起動する。** 上の表のとおり待ち続ける
