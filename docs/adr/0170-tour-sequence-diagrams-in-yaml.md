# ADR-0170: 案内の「いつ何が動くか」は、YAML に書いた時系列の図を React の DOM で描く

状態: 採用（ルール・リスク・フェーズ・テンプレート・プロジェクトの 5 つの管理画面に入れた）

## 状況

設定の画面の案内は、画面の部品を順に指すだけで、「ユーザがこの値を入れると、どのタイミングでどの仕組みが動くか」を見せられない。たとえばルールを保存したあと、hook がいつ読み直し、どの値に当たって止め、何を記録するか。利用者は、値を具体的にイメージできることを求めた。

図を eli10 の HTML で作り、案内に組み込む案があった。画像（PNG）にする案と、HTML のまま持つ案も比べた。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 図は、登場者を左から並べ、矢印を上から下へ時間順に並べる時系列の図にする。矢印は、実際に入れる値や出る答え（`value`）を等幅で添えられる | 「誰が誰に何をいつするか」と「どの値でどう動くか」が、1 枚で分かる。値を変えて結果が変わる例は、図を分けて並べる | 構成図（箱と線） |
| 図は画面ごとの YAML の `diagrams:` に書き、手順が `diagram:`（名前）と `focus:`（光らせる矢印の id）で指す | 案内の定義を YAML だけで足せる方針を保つ。手順が進むたびに、いま説明している矢印だけが光る | 図を TS に書く。手順ごとに別の図を作る |
| 描くのは共通の部品（`shared/SequenceDiagram.tsx`）で、DOM と CSS だけを使う | CSP を変えずに済む。VS Code のテーマに従い、ライトとダークの両方で読める。文を直すのに撮り直しが要らない。DOM でテストできる | PNG（テーマに従えず、CSP に `img-src` が要り、文の直しに画像の作り直しが要る）。HTML を iframe で出す（CSP を緩める） |
| eli10 の HTML は、図の内容と言い回しを決める下書きに使い、リポジトリには残さない | 絵の正本を YAML 1 本にする。HTML と図の二重管理を避ける | HTML をリポジトリに置く |
| 外の画面（GitLab・Claude Code）は、今までどおり画像（PNG）で見せる | ccnavi の外の見た目は、再現ではなく保存した画面が確かである | 外の画面も図に描き直す |

## 得たもの・失ったもの

- 得たもの: 値の例つきで、いつ何が動くかを案内に出せる。図の追加・修正が YAML だけで済む。構造（登場者の存在、矢印の id）をテストが見る。
- 失ったもの: 図の部品を持つ（共通の CSS と TSX）。列と矢印の単純な図に限り、曲線や入り組んだ図は描けない。図の内容が、実装の動きと食い違わないことは、文書とコードを読んで確かめる必要がある。
