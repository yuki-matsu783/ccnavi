# ADR-0090: `match: UserPromptSubmit` のルールで、利用者の発言の回にも文を渡せるようにする

状態: 採用

## 状況

「利用者の発言 N 回に 1 度、ここまでの作業を振り返ってスキルの改善を提案させたい」という要望が出た
（2026-09-27。Hermes Agent の、N ターンごとに裏でスキルを見直す仕組みを、人の承認を挟む形で取り入れる）。

`every: N`（ADR-0057）で「N 回に 1 度」は書けるが、数えるのはルールが当たった回で、ルールが当たるのは
`PreToolUse` のツール呼び出しだけだった。ツール呼び出しの回数は発言の回数と比例しない（1 回の発言で
50 回呼ぶこともあれば、0 回のこともある）。

`UserPromptSubmit` は承認の知らせのほかは何も返さない決まりだった（まだ何も起きていない時点で
文脈を 1 段積むことになるため）。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| ルールの `match` に `UserPromptSubmit` を書ける。当てる先は発言の本文（空なら `(prompt)`） | 「発言の回」を数える単位にする。本文に当てるので、`regex` で訂正の言葉などを選ぶこともできる | 当てる先を固定の文字列にする。`glob: "*"` しか意味を持たず、欄が死ぬ |
| 見るのは `allow` のルールだけ。発言は止めない。`deny` / `ask` に書いたものは `--lint` が warn で言う | 止めると利用者の言葉が消える。止めたい場面も無い | 発言を止める（`decision: block`）。守りではなく助言の仕組みなので要らない |
| ルールは全部の層の和から引く（パスを持たないツールと同じ）。本文のファイルは cwd のツリー → プロジェクト → ワークスペースルートの順に探す | どのプロジェクトで話していても同じルールが当たり、cwd に依らない | cwd の層だけ。プロジェクトで話すと共通層の促しが届かない |
| 文面・しきい値・数えは今までの `additionalContext*` と `every` をそのまま使う | 実行ファイルに持つのは当てて数えるところだけ（ADR-0057）。新しい欄を増やさない | 実行ファイルに「10 回に 1 度」を焼き込む |
| 記録には当たったルールの id だけを残し、発言の本文は残さない | 発言には秘密や個人の事情が入りうる | 本文を `subject` に残す |

## 得たもの・失ったもの

- 得たもの: 「発言 N 回に 1 度」「利用者が訂正したら」を設定だけで書ける。ルールを書かなければ今までと同じで、何も返さない
- 失ったもの: **`UserPromptSubmit` が文を返しうるようになった。** 書いたルールのぶんだけ、何も起きていない時点で文脈が積まれる。
  `every` を書かない `glob: "*"` は毎回積むので、`--lint` の「広い allow に文」の warn に当たる
- 失ったもの: 発言のたびにルールファイルを読む。今までは読まなかった
- 失ったもの: 数えは `SessionStart`（compact の後を含む）で 0 に戻る（ADR-0057 と同じ代償）。長いセッションでは正確に N 回ごとにはならない
- 失ったもの: `match` に書ける名前にツールでないものが 1 つ混じった。`UserPromptSubmit` をツールと並べて書く
  （`Bash|UserPromptSubmit`）と、数えは両方で 1 本になる
- 失ったもの: サブエージェントには届かない（`UserPromptSubmit` はメインにしか来ない）

## 採らなかった案

- **設定だけで近づける（`PreToolUse` の全ツールに `every: 50`）。** 実行ファイルに触らずに済む。採らなかったのは、
  数えるのがツール呼び出しで発言ではなく、作業の途中（書きかけのまま）で届くため。道具の多いターンほど早く、
  話すだけのターンでは一度も進まない
- **`Stop` で数える。** ターンの終わりに 1 回だけ。採らなかったのは、`Stop` で文を渡すにはターンを続けさせる
  （`decision: block`）しかなく、促しのたびにターンが伸びるため（ADR-0087 は 1 回だけに絞ってそれを受け入れた）
- **専用の hook スクリプト。** `.claude/hooks/` は保護済みで人が写す必要があり、数えの控えも別に持つことになる
