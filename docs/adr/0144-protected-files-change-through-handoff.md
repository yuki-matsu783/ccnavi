# ADR-0144: 保護対象の変更は、すべて handoff を通して取り込む

状態: 採用（2026-10-18 に実装）

## 状況

エージェントが書けない保護対象（`rules.yml`・hook・ラッパースクリプト・テンプレートなど）を直す手順が、2 本ある。

- 一般の保護対象: `ccnavi-stage.sh <パス>` が元のファイルを `wip/handoff/<ルートからの相対パス>` にコピーする。エージェントはそれを編集する。ユーザは `ccnavi-stage.sh --commands` が出す `mv` をターミナルで打って差し替える
- テンプレート（`.ccnavi/config/{common,project}/templates/`）だけは別の手順: 下書きを `wip/proposals/templates/` に作り、ユーザ専用の `--templates --import` / `--save-draft` / `--delete-draft` / `--rename-template` / `--move-template` / `--delete-template` で取り込み・編集する。差分の表示・ハッシュの照合・検査・ターミナル要求・ボードの画面を、テンプレートのためだけに実装している（約 1,900 行）

同じ「保護対象への書き込みをユーザが決める」処理が 2 つあり、ボードの画面もテンプレートにしか無い。

この ADR は、1 度書いた案に 2 人の敵対的レビューを受けて書き直したもの。最初の案は取り込み先を「禁止の一覧」で決め、ボードからも防御のファイルまで書けるとしていた。レビューで、ワークツリーの `.git` ファイルの差し替えによる任意コードの実行、承認済みチケットの置き場の差し替え、擬似ターミナルの穴を通って防御そのものを書き換える経路が見つかった。この版は、取り込み先を許可リストにし、防御のファイルはボードの経路では取り込めないようにする。

## 決定

### 手順

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 保護対象の変更は、`wip/handoff/<ツリーからの相対パス>` に置いた下書きを、ユーザが `ccnavi user handoff` で取り込む一本の手順にする。取り込み先は、下書きがあるツリーの同じ相対パス（`ccnavi-stage.sh` がコピーしたのと同じ約束） | 差分・ハッシュ・検査・ターミナル要求の実装を 1 つにする。取り込みの結果は、そのツリーのブランチの変更として残り、ふつうの合流で届く | テンプレート専用の手順を残す。拡張が直接書く（検査が二重になる）。常にワークスペースルートへ書く |
| `ccnavi user handoff [<相対パス>…] [--yes --expect <ハッシュ>] [--via board] [--json]`。`--yes` なしは見るだけ（何も書かない）。パスを省くと、許可リストに該当する下書き全部が対象。見るだけの形を含めて、すべてユーザ専用（`user` の入口） | 1 つのコマンドで一覧・差分・取り込みが済む。ターミナルのユーザは `mv` の代わりに使え、拡張は同じコマンドを呼ぶだけ | 見るだけの形をエージェントに許す（免除の判定が増える。エージェントは `ccnavi-stage.sh --commands` で状態を見られる） |
| ツリーは `--root` で指した 1 本。ほかのツリーの `wip/handoff/` は読まない。`ccnavi-stage.sh` と `user handoff` は、同じツリーの決め方（`ccnavi_workspace` と同じ規則）を使い、docs と sh の食い違いを直す | 相対パスだけでは、どのツリーかを表せない。1 回の取り込みで複数のツリーを書き分けない | 全ツリーを走査して同じ中身をまとめる |

### 取り込み先（許可リスト）

取り込み先は「禁止の一覧」ではなく、種類の表に載せたものだけにする。下書きのパスは、リンクを解いた実パスの全要素を `pathcase.fold` と NFC に正規化してから、表に適用する。表に該当しないパスは「対象外」とし、一覧に件数だけ出す。error には数えない（`wip/handoff/` には ccnavi が書く `learnings/`・`inbox/` や、再現用のスクリプトも置かれる）。

種類（`template`・`layer-config`・`docs`・`defense`）ごとのパス・新規作成の可否・ボードの可否・検査の表は、設計書の [9.19 保護対象の変更の取り込み](../design/tickets/handoff.md) にある。`defense` はボードから取り込めず、ターミナルの前のユーザだけが取り込む。

`layer-config` の `rules.yml` のうち、防御の記述を動かす取り込みは、`defense` と同じくターミナルに限る（`--via board` は断り、`--json` の `board` は偽になる）。防御の記述とみなすのは、`guard-` で始まる id のルール（足す・消す・判定を移す・`except` を含む中身を変える）と、今ある deny（消す・中身を変える）。deny を足すのは止める側への変更なので数えない。今の中身か下書きが読めなければ、確かめられないのでターミナルに限る（`handoff._defense_change`）。`phases.yml`・`risks.yml` はこの判定の外。

表に無いものは、取り込めない。表に足すときは、行を足し、テストで表と docs の食い違いを検出する。バイナリ（NUL を含む）と、実行ファイル（`.ccnavi/bin/`）は対象外。

### 取り込みの安全

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 次は断る（error）: 絶対パス・`..`・リンクを含むパス（途中も）・通常のファイルでない・ハードリンク・全要素のどれかが `.git` で始まる（`.git` ファイル自体、`.gitmodules` などを含む）・ワークスペースの外。同じ取り込み先に落ちる下書きが 2 本あれば（大文字小文字、NFC/NFD の違い）両方を断る | 許可リストだけでも、表の正規表現の書き間違いに備えて、防御の層を重ねる | 禁止の一覧だけで決める |
| `--expect` は、対象の一覧から作った 1 つのハッシュ。各対象について、(相対パスの NFC・fold、種類、下書きのバイト列の SHA-256、取り込み先のバイト列の SHA-256（無ければ `-`）、`.orig` のバイト列の SHA-256（無ければ `-`）) を、長さの前置きつきで並べ、パスの並び順で連結して SHA-256 を取る。改行コードは正規化せず、バイト列のまま。`--json` の見るだけの形は、対象ごとの `entry_sha` と、選んだ集合の `expect` を返す（拡張はハッシュを自分で組み直さない） | 見たものだけを書く。`.orig` を直しても、取り込み先を変えても、ハッシュが変わる | ハッシュの定義を実装に任せる |
| `ccnavi-stage.sh` がコピーした `<下書き>.orig` と取り込み先を比べ、コピーしたあとに取り込み先が変わっていれば、その対象は `conflict`。選んだ対象に 1 つでも `conflict` か error があれば、**何も書かない**（選び直させる）。`.orig` が無い対象（新規のテンプレートなど）は、この確認をしない | 部分的に書くと、見せたものと違う状態になる。`.orig` の確認は助言で、本来の歯止めは `--expect` が取り込み先の今のハッシュを含むこと | 変わった対象だけ飛ばして残りを書く |
| 差分は、バイト列の違いを必ず出す: 改行コード（CRLF）・BOM・末尾の改行・制御文字・ゼロ幅の文字は、見える形（`\uXXXX`）に直して見せる。差分が空なのにバイト列が違うときは、そう言って断る | `splitlines` の差分は、改行コードだけの変更を「差分なし」と見せる。`.sh` の CRLF は hook を全部止める | 行の差分だけを見せる |
| 書くのは、一時ファイル → `fsync` → 差し替え。書く直前に、リンクと取り込み先のハッシュをもう一度確かめる。複数の対象を書く途中で失敗したら、書いたものを元に戻し（書く前のバイト列をメモリに持つ）、戻せなかったものを名指しする。複数ファイルの書き込みは、プロセスの途中終了に対して原子的ではない | 書く前の検査の通過後に、途中のディレクトリが差し替えられても、今のテンプレートの取り込みと同じ水準を保つ | 原子的と書く |
| 取り込めたら、下書きの今のバイト列が取り込んだものと同じときだけ、下書きと `.orig` を消す。違えば消さずにそう言う。リンクは消さない | 編集中の下書きを消さない | 常に消す |

### ターミナル要求と錠

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `--yes` で書くときは、標準入力がターミナルであること。`--via board` はターミナルを求めず、`--expect` と `--json` が揃うこと、種類のボード欄が「可」であること、hook の止めに頼る。**`defense` の種類と、防御の記述を動かす `rules.yml` は `--via board` を断る** | ボードの子プロセスはターミナルを持たない。ボードの経路は擬似ターミナルなどの既存の穴の影響を受けるので、防御そのものを書ける入口にしない | 全種類をボードから許す |
| 「作業中のチケットがある間は取り込めない」制限は、今のまま拡張の画面だけが持つ。実行ファイルには足さない。拡張の制限は、`template` と `layer-config` の種類の取り込みに掛ける（今のテンプレートの取り込みと同じ範囲） | 実行ファイルに足すと、ルールの不具合で作業が止まっているときに、ルールを直せない行き詰まりが起きる。今の `mv` にも制限は無い | 実行ファイルで止める |

### テンプレート

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 実行ファイルから外すもの: `--import`・`--replace`・`--save-draft`・`--delete-draft`・`--rename-template`・`--move-template`・`--delete-template`・`--new-name`・`--on`・`--to-layer`。`wip/proposals/templates/`（下書きの置き場）もやめる。残すもの: 一覧・検索・表示（`--templates`・`--keyword`・`--show`・`--layer`・`--json`）と `--draft`（`--name`・`--to`・`--layer` を含む） | 取り込み・編集は handoff に一本化する。改名・移動・削除は、ほかの保護対象の削除と同じく、ユーザがファイルを直接操作する | 改名・移動・削除を handoff の取り込みで表す |
| `--draft <親> [--name <名前>] [--to common\|project] [--layer <名前>]` は、下書きを handoff の取り込み先と同じ相対パスに書く（`--to` の既定は `project`。共通は他のプロジェクトへ配られる）。取り込み先に同名のテンプレートが既にあるときは、上書きになる下書きを作らず断る（直すときは `ccnavi-stage.sh` で既存をコピーして編集する）。同名の下書きがあれば上書きせず断る | `--replace` が無くなるので、黙って置き換わる下書きを作らない | 同名を黙って許す |
| `ready` は、許可リストに該当する未取り込みの下書き（取り込み先と中身が違うもの）が `wip/handoff/` に残っているとき、止める。取り込むか、下書きを消してからにする | 今は `wip/proposals/templates/` の未追跡の下書きが `ready` を止めている。handoff は `ready` が消す置き場なので、同じ性質を保つ | 黙って消す |
| `ccnavi --lint` は、`wip/handoff/` の `template` の下書きを検査する（`lint_templates.py` の置き場を変える）。`--templates --json` の `drafts[]` は、`wip/handoff/` の `template` の下書きを返す形で残す | 今の検査と、ボードの一覧を保つ | 検査をなくす |

### 検査の共有

`layer-config` の検査は、`ccnavi --lint` が同じファイルに掛ける検査と同じ水準にする。`--lint` が持つ「防御を消す・全部止める記述」の error、期待する判定（`rule-expectations.yml`）、共通との合成の衝突を含む。そのために、`policy`・`tickets` の側に「ファイルのパスを受けて検査する関数」を切り出し、`--lint` と `user handoff` の両方がそれを呼ぶ。`tickets` から `entry` を読まない。同じ回に取り込む対象は、取り込んだあとの状態で検査する（`phases.yml` とそれを使うテンプレートを同時に取り込むときなど）。

### ボードと表

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| ボードに、テンプレート専用の取り込み・編集の画面の代わりに、handoff の一覧の画面（`template`・`layer-config`・`docs` の種類）を置く。一覧は `user handoff --json`（見るだけ）で作り、取り込みは `user handoff <パス…> --yes --expect <ハッシュ> --via board --json`。テンプレートの画面は、一覧・検索・表示だけにする。`defense`（と、防御の記述を動かす `rules.yml`）は一覧に出し、「ターミナルで取り込む」ことと打つコマンド（`ccnavi --root <ツリー> user handoff <パス> --yes --expect <ハッシュ>`。引用は POSIX の sh の形）を案内する | 拡張も、同じ 1 つのコマンドを呼ぶだけ | テンプレートの画面だけ残す。拡張が直接書く |
| `user_only.py` の表に `handoff` の操作と `--handoff` を足し、テンプレートの書き込みの操作を実行ファイルの `user` から外す。ボードの組み合わせの語のグループ（`user-board-verb`）に `handoff` を足す | 表を正本のままにする | |
| エージェントが `wip/handoff/` の下のコピーを編集できるよう、名指しのツール（Write / Edit）の保護に例外を入れる。対象は、ツリー（ワークスペースルート、`.claude/worktrees/<名前>`、`projects/<名前>`）の直下の `wip/handoff/` の下だけ。組み込みの `guard-project-home` と、リポジトリのルール `guard-hooks`・`guard-scripts`・`guard-ccnavi-config`・`guard-settings` に入れる。`..` の段・リンク・ハードリンクのあるパス、`docs/wip/handoff/` や `wip/handoffX/` のような綴りは除かない。リポジトリのルールの `except` は式でファイルを見ないので、置き場の中のリンク・ハードリンクの対象への書き込みは組み込みの `builtin:guard-handoff-links` が別に止め、置き場の中にリンクを作るシェルの形（`ln`・`link`・リンクを作る `cp`）は `builtin:guard-handoff-ln` が止める。シェルからの書き込みの保護は、ほかは変えない | `ccnavi-stage.sh` はコピーを元と同じ相対パスに置く。パスに `.ccnavi/` や `.claude/` が入るので、保護の glob に該当し、エージェントがコピーを編集できなかった（この手順が一般の保護対象では最初から成り立っていなかった）。コピーはユーザが取り込むまで効力が無い | 例外を入れず、ユーザがコピーを編集する |
| ボードの rules・phases・risks の画面は、今は拡張が直接書く。この ADR では変えない | 範囲を広げすぎない。画面を handoff に寄せるかは別に決める | 同時に直す |

## 得たもの・失ったもの

- 得たもの: 保護対象の変更の手順が 1 つになる。差分・ハッシュ・検査・ターミナル要求の実装が 1 つになり、テンプレート専用のコード（約 1,900 行）が減る。ボードで、テンプレートに限らず設定と docs を取り込める。ターミナルのユーザは `mv` の代わりに 1 コマンドで取り込める
- 失ったもの: **コマンドの形が変わる。** テンプレートの取り込み・保存・改名・移動・削除、`--draft` の置き場、ボードのテンプレート管理の編集の画面、`.ccnavi/docs/` と docs、テスト（約 50 件）が変わる。ADR-0130 と ADR-0134 の取り込み・編集の手順を置き換える
- 失ったもの: テンプレートの改名・移動・削除を実行ファイルでできなくなる。ユーザがファイルを直接操作する（その間は衝突の検査と錠を通らない）
- 失ったもの: 共通テンプレートの取り込みが「どのツリーの下書きでもワークスペースルートに書く」から「下書きがあるツリーに書く」に変わる。ワークツリーで取り込んだ結果は、そのブランチの変更として合流して届く
- 失ったもの: ボードから `defense` の種類（スキルを含む）と、防御の記述を動かす `rules.yml` は取り込めない。ターミナルで打つ

## 採らなかった案

- 拡張が `wip/handoff/` のファイルを直接コピーする: 検査が拡張と実行ファイルの二重になる
- 取り込み先をテンプレートだけにして、ほかの保護対象は `mv` のままにする: ボードで取り込めない保護対象が残る
- 取り込み先を禁止の一覧で決める（最初の案）: レビューで任意コードの実行と承認の迂回が見つかった

## 他の ADR との関係

- ADR-0130（作業・レビュー計画のテンプレート）と ADR-0134（ボードからのテンプレートの編集）の、取り込みと編集の手順を置き換える。テンプレートの形・検査・一覧・使う側は変わらない
- ADR-0143（ユーザ専用の入口の分離）の対象のうち、`templates` の書き込みを `handoff` に置き換える
