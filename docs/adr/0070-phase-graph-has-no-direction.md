# ADR-0070: フェーズの関係を図にする。線に向きは付けず、置き場所は id だけで決める

状態: 採用

## 状況

フェーズ管理画面は種類を一覧で見せる（ADR-0064）。`requires` と `overlap` は並びの欄に
`,` 区切りで出るだけで、**どの種類がどの種類と結ばれているかは、読んだ人が頭で辿る**。
種類が増えると辿れなくなる。

図にするなら 2 つを決める必要がある。**線に向きを付けるか**と、**何で描くか**。

### 線の向き

最初の案は `requires` を辺にした有向グラフ（DAG）で、レイヤに分けて「先にやる種類」を左に置く
ものだった。**これは間違っている。**

- `ccnavi.md` の種類の表: `requires` は「計画にこの種類を置くなら一緒に置くべき種類」。用途は「承認」
- `ccnavi/approval.py`: `for need in pt.requires: if need not in seen_types:` —
  `plan:` に**入っているか**しか見ない。前後は見ない
- `overlap` は定義からして対称

順序を持つのは親チケットの `plan:` の並びのほうで、`phases.yml` に順序の情報は無い。
矢印を描くと、**無い制約を描く**ことになる。

このリポジトリ自身の `.ccnavi/config/phases.yml` で既に破綻する。`acceptance.overlap: [implement]`
（並行してよい＝同じ段に置きたい）と `implement.requires: [acceptance]`（レイヤに分けると 1 段後ろ）が
衝突する。`phases-doc.ts` の雛形も同じ組なので、**最初に開く絵から壊れる**。

### 判定

同じ案には「循環・到達不能・孤立を見つけて知らせる」が入っていた。これも採らない。
実行ファイルは循環を見ない（`phasetypes.py` が見るのは自己参照の警告と、参照先が
合成後の集合に居るかの検査だけ）。画面が循環を言えば、実行ファイルが出さない答えを画面が
出すことになり、ADR-0035 が禁じた形そのものになる。相互 `requires`（A と B は常に一緒に
置く）は合法で、意味もある。

**行き先の無い参照も、画面は理由を言わない。** 線にしないだけにする。綴り違いなのか他の層の
種類なのかを決めるのは実行ファイルのほうで、`phasetypes.py` の `reference_problems` が
合成した集合で確かめ、無ければ `SEVERITY_ERROR`「`x` という種類は無い」を出す。画面がその
手前で「他の層だろう」と言うと、保存したときに実行ファイルが逆のことを言う。

層をまたぐ参照も同じ。画面が受け取るのはその層 1 本だけ（`phases-view.ts` の `PhasesPage`）で、
行き先が共通層の種類なのか綴り違いなのかは**画面には解けない**。解こうとすると層の合成を
拡張が作り直すことになる。

## 決定

**種類の関係を、向きの無い図で見せる。描くのは `@xyflow/react`（React Flow v12、MIT）。**

| 決めたこと | なぜ |
|---|---|
| **線に向きを付けない。** `requires` は実線、`overlap` は破線。矢印は描かない | `requires` は同席の条件で、順序ではない（上記）。両側が挙げていても 1 本にする |
| **判定をしない。** 循環も到達不能も孤立も見つけない。行き先がこのファイルに無い参照は、黙って線にしない | ADR-0035。実行ファイルに対応する判定が無い領域に画面が踏み込まない。「無い」と言わないのは、共通層の種類かもしれないから |
| 描いていないもの（向きが無いこと・このファイルだけを描くこと・id の無い種類が出ないこと）は、図の下に**常に**出す（`text.ts` の `graphNote`） | 絵は「描いてあるもの」しか語らない。読み方は絵の外に書く。種類ごとの良し悪しは言わない |
| **置き場所は id だけで決まる。線は見ない**（`phases-graph.ts`）。id の順に並べた格子に置く | 保存が通るたびに `model` が丸ごと届き直す（ADR-0062）。**繋がっている種類を近くに寄せると、線を 1 本足しただけで触っていない点まで動く**（最初の実装がそうなっていて、関係を 1 本足すと無関係な点が動くのを実測した）。関係を直しながら確かめる、というこの画面の用途と正面から矛盾する。近くに置きたいときは人が摘まむ |
| 人が摘まんで動かした位置は **Webview の控え**（`state.ts` の `spots`）に入れ、`phases.yml` には書かない | 座標は人が持つ設定に入れるものではない。他の機械へ運ぶものでもない |
| 図は**読むだけ**。関係を直すのは一覧のほう。点を押すと一覧へ戻り、その行が開く | 編集の口を 2 つ持つと、どちらが本当かが分からなくなる |
| v11 ではなく **v12（`@xyflow/react`）** | v11 の最後の版は 2024-06 で、React 19 は保守側が見ていない。v12 は色が `--xy-*` の変数で出来ていて、`--vscode-*` に置き換えられる（v11 は直書きで、打ち消しの CSS が 380 行要る） |
| React Flow の CSS は**束ねの入口が `@import` する 1 行**（`src/webview/phases/style.css` の先頭） | ADR-0066 の段取りをそのまま使う。拡張ホストは出来上がった 1 本を `<style nonce>` に流し込むだけで、nonce はどこにも増えない |

## 理由

### なぜ外から部品を入れるか

自前の SVG でも描ける（試作で 57 行・+2KB）。それでもライブラリを入れるのは、
パン・ズーム・当たり判定・キーボード操作・点の摘まみが**全部ついてくる**から。
自前だと、そこから先は自分で持つことになる。

### 払った代償

**`out/webview/phases.js` が 237.7KB から 420.4KB になる（+182KB、+77%）。** 5 画面のうち
フェーズ管理だけが突出して重くなる。分割はしない方針（`bundle-webview.js`。chunk をファイルとして
読ませると `localResourceRoots` を空にしておけない）なので、この増分はそのまま 1 枚の HTML に入る。
フェーズ管理は対象ごとに 1 枚ずつ開けるので、3 枚開けば 3 倍持つ。

**テストの土台に 2 つ手を入れた。**

- `test/shared/style.test.ts` の `importsOf` に node_modules の解決を教えた。
  教えないと CB-T166 は落ちるのではなく `readFileSync` の ENOENT で**転ぶ**（`@import` の綴りを
  相対としか解かないため）。教えたあとは、vendor の CSS が束ねに入っていることも CB-T166 が見る
- `test/helpers/dom.ts` に大きさの偽物（`measure`）を足した。happy-dom の `ResizeObserver` は
  `observe()` が何もしないので、**細工をしないと React Flow は点を隠したまま線を 1 本も描かず、
  空の絵のまま緑になる**。偽るのは大きさだけで、置き場所は偽らない（線の経路は単体では見られない。
  README の手動確認に回す）
- **掴んで離す仕草は自動で試せない。** d3-drag は happy-dom の下で待ちが終わらず、DOM のテストが
  固まる（実測）。仕草が呼ぶ中身（`withSpot` / `keepSpots`）を純関数にして単体で試し（CB-T191）、
  仕草そのものは README の手動確認 42e が見る

**`out/webview/phases.css` が 13.2KB から 34.4KB になる（+21KB、+161%）。** ADR-0066 は
「CSS は 13〜18KB で、小さくすると board で 2.9KB 減る。その 2.9KB より開発者ツールで読める得の
ほうが大きい」と書いて、束ねた CSS を小さくしないと決めた。**その前提はこの画面では崩れる。**
それでも小さくしないのは、5 画面で並べ方を分けないため。入ってくる規則には、描かない部品
（minimap・controls・resizer）のぶんも含まれる。

**CSS の置き方に例外が 1 つ増えた。** ADR-0066 は「部品 1 つに CSS 1 本、同じ名前の部品がある」
（CB-T168）で、例外は 2 つ（見た目を持たない部品、画面の中で分け合う `App.css`）と書いてある。
外から来る CSS はその 3 つめになる。置き場が `node_modules` なので CB-T168 の検査には当たらないが、
**決まりの外にあることは `style.css` の頭に書いた**。

**CSP は 1 文字も変えていないが、それは保証ではない。** 画面の CSP は `style-src 'nonce-…'` だけで
`'unsafe-inline'` が無く、この下では `style` 属性（`setAttribute("style", …)` を含む）は黙って無効になる。
Chromium で実測したところ、無効になるのは属性のほうだけで、CSSOM（`el.style.x = …` /
`setProperty`）は通る。React の style プロップも React Flow の viewport の transform もそちらを通る。
ただしこれは**いまの版の実装がそうだという事実**であって、設計上の約束ではない。版が上がって
変わっても例外は飛ばず、見た目が黙って抜ける。CB-T190 が束ねたものを見て、止められるやり方が
増えていないかを確かめる。

**React Flow の表示（attribution）はそのまま出す。** 消すには上流が購読を求めている。
MIT の条件ではないので消すこともできるが、こちらから決めることではない。

ただしこれは**押すと外へ出るリンク**（`https://reactflow.dev?utm_source=attribution`）で、
VS Code は Webview のリンクを外部ブラウザへ流す。画面は自分から外を見に行かない（CLAUDE.md の
実行ファイルの境界）が、**人が押せば外へ出る口が 1 つできる**。CB-T167 は CSS しか見ないので、
これは検出されない。色は変数ではなく直書き（`#999`）なので、`Graph.css` で
`--vscode-textLink-foreground` に寄せた（高コントラストの明るいテーマで #999 は 3:1 に届かない）。

**増えた包みは 1 つではない。** `@xyflow/react` が連れてくるぶんを含めて、`pnpm-lock.yaml` には
20（実行時 14: `@xyflow/system`・`zustand`・`use-sync-external-store`・`classcat`・`d3-*` 9 本。
残りは `@types/d3-*`）。

## 代案

- **自前の SVG**（+2KB、依存ゼロ）。パン・ズーム・当たり判定・キーボード操作を自分で持つ。
  150〜250 行。バンドルもテストの土台も動かさずに済む
- **Mermaid**。Webview に入れると 5.3MB で、しかも `<style>` を注入するので nonce の CSP が止める。
  VS Code 内蔵の Markdown プレビューは Mermaid を描かない（第三者の拡張が要る）。採れない
- **図を作らず、一覧に逆参照を出す**（「この種類を requires に挙げている種類: implement, staging」）。
  依存ゼロ・判定ゼロで、`requires` が同席の条件である以上、絵より正確に「頭で辿る」を無くす。
  関係が増えたときに一覧では追えなくなる

## やらなかった場合

一覧のまま。8 種類・線 2 本なら実害は小さい。種類と関係が増えたときに読めなくなる。
