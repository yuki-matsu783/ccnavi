# ADR-0051: レビューはマージリクエストのほかに、このセッションでも受ける

状態: 採用

## 状況

フェーズの種類の `review` は `none` と `mr` の 2 値だった。人が見る道はマージリクエスト 1 本で、
そこにはホストの認証（`GITHUB_TOKEN` / `GITLAB_TOKEN` か gh / glab）が要る。

その結果、ワークスペースの中で完結する作業の進め方が 2 つに割れていた。`review: none` で
チケットとフェーズの範囲は効かせるがゲートは閉じない（人が見る場所が無い）か、`review: mr` で
ホストまで出るか。前者は止まらないので「人が見る」を挟めず、後者は小さな作業に認証と
マージリクエストを要求する。2026-09-16。

## 決定

`review` を 3 値にする（`none` / `chat` / `mr`）。`chat` は「このセッションで人が差分を見る」。
ホストへは出ない。

| 決めたこと | なぜ |
|---|---|
| ゲートは `mr` と同じに閉じる | 「人が見る」を挟むのがゲートの仕事で、見る場所は関係ない |
| 開けるのは端末から打つ `ccnavi --reviewed <N> --chat` | 人の合意の経路を既存の 2 つの守り（標準入力が端末であること・`DENY_TICKET_APPROVAL_CLI`）にそのまま乗せる。`--reviewed` は既にその正規表現に入っているので、新しい綴りを足さない |
| `--chat` は種類が `chat` と宣言したフェーズにしか当たらない | 当たると、`mr` と宣言したフェーズを安い経路で通せる。宣言を緩める道は作らない |
| 見る場所は `none` < `chat` < `mr` の厳しい側が勝つ | 延期を引き受けたフェーズが、引き受けた分より緩い場所で見ることを防ぐ |
| 子の `human_review.required` と実績のリスクは、`none` を `chat` へ上げるだけ | どちらも「要る」としか言わず、場所を言わない。場所を言う宣言（種類と計画の項）を上書きしない |
| 実績のリスクが高いフェーズでは MR を勧めるが、強制しない | 強制すると、ローカルで回している作業が大きくなった瞬間に認証を要求してくる。勧めたうえで、選ぶのは端末に座っている人。選んだ結果はマーカーに残す |
| `kind: feedback` の種類は `chat` も許す（`none` は引き続き許さない） | フィードバック対応の結果を人が見ない道は作らないが、見る場所までホストに縛る理由は無い |
| 親を閉じたとき `phases/<親>/closed.json` を置く | 提案（`wip/`）は統合先へ戻す前に消える。マージリクエストを作らない運び方では、締めた事実の残る先がここしか無い |

## 理由

人の合意を確かめる材料は、もともとマージリクエストの中身ではなく、**打った人が端末に居ること**
だった（`--reviewed --accept-unresolved` がそうなっている）。その材料は写しが無くても揃うので、
`chat` は既存の経路の引数違いで済む。sh は 1 行も変わらず、実行ファイルがネットワークに
出ないという境界（ADR-0028）にも触れない。

## 得たもの・失ったもの

- 得たもの: ホストの認証もマージリクエストも無しに、フェーズのゲートと人の確認が効く。
  「チケットは起こすが外へは出さない」進め方が、止まる形で持てる
- 失ったもの: 「人が見た」の証拠が痩せる。`mr` なら未解決スレッドの数という外形が残り、
  写しと依頼の記録を突き合わせる（ADR-0031）。`chat` に突き合わせる相手は無く、残るのは
  「端末から打たれた」ことと、人が y と答えたことだけ
- 失ったもの: レビューの中身が残らない。何を見て良しとしたかはマーカーの外に出ない
- 失ったもの: 変更要求（REQ-TKT-19 の「このままではマージしない」）に当たる状態が `chat` に無い。
  人が「まだ駄目」と答えたことは、次の呼び出しには残らない
- 失ったもの: 実績のリスクが高いフェーズが、ホストに何も残さずに閉じられるようになった。
  ADR-0027 の「測る」は残るが「効かせる」は勧めるところまでになる。緩めた事実は
  `reviewed.json` の `recommended` に残す

## 採らなかった案

- **リスクが高ければ `mr` へ強制的に上げる。** 安全側だが、ローカルで回している作業が
  途中で認証を要求してくる。止まる場所を作ることと、どこで見るかを決めることは別の問題で、
  後者は人が決められる
- **計画の項（`plan:` の `review:`）でも `chat` を書けるようにする。** 項は `mr` に強めるだけ、
  という不変条件を崩す。緩める道は種類（人が持つ設定）の側にだけ置く
- **`chat` 用の副命令（`ccnavi review chat <N>`）を足す。** `DENY_TICKET_APPROVAL_CLI` の
  一覧に足し忘れると、エージェントが自分でゲートを開けられる。既にある `--reviewed` に
  フラグを足すほうが穴を開けない
