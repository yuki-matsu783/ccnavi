# ADR-0154: 直接作業の取り込み先を記録し、一時ワークツリーで作ったコミットをfast-forwardで載せる。横で作業するユーザとは指定があるときだけ共存する

状態: 採用（切る・integrate・確定・abort・hook・`--lint`・記録の無い既存のワークツリーを引き取る `--adopt` を実装）

## 状況

直接作業は、統合先（`origin/HEAD`。ADR-0148）から切り、終わったら統合先をチェックアウトしているツリーへ `merge --squash` でstagedにして載せていた。この形には次の問題があった。

- ユーザがルートでfeatureブランチを開いていると、統合先をチェックアウトしたツリーが無く、取り込めない。ユーザの意図ともずれる。
- 確認の間、ルートのindexにエージェントの変更がstagedで載る。ユーザが横で作業してコミット・stash・`add -A` をすると、エージェントの変更と混ざる。
- 確認の途中でユーザがブランチを切り替えると、知らないうちに別のブランチへ取り込む。
- ルートの書きかけをコピーして切った場合に、書きかけがコミットに混ざる。

## 決定

| 決めたこと | なぜ |
|---|---|
| 取り込み先は、切った時点でメインのチェックアウト（`git worktree list` の先頭）が開いていたブランチにし、記録（gitの共通ディレクトリの `ccnavi-direct/<名前>`）に残す。統合先（`origin/HEAD`）の扱いは変えない | ユーザが了承したブランチだけに載せる。pushの拒否・MRの宛先・チケットの起点は統合先のままで、取り込み先とは別の概念として分ける |
| 切るときの確認は、ずれ（cwdのHEADと取り込み先の違い、取り込み先が統合先でない、`origin/<取り込み先>` との遅れ・進み・分岐・不在・未確認、書きかけ）がある場合だけ求める。ずれの状態から 8 桁の確認コードを作り、`--accept` に渡すとユーザの了承になる。`--base`・`--accept`・`--side-by-side` は `ask` ルールでユーザの確認ダイアログに出す | 了承した状態と、実行したときの状態が違えば、報告からやり直せる。ダイアログに取り込み先と選んだ指定が見える |
| 書きかけをコピーするかは `--copy-wip` と `--no-wip` のどちらかを選ばせる。コピーするときは、確認した時点のスナップショットのコミットを一時indexで作って `refs/ccnavi/direct/<名前>/pending` に置き、確認コードに含める。作ってもユーザのindexとワークツリーは変えない | 確認したあとの編集が黙って入らないようにする。`--no-wip` で書きかけが入る不整合を作らない |
| `integrate` は、取り込み結果（C）を `merge-tree --write-tree --merge-base=S HEAD T` で計算し、一時ワークツリー（`logs/direct-tmp/<repo>/<名前>`）に展開して止まる。メインのチェックアウトのindex・ワークツリー・HEADには書かない | 確認の間にユーザが横で作業しても、エージェントの変更と混ざらない |
| 基準 S は、作業ブランチが取り込み先を取り込んでいない間だけ使う。取り込み先を取り込んで衝突を解いたあと（先頭と HEAD の共通祖先 M が確認時点の HEAD より新しいとき）は、基準を M にして T を作り直す | S のままだと、取り込み先側と同じ箇所を直した解決結果が「両側が変更」と読まれ、解いても `integrate` が収束しない。M を基準にしても、コピーした書きかけと `wip/handoff/` は成果に含めない |
| `integrate-done` は、一時ワークツリーでCの木を持つコミット（K）をフックを通して作り、Kの親と木を確かめてから、メインのチェックアウトで `merge --ff-only --no-overwrite-ignore K` を打つ | 載せるのは 1 コミットだけにする。ユーザの未コミット・staged・新規ファイルはgitが持ち越し、同じファイルが未コミットならgitが何も変えずに断る。ignoredのファイルは上書きしない |
| 元の作業ワークツリーではKを作らない | 下書きとワークツリーの保護、中断からの再開が難しくなる。一時ワークツリーなら、Cの検証場所とKの作り場を兼ねられる |
| `merge --squash` でstagedに載せる形をやめる。版が 4 でないmarker（版の無いものを含む）は、「版を知りません」で止める | ルートのindexを使う形は、横で作業するユーザのコミット・stash・`add -A` と衝突する。一時ワークツリーでは検証でフックやビルドの生成物が書かれても、ルートに影響しない |
| 一時ワークツリーは、生成物（`node_modules`・`.venv` など）を消したあと、indexの木が期待どおりで追跡ファイルに変更が無く、未追跡のファイル（ignoredを含む）も残っていないときに限って消す。そうでなければ残して通知する | 何が入っていても破棄してよい場所にはしない |
| `--side-by-side` を付けたワークツリーが残っている間だけ、そのメインのチェックアウトで新しく見つかった変更を実行後チェックで戻さず、「出所不明の変更（ユーザか別のセッションの可能性）」として報告する。ワークスペースの他の部分、他のプロジェクト、作業ワークツリーは従来どおり戻す。実行前の判定と、ccnaviの設定ファイルの自己防衛は変えない | 横で作業すると明示されている間に、ユーザのソースの編集を自動復元で失わせない。指定は自動復元を緩めるので、ずれの有無にかかわらず必ずダイアログに出す |
| 取り込み先がチケットに結び付くときは切るのを断る（`ccnavi tree base-bound`）。見るのは、識別子の衝突はワークスペース全体、取り込み先との結び付きは取り込み先のリポジトリだけ。判定できなければ断る | 別のリポジトリの同名ブランチを理由に断らず、チケットの作業を取り込み先に直接載せない |
| 対応範囲はワークスペース自身と、通常の `.git` を持つ `projects/<名前>` のclone。Claude Codeはワークスペースで起動する。gitは 2.40 以上（`merge-tree --merge-base` のため）で、未満は断る | プロジェクトのディレクトリでの起動は、hookとshのルートが割れる問題を全面的に直す必要があり、範囲外にする |
| SessionStartの `ccnavi-fetch.sh` の `merge --ff-only`（3 か所）と `ccnavi-sync.sh`・`ccnavi-start.sh` の早送りにも `--no-overwrite-ignore` を付ける。非ffのmergeには効かないので、付けない | ignoredのファイルを上書きして進めない |

## 許容する不整合・許容しない不整合

| 許容する（打ち直しや通知で済む） | 許容しない（中身を失う・誤って取り込む） |
|---|---|
| 確認したあとにHEADや作業ブランチの先頭が動くと、確認のやり直しになる | `--no-wip` を選んだのに書きかけが入る |
| 取り込まれないKが余分に残る | 中身を確かめていないKが取り込まれる |
| 片付けが一度で終わらない | 下書き・作業ワークツリー・一時ワークツリーの中身を黙って消す |
| gcのあと、正規の取り込みが実行後チェックで報告される | ignoredファイルや、ユーザの未コミットの変更を上書きする |
| 確認したあとの書きかけはコピーされない | 横で作業すると明示されている間に、ソースの編集を自動復元で戻す |
| 横で作業している間、エージェントがBashでルートを書き換えた分は戻らない（報告だけ） | 了承していないブランチ・別のリポジトリへ取り込む |

残る限界は次のとおり。

- エディタで保存していない編集はgitから見えない。fast-forwardのあとに保存するとエージェントの変更を上書きするので、integrateが変わるファイルの一覧を伝え、事前に保存してもらう。
- gitが「上書きされるファイルは無い」と判断してから書き込むまでの間に、ユーザが同じファイルを保存した場合は防げない。範囲はエージェントが触ったファイルだけ。
- フックは一時ワークツリーで走る。カレントディレクトリやルート直下の未追跡ファイルに依存するフックは結果が変わりうる。ルートではfast-forwardなのでpre-commitは走らず、post-mergeだけが走る。
- コピーした書きかけに依存する変更は、取り込み結果だけでは動かないことがある。一時ワークツリーで検証できる。
- 自己防衛は緩めない。横で作業する間も、ccnaviの設定ファイルをユーザがターン中に編集すると戻される。
- 記録・markerは `.git` の中にあり、エージェントにも書ける。gitの状態で照合するが、意図的な偽装は防げない。
- 履歴はエージェントの 1 コミットになる。

## 得たもの・失ったもの

- 得たもの: ルートがfeatureブランチでも取り込める。確認の間にユーザが横で作業しても混ざらない。ブランチが切り替わっていたら断る。Kは確かめてからしか載らない。
- 失ったもの
  - 手順が増える（確認コード、`--accept`、一時ワークツリー）。
  - 履歴が 1 コミットになる点は変わらない。
  - `--side-by-side` の間は、ルートのBashによる書き換えが戻らない。

## 採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 取り込み先を `origin/HEAD` に固定する（従来の作り） | ルートがfeatureのときに取り込めず、ユーザの意図ともずれる |
| integrateのときに、その時点のルートのブランチへ取り込む | 途中でブランチが切り替わると、知らないうちに別のブランチへ取り込む |
| ルートのindexにstagedで載せて確認する | 横で作業するユーザのコミット・stash・`add -A` と衝突する |
| ルートへ 1 ファイルずつ書いて戻す | 競合や失敗時の戻しが複雑で、gitのfast-forwardの保証を使えない |
| 元の作業ワークツリーでKを作る | 下書きとワークツリーの保護、中断からの再開が難しくなる |
| `patch-id` で了承を引き継ぐ | 空白や行番号を無視するので、同じ差分の証明にならない |
| HEADが動いたら自動で追従する | 一時ワークツリーの作り直しなど、分岐が増える。初版では打ち直しで足りる |
| markerに段階を持たせる | 再開の判定はKの有無・正しさ・取り込み先に載ったか・doneの記録で足りる |
| フックが無ければ `commit-tree` に切り替える、検証場所を省く | 署名設定などフック以外の違いがあり、分岐も増える |
| 横で作業するかどうかを「何か確認したか」で決める | リモートのずれを了承しただけで、自動復元が緩んでしまう |
| メインのチェックアウトでは常に自動復元しない | エージェントがBashでルートを書き換えた分の防御が、常に失われる |
| 作業ワークツリーを `projects/<名前>/.claude/worktrees/` に置く | 今の識別の仕組みのままで足りる |
| プロジェクトのディレクトリでの起動に対応する | hookとshのルートが割れる今の問題を全面的に直す必要がある |

## 置き換え関係

- 直接作業の取り込みをsquashでstagedにする部分（ADR-0110 の `integrate` の説明、ADR-0118 の `integrate` / `integrate-done` の状態操作）を置き換える。`integrate-ticket` の判定をshに置く例外の条件は変わらない。
- 統合先の決め方（ADR-0148）は変えない。取り込み先は統合先とは別に、直接作業ごとに記録する。
- 直接作業のワークツリーの起点は、統合先の最新（ADR-0060）から、取り込み先のHEADに変わる。手元の統合先を進めるのがSessionStartの `ccnavi-fetch.sh` だけである点は変わらない。
