# ADR-0046: 引用の外のブレース展開は、展開して読まずに一律に止める

状態: 採用

## 状況

`shellread` は `{` `}` `,` を特別扱いしていなかった。引用の外のブレース展開は 1 語として読まれるが、シェルは実行する前に
複数の語に広げる（Issue #38。shellread-subst の敵対的レビューで見つかった）。

| 書いたコマンド | 読み | 判定 | bash 3.2 | zsh |
|---|---|---|---|---|
| `{git,push,origin,main}` | 1 語 | ask（UNDECLARED） | `git push origin main` を実行 | 実行しない |
| `{rm,-rf,/tmp/x}` | 1 語 | ask（UNDECLARED） | `rm -rf /tmp/x` を実行 | 実行しない |

raw-git にも recursive-delete にも当たらず、deny のはずが ask になる。権限モードが `auto` なら判定を渡すので（ADR-0009）、
人の確認なしに実行されうる。

広げ方はシェルで割れる。2026-09-15 に bash 3.2 と zsh で確かめた。

| 形 | bash 3.2 | zsh |
|---|---|---|
| `{1..5..2}` | 広げない | `1 3 5` |
| `{01..03}` | `1 2 3` | `01 02 03` |
| `${x:-{a,b}}` | `{a,b}` | `a b` |
| `{1..a}` | 広げない | 文字の範囲として広げる |
| `x={a,b}`（代入） | 広げない | 広げない |

このワークスペースの記録（Bash のコマンド 2,841 種類）では、引用の外のブレース展開は 14 件（約 0.5%）だった。
コマンド名の位置は 0 件で、すべて引数の位置にあった（`grep --exclude-dir={…}` がほとんどで、ほかに `grep … ccnavi/{a,b}.py`、
`mkdir -p $S/{a,b}`）。

## 決定

**読む側（`shellread`）は、引用の外のブレース展開を展開せずに見つけて並べる（`Reading.braces`）。**

- 並べるのは、どちらかのシェルが広げる形。引用の外にカンマがある `{…}` と、数か 1 文字の範囲（刻み付きを含む）の `{…}`
- 探す場所は、引用の外のコマンド、引用の外の `${ }` の中、置換の中身、`sh -c` と `eval` に渡った文字列
- 並べないのは、引用の中、`$'…'`、`\{`、引用やエスケープで書いたカンマ（`{"a,b"}`・`{a\,b}`）、ヒアドキュメントの本文、
  コメント、カンマも範囲も無い `{}` と `{a}`
- 入れ子は外側の綴りだけを並べる
- 読み（`text`・`bare`・`degraded`・`unwrapped`）は変えない。縮退した形でも、走査が通った範囲で見つけたものは並ぶ

**判定は、並んでいればルールより先に止める。** コードは `DENY_BRACE_EXPANSION`、記録の `rules` は `(brace-expansion)`。
見る順は、サブエージェントの禁止・フェーズのゲート・プロジェクトの食い違いの後、ルールの前。文面は見つけた綴りを
5 件まで名指しし、語を並べて書く例（`--exclude-dir=a --exclude-dir=b`、`cp f f.bak`、`1 2 3`）と、文字なら単一引用で包むことを案内する。

## 理由

**展開して読まないのは、読み違いが緩む向きに効くから。** 展開した形を元の読みにすると、広げた語が `allow` に当たって通る。
広げ方は bash と zsh で割れるので、どちらかに決めて読むと、決めなかった側で読み違える。展開の規則（入れ子、範囲、刻み、
0 埋め、引用との組み合わせ）を自前で持つことにもなる。

**縮退にしないのは、縮退では止まらないから。** 縮退は生の文字列に当てる。`{git,push,origin,main}` の生の文字列には
`git push` が無いので raw-git に当たらず、`PARSE_UNCERTAIN` の確認にしかならない。縮退の文面は「読めなかったので文字列に当てた」で、
書き直し方も言わない。

**一律に止めるのは、書き直す道が必ずあるから。** ブレース展開は省略記法で、どの形も語を並べて書ける。文字として渡したいなら
引用すればよい。止めた文面に直し方を書いておけば、エージェントは次から並べて書く。

**ルールより先に見るのは、ルールを当てる読みが信用できないから。** 読みと実行される語が違うので、どのルールの判定も
実行されるものについての判定にならない。

## 得たもの・失ったもの

- 得たもの: `{git,push,origin,main}`・`{rm,-rf,/tmp/x}` が止まる。bash と zsh のどちらで実行されても、広げた語がルールをすり抜けない
- 得たもの: 読みを変えないので、既存の読みと判定の表はそのまま
- 失ったもの: 引用の外のブレース展開を使った普通の作業が止まる。記録では約 0.5% のコマンドで、読み取りの `grep` が大半。
  今までは allow だった。書き直せば通る
- 失ったもの: シェルが広げない位置のブレースも止まる。代入の右辺（`x={a,b}`）、case のパターン（`case $x in {a,b})`）、
  `[[ $f == *.{jpg,png} ]]`、bash 3.2 だけで動かす `{1..5..2}` など。引用するか、パターンを `|` で書けば通る（許容する誤検知、
  ccnavi.md §12.2）。位置を見分けて外すと止まっていたものが通る向きになるので、ここでは外さない
- 失ったもの: 層の深さ（4）と語数（2000）を越えて読み直す文字列の中のブレースは並ばない。その形は `sh -c` などで元から縮退していて、
  確認に落ちる
- 失ったもの: 理由コードが 1 つ増える

## 採らなかった案

| 案 | `{git,push,origin,main}` | `grep --exclude-dir={a,b}` | 落とした理由 |
|---|---|---|---|
| 展開した形を元の読みにする | deny | allow | 読み違えると allow に当たって通る。zsh と答えが割れる |
| 展開した形を ADR-0045 の層として deny / ask にだけ当てる | deny | allow | 緩まないが、展開の規則を自前で持つ。通したい普通の作業は約 0.5% で、書き直せば通る |
| 引用の外の `{…,…}` があれば縮退する | ask（`PARSE_UNCERTAIN`） | ask | 生の文字列に `git push` が無く deny に届かない。文面が直し方を言わない |
| 限界として文書に書くだけ | ask / handover | allow | 穴が残る |
| **一律に止めて書き直し方を案内する（採った）** | deny | deny | — |
