# ADR-0024: 並行するチケットの骨：行き先で結ぶ、子は親の部分集合、状態は置き場

状態: 採用

## 状況

メインエージェント（親）が作業を子チケットに分け、サブエージェントに 1 本ずつ実行させる。
子は別々の git worktree で同時に走る。1 本のチケットと 1 つの台帳では、同時に効く承認が複数ある
こと、呼び出しがどのチケットの仕事かを hook が 1 件ごとに決めること、親の承認と子の承認の
関係を決めること、の 3 つが成り立たない。2026-09-09 に利用者と 1 問ずつ詰めた。

## 決定

| 決めたこと | 採らなかった側 | なぜ |
|---|---|---|
| 判定の鍵は Write の行き先が属する作業ツリー | `cwd`、`session_id`、`agent_id` | サブエージェントは親と `cwd` を共有しうる。行き先なら誰が書いても同じ判定になる |
| 作業ツリー名 = チケット識別子。親が git ラッパで作る | チケットに `worktree:` を書く、`Agent` の `isolation: worktree` に任せる | `isolation` は名前を選べない。名前で結べば `--lint` で一致を確かめられる |
| 子は親の部分集合。書いていない場所は範囲外 | 親からの差分だけ書く | 子のファイルだけ読んで、子が書ける場所が分かる |
| 親子は厳しい側が勝つ。深さ 2 段 | 無制限 | 承認画面で祖先を全部たどらずに済む。要ったら上限を上げるだけ |
| 親も自分のチケットに縛られ、作業ツリーを持てる | 親は main で 1 本だけ | 複数の親を同時に走らせたい。main はチケットを持たない |
| 承認済みの姿はチケットごとの写し（ADR-0023） | 識別子ごとに引ける台帳 | 有効な集合 = ディレクトリの中身 |
| 状態は提案の置き場（`todo` / `doing` / `done` / `cancelled`）で表し、保護済みスクリプトだけが動かす | frontmatter の欄 | `ls` で見え、コミットに残り、「閉じたつもり」が起きない |
| 閉じるのは親だけ。承認は要らない | `ccnavi --close` を打たせる、作業ツリー削除で閉じる | 閉じるのは範囲の消える向き。エージェントに ccnavi のコマンドを打たせない |
| 計画中の親はルールだけ。計画の終わりに束で承認 | 親を先に承認、未承認の親に `wip/tickets/` だけ開ける | 「未承認は 1 ミリも効かない」（ADR-0022）を壊さない |
| フェーズは子の `phase:`。同じ番号に足せる | 必ず次の番号 | 足した時点で印を消せば意味は保てる |
| ゲートは `Agent` と Bash（3 本の sh は例外）。Write は通す | Write も止める | 次のフェーズの計画はレビュー前に進めてよい |
| ゲートを開けるのはマージリクエストの未解決スレッドが 0 | 人が印を打つだけ | レビューの実物に結ぶ。GitLab と GitHub をリモート URL で見分ける |
| 未解決を残して進めるのは人が端末で | チャットの OK をエージェントが伝える、UserPromptSubmit で文を拾う | 止められた側がゲートを開ける形にしない。人の手が入る場所を承認と同じ 1 種類に寄せる |
| ブランチの親子と範囲の重なりは見ない | `--lint` で merge-base を見る、重なる承認を拒む | write の範囲だけを見る。重なりを止めると範囲を広げて逃げる向きに働く。レビュー依頼の前提としてだけ合流を見る |

書いてみて決まったことも 4 つある。

| 決めたこと | なぜ |
|---|---|
| 子の作業ツリーにある提案は読まない。同じ識別子が複数のツリーにあれば、親のツリーの側を採る | 子は親のブランチから切るので、親の `wip/tickets/` がそのまま写っている。全部を数えると「複数の場所にある」で状態を動かせない |
| 子が親の部分集合かは、子の項の字義どおりの前置に 1 文字足した綴りを親に当てて決める（`src/b/*` → `src/b/x`） | 前置の末尾の `/` を落として当てると、親の `src/b/*` が `src/b` に当たらず、正当な子を「超えている」と読んだ |
| スクリプト 2 本は実行ファイルを探して渡すだけの薄い形。本体は `ccnavi ticket` と `ccnavi review` | 判定と同じ写しの読み方を 1 か所に保つ。`.git` の `gitdir:` から切り元を引くので、作業ツリーの中から呼んでも写しは切り元の側 |
| 状態の移動は欄の行だけを書き換える。元を消せなければ書いた側を消して戻す | 読み直して書き出すと人の書いたコメントが消えた。両方に残ると以後の操作が全部止まった |

## 理由

参考にした運用（ADR-0025）は判定の材料を cwd のツリーの作業中チケットから採っていて、そのために
並列実施を「隔離はされるが統制が効かない」で発効保留にしていた。「行き先で結ぶ」がその穴を越える。

## 得たもの・失ったもの

- 得たもの: サブエージェントの起動の仕方が判定に影響しない
- 失ったもの: 書き込みは行き先、起動とシェルは `cwd`、と鍵を使い分ける。`cwd` は `cd` 1 回で
  外れ、ゲートはそこで緩む向きに外れうるが、外れた先で起動したサブエージェントの書き込みは
  行き先で止まるので致命傷にならない
- 失ったもの: Stop の exit 2 は「続行させる」道具で、「ターンを終えて人に聞け」を強制する
  手段は hook に無い。先に文で言い、進んだら止める、という 2 段になる
- 決めていないこと: `ticket start` / `done` は写しの有無を見ず、未承認のまま `doing/` `done/` まで
  進める（`--lint` は言う）。`--approve` は `done/` にある未承認の提案も束に入れる。人が子を
  再開しても、そのフェーズの `reviewed` は残る
