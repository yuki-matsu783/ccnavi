# ADR-0079: 端末要求を切る形は、実行ファイルの呼び方によらず止める

状態: 採用

## 状況

2026-09-23、敵対的レビューで次の抜け道が見つかった。人の判断の経路（`--approve` / `--reviewed` /
`--close-early`）は 2 段で守っている。

1. hook の組み込み `builtin-guard-ticket-approval` が、実行ファイルをこれらの付きで打つ形を止める
2. 実行ファイルが、標準入力が端末であることを求める

1 段目は実行ファイルの綴り（`ccnavi`、設定の実行ファイルのパス、`python -m ccnavi`）で呼び出しを
見分けるので、`uv run -m ccnavi`・`python -m ccnavi.__main__`・名前を変えた写しでは当たらない。
2 段目は `CCNAVI_GUARD_TICKET_APPROVAL=disable` か `--guard-ticket-approval disable` で外れる
（テストと CI が端末を持たずに回すため）。両方を組み合わせると、エージェントが人の判断を自分で出せた。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| エージェントのコマンド行で端末要求を切る形（変数の代入、`enable` 以外の値のフラグ）を、何を呼んでいるかによらず `DENY_TICKET_APPROVAL_CLI` で止める | 切れなければ、端末を持たないエージェントは 2 段目で止まる。呼び方は追い切れないが、切る形は 2 つの綴りに絞れる | 1 段目の実行ファイルの綴りを増やす。綴りは写し・別名・ラッパーでいくらでも作れ、足すたびに追い直すことになる |
| 見るのは生の文字列 | `bash -c '…'` や `$( … )` の中に書いた形も同じに数える。シェルの読みを通すと、読めない形で見落とす | 語に割ってから代入だけを見る。grep の誤検知は減るが、中に書いた形を落とす |
| 守りそのもの（hook の `CCNAVI_GUARD_TICKET_APPROVAL`）を切っているときは当てない | テストと CI はこの変数を使って回す。その環境では 1 段目も外している | 常に当てる |

## 失うもの

- この綴りそのものを `grep` で探すコマンド（`grep -rn 'CCNAVI_GUARD_TICKET_APPROVAL=' .` など）も止まる。
  Grep ツールで探せば済むので、文面でそちらを案内する
- 変数の値をファイルに書いて `source` する、のように、コマンド行に綴りが現れない形は見えない。hook は
  最終防衛線ではない（§12.4）
