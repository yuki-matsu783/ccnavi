# ADR-0021: コアファイルはルールの外で守る

状態: 採用

## 状況

実行後の監視の保護領域はルールファイルの `deny` と `ask` から導く（ADR-0017）。だから
ルールファイル自身をそこで守ることはできない。書き換えられた瞬間に「何を守るか」の一覧ごと
消えるので、`deny` を空にされた形も、壊れて組み込みの既定に落ちた形も、保護領域は 0 件になり、
監視は何も検知しない。

## 決定

次のものだけは、ルールファイルの外に組み込みで持つ（`CCNAVI_GUARD_CORE_FILES`）。

| 対象 | 何が懸かっているか | 控えを取る時点 |
|---|---|---|
| `.claude/settings.json` / `.claude/settings.local.json` | hook の登録そのもの | ツール実行前 |
| `CCNAVI_RULES` が指すファイル | 判定の中身そのもの | ツール実行前 |
| 各プロジェクトの `config/rules.yml` | 同上（ADR-0033 で足した） | ツール実行前 |
| `CCNAVI_BIN_PATH` が指すファイル | 判定器の実体 | セッション開始 |

止める側と戻す側の両方を持つ。この面が有効な間、対象へシェルから書き込む形はルールに
書いていなくても拒否し、実行ファイルとプロジェクトのルールは `Write` / `Edit` からも拒否する。
実行前に控えを取り、実行後に突き合わせて、変わっていれば控えから戻す。控えが無いときだけ
git から戻し、落ちたことを報告に書く。

## 理由

守りの根拠を、守られる対象の外に置く（REQ-SLF-04）。

止めるほうが本筋で、戻すほうは止めきれなかったぶんの受け皿になる。戻せるだけでは、実行後に
戻すまでの間、書き換わった設定が効いている時間が残る。その間に実行後のイベントごと消されると、
戻す機会が来ない。実行前にも見るのは、`PostToolUse` の登録を消されるとその次の呼び出しから
実行後の監視が動かないため。ただし `PreToolUse` の登録ごと消された場合は ccnavi が一切動かない。
hook の登録を hook 自身で守ることはできない。

実行ファイルだけ控える時点が違うのは大きさの差による。17 MB ほどのものを呼び出しのたびに写すと、
判定を待たせないために置いた仕組みが判定より重くなる。実行ファイルの実体は中身のハッシュで
名前を付けて 1 本だけ置き、セッションの側は参照だけ持つ。突き合わせは大きさと更新時刻。
指定しなければ対象に入らない。置き場を推測して守ると、そこに在る別のファイルを実体として
扱うことになる。

設定ファイルを名指しのツール（`Write` / `Edit`）から守るぶんはプロジェクトのルールに任せてある。
そこは `deny` に 1 行書けば済み、書いたことが読める場所に残る。実行ファイルは置き場が設定で
動くので、ルールファイルに綴りを固定できない。

止めるのは書き込む綴りと場所の組で、場所の名前が出ただけでは止めない。名前で止めると、
いちばんガードを直したいときにいちばん強く効く。プロジェクトが同じ id で自分のルールを
書いていれば、組み込みは足さない。書いたとおりに効いているほうが読める。

置いていない設定ファイルについては何も言わない。無かったところに現れた場合は言うが、消しはしない。
人が置くこともあるファイルで、消すほうが取り返しが付かない。控えは 3 日より長く触られていない
セッションのぶんを次のセッション開始で落とす。件数の上限にしないのは、人の返事を長く待っている
だけのセッションが、他が増えたという理由で戻す先を失わないため。

## 得たもの・失ったもの

- 得たもの: ルールを空にされても、hook の登録・ルール・実行ファイルは戻る
- 失ったもの: `phases.yml` と `risk.yml` はこの面の対象に無く、ルールの `deny` で止めている。
  ルールを空にされればそこは緩む
- 失ったもの: `SessionStart` に登録しておかないと、実行ファイルは守られない

## 採らなかった案

- コアファイルもルールから導く。上のとおり
- 場所の名前が出たら止める。修復を妨げる
