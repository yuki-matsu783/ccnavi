# ADR-0001: 言語を Go から Python に移す

状態: 採用

## 状況

最初は Go で書いていた。コマンド文字列を語に分ける処理を自作していて、`FOO="bar" cmd` を
代入と読めない不具合を実際に踏んだ。自作の字句解析はシェルの規則を写し損ねるたびに
穴になり、その穴は素通りの側に開く。

## 決定

Python 3.12 で書き、コマンドの分割は標準ライブラリの `shlex` に任せる。

## 理由

`shlex` はシェル自身の字句規則で、こちらが間違える筋合いのものではない。引用とコメントと
区切り記号を解き、`$( )` の括弧が区切り記号として出るのでコマンド置換の中身が独立した
コマンドとして扱われるのはただで付いてくる。引用を剥がして語を組み直すので、`"git" push` を
「特定できない」と諦める必要も無くなった。

速度は理由にならない。移す前に測った。Windows ではプロセス生成が支配的で、Go の実行ファイルが
106〜146 ms/呼び出し、Python 3.12 が 130〜167 ms/呼び出し。差は誤差の中にある。ただしこれは素の
インタプリタでの数字で、実際に配る形（PyInstaller の onedir）は約 220 ms になる（ADR-0002）。
参考資料にある「Python の起動に 0.5 秒」は `uv run` を挟んだ場合の数字で、
インタプリタを直接呼べば再現しない。

## 得たもの・失ったもの

- 得たもの: 字句解析の不具合の元を 1 つ消した。縮退（読み切れない）の理由が 3 つから 2 つに減った
- 失ったもの: 実際に配る形では Go より 1 呼び出しあたり 80 ms ほど遅い（ADR-0002）
- 失ったもの: ヒアドキュメントは `shlex` の概念に無いので、本文を落とす処理は自分で書いた。
  このリポジトリがいちばん踏む誤検知がそこなので、移してもこの部分は消えない
- 失ったもの: Go の RE2 は正規表現の組み合わせ爆発を起こさないが、Python の `re` は起こす。
  ルールの `regex` に病的な式を書くと判定が固まり、hook が期限に達して素通りになる。
  `re` に時間制限は無く、C の中で GIL を握るので別スレッドの見張りも動かない。
  読み込み時に先読み・後読み・後方参照を弾いて書ける範囲を狭くしてあるだけで、
  爆発そのものは塞げていない。ルールを書くのは人で、エージェントは設定ファイルの編集を
  止められているので、脅威というより足元の穴

## 採らなかった案

- Go のまま字句解析を直し続ける。直すたびに別の規則を写し損ねる
