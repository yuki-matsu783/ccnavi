# ADR-0030: push とマージリクエストの作成を親に渡し、人の手を 3 回にする

状態: 採用

## 状況

issue から close まで 1 周させたあとの見直し（2026-09-10）。人の手が 4 回入っていた。
push とマージリクエストの作成も人だった。

## 決定

人に残るのは範囲の承認・レビュー・未解決の受け入れの 3 つ。

| 変えたこと | なぜ |
|---|---|
| `ccnavi-git.sh` が push を通す。ただし今いるブランチを同じ名前で push する形だけ。force / delete / all / mirror / tags / refspec は不可、`main` `master` `develop` `release` `release/*` へ直接は不可 | レビューはマージリクエストそのものと結び付けるので、マージリクエストを作るところまでは親が進められたほうがよい。統合を決めるのは人なので、マージは人の側に残す。通さない形は「戻せなくなるもの」と「人の判断を飛び越すもの」の 2 つに絞った |
| push は親だけ。ラッパースクリプトは子チケットのワークツリー（承認済みチケットに `parent:`）からの push を拒み、hook はサブエージェントからの `ccnavi-git.sh push` を `DENY_SUBAGENT_TICKET_OP` で拒む | push を開けた直後の見直しで、子のツリーからも送れることが分かった。リモートに置くブランチは親ブランチ 1 本で、子のブランチが push されるとレビューの外にあるブランチができる。ラッパースクリプトはツリーを、hook は呼び出し元の素性を見る 2 段構えにしたのは、サブエージェントが親のツリーへ `cd` して打つ形をラッパースクリプトが見分けられないため |
| `review request` が、マージリクエストが無ければ作る（下書きで） | 人はレビューをそこで行う。マージリクエストが無いからといって止める意味はない。題・本文・`Closes #<番号>` は親チケットから写す |
| チケットに `issue` のキー（親だけ、省ける）を足した | `Closes #<番号>` を機械が書けるようにするため。マージで課題が閉じる |
| Draft を外すのは親（`ccnavi-review.sh ready`）。条件は親を閉じられる条件と同じで、`ops.close_problems` を 2 つの経路で共有する。マージは人のまま | 「Draft を外す」は判断ではなく合図で、親が出せる。判断（マージ）は人に残す。条件を 2 か所に持つと片方だけが緩む |
| `ready` は「`wip/` が追跡から消えている・未コミット無し・push 済み」も求め、GitLab では `squash` を有効にする。`wrapup` は Draft を外さず、外すのは `ready` の 1 本 | 途中のコミットとチケットの置き場を既定のブランチに残さない（人は squash で取り込む）。締めた直後は状態の移動が未コミットで `wip/` も残っているので、そこで Draft を外すと「片付いていないマージリクエスト」が世に出る。外す経路を 1 本にすれば、Draft の外れたマージリクエストは必ず片付いている |
| ユーザが締める手段 `ccnavi-review.sh wrapup --reason`。未着手の子を取り消し、マーカーを置き、未解決を受け入れ、残りを issue に写す。`wrapup.json` があれば親はフィードバック計画が無くても閉じられる | 「まだ todo があるが、キリの良いところまでやった」は現実に起きる。検査を 1 つずつ人が迂回する形にすると、迂回した形跡があちこちに残る。1 回の操作で締めて、残りはいつもの場所（cancelled/・skipped・accepted・issue）にいつもの形で残す |
| 受け入れたスレッドの控えを `phases/<親>/accepted.json` へ移した | マーカーに書いていたので、次に通った `check` が同じマーカーを `accepted: []` で上書きし、記録が消えていた。子を足したときのマーカーの消去でも消えていた。人が 1 度言った「これは承知で進める」は取り消されるまで残す |

## 得たもの・失ったもの

- 得たもの: 人の手が承認・レビュー・受け入れの 3 か所に集まる
- 失ったもの: 止められている間に親ブランチを push すれば依頼時の HEAD と食い違い、`check` が依頼のやり直しを求める
- 失ったもの: GitHub は squash をマージリクエストごとに持てないので note に書き、マージのときに人が選ぶ
