# ADR-0008: ルールを `deny` / `ask` / `allow` の 3 タイプに分け、既定を許可にしない

状態: 採用

## 状況

当初の設計は、`sandbox_root` と `expected_roots` で囲った内側に `target_directories` と
`deny_commands` を置き、チケットがその内側で allow を宣言する層構成だった（ADR-0037）。
実装はそこまで作らず、ルールファイル 1 本で判定を始めた。

## 決定

ルールファイルは `.claude/ccnavi/rules.yml`（YAML）で、`deny` `ask` `allow` の 3 つのタイプに
分かれる。強い順に見て、どこにも当たらなければ Claude Code の権限モードに従う（ADR-0009）。
`allow` を書き切るまで、言及されていない呼び出しはすべてそこへ渡る。

## 理由

設計の判定順（deny > ask > allow > 未宣言）をそのまま入れたことになるが、囲いが無いぶん、
絞り込みは `allow` の書きぶりだけが担う。書きすぎれば人が見なくなり、書かなければ確認が
止まらない。だから `allow` は「このプロジェクトで普通にやること」を並べる場所で、
権限を配る場所ではない。ここは実測で調整する。

## 得たもの・失ったもの

- 得たもの: ルール 1 本で判定が始められる。書式が Claude Code の権限ルールと同じ 3 値
- 失ったもの: 層の合成（上位の宣言を下位が緩められない）は、層が無いぶん「チケットは
  絞る向きにしか使えない」（ADR-0022）という形で担保することになった

## 採らなかった案

- 既定を許可にする。言及されていない呼び出しが黙って通り、ルールの抜けに気づけない
- 設計どおりの 4 層。作る前に 1 本のルールで実測するほうが先
