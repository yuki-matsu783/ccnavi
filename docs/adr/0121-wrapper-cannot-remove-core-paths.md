# ADR-0121: git のラッパーでも、自己防衛の対象を消す・別のコミットの中身に戻す形は hook が止める

状態: 採用

## 状況

2026-10-11 の見直しで、`sh .ccnavi/scripts/ccnavi-git.sh rm .ccnavi/scripts/ccnavi-git.sh` が hook で allow になり、
ラッパーも実際にファイルを消すことが分かった（`rm -r .ccnavi/scripts`・`restore --source=HEAD~5 -- .ccnavi` も同じ）。
シェルの `rm .ccnavi/scripts/ccnavi-git.sh` は `builtin-guard-setting-files` で止まる。止める式は書き込みのコマンドが
コマンドの頭に立つ形だけを見るので、`sh … ccnavi-git.sh rm <パス>` はヒットせず、共通ルールの allow（`ccnavi-git`）がヒットしていた。
ラッパーの中の `rm` は `-f` と木全体だけを、`restore` は承認済みチケットの置き場だけを見ていた。

ADR-0114 は、生の git の組み込みの止めを「チケット制御が有効で、ラッパーがあるとき」に足すと決めた。ラッパーを消すと
その条件が外れ、生の git が確認に落ちる。権限モードが auto か bypass なら通る。1 手で組み込みの止めを外すレバーになっていた。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| hook の組み込み `builtin-guard-wrapper-paths`（`DENY_WRAPPER_CORE_PATH`）で、`ccnavi-git.sh` の `rm`（`--cached` も）・`mv`・`restore --source <ref>`・`checkout <ref> <パス>` が自己防衛の対象に向く形を、ルールより先に止める | 止める判定は hook が持つ（P13）。ルールの allow より先に見ないと、共通ルールの `ccnavi-git` の allow が通す | sh の中だけで止める。sh は書き換えられる側で、P13 では 2 重目 |
| 対象は `builtin-guard-setting-files` と同じ場所の式で見る。書いたとおりのパスと、居場所（cwd と `cd` の追跡）で解いた絶対パスの両方に適用する | シェルの書き込みと同じ場所を守る。実行ファイル・動かした ccnavi ディレクトリ・共通レイヤーも同じ式に入っている | 名前の一覧を別に持つ。2 か所の一覧が食い違う |
| 守る場所を中に含むディレクトリ（ツリーの頂上、`.ccnavi`・`.claude`・`.git` を直に、または 1 つ下に持つディレクトリ、実行ファイルなどの上）もヒットする | `restore --source <ref> -- .`・`rm -r projects` で中身ごと消す・戻す | パスの文字列だけを見る |
| `:` で始まる pathspec、グロブの前に固定のディレクトリが無い指定、`--pathspec-from-file`、居場所が読めないときの `..` はヒットするとみなす | git の pathspec のグロブは `/` もまたぐので、`*.sh` はラッパー自身にヒットする。読みで決められないものは止める側に倒す（ラッパーの承認済みチケットの置き場の検査と同じ） | グロブを展開して確かめる。hook は git を起こして pathspec を解かない |
| 索引の中身に戻す `restore`（`--staged`、衝突を解く `--ours` / `--theirs`）は通す | ルールファイルが衝突したときに直す道がここしか無い（ADR-0114 がラッパーで通すと決めた経路）。索引の中身はエージェントが書けない場所から来る | `restore` を全部止める。衝突したルールファイルを直せなくなる |
| `CCNAVI_GUARD_CORE_FILES` で切れる。チケット制御と、組み込みの既定への退避に依らず足す | 自己防衛の一部で、シェルの `rm` を止める組み込みと同じ口で切る。退避の間もシェルの `rm` は既定の 1 本が止めている | チケット制御に揃える。チケット制御を切ったワークスペースで、ラッパーだけが自己防衛の対象を消せる |
| ラッパーにも同じ検査（`core_hit`）を 2 重目に置く。見るのは既定の置き場の名前だけ | hook が読み切れずに確認に回した呼び出しを、ユーザが許したときの受け皿（追記: 実際には共通ルールの allow がヒットするので、読み切れない形は下の追記で hook が止める） | sh には置かない |
| 拒否の文面は、変更をユーザに依頼することと、通る形（衝突の解決・索引だけを戻す形）を案内する | P8。止めた理由と代わりの道を同じ文で返す | 止めたことだけを言う |

## 得たもの・失ったもの

- 得たもの: ラッパー越しに、シェルの `rm` で止まる場所を消せない。ラッパー自身が消えず、生の git の組み込みの止めが外れない
- 失ったもの: `rm '*.pyc'` のように、固定のディレクトリの無いグロブはラッパーでも通らない。1 つずつ名指しするか、ディレクトリを前に付ける
- 失ったもの: 自己防衛の対象をエージェントが git で過去の中身に戻す道は無い。戻すのはユーザ
- 見ないもの: `stash pop` / `apply` と `merge` はワークツリーの変更を退避・取り込むだけで、守る場所を自分では過去の中身にしないので見ない

## 追記: 敵対的レビューの指摘への対応（2026-10-11）

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 承認済みチケットの置き場（`.ccnavi/approved/` とその下）は、sh の `core_hit` では見ない。過去の中身に戻す形は前からの検査（`store_hit` の `restore-store-source`・`checkout-store`）が止め、`rm` は通す | レビュー済みのマーカーを消す手順（`phase._erase_steps`・設計 state-transitions）は、ユーザがターミナルで `ccnavi-git.sh rm .ccnavi/approved/phases/<親>/<N>.reviewed` を打つ形で、origin/main では通っていた。sh はユーザとエージェントを見分けられないので、sh で止めるとユーザの手順が通らない | 案内をユーザが生の git で打つ形に変える。マーカーを消すサブコマンドを作る |
| hook は、エージェントがラッパーで置き場を消す・戻す形を同じ `DENY_WRAPPER_CORE_PATH` で止め、文面は「動かすのはユーザと ccnavi のスクリプト。ユーザに依頼する」にする | 置き場を Write で書く形（共通ルールの `guard-approved-tickets`）と同じく、承認の記録はエージェントが動かさない | エージェントにも通す |
| 対象を読み切れない形はヒットするとみなす。変数・置換で組み立てたパスの語、居場所の読めない `cd` / `pushd` の後の相対パス、走査が読み切れないコマンド行（`rm`・`mv`・`restore`・`checkout` がラッパーの後ろにあるもの） | 共通ルールの allow（`*ccnavi-git.sh*`）が生の文字列にヒットするので、読み切れない形も確認に落ちずに allow になっていた。最初の決定の「hook が読み切れずに確認に回した」は成り立っていなかった。sh が名前を知らない置き場（動かした実行ファイル・共通レイヤー）は hook だけが守る | 確認に落ちる前提のまま見ない |
| 起点（`restore --source` の値・`checkout` の最初の語）だけが変数の形は、対象が読めるので見ない | 戻す先のパスが守る場所でなければ、どのコミットから戻しても守る場所は変わらない | 起点も読めなければ止める |
| `rm -n` / `--dry-run` は何も消さないので、hook も sh も通す | 消える形だけを止める | 消すときと同じに止める |
| hook も、git が受ける長いオプションの省略形（`--sou=`・`--so`・`--pathspec-fr…`）を `--source` / `--pathspec-from-file` と読む | sh は省略形を断るが、sh の許可を広げたときに hook が先に止める前提が崩れないようにする | 完全一致だけを見る |
| `checkout -- <パス>`（起点が無く、索引の中身に戻す）は、守る場所にヒットすれば止め、文面は sh の拒否と同じく `restore <パス>` を名指しで使うよう案内する | sh はこの形を「書きかけを消す」として通さない。理由と次の一手を 2 つの層でそろえる | 別のコミットに戻す形と同じ文で止める |
| sh の `core_hit` の記録の置き場（`logs/`・`logs/state/`・`logs/archive/`・`logs/decisions*.jsonl`）は、ワークスペースルートの下だけに適用する | hook は記録の置き場を絶対パスで見る。sh だけがどの階層の `logs/` にもヒットし、`rm -r tests/logs` を止めていた | どの階層にも適用する |

追記で増えた「失ったもの」:

- 値を変数で組み立てて消す・戻す形（`X=…; … rm $X`）と、`cd "$D"`・`pushd` の後の相対パスは、守る場所に向いていなくても hook で止まる。
  パスを先に読み、そのまま書いて打ち直す（1 手増える）
- 承認済みチケットの置き場の `rm` は、sh では止めない。ユーザがターミナルで打てば通り、エージェントの呼び出しは hook だけが止める
  （hook を切ったワークスペースでは、エージェントもマーカーを消せる。消したことはコミットの差分に残る）

## 追記: ラッパーの名前があるのに読めない呼び出しのうち、単純な規則で止められるもの（2026-10-11 の再レビュー）

共通ルールの allow（`*ccnavi-git.sh*`）は、コマンド行のどこかにラッパーの名前があるだけでヒットする。そのため、ラッパーの
呼び出しを hook が読み切れない形は、確認に落ちずに allow になる。サブコマンドを変数で書く形（`S=rm; sh …ccnavi-git.sh $S
.ccnavi/approved/…`）は、承認済みチケットの置き場の `rm` を sh が通すので、レビュー済みのマーカーを消せた。
ユーザの判断で、塞ぐのは規則 1 本で済むものだけにし、読むのに解析を足す必要がある形は限界として書き残す。

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| ラッパーのサブコマンドが文字どおりの語でなければ（`$`・バッククォート・glob 文字を含めば）止める。`$S`・`${S:-rm}`・`$(echo rm)`・`r?` がこれで止まる | どのサブコマンドが走るかを読めない。規則 1 本で済む | サブコマンドごとに展開を追う |
| 標準入力から読むシェルがあり（ユーザの入口の止めと同じ見方。`shellread_words.reads_stdin`）、呼び出しの語でない語にラッパーの名前があれば止める（`echo '…ccnavi-git.sh rm …' \| sh`） | 既存の検査をラッパーにも適用するだけで済む。ラッパーの名前を混ぜるだけで任意の文字列を流せた（`echo 'sh …ccnavi-git.sh status; rm -rf .ccnavi' \| sh`） | 流し込む文字列を読み直す |
| 走査が読み切れないコマンド行では、ラッパーの名前の直後に文字どおりのサブコマンドが無ければ止める（`… \| xargs sh …ccnavi-git.sh`・`xargs -a f sh …ccnavi-git.sh`）。消す・戻すサブコマンドが並ぶ形は前のとおり止め、ほかのサブコマンドは確認に回す | サブコマンドを文字どおりに読めない形と同じ規則 | 確認（PARSE_UNCERTAIN）のまま |
| 文面は「ラッパーはサブコマンドと対象をそのまま書いて直接呼ぶ。値は先に読んでから書く」を案内する | P8 | 止めたことだけを言う |

限界（止めない形）。どれも、読むのに要る解析の複雑さが、塞げる範囲に見合わない（設計 12.1 にも載せる）。

- **`CDPATH` で居場所を読み違える形**（`CDPATH=.ccnavi cd approved && sh …/ccnavi-git.sh rm t2/reviewed`・環境の `CDPATH`）。
  hook は `cd <名前>` を cwd からの相対と読む。環境の `CDPATH` は hook から見えず、`cd <名前>` を全部読めないとみなすと普段の形まで止まる。
  2 重目: sh の `core_hit` は git が返す実際の居場所で見るので、自己防衛の対象は止める。承認済みチケットの置き場の `rm` は sh も通す
- **別の言語の中で組み立てる形**（`python3 -c 'os.system("sh …ccnavi-git.sh rm …")'`・`perl -e`・`awk` の `system()` など）。
  中の文字列は言語ごとの読み方が要る。2 重目: sh の `core_hit` が展開後の引数で見るので、自己防衛の対象は止める。承認済みチケットの置き場の `rm` は通す
- **xargs に読み込む値の中身**（パイプの左の出力・`xargs -a <ファイル>` の中身）。hook はラッパーの名前の直後のサブコマンドだけを見る。
  2 重目: sh が展開後の引数で見る（承認済みチケットの置き場の `rm` は通す）
- **オプションを変数で書く形**（`restore $O HEAD~1 <対象>`・`checkout $R`。語分割で `--source` や `-- <パス>` になる）。パスの位置の展開は止めるが、
  オプションの位置の展開は追わない。2 重目: sh が展開後の `--source` と対象を見て、自己防衛の対象と承認済みチケットの置き場（`restore-store-source`・`checkout-store`）を止める

未決: ワークスペースルートでのブランチの切り替え（`checkout -b tmp HEAD~3`・`checkout HEAD~3`・
`switch --detach HEAD~3`）は、守る場所をまとめて古いコミットの中身にする。この ADR は消す・パスを名指しで戻す形だけを扱い、
ブランチの切り替えはいまは見ていない。塞ぐかどうかは判定の方針（切り替え先を統合先と親のブランチに限るか）をユーザが決めてから扱う。

## 追記: レビュー待ちの置き場も、エージェントのラッパーの呼び出しから守る（2026-10-11）

レビュー待ちの置き場（`wip/proposals/review/`）は、シェルの `rm` と Write が共通ルールと組み込みで止まるのに、
`sh .ccnavi/scripts/ccnavi-git.sh rm wip/proposals/review/<チケット>.md` は hook も sh も通していた。
エージェントがレビュー待ちの提案を置き場から外すと、ユーザのレビューを経ずにレビュー待ちでなくなる。

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| hook は、エージェントがラッパーの `rm`・`mv`・`restore --source`・`checkout <ref> <パス>` でレビュー待ちの置き場（とその下）を消す・戻す形を、承認済みチケットの置き場と同じく `DENY_WRAPPER_CORE_PATH` で止める。文面は「レビュー待ちの提案を外すのはユーザに依頼する」 | 置き場を動かすのはユーザ（レビュー）と ccnavi のスクリプト（`finish`）。P8 で、代わりの道（ユーザに依頼）を同じ文で返す | 別の理由コードを作る。止める理由と通る形は承認済みチケットの置き場と同じ |
| 置き場の親（`wip/`・`wip/proposals/`。グロブの前の固定の部分も）を丸ごと消す形もヒットする。ただし、置き場にファイルかディレクトリがあるときだけ | 親ごと消すと置き場も消える。空なら消えるものが無い。親を閉じた後の案内（マージリクエストを使わない進め方の `ccnavi-git.sh rm -r wip`。`ops._close_parent`）はこの形で、そのときはレビュー待ちの子が残らない（残っていれば親を閉じられない） | 中身を問わず止める。案内どおりの片付けが止まる |
| sh の 2 重目では止めない。過去の中身に戻す形は、前からの置き場の検査（`store_hit` の `restore-store-source`・`checkout-store`）が止める | sh はユーザとエージェントを見分けられない。ユーザがターミナルで打つ手順を塞がない | sh でも `rm` を止める |
| 置き場の場所は設定の提案の置き場（`tickets`。既定 `wip/proposals`）の下の `review/` で見る。どのツリーのものかは問わない | 承認済みチケットの置き場と同じ見方 | ワークスペースルートのものだけを見る |

追記で増えた「失ったもの」と限界:

- エージェントはレビュー待ちの提案をラッパーで外せない。外すのはユーザ
- 置き場の親の当たり外れは、hook が見たときのディスクで決める。置き場のファイルをディスクから先に消してあり、索引にだけ残る形は、
  親を消す `rm -r wip` で索引から外れる（シェルの `rm` と Write は置き場で止まるので、エージェントがこの形を作るのは難しい）
- ユーザが早めに閉じた（`close-early`）親で、レビュー待ちの子が残ったまま案内の `rm -r wip` を打つと止まる。ユーザに依頼する

## 追記: PR 前の敵対的レビューの指摘（2026-10-11）

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 標準入力から読むシェルの見分け（`shellread_words.reads_stdin`）で、`--norc`・`--posix`・`--noprofile` のような `--` で始まるオプション、値を取るオプション（`--rcfile <値>`・`--init-file <値>`・`-o pipefail`・`-O extglob`・`-euo pipefail`）を読み飛ばす。前に置いた `env`・`command`・`exec`（と代入・オプション）も外して見る | `echo '…ccnavi-git.sh rm wip/proposals/review/…' \| bash --norc` や `\| env sh` が通っていた。sh はレビュー待ちの置き場の `rm` を通すので、hook を抜けるとレビュー待ちの提案を外せた | 「`-c` も `-s` も無く、最初の非オプション語がスクリプトのパスでない」で判定する（`--version` のようなオプションの扱いは同じになるが、値を取るオプションの見分けは結局要る） |
| レビュー待ちの置き場の空の親を通す例外は `rm` だけにする。`restore --source <ref>`・`checkout <ref> --` で親（`wip/`・`wip/proposals/`）を戻す形は、置き場の中身に依らず止める | いまの置き場が空でも、古いコミットの `wip/` にはレビュー待ちの提案がありうる。戻すと提案が置き場に戻る。止めていたのは sh の `store_hit` だけで、hook が先に止める前提（P13）と食い違っていた | 戻す先のコミットの中身を git で読む（hook は git を起こさない） |
| `rm` の `--no-dry-run`（省略形 `--no-d…` も）を見たら、それより前の `-n` / `--dry-run` を取り消す。後に書いたほうを採る | git は後に書いたほうを採るので、`rm --dry-run --no-dry-run <対象>` は消す。sh は `--no-dry-run` を許可リストで断るが、許可を広げたときに hook が先に止める前提が崩れないようにする | `--dry-run` があれば通す |

## 採らなかった案

- **ADR-0114 の条件からラッパーの有無を外す。** ユーザの決定で、ラッパーの無い配布先で git を打つ道が無くなるため採らない。穴はこの ADR で別に塞ぐ
- **シェルの書き込みの式（`builtin-guard-setting-files`）に `ccnavi-git.sh rm` の形を足す。** `restore` の `--source` の有無や `checkout` の語の位置、
  居場所から解いた絶対パスは式で読めない
