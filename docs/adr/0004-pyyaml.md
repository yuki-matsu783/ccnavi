# ADR-0004: 実行時の依存に PyYAML を 1 本だけ許す

状態: 採用

## 状況

以前の方針は依存ゼロだった。ルールファイルとチケットの frontmatter を YAML にした時点で、
読み手をどうするかを決める必要が出た。

## 決定

実行時の依存は PyYAML 1 本。読むのは `safe_load` に限る。PyInstaller と ruff は開発時にしか
要らず、配布物には入らない。

## 理由

自前の読み手を書くと、書式の解釈違いがそのままガードの穴になる。チケットの frontmatter は
エージェントが書くファイルで、そこの読み方が正規の YAML と食い違えば、範囲の宣言を
読み違える。任意の Python の型を組み立てる `load` は、エージェントが書けるファイルに
向けては使わない。

YAML の解析エラーは `ValueError` に包み直す。包まないと、ルールファイルの書き損じが hook の
異常終了になり、組み込みの既定に落ちる経路（ADR-0012）を通らずに落ちるので、壊れた
ファイルを直す呼び出しも止まる。テストで見つけた。読み手を替えるときは包み直しの側も
一緒に見ること。

## 得たもの・失ったもの

- 得たもの: 書式の解釈をライブラリに任せられる
- 失ったもの: 増やした 1 本ぶん、ガード自身が点検できない供給網が増えた。
  `pyproject.toml` と `uv.lock` の編集はルールの `ask` で一言添えるようにしてある

## 採らなかった案

- 依存ゼロのまま自前で読む。上のとおり
- JSON にする。人が書く設定とチケットの frontmatter に向かない
