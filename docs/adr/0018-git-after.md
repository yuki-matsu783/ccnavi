# ADR-0018: 実行後の監視は git を起こし、外部プロセスを起こさない条件は実行前に限る

状態: 採用

## 状況

配布物の条件に「判定の間に外部プロセスを起こさない」と書いてあった。実行後の監視で
作業ツリーの実物を見る手段は git しかない。

## 決定

実行後の監視は `git status` をツリーごとに 1 回起こす（期限 2 秒）。外部プロセスを起こさない
条件は、実行前の判定に限る（REQ-CMN-01）。

## 理由

条件が守っていたのは「呼び出しを止めている最中の遅れがガードの穴に化ける」こと。実行後は
止めていないので、その理屈が掛からない。読めなければ何も言わないだけで穴も開かない。

自前で持つなら、保護領域に当たりうるファイルを毎回歩いて指紋を取り続けることになり、
それは git がすでに持っている情報を作り直すことになる。

## 得たもの・失ったもの

- 得たもの: 引数に現れない書き込み（ビルドの出力、スクリプトの中のファイル操作、読み切れない
  シェル構文で書いたもの）を拾える
- 失ったもの: `.gitignore` の中、git の作業ツリーの外、追跡されていない変更は見えない
- 失ったもの: git を読めなかった回は `worktree-unreadable` として記録に残るだけ。違反が
  無かったのか監視が動いていなかったのかを、記録でしか見分けられない
- 子を閉じるときのリスクの計測で、配点の `script` 項目も `sh` で走らせる。これも実行前ではない

## 採らなかった案

- 保護領域を自前で歩いて指紋を取る。上のとおり
- 実行後も外部プロセスを起こさない。監視が何も見られない
