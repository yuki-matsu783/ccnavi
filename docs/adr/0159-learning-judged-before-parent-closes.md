# ADR-0159: 気づきを親を閉じる前に統合の子で判定し、観測元の数と MR のマージで提案を決着する

状態: 採用（ADR-0135 の統合フェーズ・ルートの受信箱・`--learning-decide`・再発の回数・`index.md`/`log.md` を置き換える。今ある wiki の移行と後方互換は扱わない）

## 状況

ADR-0135 は、統合を親のフィードバック計画のフェーズに置いた。計画に置かなければ統合は行われず、気づきは判定されないまま、`ready`（`wip/` の削除）と squash マージで失われた。
再発の回数は、独立した観測であることを保証できなかった。採否は専用コマンドで書く案だったが、コミットの経路が決まらなかった。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `CCNAVI_LEARNING` の既定を `enable` にする | 何も設定しなくても気づきが溜まるため | 既定 `disable` |
| 親の `finish` が、学び以外の検査を通したあと、親の今の HEAD で気づきごとの処理の行（`処理: 反映 <パターン>` / `処理: 対象外 <理由>`）とパターンの `sources` を照合して止める。毎回検査し直す | 統合の子が閉じたことは処理の証拠にならず、未コミットの変更は届かず、追記や子の追加も同じ検査で扱えるため | 計画のフェーズに置く、`ready` で記録を受信箱へ移す保険 |
| 統合は保守用の子（`<親>-00-NN`、`phase: 0`、`maintenance: learning-consolidate`）が行い、`ticket consolidate` が write-and-push の中で作る。例外は `is_consolidate` の 1 か所から適用する | 計画やレビューを外す条件を曖昧にせず、実行後チェックで違反と扱われないようにするため | 識別子の形からの推定、提案・承認の経路 |
| 統合の子は記録を求めず、リスクを測らず、レビューなしで `done/` へ移り、範囲は ccnavi の中の固定の定義（`docs/wiki/patterns/*`・`docs/wiki/inbox/*`）を上限にする | wiki は直接効かない材料で、人の承認は提案の段にあるため。判定待ちで止まる余地を消すため | 親の範囲を適用する |
| 観測元の数（`sources`、重複しない観測元の ID の数）で数える。ルートの受信箱はやめる | 「再発の回数」とは言えないため。ルートは追跡されず、誰がまとめるかも決まらないため | 再発の回数 |
| 提案の採否は MR のマージで決める（`impact/<提案>.md` の `status`: 承認待ち・承認・却下・延期）。パターンの状態は 1 つに決める。決着のときに `patterns` の数を書き直す | 専用コマンドなしで決着が統合先に残るため。提案中に観測元が増えた延期が、マージ直後に候補へ戻らないようにするため | `--learning-decide` |
| 候補が溜まったとき、または新しい候補が現れたときに、SessionStart の `systemMessage` でユーザにだけ知らせる。統合先の手元の参照のコミットから数える | wiki を作業のセッションに渡さないため。統合先がチェックアウトされているとは限らないため | `additionalContext` に載せる |

## 得たもの・失ったもの

親は処理の証跡がそろうまで閉じられなくなる。対象外とした気づきの本文・理由は、親を閉じるまでの一時的な証跡で、統合先には残らない（squash マージと `ready` の削除で消える）。
統合の子の印は、署名や台帳では保証しない。記録は処理の行を足すだけ、受信箱は消すだけ、という制限も機械では検査しない。

## 採らなかった案

上の表のとおり。複数の親が同じ受信箱を処理するときの排他制御と、まだマージされていない MR の追跡は持たない。
