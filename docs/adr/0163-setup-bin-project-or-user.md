# ADR-0163: 導入スクリプトに、実行ファイルをユーザの置き場に置く選択を足す

状態: 採用

## 状況

実行ファイルを置く場所は、配布先の `.ccnavi/bin/<os>-<arch>/` に固定していた。振り分けの sh は、`bin/` に無いときだけ PATH の `ccnavi` を使うので、PATH に置く使い方（clone 済みのディレクトリで起動し、実行ファイルは環境に登録したものを使う）は、導入スクリプトの外で、ユーザが自分で用意していた。

置き場のパスを指定するオプションは、置き場が動かないことを保つため、持たないと決めていた。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `--bin project\|user` を足す。既定は `project`（従来どおり） | 実行ファイルの置き方は、使い方（ワークスペースを用意するか、clone 済みのディレクトリで起動するか）とは別の軸で、どちらとも組み合わせられる | 置き方を選べない |
| 取るのは `project` と `user` の 2 値だけで、パスは取らない | 置き場が動かないことを保つ。置き場の食い違いで、hook が起動しなくなるのを避ける | 置き場のパスを取る |
| `user` は、実体（同梱物ごと）を `~/.local/share/ccnavi/<os>-<arch>/` に置き、PATH に通す `~/.local/bin/ccnavi` からリンクを張る | PATH に通す実行ファイルは、隣に `_internal/` が要る。単体のコピーは動かない。リンクなら、実体を 1 か所に保てる | `~/.local/bin/` に同梱物ごと置く |
| `user` で配布先の `.ccnavi/bin/` には何も置かず、`.gitignore` にも足さない | 実体はユーザの置き場にある。配布先に二重に置かない | 両方に置く |
| `user` でユーザの置き場に書く回は、書く前に端末で確認する。端末でなければ、何も書かずに断る。確認を飛ばす指定は持たない | ユーザの環境に書く操作で、エージェントが代わりに答えられる形を作らない | `--yes` を持つ |
| 書くものが無い回と `--check` は、確認しない | 確認が要るのは書くときだけ | 毎回確認する |
| PATH への追加は、足す行を知らせるだけで、シェルの設定ファイルは書き換えない | シェルごと・環境ごとに設定ファイルが違い、壊したときの被害が大きい | 設定ファイルに追記する |
| Windows（Git Bash）では `user` を断る | リンクを張れないことがある。コピーすると `_internal/` との関係が崩れうる | コピーで代用する |

## 理由

PATH に置く使い方は、導入スクリプトの外の手作業になっていて、置き場や隣の同梱物を間違えると動かない。選択肢として導入スクリプトが受け持てば、手順が 1 つになる。ユーザの環境に書く操作なので、確認は端末で取り、エージェントが代わりに答えられる経路を作らない。

## 得たもの・失ったもの

- 得たもの: 複数のプロジェクトが、1 つの実行ファイルを PATH から使える。配布先の `.ccnavi/bin/` は空のまま
- 失ったもの: Windows（Git Bash）では使えない
- 失ったもの: 導入スクリプトが、ユーザの `HOME` の下に書く。書くのは決まった 2 か所だけで、端末で確認する
- 失ったもの: PATH を通す作業は、ユーザの手に残る

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| `--bin <パス>` で置き場を指定する | 置き場を動かすと、振り分けの sh と設定の食い違いを作れる。固定のまま、置き方だけを選ばせる |
| 導入スクリプトに触らせず、手順書で案内する | 置き場や隣の同梱物を間違えやすい |
