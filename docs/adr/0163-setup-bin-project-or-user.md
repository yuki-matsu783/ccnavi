# ADR-0163: 導入スクリプトに、実行ファイルをホームディレクトリの下に置く選択を追加する

状態: 採用

## 状況

実行ファイルを置く場所は、配布先の `.ccnavi/bin/<os>-<arch>/` に固定していた。振り分けの sh は、`bin/` に無いときだけ PATH の `ccnavi` を使うので、PATH に置く使い方（clone 済みのディレクトリで起動し、実行ファイルは環境に登録したものを使う）は、導入スクリプトの外で、ユーザが自分で用意していた。

配置先のパスを指定するオプションは、配置先が動かないことを保つため、持たないと決めていた。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `--bin project\|user` を追加する。既定は `project`（従来どおり） | 実行ファイルの置き方は、使い方（ワークスペースを用意するか、clone 済みのディレクトリで起動するか）とは別の軸で、どちらとも組み合わせられる | 置き方を選べない |
| 受け取るのは `project` と `user` の 2 値だけで、パスは受け取らない | 配置先が動かないことを保つ。配置先の食い違いで、hook が起動しなくなるのを避ける | 配置先のパスを受け取る |
| `user` は、実体（同梱物ごと）を `~/.local/share/ccnavi/<os>-<arch>/` に置く。macOS・Linux・WSL は、PATH に通す `~/.local/bin/ccnavi` からそこへリンクを張る | PATH に通す実行ファイルは、隣に `_internal/` が要る。単体のコピーは動かない。実体はデータの保存先（`~/.local/share/`）、PATH に通す入口は `~/.local/bin/` に分け、リンクで結ぶ。pipx や uv tool など、同梱物ごと置くツールが使う形と同じ | `~/.local/bin/` に同梱物ごと置く |
| Windows（Git Bash）では、リンクを張らず、実体のフォルダ（`ccnavi.exe` と `_internal/`）を PATH に通す | Git Bash ではリンクを張れないことがあり、`.exe` と同梱物が並ぶフォルダを PATH に通せば、リンク無しで動く | リンクで揃える。断る |
| `user` で配布先の `.ccnavi/bin/` には何も置かず、`.gitignore` にも追加しない | 実体はホームディレクトリの下にある。配布先に二重に置かない | 両方に置く |
| `user` でホームディレクトリに書き込むときは、書く前に端末で確認する。端末でなければ、何も書かずに断る。確認を飛ばす指定は持たない | ユーザの環境に書く操作で、エージェントが代わりに答えられる形を作らない | `--yes` を持つ |
| 書くものが無いときと `--check` は、確認しない | 確認が要るのは書くときだけ | 毎回確認する |
| PATH への追加は、環境に合った追加の仕方を案内するだけで、シェルの設定ファイルも Windows の環境変数も書き換えない。Windows は PowerShell でユーザの環境変数 `Path` に追加する手順と画面から追加する手順、macOS・Linux・WSL は使っているシェルの設定ファイルに `export` の 1 行を追加する手順（fish は `fish_add_path`） | シェルごと・環境ごとに設定ファイルが違い、壊したときの被害が大きい。環境変数は、どのプログラムから見えるかが変わる | 設定ファイルや環境変数に自動で追記する |

## 理由

PATH に置く使い方は、導入スクリプトの外の手作業になっていて、配置先や隣の同梱物を間違えると動かない。選択肢として導入スクリプトが受け持てば、手順が 1 つになる。ユーザの環境に書く操作なので、確認は端末で取り、エージェントが代わりに答えられる経路を作らない。

## 得たもの・失ったもの

- 得たもの: 複数のプロジェクトが、1 つの実行ファイルを PATH から使える。配布先の `.ccnavi/bin/` は空のまま
- 失ったもの: Windows（Git Bash）での動作は、実機で確かめていない（模した環境でのテストだけ）
- 失ったもの: 導入スクリプトが、ユーザの `HOME` の下に書く。書くのは決まった 2 か所だけで、端末で確認する
- 失ったもの: PATH を通す作業は、ユーザの手に残る

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| `--bin <パス>` で配置先を指定する | 配置先を動かすと、振り分けの sh と設定の食い違いを作れる。固定のまま、置き方だけを選ばせる |
| 導入スクリプトに触らせず、手順書で案内する | 配置先や隣の同梱物を間違えやすい |
