# ADR-0162: 導入スクリプトは、配布元と中身が違う実行ファイルを確認なしで入れ替える

状態: 採用

## 状況

導入スクリプトは、配布先に既にあるものには触らず、入れ替えるのは `--force` を付けたときだけだった。ルールも sh も、配布先で直されている前提だったためである。

この決まりを実行ファイルにも当てると、`build.py` で組み立て直しても、配布先には古い実行ファイルが残る。sh は新しい版に揃うのに実行ファイルだけが古いと、互換の版が食い違い、hook が働かなくなる。気づくのは、食い違いの案内が出てからになる。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| この機械の実行ファイルの置き場（`.ccnavi/bin/<os>-<arch>/`）は、配布元と中身が違えば、`--force` が無くても入れ替える。確認は挟まない | 実行ファイルは配布先で手直しされるものではない。違いは「組み立て直した」か「古い」かのどちらかで、入れ替えて困る手直しは無い | 違っても触らない（従来） |
| 比べる単位は、配布元の直下の 1 つずつ（入れ替えで動かす単位と同じ）。配布先にだけあるファイルは、配布元の名前の下にあるものだけを見る | 前の組み立ての残りは入れ替えのときに消えるので、見落としても収束する。配布先の別のファイルを理由に、毎回入れ替えることもない | 配布先の全体を比べる |
| 比べられないとき（`diff` が無い、読めない）は、違わないものとして扱う | 確かめられないまま、動いている実行ファイルを入れ替えない | 比べられなければ入れ替える |
| ルール・sh・文書・テンプレート・スキルは、これまでどおり `--force` のときだけ入れ替える | 配布先で直されている前提のものは、中身が違うだけでは、直されたのか古いのか区別できない | 全部を差分で入れ替える |
| `--check` は、中身が違う実行ファイルを「揃っていない」に数える | 入れ替えが要る状態を、通過として扱わない | 数えない |

## 理由

実行ファイルは、sh と互換の版でつながっている。実行ファイルだけが古いまま残る状態は、直し方の案内が出る前に、判定が働かなくなる。手で直すものでないなら、違いを確認する意味が無く、再実行のたびに最新へ揃うほうが、利用者が間違えにくい。

## 得たもの・失ったもの

- 得たもの: 組み立て直したあとの再実行だけで、実行ファイルが揃う。`--force` を付けて、手直ししたルールまで巻き込む必要が無い
- 失ったもの: 配布元が古い組み立てのとき（別のチェックアウトから配るなど）は、新しい実行ファイルが古いものに入れ替わる。入れ替えた旨は出力に出る
- 失ったもの: 動いている間に入れ替えると、環境によっては失敗する（Windows で実行中のファイルなど）。`--force` で入れ替えるときと同じ制約で、入れ替えに失敗したら報告する

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| 入れ替える前にユーザへ確認する | 入れ替えて失うものが無く、確認は再実行のたびの手間になる |
| ルール・sh も、配ったときのハッシュを記録して未編集なら入れ替える | 記録の置き場と、編集済みのときの扱いを決める必要がある。実行ファイルだけで、先に困りごとが解ける。必要になったら別の判断にする |
