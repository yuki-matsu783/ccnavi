# ADR-0146: dry-run でも、チケットの関門と補助の保護は止める

状態: 採用

## 状況

`CCNAVI_MODE=dry-run` は、理由に関わらず、止めるはずだった呼び出しを通して報告だけにしていた。導入の途中で
様子を見るには正しいが、チケット制御の関門まで外れた。dry-run のあいだ、エージェントは承認済みの置き場
（承認のマーカー、`done/`、`phases/`、`flows/`）にも操作記録にも書けて、サブエージェントは状態を動かす sh を打て、
範囲の外にも書けた。関門を外した状態で進めた作業の記録は、あとから信用できない。

承認済みの置き場を守っていたのは、ルールファイルの `guard-approved-tickets` と、`CCNAVI_GUARD_CORE_FILES` で
切り替わる自己防衛だけで、組み込みのチケットゲートには入っていなかった。

## 決定

止めている箇所を 3 つに分ける。dry-run で報告だけにするのは一般の保護だけ。

| 分類 | 箇所 | dry-run |
|---|---|---|
| 関門（GATE） | サブエージェントの状態操作、親のツリーへの書き込み、子のワークツリーからの push、レビュー待ち、範囲・チケットの deny と ask、プロジェクトの取り違え、フローのロック、ユーザの判断の経路、提案の状態の置き場、承認済みの置き場と操作記録の置き場への書き込み | 止める |
| 補助（AUX） | 生の git、保護済みの sh への環境変数の指定、生の git や ccnavi の入口を隠しうる書き直し要求（サブエージェントの回、実行時に決まるコマンド名、語としての `git`・`ccnavi`・保護済みの sh の名前が現れる回） | 止める |
| 一般（GENERAL） | ルールファイルの deny と ask、設定ファイル・hook の自己防衛、記録の削除、上記以外の書き直し要求 | 報告だけ |

- 承認済みの置き場（`.ccnavi/approved/` の下すべて）と操作記録の置き場（`logs/state/ops/`）は、組み込みのゲートにする。
  `CCNAVI_GUARD_CORE_FILES` の値にも dry-run にも依らず止める。
- `>` の数の上限で上げた拒否は、シェルから書き込む形の保護（関門の置き場を守る 2 本を含む）を生の文字列に当てない
  代わりなので、チケット制御が有効なら関門として dry-run でも止める。
- 保護済みの sh への環境変数の指定の止めは、`CCNAVI_GUARD_CORE_FILES` では切れない（補助）。
- チケット制御が無効なときは関門を足さない。生の git の止めはチケット制御の有無に関わらず足すが、
  無効なときは一般の保護として扱い、dry-run では報告だけにする。
- 関門と補助で止めた回は、dry-run でも `enforced` が真になり、拒否文に「dry-run でもこの止めは効く」の 1 行を添える。
- `CCNAVI_GUARD_TICKET_APPROVAL=disable` で外れるのは、今までどおり承認の経路の形だけ。

## 得たもの・失ったもの

得たもの: dry-run で導入しても、関門は外れない。限界: 関門を支える設定ファイル・hook 本体・保護済みの sh の書き換えを
止める自己防衛は一般の保護のままで、dry-run のあいだはそれらを書き換えれば関門を外せる。dry-run は様子を見る
段階であり、そのあいだ書き込みの権限を持つ相手は信頼する前提とする。失ったもの: dry-run の「何も止まらない」という単純さ。導入直後に
チケットの関門で作業が止まることがあり、文面でその理由を伝える。

## 採らなかった案

- dry-run をまるごと止める側に寄せる: 一般の保護の抜けを記録だけで見る使い方がなくなる。
- 関門の保護を `CCNAVI_GUARD_CORE_FILES` に任せる: 自己防衛を切った設定で承認済みの置き場が無防備になる。
