# ADR-0092: 判定の記録のファイル名を `logs/decisions.jsonl` にする

状態: 採用

## 状況

判定の記録（CONTEXT.md の用語）は `logs/log.jsonl` に書き、ローテートした分は `logs/log.<日時>.jsonl` だった（ADR-0089）。
`log` はどの記録にも当てはまる名前で、ファイル名から「判定の記録」だと読めない。`logs/` には git のラッパースクリプトの
記録（`git-<日時>.log`）も並び、これから ccnavi 自身の診断ログを `logs/diag/` に足す。名前が `log` のままだと、
どれが判定の記録か、診断ログとどう違うかを、置き場を覚えていないと見分けられない（2026-09-27）。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 既定の記録先を `logs/decisions.jsonl`、ローテート先を `logs/decisions.<日時>.jsonl` にする。ローテートの規則（同じディレクトリ、`<名前>.<日時><拡張子>`、`-2` からの重複よけ）は ADR-0089 のまま、名前だけを置き換える | 1 行が 1 回の判定（`decision`）なので、用語「判定の記録」とファイル名が対応する。診断ログ `logs/diag/` とも名前で紛れない | `log.jsonl` のまま。診断ログを足すと `logs/` の下で見分けにくい |
| 組み込みの守り（シェルの `builtin-guard-setting-files`、名指しのツールの `builtin-guard-records`）の既定の綴りを `logs/decisions*.jsonl` にする。ローテートした分も同じ綴りで守る | 守る範囲は名前が変わっただけで、ADR-0089 と同じ（いま書いている 1 本とローテートした分）。緩めない | いま書いている 1 本だけを守る |
| 環境変数 `CCNAVI_LOG`、設定の `log` のキー、`--log` の名前は変えない | 変えるのはファイル名と文面だけ。キーや変数の名前を変えると、設定と呼び出しの側まで直す範囲が広がる | キーと変数も `decisions` に揃える |
| 古い名前（`log.jsonl` / `log.*.jsonl`）からの移行は扱わない。読み込み・守り・変換の互換は書かない | 利用者の決定。最新の仕様だけを持つ | 古い名前も読み、守り、改名する |

## 得たもの・失ったもの

- 得たもの: ファイル名から判定の記録だと読め、`logs/diag/` の診断ログや git のラッパースクリプトの記録と紛れない
- 失ったもの: **すでにある `logs/log.jsonl` と `logs/log.<日時>.jsonl` は、読まれず守られもしない。** `--suggest` は数えず、`--prune` はローテートも削除もしない。
  組み込みの守りも既定の綴りでは当たらない。残したいなら人が名前を変えるか、`CCNAVI_LOG` で古い名前を指す
- 失ったもの: 記録を名前で読む手元のコマンド（`jq ... logs/log.jsonl` など）は打ち直しになる
- ADR-0089 ほか既存の ADR の本文は、決めた時点の記録として `log.jsonl` のまま残す

## 採らなかった案

- **`logs/decision.jsonl`（単数）。** 1 行が 1 件の判定なので中身は複数で、`decisions` の方が「判定の並び」と読める
- **`logs/decisions/` の下にまとめる。** ローテートした分を 1 か所に寄せられるが、ローテートと守りの規則（同じディレクトリに並べる）まで変わる
