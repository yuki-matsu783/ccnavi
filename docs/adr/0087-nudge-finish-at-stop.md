# ADR-0087: 作業を終えたように見えるのに `finish` されていないチケットは、Stop で 1 回だけ止めて促す

状態: 採用

## 状況

チケットの作業は `ccnavi-ticket.sh finish <識別子>` で閉じる（ADR-0055）。閉じるのはエージェントで、
閉じないとフェーズが終わらず、レビューの依頼（9.10）にも親の締め（9.11）にも進めない。

エージェントが作業を終え、コミットまで済ませたのに `finish` を打たずにターンを終える、という形が
繰り返し起きた（2026-09-26）。ボードでは作業中の列に残ったまま、判定も何も言わない。人が気づいて
「finish して」と打つまで止まる。

`Stop` はこれまで、このターンで変わった保護領域を人へ報告するだけで、止めていなかった
（ターンを続けさせる意味になるので、報告のためには止めない）。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| メインエージェントの `Stop` で、cwd のワークツリーに結び付いた承認済みチケットが「着手済み（`doing/`、`started_at` あり、閉じても取り消してもいない）∧ ワークツリーに未コミットの変更が無い（追跡していないファイルも数える）∧ 基準点（`base_sha`）より先に自分で作ったコミットがある」なら、止めて `finish` を促す。自分のコミットは `rev-list --count --no-merges <base_sha>..HEAD ^<取り込み元>` で数える。取り込み元は、子なら親のブランチ（名前は親の識別子。子のブランチを識別子で引くのと同じ慣習）、親ならワークツリーの起点の `origin/HEAD`（ADR-0060。無ければ除かない）。子で親のブランチを引けなければ促さない | この 3 つが揃うのは、作業の手が止まっていて成果が積まれている形。どれかが欠ければ、まだ作業中か、何も始まっていない | ターンの終わりごとに毎回促す。作業中のターンの区切りのたびに止まり、促しが読まれなくなる |
| 促す文は理由コード `NUDGE_TICKET_FINISH` で始め、打つ sh の綴り（`{root}` からの絶対パス）と「まだ続けるなら理由を利用者に書いてから終える」を言う | 次の一手が 2 つに決まる。続ける正当な理由があるのに `finish` を強いない | `finish` を自動で打つ。閉じるかどうかの判断は作業した側にあり、定性のリスク判定（9.9）など閉じる前の手順も飛ぶ |
| 同じセッションで同じチケットを同じ HEAD のまま促すのは 1 回だけ。促した (チケット, HEAD) を状態の置き場の `nudged-<セッション>.json` に控える（差し戻しの印と同じ置き場。git では運ばず、状態の跡 ADR-0086 にも入れない）。HEAD が進めばまた促す。加えて payload の `stop_hook_active` が真なら促さない。控えの置き場が無い（`--state ""`）か書けなければ促さない | **最初は `stop_hook_active` だけに頼り、ターンの終わりのたびに止まる穴を作った**（2026-09-26 のレビューで再現）。`stop_hook_active` は同じ連鎖の 2 回目しか言わず、エージェントが理由を書いて終えた次のターンでは偽に戻る。覚えられないまま止めると毎回止まるので、黙る側を採る | `stop_hook_active` だけに頼る。上の穴。チケットごとに 1 回だけ（HEAD を見ない）にすると、促しのあとで作業を足してまた閉じ忘れた形を拾えない |
| 応答は一番外の `decision: block` と `reason`。exit 2 と標準エラーは使わない | 同じ `Stop` で人への報告（`systemMessage`）も返すので、1 つの JSON にまとめる。exit 2 だと標準出力の JSON は読まれず、報告が消える | exit 2 で返す。報告と促しのどちらかが落ちる |
| 除くもの: `stop_hook_active` が真、チケット制御が `disable`、モードが `disable`、cwd がワークスペースルートかチケットの無いワークツリー、未着手、信じられない承認済みチケット（`blocked`。ADR-0058）、基準点が無い、未コミットの変更がある、基準点より先にコミットが無い、親で `close_problems` が空でない（開いている子・レビュー準備中／レビュー待ち・フィードバック計画待ち・終わっていないフェーズ）、git を読めない、`SubagentStop` | それぞれ「`finish` が通らない」か「作業が終わっていると言えない」形。親は `finish` と同じ関数（`close_problems`）で見るので、促したのに `finish` が断る、が起きない。レビュー準備中の親は既存の案内が「ターンを終えて利用者を待つ」と言っていて、促すと食い違う | 親は子と同じ条件だけで見る。開いた子を持つ親で毎回止まる |
| `dry-run` では止めず、止めたはずの文を人への報告（`systemMessage`）に載せる | 実行後の監視と同じ扱い。止めないことがモードの約束で、何が起きていたかは見られる | `dry-run` でも止める。モードの約束を破る |
| 判定は実行ファイルの `ops.unfinished_at_stop` に置く。見るのは承認済みチケットと git（`status --porcelain --untracked-files=all`、`rev-parse`、`rev-list`）だけ | 実行ファイルの境界の中（ADR-0028）。ネットワークには出ない | sh で見る。判定は hook が受け持つ（ADR-0077） |
| 記録（`logs/log.jsonl`）の `decision` は `nudge`。`deny` にしない | 促しはツール呼び出しの拒否ではない。`deny` の集計（止めた呼び出しの数）に混ぜると、ガードの効き方が読めなくなる | `deny` で残す。集計が膨らむ |

## 得たもの・失ったもの

- 得たもの: 作業を終えてコミットしたのに閉じ忘れた形が、そのターンのうちに見つかる。人が気づいて
  打ち直す往復が減る
- 失ったもの: **`Stop` がターンを続けさせることがある。** 促された回はエージェントがもう 1 手動く
  （`finish` を打つか、理由を書く）。そのぶんターンが伸びる
- 失ったもの: 「未コミットの変更が無い」は文字どおりに見る。承認済みチケットの置き場（親のツリーの
  `.ccnavi/approved/`）の未コミットの変更も数えるので、親のツリーでは、状態の移動や跡（ADR-0086）を
  コミットするまで親への促しは出ない
- 失ったもの: 続ける正当な理由があるときも 1 回は止まる。理由を書けば通る
- 失ったもの: 見るのは cwd のワークツリーだけ。ワークスペースルートに居て絶対パスで子のワークツリーを
  触っているセッションには促しが出ない
- 失ったもの: 控えはセッションごと。別のセッション（再開を含まない新しいセッション）では、同じ HEAD でももう 1 度促す
- 失ったもの: 親は `origin/HEAD` だけを取り込み元として除く。デフォルトブランチ以外（別の親のブランチなど）を取り込んだ親は、
  取り込んだコミットを自分のものと数えて促すことがある
- 失ったもの: 自分のコミットを数えるのに `--no-merges` を使うので、衝突を解いただけのマージのコミットは作業として数えない
- 失ったもの: `stop_hook_active` は他の `Stop` の hook（テストの差し戻し、ADR-0036）が続けさせた回でも真に
  なる。そのときは、ccnavi がまだ 1 度も促していなくても促さない。その回の連鎖が終われば、次のターンの
  終わりでまた見る

## 採らなかった案

- `PostToolUse` で、コミットの直後に促す。コミットのたびに作業が終わったとは限らず、次のコミットの
  前に毎回言うことになる
- ボードにだけ「閉じ忘れ」を出す。人がボードを見るまで気づかれない。直せるのはエージェントで、
  エージェントはボードを見ない
- 未コミットの変更を無視して、コミットがあれば促す。書きかけのまま `finish` を勧めることになり、
  `finish` は未コミットを見ないので、書きかけが閉じた子の外に残る
