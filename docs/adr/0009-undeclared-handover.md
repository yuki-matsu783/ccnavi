# ADR-0009: ルールが言及しない呼び出しは判定を返さず、権限モードに委ねる

状態: 採用

## 状況

当初の設計は、ルールが言及しない呼び出しを「暗黙的 ask」と呼んで ask の一種として扱い、
人が意図して置いた「明示的 ask」と UI とキャッシュで分ける計画だった。実装でも一時期、
言及の無い呼び出しを ask に格上げして返していた。

## 決定

ccnavi はその呼び出しについて判定を持たない。判定を返さず、扱いを Claude Code の権限モードに
委ね、委ねたことを記録に残す。「暗黙的 ask」という考え方はやめ、理由コードも
`IMPL_UNDECLARED` / `EXPL_ASK` から `UNDECLARED` / `RULE_ASK` に改めた。

| `permission_mode` | 結末 | 記録の `decision` |
|---|---|---|
| `auto` | classifier が判断する | `handover` |
| `default` / `acceptEdits` / `plan` / 空 / 不明 | 人に確認が出る | `ask` |
| `dontAsk` / `bypassPermissions` | 通さない（REQ-PRE-08） | `deny` |

ルールが `ask` と書いた場所は権限モードによらず確認に出す。文面は「危険だから聞いている」
とは書かない。言えないから委ねている。

## 理由

持っていない判定を ask として返すと、判断できるモードでも必ず人に止まり、`auto` が実質
効かなくなる。逆に、人が意図して置いた確認ポイントを classifier の判断で消してはいけないので、
ルールの `ask` は委ねない。確認できる者が居ないモードだけは通さない。あそこで ask を返しても
「誰も答えないまま通る」に化けるため。知らないモードの名前は確認に倒す。名前が 1 つ増えたときに
素通りではなく確認になるように。

記録で分けるのは、ルールを足すべき場所は `handover` の数で決まり、ガードが実際に効いた回は
`ask` と `deny` で決まるから。同じ欄には置けない。

## 得たもの・失ったもの

- 得たもの: `auto` モードが使える。ルールの薄い場所を記録で数えられる
- 失ったもの: 端末からの試験には `permission_mode` が来ないので、言及の無い呼び出しは
  `ask` として出る。`auto` で渡る形や `bypassPermissions` で止まる形は試験では見えない

## 採らなかった案

- 暗黙的 ask を ask の一種として返し、UI とキャッシュで分ける。上のとおり
