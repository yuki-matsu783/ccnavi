# ADR-0167: 大きな会話の放置は、キャッシュが切れる前に引き継ぎ文書を書かせる

状態: 採用

## 状況

Claude は、会話の内容を一定時間だけキャッシュして、続きを安く処理する。保持時間は 1 時間のことも 5 分のこともある。会話が大きく育ったまま、夜通しの作業や席を外した間にキャッシュが切れると、続きを送るたびに会話全体の書き直しになり、利用枠の消費が大きくなる。

キャッシュが温かいうちに引き継ぎ文書を書かせておけば、新しいセッションを小さな会話から始められる。引き継ぎを書かせるターン自体は、キャッシュの読み取りで済む。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 会話の大きさ（トークン数）が閾値以上のとき、次のセッションへの引き継ぎを促す。環境変数 `CCNAVI_HANDOFF_SUGGEST_TOKENS`、既定 400000、0 で無効 | 大きな会話ほど、キャッシュ切れのあとの書き直しが高い。小さな会話では引き継ぎの手間のほうが大きい | 既定を無効にする。常に促す |
| 促しは 2 段。ターンの終わりにユーザへ知らせる（1 セッション 1 回）。放置が待ち時間を過ぎたら、モデルを起こして引き継ぎ文書を `scratchpad/` に書かせる | 知らせはユーザが戻っていても役に立つ。書かせるのは、放置されたときだけにしたい | 知らせだけにする。放置の検知だけにする |
| 待ち時間はキャッシュの保持時間から決める。1 時間なら 55 分、5 分なら 4 分。保持時間は、トランスクリプトの直近の書き込みの内訳（`cache_creation`）で見分ける | 保持時間は認証方式や利用状況で変わる。固定値だと 5 分のときに間に合わない | 55 分に固定する |
| 引き継ぎを書かせたあとの基準を持つ。次に促すのは、基準 + 閾値以上に会話が育ってからにする。会話が基準より小さくなったら基準を 0 に戻す | 同じセッションで続けると、閾値を超えたままなので、放置のたびに引き継ぎが書かれてしまう | 毎回促す。1 セッション 1 回だけ書かせる |
| 知らせは `ccnavi-idle.sh notice`（Stop、同期）、待機は `ccnavi-idle.sh start`（Stop、`asyncRewake`、上限 3600 秒）、取り消しは `ccnavi-idle.sh reset`（UserPromptSubmit）。既存の hook は変えず、別の行として登録する | 55 分待つ処理を同期の hook に載せると、ターンの完了が止まる。既存の入口の判定と混ざらない | 既存の Stop の上限だけを延ばす |
| 判断は実行ファイル（`ccnavi idle`）、待機は sh。状態は `<state>/idle/<セッション>.json` | 実行ファイルはネットワークに出ない。待つだけの処理は sh で足りる | 全部を sh で書く（jq 無しで JSON を読めない） |
| 見ている人がいない実行（`claude -p`・SDK）とサブエージェントは対象にしない。起こすときの指示（目印 `[idle-handoff]`）とバックグラウンド作業の完了通知では、待機を取り消さない | 待機がプロセスを引き止める。自分の指示で取り消すと、書かせる処理が止まる | 全部を対象にする |
| 配布先にも配る。`ccnavi-setup.sh` が 3 本を登録する。要らないときは `--no-idle` | 長時間セッションの費用の問題は、配布先でも同じ | このリポジトリだけに入れる |

## 理由

キャッシュの失効そのものは防げない。防げるのは、失効のあとに大きな会話を書き直す費用である。引き継ぎを失効の前に書かせれば、新しいセッションを小さく始められる。

## 得たもの・失ったもの

- 得たもの: 放置のあとの再開を、小さな会話から始められる。ユーザに事情を説明する知らせが出る
- 失ったもの: 放置のたびに、引き継ぎを書かせるぶんの読み取り費用がかかる。同じセッションで続けるなら、書き直しの費用は避けられない
- 失ったもの: `asyncRewake` の挙動（ユーザの入力との競合を含む）に依る。Claude Code の仕様が変われば直す
- 失ったもの: 待機のプロセスが、応答のたびに 1 つずつ増え、自分の待ち時間が過ぎるまで残る（軽い）

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| キャッシュを温かく保つために、定期的に空の入力を送る | 利用枠を使い続ける。放置の間の費用が、書き直しより高くなりうる |
| 失効したあとの最初の入力で、引き継ぎを勧める | そのときには書き直しの費用がかかる。節約にならない |
| 閾値に達したら、毎ターン促す | うるさい。同じセッションで続けているときの再通知は、基準の刻みで抑える |
