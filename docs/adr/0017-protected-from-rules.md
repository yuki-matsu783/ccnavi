# ADR-0017: 実行後の監視の保護領域はルールから導き、別の宣言を持たない

状態: 採用

## 状況

当初の設計では、実行後の監視が見る保護領域はプロジェクト設定の `target_directories` が
宣言する予定だった。実装にはその設定が無い。

## 決定

`match` に `Write` `Edit` `NotebookEdit` のどれかを含む `deny` / `ask` のルールが、そのまま
「この場所に書かせない」の宣言になる。実行後の監視は、走ったあとの作業ツリーを `git status` で
読み、そこに当たる変更を拾う。

監視は自分の書き込みを自分の違反にしない。記録も控えも `.claude/ccnavi/` にあり、
このリポジトリのルールはそこを保護領域として宣言している。塞がないと、記録を 1 行足すたびに
自分がそれを違反として報告し、その報告がまた記録を増やす。無視設定にも入れてあるが、
それだけに頼らない。

## 理由

宣言を 2 か所に分けると必ず食い違い、食い違った側は誰にも気づかれないまま緩む。

## 得たもの・失ったもの

- 得たもの: 宣言が 1 か所。ルールを直せば監視も同じ場所を見る
- 失ったもの: 宣言そのものが書かれているルールファイルは、この面では守れない。
  書き換えられた瞬間に「何を守るか」の一覧ごと消える。そこは中核ファイルの保護（ADR-0021）が受け持つ

## 採らなかった案

- `target_directories` を別に持つ。上のとおり
