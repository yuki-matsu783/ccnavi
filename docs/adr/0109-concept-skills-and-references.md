# ADR-0109: スキルは標準概念ごとの入口に絞り、細かい挙動は references に溜めて ccnavi --docs で引く

状態: 採用（2026-10-11 にユーザが決めた）

## 状況

スキルの `name` と `description` はセッションの文脈に常に入る。振り返りで新しいスキルを足し続けると、数に比例して文脈が汚れる。
一方、`references/` の中身は開かれるまで文脈に入らず、`ccnavi --docs` は frontmatter の `type` `tags` `keywords` でワークスペースとプロジェクトの両方から引ける。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 標準概念ごとに薄い入口のスキルを5本置く（`designing` `testing` `debugging` `reviewing` `releasing`）。本文は基本の考え方と引き方の一文だけ | 常駐する説明文を5本に固定し、概念の見つけやすさは保つ | 作業ごとにスキルを足す。数に比例して文脈が汚れる |
| 細かい挙動は `references/` に足す。振り返りとスキル改善は、原則 reference の追加か追記として入れる | 開かれるまで文脈に入らない。wiki で確かめた手順の行き先になる | SKILL.md に書き足す。本文が膨らむ |
| 共通は `.claude/skills/<概念>/references/`、プロジェクト固有は `projects/<名前>/docs/skills/<概念>/references/` | プロジェクトだけを clone しても、その範囲のスキルが使える。プロジェクトの目録の仕組みにそのまま乗る | プロジェクト固有を共通の置き場へ書く。clone 単体で使えない |
| `references/` の中のディレクトリ構造は任意にする。引く鍵は frontmatter の `tags`（概念のスキル名を必須）と `keywords` | 構造はまだ見えていない。索引はどの深さのファイルも拾う | 先に構造を固定する |
| 引く指示は SKILL.md の一文だけにする | まず最小で始める。使われなければ後から ccnavi 側の案内を足す | 作業の種類を見て ccnavi が案内を出す。コードの変更になる |
| 既存のスキル（`commit` `ccnavi-config` `eli5` `eli10` `yomiyasu`）は対象外にする | 外部取り込みや用途が固定のものがあり、移すと崩れる | 全スキルを概念に寄せる |

## 得たもの・失ったもの

- 得たもの: 常駐するスキルの説明文が増えない。共通とプロジェクト固有を、置き場で分けられる
- 失ったもの: **検索に頼る。** エージェントが引かなければ使われず、`keywords` の付け方が悪いと拾われない。SKILL.md の一文に頼る
- 失ったもの: プロジェクト側にも同名の概念スキル（`docs/skills/<概念>/SKILL.md`）が要る。そのプロジェクトの中では、目録に概念名が重ねて出る
- 失ったもの: 概念に当たらない手順の置き場がない。新しい入口を足すにはユーザの承認が要る

## 採らなかった案

- **概念スキルを作らず、既存スキルだけに reference を足す。** 概念ごとの共通の入口が無く、プロジェクトが単体で使えない
- **reference を wiki に統合する。** wiki は確かめる前の知識で、reference は手順として確かめたもの。役割が混ざる
