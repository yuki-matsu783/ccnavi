# ADR-0171: ユーザが打つ入口は ccnavi-user-*.sh にそろえ、実行ファイルの user は印が無いと断る

状態: 採用

## 状況

ユーザだけが打つ操作の入口が 3 通りに分かれていた。

- sh が正規の入口（承認、残った指摘の対応方針、早めに閉じる）。
- 実行ファイルの `ccnavi user <操作>` が正規の入口（取り込み、ミラーの同期、記録の整理）。
- 実行ファイルの `ccnavi user agree` など、打てるが途中までしか進まない入口。

実行ファイルはネットワークに出ず、コミットもしない。そのため `ccnavi user agree` を直に打つと、承認だけが済み、承認済みチケットが親のブランチに未コミットのまま残った。ここで `ccnavi-ticket.sh` の `start` と `propose` が write-and-push に止められ、子を作って着手できなかった（受入シナリオ UC-09 の 2 回目の実行）。シナリオの人間の操作が、実行ファイルの形で書かれていたのが直接の原因だった。

## 決定

- ユーザが打つ入口は `ccnavi-user-<操作>.sh` にそろえる。足りなかった `handoff`・`mirror`・`prune` の sh を足す。この 3 本は、実行ファイルを入口の印を付けて起こすだけの薄い包み。
- 実行ファイルの `user <操作>` は、入口の印 `--entry sh|board` が無いと、見るだけの形も含めて断る（終了コード 2）。断りの文は、その操作の sh を案内する。sh は `--entry sh`、拡張のボードの子プロセスは `--entry board` を付ける。
- テストと端末の無い実行環境の逃げ道は、端末要求を切る既存の切り替え `CCNAVI_GUARD_TICKET_APPROVAL=disable` に乗せる。切ると印が無くても通る。新しい切り替えは足さない。
- 印は `WRAPPER_OPTIONS` に入れる。hook の正規表現と読み替えは印を読み飛ばすので、印を付けてもエージェントが打つ `user …` は止まる。
- `--version --json` の `features` に `entry-marker` を足す。拡張は、これを持たない古い実行ファイルに対して `--entry` を付けて呼ばない。

## 理由

- 打つ入口が 1 通りなら、利用者は「sh を打つ」だけ覚えればよい。承認のあとのコミットと push のような後始末が、入口を間違えて抜けることがなくなる。
- 実行ファイルの責務（ネットワークに出ない、コミットしない）は変えない。後始末は引き続き sh が受け持つ。
- 印は守りではない。守りは hook の止めと端末要求のまま。印は、実行ファイルを直に打った人に、正しい入口を案内するために使う。偽装できても、エージェントが打つ形は hook が止める。
- 逃げ道を既存の切り替えに乗せれば、テストは今までの書き方（`CCNAVI_GUARD_TICKET_APPROVAL=disable`）のまま実行ファイルを直に呼べる。

## 得たもの・失ったもの

- 得たもの: 入口を取り違えても、承認が push まで行われない事故は起きなくなる。
- 得たもの: ユーザが打つコマンドの説明が、sh の名前 1 通りになる。
- 失ったもの: 実行ファイルの `user …` を直に打つ使い方。使うには切り替えを切る。
- 失ったもの: 拡張と sh が、実行ファイルを呼ぶときに印を付け忘れると断られる。拡張には、引数を作る関数に印を持たせ、テストで確かめた。

## 採らなかった案

- 既存の `--via` を印に広げる案: `--via` は「端末を求めない経路」の印で、hook の止めもそれに依っている。意味が重なって、止めを緩めるおそれがある。
- 実行ファイルに承認の push まで持たせる案: ネットワークに出ない、コミットしない、という実行ファイルの境界（`docs/claude/exe-boundary.md`）を崩す。
- 見るだけの形は印なしで通す案: ボードの一覧取得などを壊さずに済むが、「入口は sh」という説明に例外が残る。例外を作らず、ボードにも印を付けさせた。
