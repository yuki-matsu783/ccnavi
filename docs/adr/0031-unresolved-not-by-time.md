# ADR-0031: 未解決の指摘は時刻で絞らず、いま残っている全部を数える

状態: 採用

## 状況

以前の `check` は「依頼より後」の指摘だけを数えていた。指摘が残ったまま、子をもう 1 本足して
承認してもらうとその番号のマーカーが全部消え、依頼をやり直せる。やり直した時点で前回の指摘が
「依頼より前」の扱いになって数から消え、人が解決も受け入れもしていないのに `check` が通った。
GitLab API v4 の代役サーバで issue から close まで 1 周させたときに出た穴。

同じ 1 周で、ほかに 2 つ不具合が見つかった。origin の URL からポートが落ちてプロジェクトのパスの先頭に
混ざり、scheme が https 固定だった（手元や社内に平文で立てた GitLab にはどれもつながらなかった）。ワークツリーの
ルートからの相対パスが小文字になっていて、チケットが `README.md` と宣言した範囲に永久に
当たらなかった。

## 決定

`check` が数えるのは、いま解決されていない指摘の全部。除くのは機構自身の投稿
（`<!-- ccnavi: ...`）と、人が `accept` で受け入れたもの（`accepted.json`）だけ。
レビューの状態（変更要求）はレビュアーごとの最新だけを見るので、そちらは時刻をエポック秒に
直して比べる。

origin はホストのポートと scheme をそのまま使う。ssh の `git@host:g/p` の `:` はパスなので、
数字だけのときにポートと見なす。相対パスは比較にだけ大小無視を使い、返す表記は元のまま。

## 理由

時刻で絞る限り、依頼をやり直すだけで指摘が消える抜け道が残る。

## 得たもの・失ったもの

- 得たもの: 人が解決も受け入れもしていない指摘は必ず数に残る
- 未了: `ccnavi-review.sh` の usage の 1 行が「依頼より後の未解決スレッドが無ければ」のまま。
  使う人が読む唯一の入口なので直す（HANDOVER.md の「次にやること」）
- 失ったもの: 古い指摘を「もう関係ない」として断りなく落とすことはできない。人が `accept` で
  受け入れるか、レビュアーが解決する

## 採らなかった案

- 依頼より後だけを数える。上のとおり
