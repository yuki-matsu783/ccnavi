# ADR-0031: 未解決の指摘は時刻で絞らず、いま残っている全部を数える

状態: 採用

## 状況

以前の `check` は「依頼より後」の指摘だけを数えていた。指摘が残ったまま、子をもう 1 本足して
承認してもらうとその番号の印が全部消え、依頼をやり直せる。やり直した瞬間に前回の指摘が
「依頼より前」に落ちて数から消え、人が解決も受け入れもしていないのに `check` が通った。
GitLab API v4 の代役サーバで issue から close まで 1 周させたときに出た穴。

同じ 1 周で、あと 2 つ落ちていた。origin の綴りからポートが落ちてプロジェクトのパスの先頭に
混ざり、scheme が https 固定だった（手元や社内に平文で立てた GitLab は全滅）。作業ツリーの
ルートからの相対パスが小文字になっていて、チケットが `README.md` と宣言した範囲に永久に
当たらなかった。

## 決定

`check` が数えるのは、いま解決されていない指摘の全部。除くのは機構自身の投稿
（`<!-- ccnavi: ...`）と、人が `accept` で受け入れたもの（`accepted.json`）だけ。
レビューの状態（変更要求）はレビュアーごとの最新だけを見るので、そちらは時刻をエポック秒に
直して比べる。

origin はホストのポートと scheme をそのまま使う。ssh の `git@host:g/p` の `:` はパスなので、
数字だけのときにポートと見なす。相対パスは比較にだけ大小無視を使い、返す綴りは元のまま。

## 理由

時刻で絞る限り、依頼をやり直すだけで指摘が消える道が残る。

## 得たもの・失ったもの

- 得たもの: 人が解決も受け入れもしていない指摘は必ず数に残る
- 失ったもの: 古い指摘を「もう関係ない」として黙って落とすことはできない。人が `accept` で
  受け入れるか、レビュアーが解決する

## 採らなかった案

- 依頼より後だけを数える。上のとおり
