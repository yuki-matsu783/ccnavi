# ADR-0049: 未宣言の呼び出しは判断できる相手が居るモード全部に委ね、確認できない側は設定で選ぶ

状態: 採用

## 状況

ADR-0009 は、ルールが言及しない呼び出しを `auto` にだけ委ね、`default` / `acceptEdits` / `plan`
では確認を返し、確認できる者が居ないモード（`dontAsk` / `bypassPermissions`）では通さないと決めた。

`default` で確認を返すことは、Claude Code 自身の確認への上乗せになる。Claude Code はそのモードでも
`settings.json` の `permissions` とモードの既定で判断していて、書き込みとシェルには確認を出し、
読み取りは通す。判定の記録（`PreToolUse` 6145 行）では未宣言が 2916 件あり、うち `Read` が 1172 件。
`auto` 以外に切り替えた瞬間、その全部が ccnavi の確認になる。読み取りは Claude Code だけなら
黙って通る呼び出しで、そこに確認が出る理由は「ルールに書いていない」だけになる。

確認できる者が居ないモードで通さない判断は、配る先によって評価が割れる。人が意図して確認を捨てた
モードに ccnavi が別の確認層を建てても、利用者に残る選択は「設定を切るか ccnavi を切るか」になる。
一方で、配った先が `bypassPermissions` を使うなら、そこがルールの薄さに気づける最後の場所でもある。

## 決定

- 判断できる相手が居るモード（`auto` / `default` / `acceptEdits` / `plan`）には、未宣言の呼び出しを
  委ねる。ccnavi は判定を返さない
- 知らないモードの名前と、モードが来ない呼び出しは、今までどおり確認に倒す
- 確認できる者が居ないモードの扱いは `CCNAVI_GUARD_UNWATCHED` で選ぶ。`enable`（既定）は通さない、
  `disable` は委ねる。値は 2 つだけで、この門に `dry-run` は無い
- 読み切れなかった呼び出しは、どの設定でも委ねない（REQ-PRE-04）
- 切ってあることは `--lint` が warn で言う。止めも書き換えもしない

## 理由

ccnavi が確認を上乗せしても、判断する者は増えない。増えるのは、同じ呼び出しで 2 度聞かれる回数だけ。
判断できる相手が居るなら渡す、というのが ADR-0009 の理屈で、`auto` にしか適用していなかったのは、
Claude Code 自身の権限の仕組みを「判断する相手」に数えていなかったため。数えれば 4 つになる。
これは REQ-PRE-10 の文面（判定を返さず権限モードに委ねる）に近づく向きでもある。

確認できる者が居ないモードを設定にしたのは、ここだけは「ccnavi は権限の層か、ルールの層か」という
立場の違いがそのまま結末を分けるから。自分たちのワークスペースで決め切れる話ではなく、配る先ごとに
違う。プロジェクトの `.claude/settings.json` に置けば、個人が `bypassPermissions` で動かしても
プロジェクトの決めた側に倒れる。個人がその `settings.json` を書き換えれば通るが、それは人の操作で、
エージェントにはできない（コアファイルの守り、§8）。`env` は同じセッションでは読み直されないので、
効かせるにはセッションを開き直すことになる。

既定を `enable` に置いたのは、配った先で黙って弱くならない側だから。弱くする側を選ぶ人は、
自分で 1 行書く。

## 得たもの・失ったもの

- 得たもの: `default` / `acceptEdits` / `plan` で二重の確認が出ない。プロジェクトが
  「確認できないモードをどう扱うか」を設定で決められる
- 失ったもの: `default` / `acceptEdits` / `plan` では、ワークスペースの外を含む読み取りが ccnavi の
  目には静かになる（Claude Code 自身の `deny` は効く）。REQ-PRE-08 は、未宣言の呼び出しについては
  既定に格下げされ、`disable` の層では未宣言が全部通る。ルールの薄さに気づける場所は記録だけになる

## 採らなかった案

- つまみを 4 段（常に確認 / モードに従う / 読み取りは委ねる / 常に委ねる）にする。`default` の行を
  直せば 2 値で足りる。段を増やすと、組み合わせの表と文書だけが増える
- 共通層に読み取りの `allow` を 1 件足して済ませる。つまみは増えないが、段を変えるたびにルールの
  書き換えになり、プロジェクトごとに毎回書くことになる
- 読み取り専用ツール（`Read` / `Grep` / `Glob`）だけコードで委ねる。REQ-PRE-08 に例外を開けるわりに、
  厳しくしたい層が戻せない
