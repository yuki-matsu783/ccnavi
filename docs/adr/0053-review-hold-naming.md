# ADR-0053: 止めている状態は「ゲート」ではなく「レビュー準備中」「レビュー待ち」と呼ぶ

状態: 採用

## 状況

人間レビューが要るフェーズが終わってから `reviewed` のマーカーが置かれるまで、サブエージェントの
起動とシェル実行を止める（9.8）。この働きを「ゲート」と呼び、拒否の文面・`--explain`・ボードのバッジまで
その語で出していた。

2026-09-16 の時点で、困っていたことが 3 つあった。

- **語から何も読み取れない。** 「ゲートが閉じている」と言われた側は、止まっていることは分かるが、
  次に何をすればよいかが分からない。エージェントも人も同じ
- **止まっている区間が 1 つの名前にまとめられていた。** 実際には性質の違う 2 つの段がある。依頼を
  出すまでに動くのはエージェント（合流・push・依頼）で、出した後に動くのは人。判定は
  この 2 つを `gate_closed` と `review_waiting` で既に区別していたのに、表示は「ゲート閉」
  1 枚で、ボードでは「ゲート閉」と「レビュー依頼済」の 2 つのバッジを人が突き合わせて読んでいた
- 「ゲート」はもう 1 か所、提案の承認（REQ-APV）でも「チケット承認ゲート」として使っており、
  同じ語が別の物を指していた

## 決定

止めている区間を、次に動く者で 2 つに分けて名前を付ける。止まるところそのものは
「HITL ポイント」（Human In The Loop。人の手が入るところ）と呼ぶ。人の手が入る場所を 3 か所にまとめた
ADR-0030 の語をそのまま引き継いだもので、この道具だけの造語は作らない。

| 判定の値 | 呼び名 | 次に動く者 |
|---|---|---|
| `gate_closed` ∧ `review_waiting` でない | レビュー準備中 | エージェント（合流・push・依頼） |
| `review_waiting`（= `gate_closed` ∧ 依頼済み） | レビュー待ち | 人 |

| 決めたこと | なぜ |
|---|---|
| 拒否の文面の「やること」を段ごとに書き分ける | 「レビュー待ち」の親に「request で頼め」と伝えても、打つコマンドが無い。依頼済みなら、やることは「待って、済んだら check」に変わる |
| 理由コードを `DENY_PHASE_GATE` から `DENY_PHASE_REVIEW` へ | 理由コードは文面の先頭に出るので、ここに `GATE` が残ると「ゲート」という語が消えない |
| ボードのバッジは 2 つから 1 つに（段の名前だけ） | 「ゲート閉 + レビュー依頼済」の読み合わせを、名前 1 つにまとめる。依頼のマーカー自体はフェーズ行の全文に経過として残る |
| JSON のキー名 `gate_closed` は変えない | このキー名は判定とボードの間の契約になっている。変えると、古い拡張と新しい実行ファイルが混ざったときに、知らないうちにバッジが消える。人に見せる名前だけを変える |
| `review: chat` のフェーズは「レビュー準備中」のまま（`request` を通したときだけ「レビュー待ち」へ移る） | 依頼という段が無く、「合流して差分を見せた」ことを記録するマーカーも無い。マーカーを新しく作ると人が置くことになるので、作らない。マージリクエストに出したときは取得結果の JSON があるので `mr` と同じでよい |
| 「チケット承認ゲート」（REQ-APV）は「チケットの承認」へ | 同じ語で別の物を指すのをやめる |
| 仕組みを指す名詞は「HITL ポイント」、止まる動きは動詞で書く | 「ゲート」も「足止め」もこの道具の中だけの語になる。HITL は道具の外でも通じる |

## 理由

止めることの目的は、人が見ていない成果を合流させないこと（3 章）で、止まっていること自体を
伝えるのが目的ではない。止めることは、止められた側が次の一手を打てて初めて役に立つ。これは「拒否は目的を
諦めさせるのではなく別の道へ向け直す」という、この道具の出発点と同じ考え方である。

## 得たもの・失ったもの

- 得たもの: 止められたときの文面から次の一手が分かる。ボードのバッジが 1 つ減る。「ゲート」という
  この道具だけの語を覚えなくてよくなる
- 失ったもの: 内部の表記（JSON の `gate_closed`）と表示名が一致しなくなった。`phase.review_label`
  と `holdLabel()` の 2 か所が対応表を持つ
- 記録（`logs/log.jsonl`）の `code` が変わるので、`DENY_PHASE_GATE` で数えていた集計とは続けて数えられない
