# ADR-0126: 概念スキルを工程スキルと呼び、調査の工程を足す

状態: 採用（2026-10-12 にユーザが決めた。ADR-0111 の「概念スキル」の呼び名とキー、「5本」を改める。ほかの決定は ADR-0111 のまま。工程スキルの名前と「6本」は ADR-0133 で改めた）

## 状況

ADR-0111 の5本は、標準の作業ごとに置く薄い入口で、細かい挙動を `references/` に溜める。「概念」はこの役割を言い当てておらず、`commit` のような手順スキルとの違いも名前から読めない。
また、不具合に限らない調べもの（既存コードの読み解き、技術や案の比較、影響範囲の洗い出し）の入口が無かった。`debugging` は不具合の原因調査に当たる。
配布はまだしていないので、呼び名とキーの互換は考えなくてよい。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 呼び名を「工程スキル」にする | 設計・調査・テスト・レビュー・リリースは開発の工程の名前で、5本の共通点（標準の工程ごとの入口）が名前に出る。短く、既存の語と衝突しない | 入口スキル（CCNAVI.md の「git の入口」と重なる）、標準スキル（ほかのスキルが非標準に見える）、作業スキル（`commit` も作業で区別がつかない）、領域スキル、フェーズスキル（`phases.yml` と紛れる） |
| SKILL.md の frontmatter のキーを `concept: true` から `process: true` に改める | 呼び名に揃える。ccnavi の中で `process` に別の用法が無い | `stage`（`git add` の stage と紛れる）、`phase`（フェーズ定義と紛れる）、`concept` のまま |
| `investigating` を6本目に足す | 不具合に限らない調べものの入口が無かった。`debugging` は不具合の原因調査に絞り、それ以外の調べものは `investigating` に分ける | `debugging` に混ぜる（description が膨らみ、当たる作業が曖昧になる） |
| 文書 `.ccnavi/docs/skill-concepts.md` を `skill-processes.md` に改める | 呼び名に揃える | 古い名前のまま |

## 得たもの・失ったもの

- 得たもの: 名前から役割が読める。調べものの入口ができる
- 失ったもの: 常駐するスキルの説明文が1本増える（6本）
- 失ったもの: `concept: true` を持つ SKILL.md は、写されなくなる。まだ配っていないので、ワークスペースの5本を `process: true` に直した
- 失ったもの: ADR-0111 の本文は「概念スキル5本」のまま残る。読むときはこの枚で読み替える

## 採らなかった案

- **呼び名だけ変えて、キーは `concept` のままにする。** 呼び名とキーが食い違い、読む人が迷う
