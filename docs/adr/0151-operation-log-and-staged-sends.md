# ADR-0151: ホストへの送信は操作記録に載せ、段階ごとに照合してから送る

状態: 採用

## 状況

decide は、ホストへの返信・issue 作成・コメント投稿を行う。その途中で失敗しても、決めたこと（ローカルへの適用）は戻せない。失敗すると、何を送ったか分からなくなり、打ち直すと二重に投稿するか、送り漏れたまま気づけなかった。

## 決定

- 操作ごとに記録 `logs/state/ops/<32 桁の 16 進>.json` を作る。段階（返信・issue・コメントなど）は `pending`・
  `sent`・`unknown` のどれかで持つ。`sent` は戻さない。記録は prune で消さない
- 本文の末尾に目印 `<!-- ccnavi:op=<操作ID> stage=<段階ID> -->` を足す。前に試した形跡のある段階は、送る前に
  ホストの一覧を目印で照合する。1 件なら送り済み、複数なら止める。0 件は、一覧を最後まで読めて、同じアカウントで、
  作成直後でないときだけ送っていないと確定する。それ以外は `unknown` にして自動では送り直さない
- decide の判断（digest）は版 2。指摘ごとの版を持ち、確認の間に増えた指摘は保留のまま残す。指摘の最初のコメントは
  全文を転記する
- decide は `ccnavi-user-decide.sh --resume <操作ID>` で、保存した選択と記録から続きを送れる
- エージェントの単発の投稿（request・comment・ready・close-early）は、キーから決めた操作IDの記録に載せる
- `ccnavi ops` の書き込み系（begin・stage-set・applied・done）はエージェントから直接打てない。未完了の記録は `status` が出す

- 返信は、スレッドごとに「送る前」「送れた後」を記録の applied に残す。試して結果が分からないスレッドは、
  ホストの最後のコメントが自分のものなら送り済みとみなし、そうでなければ送り直す
- 記録の更新は短いロックで直列にし、同じ操作の単発の投稿は操作IDのロックで直列にする。親を閉じる片付け
  （ready）は、その親の送り終わった記録だけを消す
- MRの作成は記録に載せない。作る前に元ブランチで開いている MR を探すので、打ち直しても同じ MR に行き着く

## 得たもの・失ったもの

得たもの: 失敗しても二重投稿せず、続きを送れる。失ったもの: 返信は照合の対象にしない。確定できない段階は人が
ホストで確かめるまで進まない。

## 採らなかった案

- 本文を記録に保存する: 長く、秘密を含みうる。判断（選択・digest）から作り直す
- 毎回ホストを検索 API で探す: 検索の上限や索引の遅れで、見つからないのに送っていないと誤って確定しうる
