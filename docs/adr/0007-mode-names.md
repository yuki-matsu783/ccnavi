# ADR-0007: モードの名前を `enable` / `dry-run` / `disable` にする

状態: 採用

## 状況

以前のモード名は `off` / `warn` / `block` で、ツール呼び出しがどうなるかを言っていた。
判定に `deny` と `ask` の 2 つが入った時点で、その言い方が破綻した。`ask` で済む回に
「ブロックするモード」と名乗るのは嘘だし、`warn` は「警告する」と読めるが実際にやっているのは
判定の予行でしかない。

## 決定

名前はガードそのものの状態で言う。`enable`（判定を適用する）、`dry-run`（判定して報告するだけ）、
`disable`（判定しない）。指定が無いときは `enable`。旧い名前は受け付けず、未知の値として
報告したうえで `enable` に倒す。

戻す働きの 2 つ（`CCNAVI_RESTORE_IF_DENY` / `CCNAVI_GUARD_CORE_FILES`）も同じ 3 値を取る。
2 値（`enable` / `disable`）なのは `CCNAVI_GUARD_TICKET_APPROVAL` と `CCNAVI_TICKET_CONTROL` の 2 本。
前者は承認が通れば済んでしまい、済んだものは報告では戻らないので「止めずに報告する」段が持てない。
後者は機能を使うかの二択で、予行に意味が無い。

## 理由

読み手が 2 通りある状態を残さないため、旧い名前は受けない。未知の値が `enable` に落ちるのは
緩む側ではない。ただし `dry-run` のつもりだった設定が止めはじめるので、名前を変えるときは
設定の側も一緒に直す。

## 得たもの・失ったもの

- 得たもの: モード名が判定の種類（deny / ask）に依存しない
- 失ったもの: 旧い名前の設定はそのまま `enable` として動きはじめる

## 採らなかった案

- 旧い名前を別名として受ける。同じ状態に 2 つの名前が残る
