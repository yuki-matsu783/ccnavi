# ADR-0045: シェルのコマンドは、実行役のコマンドの中で実行されるコマンドにも止める側のルールだけを当てる

状態: 採用

## 状況

別のコマンドを実行することが仕事のコマンドがある。`env`・`sudo`・`timeout` のように後ろの語を実行するもの、
`sh -c` のように文字列を読み直して実行するもの、`xargs`・`find -exec` のように後ろに書いたコマンドを実行するもの。
ここではこれを**実行役のコマンド**、実行役のコマンドが実行するコマンドを**中で実行されるコマンド**と呼ぶ。

組み込みの守りとサブエージェントの禁止は、コマンドの先頭の語に固定して書かれていた。実行役のコマンドを前に置くだけで
当たらなくなる。振り分けの sh の名前に `.sh` が付くと `sh <sh> --approve --yes` が自然な打ち方になることから調べ始め、
承認の経路だけでなく他の守りにも同じ穴があることを、2026-09-13 に `--test` で確かめた。

| 守り | そのまま | `env`・`sudo -u me`・`timeout 5` など 13 通り | `sh -c`・`xargs` |
|---|---|---|---|
| 設定ファイルへのシェル書き込み（`rm`・`mv`・`tee`・`sed -i`・`cp`・`truncate`） | deny | ask | ask |
| チケットの状態の置き場への移動 | deny | ask | ask |
| 承認の経路（`builtin-guard-ticket-approval`） | deny | ask | ask |
| 利用者の先頭に固定したルール（`curl` を ask にする `prefer-webfetch`） | ask | 当たらない | 当たらない |
| サブエージェントの禁止（`sh .ccnavi/scripts/ccnavi-ticket.sh start`） | 禁止 | `env sh`・`command sh`・`/bin/sh` は通る | 通る |

ask になる形は人に確認されるが、読み切れる形は判定を権限モードに渡す（ADR-0009）ので、モードによっては尋ねずに通る。
サブエージェントの禁止には確認の段が無い。`cd /tmp && …`・`( … )`・`$( … )` は当たっていた。コマンドの切り分けは
効いていて、足りないのは実行役のコマンドの読みだけだった。

## 決定

**読む側（`shellread`）が、1 本のコマンドから中で実行されるコマンドを 1 枚ずつ取り出して並べる。**

| 形 | 中で実行されるコマンド |
|---|---|
| `FOO=1 <cmd>` | `<cmd>` |
| `/bin/sh x`、`git.exe x`（道筋や拡張子が付いた名前） | `sh x`、`git x` |
| `env` `command` `exec` `nohup` `time` `nice` `sudo` `doas` `timeout` `stdbuf` `chrt` `ionice` `taskset` | オプション、値を取るオプションの値、位置引数（`timeout` の時間など）、`--`、`env` の `FOO=1` を飛ばした残り |
| `sh` `bash` `zsh` `dash` `ksh` `<ファイル> <引数>`、`.` / `source` `<ファイル> <引数>` | `<ファイル> <引数>`。引数の先は取り出さない（スクリプトの引数をコマンドと読まない） |
| `sh -c '<文字列>'`（`-lc` などの組み合わせも）、`eval <語…>` | 文字列を読み直したコマンドと、その中で実行されるコマンド |
| `xargs [オプション] <cmd…>` | `<cmd…>` |
| `find … -exec` / `-execdir` / `-ok` / `-okdir` `<cmd…> ;` または `+` | `<cmd…>`（`-exec` が複数ならそれぞれ） |

- 元の形は含めない。途中の層も残す（`env sh .ccnavi/scripts/ccnavi-approve.sh` は、途中の `sh …approve.sh` に承認のルールが当たる）
- 深さは 4 まで（元の形は数えない）。1 回の読みで作る層は 2000 語まで
- `command -v` / `-V` と `sh -s` からは取り出さない
- 読み切れない形（`degraded`）でも、語に割れる限り取り出す。閉じない引用と閉じないヒアドキュメントでは取り出さない。
  `degraded` とその理由はそのまま残す
- 実行役のコマンドと値を取るオプションの一覧は、`shellread` の組み込みに持つ。`rules.yml` からは足せない

**当てる先を、止める側に限る。**

| 当てる先 | 元の形 | 中で実行されるコマンド |
|---|---|---|
| deny（組み込み・利用者） | 当てる | 当てる |
| ask（組み込み・利用者） | 当てる | 当てる |
| allow（利用者） | 読み切れたときだけ当てる（ADR-0011） | 当てない |
| サブエージェントの禁止 | 当てる | 当てる |
| ゲートの中で通す形 | 読み切れたときだけ当てる | 当てない |
| チケットの範囲 | 名指しのツールの行き先だけを見る | 当てない |

ルールの照合（`Rule.matches`）は変えない。判定が、タイプごとに当てる文字列の並びを変える。承認のルールの正規表現も
変えない。PowerShell は `shellread` で読まないので変わらない。

**当たったことを、記録と文面に残す。**

- 記録（`log.jsonl`）と `--test` の JSON に欄 `unwrapped` を足し、ルールに当たった中で実行されるコマンドだけを残す
  （取り出した層の全部ではない）。元の形で当たったときは空。`--test` の JSON の版は 1 のまま（知らない欄は読み飛ばされる）
- 拒否と確認の文面、サブエージェントの禁止の文面に「`<実行役のコマンド>` が実行する `<中で実行されるコマンド>` に当たりました。」を
  1 行足す（例:「`env` が実行する `rm -f .ccnavi/common/rules.yml` に当たりました。」）
- 中で実行されるコマンドで当たった理由には、「読み切れなかったので生の文字列に当てた」断りを付けない
- 拒否で、当たったルールがすべて中で実行されるコマンドで当たったなら、元の形が読み切れていなくても理由コードを
  `PARSE_UNCERTAIN` にせず `DENY_COMMAND_PATTERN` にする。1 件でも元の読み切れない形で当たっていれば `PARSE_UNCERTAIN` のまま。
  例外は承認のルール（`builtin-guard-ticket-approval`）で、当たった件に入っていれば、どう当たったか・読み切れたかに依らず
  `DENY_TICKET_APPROVAL_CLI` を優先する（この決定より前からの扱いで、変えない）。元の形が読み切れないまま承認のルールに
  当たったときも、読み切れなかった断りは付く。判定（deny / ask）はどちらでも変わらない

## 理由

穴はルールの書き方ではなく、読む側の不足だった。ルールごとに実行役のコマンドを書かせると、組み込みの守りも
利用者のルールもサブエージェントの禁止も、同じ穴を 1 本ずつ塞ぐことになる。読む側で取り出せば、ルールを書く人は
実行役のコマンドを意識しなくてよい。

**止める側にだけ足すのは、読み違いを緩む向きに効かせないため。** 中で実行されるコマンドは、元の形の判定を消さずに
当て先を足すだけなので、層を読み違えても、当たるはずのものが当たらないだけで今より緩くはならない。許す側に当てると
逆になる。

- allow: `sudo -u me cat /etc/shadow` は元の形では確認になるが、中の `cat …` が読み取りの allow に当たって通るようになる
- ゲートの中で通す形: `env sh .ccnavi/scripts/ccnavi-review.sh …` が、ゲートの中で通るようになる
- チケットの範囲: 範囲の中は allow になる。そもそも名指しのツールの行き先で決まり、シェルのコマンドを見ない

**一覧を組み込みに持つのは、守りの根拠を守られる側に置かないため**（ADR-0021 と同じ向き）。`rules.yml` から足せるなら、
消すこともできる。

**記録と文面に残すのは、元の形だけを見た読み手には、どこが当たったのかが分からないため。** ルールは `rm` について書かれて
いて、`env` については何も言っていない。記録の欄を当たった層だけにするのは、どの層が判定を下したかを探さずに読めるようにするため。
欄があれば、実行役のコマンドを通して当たった件数も数えられる。

**コードを `PARSE_UNCERTAIN` にしないのは、REQ-HNT-04 の区別を保つため。** そのコードと断りは「読めない文字列のどこかに
その語がある」を意味し、読み手に「本文をファイルへ逃がす」を促す。中で実行されるコマンドで当たったときは、ルールは読み直した
コマンドに当たっていて、生の文字列には当てていない。断りを出すと、実際に実行されるコマンドを止められた読み手に、書いた覚えの
ない文字列を探させることになる。

承認の経路は、承認のルールだけに実行役のコマンドの並びを持たせる案（下の B）を一度採ったが、同じ穴が他の守りにも
あると分かり、この仕組みで一緒に塞ぐことにした。

## 得たもの・失ったもの

- 得たもの: 組み込みの守り・利用者のルール・サブエージェントの禁止が、実行役のコマンドを通しても同じ判断になる。試作で
  止めたい 20 形（`env rm -f …rules.yml`、`sudo -u me sh -c '<sh> --approve --yes …'`、`find … -exec <sh> … ;`、
  `env curl …`、`env sh …ccnavi-ticket.sh start` など）がすべて止まった
- 得たもの: 承認のルールだけの案で残っていた `sudo -u me sh -c '…'` と `find -exec` も止まる
- 失ったもの: 一覧に無い実行役のコマンド（`script -c`、`watch`、`parallel`、`busybox sh`、`ssh host <cmd>`、`perl -e`、`python -c`）は
  取り出さない。先頭に固定したルールは今までどおり外れる。一覧に足すには ccnavi を組み立て直す
- 失ったもの: 一覧に無い、値を取るオプションは値をコマンドと読み、層がずれる。ずれた層は当たらないだけで、緩くはならない
- 失ったもの: 変数の値・alias・関数には届かない。`shellread` の既知の限界のまま（コマンド名に変数を置いた
  `$SUDO rm …` は、ADR-0047 で止めるようにした）
- 失ったもの: 実行役のコマンドの後ろに書いた、利用者の deny や ask に当たるコマンドが止まるようになる。普通の作業 27 形
  （`time uv run pytest`、`timeout 60 pnpm test`、`bash -lc 'uv run ruff check .'`、`. .venv/bin/activate && uv run pytest` など）では
  新しく当たったものは 0 だったが、今まで通っていた形が止まりうる。その deny はもともとそのコマンドを止めるために書かれたもの
- 失ったもの: 当てる文字列が増え、判定の期限に効く。深さ 4 と語数 2000 で抑える
- 失ったもの: 記録と `--test` の JSON の欄が 1 つ、文面の行が 1 つ増える
- 失ったもの: 読み切れない形で中で実行されるコマンドに当たった拒否が `PARSE_UNCERTAIN` に数えられなくなり、そのコードの
  件数で数える集計とずれる

## 採らなかった案

| 案 | 止めたい 25 形 | 止めすぎ 7 形 | 落とした理由 |
|---|---|---|---|
| 承認のルールの正規表現に `((sh\|bash)\s+)?` を足す | 一部 | 0 | `/bin/sh`・`env`・`command`・`exec`・`zsh`・`sh -c`・`source` などが残る |
| A: 同じコマンドの中なら語の位置を問わずに当てる | 25 | 7 | 引用しない `echo ccnavi --approve --yes x`、`git log --grep ccnavi --yes` などを止める |
| B: 承認のルールだけに実行役のコマンドの並びと引用を持たせる | 23 | 0 | 同じ穴が組み込みの守り・利用者のルール・サブエージェントの禁止に残る。`sudo -u me sh -c '…'` と `find -exec` も残る |
| **中で実行されるコマンドに、止める側のルールを当てる（採った）** | 25 | 0 | — |

- 中で実行されるコマンドを allow とゲートの中で通す形にも当てる。上の「理由」のとおり、読み違いが緩む向きに効く
- 実行役のコマンドの一覧を `rules.yml` から足せるようにする。利用者が足せるが、消すこともできる
- 当たったことを記録と文面に残さない。文面は短くなるが、`env rm …` がなぜ止まったのか読み手に分からない
- 記録に取り出した層を全部残す。どの層が当たったのかを読み手が探すことになる
- 読み切れない形で当たった拒否のコードを `PARSE_UNCERTAIN` のままにする。集計はずれないが、読み直したコマンドに当たった拒否に
  「読めない文字列に当てた」断りが付く
