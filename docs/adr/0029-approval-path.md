# ADR-0029: チケットの承認の経路を守る

状態: 採用

## 状況

実行ファイルを各プロジェクトに配って使う前提で、サブエージェントによる敵対的なレビューを
2 本走らせ、通ったものを直した。いちばん大きい穴は、スクリプト 2 本の中身が実行ファイルの
呼び出しなので、スクリプトを経由せずに打てば全部の門が開くことだった。

## 決定

| 直したこと | 理由 |
|---|---|
| `CCNAVI_GUARD_TICKET_APPROVAL`（既定 enable）。シェルから実行ファイルを `--approve` / `--reviewed` / `ticket …` / `review …` 付きで打つ形を止め、`--approve` と `--reviewed` は標準入力が端末であることを求める | 環境変数で切れるのは、テストと端末を持たない配管のため。`dry-run` は取らない（ADR-0007） |
| 親の `done` / `cancel` は、開いている子か閉じたゲートがある間は拒む | 親の承認済みチケットが閉じるとゲートの鍵（cwd から引く親）が消え、レビュー待ちのまま誰も止めなくなった |
| `check` は依頼時の HEAD と同じで push 済みであることを求める。`since` はホストの時計 | 依頼の後に積んだコミットが「レビュー済み」に含まれた。手元の時計だと、依頼直後の指摘が依頼より前に落ちて黙って除かれた |
| GitHub のレビューはレビュアーごとに最新だけ。取り下げ（dismissed）は無い扱い。REST も GraphQL もページを最後まで読み、読み切れなければ拒む | 過去の全レビューを返すので、後で approve しても古い変更要求が残った。100 件で切れると 101 件目の未解決が見えなかった |
| GitLab の変更要求は `/reviewers` の `requested_changes` | 「GitLab に変更要求は無い」は誤り。ただし CE には無く EE 限定 |
| 子のブランチは作業ツリーではなくブランチ名で引く。引けなければ前提の未充足 | 作業ツリーを消すと検査から外れた |
| `request` の未コミット検査は未追跡を数えない。`--body-file` の相対は `--cwd` から | 依頼文そのものを作業ツリーに置くと前提を落とした |
| 状態の置き場と例外・禁止の形は PowerShell にも当てる。ゲートの例外は読み切れないコマンドに与えない。状態ディレクトリは綴りまで同じものだけ読む | Windows で `DONE/` が `done/` として開け、PowerShell はシェルとして扱われていなかった |
| サブエージェントが差し戻しを無視して終わったことを、PostToolUse(Agent) で親に言う | 差し戻しは 1 回きりなので、2 度目の終了は黙って通っていた |
| 束の承認の鍵は最も重い親の識別子。子の画面の親は同じ束から引く | 識別子順の先頭にすると軽い親の識別子で重い親まで通った |
| `--lint` が、超えている子・深さ・ホストに合うトークン・SubagentStart/Stop の登録・スクリプトの有無・`CCNAVI_GUARD_TICKET_APPROVAL=disable` を言う | 承認の場で初めて知るより早く |

旧名 `CCNAVI_GUARD_CLI` は `CCNAVI_GUARD_TICKET_APPROVAL` に改めた。守る手段（CLI から打つ形）
ではなく、守る対象（チケットの承認の経路）で名乗る。旧名はもう効かず、`--lint` が言う。
旧名で `disable` と書いてあった設定は、読まれなくなった時点で既定の `enable` に戻る。

## 得たもの・失ったもの

- 得たもの: 人の合意を出せる場所が端末の 1 種類に寄る
- 失ったもの: テストや端末を持たない配管は `CCNAVI_GUARD_TICKET_APPROVAL=disable` で切る。
  切っていることは `--lint` が warn で言う
