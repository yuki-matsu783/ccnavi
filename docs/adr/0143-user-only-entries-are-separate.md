# ADR-0143: ユーザ専用の入口を、エージェントも使う入口から分離する

状態: 採用（2026-10-18 に実装）

## 状況

ユーザだけが打つ操作（承認・レビュー済みの記録・早めに閉じる・記録の削除・テンプレートの取り込み・親を閉じたあとの
片付けなど）は、エージェントも使う入口と同じ実行ファイル・同じ sh に同居している。同じオプションで、エージェントに
許す形と許さない形が分かれている（`--agree` は止め、`--agree --preview` は通す。`ccnavi-review.sh decide <N>` は
`--preview` なら通し、`--choices` なら止める。`ccnavi-review.sh` は `decide --choices` だけ止める、など）。

そのため hook はオプションの綴り・並び・組み合わせを読む。免除の `--preview` を単独の語として読む後読み、
ボードの経路のオプションの組み合わせ、引数を変数や glob で組み立てて隠す形の判定があり、抜け道が見つかるたびに
足されてきた。ユーザ専用の定義も、hook の正規表現、オプションの一覧、実行ファイルのターミナル要求の呼び出し、拒否文、
各 sh のヘルプに散らばっている。

この ADR は、一度書いた案に 2 人の敵対的レビューを受け、書き直したもの。最初の案は
「hook は入口の名前だけで止める」としていたが、現行の止めのうち、ターミナルを求めない操作を名前に依らず止める文字列検査と、
ターミナル要求を切る形の検査が消えて、止まっている形が止まらなくなると分かった。この版は、それらを残す。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 実行ファイルの、ユーザだけが打つ操作は `ccnavi user <操作>` に集める。対象は `agree`・`reviewed`・`close-early`・`prune`・`handoff`（保護対象の下書きの取り込み。ADR-0144） | 入口の綴りを 1 つに揃えれば、hook も実行ファイルも「`user` かどうか」で決められる | 操作ごとに別の入口を作る |
| `user` は、`--root`・`--cwd`・`--record-writes`・`--record-tree`（ラッパーが先に付ける、値を取るオプション。表の `WRAPPER_OPTIONS`）を読み飛ばした後の最初の語。ASCII の大文字小文字は区別しない（`casefold` は使わない。`uſer`・`handoﬀ` のように互換の読みで入口の語になる ASCII でない綴りは断る）。先頭の `--` は読み飛ばさず、実行ファイルは名前空間として扱わない（hook は `--` を挟んだ形も止める） | sh と拡張は、実行ファイルを呼ぶときに必ずこれらを先頭に付ける。`user` を絶対の先頭にすると、呼び出し側の全部を作り替えることになる。オプションの一覧は実行ファイルの読み飛ばしと hook の正規表現の両方が表から作るので、食い違わない | `user` を `argv[0]` に限る。`user` をコマンド行のどこでも探す（`--keyword user` まで止まる） |
| 実行ファイルは、argparse の前に `user <操作> …` を、今の内部の形（`user agree` → `--agree`、`user reviewed <N>` → `--reviewed <N>`、`user handoff <パス>` → `--handoff <パス>` など）に書き換える。「ユーザの入口から来た」という事実は argparse の結果（`args`）には入れず、別の変数で持つ | 内部の文法を変えないので、識別子を並べる位置・`--yes` の値・`--json` など、今動いている引数の読みが変わらない。`args` に入れないので、`--user-entry` のようなオプションで偽装できない | argparse に `user` のサブコマンドを足す（位置引数の塊を 1 つしか取れず、`--agree --yes a,b --digest d --json only1` の形が壊れる） |
| `user` の外でユーザ専用のオプションが読まれたら、実行ファイルは何も動かさず終了コード 2 で断り、`user` の形を案内する。見るだけの形は断らない: `--agree --preview [--verify]`、`--prune --preview`、`--reviewed … --preview`（`ccnavi-review.sh decide <N> --preview` が内部で呼ぶ）、`--yes` の付かない `--delete-draft` | 古い形でも動く入口を残すと、定義が二重になる。見るだけの形はエージェントが使い、動かす形と同じ関数を呼ぶので、実装は 1 つ。断る判定は argparse の読んだ結果で行う（argv の文字列を探すと、`--keyword=--agree` のような値まで断る） | 見るだけの形も `user` に入れてエージェントに使わせない |
| 実行ファイルを通さず sh から呼ぶだけの操作は、`user` に入れず、`sh-only` として表に残す: `ticket start/finish/cancel/record-risk/prepare/requested/confirm/ready`、`review confirm`（`--result` に偽の JSON を渡せるので、ユーザか sh が渡す）、`sync tidy`、`worktree retire/branch`。実行ファイルを直に呼ぶ形は今までどおり hook が止める | これらは sh の中から呼ばれる。ユーザ専用の入口に入れると、sh が `user` を呼ぶことになる | `user` に移す |
| hook の止めは、すべて表から作る。手書きの正規表現を持たない。種類は次の 5 つ。(1) `user` の入口（上の位置の規則で、変数・glob・コマンド置換で `user` になりうる語も止める）。(2) `ccnavi-user-*.sh`（コマンド行のどこに名前が出ても止める。表示・検索・閲覧の道具だけが並ぶ行は通す）。(3) 古い形（古いオプション・古い sh 名・古い sh の中のユーザ専用のモード。表の `legacy`）。(4) 名前に依らない文字列の検査。ターミナルを求めない操作（`user agree/reviewed/handoff/templates` と `--yes` の組み合わせ、`--choices` と `--digest`、`user` を伴わない単独の `--via board` / `--via=board`、古い形、`user` の語と展開（`$`・バッククォート）を含む `--` の語が並ぶ形）と、ターミナル要求を切る形（`CCNAVI_GUARD_TICKET_APPROVAL`・`CCNAVI_` で始まる名前に展開が混じる代入・`--guard-ticket-approval`）。(5) `sh-only` の操作の直打ち。実行ファイルを Python から走らせる表記は、インタプリタの選択肢（`-u`・`-I`・`-W x`・`-Xutf8` など）・`-m ccnavi.__main__`・`main.py`・`py`・`uv run`・`poetry run`・`pipenv run` を読む | `--yes` を使う経路はターミナルを求めず、hook の文字列検査が唯一の防御。ここは名前を変えたコピー・`python -c`・`awk` の `system()` でも止まっていて、入口の名前だけにすると止まらなくなる。(3) は、古い実行ファイル・古い sh が手元に残るときのため | 入口の名前だけで止める |
| 表の `Op` に、操作の種類（`user`・`sh-only`・`read`）、止める設定（`approval`: チケット制御と承認の止めの設定に従う。`prune`: コアのファイルの保護に従う）、ターミナルを求めるときに表示するオプション名を持たせる | `prune` はチケット制御を切ったワークスペースでも止まる。今の動作を保つ | 一律に承認の設定で止める |
| ユーザ専用の sh は `ccnavi-user-<操作>.sh` に分ける: `agree`・`push-approved`・`close-early`（`ccnavi-review.sh close-early`）・`decide`（`ccnavi-review.sh decide` の書く側）・`clean-branch`（`ccnavi-clean.sh --branch`）。もとの sh からそれらを外す。`decide <N> --preview`（見るだけ）は `ccnavi-review.sh` に残す。書く処理（返信・解決・マーカーを置く呼び出し）は `ccnavi-user-*.sh` の中だけに置き、共通のファイルには読む側と、エージェントも使うホスト API の関数だけを置く | 共通のファイルに書く処理の関数を置くと、`sh -c '. …common….sh; 関数'` で名前の一致を外して呼べる | 混在した sh の中で引数を読む |
| 互換: 互換の版（COMPAT）を上げ、古い sh が新しい実行ファイルの断りにヒットしたときは、sh の再配布を案内する。setup は、配る sh を置き換え、`legacy` の古い名前の sh を消す。VS Code・Chrome の拡張は、`--version --json` の機能名（`user-entry`）で確かめ、拡張の互換の版を上げる | 古い sh が残ると、片付け（`worktree retire`）が黙って止まる。古い拡張が新しい実行ファイルを呼ぶと断られる | 互換の版を上げない |
| 実行ファイルのターミナル要求（`_from_terminal`）は残す。ただし、ターミナルを求めない経路（`--yes` の承認、ボードの指摘の対応方針、テンプレートの取り込み）では、hook の文字列検査（4）が唯一の防御で、ターミナル要求は 2 段目ではない | 擬似ターミナル（`script -qc`）を使えば、ターミナル要求は通ってしまう。この穴は今もあり、この ADR では直さない | ターミナル要求だけに頼る |
| ユーザ専用の定義は `tickets/user_only.py` の表を正本にする。hook の正規表現、実行ファイルの書き換えと断り、拒否文の入口の一覧、setup が消す古い名前は、この表から作る。表と各 sh・docs・拡張の食い違いはテストで検出する | 操作を足すとき、直す場所を 1 か所にする | 各所に正規表現を書く |
| `ccnavi user --help` は hook が止める。使い方は `ccnavi --docs` で引く | `user` の入口は、エージェントには打たせない | |

## 得たもの・失ったもの

- 得たもの: ユーザ専用の定義が表 1 つになり、hook・実行ファイル・拒否文・setup がそこから作られる。実行ファイルは `user` の外の古い形を断るので、古い形を別名として残さない。sh の混在がなくなり、ユーザ専用の sh は名前で見分けられる
- 失ったもの: **hook は入口の名前だけでは止められない。** ターミナルを求めない経路のために、名前に依らない文字列検査（4）を残す。「オプションの組み合わせと免除の判定が要らなくなる」という当初の利点は、古い形（3）が残るあいだは得られない。古い形の行は、互換の版の下限を上げたあとの版で消す
- 失ったもの: **コマンドの形が変わる。** 承認・レビュー済み・早めに閉じる・片付けなどを打つ手順、拡張、docs、テストが変わる。更新量は、`--agree` を含む tests と extensions が約 45 ファイル、`ccnavi-push-approved` が約 19 ファイル、`close-early` が約 14 ファイル、docs が約 45 ファイル
- 失ったもの: 擬似ターミナルを作る実行役（`script`・`tmux`・`screen`・`expect`）越しの呼び出しは、これまでどおり hook が読めない
- 失ったもの: 展開を含む `--` の語の検査（4）は、入口を読めない形のための暫定の止めで、`user` の語がある行の `--author=$(…)` のような無関係の語も止める。逆に、`--` で始まらない語（`$X` だけ）で `--yes` を組み立てる形と、`user` の語そのものを組み立てて入口の表記からも外す形は、この検査では止まらない
- 失ったもの: `ccnavi user --help` をエージェントが打てない

## 採らなかった案

- ユーザ専用だけを別の実行ファイル（`ccnavi-user`）にする: ビルド・配布・導入 sh・拡張が 2 本になり、影響が最も広い
- sh だけを分離して、実行ファイルのオプションは残す: オプションの定義が hook と実行ファイルに二重に残る
- 入口の名前だけで止める（この ADR の最初の案）: レビューで退行が見つかった。上の「失ったもの」を参照

## 他の ADR との関係

- ADR-0122（引数を読み切れない形を止める）の対象のうち、実行ファイルの承認の経路は、`user` の入口の判定（変数・glob・コマンド置換で `user` になりうる語を止める）に引き継ぐ。スクリプトの `decide --choices` の判定は、古い形が残るあいだは残る
- ADR-0080（ターミナル要求を切る形を止める）は、そのまま残す

## 実装の段階

1. 表（操作の種類・止める設定・古い形・ラッパーのオプション）、実行ファイルの `user` の書き換えと断り、hook の生成。古い形の止めは残す
2. テストの移行（古い形を `user` の形に）
3. sh の分離、setup、互換の版
4. VS Code・Chrome の拡張
5. docs・README・`.ccnavi/docs/`
