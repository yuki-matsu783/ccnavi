# ADR-0013: ヒアドキュメントを既定のルールで止める

状態: 採用

## 状況

ヒアドキュメントの本文は実行位置として数えない（本文に禁止語を書いただけでは止まらない）。
それと、ヒアドキュメントを使わせるかどうかは別の話。ヒアドキュメントで書いたファイルは、
`permissions` の宣言も `PostToolUse` に登録した検査も通らない。ファイルの中身を落とす経路が
そこだけ素通しになっていた。

## 決定

このリポジトリの既定のルールは、`<<` を含む Bash 呼び出しを止める。代わりは `Write` / `Edit`
ツール。プログラムに読ませる入力も、`Write` でスクリプトをファイルに置いてから渡す。
算術式の `$((1 << 2))` は左シフトであってヒアドキュメントではないので、読む前に落としてある。

## 理由

ファイルへ書き出す形だけを止める案もあったが、プログラムへ渡す形（`uv run python - <<'PY'`）も
`Write` でスクリプトを置けば代わりが効くので、全部止めるほうにした。実装がルール 1 行で済み、
抜け道も少ない。記録では Bash 883 件中 42 件が該当で、内訳はファイルへ 17 件、
プログラムへ 25 件だった。

## 得たもの・失ったもの

- 得たもの: 権限の宣言と検査を通らない書き込み経路が閉じる
- 失ったもの: `grep -n "<<" README.md` は止まる。引用された `<<` と素の `<<` を `shlex` が
  区別しないため（ADR-0011）。止まる側に倒れること、文面が「読めなかったので文字列に当てた」と
  名乗って本来の禁止と混ざらないこと、対象をファイルへ逃がせば回避できることの 3 つが
  揃っているので許容する

## 採らなかった案

- ファイルへ書き出す形（`<<EOF > file`）だけを止める。プログラムへ渡す形にも代わりがあるので
  区別する意味が無く、区別するぶん抜け道が増える
