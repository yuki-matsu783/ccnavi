CCNAVI / IDEA

ccnavi の思想

なぜ作るか、何を作るか、どう実現するか

エージェントに任せる範囲を広げながら、人間の判断と目が届く道を失わせない。

アプリの根底にある考え方。ユーザが依頼しない限り変えない。正の文書は docs/00_idea.md。

WHY 1 / 課題

エージェントは、目的のために制約を突破しうる

悪意はない。「hook が邪魔なので外す」「deny が厳しいので緩める」を、目的を達しようとして普通に選ぶ。

任せる範囲を広げるほど、人間が一手ずつ見ることはできなくなる。

WHY 2 / 既存の防ぎ方の穴

既存の防ぎ方には 4 つの穴がある

構造を見ないパターン一致は連鎖・サブシェル・リダイレクトを見ず、複合コマンドの後段が素通りする
確率でしかないプロンプトの禁止は、守られる確率を上げるだけで 0 にはならない
二択になる静的な権限は、広く開けるか毎回確認するか。前者は守れず、後者は承認が形骸化する
根拠を書き換えられる拒否の根拠が、エージェントの書き換えられる作業ツリーの中にある
WHY 3 / 解きたいこと

守る対象はプロジェクトが決め、あとは合意に委ねる

逸れたときは、人間の目に触れさせる。
  • エージェントは、止められても、代わりに何をすればよいか分かり、自力で進められる
  • 人間は承認・レビュー・採否という判断に集中できる。その判断は代行されない
  • 記録が残り、同じ失敗を繰り返さないよう、決まりと手順が育つ
WHAT 1 / 何を作るか

Claude Code の開発を支える 4 つのコア機能

1ガードとガイドルールで判定し、止める・確認する・伝える。拒否には代わりの手段を添える
2チケットとレビュー目的・範囲・計画を合意し、承認からレビューまで進める
3検索と必要時の参照文書と手順は全部は渡さず、目録で絞り、必要なときに読ませる
4記録と振り返り記録から改善候補を出し、人間が採ったものを次に活かす

記録・dry-run・診断・ワークツリー・拡張などは、この 4 つを支える仕組みと入口である。

WHAT 2 / 作らないもの

ccnavi がやらないこと

OS 権限分離の代わり同じ権限で任意のシェルを動かせる相手には境界にならない。逸れるエージェントと事故への柵である
人間の判断の代行承認・レビュー済み・採否を、エージェントが出せる形は作らない
モデルの学習改善するのはルール・手順・文書・計画の側
守られる保証そうなるよう設計するが、保証はしない
HOW 1 / 3 つの原則

製品として共通する 3 つの原則

1必要な情報を、必要なタイミングで開始時は前提と入口だけ。理由と手順は場面で、詳しい資料は引いて読む。先に詰め込まない
2人間の判断を残し、守る承認・レビュー・採否とガード自身の変更を、エージェントが代行できる形にしない
3単一の場所に閉じ込めないチケットはブランチに載せ、レビューはホスト上で。対話も自動実行も同じ道で扱う
HOW 2 / 考え方

原則を支える考え方

判定はモデルの外でhook の処理がコンテキストの外で判定する。エージェントの自発的な遵守に頼らない
拒否は誘導と一緒に止めるだけでは打ち直される。理由と代わりの手段を名指しで返す
失敗の向きは非対称誤検知は一手止まるだけ、素通りは気づけない。迷ったら止める。ただし回復手段は奪わない
制約は緩められないチケットは絞る向きにだけ働く
逸脱は必ず見せる委ねた回も既定に落ちた回も記録に残す
親は清潔に、育てる親は判断と報告、作業は子へ。記録から改善候補を出し、採否は人間が決める
