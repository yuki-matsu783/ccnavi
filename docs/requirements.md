# ccnavi 要件書

## 0. 位置付け

ccnavi は、Claude Code を使った開発を、ルール・チケット・必要時の情報参照・振り返りで支えるツールである。
次の 4 つをコア機能とし、要求の各面（2 章）はそのどれかを支える。

| コア機能 | 内容 | 主な面 |
|---|---|---|
| ルールによる作業のガードとガイド | ツール実行とファイル操作をルールに照らして判定し、止める・確認する・注意点を伝える。拒否には代わりの手段を添える。判定は hook の処理がモデルのコンテキストの外で行い、関係する場面で理由・注意点・手順を届ける | REQ-PRE・REQ-HNT・REQ-RUL・REQ-PST・REQ-SLF・REQ-SES |
| チケットによる作業・レビュー管理 | 作業の目的・範囲・計画を承認、フェーズ、先行、分担、レビュー、指摘への対応で、合意した作業をレビューまで進める。リスク評価と計画テンプレートの利用を含む。複数人・別 PC・別セッションでの作業とレビューを想定する | REQ-APV・REQ-RSK・REQ-TKT・REQ-MLT・REQ-EXT |
| ドキュメント・スキルの検索と必要時の参照 | 文書とスキルの本文は最初から渡さず、frontmatter の索引と目録で読む対象を絞り、本文は必要なときに読む | REQ-SES-06（開始時に引き方を示す）。検索そのもの（`ccnavi --docs`）には個別の REQ が無く、挙動は [利用者向けの手引き](guide/docs-search.md)と設計に書く |
| 記録と振り返りによるルール・作業手順の改善 | 判定ログ・気づき・振り返りから改善候補を見つけて提案し、人間が採ったものを次に活かす。AI モデル自体の学習ではない | REQ-LRN（一部実装済み）。判定ログからの候補生成（`--suggest`）には個別の REQ が無く、[手引き](guide/records.md)に書く |

コア機能に共通する原則が 3 つある。必要な情報を必要なタイミングで届ける（開始時には作業の前提と入口だけを渡し、具体的な案内は関係する場面で、詳しい資料は必要なときに引く）。
人間の判断を残し、その経路を守る（承認・レビュー・改善の採否をエージェントが代行できる形を作らない）。
作業とレビューを単一 PC・単一セッションに閉じ込めない（親のブランチに載るチケットとマーカー、ホスト上のレビューでつなぐ。同期は操作の時点で行う。2.11、4 章）。

判定の記録、dry-run、診断、設定の検証、保護領域の変更検知と復元、ガード自身の保護、リスク評価、ワークツリー、リモート経由の共有、フェーズ・フロー・計画テンプレート、VS Code と Chrome の拡張、
複数のリポジトリは、4 つを支える仕組み・操作の入口・利用範囲であり、5 つ目以降のコア機能ではない。

### 0.1 想定する使い方（大前提）

ccnavi は、次の 2 つの使い方のどちらでも動くことを大前提にする。同じプロジェクトを 2 つの使い方で使う人が混ざっていても動く。

| | 使い方 A: ワークスペースを用意する | 使い方 B: clone 済みのディレクトリで起動する |
|---|---|---|
| 準備 | エージェントが動くための専用のディレクトリ（ワークスペース）を用意し、導入スクリプトで実行ファイル・sh・設定を置く。プロジェクトは `projects/` の下に clone する | プロジェクトを clone したディレクトリをそのまま使う。ワークスペースは無い |
| Claude Code を起動する場所 | ワークスペースのルート | プロジェクトのディレクトリ |
| 作業するプロジェクト | ユーザの依頼をもとにエージェントが考えて選び、その `projects/<名前>` の中で作業する | 起動したディレクトリのプロジェクト |
| 共通の設定 | ワークスペースの共通レイヤー | プロジェクトにあるミラー（共通レイヤーのコピー） |

- どちらの使い方でも、判定は共通レイヤーと 1 つのレイヤー（プロジェクトの作業ならプロジェクトのレイヤー、ワークスペース自身の作業ならワークスペース自身のレイヤー）の和で決まる（REQ-MLT-41・REQ-MLT-42）
- 共通レイヤーはワークスペースの git にあり、使い方 B の人には見えない。そこで、プロジェクト向けの親チケットに着手するとき、共通レイヤーのコピーをプロジェクトの `.ccnavi/config/common/` に置き、プロジェクトの git で運ぶ（REQ-MLT-34）。コピーが無くても、ccnavi は動く（REQ-MLT-40）
- 使い方 B で起動したときは、そのプロジェクトの hook と設定が使われ、ワークスペースの hook は動かない

実行ファイルの置き方は、使い方 A・B とは別の軸で、どちらの使い方とも組み合わせられる。

| 置き方 | 内容 |
|---|---|
| ツリーの `bin/` に置く | 導入スクリプトが、起動するツリー（A ならワークスペース、B ならプロジェクト）の `.ccnavi/bin/<os>-<arch>/` に配る（`--bin project`。既定）。機械ごとに合うものが選ばれる |
| 環境の PATH に登録する | ツリーには置かず、PATH に登録した実行ファイルを使う。導入スクリプトの `--bin user` で、ユーザのホームディレクトリの下（`~/.local/`）に置ける。PATH への足し方は、環境（Windows の環境変数、シェルの設定ファイル）に合わせて案内する。ホームディレクトリに書き込むので、ターミナルで内容を確かめる |

両方あるときは、ツリーの `bin/` に合うものがあればそれを使い、無いときだけ PATH のものを使う。

## 1. 背景

Claude Code のエージェントは、作業に必要だと判断すると、禁止された操作をどうにか突破して実行しようとする。
「hook が邪魔なので外す」「deny が厳しいので緩める」も、目的を達成しようとするエージェントが普通に選ぶ手である。

既存の防ぎ方には 4 つの穴がある。

- 設定ファイルのパターン一致はコマンドの構造（連鎖・サブシェル・リダイレクト）を見ないため、複合コマンドの後段が素通りする
- プロンプトに書いた禁止は確率を下げるだけで 0 にはならない
- 権限を静的に固定すると、作業ごとに必要な範囲が違うため、広く開けるか毎回確認するかの二択になる。広く開ければ守れず、毎回確認すれば承認が形骸化する
- 拒否の根拠がすべてワークツリーの中にあり、エージェントが書き換えられる。設定の変更は次のツール呼び出しから反映される

ccnavi は「守る対象はプロジェクトが列挙し、それ以外は作業チケットに委譲する」という
分担を成り立たせ、委譲した先の逸脱を人間の目に触れさせることで、この二択を崩す。

失敗の向きは非対称である。誤検知はエージェントが一手止まるだけで、理由が返れば書き直せる。
素通りは強制の仕組み自体を無意味にし、しかも気づけない。判断がつかないときは拒否にする。
ただし、設定 1 つの破損で回復手段まで奪う形は作らない。

拒否するだけではエージェントは止まらない。`git push` を禁じられたエージェントは、絶対パスで同じコマンドを打ち直す。
そこで、拒否と同時に、止めた理由と代わりに何をすればよいかを名指しで返す。

## 2. 外部要求

ccnavi は Claude Code の hook から呼ばれる。1 回の呼び出しは、標準入力で
受け取った JSON を読み、標準出力に応答を返して終わる。実行ファイルは 1 本で、
複数のイベントに同じコマンドとして登録する。

外から縛るのは、期限までに応答が返ること、ガードが知らせずに消えないこと、
直した設定が次の呼び出しから反映されること、試験の判定が実運用と一致することである。構成の取り方は問わない。

要求の「型」は、その要求がいつ適用されるかを表す。常時（いつでも成り立つ）、事象（あることが起きたとき）、
状態（ある状態である間）、異常時（望ましくないことが起きたなら）、任意（その機能を使う場合）の 5 つがある。

以下の面は、呼ばれ方によって分かれている。

| 面 | 呼ばれ方 |
|---|---|
| 起動と登録 (REQ-HKS) | すべてのイベントに共通 |
| 共通の動作 (REQ-CMN) | すべてのイベントに共通 |
| ルールの注入 (REQ-RUL) | すべてのイベントに共通 |
| ツール実行前チェック (REQ-PRE) | ツール実行前のイベント |
| 返す文面 (REQ-HNT) | ツール実行前・実行後のイベント |
| ツール実行後チェック (REQ-PST) | ツール実行後、およびターンの始まりと終わりのイベント |
| 設定ファイルの自己防衛 (REQ-SLF) | ツール実行前・実行後、およびセッション開始のイベント |
| セッション開始時の提示 (REQ-SES) | セッション開始のイベント |
| チケットの承認 (REQ-APV) | セッション開始のイベント、およびユーザが直接起動したとき |
| 実績で測るリスク (REQ-RSK) | ユーザが直接起動したとき（子を閉じるとき）、およびツール実行後のイベント |
| 診断コマンド (REQ-DIA) | ユーザが直接起動したときのみ |
| 学びの蓄積 (REQ-LRN) | ユーザが直接起動したとき（子を閉じるとき・親を閉じるとき・診断）、およびサブエージェントの開始のイベント |
| 並行するチケット (REQ-TKT) | ツール実行前・実行後、サブエージェントの開始と終了のイベント、およびユーザが直接起動したとき |
| 複数のリポジトリ (REQ-MLT) | すべてのイベント、およびユーザが直接起動したとき |
| 拡張との取り決め (REQ-EXT) | VS Code 拡張が実行ファイルと sh を起動したとき、および Chrome 拡張が同梱の ccnavi の関数を呼んだとき |

登録するイベントの正確な名前と設定ファイルへの書き方は仕様側にある。
