# 下書きと使い捨ての置き場

コミットしない下書きや使い捨てのファイルは`scratchpad/`に置く。設定ファイルのコピー、再現用のスクリプト、調べたときのコマンド出力、渡す前の下書きなどがこれに当たる。ワークツリーで作業しているときはそのワークツリーの`scratchpad/`に置き、ワークツリーが無いときはセッションのスクラッチパッドに置く。置いたファイルを渡すときは、パスも必ず伝える。

## ワークツリーの`scratchpad/`

`scratchpad/`は`.gitignore`に書かれているので追跡されず、`git status`にも出ない。中にファイルがあっても`worktree remove`は止まらず、ワークツリーを消せば下書きも一緒に消える。

チケットが結び付いたワークツリーでも、`scratchpad/`にはそのまま書き込める。実行前チェックは`scratchpad/`への書き込みをチケットの範囲と照らし合わせないので、範囲に`scratchpad/*`を足す必要は無い。

照らし合わせの対象から外れるのは、ルート直下にある`scratchpad/`という名前のディレクトリだけで、大文字と小文字も区別する。`SCRATCHPAD/`・`scratchpadX/`・`docs/scratchpad/`や、`scratchpad`という名前のファイルは普通の作業対象と同じように判定され、チケットの範囲の外なら止められる。

## `scratchpad/`が追跡されているとき

`scratchpad/`が追跡対象になっているリポジトリでは、実行後チェックとサブエージェント終了時チェックで、下書きが範囲外の変更として報告される。報告が出ても下書きは消さず、そのリポジトリの`.gitignore`か`.git/info/exclude`に`/scratchpad/`が書かれているかを確かめる。`ccnavi --lint`を実行したときも、この状態は警告として出る。

## ワークツリーがまだ無いとき

ワークスペースルートで設定の下書きを作るときなど、ワークツリーがまだ無いならセッションのスクラッチパッドを使う。ワークスペースルートへの書き込みは`main-tree`のルールで止められるので、そこに`scratchpad/`を作っても中に書き込めない。セッションのスクラッチパッドの場所はEnvironment欄に書かれている。
