# 下書きと使い捨ての置き場

本番に入れないもの（設定の写し、再現用のスクリプト、調べた出力、渡す前の下書き）は、ワークツリーの中で作業しているならそのワークツリーの `scratchpad/` に置く。ワークツリーが無ければセッションのスクラッチパッドに置く。渡すときは必ずパスを伝える。

## ワークツリーの `scratchpad/`

`scratchpad/` は `.gitignore` に入っているので追跡されず、`git status` にも出ない。`worktree remove` も止まらずに通り、ワークツリーを畳めば下書きも一緒に消える。

チケットが結び付いたワークツリーでも、`scratchpad/` にはそのまま書ける。実行前の判定は `scratchpad/` をチケットの範囲と照らし合わせないので、範囲に `scratchpad/*` を足す必要は無い。

判定から外れるのはルート直下1段の `scratchpad/` だけで、大文字小文字も区別する。`SCRATCHPAD/`・`scratchpadX/`・`docs/scratchpad/` や、`scratchpad` という名前のファイルは普通の作業対象として扱われ、範囲の外なら判定で止まる。

## `scratchpad/` が追跡されているとき

`scratchpad/` を追跡しているリポジトリでは、実行後の監視とサブエージェント終了時の検査が下書きを範囲外として報告する。そのときは下書きを消さずに、そのリポジトリの `.gitignore`（または `.git/info/exclude`）に `/scratchpad/` が書いてあるかを確かめる。`ccnavi --lint` もこの状態を警告する。

## ワークツリーがまだ無いとき

ワークスペースルートで設定の下書きを作るときなど、ワークツリーがまだ無ければセッションのスクラッチパッドを使う。ルート直下への書き込みは `main-tree` が止めるため、そこに `scratchpad/` を作っても書き込めない。セッションのスクラッチパッドのパスは Environment 欄に載っている。
