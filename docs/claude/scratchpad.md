# 下書きと使い捨ての置き場

CLAUDE.md「ソースコード編集方法」の詳細。設定の写し・再現用のスクリプト・調べた出力・渡す前の下書きを置くときに読む。

本番に入れないもの（設定の写し、再現用のスクリプト、調べた出力、渡す前の下書き）は
**そのワークツリーの `scratchpad/`** に置く。名前が `tmp` でないのは、`tmp/` を追跡対象として
使うリポジトリが実在するため（Rails は `tmp/` の下に置き石を追跡させる）。追跡されている
場所を外すと、承認した範囲の外のものが統合先へ乗る道ができる。

- `.gitignore` に入っているので追跡されず、`git status` にも出ない。`worktree remove` は
  止まらずに通り、ワークツリーを畳めば一緒に消える
- ワークスペースの中にあるので、利用者がエディタからそのまま開ける。**渡すときは
  必ずパスを言う。** 開けない場所に置いた下書きは、無いのと同じ
- **チケットが結び付いたワークツリーでも、そのまま書ける。** 実行前の判定はチケットの範囲を
  `scratchpad/` に当てない。範囲に `scratchpad/*` を足す必要は無い
- **外れるのはルートの直下 1 段の `scratchpad/` だけ。** 綴りの大文字小文字も区別する。
  `SCRATCHPAD/`・`scratchpadX/`・`docs/scratchpad/` と、`scratchpad` という名前のファイルは普通の作業対象で、範囲の
  外なら止まる。`.gitignore` が追跡から外す範囲と一致させてある
- **`scratchpad/` が追跡されているリポジトリでは、下書きが範囲外として報告される。** 実行後の
  監視とサブエージェント終了時の検査は `scratchpad/` を外さない。報告が出たら、下書きを消すの
  ではなく、そのリポジトリの `.gitignore`（または `.git/info/exclude`）に `/scratchpad/` が
  入っているかを見る。`ccnavi --lint` が同じことを警告で言う
- **ワークツリーがまだ無いときは、ワークスペースの外にあるセッションのスクラッチパッドを
  使う。** ワークスペースルートで設定の下書きを作る場面がこれにあたる。ルート直下は
  `main-tree` が止めるので、そこに `scratchpad/` を作っても書けない。セッション側の綴りは
  Environment 欄が持つ。同じ「下書きを置く場所」が 2 つあり、**ワークツリーの中なら
  `scratchpad/`、無ければセッションのほう**、と読み分ける
