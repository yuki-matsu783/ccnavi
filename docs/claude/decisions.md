# 提案と判断・セッションの役割分担

## 提案と判断

- 提案にはメリットとデメリットを両方書く。代償が本当に無いなら「無い」と書く
- 次のどれかに当たる対応は自分で決めず、手を動かす前に「何をなぜ変えるか・得るもの・失うもの・
  やらない場合どうなるか・代案」を出して待つ
  - 止まっていたものが通るようになる（判定が緩む、例外が増える、確認が減る）
  - 判定を握りつぶす、条件を狭める、報告を消す
  - 戻せなくなる（消す、履歴を書き換える、他セッションの作業に触る）
  - 影響範囲が読み切れない（共有の設定、hook、スクリプト、配布物、他のプロジェクトへ配るもの）
- 調べること（再現・読む・隔離した場所で試す）は相談を待たない。相談が要るのは結果をこのリポジトリに入れるとき

## セッションの役割分担

- メインは利用者とのやり取り（相談・判断・報告）を受け持ち、実装・調査・テストはサブエージェントを
  バックグラウンドで起動して任せる
- 任せないもの: 1 ファイルで済む小さな確認や修正、レビュー準備中以降の合流・push・依頼
- 並行で走らせるときは、サブエージェントごとに別のワークツリーを割り当てる
- サブエージェントは利用者に直接は聞けない。相談条件に当たったら、手を止めて聞きたいことを添えて返す。
  メインが利用者に聞き、答えを持って同じサブエージェントを再開させる
- メインはサブエージェントの報告を差分とテスト結果で確かめてから、利用者に伝える
- 入れ子で起こすときは、プロンプトに担当の子チケット・ワークツリー・範囲と、他の子のワークツリーに
  触れないことを必ず書く（孫の hook の `cwd` はメインの `cwd` で、ccnavi は孫の担当を見分けられない）
- 入れ子の上限（`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`）に達したサブエージェントには Agent ツールが無い。
  入れ子が要るのに無ければ、起動してほしいエージェントの種類・プロンプト・担当を添えてメインに返す。
  メインがそのとおり起動し、結果を持って同じサブエージェントを再開させる。上限の値と実測は
  ccnavi.md 付録 C「入れ子のサブエージェント」
