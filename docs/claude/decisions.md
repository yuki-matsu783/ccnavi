# 提案と判断・セッションの役割分担

CLAUDE.md「提案と判断」「セッションの役割分担」の詳細。提案を書くとき、相談が要るか迷うとき、サブエージェントに任せるときに読む。

## 提案と判断

- 提案には必ずメリットとデメリットを両方書く。得るものだけを書いた提案は提案ではない。
  デメリットが思いつかないなら、探し方が足りない。本当に代償が無いなら「無い」と書く
- 不安定な方向に倒れうる対応は、自分で決めずに相談する。次のどれかに当たったら、
  手を動かす前に「何をなぜ変えるか・得るもの・失うもの・やらない場合どうなるか・代案」を
  出して待つ
  - 止まっていたものが通るようになる（判定が緩む、例外が増える、確認が減る）
  - 判定を握りつぶす、条件を狭める、報告を消す
  - 戻せなくなる（消す、履歴を書き換える、他セッションの作業に触る）
  - 影響範囲が読み切れない（共有の設定、hook、スクリプト、配布物、他のプロジェクトへ配るもの）
- 調べること自体は相談を待たない。再現させる、読む、隔離した場所で試す、はいつでもやってよい。
  相談が要るのは、その結果をこのリポジトリに入れるとき

## セッションの役割分担

- メインのセッションは利用者とのやり取り（相談・判断・報告）を受け持つ。
  実装・調査・テストなど手を動かす作業は、サブエージェントをバックグラウンドで起動して任せる
- 任せないもの: 1 ファイルで済む小さな確認や修正、レビュー準備中以降の合流・push・依頼
  （サブエージェントの起動が止まる段）
- 並行で走らせるときは、サブエージェントごとに別のワークツリーを割り当てる
- サブエージェントは利用者に直接は聞けない。「提案と判断」の相談条件に当たったら、
  手を止めて何を聞きたいかを添えて返す。メインが利用者に聞き、答えを持って同じサブエージェントを再開させる
- メインはサブエージェントの報告を差分とテスト結果で確かめてから、利用者に伝える
- サブエージェントがさらにサブエージェントを起こす（入れ子）ときは、そのプロンプトに担当の子チケット・
  ワークツリー・範囲を必ず書き、他の子のワークツリーに触れないことを書く。孫の hook の `cwd` はメインの
  `cwd` なので、ccnavi の案内と差し戻しは孫の担当を見分けられない
- 入れ子には上限がある（`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`、既定 3。クラウドの環境は 1）。上限に
  達したサブエージェントには Agent ツールが渡らない。入れ子が要るのに無ければ、手を止めて、起動してほしい
  エージェントの種類・プロンプト・担当を添えてメインに返す。メインがそのとおり起動し、結果を持って
  同じサブエージェントを再開させる（実測と文書は ccnavi.md 付録 C「入れ子のサブエージェント」）
