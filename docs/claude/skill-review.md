# スキルの振り返り

この文が届いたら（ターンの終わりに ccnavi が止めたとき、提案を書くとき）、ここまでの作業を 1 度だけ振り返る。
ほとんどの回は何も出ない。止めた回の決まり（タスクを続けない、問いで終わっていたら問いを最後に書き直す、
無ければ「振り返り: 無し」）は、止めた文の頭に ccnavi が書いている。

## 直接書かない

振り返りで `.claude/skills/` もプロジェクトの `docs/skills/` も書き換えない。出すのは候補か提案だけで、スキルを直すのは
ユーザが承認したフェーズかチケットの中。

## 拾うもの

- ユーザの訂正や苛立ち（「そうじゃない」「毎回〜しないで」「覚えておいて」）。いちばん強い信号
- 手順の順番や進め方の訂正
- 時間を食った末に分かった、次も効く手順・落とし穴
- 読んだスキルの誤り・手順の抜け・古さ
- サブエージェントの報告の「スキル候補」の節（サブエージェントには振り返りが届かないので、報告で受け取る）

## 拾わないもの

- 環境のせいの失敗（コマンドが無い、認証が無い、入れ忘れ）。直し方が分かったならその手順だけ
- 道具や機能を否定する主張（「X は使えない」）
- 途中で解けた一時的なエラー、1 回きりの作業の経緯
- 解決しないまま終わった試行錯誤
- CLAUDE.md・docs/claude/・ADR にすでに書いてあること

## どこに足すか（上ほど優先）

1. このセッションで読んだスキルを直す
2. 同じ種類の作業を扱う既存のスキルを直す（節・落とし穴・使う場面を足す）
3. 既存のスキルに `references/<話題>.md` を足すか広げ、SKILL.md に 1 行の案内を足す
4. 作業の種類の単位で新しいスキルを作る。今日の作業名・チケット番号・エラー文を名前にしない

- 直す前に、対象の SKILL.md と触る references/ を読み直す。会話中の引用で済ませない
- 1 つの事実は 1 か所。同じ規則がもうあるなら、足さずにその文を強めるか言い直す
- 手順の順に書き、落とし穴は該当する手順に「規則 + なぜ（1 句）」で添える。日付・番号・ユーザの言葉の引用を中身にしない
- yomiyasu スキルはユーザが明示的に頼んだときだけ使う。`docs/claude/`・`CLAUDE.md`・`.claude/skills/`・プロジェクトの `docs/skills/`・`rules.yml` の `message` には当てない（表・箇条書き・規則 + なぜ の形を平文に崩すため）
- 誤りは、間違った文そのものを直す

## 対象のスキル

| 振り返る作業 | 対象 |
|---|---|
| ワークスペース自身 | `.claude/skills/<名前>/` |
| `projects/<名前>/` の作業 | `projects/<名前>/docs/skills/<名前>/`（Claude Code のスキルと同じ形。ccnavi が目録を渡す） |

決めるのは、学びが使われる作業の側。両方にまたがるなら、手順が使われる側に 1 本だけ。

## 候補の持っていき方

| 今の作業 | すること |
|---|---|
| 計画のある親チケットの下で、フィードバック計画をまだ出していない | 親のワークツリーの `scratchpad/skill-candidates.md` に候補を足す（対象・作る/直す・中身の下書き・根拠）。フィードバック計画を書くとき、候補があり、`skill-improve` の種類があり、親の範囲に対象の置き場が入っていれば、`feedback:` に `skill-improve` を入れる。承認後、そのフェーズの子でスキルを直し、MR で見てもらう |
| それ以外（計画の無いチケット、フィードバック計画が承認済み、親の範囲に置き場が無い、チケットの外） | 提案チケットを書く（下） |
| サブエージェント | 自分では書かない。最後の報告に「スキル候補」の節を足してメインに返す |

## 提案チケット

置き場は 1 つに決める。作業中の MR に提案のファイルを混ぜない。

| 対象 | 書くツリー |
|---|---|
| ワークスペースのスキル | `.claude/worktrees/skill-proposals`。無ければワークスペースルートで `<統合先>` から切る |
| プロジェクトのスキル | `.claude/worktrees/<プロジェクト>-skill-proposals`。無ければ `cd projects/<プロジェクト>` してそのプロジェクトのブランチから切る |

そのツリーの `wip/proposals/todo/<識別子>.md` に書いてコミットし、パスをユーザに伝えて承認を頼む。
識別子は `skill-<スキル名>-<要点>` のように 1 語。

```yaml
---
version: 1
ticket: skill-commit-push-retry
human_review:
  required: true
  reason: エージェントの手順を変えるため
title: commit スキルに push の打ち直しを足す
rationale: |
  直す（新しく作るなら「作る」）。拾った信号と、次のセッションで何が変わるか。
allow:
  - match: Write|Edit
    glob: ".claude/skills/commit/*"
---
対象の SKILL.md（と references/）の差分か、新しく作るなら全文の下書き。
```

プロジェクトのスキルの提案は、そのプロジェクトの提案として `allow` に `docs/skills/<スキル>/*` を書く
（綴りはプロジェクトのルートからの相対）。
