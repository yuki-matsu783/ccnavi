# 思想（00_idea.md とスライド）の書き方

ccnavi の根底にある考え方を書く文書の決まり。要件書・設計書・ADR の書き分けは[要件書・設計書・ADRの書き分け](docs-writing.md)にある。

## 置き場と扱い

| もの | 置き場 | 読み手 |
|---|---|---|
| 思想（正） | `docs/00_idea.md`（`type: idea`） | 開発者、エージェント |
| スライド | `docs/01_idea/index.html`（1 ファイルで動く HTML） | 人間。Claude Code を知らない人も読む |

- 思想は要件書より上段にある。ユーザが依頼しない限り直さない。機能の追加や仕様の変更では動かさず、要件書・設計書・ADR を直す
- 思想を直すときは、同じ変更の中で、スライドと、設計書の「コア機能と設計原則」にあるテーマと P の対応を揃える
- 要件書・設計書・ADR に、思想の中身を写さない。`00_idea.md` を指す
- 思想に書かないこと: 外から観測できる約束（要件書）、いまの実装（設計書）、個々の決定の経緯（ADR）、個別の関数・ファイル・オプションの仕様

## 構成

`00_idea.md` は次の順に書く。

1. 一文で言うと
2. 全体像: 解決するテーマの表（要点と、4 つのコア機能への対応を 1 つの表に）と、想定する環境（手元の PC・別の PC・コンテナの実行）。テーマの前に、前提（コンテキストロット・費用・スキルの budget）
3. テーマごとの Why・What・How・具体例
4. 作らないもの・限界
5. 下位の文書との関係

## テーマの切り方

- テーマは、ccnavi が解決する内容で切る。機能名やモジュールの単位では切らない
- 数は 5 前後にする。同じ解決策で片づくもの、同じ原因から出るものは 1 つにまとめる。1 つのテーマが、関係の薄い 2 つを抱えていたら分ける
- 4 つのコア機能とは別の軸で切るので、対応は全体像の表に 1 列で書く。章の中で 2 つの分類を並べない
- 共通の原則を別の節に立てない。どれかのテーマの What か How に入れる
- 新しい課題感を足すときは、既存のテーマに入るかを先に問う。入らないときだけテーマを足す

## Why・What・How・具体例の書き分け

| 見出し | 書くこと |
|---|---|
| Why | 何が困るか。なぜ既存のやり方では足りないか。読み手が自分の問題として分かる場面 |
| What | ccnavi が何を実現するか。どうやるかは書かない |
| How | 実現の考え方。実装の細部ではなく、設計書の原則に落ちる粒度 |
| 具体例 | 1 つの場面を、順を追って書く |

- 具体例は、特定のコマンドや設定の仕様に寄せすぎない。たとえば、止める例は「一括削除を止めて、ファイル名の指定へ案内する」のように、場面が分かるものにする
- 具体例の固有名（ファイル名、件数など）は、分かりやすさのための想定でよい。ただし、実際の挙動と食い違うことは書かない
- 確率や数式は、前提を添える（例: 「やり直しが互いに独立なら」）

## 言葉の揃え方

- 解決する内容のまとまりは「テーマ」と呼ぶ。「課題」と呼ばない
- 止めるのは ccnavi で、主語を ccnavi にした能動で書く（「ccnavi が止める」「機械的に止める」）。「止まる」「止められる」は使わない
- 止めるときは、理由と代わりの手段を一緒に返す、と書く。止めるだけだと別の書き方で打ち直される
- 人間の判断は、エージェントが代行できない形にする、と書く

## スライドの作り方

読み手は、Claude Code を知らない人も含む。問題が分かり、それをどう解決しようとしているかが分かるようにする。

- 構成は、前提（Claude Code とは、ツール呼び出し、hook、文章の指示と hook の違い、コンテキストロット、費用、スキルの budget、ccnavi とは、想定する環境、Claude Code とモデルの進歩を見込むこと）、5 つのテーマ、作らないもの・限界、まとめ、文書の地図の順
- テーマごとに、問題、解決、具体例の順に、3 枚以上に分ける。1 枚に Why・What・How を詰め込まない
- 1 枚に 1 つの図を置き、短い文を添える。図で具体例を説明する
- 1 つの HTML ファイルで動くようにする。外部の読み込みを使わず、図はインライン SVG にする。明暗の両方で読めるようにし、キー・ボタンで送れる
- 色は、ccnavi が通す・人間が操作するものを青、止めるものを赤で揃える
- 拡張の画面を見せるときは、拡張の見本のデータ（`extensions/vscode/ccnavi-board/src/webview/tours/*.yml` の `sample:`）で画面を描いて撮り、WebP にして HTML へ埋め込む。実際のチケットや絶対パスが写る画面は使わない。見本の画面だと、スライドに書く
- eli10 で図を試作してから、スライドに移してよい。試作は正本ではない。`00_idea.md` が正で、スライドはそれに従う

## 確かめ方

- スライドは、全枚を描画して、文字のはみ出しと線の重なりを見る。図の中の文字は、箱に収まる長さにする
- `00_idea.md` に「課題」「止まる」「止められる」が残っていないか、文字列で検索する
- 思想を直したら、スライドの該当箇所と、設計書のテーマと P の対応を見直す
