# ワークツリーで作業する

## 基本

- gitは`ccnavi-git.sh`を通して使う。受け付ける形は、そのスクリプトの`--help`に出る
- `.ccnavi/scripts/`はワークスペースにしか無いので、shのパスの書き方はcwdによって変わる

  | cwd | 書き方 |
  |---|---|
  | ワークスペースルート | `sh .ccnavi/scripts/ccnavi-git.sh ...` |
  | ワークツリーの中 | `sh ../../../.ccnavi/scripts/ccnavi-git.sh ...` |
  | `projects/<名前>`の中 | `sh ../../.ccnavi/scripts/ccnavi-git.sh ...` |

  拒否の文面が案内するコマンドは`{root}`から始まる絶対パスで書かれているので、そのまま実行すればどこからでも通る

## 他セッションの作業を踏まないために

- 自分のワークツリーの外（ワークスペースルートや他のワークツリー）にある未コミットの変更は、他セッションのものとして扱う
- 他セッションの書きかけは、コミットも、ブランチの移動も、`reset`もしない。ビルドが壊れていても直さず、
  何が壊れているかを報告して判断を仰ぐ
- 退避が必要なときは`ccnavi-git.sh stash push -u`を使う。消す前に、下書きの置き場（docs/claude/scratchpad.md）へ
  コピーも取っておく。コピーは他セッションのツリーの中には置かない

## ワークツリーの作り方

- 置き場はワークスペースの`.claude/worktrees/<ブランチ名>`。プロジェクトから切る場合も同じ場所に置く。
  置き場は1段だけで、その下に階層を作らない
- `ccnavi-git.sh worktree add <行き先> -b <名前> <統合先>`で作る。末尾を省くと今いるブランチが起点になるので、
  `<統合先>`が`main`のときも省かない
- `<行き先>`はcwdを基準に決まる。ワークスペースルートからなら`.claude/worktrees/<名前>`、
  `projects/<名前>`の中からなら`../../.claude/worktrees/<名前>`と書く。間違えると止まり、拒否の文面に正しい書き方が出る
- `worktree add`に渡せるオプションは決まっている（`-b` `--reason` `--track`など）。
  一覧に無いものは通らない。必要なものが出てきたら、ユーザに足してもらう
- 行き先の名前とブランチ名は揃える（`-b <行き先の名前>`）。`-B`・`--detach`・`--force`は通らない。
  `-b`を付けずに2つ目の語を渡すときは、行き先と同じ名前の手元のブランチか`origin/<名前>`だけが通る（タグ・shaは通らない）。
  親のワークツリーでは、別のブランチへ`checkout` / `switch`できない（ADR-0093の段階2b）
- `branch` `checkout` `switch` `fetch` `pull` `merge` `commit` `rm` `restore`のオプションは、許可リストに照らして判定する。
  長いオプションは略さずに書く（`--force-c`のように略したものは通らない）
- プロジェクトのワークツリーは、`cd projects/<名前>`してから切る。`<統合先>`はそのプロジェクトのブランチで、
  ワークスペースの`main`ではない
- `<統合先>`がリモートにしか無いときは、先にプロジェクトの中で`ccnavi-git.sh fetch <リモート> <統合先>`を実行する
- 起点はリモートの最新の統合先（`CCNAVI_INTEGRATION_BRANCH`、無ければ`ccnavi-sync.sh`が控えに書いた名前、
  無ければデフォルトブランチ＝`origin/HEAD`が指すもの）。セッションの開始時に`ccnavi-fetch.sh`が
  ffで進める（ADR-0060）。進められなかったときは、セッションの頭に「ワークツリーの起点になる ... 」で始まる行が出ている。
  その場合は、切る前に原因を解消する（分岐ならユーザに合流させてもらい、未コミットならそのツリーの持ち主に聞く）。
  セッション中にリモートが進んだときは、`ccnavi-git.sh fetch origin <統合先>`をもう一度実行する
- 作業が完了したら`<統合先>`へ戻す。コンフリクトして判断に困る場合はユーザに確認する

## `<統合先>`へ戻す

- ワークツリーのブランチが`<統合先>`のHEADのすぐ後に続いているなら、fast-forwardで取り込める
- `<統合先>`が先に進んでいたら、ワークツリーの中で`ccnavi-git.sh merge <統合先>`を実行し、衝突を解消してから戻す
- `<統合先>`が保護されていて直接は取り込めないなら、マージまでは行わない
- 直接`<統合先>`に戻した場合は、統合が済んでから`ccnavi-git.sh worktree remove <パス>`と
  `ccnavi-git.sh branch -d <名前>`で片付ける
- マージリクエストに出した場合は、マージを待たず、`ready`でDraftを外した直後にワークツリーを片付ける。
  手順は「`ready` → マーカー`.ccnavi/approved/phases/<親>/ready.json`をコミットしてpush →
  `ccnavi-clean.sh` → `worktree remove`」の順。マーカーはpushの後に書かれるので、コミットせずにワークツリーを消すとマーカーも消える。
  親に取り込んで閉じた子のワークツリーも、このときに外す
- マージリクエストに出したブランチは消さない。リモートのブランチは、マージのときにホストが消す。ローカルのブランチは
  squashで取り込まれるので`branch -d`では消せず、ラッパースクリプトは`-D`を通さない。残ったローカルのブランチはユーザが消す
- `worktree remove`の前に、`ccnavi-clean.sh <名前>`で生成物（node_modules・.venvなど）を消す（Windowsで削除が
  途中で止まるのを防ぐため）。`ccnavi-clean.sh`は、未コミットの変更があるワークツリーでは何も消さずに止まる
