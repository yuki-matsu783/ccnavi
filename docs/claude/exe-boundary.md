# 実行ファイルの境界

- ccnaviの実行ファイルはネットワークにアクセスしない。実行ファイルが自分で読んで判断するのは、
  プロジェクトのディレクトリの中で把握できるものだけで、作業ツリー、git、承認済みチケット、マーカー、hookのpayloadが当たる
- ディレクトリの外にあるもの（マージリクエスト、レビューのスレッド、ホストのAPI、認証）は、
  `.ccnavi/scripts/` のshが取ってきて `--result` に渡す。実行ファイルは渡された写しを読み、チケットとマーカーを動かすだけ
- 止めるか通すかの判定は、hookと実行ファイルが受け持つ（P13）。shがccnaviの状態を読んで止めるのは、2重目の守りにあたる。
  shに新しい判定を足したくなったら、まずhookの側に置けないかを考える
- 実行ファイルには「外を見に行く」コードを足さない。その処理はshの仕事として分け、実行ファイルには「その結果をどう読むか」
  だけを足す。写しの形式が、shと実行ファイルの間の契約になる
