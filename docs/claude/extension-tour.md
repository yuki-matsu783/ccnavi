# VS Code 拡張の案内（ガイドツアー）を作る・直す

拡張（`extensions/vscode/ccnavi-board`）の画面は、ヘッダ右上の「?」から吹き出しの案内を出す。案内の中身は画面のコードではなく、画面ごとの YAML に書く。
案内を足す・直す・新しい画面に付けるときは、この文書の決まりに従う。構成の一覧は `extensions/vscode/ccnavi-board/docs/design/structure.md`、動いている実例は下の「実例」を読む。

## 考え方

- 案内の目的は、利用者が自分の設定やチケットを壊さずに、画面の使い方を試し見できること。そのため、案内の間は今の中身を使わず、案内用の見本を描く。
- 初回の案内は短く、「?」から目的ごとの案内を選べるようにする。画面の部品を順に説明するだけでなく、「〜したいとき」の流れで見せる。
- 案内の中身を YAML にするのは、ユースケースを足すときに画面のコードを直さなくて済むようにするため。画面のコードが決めるのは、見本の上で何を動かせるか（`scene` の鍵）だけ。

## 構成

| 置き場 | 役目 |
|---|---|
| `src/webview/tours/<画面>.yml` | その画面の案内の定義。`screen`（ファイル名と同じ）・`sample`（見本）・`courses`（案内の一覧） |
| `src/core/tour-def.ts` | YAML の形の検査（`parseTour`）。知らない鍵・不正な `target` は拒否する |
| `src/core/tour-<画面>.ts` | `sample` を画面が描く形にする小さな読み取り |
| `src/webview/Tour.tsx` | 吹き出し・「?」のメニュー（`TourButton`）・出し入れ（`useTour`）・`coursesOf` / `courseOf` |
| `scripts/bundle-webview.js` | YAML をビルドのときに JSON にしてバンドルへ入れる。画面は実行時に YAML を解析しない |

画面の `App.tsx` は、`tourOf(yaml)` で定義を読み、`coursesOf(def, 画面の scene を入れる関数)` で案内の一覧を作り、`<TourButton courses onPick={tour.start}>` と `<Tour steps={courseOf(courses, tour.course).steps}>` に渡す。

## 案内の決まり

1. 先頭の案内は `id: intro`（基本の案内）。拡張ホストが初回に自動で出すのはこれ。末尾の段は `target: tour`（「?」を指して、案内の一覧があることを知らせる）。
2. 2 本目からがユースケース。`id` は小文字の英字で始まる英小文字・数字・`-` だけ。画面の中で一意にする。
3. 案内が 1 本だけの画面は、「?」が一覧を挟まずに始まる。ユースケースを足すと一覧になる。
4. ユースケースの切り方:
   - 利用者の目的で切る（題は「〜したいとき」）。画面の部品の説明を並べない。
   - 1 本 4〜9 段。1 段に 1 つのことだけ言う。
   - ユースケース同士で内容が重ならないようにする。基本の案内と重なる説明は、基本の案内の側に任せる。
   - 実際に画面にある機能だけを書く。ボタン名・欄名・用語は画面の文言と一致させる（コードで確かめる）。
   - 機能の数で本数を決める。目安は 3〜8 本。
5. 段は `target`（指す先）・`title`・`body`・`scene` を持つ。`target` を空にすると、吹き出しを中ほどに出して文だけを見せる。
6. 基本の案内の題と順序は、既存のテストが見ているので、変えるときはテストも直す。

## 見本の決まり

- 案内の間は常に見本を描く（「何も無いときだけ」ではない）。実際の設定・チケット・編集中の内容・開いた行・タブは使わず、動かさない。閉じたあとに戻すものが無いようにするため、見本は表示のときに差し替えるだけにする（画面の state に書かない）。
- 見本は YAML の `sample:` に書く。形は実行ファイルの出力、またはその設定ファイルと同じ書き方にする（`rules.yml` のルール、`risks.yml` の配点、`ccnavi --explain --json` のボードなど）。
- `sample` は `src/core/tour-<画面>.ts` で画面の形にする。この読み取りは、実際の読み取り（`readRules`・`readRisk`・`parseBoardJson`・`parsePlanOrder` など）と同じ結果になること。実際の読み取りが `yaml` に依存していて画面から読めないときは、同じ読み方の小さな版を持ち、一致をテストで守る。
- 見本が実際の形から外れたときにテストで気づけるようにする。実行ファイルの JSON と同じ形のものは、既存の読み取りに通す。
- 見本の題・id には、利用者が実際のものと取り違えない名前を付ける。案内の間は「案内のための見本」の帯（`SAMPLE_NOTE`）を出す。
- 見本に実際の問題・注意（読み込みの苦情など）を重ねて出さない。

## scene の決まり

- `scene` は「その段で画面がとる様子」（開く行・タブ・選ぶ点・入れる文字など）を書く。鍵と値は画面ごとに決め、YAML 冒頭のコメントに一覧を書く。値は文字列・数・真偽だけ。
- 段ごとに全部書き直す。前の段を引き継がない。そうすると「前へ」で戻っても同じ様子になる。
- 画面は `scene` を描くだけにする。段の順序や前の段に依らない。
- 畳んだ中を指さないよう、案内の間は畳みを外す（指す先が 0×0 になる）。
- 存在しない見本の id・名前を書かない。綴り違いは黙って既定に戻るので、テストで鍵と値を見本と突き合わせる。

## data-tour の決まり

- 指す先は `data-tour="名前"` で指す。見た目用のクラス名や id には依らない（見た目を直しても案内が壊れない）。
- 名前は `^[a-z][a-z0-9-]*$`。行や項のような繰り返しの要素は `rule-<id>`・`node-<番号>` のように接頭辞を付ける。`parseTour` が、この形でない `target` を拒否する。
- 同じ印を持つ要素は、案内が指す時点で画面に 1 つにする（複数あると先頭を指す）。繰り返しの要素は、案内が指す行だけに印を付ける。
- 図（React Flow）のように、後から要素が描かれるものは、描かれたあとに案内に測り直させる（`resize` を流す）か、印を付ける仕組みを画面の側で持つ。共通の部品に口が無い場合は、画面の側で付ける。

## 案内の間の守り

案内の間、見本の上の操作は実際には何も起こさない。実際の編集・拡張ホストへの送信・永続の state を、次のように止める。

1. 送信口で止める。案内の間は `tourDone`（と `ready`）以外を拡張ホストへ送らない（ボード・ルール・フローの `post.ts` の `mutePosts` / `muteForTour`）。
2. ハンドラの先頭で止める（`if (tour.touring) return;`）。編集・開閉・畳み・絞り込み・タブの切り替え・追加・保存・読み直し・開く。
3. 描画は `touring` のとき見本に差し替える。実際の state（編集中のルール・タブ・絞り込みなど）は書かない。
4. 案内の最中に画面が読み込み中・エラーへ替わったら、案内を閉じて `tourDone` を返す（`useTour` が行う）。閉じずに残すと、中身が戻ったときに案内が 1 段目から出直す。
5. 全面の覆いがクリックを受ける。焦点は吹き出しの中だけを巡る。これらを前提にせず、1 と 2 を必ず入れる。

## テスト

新しい案内には、次のテストを付ける（実例は下の「実例」）。

- 全ユースケースの全段で、指す先が画面にあり、吹き出しが中ほどへ逃げない（`.tour-bubble.center` が無い）。
- 見本だけが描かれ、実際のものが出ない。閉じたら実際の表示に戻る。
- 案内の間に `tourDone` 以外を拡張ホストへ送らない。実際の state（タブ・絞り込みなど）が動かない。
- `scene` の鍵と値が見本と合う。
- 見本が実際の読み取りと同じ形になる。
- 「?」が一覧を開き、選んだ案内だけが始まる（案内が複数ある画面）。

YAML の形の検査（`test/shared/tour-def.test.ts`）は、すべての `tours/*.yml` に自動で効く。図の画面は `measure: true` で開く（`test/helpers/dom.ts`）。
テストの ID は `docs/design/structure.md` の「テストの ID」に従い、並行して作業するときは担当ごとに ID の範囲を分ける。

## ユースケースを足す手順

1. 画面の機能をソースコードから読み、利用者の目的ごとに切る。画面にあるボタン・欄の文言を控える。
2. 見本が足りなければ `sample:` に足す。
3. 画面の `scene` の鍵が足りなければ、画面の `shown*`（見本の描き分け）に足す。YAML 冒頭のコメントの鍵の一覧も更新する。
4. 指す先に `data-tour` を付ける。
5. YAML に `courses` を足す。
6. 上の「テスト」を足し、修正に関わるグループを回す（`node scripts/test-groups.js <グループ>`）。
7. `docs/design/structure.md` と、拡張の `README.md` の手動確認表に、変えたことを書く。
8. 実ブラウザで見る（Playwright と Chromium）。VS Code のテーマ変数が無い環境でも、指す先の位置と吹き出しが中ほどへ逃げないことは確かめられる。

共通の部品（`Tour.tsx`・`Tour.css`・`tour-def.ts`・`bundle-webview.js`）を直したくなったら、画面の担当の中で直さず、直す理由を提案として出す。全画面に効くため。
