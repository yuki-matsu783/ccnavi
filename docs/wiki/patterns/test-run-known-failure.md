# 既知の失敗がある間は全件の結果が見えない

## 説明

既知の失敗が 1 本あると、全件（`go test ./...`）の出力に失敗が混ざり、新しい失敗と既知の失敗を取り違えやすい。
親の最後のフェーズの子を finish した後のレビュー準備中は、シェルの実行が止まって全件を回せない。

## 原因

- 全件の出力は長く、既知の失敗と新しい失敗が同じ形で並ぶ
- 実ルールを使う bench は `*x*` 形の glob の照合が入力の長さの 2 乗で伸びる
- レビュー準備中はシェルの実行が止まる

## 操作の例

feature-207 で、既知の失敗 1 本のために全件の結果が見えず、bench を前で回して数分待ち、最後の子を finish した後に全件を回せなかった。

## 回避策

- 既知の失敗がある間は、パッケージごとに `go test ./internal/clitest/<パッケージ>/` で回し、失敗の数を既知と比べる
- bench は名指しで、ターンの中ならバックグラウンドで回す
- 全件は、親の最後のフェーズの子を finish する前に回す
