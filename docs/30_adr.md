# 設計判断の記録（ADR）

設計書 [docs/20_design.md](20_design.md) は「いまの実装がどう作られているか」だけを書く。
「なぜそう決めたか」「以前はどうだったか」「何を採らなかったか」は、判断 1 つにつき 1 枚、ここに置く。
一度やめた道へ戻らないための記録で、設計書を読んで「なぜ」が気になったときに引く。

書式は 1 枚ごとに同じ。

| 見出し | 書くこと |
|---|---|
| タイトル | `# ADR-<番号>: <タイトル>`。番号はファイル名の先頭 4 桁と合わせる |
| 状態 | `採用`、`提案`（決めたが、段階を分けて入れるので有効になっていない部分があるもの。括弧で入れた範囲を書く）、または `置き換え（ADR-NNNN）`。タイトルの次の行に置く |
| 状況 | 何が問題だったか。以前の形があればそれも。日付は書かない（git の履歴が持つ）。要件書・設計書を指すときは行数や節番号でなく、文書名と見出し・項目の言葉で書く（[書き分け](42_claude/docs-writing.md)） |
| 決定 | 何にしたか。1 段落、または「決めたこと / なぜ」の表 |
| 理由 | なぜその側を採ったか。決定が表なら、表の「なぜ」の列がこれを兼ねる |
| 得たもの・失ったもの | 決定の代償。無いなら「無い」と書く。**唯一の必須** |
| 採らなかった案 | 比べた案と、落とした理由。決定が表なら、表の「採らなかった側」の列がこれを兼ねる |

決定が十数個の判断をまとめた表になる枚（0024、0029、0030）では、理由と採らなかった案を表の列が
兼ねる。そのぶん、**行単位で後から覆されたときに「置き換え」が使えない**ので、覆した側の ADR 番号を
その行に書き添える（0024 の `ccnavi-review.sh` の行がその例）。

状態は「採用」「提案」か「置き換え（ADR-NNNN）」。決定をまるごと覆したときは新しい 1 枚を足し、古い側の
状態を「置き換え」にする。古い 1 枚は消さない。

番号は 1 枚につき 1 つで、**重複させない**。足すときは、`origin/main` を取ってきたうえで
最後尾の次を採る（重複は並行して伸びた枝が合流したときに起きる）。

**最後尾は、主題のディレクトリを横断して探す。** 1 つのディレクトリだけを見ると、別の主題が
使っている番号を採ってしまう。次のコマンドで、全体の最大の番号が出る。その次を採る。

```sh
ls docs/30_adr/*/ | grep -oE '^[0-9]{4}' | sort | tail -1
```

このリポジトリでは、ADR を書いた直後に `.claude/hooks/check-adr.sh` が番号の重なりを見て、
重なっていれば次の空き番号を添えて差し戻す。

重複させてしまったら、引かれている数が少ないほうを空き番号へ動かし、下の「動かした N 枚」の表に
古い番号を残す。数がほぼ同じときは、保護された場所（`.ccnavi/scripts/`・`.ccnavi/config/common/`）から
引かれている側を残す。そちらを動かすと、書き換えにユーザの手が要る。「後から置いたほう」を動かす
（テストの ID で採った決め方、issue #88）のと逆にしたのは、後から置いた側が本文と実装から
何十か所も引かれていることがあるため。数え方は「追跡されているファイルのうち、その枚自身を
除いて `ADR-00NN` と書かれている行」。

**動かすと失うものがある。** (1) 番号が置いた順でなくなる（0064 は 0062 より先に決めたのに
番号は後ろ）。(2) git の履歴と、GitHub の issue・PR の本文は書き換えられない。そこに書かれた
古い番号は、いまは別の決定を指したままになる。(3) 古いファイル名へのリンクは切れる。動かすのは、
「`ADR-00NN` と書かれた参照がどの決定を指すか読めない」ほうが重いと判断したときだけ。

`tests/core/test_adr_numbers.py` は、番号が重複していないこと、タイトルが `# ADR-<番号>:` で始まること、ADR が下の「置き場と分け方」の表にあるディレクトリに置かれていることを確かめる。**ただし、このテストは ADR を足しただけのコミットでは回らない**（コミットの検査は、ドキュメントだけの変更では回さないため）。重複が合流するまで気づけない点は変わらない。変わったのは、合流したあとに誰かが `core` を回したときに気づけるようになった点だけ。

## 置き場と分け方

ADR は `30_adr/<主題>/NNNN-名前.md` に置く。番号は主題をまたいで一続きに振る。パスが変わっても、
`ADR-00NN` という参照は変わらない。全件の一覧は持たない（足すたびに直す場所を増やさないため）。
探すときは、ディレクトリを開くか、`ccnavi --docs` で `tags` や `keywords` から引く。

| ディレクトリ | 置く判断 |
|---|---|
| `30_adr/rules/` | 判定とルール（書式・適用の仕方）、実行後チェック、自己防衛、hook、ユーザ専用の入口 |
| `30_adr/ticket/` | チケット・フェーズ・計画・承認・レビュー・学びの蓄積 |
| `30_adr/config/` | 設定と共通レイヤー、導入と配布、プロジェクト、スキル |
| `30_adr/base/` | 言語・ビルド・テスト方針・設計方針・記録（ログと state）・文書 |
| `30_adr/extension/` | VS Code 拡張・Chrome 拡張・ボード |
| `30_adr/worktree-git/` | ワークツリー・git・下書きの置き場・PC をまたぐ同期 |

- 主題をまたぐ判断は、主になる側の 1 か所に置く。ほかの主題からは `tags` で引く。
- 置き場は、足すときにこの表から選ぶ。どの置き場にも主になる判断が入らないときだけ、新しいディレクトリを作って、
  この表に 1 行足す。それ以外の場合は、この文書を直す必要はない。
- ADR は別の主題へ動かしてもよい。番号は変わらないので、直すのは、そのファイルへのパスのリンクだけでよい。
