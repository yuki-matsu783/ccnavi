### 2.1 起動と登録 — REQ-HKS

| ID | 型 | 要求 |
|---|---|---|
| REQ-HKS-01 | 常時 | ccnavi は、Claude Code の複数の hook イベントに、同一のコマンドとして登録できること |
| REQ-HKS-02 | 事象 | hook から呼ばれたとき、ccnavi は、どのイベントから呼ばれたかを標準入力の内容から判別し、そのイベントに対応する判定だけを行うこと |
| REQ-HKS-03 | 異常時 | もし対応する判定を持たないイベントから呼ばれたならば、ccnavi は、何も判定せず、ツールの実行を妨げずに終わること |
| REQ-HKS-04 | 常時 | ccnavi は、シェルを介さず絶対パスで直接起動でき、利用する側にランタイムやパッケージの追加導入を求めない実行ファイルとして配布できること |
| REQ-HKS-05 | 常時 | ccnavi は、起動時の作業ディレクトリがどこであっても、同じ入力に対して同じ判定を返すこと |
| REQ-HKS-06 | 常時 | ccnavi の判定は、同じイベントに登録された他の hook の結果に依存しないこと |
| REQ-HKS-07 | 異常時 | もし hook の入力を与えられずに直接起動されたならば、ccnavi は、判定を行わず、hook として使う道具である旨と使い方を示して非ゼロの終了コードで終わること |
| REQ-HKS-08 | 常時 | 導入スクリプトは、hook が起動する振り分けのスクリプトと実行ファイルを、それぞれ決まった置き場に置き、置き場を引数で動かせないこと |
| REQ-HKS-09 | 事象 | 会話の大きさが促す大きさ（環境変数 `CCNAVI_HANDOFF_SUGGEST_TOKENS`。既定 400000、0 で無効）以上のターンが終わったとき、ccnavi は、記憶（プロンプトキャッシュ）が切れると続きの費用が増えること、このあと何が起きるか、どう止めるかを、費用の仕組みに詳しくない人にも分かる言葉でユーザに知らせること。知らせは 1 セッションに 1 回とする |
| REQ-HKS-10 | 事象 | 促す大きさ以上の会話が、ユーザの入力のないまま記憶の保持時間の少し手前（1 時間なら 55 分、5 分なら 4 分）に達したとき、ccnavi は、モデルを起こして、次のセッションへの引き継ぎプロンプトをワークスペースルート直下の `scratchpad/` に書かせること。その間にユーザが入力したら、書かせないこと |
| REQ-HKS-11 | 常時 | 引き継ぎプロンプトを書かせたあと、ccnavi は、同じセッションの会話が促す大きさのぶん（書かせたときの大きさ + 促す大きさ）育つまで、次を促さないこと。会話が小さくなったら（`/compact`・`/clear`）数え直すこと |
| REQ-HKS-12 | 常時 | 見ている人がいない実行（`claude -p`・SDK）とサブエージェントでは、REQ-HKS-09 と REQ-HKS-10 の働きを起こさず、待機でプロセスを引き止めないこと |

REQ-HKS-02 が入力からイベントを判別するのは、登録側に引数で教えさせると、書き間違えたときに気づかないうちに別の判定が走るため。

REQ-HKS-03 と REQ-HKS-07 は、設置を誤ったときの失敗のしかたを分ける。知らないイベントに登録されても作業は止めない。
入力なしの直接起動は、何も示さずに 0 を返すと設置の誤りに気づけないので失敗させる。

REQ-HKS-06 は、同じイベントの hook が同時に走り、順序が決まらないことによる。

REQ-HKS-08 が置き場を固定するのは、振り分けのスクリプトが自分の位置から実行ファイルを一意に決め、
自己防衛（REQ-SLF-07）が同じパスで両方を守るため。置き場を動かす引数を渡されたときは、何も書かずに断る。
