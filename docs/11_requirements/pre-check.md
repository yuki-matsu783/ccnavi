### 2.4 ツール実行前チェック — REQ-PRE

| ID | 型 | 要求 |
|---|---|---|
| REQ-PRE-01 | 事象 | ツールの呼び出しが発生したとき、ccnavi は、その呼び出しを許可・確認・拒否のいずれかに判定し、Claude Code が解釈できる応答として返すこと。ただし設定がその対象に言及していない呼び出しについては、REQ-PRE-10 に従う |
| REQ-PRE-02 | 常時 | ccnavi は、プロジェクト設定が拒否と宣言した対象への操作を、チケット・環境変数のいずれによっても許可しないこと |
| REQ-PRE-03 | 常時 | ccnavi は、プロジェクト設定が確認と宣言した対象への操作を、人間の確認を経ずに実行させないこと |
| REQ-PRE-04 | 異常時 | もし操作の対象を一意に確定できないならば、ccnavi は、その操作を許可としないこと |
| REQ-PRE-05 | 常時 | ccnavi は、自身の設定・承認済みチケット・レビュー済みのマーカーを、エージェントの操作によって書き換えさせないこと |
| REQ-PRE-06 | 異常時 | もし設定を読み取れないならば、ccnavi は、組み込みの既定で判定を続け、既定を使ったことを示したうえで、読み取りと設定自身の修復を妨げないこと |
| REQ-PRE-08 | 状態 | 人間に確認できないセッションである間、ccnavi は、確認が必要な操作を許可しないこと。ただし設定がその対象に言及していない呼び出しについては、プロジェクトの設定が委ねると宣言している間を除く |
| REQ-PRE-09 | 常時 | ccnavi は、ある呼び出しへの判定を、その呼び出しの内容だけから決め、その呼び出しを引き起こしたテキストの出どころによって変えないこと |
| REQ-PRE-10 | 状態 | 設定がその対象に言及していない間、ccnavi は、その呼び出しについて扱いを Claude Code の権限モードに委ね、委ねたことを記録に残すこと。ただし REQ-PRE-04 と REQ-PRE-08 に該当する呼び出しを除く |
| REQ-PRE-11 | 事象 | ヒットしたルールがモデルへ渡す文（`additionalContext`）を持つとき、ccnavi は、判定が許可・確認・拒否のいずれであっても、またモードが判定に手を出さないものであっても、その文を判定とは別の経路でモデルに届けること。文を持たないルールでは何も足さないこと。ルールが「1 度だけ渡す文」（`additionalContextOnce`）を持つなら、その文は同じ文脈（セッション、サブエージェントはその起動ごと）では最初にヒットしたときだけ届け、セッションの開始のたびに改めて届けること。両方の文を持つルールでは、初回は両方を、2 回目からは毎回渡す文だけを届けること |
| REQ-PRE-12 | 事象 | ルールがモデルへ渡すファイル（`additionalContextFile` / `additionalContextOnceFile`）を持つとき、ccnavi はそのファイルの本文を対応する文の後ろに並べて届けること。探す先は行き先のワークツリー、その元リポジトリ、ワークスペースルートの順とし、最初に在ったものを読むこと。無ければ何も足さないこと。読むのはワークスペースの中だけとし、絶対パスと上に出るパスは読まないこと。本文は固定の上限で切り、切ったときはそのことと続きの在りかを本文の末尾に添えること |
| REQ-PRE-13 | 常時 | シェルのコマンドが実行役のコマンド（環境変数の代入、`env`・`sudo`・`timeout` など、`sh -c` の文字列、`xargs`・`find -exec` の後ろ）を通して実行される場合、ccnavi は、拒否と確認のルールとサブエージェントの禁止を、中で実行されるコマンドにも適用すること |
| REQ-PRE-14 | 常時 | ccnavi は、中で実行されるコマンドに、許可のルールと、止めている間でも通す形を適用しないこと |
| REQ-PRE-15 | 事象 | 中で実行されるコマンドでルールにヒットしたとき、ccnavi は、ヒットした中で実行されるコマンドを記録に残し、返す文面ではそれを実行した実行役のコマンドとともに示すこと |
| REQ-PRE-16 | 常時 | シェルのコマンドが作業ディレクトリを移したうえで引数やリダイレクトの行き先を書く場合、ccnavi は、移った先から見たパスにも拒否と確認のルールとサブエージェントの禁止を適用し、許可のルールと止めている間でも通す形には適用しないこと。行き先が書かれた文字列から決まらない場合は、移った先を適用する先に足さないだけとし、書かれたパスに対する判定は変えないこと |
| REQ-PRE-17 | 事象 | メインエージェントのターンが終わったとき、共通レイヤーかワークスペース自身のレイヤーに `match` に `Stop` を持ち刻みが 2 以上の許可のルールがあれば、ccnavi はそのルールを数え、渡す回になったときだけターンの終わりを止めて、決まった前置き（タスクの続きではない・振り返りだけをする・ユーザへの問いで終わったならその問いを最後に書き直す・何も無ければ無しと答える）とルールの文を理由として返すこと。本文のファイルはワークスペースルートの版だけを読むこと。プロジェクトのレイヤーの同じ形のルールは使わず、同じ識別子は 1 本として数えること。数えは文脈の入れ替わり（compact・再開・clear）では破棄せず、セッションの起動と後始末でだけ破棄すること。同じ終わりで `finish` かレビュー依頼までの道（REQ-PRE-18）を促すなら、そちらだけを返してルールは数えないこと。Stop の hook が続けさせた終わり、サブエージェントの終わり、数えを覚えられないときは止めないこと。予行（`dry-run`）でも同じく止めること。記録には渡したルールだけを残すこと |
| REQ-PRE-18 | 事象 | メインエージェントのターンが終わったとき、cwd のツリーが承認済みの親（着手済みで、信頼でき、早めに閉じられていない）に結び付いていて、作業中の子が残っているか（子のツリーでは自分の子だけ）、子が全部閉じたのにレビューを要するフェーズに依頼のマーカー（`requested`）がまだ無ければ、ccnavi は、ターンの終わりを止めて、決まった道の途中でユーザの許可は要らないこと・状態に応じた次の一手のコマンド（子の `finish`・合流・ELI5・`request`）・ユーザの判断が本当に要る問いならその問いを最後に書き直すことを理由として返すこと。最後の発言は読まず、状態だけで決めること。同じ状態（親・フェーズ・残っている子・HEAD）では 1 回だけ止め、進めば次の終わりでまた止めてよいこと。同じ終わりで `finish` を促すなら、そちらだけを返してこの促しは出さず覚えもしないこと。この促しで止めるなら、REQ-PRE-17 のルールは数えないこと。依頼のマーカーがある間（変更要求のレビューが残る間を含む）、レビューが要らないか延期したフェーズ、Stop の hook が続けさせた終わり、サブエージェントの終わり、記録を覚えられないときは止めないこと。そのセッションに実行中のサブエージェント（開始して終わっていない。入れ子も数える）が居る間、またその記録を読めないときも止めず、このとき「1 回だけ」の記録を進めないこと。終わりの記録が来ないまま開始から 4 時間を過ぎたサブエージェントと、セッションの起動と再開より前の記録は実行中と数えないこと。compact・clear では実行中の記録を破棄しないこと。予行（`dry-run`）でも同じく止めること |

REQ-PRE-02 と REQ-PRE-03 が信頼境界である。設定はユーザが管理するので信頼し、チケットはエージェントが書くので信頼しない。
チケットの宣言は権限を絞ることしかできない。REQ-PRE-05 が無いと、この境界はチケットを書き換えるだけで消える。

REQ-PRE-06 は REQ-PRE-04 の例外にあたる。拒否にすると、破損した設定を直す操作まで止まり、回復できなくなる。

REQ-PRE-10 は、ccnavi が判定を持たない呼び出しに確認を上乗せしても、同じ呼び出しで 2 度聞かれるだけだから。
除外の 2 つは、どちらも許可にしないためのものである。REQ-PRE-04 では確定できなかった事実が委ねた先に伝わらず、
REQ-PRE-08 では確認に答える者が居ない。REQ-PRE-08 の除外をプロジェクトの設定に開いても、REQ-PRE-04 の除外は残る。
委ねた回の記録は、設定のどこが薄いかを数える手立てになる。

REQ-PRE-09 は、hook の入力に出どころが書かれておらず、出どころを理由にした例外は注入された文からも宣言できるため。

REQ-PRE-11 が判定と別の経路で届けるのは、通す呼び出しにも「これを踏まえて進めろ」を言えるようにするため。
報告するだけのモードでも届ける。

REQ-PRE-18 は、決まった道の途中の確認（「進めてよいですか」）でターンが終わり、ユーザが「進めて」と打つ往復を減らすため。最後の発言の問いを読むと文面の解釈に頼るので、状態だけで見る。問いで終わった回も止めるが、ユーザの判断が本当に要る問いは、促しの文が最後に書き直させるので消えない。`requested` が変更要求の間も残るので、その間は止めない。委任して待つ回を止めると、待つたびに無駄な往復が出るので、実行中のサブエージェントが居る間は止めない。止め損ねた促しは、終わったあとの終わりで出せるよう「1 回だけ」を進めない。開始だけ残った記録が促しを止め続けないよう、期限と起動での破棄を置く。対象はサブエージェントだけで、チームメイトとバックグラウンドのシェルは数えない。

REQ-PRE-13 は、先頭の語に固定したルールやサブエージェントの禁止が `env rm …` のような形で外れるのを防ぐ。
取り出す実行役のコマンドは組み込みの一覧で決まる（REQ-SLF-04 と同じ向き）。

REQ-PRE-14 は REQ-PRE-13 の向きを限る。止める側は適用先を足すだけなので元の形より緩くならないが、
許す側に適用すると、`sudo -u me cat …` が中の `cat …` の許可で通るように緩む。

REQ-PRE-15 は、元の形だけを見た読み手にヒットした箇所を示すため。中で実行されるコマンドでヒットした理由には、
REQ-HNT-04 の断りを付けない。

REQ-PRE-16 は、`cd .claude && echo x > settings.json` のように、移った先の名前が書かれたパスから消える形を塞ぐ。
移った先から見たパスは書かれたパスに足すだけなので、行き先を読み違えてもヒットするはずのものは外れない。
行き先が読めないときも REQ-PRE-04 の扱いにしない。そうすると生の文字列に適用することになり、
`cd - && rm -f <守られた場所>` のように書かれたパスでは止まる形が止まらなくなる。
