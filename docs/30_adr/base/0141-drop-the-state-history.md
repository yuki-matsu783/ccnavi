# ADR-0141: 状態の履歴（events/<識別子>.jsonl）をやめ、状態は置き場とマーカーだけで持つ

状態: 採用（ADR-0086 を置き換える。ADR-0104 の「承認の時刻は状態の履歴を先に読む」という点も改める）

## 状況

ADR-0086 は、チケットの状態の動きを承認済みの領域の `events/<識別子>.jsonl` に 1 行ずつ追記して残していた。履歴は「補助で、判定も状態の操作も読まない」と決めてあった。その後、次のことが分かった。

- 履歴は判定には読まれないが、周りの仕組みが履歴に寄りかかっていた。write-and-push は「履歴への追記だけの変更」を ccnavi が書いたものと見分けて先にコミットし、`ready` の退避は履歴の行を足したり突き合わせたりし、Chrome 拡張は承認のたびに履歴の全文を書いていた。状態を持つものが置き場・マーカー・履歴の 3 つになり、書き込みの失敗も 3 通り考えることになった
- 履歴は親のブランチに入るので、別の PC や Chrome から追記すると同じファイルの末尾がぶつかる。追記の行が混ざる、戻しで行が消える、といった例外を扱うコードが要った
- 履歴を読む側は表示と警告だけだった。ボードの「履歴」、`started` の行が無いことの警告、Chrome の版の名指しは、状態の正である置き場からは組み直せない情報ではない。承認の時刻も `git log` から引ける

「親のブランチの状態からチケットの状態を決める」「別の PC で続きから動かしても動く」ことを目指すと、この追記専用の 3 つめの状態は要らない。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `events/<識別子>.jsonl` を書かない・読まない。`tickets/history.py` を消す | 状態を持つものを、置き場とマーカーの 2 つにする | 書き込みだけ残して読み手を消す |
| ボードの `ccnavi --explain --json` から `history[]`（チケットと `archived[]` の両方）と、`archived[]` の `approved_at` を外す。VS Code のボードのカードの「履歴（N 件）」と案内の手順を消す | 出す元が無い。ボードの列とバッジは元から置き場で決まる | 空で出し続ける |
| 承認済みチケットで `started_at` があるのに履歴に `started` の行が無いことの警告（`status`・`--lint`）を消す | 手で書かれた着手の欄かもしれない、という手がかりが履歴にしか無かった。判定には入れていなかった警告である。基準点が HEAD の祖先でないことの警告（`base_off_head`）は git を読んで残す | 欄の組み合わせから推し量る |
| 承認の時刻は、`doing/<識別子>.md` を足したコミットの時刻（`git log --no-renames --diff-filter=A`）か、コミットが無ければ「未コミット（手で置いた）」。履歴という出どころ（`approved_from: history`）を外す。git を打たない場（Chrome 拡張の Pyodide）では分からない（空）とする | 表示だけの値。ボードと診断が見せるだけで、判定には使っていなかった | 承認の欄をチケットに戻す（ADR-0104 が書き足しをやめた） |
| `lint` が取り込みの後の判定の違いに Chrome の版を名指しする文（履歴の最後の行の `via: chrome` と `version` から引いていた）をやめる | 出どころの履歴が無い。違いそのものは error として今までどおり出る | マーカーに版を持たせる |
| フェーズの終わりの文で、前に依頼したあと続きの子が足されて依頼の記録が外れたことを言い足す（履歴の `phase-reopened` を読んでいた）のをやめる | 文を足すだけの履歴の使い方だった。「依頼し直しが必要」は依頼済みでなくなることから分かる | マーカーを消さずに残す |
| write-and-push の見分け（b）から「履歴への追記だけの変更」を外す。`ready` の退避が動かすのは `done/`・`phases/<親>/`・`flows/` の 3 つにし、`events/` と、退避の側にだけ「退避した」の行を足す処理を外す | 履歴が無いので見分ける対象が無い | 以前の `events/` を引き続き退避する |
| 経路（`via`）とアカウント（`actor`）は、マーカーの JSON に書くために 1 回の起動の間だけ覚える。小さなモジュール `tickets/via.py`（`VIA_*`・`session(via, actor)`・`set_via`・`set_actor`・`actor()`・`via()`）に残す | マーカーの `via`・`actor` の欄は sh と拡張も読むので形を変えない | 欄ごとやめる |
| 履歴が書けなかったときの知らせの仕組みを消す。`fsio` の `FAIL_HISTORY`・`append`・`OP_APPEND`・`utc_stamp`・`view_only`、`CORE_HISTORY_UNWRITABLE`、`unwritten`、Chrome の `_unwritten` | 使い手が居なくなった | 残して将来の追記に備える |
| `core.withdraw` から `reason` を、`Actor` から `version` を外す。承認の取り下げの理由と拡張の版は履歴にしか書いていなかった。拡張の要求の `reason` の欄は受けても読まない | 書き先が無い | マーカーに理由を持たせる |

## 理由

- 判定は元から置き場とマーカーだけで決まっていた。履歴を消しても判定は変わらない
- 別の PC・Chrome・ターミナルから書く経路がどれも、末尾への追記の衝突と失敗の知らせを考えなくてよくなる
- write-and-push の見分けと `ready` の退避が、履歴という形のそろわないファイルを特別扱いしなくなる

## 得たもの・失ったもの

- 得たもの: 状態を持つものが減った。`history.py`（271 行）と、`archive`・`write-and-push`・`fsio`・`core_*` の履歴の分岐、拡張のカードの表示を消せた
- 失ったもの: 「いつ・どの経路で動いたか」を後から読む手段。`git log` が代わりになるが、経路（ターミナル・ボード・Chrome・hook）は分からない。承認の時刻は、Chrome 拡張（Pyodide）では分からない
- 失ったもの: 手で書かれた着手の欄の警告、取り込みの後の判定の違いに Chrome の版を名指しする診断、承認の取り下げの理由の記録
- すでに履歴を書いていたリポジトリでは、コミット済みの `events/*.jsonl` が親のブランチに残る。今後は読まず、書かない。`ready` は、残っていれば手元の退避へ他の記録と同じく移す。不要ならユーザが手で消してよい。古い版の ccnavi や古い版の Chrome 拡張が、更新後に同じ親のツリーへ `events/*.jsonl` を書き足すと、write-and-push は「ユーザの判断が未送信」として止まる。ユーザが確かめてコミットするか消せば進む。新しい履歴を `.gitignore` の `*.jsonl` で外している場合の「`git add` できず止まる」問題は無くなる

## 採らなかった案

- **書き込みだけ残し、読み手（ボード・警告）を消す。** 誰も読まない追記の失敗と衝突の処理が残る
- **履歴を `logs/` に移して手元の機械だけに残す。** 別の PC から見えず、親のブランチを正本にする方針（ADR-0136）に合わない
- **経路もマーカーから外す。** マーカーの `via`・`actor` を sh と拡張が読んでいる。形を変えずに残す
