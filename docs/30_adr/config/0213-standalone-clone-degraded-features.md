# ADR-0213: 単体 clone で縮退する処理の直し方の案

状態: 提案（選択肢を並べた段階で、どれも決めていない）

## 状況

ADR-0145 は、頼るものが無いことを検出して小さい振る舞いに落とすことを「縮退して動く」と定めた。次の処理は、単体 clone やワークスペース内 clone のプロジェクトで、その定義に当たらないか、合わない。いまの動きは、設計書「複数のリポジトリ」の「単体 clone での動作」にある。

- 目録（重さは major）。プロジェクトのスキルと工程スキルの入口の目録は、`project_of` が単体 clone を検出せず、黙って空を返すので出ない。工程スキルのコピーを決めたときの採らなかった案に「単体 clone で目録に載らない」があるが、実装はこれを満たしていない。工程スキルがワークスペース内 clone で目録と `ccnavi --docs` の両方に出る例外もある（`--docs` は 2 件に該当する）
- ミラー（重さは minor から中）。ワークスペースの同期は、プロジェクトのミラーとコピーを共通レイヤーの中身で上書きする。差分は親のワークツリーに出るので、静かにデータが消えるわけではない。単体 clone では、ミラーが共通レイヤーそのもので、ユーザの引き継ぎで編集もできる。「ミラーは誰も編集しない」前提が成り立たず、更新の手段はワークスペース側の同期か setup だけ
- ルールの `{root}`（info）。ワークスペースの中ではプロジェクトのレイヤーのルールでもワークスペースルートを指し、単体 clone ではプロジェクト自身を指す。同じ `^{root}/src/` が形によって別の場所に効く
- レビュー経路の検査（minor）。`--lint` は根の origin だけを見る。ワークスペースに origin が無くプロジェクトにあれば誤って警告し、逆なら漏らす
- ワークツリーの認識（重さは中）。リンクされたワークツリーを元リポジトリとして使う形、`--separate-git-dir` の形は、ワークツリーとして認識されず、`--lint` が「元のプロジェクトがありません」と言い、`ccnavi worktree remove` も断る。ワークツリーの削除側は `git rev-parse --git-common-dir` で元を求めるが、名前が `.git` であることを要求し、認識側は元リポジトリの `.git/worktrees/` しか見ない。後ろの 2 つの形は、コードを読んだだけで再現していない
- 分岐名の先頭の語（minor）。`CCNAVI_BRANCH_PREFIXES` は環境変数 1 つで、ワークスペース内の全プロジェクトに効く
- `ccnavi-user-push-approved.sh` の `given_in`（minor）。根のツリーに対して `projects/` の下を無言で除く。単体 clone が `projects/` を実ディレクトリとして使っていると、その下の `--path` が飛ばされる。取得と git の sh は `.git` の有無を見ているので、実害はここだけ。単体 clone での再現は読んだだけ

## 決定

まだ決めていない。選択肢は次のとおり。

- 目録: `project == ""` の根でも、根に `skills/` があれば目録を出す。または、単体 clone を検出して、決めた小さい振る舞い（案内の 1 行など）に落とす。工程スキルの二重の例外との整理も要る
- ミラー: 単体用とワークスペース用のコピーを印（指紋）で見分ける。または、ミラーがワークスペースの共通と違うときは上書きせず、差を warn して止める
- `{root}`: 注意書きを 1 行足す。またはツリー相対の合言葉（`{home}` など）を足す
- レビュー経路の検査: 承認済みの親の `project` ごとに、そのリポジトリの origin を検査する
- ワークツリーの認識: `git rev-parse --git-common-dir` 相当で元を求める。または `.git` ファイルの gitdir を 1 段読んで比べる
- 分岐名の先頭の語: プロジェクトごとに持つか、ワークスペースで 1 つのままにするか
- `given_in`: `projects/` を別のツリーとして除くのは、その下に `.git` を持つものだけにする

## 理由

どれも、ワークスペースの有無を前提に作った処理が、前提の外で黙って働かない、または別のものを指す点である。静かに間違う側を、止めるか言う側に倒したい。ただし、目録とミラーは機能の置き場に関わるので、ADR-0111 のコピーの決定と ADR-0091 の置き場の決定を見直すかどうかと一緒に決める。

## 得たもの・失ったもの

決めていないので、案ごとの得失を残す。

- 目録を単体 clone でも出す: 単体 clone の利用者にスキルが届く。ワークスペース内 clone との二重の出方を整理する手間が要る
- ミラーを指紋で見分ける: 上書きの事故を避けられる。指紋の持ち方と更新の手順が増える
- ミラーを止めて差を warn する: 実装が小さい。単体で編集したミラーはワークスペースの更新を受けられない

## 採らなかった案

無い（未決のため）。
