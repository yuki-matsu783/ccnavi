# ADR-0174: 導入スクリプトが .gitignore に足す行を目印の領域にまとめ、.claude/worktrees/ も足す。ワークツリーを切る sh は、その置き場を書きかけに数えない

状態: 採用

## 状況

導入スクリプトは配布先の `.gitignore` に、実行ファイルの置き場・`--docs` の索引・`/scratchpad`・`/logs/` の 4 つを、ブロックごとの見出しをつけて足していた。ccnavi が直接作業で作るワークツリーの置き場 `.claude/worktrees/` は足さなかった。最初のワークツリーを切ると、置き場が未追跡のままユーザのチェックアウトに残り、ワークツリーを切る sh は未追跡の新規ファイルを「書きかけ」と数える。2 本目以降は毎回 `--copy-wip` か `--no-wip` の選択と `--accept` の了承が要り、ユーザに確認できない非対話（`claude -p`）では作業に入れなかった。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `.gitignore` に `/.claude/worktrees/` を足す。同等以上の綴りがあれば足さず、`!` の否定があれば足さずに伝える。`--check` では欠けを「揃っていない」に数える。`--bin user` でも足す。`wip/` は足さない | 症状の根にある。実行ファイルの置き場とは関係なく、ワークツリーは配布先に切られる。`wip/handoff/` と `wip/proposals/` は追跡して push するのが設計 | 実行ファイルの置き場に従って足す。`.claude/` を丸ごと無視する（`.claude/settings.json` や skills を追跡する配布先が外れる） |
| 足す行は、目印の行（`# ---ccnavi begin--- …` と `# ---ccnavi end---`）で囲んだ 1 つの領域にまとめる。定数 `IGNORE_REGION_BEGIN`・`IGNORE_REGION_END` に持ち、行全体の一致（`grep -x`）で照合する | 行の種類が増えるたびにブロックの見出しが増え、どこまでが ccnavi の足した行か分からなくなる。1 つの領域なら、ユーザが範囲を一目で区別できる | ブロックごとの見出しを続ける |
| 領域には足すだけにする。領域が無ければ末尾に領域ごと足し、あれば end の直前に足す。領域の中の既存の行は書き換えない。同じコメントが領域にあれば重ねない。領域の外にあるユーザの行と同等なら足さない | 足すだけなら、ユーザが領域の中に入れた行や順序を壊さない。冪等にできる。書き換えや削除は、ユーザの意図を読み違えたときに取り返しがつかない | 領域の中を毎回作り直す |
| begin だけ・end だけ・順序が逆・begin が複数、のような壊れた領域には触らない。行番号と直し方を知らせ、`--check` は「揃っていない」に数える | 壊れた領域に推測で足すと、ユーザの行を領域に巻き込むか、領域が増える | 壊れた領域を直して書く |
| 領域を使い始める前の古い見出しブロックはそのまま残す。領域へ移さない | 移行の処理は、ユーザの行との境目を推測する必要がある。古いブロックの行は、領域の外の行として「あれば足さない」の判定に効くので、二重にならない | 古い見出しを探して領域へ移す |
| 領域の中への挿入は、`awk` で一時ファイルに書いてから元のファイルへ流し込む。足す行は一時ファイルから読む。CRLF のファイルには CRLF で足す | `awk -v` に改行を入れると環境で動きが違う。`mv` で置き換えると実行ビットや symlink を壊す | `sed -i`（BSD と GNU で書き方が違う） |
| 保険として、ワークツリーを切る sh は、`.claude/worktrees/` の下のパスを書きかけ（変更・新規・staged の数と、確認が要るかの判定）から除く | `.gitignore` に行が無い既存の配布先は、setup を再実行するまで症状が残る。置き場は ccnavi 自身が作るもので、ユーザの書きかけではない。除くのはこの置き場だけで、`wip/`・`scratchpad/`・`logs/` は今のまま | 保険を置かず、setup の再実行だけに頼る。`wip/` の ccnavi 自身のファイルまで広く除く（ユーザの下書きとの区別がつかない） |
| `--copy-wip` の候補の木を作る `git add -A` は、`.claude/worktrees` をパス指定で除く（`-- . ':(exclude).claude/worktrees'`） | ワークツリーが 1 本ある状態で `git add -A` すると、他のワークツリーが埋め込みリポジトリ（160000）として木に入ることを確かめた。入ったままだと、新しいワークツリーのスナップショットに他のワークツリーの gitlink が混ざる | 何もしない。`.gitignore` に頼る（行が無い配布先で入る）。この行の直し方は末尾の「追記」にある |

## 得たもの・失ったもの

- 得たもの: 新しく導入した配布先では、2 本目以降の直接作業が確認なしで始まる。既存の配布先も、setup を再実行する前から止まらない。ccnavi が足した行の範囲が `.gitignore` の中で分かる
- 得たもの: ユーザの `.gitignore` の行と順序を変えない。2 回目以降は何も変わらない
- 失ったもの: 古い見出しブロックと領域が `.gitignore` に並んで残る。行の重複は判定が防ぐが、見た目は 2 通りになる
- 失ったもの: 壊れた領域では、setup が何も足さず、人が直すまで `--check` が通らない

## 追記: 除外指定つきの add が、.gitignore 済みの置き場で失敗する回帰

`add -A -- . ':(exclude).claude/worktrees'` は、除外指定に挙げたパスが `.gitignore` に入っていると、git 2.43 では追加を済ませたうえで「ignored by one of your .gitignore files」と出して終了コード 1 を返した。`make_candidate` はそれを失敗と読み、書きかけがあるとワークツリーを切れなくなった（確認の案内も `--copy-wip` も `--no-wip` も「スナップショットを作れませんでした」で止まる）。この決定の setup は置き場を `.gitignore` に足すので、導入した直後の配布先が当たる。

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 一時 index には素の `git add -A` を打ち、そのあと `git rm -r --cached -q --ignore-unmatch -- .claude/worktrees` で置き場を除く。どちらの失敗も `make_candidate` の失敗に数える | 無視あり・なし × 他のワークツリーあり・なしの 4 通りを手で確かめ、どれも終了コード 0 で、木に置き場が入らないことを見た。無視済みなら `add -A` が最初から置き場を足さず、`rm` は何も除かない（`--ignore-unmatch` で 0）。未追跡で無視されていなければ、`add -A` が足した埋め込みリポジトリ（160000）を `rm` が除く。分岐が無いので、判定の食い違いが起きない | `git check-ignore` で見て、無視されていないときだけ除外指定を付ける（分岐が増え、`check-ignore` と `add` の判定が食い違いうる）。`:(exclude,glob).claude/worktrees/**` や `--ignore-errors`（どちらも終了コード 1 のままだった） |

- 得たもの: 置き場が `.gitignore` 済みでも未追跡でも、書きかけがあるときにワークツリーを切れる。置き場は木に入らない
- 失ったもの: 未追跡の置き場では、`add -A` が埋め込みリポジトリを足す警告を出す。出力は捨てており、終了コードは 0
- 除外指定つきの `git add` は、承認の push の sh にもある。そちらの除外指定はワークスペースの下の一時ファイルを glob で除くもので、実在する無視済みのパスを名指ししないので、この失敗は起きない（`.gitignore` 済みでも終了コード 0 を確かめた）
