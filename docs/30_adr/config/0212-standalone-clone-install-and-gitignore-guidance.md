# ADR-0212: 単体 clone の初回導入と、.gitignore・案内文の食い違いの直し方の案

状態: 提案（選択肢を並べた段階で、どれも決めていない）

## 状況

ADR-0145 のもとで、導入と `.gitignore` に関わる処理に、単体 clone やワークスペース内 clone のプロジェクトで合わない点がある。いまの動きは、設計書「複数のリポジトリ」の「単体 clone での動作」にある。

- 初回の導入（重さは初回 blocker。単体 clone に限らず、どの fresh clone にも起きる）。`.ccnavi/bin/` は setup が `.gitignore` に入れるので、clone 直後には無く、全 hook が終了コード 127 で終わってガードが働かない。`CCNAVI_ENTRY_PATH` が設定されているとランチャーの sh が見つかり、互換の食い違いの文面が出るが、原因は「この機械向けの実行ファイルが無い」ことで、案内が違う。ワークツリーを切る sh は別の文面、取得する sh は無言で終わる。ここで言う文面の挙動は、実物の sh を一時ディレクトリで回して確かめた時点のもので、いまの文面は読み直していない
- 互換の食い違いの案内は「ccnavi-setup.sh <このワークスペース> --force」を示す。単体 clone の利用者には該当しない（nit）
- setup が `.gitignore` に足す行は、実行した先だけ。ワークスペース内 clone のプロジェクトに `/.claude/worktrees/` は足されず、単体 clone でも setup を実行しなければ足されない。足されないと `git status` に `.claude/worktrees/` が出て、`ccnavi-git.sh add .` が埋め込みリポジトリの警告を出して gitlink を staged する（重さは minor から中）。ワークスペースの `.gitignore` に `/projects/` も足されず、案内だけが出る
- ワークスペース側の SessionStart が、プロジェクトの追跡ファイル `.gitignore` に `**/ccnavi-index.jsonl` を足すと、未コミットがあると断るプロジェクトの integrate が止まる（minor）。プロジェクトが自前で setup を済ませていれば起きない。追記先を実機で確かめていない
- 単体 clone が自分の `projects/` を実ディレクトリとして追跡していると、`--lint` が「ワークスペースの git が追跡している」という文面で警告する。追跡を外しても「無視されていない」と warn する（minor）。単体 clone でこの警告が出る条件を、実行で確かめていない
- 拡張のプロジェクト管理画面は、`projects/` の無い単体 clone でも、`.gitignore` に `/projects/` が無いという帯を出す。押すと追跡ファイルの `.gitignore` に `/projects/` が入る（nit）。画面のコードを読み直していない

## 決定

まだ決めていない。選択肢は次のとおり。

- 初回の導入: ランチャーが指す `bin/<os>-<arch>/` が空であることを専用の文面で案内し、単体 clone の導入手順（プロジェクトに setup を実行する）を入れる。案内と手順を置く場所（拒否文、`.ccnavi/` の使い方の文書、手引き）は決めていない
- 互換の食い違いの案内: 単体 clone では「このワークスペース」を「このプロジェクト」に出し分けるか、文面を中立にする
- プロジェクトの `.gitignore`: プロジェクト側にも `/.claude/worktrees/` を足すか、案内だけにするか。ワークスペース側の `/projects/` を足すかも合わせて決める
- `**/ccnavi-index.jsonl` の追記: 他のリポジトリの `.gitignore` は書かず、案内だけにする
- `--lint` と拡張の警告: `.git` を持つ子が無ければ黙る、または単体向けに文面を出し分ける。拡張の帯は「置き場のディレクトリがある」を条件に足す

## 理由

どれも、ワークスペースに頼る文面や追記が、頼れない形で出ることを避けるための選択肢である。別のリポジトリのファイルを書かない側に倒すと、利用者に手作業が増える。どちらを取るかは、初回の導入をどこまで ccnavi が面倒を見るかで変わる。

## 得たもの・失ったもの

決めていないので、案ごとの得失を残す。

- 専用の案内を足す: 初回の混乱が減る。文面と置き場が増える
- プロジェクトの `.gitignore` に足す: `git status` の汚れが無くなる。別のリポジトリの追跡ファイルを書く
- 案内だけにする: 他のリポジトリを書かない。利用者が自分で直す

## 採らなかった案

無い（未決のため）。
