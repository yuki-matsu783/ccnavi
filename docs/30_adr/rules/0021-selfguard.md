# ADR-0021: コアファイルはルールの外で守る

状態: 採用

## 状況

実行後チェックの保護領域はルールファイルの `deny` と `ask` から導く（ADR-0017）。だから
ルールファイル自身をそこで守ることはできない。書き換えられた時点で「何を守るか」の一覧ごと
消えるので、`deny` を空にされた形も、壊れて組み込みの既定を使う形も、保護領域は 0 件になり、
実行後チェックは何も検知しない。

## 決定

次のものだけは、ルールファイルの外に組み込みで持つ（`CCNAVI_GUARD_CORE_FILES`）。

守る対象（hook の登録・判定の中身であるルール・設定のレイヤー・判定器の実体）と、バックアップを取る時点の表は、設計書の [8.1 守るもの](../../21_design/self-guard.md) にある。

止める側と戻す側の両方を持つ。コアファイルの保護が有効な間、対象へシェルから書き込む形はルールに
書いていなくても拒否し、実行ファイルとプロジェクトのルールは `Write` / `Edit` からも拒否する。
実行前にバックアップを取り、実行後に突き合わせて、変わっていればバックアップから戻す。バックアップが無いときだけ
git から戻し、そうしたことを報告に書く。

## 理由

保護の根拠を、守られる対象の外に置く（REQ-SLF-04）。

止めるほうが本筋で、戻すほうは止めきれなかったぶんの受け皿になる。戻せるだけでは、実行後に
戻すまでの間、書き換わった設定が有効になっている時間が残る。その間に実行後のイベントごと消されると、
戻す機会が来ない。実行前にも見るのは、`PostToolUse` の登録を消されるとその次の呼び出しから
実行後チェックが動かないため。ただし `PreToolUse` の登録ごと消された場合は ccnavi が一切動かない。
hook の登録を hook 自身で守ることはできない。

実行ファイルだけバックアップを取る時点が違うのは大きさの差による。17 MB ほどのものを呼び出しのたびにコピーすると、
判定を待たせないために置いた仕組みが判定より重くなる。実行ファイルの実体は中身のハッシュで
名前を付けて 1 本だけ置き、セッションの側は参照だけ持つ。突き合わせは大きさと更新時刻。
指定しなければ対象に入らない。置き場を推測して守ると、そこに在る別のファイルを実体として
扱うことになる。

設定ファイルを名指しのツール（`Write` / `Edit`）から守るぶんはプロジェクトのルールに任せてある。
そこは `deny` に 1 行書けば済み、書いたことが読める場所に残る。実行ファイルは置き場が設定で
動くので、ルールファイルにパスを固定できない。

止めるのは書き込む形と場所の組で、場所の名前が出ただけでは止めない。名前で止めると、
いちばんガードを直したいときに、いちばん強く止めてしまう。プロジェクトが同じ id で自分のルールを
書いていれば、組み込みは足さない。書いたとおりに働いているほうが、読んで分かる。

置いていない設定ファイルについては何も言わない。無かったところに現れた場合は言うが、消しはしない。
ユーザが置くこともあるファイルで、消すほうが取り返しが付かない。バックアップは 3 日より長く触られていない
セッションのぶんを次のセッション開始で落とす。件数の上限にしないのは、ユーザの返事を長く待っている
だけのセッションが、他が増えたという理由で戻す先を失わないため。

## 得たもの・失ったもの

- 得たもの: ルールを空にされても、hook の登録・ルール・実行ファイルは戻る
- 失ったもの: `phases.yml` と `risks.yml` はコアファイルの保護の対象に無く、ルールの `deny` で止めている。
  ルールを空にされればそこは緩む
- 失ったもの: `SessionStart` に登録しておかないと、実行ファイルは守られない

## 追記（2026-10-18）

ユーザの発言（`UserPromptSubmit`）の時点で、前のターンの終わりからの変更を基準に取り込む。ターンの間にユーザが
設定ファイルを直したり消したりしても、次のツール呼び出しで戻さないため。エージェントが何も実行していない間の変更は、
ユーザの手によるもので、バックアップから戻す根拠が無い。設定ファイルのバックアップは、このときと実行前に取り、
`SessionStart` では取らない。バックグラウンド作業の完了通知も `UserPromptSubmit` を起こすが、その間に動いたプロセスの
変更はユーザの変更と区別できないので、通知では取り込まない。ユーザが通知の合間に発言したときは区別できず、
その発言までのバックグラウンドの変更も取り込む。得たものはユーザの編集と削除が戻されないこと。失ったものは、
`UserPromptSubmit` に登録しないとこの取り込みが働かないこと。設計は `docs/21_design/self-guard.md` の 8.3。

## 採らなかった案

- コアファイルもルールから導く。上のとおり
- 場所の名前が出たら止める。修復を妨げる
