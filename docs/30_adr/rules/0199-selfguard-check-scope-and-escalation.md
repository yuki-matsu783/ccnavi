# ADR-0199: 自己防衛の照合の範囲に関する補足（失敗した呼び出し・PATH の実体・想定外の複雑さ）

状態: 採用

ADR-0158 と ADR-0021 の補足。どちらの決定も変えない。設計書の自己防衛の節から、理由の文を削ったので、ADR に無かった分をここに残す。

## 状況

自己防衛の戻す側は、実行前に対象の中身をバックアップし、実行後に比べて、変わっていればバックアップから戻す（ADR-0021）。細かいところで、次の 3 つの判断に理由が残っていなかった。

- 失敗した呼び出し（`PostToolUseFailure`）の扱い
- `PATH` にある実行ファイルの実体を守るときの、止める範囲
- 保護の実装中に、想定していない複雑さが見つかったときの扱い（ADR-0158 は、共通のルールファイルが読めない間の修復で、判定の経路に例外を足すと、その例外が攻める入口になるとして、下書きとユーザの取り込みに変えた）

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 失敗した呼び出し（`PostToolUseFailure`）も、成功した呼び出しと同じ照合を行う | 失敗する前に消した・書き換えたものを通すと、次の発言で「ユーザが消した」ものとして受け入れられるため | 失敗した呼び出しは照合しない |
| `PATH` にある `ccnavi` の実体を止める正規表現は、実体のパスの末尾 3 要素で適用する（要素が 3 以下の浅い実体は、区切りで始まる形だけに適用する）。置き場のディレクトリ全体は守らない | `~/.local/bin` への無関係な導入まで止まるため | 置き場のディレクトリ全体を守る |
| 例外的な場面のために判定の経路が複雑になるときは、仕組みで解かない。止めて、人間に直してもらう案内にする。保護の実装中に、想定していない複雑さが見つかったときも、実装で抱え込まず、報告して判断を仰ぐ | 判定の例外を足すと、その例外が攻める入口になり、読み手も経路を追い切れなくなる（攻める入口になる点は ADR-0158） | 実装の中で、例外を足して抱え込む |

## 理由

- 失敗した呼び出しは、ツールがエラーで終わっても、それまでにファイルを消した・書き換えた可能性がある。成功した呼び出しだけを照合すると、その変更が基準に残り、次のユーザの発言で基準を取り直すときに、ユーザの手による変更として受け入れられる。
- `PATH` の実体を守る理由は、守る対象が実行ファイルそのものだから。置き場のディレクトリ全体を守ると、同じディレクトリへの無関係な導入まで止まる。
- 例外を足した判定は、読み手が経路を追い切れない。想定外の複雑さが見つかったときに、実装の側で抱え込まずに報告するのは、その複雑さを仕組みで解くか、止めて人間に任せるかを、人間が決めるため。

## 得たもの・失ったもの

- 得たもの: 失敗した呼び出しの前に起きた変更が、ユーザの変更として受け入れられない。`PATH` のディレクトリへの無関係な導入が止まらない。判定の経路が例外で読めなくなることがない
- 失ったもの: 浅い実体（要素が 3 以下）は、区切りで始まる形だけが対象になる。置き場のディレクトリ全体への書き込みは、実体の名前に当たらなければ止めない
- 失ったもの: 想定外の複雑さが見つかるたびに、実装が止まって人間の判断を待つ

## 採らなかった案

- 失敗した呼び出しは照合しない: 失敗の前に起きた変更が、次の発言で「ユーザが消した」ものとして受け入れられる
- `PATH` の置き場のディレクトリ全体を守る: `~/.local/bin` への無関係な導入まで止まる
- 想定外の複雑さを実装の中で抱え込む: 例外が攻める入口になり、経路も追い切れなくなる
