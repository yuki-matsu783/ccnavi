# ADR-0195: ターンの終わりの報告は、取り込んだ上流のコミットをリモート追跡ブランチで外し、reflog の分類は採らない

状態: 採用

## 状況

ターンの終わりの報告は、ターンの始まりに記録した HEAD から、そのツリーが積んだコミットを数える（ADR-0072）。数えるのは `--first-parent --no-merges` で、マージが持ち込んだコミットはこれで外れる。

一方、`pull --ff-only`・`checkout <上流>`・`reset --hard <上流>` は fast-forward なので、取り込んだ上流の通常コミットは first-parent の列に入る。自分が積んだコミットと区別しないと、ユーザが上流で直した保護領域まで「このターンで自分がコミットした」ものとして報告に並ぶ。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `git log` に `--not --remotes` を足し、リモート追跡ブランチに入っているコミットを外して、未 push のコミットだけを数える | `git log` は 1 回のままで、リモートがなければ数え方は変わらない。リモート追跡ブランチへの依存は単純で、穴も下の表に収まる | reflog を読み、操作の種類（`pull`・`commit`・`reset`）で分類する |

## 理由

reflog の分類を採らないのは、読む git の呼び出しが増え、操作の種類（`pull`・`commit`・`reset`）の判別が増えるわりに、reflog もエージェントが書き換えられるから。

## 残る穴

| 残る穴 | 扱い |
|---|---|
| `git update-ref refs/remotes/origin/x <自作コミット>` や `git fetch . HEAD:refs/remotes/x/y` でリモート追跡ブランチを偽造すると、自作のコミットが報告から消える | 1 手で作れるが、この報告は戻しも止めもしない通知なので許す |
| 同じターンで保護領域をコミットして push すると、リモートに入った時点で数えなくなる | 未 push のコミットだけを数える方針の範囲外。通知なので許し、push は別の経路が見る前提にする |
| `git fetch <url> <branch>` のあと `reset --hard FETCH_HEAD` で取り込んだ上流 | 追跡ブランチが動かないので外れず、自分の変更として数える。`git fetch <remote>` を使えば外れる |
| 別のセッションが同じワークツリーに積んだコミット | 自分のコミットと区別できない |
| 上流の内容を自分で rebase して積み直したコミット（sha が変わる） | 自分のコミットとして数える |

## 得たもの・失ったもの

- 得たもの: fast-forward で取り込んだ上流のコミットが、ユーザへの報告に自分の変更として並ばない。読む git の呼び出しは増えない
- 失ったもの: 上の表の穴が残る。どれも通知としての報告の精度の問題で、戻しも止めも行わない報告なので受け入れる

## 採らなかった案

- reflog で操作の種類を分類する: 読む git の呼び出しが増え、操作の種類の判別が増える。reflog もエージェントが書き換えられるので、穴は塞がらない
