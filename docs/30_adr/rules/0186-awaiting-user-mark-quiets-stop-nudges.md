# ADR-0186: 最後の行の目印でユーザの返事を待つと宣言した回は、作業の流れの Stop の促しを控える

状態: 採用

## 状況

Stop の決定的な促し（`finish`・依頼までの道・フィードバック計画・直接作業の `integrate`）は、状態だけで決まり、最後の発言を読まない（ADR-0120。AI 判定だけが読む例外は ADR-0153）。

直接作業で、エージェントが結果を報告し「どちらで進めますか」とユーザに決めてもらう問いで終えた回に、`integrate` の促しが止めた。促しの文は「まだ続けるなら、続ける理由をユーザに向けて書いてから終える」と言うので、エージェントは直前の返事の「決めてほしいこと」を言い直して、もう 1 回出力した。ユーザからは同じ内容が 2 回出たように見える。待つ理由は既に書かれており、2 回目は何も足していない。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 最後の発言の、空でない最後の行が `<!-- awaiting-user -->` だけなら、`finish`・依頼までの道・フィードバック計画・`integrate` の 4 つの促しを出しも数えもしない（「1 回だけ」の記録も進めない） | 問いの有無を文面から解釈せず、エージェントが書く決まった目印だけを見る。解釈に頼らない点は ADR-0120 の考え方を保つ。記録を進めないので、目印の無い次の Stop では同じ状態でも促せる | 最後の発言の末尾が問いかどうかで決める。言い回しで外れる（ADR-0120 で落とした案） |
| 目印は HTML コメントの形 | ユーザの画面に出ても目立たず、トークンが少ない | `[ccnavi:awaiting-user]` のように読める形。毎回の出力に残って目に付く |
| 最後の発言は Stop の入力の `last_assistant_message` から読む。欄が無ければ目印が無いものとして促す | Claude Code が Stop の入力に載せることを `claude -p` で確かめた。transcript を読む経路を足さずに済む | transcript の末尾を読む。読み方の不確かさ（書きかけの行・サイドチェーン）を抱える |
| 目印を忘れた回は今までどおり促す | 目印は控えるための申告で、無いときの振る舞いは変えない | 目印が無ければ促しを強める。忘れただけで往復が増える |
| サブエージェントの結果の促しと `match: Stop` のルールは、目印があっても変えない | 前者はユーザに知らせたい事実で、後者はユーザが書いた決まり。どちらも作業の流れの次の一手ではない | 全部の促しを控える。範囲外の変更の知らせが、エージェントの申告で消える |
| 目印の書き方は、直接作業のワークツリーを切ったときの次の一手（`NEXT_WORKTREE_EDIT`）でエージェントに渡す | 促しが出る作業に入るときに 1 度渡せば足りる。セッション開始時の決まりに足すと、促しの無いセッションでも毎回トークンを使う | セッション開始時の決まり（`.ccnavi/CCNAVI.md`）に書く |

## 得たもの・失ったもの

- 得たもの: ユーザに問いを出して終えた回に、同じ内容を言い直す 2 回目の出力が出なくなる
- 失ったもの: エージェントが目印を付けすぎると、作業の流れの念押しが出ない。促しは保護ではなく、取り込みの確定は発言をまたぐ関門（ADR-0180）が守るので、失うのは念押しだけ
- 失ったもの: 目印の書き方は直接作業のワークツリーを切ったときにしか渡さない。チケット作業だけのセッションでは、エージェントが目印を知らず、`finish`・依頼までの道・フィードバック計画の促しは今までどおり出る
- 失ったもの: 目印がある回は、`integrate` の前提を満たせない理由（`systemMessage`）も伝えない。次の目印の無い Stop で伝える
- 失ったもの: `last_assistant_message` を載せない版の Claude Code では、目印が効かない

## 採らなかった案

- 促しの文に「直前の返事で理由や問いを書いていれば、何も足さずに終える」と足す。止めること自体は残り、エージェントが何も書かずに終えても空の 2 回目のターンが走る
- 最後の発言を AI 判定（ADR-0153）に読ませる。決定的な促しの判断に LLM を挟むことになり、重い
