# ADR-0114: チケット制御が有効な間は生の git を組み込みで止め、土台の deny を表記違いに強くする

状態: 採用（生の git の止めの条件と、共通レイヤーの `raw-git` の扱いは [ADR-0131](0131-raw-git-always-builtin-no-common-sample.md) で覆す）

## 状況

見直しで 2 つ分かった。

1. **生の git を止めるのが共通ルールだけだった。** `ccnavi-git.sh` の中には、チケット制御の可否がある
   （承認済みチケットの置き場を別のコミットの中身に戻す `restore` / `checkout` を通さない、`integrate` で直接作業だけを
   取り込む、子のワークツリーから `push` しない、親のブランチへ移るときに承認済みチケットを運ぶ）。どれも、ラッパーの外から
   生の git を打てれば外れる。生の git を止めていたのは共通ルールの `raw-git` だけで、共通レイヤーは置かなくてよい（REQ-MLT-40）。
   ccnavi 自身の約束がユーザの設定しだいで消えていた
2. **土台の deny が glob の文字列一致だった。** `*git push*`・`*git reset --hard*`・`*rm -rf *` は、
   `git -C . push`・`git --no-pager push`・`git -c x=y reset --hard`・`git --git-dir=.git push`・`rm -fr`・`rm -r -f`・
   `rm --recursive --force`・`rm -f -r` にヒットしなかった（実測）。共通ルールの `recursive-delete` も同じ glob だった

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| チケット制御が有効で、ワークスペースルートに `.ccnavi/scripts/ccnavi-git.sh` があるとき、生の git を組み込みの deny（`builtin-ticket-raw-git`）で止める | ラッパーの中の可否を外させないためで、P4 の「ガード自身を守るもの」に数える。ユーザがこれを組み込みにすると決めた | 共通ルールの `raw-git` だけに頼る。共通レイヤーを置かないワークスペースで約束が外れる |
| 置き場はチケット制御の組み込み（`ticket_guard`）。judge が状態の置き場を守る組み込みと同じ条件で足す | 足す条件がチケット制御の有無で、守る対象もチケット制御の可否。設定に依らない土台（`builtin.base_data`）は条件を持たない | 土台に入れる。チケット制御を切ったワークスペースでも生の git が止まり、ラッパーを持たない配布先で git を打つ道が無くなる |
| 式は共通ルールの `raw-git` と同じ（`(^|[^\w.-])(\S*[\\/])?git(\.exe)?\s`）。文面はラッパーの打ち方を名指しする（P8） | 誘導先の `ccnavi-git.sh` にヒットしない形が既に確かめてある | — |
| 土台と同じく、共通レイヤーの `raw-git` にもヒットした回はそちらだけを言う | 拒否は変わらない。同じ拒否を 2 つの文面で返さない | 両方言う |
| ルールファイルが読めずに組み込みの既定へ戻った間も足す | 設計書のルールの「ルールが読めないとき」の節の既定が取り返しの付かない操作に絞るのは、ルールの一覧が信用できない間に広く止めると、止まった理由をユーザが確かめられないため。この 1 本は一覧の外の組み込みで、文面が理由と道を言う。チケット制御のほかの組み込み（状態の置き場・承認の経路）も既定の間に足している。ラッパーはルールファイルを読まずに動き、衝突の解決に要る `add`・`restore --ours` / `--theirs`・`merge-file -p` を通すので、REQ-PRE-06 の「設定自身の修復を妨げない」は保たれる | 既定の間は権限モードに委ねる。確認の出ないモードでは、ルールファイルが読めない間だけラッパーの可否が外れる |
| 共通ルールの `raw-git` は残す | チケット制御を切ったワークスペースでも、出力の量と `Bash(git diff:*)` の前方一致の穴の理由で止めたい | 組み込みと重なるので消す |
| セッション開始の作業の決まりの git の行は、この組み込みがヒットするときも出す | 判定と文を揃える（REQ-SES-06） | ルールがあるときだけ出す。止めるのに決まりを言わない |
| 土台の `builtin-git-push`・`builtin-git-reset-hard`・`builtin-recursive-delete` を regex にする。git はグローバルオプション（`-C <path>`・`-c <k=v>`・`--git-dir[=]`・`--work-tree[=]`・`--no-pager` など）を読み飛ばし、`reset` は後ろのどこかの `--hard`（略した形も）を見る。rm は再帰と強制の組を、まとめた形・分けた形・順序・長い形を問わずに見る | 表記違いで外れると、取り返しの付かない操作が止まらない | glob を並べて足す。組み合わせが尽きない |
| rm の式は、語を「再帰でも強制でもない語」「強制でない語」「再帰でない語」に分けて読む | ルールの regex は先読みを使えない。どの語でも読み飛ばせる形は、ヒットしない長いコマンドで語の数の 3 乗の後戻りになった（3000 語で数十秒以上） | 先読みを許す。ルールファイルの制約と土台が分かれる |
| 共通ルールの `recursive-delete` も同じ式にする | 土台と共通ルールでヒットする形が違うと、どちらの文面が出るかが表記で変わる | glob のまま。表記違いは土台の英語の文面で止まる |

ADR-0077 の P13 との関係: 生の git を組み込みで止め、git の入口を `ccnavi-git.sh` の 1 本に寄せたので、そのラッパーの中の可否の判定を
一次の判定として sh に置けるようになった。この例外の書き方は別の ADR で決める。

## 得たもの・失ったもの

- 得たもの: 共通レイヤーを置かない・壊したワークスペースでも、チケット制御の可否がラッパーの外から外れない
- 得たもの: `git -C . push`・`rm -fr` などの表記違いが、共通レイヤーの有無によらず止まる
- 失ったもの: **チケット制御が有効でラッパーのあるワークスペースでは、生の git を打つ道がルールで開けられない。** 開けるにはチケット制御を切る
- 失ったもの: ルールファイルが読めない間も、生の git が確認にならず拒否になる。直すときはラッパーの `add`・`restore --ours` を使う
- 失ったもの: `git -C push status` のように、値の位置に `push` という名のパスを置いた形も止まる（止めすぎる側）
- 失ったもの: 別名（`git config alias.p push` の `git p`）と、変数で組んだコマンド名は見ない。後者は書き直しを求める形として別に止まる

## 採らなかった案

- **ラッパーが無いときも止める。** git を打つ道が 1 つも残らない
- **`CCNAVI_GUARD_CORE_FILES` で切れるようにする。** 守る対象はチケット制御の可否なので、切る口はチケット制御に揃える
