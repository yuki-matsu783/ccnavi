# ADR-0197: 生の文字列の > が 50 個を超えたら、保護を適用せずに権限モードに依らず止める

状態: 採用

## 状況

コマンドを読み切れなかった Bash と、読まない PowerShell は、生の文字列に対して保護を照合する。生の文字列には、リダイレクトとそうでない `>` の区別が無い。シェルから書き込む形の保護は、`>` ごとに、その後ろの空白の無い語を読む。

照合の時間は、`>` の個数 × その後ろの空白の無い語の長さで伸びる。上限が無いと、`>` が増えるほど長さの 2 乗に近づく。

判定の期限は 3 秒で、超えると `deadline-exceeded` の block（終了コード 2）になる。この block は理由を返せない。

## 決定

| 決めたこと | なぜ |
|---|---|
| 生の文字列に `>` が 50 個を超えて含まれるときは、シェルから書き込む形の保護を適用せずに、`DENY_REDIRECT_LIMIT` で止める | 上限の下でも照合は `>` 50 個 × 尾の長さで伸びる（照合だけで 100KB で約 0.5 秒、400KB で約 1.8 秒）。上限は、これを長さの 50 倍の線形に抑える |
| 権限モードに依らず止め、確認には回さない | 上限は止める側のまま、Write / Edit で書くかコマンドを分ける案内を付けて返すためのもの。期限を超えた block と同じく止める側に置いたまま、理由を返せるようにする |
| ほかのルールの `deny` と `ask` には今までどおり適用し、`deny` にヒットすればそのルールの `deny` のまま。`allow` には適用しない | 上限は、保護を適用しなかった回を止めるためのもので、ほかのルールの判定を変えない |
| 上限を掛けるのは、外す保護（ガード自身の設定とチケットの置き場を守る組み込み）がそのツールにヒットするときだけ | 照合が遅くなるのは、この保護の照合だけ |

## 理由

- 上限が無いと、`>` を並べるだけで照合が長さの 2 乗に近づき、期限を超える。期限を超えた block は理由を返せず、書き直し方も案内できない。
- 上限を置けば、照合の時間は線形に収まり、止める場合も理由と書き直し方（Write / Edit で書く、コマンドを分ける）を返せる。
- 上限を超えた回は保護を適用していないので、確認に回さず止める。確認に回すと、保護を適用していない呼び出しの判断をユーザに預けることになる。確認に答える者が居ないモードでは、誰も答えないまま通る。
- 個数で切るのは、語の長さに上限を置くと、長いパスの末尾の `.ccnavi/…` を見落として通るから。

## 得たもの・失ったもの

- 得たもの: 照合の時間が `>` の個数と尾の長さの積で伸びる範囲が、`>` 50 個までに抑えられる。上限を超えた入力は、理由と書き直し方つきで止まる
- 失ったもの: `>` を 50 個を超えて含む読み切れない入力は、中身に関わらず止まる。Write / Edit で書くか、コマンドを分ける必要がある
- 上限の下でも、尾が長い入力は照合に時間がかかる（上の計測値）

## 採らなかった案

- 上限を置かない: `>` の個数が増えるほど照合が長さの 2 乗に近づき、期限を超えて、理由を返せない block になる
- 期限を超えた block に任せる: 理由も書き直し方も返せない
- 上限を超えた回を確認に回す: 保護を適用していない呼び出しの判断をユーザに預けることになり、確認に答える者が居ないモードでは誰も答えないまま通る
- 語の長さに上限を置く: 長いパスの末尾の `.ccnavi/…` を見落として通る
