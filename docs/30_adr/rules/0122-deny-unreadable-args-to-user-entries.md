# ADR-0122: 2 段目の無いユーザの入口は、引数を読み切れなければ止める

状態: 採用（`ccnavi-sync.sh --forget` は ADR-0142 が廃止し、放棄した親の記録を消す `ccnavi worktree retire --abandon <親>` に置き換えた。止める対象は `--forget` から `--abandon` に移り、実行ファイルの `worktree retire` の形の読み切れない引数として止める。ADR-0143 が承認の経路の判定を `user` の入口へ引き継いだ）

## 状況

2026-10-11 の再確認で、ユーザがターミナルで打つ入口のうち次の 3 つが、引数を組み立てるだけで hook を抜けていた
（判定は ask（UNDECLARED か PARSE_UNCERTAIN）で、権限モードが auto / bypass なら実行される）。

| 入口 | 抜けた形の例 | 2 段目 |
|---|---|---|
| `ccnavi-review.sh decide --choices` | `--cho${X}ices`・`${C}ices`・`--cho*`・`--ch[o]ices`・`sh -c` の中の `${X}`・`xargs -a` | 無い。ボードの経路で、ターミナルを求めない |
| `ccnavi-sync.sh --forget` | `--for${X}get`・`--f*`・`bash -c` の中の `${X}`・`xargs`・`sh < /dev/null …`・`busybox sh …` | 無い。実行ファイルを起動せず、sh が取り込み状態を消す |
| 実行ファイルの `--agree --yes` / `--reviewed … --yes` | `--agr${X}ee --y${X}es`・`--agr*ee --y*`・`busybox sh` / `sh < /dev/null` 越しの launcher・`xargs -a` | 無い。`--yes` はターミナルを求めない |

止めていたのは、文字として並んだ表記を見る 2 つ（`human_path_form` の文字列の組と、組み込みの script 節の
コマンドの位置の正規表現）だけだった。ADR-0093 は「deny の表記の抜け」（変数の展開・`cat … | sh -s`）を、
ADR-0080 は「表記を組み立てて隠す形」を受け入れていたが、どちらも実行ファイルのターミナル要求という 2 段目が
あることが前提だった。上の 3 つにはそれが無い。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 3 つの入口に、`$`・バッククォート・glob 文字（`*` `?` `[`）・`find -exec` の `{}` を含む引数があれば、`DENY_TICKET_APPROVAL_CLI` で止める（`phase_forms.hidden_user_entry`） | 実行の時点まで値が決まらない引数は、hook には読めない。読めなければ拒否する（設計 1.3） | 展開を含む表記を個別に並べる。分け方はいくらでも作れる |
| 実行ファイルは、展開を含む語があり、承認のオプション（`--agree` / `--approve` / `--reviewed`）と `--yes` が文字か展開でどちらもそろいうるときに止める。`--guard-ticket-approval` になりうる語も止める | 実行ファイルはほかのサブコマンドが多く、全部を止めると `--docs` も打てなくなる。ターミナルを求めない枝は `--yes` だけ | 実行ファイルへの展開を全部止める |
| 入口を引数を外から流し込む実行役（`xargs`）で起動する形、標準入力から読むシェル（`sh -s`・`cat … \| sh`）で名前が出る形、入口を `<` で読ませる形は、名前が出た時点で止める | 何が渡るかがコマンド行に無い | 流し込む中身を追う |
| 入口はコマンドの位置で探す。前に置けるのはシェル・`busybox`・`.`・シェルの選択肢・リダイレクト・代入だけ。実行役のコマンド（`env`・`sh -c`・`xargs`）は shellread が外した層で見る | `sh -x`・`sh < /dev/null`・`busybox sh` を挟んでも外れず、`git log --grep ccnavi-sync.sh` のように文字列として出るだけの形にはヒットしない | 生の文字列の全体で探す（`human_path_form` の方式）。名前を引数に書いただけの形まで止まる |
| 走査が止まる形（バッククォート）は、生の文字列の語で探し、位置を見ない | 読めなければ止める側に倒す | 通す |
| 止めた文は「値を変数や glob で組み立てず、そのまま書く。承認・受け入れはユーザがターミナルで打つ」を案内する | 正当に値を変数で渡した場合（`ccnavi-sync.sh "$P"`）も止まるので、次の一手を示す（P8） | 文面を分けない |

文字として並んだ `--forget` を `busybox sh` や `sh < x` の後ろに置く形も、同じ関数で止める。script 節がヒットする形は
script 節に任せ、文面を 1 つにする。

## 得たもの・失ったもの

- 得たもの: 2 段目の無い 3 つの入口では、表記を分けても値を組み立てても、ユーザの判断をエージェントが出せない
- 失ったもの: **値を変数で渡す正当な書き方も止まる。** `sh ccnavi-sync.sh "$P"`、`ccnavi-review.sh decide "$N" --preview`、
  `ccnavi-launcher.sh --docs "$T"` は止まり、値をそのまま書き直すことになる（1 手増える）
- 失ったもの: ccnavi の名前を持たない呼び出しは見ない。名前を変えたコピー（`/tmp/cc --agr${X}ee --yes`）と、
  入口の名前そのものを組み立てる形（`ccnavi-rev${X}iew.sh` は `DENY_COMMAND_NAME_EXPANSION` が止める）、コマンド行全体を
  変数に入れて `sh -c "$CMD"` で走らせる形は、ADR-0093・ADR-0080 の受け入れのまま
- 失ったもの: 擬似ターミナル（`script -qc`）でターミナル要求を満たす形は、この決定の外にある

## 追記: 組み立てうるときだけ止める（2026-10-11 の敵対的レビュー）

最初の決定は、展開を含む語が 1 つでもあれば止めていた。読むだけの形と、引数でない語まで止まっていた
（`ccnavi-sync.sh --preview $X`・`decide --preview $X`・`ccnavi --agree --preview $X`・`2>$LOG`・`> out-$$.txt`・
`ccnavi --docs "$Q"`・`--test Bash "$C"`・`--docs --text '*'`）。一方で、標準入力に流す文字列の中の入口の名前
（`echo "sh …ccnavi-sync.sh --forget i1" | sh`・`printf '…decide 3 --choices x' | bash`）は語として現れないので、通っていた。
止める操作を「組み立てうるか」で決め直す。

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `ccnavi-sync.sh` は、1 つ目の引数（空に展開しうる語は飛ばす）が `--forget` になりうるときだけ止める | sh は 1 つ目の引数だけを `--forget` と読み、ほかの `-` で始まる語は断る。`--preview $X` は `--preview` を断って終わる | 展開を含む語が 1 つでもあれば止める |
| `ccnavi-review.sh decide` は、`--choices` になりうる語があるときに止める。文字どおりの `--preview` があれば通す | sh は `--preview` と `--choices` を一緒に受けない | 同上 |
| 実行ファイルは、展開を含む語より前（`--` の前）に診断のオプション（`--docs`・`--test`・`--lint`・`--explain`・`--suggest`・`--version`・`--help`）か、実行ファイルの知らないオプション（`--list` など）があれば通す。文字どおりの `--agree --preview` も通す | 診断の経路は承認の経路より先に分かれる。知らないオプションは使い方の誤りで、何も動かさない。`--agree --preview` に `--yes` が来ても実行ファイルが断る。展開より後ろのオプションは、展開が `--` になるとオプションでなくなるので数えない | 診断を全部止める（ccnavi-config スキルの `--test` が書けない） |
| 実行ファイルが知っているオプションの一覧（`phase_forms.EXE_OPTIONS`）は、`ccnavi --version --json` の `flags` とテストで比べる | オプションを足して一覧を直し忘れると、新しいオプションが「知らないオプション」として通す側に入る | 実行ファイルの引数の定義を判定から読む（hook の起動が重くなる） |
| 単引用符の中と `\` を付けた `$`・バッククォート・glob 文字、二重引用符の中の glob 文字は、文字どおりの値として読む | シェルが展開しない。置換・ヒアドキュメント・`$'…'`・閉じない引用符を含むコマンド行は置き換えず、止める側に倒す | 引用を見ない |
| リダイレクトの演算子と行き先は、入口の引数として数えない | 入口に渡らない | 数える |
| 標準入力から読むシェル（パイプの先の `sh`・`bash`、`sh -s`、`sh /dev/stdin`、ヒアドキュメント、ヒアストリング）があれば、コマンド行の文字列のどこかに入口の名前があるだけで止める | 流し込む文字列の中は語として読めない。ADR の「名前が出た時点で止める」を、語ではなく文字列で見る | 流し込む文字列を読み直す（`echo` の展開・`printf` の書式まで追うことになる） |
| 止めた文は、止めた語が何になりうるか（`--forget`・`--choices`・承認のオプションと `--yes`・`--guard-ticket-approval`）と、通る形（識別子をそのまま書く・`decide <N> --preview`・診断のオプションを前に置く・`--agree --preview`）を言う | 止まった理由が読めないと、診断なのに止まった理由を探しに行く（P8） | 文面を分けない |

これで、上の「失ったもの」のうち `ccnavi-launcher.sh --docs "$T"` と `decide "$N" --preview` は通るようになった。
`ccnavi-sync.sh "$P"` は 1 つ目が `--forget` になりうるので、引き続き止まる。先の 46 形（変数・glob・`xargs`・`sh -s`・
`busybox sh` などで組み立てる形）は引き続き止まる（tests/ticket/test_ticket.py）。

## 追記: 前置きの対応漏れと、名前の誤検知（2026-10-11 の再レビュー）

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `uv run`・`uvx`・`pipx run` を、`env`・`timeout` と同じく入口の前置きとして読む。後ろに入口の名前があれば、間の選択肢と値は読み分けずにコマンドの位置とみなす | shellread の実行役に入っていないので、`uv run ccnavi --agree 3 $Y`・`uv run sh …ccnavi-sync.sh --forget P` が確認（handover）に落ちていた | `uv run` の選択肢を全部読み分ける |
| 標準入力から読むシェルがあるときに数える入口の名前は、実行される語として現れるものだけにする。流し込む文字列はコマンドの切れ目と引用符で切り、頭の前置き・代入・選択肢を飛ばした語を見る。実行ファイルの名前（`ccnavi`）は、コマンド行の語としてもコマンドの位置に立つときだけ数える。sh の入口（`ccnavi-sync.sh` など）は、ファイルとして渡すだけで中身が流れ込むので、語として出れば数える | 実行ファイルの名前を部分文字列で探していたので、`cd /home/user/ccnavi && echo ls \| sh`・`echo hi \| bash # ccnavi`・`sh -s -- ccnavi` まで止まっていた（前の追記で入った後退） | 部分文字列で探す |

限界（止めない形）: 別の言語の中で入口を組み立てる形（`python3 -c 'os.system("ccnavi --agree --yes …")'` など）は、言語ごとの読み方が要るので
見ない（設計 12.1）。実行ファイルのターミナル要求（2 段目）がある `--agree` 単独の形はそこで止まる。

## 追記: PR 前の敵対的レビューの指摘（2026-10-11）

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| shellread が実行役を外した層（`sh <入口> '$X'` の `<入口> $X`）は、語が外側のコマンドの後ろ側と同じなら、単引用の印の残った外側の語で読む。`sh -c '…'` の文字列を読み直した層は外側と並びが合わないので、組み直した語のまま読む | 層は引用を外して組み直してあるので、単引用の値（`sh …ccnavi-sync.sh '$X'`・`decide 3 '$C'`・`decide '$N'`）が展開に見えて止まっていた。上の「単引用符の中は文字どおりの値として読む」に反する後退だった。`"$X"`・引用なしの `$X` は従来どおり止まる | シェルがスクリプトを実行する層を足さない（置換の中身の `sh <入口> $X` は外側の読みに並ばないので、層が無いと見落とす） |
| 標準入力から読むシェルの見分けで、`--norc` のような長いオプションと値を取るオプション（`--rcfile <値>`・`-o pipefail`・`-O extglob`）を読み飛ばし、前に置いた `env`・`command`・`exec` を外す（ADR-0121 の同じ日の追記と同じ関数） | `echo "sh …ccnavi-sync.sh --forget i1" \| bash --norc` が確認に落ちていた | 既知のオプションだけを並べる |
| 実行ファイルが知っているオプションの一覧（`phase_forms.EXE_OPTIONS`）に、`ticket new` が足した `--title`・`--plan`・`--issue` を足す | 一覧に無いオプションは「実行ファイルが断る」として通す側に入る。`ccnavi --title t $A` が、`A` に承認のオプションと `--yes` を入れると承認になりえた | 一覧の扱いを変える（一覧とパーサーの食い違いは既存のテストが検知する） |

## 採らなかった案

- **`decide` を `--preview` 以外まるごと止める。** `decide` の語が残る限り止まるが、`--forget` と実行ファイルの `--yes` は救えない
- **`--forget` を実行ファイルへ移し、ターミナル要求を付ける。** 2 段目ができ、sh が状態を消す判断を持つ形（P13）も解けるが、
  擬似ターミナルの穴が残るうえ、sh と実行ファイルの契約と配布物が変わる
