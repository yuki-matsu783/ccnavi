# ADR-0191: 付き添いのあるセッションでは、確定の前に発言を待たず、組み込みの確認（ask）でユーザの了承を取る

状態: 採用

## 状況

ターン分離の関門（ADR-0180）は、`integrate` のあとにユーザの発言が 1 回はさまるまで `integrate-done` を拒否する。差分を見せずに確定する実害を止めるための決定で、非対話（`claude -p`）では他に守る手段が無かった。

対話のセッションでは、この関門は 1 往復を足す。ユーザが同じ発言の中で「取り込んで」と頼んでいても、確定は次の発言のあとになる。一方、対話のセッションには別の手段がある。ユーザの確認ダイアログ（ask）は、エージェントが迂回できず、許可されない限りコマンドが実行されない。直接作業の取り込み先や状態の了承（`--base`・`--accept`・`--side-by-side`・`--adopt`）は、すでにこの手段で取っている。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 関門の宣言に `ask_if_attended` を足す。立てた宣言は、付き添いのあるセッションで、B を発言を待たずに組み込みの確認（ask）に出す | 確認ダイアログの許可は、エージェントの操作とは別のユーザの操作で、ADR-0180 が置き換えたかった「見せて返事を待つ」を機械で確かめる事実になる。同じターンのうちに確定でき、往復が増えない | 全セッションで ask に置き換える |
| 付き添いのないセッション（`CLAUDE_CODE_SESSION_ATTENDED` が `0`）では、これまでの発言を待つ関門のまま | 確認に答える人が居ないので、ask は拒否になる。関門が守りの本体として残る必要がある。付き添いの有無の判定は、他の ask の理由文と同じ 1 か所（`ccnavimd.unattended`）にある | 非対話でも ask に任せる |
| 同じコマンドに A（`integrate`）と B（`integrate-done`）を並べた呼び出しは、付き添いの有無によらず止める | ダイアログに出るのはコマンドだけで、差分は出ない。差分を見せる前に確定する形を、ask に頼らず塞ぐ | 並べた形も ask に出す |
| サブエージェントの呼び出しは、付き添いのあるセッションでも確認に出さず、発言を待つ関門のままにする | 確認で先に返すと、後段のサブエージェントの禁止に届かず、本来拒否で終わる呼び出しがユーザの許可 1 つで通ってしまう。変更前と同じく、禁止に届く | 対話ならサブエージェントも確認に出す |
| 対話では A の記録を残さず、B の側で記録を読まない | 発言を待つ関門を働かせないので、記録は使われない。残すと、消えない記録が溜まる | 記録を残して使わない |
| 宣言は組み込みの表に置き、`rules.yml` には書かない。ask の判定は、ルールより先、関門の位置で返す | ユーザの了承の関門を、配布先のルールファイルで外させない。ルールが `allow` と書いていても、確認は出る | `rules.yml` の `ask` に置く |
| ask は `dry-run` でも出す（関門の分類） | 発言を待つ関門が `dry-run` でも止めるのと同じ。ユーザの了承は、予行でも省かない | `dry-run` では報告だけにする |
| ask の理由は、確認の前に差分と変わるファイルを文章でユーザに見せておくよう、次の一手で言う | ダイアログが見せるのはコマンドだけ。差分を見せる約束は、手順書と文面に戻る | 差分をダイアログに載せる |

## 得たもの・失ったもの

- 対話のセッションでは、確定までの往復が 1 回減る。ユーザの許可は確認ダイアログの 1 操作になる
- 守る事実が変わる。発言を待つ関門は「ターンが 1 回終わり、ユーザが 1 回発言した」ことを確かめたが、確認は「ユーザが許可の操作をした」ことを確かめる。どちらも、ユーザが差分を読んだことは保証しない。ダイアログは差分を出さないので、見せる約束は文面とエージェントの手順に依る
- **未検証の前提がある。** フックの ask が、`bypassPermissions` などの確認を飛ばす権限モードでも確認ダイアログを出すかは、公式の文書に明記が無く、実機でも確かめていない。auto モードでは確認を強制すると文書にある。他の ask ルール（`direct-worktree-confirm`）が同じ前提に立っているので、この決定も同じ前提を共有する。確認を飛ばすモードで ask が素通りするなら、そのセッションでは `integrate-done` の前の了承が失われる。実機で確かめて、素通りするなら権限モードで関門に戻す
- ask の判定を返した呼び出しは、失敗の連続として数えない（拒否ではないため）
- 確認は、ルールファイルの `deny` より先に返る。`integrate-done` を `deny` に書いたユーザ設定は、対話では確認に変わる。許可はユーザの操作なので、許容した
- 対話で `integrate` を打ったセッションを、同じ状態のまま非対話に切り替えると、`integrate` の記録が無く、発言を待つ関門は働かない。そのときの判定はルールに任せる。同じセッションの切り替えは稀なので、記録を常に残す案は採らなかった

## 採らなかった案

上の表の「採らなかった側」の列にある。これに加えて、`AskUserQuestion` ツールで了承を取る案は、エージェントが自分の判断で呼ぶので、呼ばれたことを機械で確かめられず、ADR-0180 が置き換えた約束に戻るため採らなかった。ユーザが事前に自分のスクリプトで同意を記録する案は、チャットを離れる手間が増えるため、今回は採らなかった。
