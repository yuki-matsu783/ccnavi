# ADR-0202: ルールの本体を、組み合わせ条件 when でも書けるようにする

状態: 採用

## 状況

ルールの本体は `glob` か `regex` の 1 本の式で、除く側は `except` で書く。`except` は「A だが B は除く」しか書けない。
「A か B」「A かつ B」は、1 本の式に詰めることになる。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 本体を `when` でも書けるようにする。ルールは `glob` / `regex` / `when` のちょうど 1 つを持つ。ノードは `glob` / `regex`（個別条件）、`all`、`any`、`not` のどれか 1 つのキーだけを持つ | 「A か B」「A かつ B」を、個別条件に分けて書けるようにするため | 組み合わせを 1 本の式に詰める |
| 入れ子 8 段、ノード 64 個の上限を置く | 判定は呼び出しのたびに組み合わせ条件をたどる。重くならないように頭打ちにする | 上限を置かない |
| `{!root}` を組み立てられない個別条件は、ルール全体で扱う。`deny` / `ask` は `match` の全部にヒットする形で止め（`except` も付けない）、`allow` はルールごと外す | 個別条件だけを外すと、`not` の下か上かでヒットする範囲が広がるか狭まるかが変わり、向きが定まらない | 個別条件だけを外す |
| 「本体にヒットしても、ここは除く」だけなら `except`、組み合わせが要るときに `when` を使う | 並んだ除外を読むだけで意味が取れる | 除外も `when` で書く |

## 得たもの・失ったもの

- 得たもの: 「A か B」「A かつ B」や、除外の中の例外を、式を詰めずに書ける
- 失ったもの: 書き方が `glob` / `regex` / `when` の 3 つに増える。組み合わせ条件の上限を超えると、ルールごと読み込まずに error になる
