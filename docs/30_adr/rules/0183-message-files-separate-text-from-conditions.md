# ADR-0183: 拒否・促し・次の一手の文を、条件から分けた文面ファイルに置く

状態: 採用（移行は段階的。移した範囲は `docs/42_claude/message-migration.md` の一覧表が持つ）

## 状況

エージェントとユーザが読む文は、4 か所に散らばっていた。ルールの `message` と `additionalContext`（条件と同じファイルにインライン）、組み込みの拒否（`hook/reasons.py` と各関門のモジュール）、Stop の促し（`standing.py` など）、sh の `printf '次: …'`（`ccnavi-start.sh` に 20 数か所）。条件の分岐と文が同じ関数の中にあるので、文を直すたびにコードを開く。文の型（何が起きたか・なぜ・次の一手・迂回しない）を機械で点検する置き場も無かった。値の差し込みは、Python は `{root}` と `{script:..}`、sh は `printf` の `%s` と `ccnavi_sh_quote` と、流儀が割れていた。

一部は独立済みだった。`additionalContextFile` は案内の本文を md に出せる（ワークスペース内、4000 字で切る）。拒否と sh の出力には、同じ仕組みが無い。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 文を YAML の文面ファイル（`.ccnavi/config/common/messages/*.yml`）に置き、条件はルール・コード・sh に残す。引くキーは識別子 | 文の直しにコードを開かず、型を欄で機械に点検させる | 文を md に書く（欄を取り出す書式を別に作る）、コードに残して定数だけ集める |
| 種類（`deny` `nudge` `next` `choices` `note`）ごとに欄を決める。拒否は「何が起きたか・なぜ・次の一手・迂回しない」の 4 欄が必須。促しと次の一手は欄が少ない | 拒否の型は止め方の文書が決めている。案内と促しは `次:` だけで足りる場面が多く、4 欄を強いると空の欄を埋める文が増える | 全部を 4 欄に揃える、欄を持たない自由文 |
| 識別子は拒否・促しなら記録の `code`、それ以外は `NEXT_*` `CHOICES_*` `NOTE_*`。同じコードで文が分かれるときだけ `__<区別>` | 受け取った文と記録の `code` から、文を引ける。コードを増やさない | 文ごとに新しいコード、ルール id を識別子にする |
| 差し込みは `{名前}` の 1 形式。`:sh` で引用、`_q` は呼ぶ側が引用した値、`{script:..}` はスクリプト。値の制御文字は空白にする | sh からも Python からも同じ書き方。引用を文面ファイルの側に寄せて、sh で値をそのまま打てる形に埋める事故を減らす。外から来る語が行を足して案内を偽装できない | `%s` の位置引数、sh と Python で別の書き方 |
| sh は `ccnavi text` を `ccnavi_text` で呼ぶ。文面ファイルを直接 grep・cat しない。呼べないときは sh の短い既定の文を出して先へ進む | 実行ファイルの境界を保つ。sh は判定に必要なものだけを持つ。文を引けないことで、止める・止めないを変えない | sh が YAML を読む、`jq` で読む |
| 1 回の起動で 1 件を引く。まとめて引く形は持たない | 1 回の実行で出す文は多くて 3 件。実行ファイルの起動を 3 回に抑えれば足りる | 一括取得の入口を最初から持つ |
| 自身のレイヤー（`.ccnavi/config/project/messages/`）に同じ識別子を書くと、文が 1 件ごと替わる。`kind` と `values` は上書けない。検査を通らない上書きは採らず、共通レイヤーの文を使う | 配布先が文だけを差し替えられる。差し替えで欄・値・`次:` の数の検査を外せず、条件も変えられない | 欄ごとの上書き、上書きの検査を lint だけに任せる |
| 文面ファイルをコア（設定 3 本のバックアップと復元の対象）に加えない。`.ccnavi/` の下を止める組み込みの保護と、下書きの取り込み前の検査で守る | コアは数を増やさない決まり。文面ファイルは判定を決めないので、書き換えられても止める・止めないは変わらず、文が替わるだけ。取り込み前の検査が、欄と `次:` を外した文を通さない | コアに加える |
| 壊れた文面ファイルがあっても組み込みの拒否は止める。文は種類ごとの既定の短い文に戻る（`texts.fallback`）。個々の文は組み込みに二重に持たない | 壊れた設定が防御を消さない。既定の文を個別に持つと、直した文と食い違う | 個々の文を組み込みに残す、壊れたら止めない |
| ルールの `message` と `additionalContext` は、この段では移さない。`message_id` は足さない | ルールの書式の版、レイヤーの合成、`--lint`、`--explain` に手が入る。最初の移行の対象は組み込みの拒否・促し・sh | `message_id` を同時に足す |

## 理由

条件を変える作業（いつ止めるか）と、文を直す作業（何を言うか）の変更頻度と担当が違う。文はモデルとユーザが読む成果物そのもので、型の点検（4 欄、`次:` は 1 行、値が埋まっている）を機械にすると、手で読み比べていた点検が回帰テストになる。

文面ファイルを共通レイヤー（ccnavi が配る）と自身のレイヤー（配布先の上書き）に置く形は、設定 3 本とテンプレートのレイヤーと同じ。実行ファイルに同梱する案は、配布先が文を直せないので採らなかった。

## 得たもの・失ったもの

- 得たもの: 文を直すのに、判定のコードを開かない。型を欄で点検できる。sh の文を Python と同じ書き方で書ける。配布先が文だけを替えられる
- 失ったもの: 文を読むために、コードと文面ファイルの 2 か所を見る。実行ファイルと文面ファイルの版が食い違うと、識別子が無い文が既定の文に落ちる（判定は変わらない）。sh の出力のたびに実行ファイルを起動する（1 回の実行で多くて 3 回）
- 残る課題: ルールの `message` と、英語の文面が残るモジュール、Stop の促しの残りは移していない。進み具合は一覧表にある

## 採らなかった案

- 実行ファイルに文を同梱し、配布先は上書きだけを置く: 文の更新が実行ファイルの配り直しになり、共通レイヤーの配り方と揃わない
- 文面ファイルを 1 つの md にする: 欄を取り出す書式を別に作る。YAML は読み手が既にある
- 文面ファイルも設定 3 本と同じくコアにする: 判定を決めないものに、バックアップと復元の対象を増やす
