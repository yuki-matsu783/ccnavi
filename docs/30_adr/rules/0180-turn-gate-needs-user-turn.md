# ADR-0180: 「見せて返事を待つ」を、A のあとにユーザの発言が 1 回はさまる関門で機械にする

状態: 採用

## 状況

直接作業の確定（`integrate-done`）は、手順書が「差分と変わるファイルをユーザに見せ、返事を待つ。了承を得たら確定する」と定めていた。止める機械は無く、非対話（`claude -p`）では、エージェントが自分の判断で止まる以外に守られなかった。実測では、エージェントが差分を見せず、返事も待たずに `integrate` から `integrate-done` までを同じセッションで続けて打ち、ユーザのチェックアウトの取り込み先に取り込んだ。`Stop` の促し（`NUDGE_INTEGRATE`）に従って同じターンで `integrate-done` まで打った例もある。

取り込み先はユーザが使っている場所で、取り込むと作業中のエディタの内容と食い違いうる。ユーザの明示した指示を優先する決まりはあるが、「取り込んで」が「差分を見ずに確定してよい」を含むかは、ユーザが決める点で、機械では判定できない。

「A という処理と B という処理を 1 ターンの間に行わない」は、`integrate-done` 以外でも使いたくなる形だった。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 「A を打ったら、ユーザの発言が 1 回はさまるまで B を打てない」を、宣言（id・A の条件・B の条件・キー・文面の素材）の表を渡して判定する汎用の部品（`hook/turngate.py`）にし、`integrate` → `integrate-done` をその最初の 1 件にする | 手順書の約束を、「ターンが 1 回終わり、ユーザが 1 回発言した」という機械で確かめられる事実に置き換える。ほかの組も宣言を足すだけで止められる | `integrate-done` 専用の実装 |
| 止めるのは B の側だけ。A と B が同じターンに両方起きたことを、あとから点検する処理は作らない | あとから気づいても取り込みは戻らない。点検は報告にしかならない | ターンの終わりの事後点検 |
| A と B をキー（`<名前>`）で結び付ける。名前が違う組は対象外 | 別の名前の作業の確定まで止めない | 宣言ごとに 1 組だけ |
| ユーザの発言の時刻を、ターンの印（`turn-<セッション>.json`）とは別の `userprompt-<セッション>.json` に書く | ターンの印は `Stop` で消えるので、ターンをまたぐ事実を持てない | ターンの印の拡張、取り込みの記録（marker）の時刻との比較 |
| 書くのは `hookio.is_user_prompt` が真の `UserPromptSubmit` だけ。数えないのは、バックグラウンド作業の完了通知（`prompt` に `<task-notification>` を含む）、ccnavi が起こす指示（`[idle-handoff]`）、外の出来事の封筒の形、システムの通知の形、空の発言、サブエージェントの中 | 完了通知は、ユーザが何も打たなくても `UserPromptSubmit` を起こす。数えると、エージェントが待っているだけで B が通る。ユーザの発言と言い切れるものだけを数える側に倒す | 完了通知もターンの始まりとして数える |
| `<task-notification>` は先頭でなく「含む」で見る。ユーザがその文字列を打っても関門は開かない | 開かないのは安全側。普通に打ち直せば通る | 先頭だけで見る |
| 動かしている作業が残っていること（`busy`）は、発言を数えない理由にしない | 予約した繰り返しが残る間、ユーザの返事でも関門が開かなくなり、詰まる | `busy` の間は発言を数えない |
| 予約した実行の `prompt` は、ユーザの文と見分けられないので、数える側に残る | payload にユーザの発言と言い切れる欄が無い | 予約の有無で一律に数えない |
| A の記録（宣言 id・キー・時刻・呼び出しの識別子）は実行前に 1 件 1 ファイルで残し、その呼び出しが拒否で終わったとき（`PreToolUse`）と失敗したとき（`PostToolUseFailure`）に消す | 同じメッセージで A と B を並べた呼び出しが、A の記録の前に B の実行前を通らないようにする。失敗した A を数えないのは、返事のあとの誤った再実行が失敗しただけで、B がもう 1 度止まらないため。1 件 1 ファイルなので、並行する呼び出しが書き換え合わない | 実行後（`PostToolUse`）に残す、1 つのファイルにまとめる |
| 同じコマンドの中に、同じキーの A と B があれば止める | 連結すると、まだ記録が無い | 記録だけで見る |
| B が通ったとき、起動と再開で A の記録を消す。compact と clear では消さない | 新しいプロセスで、前のターンは生きていない。compact はターンの途中で走りうる | すべての `SessionStart` で消す |
| 壊れた記録・無い記録は、閉じる側（B を止める）に倒す。ユーザの発言の記録が無ければ「まだ発言が無い」、関門の記録が読めなければ更新時刻で数え（ADR-0186 で、推さずに止めて次の発言で消す形に変えた）、置き場を読めなければ止める。A の記録を書けなければ A を止める。文面が次の一手を言う | 壊れた記録が防御を消さない。ユーザの発言の記録は次の発言が書き直すので、詰まらない | 開く側に倒す |
| 拒否コードは宣言ごとに分けず `DENY_NEEDS_USER_TURN` の 1 つにし、宣言の id を記録の `rules`（`builtin:turn-gate:<id>`）と文面に出す。`dry-run` でも止める（関門の分類） | 受け取る側の次の一手は同じ。ユーザの了承を求める関門を、`dry-run` で通過させない | 宣言ごとにコードを持つ |
| 宣言は組み込みの表だけに置き、`rules.yml` の `turn-gates:` は足さない | ユーザの了承の関門を、配布先のルールファイルで外させない。最初の利用は 1 件で、2 件目の具体的な需要が無い。足すと書式の版、レイヤーの合成、lint、`--explain` に手が入る | 最初から `turn-gates:` を足す |
| `Stop` の促しで続けたターンは、ユーザの発言に数えない。促しの文・`integrate` の出力・手順書は、確定をユーザの次の発言のあとと言う | 促しは `decision: block` で同じターンを続けさせるだけで、`UserPromptSubmit` を起こさない | 促しで続けたターンを開く |

## 得たもの・失ったもの

- 非対話（`claude -p` 1 回）では、1 回の発言で `integrate` と `integrate-done` が両方は通らない。差分を見せずに確定する再現が止まる
- 保証するのは、ターンが 1 回終わり、ユーザが 1 回発言したこと。ユーザが差分を読んだことは保証しない。返事が無関係でも関門は開く
- ユーザが同じ発言の中で「取り込んで」と明示しても、そのターンの `integrate-done` は通らない。もう 1 往復増える
- 予約した実行（`session_crons`・`ScheduleWakeup`・`send_later`）の `prompt` は、ユーザの文と見分けられず、関門を開きうる。外の出来事の封筒の形は、実行環境の案内が示すものを数えない側に入れたが、実機の payload では確かめていない
- 失敗した A の記録を消すのは `PostToolUseFailure` に依る。そのイベントが来なければ、記録は次のユーザの発言まで残り、B が 1 度余分に止まる。閉じる側に倒れる
- 組み込みの宣言を足すにはコードを直す。ユーザがルールファイルから足せない
