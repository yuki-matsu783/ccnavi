# ADR-0214: 識別子と退避の記録がワークスペース内 clone と単体 clone で変わることを受け入れる

状態: 採用

## 状況

ADR-0145 のもとで、ワークスペース内 clone と単体 clone を同じ機能で動かすと、次の 2 つが形によって変わる。動きは、設計書「複数のリポジトリ」の「単体 clone での動作」の識別子と記録の項にある。

- issue 起点の親の識別子は、ワークスペース内 clone ではプロジェクト名を含み（`feature-12-p-<slug>`）、単体 clone では含まない（`feature-12-<slug>`）。同じ remote に別名のブランチが並ぶ
- 同じリポジトリを同じ PC でワークスペースの下と単体の 2 通りに clone すると、退避した記録（`logs/archive/<リポジトリ>/`）、退役の記録、閉じた子の連番の使い済みが割れる。識別子が全リポジトリで一意であることの検査はワークスペースでだけ働き、単体では強制されない。退避の置き場は手元にしか無く、別の機械では使えない

## 決定

どちらも直さずに受け入れる。

| 決めたこと | なぜ |
|---|---|
| 識別子にプロジェクト名を付けるのは、ワークスペース内 clone だけ | issue の番号はリポジトリごとに振られる。ワークスペースには同じ番号の issue がワークスペース自身と別のプロジェクトにあり、名前を分ける必要がある。単体 clone にはその衝突が無い |
| 同じリポジトリを 2 通りに clone したときの記録の割れは、扱わない | 退避の置き場は手元にしか無く、別の機械では使えない。その旨は退避を扱うコードに明記されていて、割れることはユーザが受け入れている |

## 理由

識別子は、番号の衝突を避けるためにプロジェクト名を付ける。単体 clone では衝突しないので、名前を付けないほうが短く済む。記録の割れは、手元の記録という前提のうえで受け入れる。

## 得たもの・失ったもの

得たもの: 識別子と記録の仕組みを、形ごとに分岐させずに済む。

失ったもの: 同じ issue から作った識別子が、形によって違う。2 通りの clone を併用すると、退避の記録などが 2 か所に分かれ、利用者が自分でそろえる。

## 採らなかった案

議論した案は記録していない。直す案を後から出すときは、新しい 1 枚で置き換える。
