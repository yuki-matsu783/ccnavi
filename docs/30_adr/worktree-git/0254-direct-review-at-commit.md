# ADR-0254: 直接作業のレビュー手順をコミットのときに案内し、再開の位置を一覧で言う

状態: 採用

## 状況

思想（`docs/00_idea.md` のテーマ 5）は、連続する作業の指示は前の作業が完了したときに次の案内だけを出し、全体を最初に渡さないと言う。直接作業（チケットを使わず、ワークツリーで編集・コミットし、レビューを 2 段挟んで `integrate` で取り込む）は、コミットのあと `integrate` の前のレビュー手順を、セッションの開始時に作業の決まり（`.ccnavi/CCNAVI.md`）で先渡ししていた。これは思想に反する。

- コミットの直後に出る案内が無かった
- `integrate` を促す Stop の文は、レビューに触れなかった
- Stop の促しはターンを 1 回伸ばす（止めて続きをやらせる）ので、案内の主経路にはできない
- 別のセッションが作業の途中で止まっているとき、再開する側が位置を知る手がかりが無かった

## 決定

| 決めたこと | なぜ |
|---|---|
| メインのエージェントの `ccnavi-git.sh commit` が直接作業のワークツリーで成功したら、`PostToolUse` の追加の文脈でレビュー手順の次の一手を足す（`hook/commitnote.py`）。条件つきの文にして、コミットが続くなら全部済んでからと言う | 完了の時点で次だけを案内する。「終わった」と読まれないよう、条件を文に入れる |
| ワークツリーの名前ごとにセッションで 1 度だけ出す。数えは既存の `additionalContextOnce` の仕組み（`ctxfile`）を使い、新しい状態を持たない。起動・再開・compact で忘れる | 複数回コミットしても黙らせる。覚え方を増やさない |
| 出す条件は、サブエージェントの中でなく、直接作業のワークツリー（Stop の促しと同じ `bound_check`）で、HEAD の履歴の最後が直前の commit のとき。`--dry-run` の類いは除く。判定できないときは何も出さない | 判定は既存の関数に一本化する。案内の足しなので、迷ったら黙る |
| `integrate` を促す Stop の文と、ワークツリーを切った直後の文に、「レビュー済みなら」と条件つきの一言を足す | 主経路が外れた場合（サブエージェントのコミット、再開）の副経路にする。矛盾させない |
| SessionStart で、直接作業のワークツリーの一覧を事実として言う（名前・未コミットの有無・起点からのコミット数・`integrate` の記録の有無。新しい順に最大 10 件。超えた分は本数）。親子のワークツリーは親の一覧が言うので入れない。別のセッションの作業の可能性を添える | 再開する側が位置を判断できるようにする。「どこまで完了したか」の印は作らない（印は状態になり、食い違う） |
| 作業の決まりのレビュー手順は、`.ccnavi/docs/direct-flow.md` への指し 1 行にする | 先渡しをやめる。細部は文書に一本化する |

## 理由

案内は、それが要る時点で出すほど読まれる。コミットの成功は、レビューへ進む自然な区切りで、hook が出力を変えられないツールの完了後に文脈を足せる位置でもある。Stop は最後の手段として残すが、ターンを伸ばすので主にしない。

## 得たもの・失ったもの

得たもの: レビュー手順の先渡しが消え、セッションの頭が短くなる。コミットの直後に次が届く。再開のとき、ワークツリーの一覧から位置を判断できる。

失ったもの: サブエージェントがコミットしたときは、コミット後の案内が出ない（サブエージェントの文脈にも親にも足さない）。親には `integrate` の促しの文のレビューへの一言だけが届く。一覧はレビュー済みかを言わないので、再開する側はレビューを重ねることがある。

## 採らなかった案

- サブエージェントの完了の知らせ（`subagent_outcome`）に同じ案内を足す案: コミットした場所を SubagentStop で突き止める新しい記録が要り、変更が大きいので採らなかった
- レビュー済みの印を状態として持つ案: 印は実際の状態と食い違いうるので採らなかった
