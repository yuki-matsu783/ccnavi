# ADR-0191: 直接作業のコミットは integrate の直前にまとめ、Stop の促しはコミットがあるのに integrate が無いときだけ出す

状態: 採用

## 状況

直接作業の `integrate` の促し（`NUDGE_INTEGRATE`）は、直接作業のワークツリーに「作業が残っている」とき、Stop で 1 回だけ止めていた。作業が残っているとは、未コミットの変更があるか、取り込み先に入っていないコミットがあることだった。取り込みの途中（`integrate` を打って marker がある）も、確定を待っているとして 1 回止めていた。

エージェントが結果を報告し、ユーザに判断を求めてターンを終えた回に、この促しで止められた。促しの文は「まだ続けるなら、続ける理由をユーザに向けて書いてから終える」と言うので、エージェントは直前の返事の問いを言い直し、もう 1 回出力した。ユーザからは同じ内容が 2 回出たように見える。手順どおりに `integrate` を打ち、差分を見せて返事を待って終えた回も、marker があるので同じように止まっていた。

促しは最後の発言を読まず、状態だけで決める（ADR-0120）。未コミットの変更がある状態は「作業を終えたが打ち忘れた」と「作業の途中でユーザに確かめている」の両方で起き、状態だけでは見分けられなかった。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 直接作業では、コミットは作業を終えて `integrate` を打つ直前にまとめて打ち、続けて `integrate` を打つ。ユーザの確認を待つ間はコミットしない。ワークツリーを切ったときの次の一手と手順書でエージェントに伝える | コミットを「作業を終えた」合図にすれば、状態だけで打ち忘れを見分けられる。直接作業は小さな作業で、`integrate` は差分を 1 コミットにまとめて載せるので、途中のコミットは取り込み先に残らない | 途中でもコミットしてよいままにする。打ち忘れと返事待ちを状態で見分けられない |
| `integrate` の促しは、取り込み先に入っていないコミットがあって `integrate` の記録が無いときだけ出す。未コミットの変更だけでは促さない。コミットと未コミットの変更が両方あれば、促しの文に先にコミットすることを足す | 上の決まりの下では、コミットがあるのに `integrate` が無い状態が打ち忘れで、未コミットだけの状態は作業中か返事待ちになる | 未コミットだけでも促す。返事を待つ回に言い直しが起きる |
| 取り込みの途中（版 4 の marker がある）は促さない。版を知らない marker だけは、ユーザに片付けを頼むよう促す | `integrate` の出力が、差分を見せて返事を待つよう既に言っている。確定（`integrate-done`）はユーザの発言を挟む関門（ADR-0180）が守る。促すと、手順どおりに待った回に言い直しが起きる | 確定を待っていることを 1 回促す。手順どおりの回でも必ず重複する |
| 統合先の ref を引けないときの理由の知らせ（未コミットの変更があるときだけ出していたもの）をやめる | 未コミットだけでは促さないので、知らせる場面が無くなる。コミットがあって ref を引けないときは、もとから不明として黙っていた | 残す。促さない状態について、理由だけを言うことになる |

## 得たもの・失ったもの

- 得たもの: 直接作業で、ユーザに判断を求めて終えた回と、`integrate` のあと返事を待って終えた回に、同じ内容を言い直す 2 回目の出力が出なくなる。最後の発言は読まず、状態だけで決める方針は変えない（ADR-0120）
- 失ったもの: 作業を終えたのに、コミットも `integrate` もせずに終えた回は、促しでは拾えない。コミットと `integrate` を続けて打つ手順にしたので、コミットだけを忘れる場合は減ると見ている
- 失ったもの: 直接作業の途中のコミットを、作業の区切りの保存として使えない。直接作業は小さい作業なので、損は小さいと見ている
- 失ったもの: `integrate` のあとにユーザの直しを受けて追加でコミットしても、Stop では促さない。確定（`integrate-done`）は作業ブランチの先頭が動いたことで断り、`integrate --abort` で戻して打ち直すよう言うので、古い取り込み結果が載ることは無い
- 失ったもの: エージェントが手順に反して途中でコミットすると、今までどおり促しが出て、返事を待つ回に言い直しが起きる
- 失ったもの: チケット作業の促し（`finish`・依頼までの道・フィードバック計画）の言い直しは、この決定では直らない。チケット作業は途中でコミットする流れなので、同じ手は使えない

## 採らなかった案

- エージェントが最後の行に目印（`<!-- awaiting-user -->`）を書いた回は、促しを控える。Stop の入力の `last_assistant_message` で読める。ただ、目印を付けすぎると打ち忘れの念押しまで消えてしまい、付けすぎを状態では抑えられない。決定的な促しが会話の文面を読むことにもなる
- 促しの文に「直前の返事で理由や問いを書いていれば、何も足さずに終える」と足す。止めること自体は残り、中身のない 2 回目のターンが走る
