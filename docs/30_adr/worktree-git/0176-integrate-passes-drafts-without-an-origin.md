# ADR-0176: integrate は、元の無い wip/handoff/ の下書きを止めずに一覧へ出し、元との突き合わせは実行ファイルがする

状態: 採用

## 状況

直接作業の `integrate` は、作業ワークツリーの `wip/handoff/` のファイルを、起点（S）の同じ `wip/handoff/<パス>` と比べ、無いか中身が違えば止めていた。
S の `wip/handoff/` に何も無いと、ユーザに渡すメモや報告のような新規の下書きが 1 つあるだけで必ず止まり、本題の変更も取り込めなかった。
止めたときの案内（`ccnavi-user-handoff.sh` を頼む）は、保護対象の写しを元の場所へ戻す道具の案内で、元の場所が無い新規の下書きには合わない。
非対話のセッションは、この道具を打てず、そこで行き詰まる。一方、ccnavi の作業の決まりは「ユーザに渡す物は `wip/handoff/` に置く。`integrate` が外し、`ready` が消す」と書いており、実装と食い違っていた。

## 決定

| 決めたこと | なぜ |
|---|---|
| 検査を、下書きを S の同じ `wip/handoff/<パス>` と比べる形から、元のパス（`wip/handoff/` を除いた相対パス）の S の版と比べる形に変える | 守りたいのは、保護対象を直した写しの取り込み漏れだけ。元の無い下書きは、取り込む先が無いので取り込み漏れが起きようがない |
| 元が無い下書きは通し、`integrate` の出力に「取り込まない下書き」として一覧を 1 行で出す。取り込み結果には含まれず、作業ブランチを片付けると消える | 止めずに、ユーザへ伝える材料だけを足す。差分と変わるファイルをユーザに見せる段が既にあるので、新しい待ちの段・承認の印・コマンドは足さない |
| 元があり中身が同じ写し（編集していないもの）は通す。元があり中身が違う写しは、従来どおり止めて `ccnavi-user-handoff.sh` を案内する | 写しの編集は、取り込まないと失われる。許可リストの表に当たらない保護対象（例: `ccnavi-clean.js`）の写しは `stage` で作れるが `user handoff` では取り込めず、この検査だけが守る |
| 許可リストに当たる下書きの取り込み漏れの検査は変えない | 取り込み先と中身が違うものを残さない、という別の守り |
| 元の無い下書きでも、まだコミットしていないものは通さない | 作業ワークツリーを片付けると、コミットの無いファイルは戻せずに失われる。取り込み結果から外れる下書きのうち、ブランチに載っているものだけを、消えてよいものとして扱う |
| 元との突き合わせは、`ccnavi tree handoff-pending <ツリー> <起点>` に寄せる。応答に `foreign <パス>`（元があり中身が違う）と `note <パス>`（元が無い）を足し、sh はこの行を読むだけにする | パスは大文字小文字・NFC/NFD の違いを同じものとして比べる決まり（`pathcase.fold`）がある。`git ls-tree` と `git rev-parse <S>:<パス>` は大文字小文字や NFC/NFD の違いを区別するため、そのままでは使えず、sh には `fold()` 相当が無い。比べるのは見つけるためだけで、元を読むときは起点の木の表記を使う |
| 呼び出し元（`integrate`・ワークツリーの片付け・`integrate-done`）は変えない | 通す下書きが増えるだけで、どこも新しく止まらない。一覧を出すのは `integrate` だけで、`integrate-done` は重ねて出さない |

## 得たもの・失ったもの

- 得たもの: 新規のメモが `wip/handoff/` にあっても `integrate` が通る。非対話でも行き詰まらない。大文字小文字だけ違う写しも、元と同じものとして守られる。
- 失ったもの: 元の無い下書きは取り込み結果に入らず、ブランチを片付けると消える。ユーザへの伝達は、エージェントが一覧を読んで伝えることに頼る（止める仕組みではない）。起点の木を実行ファイルが読むため、`integrate` は、起点の木の読み出しに 1 回と、元がある下書き 1 件ごとに 1 回、git を余分に起動する。

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| sh のまま、起点の木を `git ls-tree` で読んで `tr` で小文字にして比べる | ASCII の大文字小文字しか同じにできない。`É`/`é` と NFC/NFD の違いを同じものとして扱えず、決まりと両立しない |
| 元の無い下書きは外してよいかを 1 行でユーザに確認する（新しい待ちの段） | 非対話では確認が取れず、行き詰まる。承認の印を増やすことになり、既にある差分の確認の段で足りる |
| 検査 2 を丸ごと消す | `user handoff` で取り込めない保護対象の写しを守る検査が無くなる |
