# ADR-0134: テンプレート管理画面から下書きの保存と、取り込み済みの改名・移動・削除をできるようにする

状態: 採用（書き込みの担当・ターミナル確認の水準・範囲・錠の対象・カードの入口・新しい ADR の 5 点をユーザが決めた。ADR-0130 の「ボードのカードからの入口は作らない」を改める。取り込み・編集の手順は ADR-0144 が置き換えた）

## 状況

テンプレート管理画面（ADR-0130）は、一覧・本文・下書きを読み、下書きを取り込むところまでだった。本文を直す、改名する、層の間を動かす、消す、親から下書きを作る、といった操作は、実行ファイルにオプションが無く、画面にも入口が無かった。取り込みで消えるのは取り込んだ下書きだけで、いらない下書きは手で消すしかなく、未追跡の下書きは親の `ready` を止める。

制約。

- 取り込み済みのテンプレートは `.ccnavi/` の下にあり、フローの文は案内文になる。エージェントが書き換えられてはならない（ADR-0100）
- 拡張は判定を自分で出さず、実行ファイルの答えを読む（ADR-0035）
- Python の PyYAML（YAML 1.1）と拡張の `yaml`（1.2）は読み方が食い違う

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 書き込みは実行ファイルが行う。拡張はオプションを呼ぶだけで、YAML を書かない | 1.1 と 1.2 の食い違いを持ち込まない。検査・衝突の判定・リンクの拒否が取り込みと同じ場所に揃う | 拡張が YAML を直接書く（`core/yaml11.ts` の対応が要る） |
| オプションは `--templates` に 5 つ足す。`--save-draft`（下書きの本文を `--body-file` で置き換える）、`--delete-draft`、`--rename-template`（`--on draft\|common\|project`）、`--move-template`（`--to common\|project`）、`--delete-template` | 取り込みの `--import` と同じく、1 オプションが 1 操作 | `--import` に別の組み合わせで詰める |
| どのオプションも下見と実行の 2 段にする。`--yes` なしは何も書かず、変更後の差分・検査・主語のハッシュを返す。`--yes` には `--expect <主語のハッシュ>` を必ず添え、見せた中身と違えば書かない。書く直前にも主語を読み直して比べる | 見た内容だけを書く。取り込みと同じ歯止め | 確認なしで書く |
| 編集の下見が検査を兼ねる。本文を差し替えて検査するオプション（`--lint` に相当する差し替え）は足さない | 下見が本文の検査・差分を返すので、足りる | `--lint` に差し替えを足す |
| 画面から書くときは `--via board` を付け、ターミナルの確認を免除する。止めるのは hook の止め（`--yes`）と見せた中身との一致（`--expect`）。取り込みと同じ水準 | 画面の中で差分を読んで押す使い勝手を、取り込みと揃える | 編集だけターミナルの確認を残す |
| エージェントには取り込み済みを触る形（`--rename-template`・`--move-template`・`--delete-template`）と `--save-draft` を、下見も含めて打たせない（`_CLI_FORMS`）。下書きの削除は `--yes` が付かない下見だけ打てる。下書きの保存は打たせない（`--body-file` に任意のパスを渡すと、読んだ中身が下見の出力に出るため。下書きの編集は Write でできる） | 下書きの置き場は効力が無い。取り込み済みは効力があり、フローの文が案内文になる | 全部打てる |
| launcher の書き方に依らない 2 段目の止め（`--templates` と編集の 5 オプションのどれかと `--yes` の組）も足す | `uv run ccnavi` のように launcher が認識されない書き方でも、`--via board` の経路でエージェントが取り込み済みを書けてしまうため | launcher を認識できる書き方だけで止める |
| 保存できるのは下書きだけ。取り込み済みの本文を直すには、下書きに直して `--import --replace` で取り込む。保存で `name` を変えるのは断り、改名は `--rename-template` に分ける | 取り込み済みを書く入口を、差分を読む取り込み 1 本に保つ | 取り込み済みを画面で直接編集する |
| 保存では、検査に error があっても書く（下書きは作りかけでよい）。ただし UTF-8 でない、制御文字・書式文字を含む、上限を超える本文は断る | 取り込みの前提は取り込みの下見が見る。読み違えを誘う文字は保存の時点で止める | error があれば保存を断る |
| 取り込み済みを触る操作は作業中のチケットで止める。共通とワークスペースの設定はどのツリーの作業中でも、プロジェクトの設定はそのプロジェクトの作業中だけ。移動は行き先の錠も見る。下書きだけを触る操作は止めない | 効く側が途中で変わると、進行中の親の判定の前提が揺れる。取り込みの錠と同じ規則 | 下書きも止める |
| 画面からの新しい操作を使えるかは、`--version --json` の `flags` と、新しい欄 `features`（`templates.edit`・`templates.draft-text`・`board.template-draft`）で見分ける。`features` を足しても互換の版は上げない | `drafts[]` の本文など、オプションの有無から読めない振る舞いを古い実行ファイルと見分ける | オプションごとに渡してみる |
| ボードの JSON のチケットに `template_draft` を足す。完了した（`done/` の）計画付きの親だけ真。親のカードに「テンプレートの下書きを作る」を出し、`--templates --draft <親>` を呼ぶ。成功したら通知で知らせ、テンプレート管理画面へ進める | 親が閉じる前に下書きを作る入口をカードに置く。下書きは効力が無いので確認は要らない | カードに入口を作らない（ADR-0130 の判断） |

## 得たもの・失ったもの

- 得たもの: 下書きの手直し・整理と、取り込み済みの整理が画面でできる。親のカードから下書きを作れる。書き込みの検査が取り込みと同じ場所に揃う
- 失ったもの: 実行ファイルのオプションと hook の止めが増える。画面からの編集はターミナルの確認を通らず、hook の文字列の照合と `--expect` に頼る（ADR-0130 の「設計の限界」と同じ）。`features` という見分けの口が 1 つ増える

## まだ決めていないこと

- 削除したテンプレートの復元。git に入れていなければ戻せない。ごみ箱は作っていない
- 画面の案内（ツアー）への編集の説明
