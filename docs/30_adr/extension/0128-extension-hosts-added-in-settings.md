# ADR-0128: 通信先を設定画面で足せるようにする

状態: 採用（ADR-0093 の D24 の行を改める。D24 の「設定画面でホストを足さない」は、この ADR の決定で取り下げる）

## 状況

ADR-0093 の D24 は、通信先を配布するときにビルドへ埋め込み、設定画面でホストを足す方法は持たないと決めた。
`connect-src` と `host_permissions` をビルドの一覧の API のオリジンだけにし、PAT を外へ送りにくくするためだった。

このため、セルフホストの GitLab や GHES、手元の `http://localhost:8080` を使うには、そのホストを書いた一覧で組み直すしかなかった。
組織ごとにビルドし直して配る手間が、ホストが 1 つ増えるたびに要った。

## 決定

- 通信先は、ビルドの一覧（`hosts.json`）に加えて、設定画面の「通信先」で足せる。ビルドの一覧は従来どおり `host_permissions` に入る。
- 足したホストは `chrome.storage.local` の `customHosts` に、種類と URL（オリジン）だけを保存する。API・GraphQL・web の欄は読むたびに、一覧と同じ規則（`endpoint`）で組み直す。
  組み直せない行は読まずに破棄する。ビルドの一覧と同じ名前の行も破棄する。
- 足すときは、そのホスト名への通信を `chrome.permissions.request` で許可してもらう。許可が断られたら足さない。Chrome の一致パターンは port を書けないため、許可は port を問わない（`https://ホスト名/*`）。
  `optional_host_permissions` は `https://*/*`・`http://localhost/*`・`http://127.0.0.1/*` とし、実際に許すのは足したホスト名だけ。
- 外すときは、そのホストの PAT を消してから、行と許可を外す。リポジトリが残っているホストは外さない（先にリポジトリを外させる）。
  許可は、同じ許可の型（ホスト名）を組み込みや別の行が使っているあいだは外さない（別の port の行の通信が止まるのを防ぐ）。
  足せなかったときも、同じ許可を他が使っていなければ、いま付けた許可を外す。読めない行は、足す・外すのあとも残す。
- ホストの id は `ホスト名[_ポート][_http]` とし、ホスト名に `_` と末尾のドットを認めない。こうすると、同じサーバーに別の id（＝別の PAT のキー）が付かない。
- 拡張のページの CSP の `connect-src` は `'self' https: http://localhost:* http://127.0.0.1:*` にする。CSP は manifest に固定され、実行時には変えられないため。
  `'unsafe-eval'`・`'unsafe-inline'` は入れない（ADR-0093 のまま）。
- service worker は頼みのたびに通信先の一覧を読む。ボードは開いたときの一覧で動き、開いたあとに足したホストは開き直すまで出ない。

## 理由

実行時にホストを足すには、拡張のページの CSP が事前に任意のホストを許していなければならない。Chrome は CSP を実行時に変えられない。
そのため `connect-src` を広げるしかない。広げた先で PAT を送る先を絞るのは、ユーザが足したホストと、その許可の画面にする。
許可を `optional` にしておけば、ホストを足した時点で初めて Chrome が許可を求め、ユーザが見ていないホストへの通信は始まらない。

## 得たもの・失ったもの

- 得たもの: GHES・セルフホストの GitLab・`localhost` を、ビルドし直さずに設定画面から足せる。
- 失ったもの: `connect-src` が https 全般になった。XSS が起きたときは、任意の https へ PAT を送られうる。
  D24 が防いでいた範囲（一覧の外へは送れない）は、この決定で失う。PAT は service worker だけが読むことと、画面の XSS 対策（DOMPurify・`script-src` の制限）は残る。
- 失ったもの: 足したホストの許可は、ユーザが Chrome の画面で受けたときだけ有効。許可を Chrome の設定から外すと、そのホストへの頼みは通信の失敗になる。
- 失ったもの: ボードは開いたときの一覧で動く。設定画面で足したあとは、ボードを開き直す必要がある。

## 採らなかった案

- **CSP を実行時に変える**: Chrome の拡張ページの CSP は manifest で固定される。実行時の変更は使えない。
- **`connect-src` を `*` にする**: http も含めて全部を許すことになり、http で PAT が平文で流れうる。http は loopback に限る。
- **足したホストの数だけ組み直す（組織ごとのビルドを個人の操作に広げる）**: 配布の手間が残る。ホストを足すたびに拡張を配り直すことになる。
- **一覧を拡張の中のファイルで書き換えさせる**: 拡張のファイルはユーザが編集する前提にない。編集すると配布の前提（同じ拡張が同じ通信先を持つこと）が崩れる。
- **`host_permissions` に `https://*/*` を入れる**: 導入の時点で「すべてのサイトのデータの読み取りと変更」の警告が出る。許可は足したときだけ `optional` で求める。
