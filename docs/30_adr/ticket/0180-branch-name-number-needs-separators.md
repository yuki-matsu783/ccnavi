# ADR-0180: ブランチ名の番号は、前後が区切りか端のときだけ issue の番号として読む

状態: 採用

## 状況

ADR-0103 は、issue 指定の候補に「名前に番号を含むブランチ」を足し、番号の前後が数字でないことを条件にした。
英字が隣にあっても一致するので、Claude の web セッションが作る `claude/<形容詞>-<名前>-<6 文字の乱数>` の乱数に
番号と同じ数字が入ると、無関係なブランチが候補になった（`claude/tender-volta-qmy99q` が `--issue 99` の候補になり、
`ccnavi-start.sh --issue 99` が終了コード 3 で止まった）。番号が小さいほど起きやすい。

## 決定

| 決めたこと | なぜ |
|---|---|
| 番号の前後が区切り（`-` `/` `_` `.`）か文字列の端のときだけ、名前に番号を含むと読む。実行ファイルの `names_number` と、`ccnavi-branches.sh` が GitHub の開いた PR の元ブランチを選ぶ jq を同じ規則にする | 判定が 2 か所にあり、片方だけ直すと同じ誤りが残る |
| 英字・数字が隣にあるものは読まない。`i152` も読まない | 英字が直に付くと番号の語の一部かもしれず、番号を指すと言えない。通すと乱数の中の数字を防げない |
| 名前だけで見つかった候補（MR もチケットも結び付かない）は、一覧の出力で「名前の一致は弱い根拠」と案内する | 候補をユーザに見せる前に、無関係なブランチでないかを確かめさせる |

## 得たもの・失ったもの

- 得たもの: 乱数や語の中の数字で、無関係なブランチが候補になって新規作業が止まる、また無関係なブランチに issue が結び付く恐れが無くなる。
- 失ったもの: `i152`・`issue152`・`pr152` のように英字に直に続く番号は、名前では見つからない。MR かチケットの結び付きでは今までどおり見つかる。

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| `i152` のような英字 1 字だけは通す | 英字の隣は除く、の原則に例外ができ、`claude/…-x5y7z9` のような乱数の 1 桁の番号を防げなくなる |
| `claude/` で始まるブランチだけ除く | web セッション以外の機械が作る名前や、乱数の無い語の中の数字を防げない |
