# ADR-0230: レビュー依頼から ELI5 の HTML と crit の流れを取り下げる

状態: 採用

ADR-0094・0095・0096・0097 の決定をまるごと取り下げる。ほかの ADR に残る ELI5 の言及（ADR-0120・0225 など）は、当時の流れの記録として残す。

## 状況

`review-request` は ELI5 の HTML（`--eli5`）を必須にし、`wip/eli5/` にコミットさせ、ユーザが `crit push` で指摘を送る形だった。
依頼のたびに HTML を 1 枚書く手間がかかり、中身の質は確かめられず、置き場・名前・除外・依頼し直しの扱いに決まりが増え続けていた（ADR-0096・0097）。
ユーザと確かめ、この流れをチケット作業から外すことにした。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| `review-request` の `--eli5` とその検査、`wip/eli5/` の置き場、ゲート、Stop の促し、文面、依頼文末尾の `crit` の案内を実行ファイルと sh から外す | 必須の手間に見合う効果が無く、周辺の決まりが増え続けた | `--eli5` を任意にして残す。書かない依頼が普通になり、決まりだけが残る |
| ユーザの指摘は、マージリクエストの差分とスレッドに付ける。未解決のスレッドの扱い（`confirm`・`decide`）は変えない | 判定は ELI5 に依存していなかった | 指摘の送り方を別の道具で作り直す |
| 単独のスキル `eli5`（`/eli5 <topic>`）は残す | チケット作業と無関係の説明スキルで、この決定の対象ではない | スキルも消す。依頼されていない |

## 得たもの・失ったもの

- 得たもの: 依頼の前提が減り、ELI5 に関わる置き場・名前・除外の決まりが要らなくなった
- 失ったもの: 変更の目的を専門用語なしで先に掴める材料が、依頼に自動では付かない。依頼文の本文で補う
