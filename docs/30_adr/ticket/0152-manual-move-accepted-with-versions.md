# ADR-0152: 手で動かした子は、経路の欄と受け入れ台帳で版つきで受け入れる

状態: 採用

## 状況

ユーザがホストの画面などで、レビュー待ちの子を `review/` から `done/` へ手で動かすことがある。置き場の移動は
レビューが済んだというユーザの意思だが、ccnavi は `reviewed` マーカーが無いままの親を止め続け、ユーザは
置き場を動かしたのに先へ進めなかった。置き場だけからは、ccnavi が動かしたのか手で動かしたのか見分けられない。

## 決定

ADR-0139 は受け入れの記録ファイル `accepted.json` を廃止した。この ADR では、手で動かした子の確定に限り、版つきの台帳として `accepted.json` を復活させる。`decide` と `close-early` の受け入れは 0139 のまま、ホストのスレッドで持つ。

- `finish` が置いた先を `finished_to` に、ccnavi が `review/` から動かした経路を `settled_by`（confirm・decide・
  close-early・feedback-plan・chrome）に書く。`finished_to: review` で `settled_by` が無い子が `done/` にあれば、
  手で動かした子とする。`finished_to` が無い子（この変更より前に閉じた子）は手動とみなさない
- 手で動かした移動を確定してよいのは、次の全部が成り立つときに限る（`manual_settle.assess`）。依頼のマーカーがある。
  レビューを待つ子が残っていない。動かした子の `done/` のファイルが HEAD にコミット済みで
  `origin/<親のブランチ>` に入り、未コミットの変更が無い。子の重複や読めないファイルが無い。判定に使うのは
  親の正本の置き場と git の履歴だけで、PCごとの state は使わない。エージェントは代わりに push しない
- 確定は `confirm` が行う。未解決の指摘はホストで解決せず、版つき（キー・指摘の版・最後のコメントの id）で
  受け入れ台帳 `phases/<親>/accepted.json` に足す。受け入れるのは、移動コミットの時刻より余裕幅（10 分）以上前に
  ホストで作られたスレッドだけ。後に付いた指摘、時刻を読めない指摘が残れば確定しない（decide へ案内する）。
  変更要求があれば移動は保持して確定を保留する
- 台帳に受け入れた指摘は、版が同じで、受け入れた後に最後のコメントが変わらない間は未解決として数えない。
  本文が変わる、受け入れた後にコメントが付く（再提起）、新しい指摘は数える。台帳はフェーズを開き直しても残る。
  読めない台帳は空として扱い、未解決を隠さない
- reviewed マーカーには `via: manual` と `moved: [子の識別子]` を足す。共有済みの手動移動を見つけたとき、Stop は confirm を打つよう 1 回だけ促す

## 得たもの・失ったもの

得たもの: 置き場を手で動かしたレビュー完了の意思を、版つきで確定できる。

失ったものは次のとおり。

- ホスト上のスレッドは未解決のまま残る。GitLab の「すべてのスレッドを解決しないとマージできない」設定がある
  リポジトリでは、ccnavi上はレビュー済みでも MRはマージできないので、ユーザがホストで解決する
- 再提起は、受け入れた後に付いたコメントでしか見分けない。返信のすべてを再提起とはみなさない
- Chrome拡張の確定も手動移動を扱う。git が無いので、移動の時刻（動かした子の done/ のファイルを最初に加えたコミット）は拡張がホストの履歴から読んで渡す。履歴が上限に達する・読めないときは確定しない

## 採らなかった案

- 置き場の移動だけから手動と推し量る: ccnavi が動かしたものと区別できない
- 手動移動の確定でホストのスレッドを自動で解決する: ユーザが解決していないものを ccnavi が閉じることになる
