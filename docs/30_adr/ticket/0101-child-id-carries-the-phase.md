# ADR-0101: 子チケットの識別子にフェーズ番号を入れ、連番はフェーズごとに振る

状態: 採用

## 状況

子の識別子は `<親>-<2 桁の連番>` で、連番は親ごとに 1 本だった（`i0012-01`、`i0012-02`、…）。
フェーズ番号は子の frontmatter の `phase:` にだけあり、識別子からは読めなかった。

連番が親ごとに 1 本なので、後から前のフェーズに子が足されると番号の順と作業の順が食い違う。
フェーズ 5 で `-06` を取った後に、レビューで残った指摘を直す続きの子（ユーザが `decide` で起こす）が
フェーズ 2 に `-07`・`-08` で入る。一覧を番号で並べると、フェーズ 2 の直しがフェーズ 5 の後ろに来る。
識別子だけを見ても、どのフェーズの子かが分からない。

識別子だけから親を割り出す箇所は 4 つあった。`ticket_ids.py` の `_CHILD`（`child_pattern()`。Chrome 拡張の
`family_of` もこれを使う）、hook の write-and-push の `family_of`、`ccnavi-common.sh` の `ccnavi_wap_family`（`%-[0-9][0-9]` で
末尾を剥がす）、lint の「親なのに子の形」の検査。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 子の識別子は `<親>-<2 桁のフェーズ番号>-<2 桁のフェーズ内の連番>`。親 i0012 のフェーズ 5 の 1 枚目は `i0012-05-01`。計画の無い親の子はフェーズ 0 なので `-00-01` | 番号の順がフェーズの順と一致し、後から前のフェーズに足した子もそのフェーズの中に並ぶ。識別子だけでフェーズが読める。0 埋めの 2 桁なので、文字列の順のまま数の順になる | 連番だけを残し、並べるときに `phase:` を読む（識別子を見ただけでは分からないまま）。フェーズ番号を 0 埋めしない（文字列の順と数の順が食い違う） |
| 識別子の中のフェーズ番号と `phase:` が食い違えば error で読まない | 2 か所に同じ値を書くので、食い違いを許すとどちらが正か決まらない | 識別子の側を正として `phase:` を読まない（`phase:` を読む既存の箇所が多い） |
| 古い形式（`<親>-<2 桁>`）は読まず、読むのは新しい形だけにする。古い形式の子は error | 読み手を 2 通り持つと、親の割り出し・採番・lint のどれもが 2 通りを扱うことになる | 古い形式も読み続ける（割り出しが 2 通りになり、`foo-01` が古い形式の子か新形式の親の途中か決まらない） |
| ccnavi が採番する続きの子（`next_child_id`）は、親とフェーズごとに最大の連番 + 1 | フェーズ内の連番の定義どおり | 親ごとの最大 + 1 をそのフェーズに付ける（フェーズ内の連番が飛ぶ） |
| 識別子だけから親を割り出すときは、右から 2 段（`-\d{2}-\d{2}$`）を剥がす。Python・hook・sh で同じ規則にする | 親が `-` や数字を含んでも（`web-i0012-05-01` の親は `web-i0012`）割り出し方が 1 通りに決まる | 左から最初の `-` で切る（`web-i0012` のようにプロジェクト名を持つ親で誤る） |
| lint は、親の識別子の末尾が `-\d{2}` なら今までどおり warn。`-\d{2}-\d{2}` で終われば子の形そのもので、どの親の子として扱われるかを言う。`-\d{2}` だけなら別の親の子の識別子の途中（`<親>-<フェーズ番号>`）と紛れると言う | 割り出しは右から 2 段なので `-\d{2}` だけで終わる親は誤って割り出されないが、人が読むと紛れる。前の規則（`-\d{2}$` を避ける）を緩めずに済む | `-\d{2}-\d{2}` だけを warn にする（規則が緩み、古い形式と同じ綴りの親が通る） |

## 互換の版

子の識別子の形は、実行ファイルと sh（親の割り出し）と Chrome 拡張（同梱の ccnavi）の契約にヒットする。古い sh や拡張が新しい形の識別子を前の規則で割り出すと、別の親子のチケットとして扱う。そこで互換の版を上げ、食い違えば sh と拡張の版の検査が名指しする。Chrome 拡張は同梱の ccnavi の版を組み立てのときに埋め込むので、作り直して入れ直す（入れ直すまでは「始める」を断る）。

## 得たもの・失ったもの

- 得たもの: 番号の順と作業の順が一致する。識別子だけでフェーズが読める。続きの子がどのフェーズのものかが名前で分かる
- 失ったもの: 識別子が 3 文字長くなる。フェーズが 100 以上の子は読まず（error）、
  1 つのフェーズの連番が 99 を超える続きの子は起こさない（2 桁で足りない）。続きの子は、同じ名前のファイルがどこかの
  置き場に在れば（読めないものも）上書きせずに止まる。保護された sh のコピーと Chrome 拡張の入れ直しに、ユーザの手が要る

## 採らなかった案

- **古い形式を読み続ける。** 親の割り出しが「右から 2 段、無ければ 1 段」の 2 通りになり、`foo-01` が新しい形の
  親 `foo-01` なのか古い形式の `foo` の子なのか決まらない。lint・採番・write-and-push・Chrome の 4 か所で扱いが要る
- **フェーズ番号を `phase:` だけに置き、表示で並べ替える。** 識別子を見る場所（ブランチ名・ワークツリーの名前・コミットの
  メッセージ）では順が直らない
