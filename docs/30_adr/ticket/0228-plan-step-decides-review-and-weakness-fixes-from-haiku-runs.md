# ADR-0228: レビューの要否を計画のステップで決め、Haiku の実行で見つかった弱点を直す

状態: 採用

## 状況

Haiku に 45 回の作業をさせて、ccnavi が詰まった場所を調べた。事実と確かめたものは次のとおり。

- 親の計画（フェーズ定義の `review: false`）でレビュー不要にしても、`human_review` を書かない子は「要る」扱いになり、子がレビュー待ちに入って親へ進めない。子の既定が `required: true` で、「要る」は定義より優先されるため
- 計画のステップの `review` は `true` しか書けず、チケットに書いた計画でレビューを外せなかった。範囲（`scope`）は子のチケットを親の範囲と定義の上限で切り詰める作りで、チケットの記載が正になっている。レビューだけが逆だった
- 調査の定義は成果物の置き場も範囲も `wip/research/` だけで、`ready` が `wip/` を消すので、調査だけの親は結論が main に残らない。`finish` は消えることを言わなかった
- 止めている間（レビュー準備中・待ち）に通すのはスクリプト 3 本の単独実行だけで、資料を引く `ccnavi-launcher.sh --docs` も止まった
- 子の `finish` は学びの記録の存在と非空だけを見て、`learnings` の形式の誤りは親の `finish` で初めて断られた
- 人が `decide` を打ったコメントは、エージェントと同じアカウントで投稿され、後から誰が判断したか読めない
- 工程スキルへの促しは、コードや文書への最初の書き込みで 1 度だけ出る文で、調査のように書き込まない作業には届かず、名前も出さない

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 計画のステップの `review` に `true` と `false` を書けるようにし、書けば定義の `review` より優先する。書かなければ定義に従う。`deferred` とは同時に書けない | チケットに書いた計画を正とし、定義は既定の型にする。範囲と揃う。承認画面は項ごとの要否を出すので、承認する人がレビューを省く判断を目にする | 定義だけで決める（チケットごとに型を作る必要が出る） |
| 子の `human_review` を省いたら宣言なしにする（既定の `required: true` をやめる）。`required: true` は「要る」を足すだけで、要らないことは言えない（変えない）。実績のリスクが上げる仕組みも変えない | 子の既定が、計画とフェーズ定義の指定を黙って上書きしていた | 承認や `--check` で食い違いを警告する（食い違う既定をそのまま残す） |
| 要否を言う根拠が 1 つも無い番号（計画が無い親）は、子が `required: false` と明示しない限り要る | 定義が読めないときにレビューが消えない側に倒す | 宣言なしを「要らない」と読む |
| 子の `finish` が、成果物が `wip/` の下にあるとき、`ready` で消えることを案内する（止めない） | 調査は範囲が `wip/` だけで、置き場を変えられないことがある。止めずに、書き写す先を言う | 止める。成果物の置き場を `docs/` へ移す |
| 止めている間も、`ccnavi-launcher.sh --docs` を `sh` で単独で実行する形は通す | 次に何をするかを調べる手段を残す。読むだけの操作 | `--help` と `status` を足す（`--help` と `status` は既に通る）。連結の形を通す |
| 子の `finish` が、親の `finish` と同じ読み取りと整合の検査を学びの記録に掛ける。関数名は `record_missing` から `record_blocked` へ | 間違いに早く気づき、閉じた子へ戻る手戻りを無くす | 親だけで検査する |
| `decide` のコメントに「ユーザの判断（経路・アカウント）」の行を足す | 投稿者はエージェントと同じアカウントで、ホストの記録だけでは判断した人が分からない | Approve を必須にする（今回は見送る） |
| フェーズ定義に `skill` 欄（案内にだけ使う工程スキル名）を足し、子の着手の出力と、子へ渡す案内に、この機械にあるスキルだけ名前で出す | 「あれば」の促しは読まれない。名前を言い、無いスキルは言わない | 促しの文だけを具体的にする（書き込まない作業には届かない） |

## 得たもの・失ったもの

- 得たもの: レビューの要否をチケットの計画で決められる。子が書かなくても計画と食い違わない。調査の結論が消えることと、学びの形式の誤りと、判断した人が、早く分かる。止まっている間も資料を引ける。工程スキルの名前が子に届く
- 残る制限: `ready` が `wip/` を消す仕組みは変えない。結論を残す書き写しはエージェントとユーザの判断に任せる。観測元を親の単位で数えることと、`uv.lock` の扱いは、この決定に含めない（`uv.lock` は追跡する運用で対応する）
- 失ったもの: 子の既定の「要る」が持っていた安全側の倒し方。計画のステップかフェーズ定義が「要らない」と言えば、子が何も書かない限りレビューが外れる。承認の画面で、その判断が見える
