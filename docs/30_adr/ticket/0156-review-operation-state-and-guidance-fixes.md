# ADR-0156: レビュー運用の状態遷移と案内の修正をまとめて出す

状態: 採用（GHE.com と GitLab の実物での挙動は未検証）

## 状況

GitLab 中心のレビュー運用で、状態の数え方と案内に次の食い違いがあった。

- origin のホストの分類が `github.com` だけで、GHE.com（`*.ghe.com`）が GitLab として扱われ、API の URL も合わなかった。分類は sh・実行ファイル・Chrome 拡張の 3 か所に別々にあった
- GitLab では ccnavi の依頼コメントに返信するとスレッドになるが、取得も未解決の数え方も最初の note だけを見るため、ユーザの返信が指摘として数えられなかった
- 変更要求の案内がホストを問わず「approve（または dismiss）」で、GitLab では dismiss に該当する操作を適用していなかった
- fix で直した指摘のスレッドは未解決のまま残る仕様だが、誰が resolve するかを案内していなかった
- 依頼のあとに親の HEAD が動いて止めても、何が見られていないかを言わなかった
- レビュー待ちの間に別の親・別の目的の依頼を同じセッションで受けてしまう
- Stop の促しが、ユーザが止めた・待たせたあとでも次の一手を実行させた

## 決定

| 決めたこと | なぜ |
|---|---|
| 分類に使うホストは、origin のホストを小文字にしポートを除いたもの。`.` の区切りで照合する。GitHub は `github.com` と `ghe.com`・`*.ghe.com`、GitLab は残り全部。GitLab の接続先は元の scheme・ホスト・ポートを保ち、GHE.com は `https://api.<ホスト>`（GraphQL は `/graphql`）。GHE.com のポート付きは API の URL を組めないので止める。共通の表（`tests/fixtures/host-kinds.json`）で 3 か所を突き合わせる | 末尾一致では `evilgithub.com` が該当する。3 か所の食い違いをテストで見つけられる形にする。GHE.com の URL の規則は実物では未検証 |
| Chrome 拡張では、ユーザが設定画面で明示した種類を自動判定より優先する。権限は画面と API・GraphQL の origin のすべてに取る | 未知の GHES を GitHub として登録する機能を変えない。GHE.com は画面と API の origin が違う。未登録のホストへ自動で通信しない |
| GitLab の判定に使う note は、discussion の note から `system: true` を除いたもの。1 つでも `resolvable` なら対象。代表の note（本文・URL・位置・書き手）は、本文が ccnavi の目印で始まらない最初の note。`own` は note が全部目印で始まるときだけ真。`last_*` は集合の最後の note | ユーザの返信を指摘にする。受け入れの返信（目印つき）を足しても、キー・URL・版は変わらない |
| `Thread.own` は JSON の真偽値だけを受け、それ以外は None（従来の判定）。ccnavi の投稿と見るのは、書き手が依頼の投稿者で `own` が真のとき | 型の崩れた入力で未解決を隠さない |
| `decide` のダイジェストはキーと代表の本文の版だけで照合する（同じ discussion に付いた別の返信は検知しない） | 今回は変えない制約。`last_*` は手で動かした子の確定と台帳の再提起の判定だけに使う |
| 変更要求の案内をホストごとに出し分ける。判定は変えない | GitLab は Approve で解除する。再依頼で状態が戻るかは未検証 |
| fix のスレッドは、ユーザが確認して resolve する。エージェントは fix を理由に resolve しない。依頼本文の固定の 1 文の分は依頼の目印のキーに入れない | keep・issue の返信と解決は sh の仕組みで対象外。1 文を足す前に投稿した依頼を打ち直しても二重に投稿されない |
| 依頼のあとに HEAD が動いて止めたときは、判定を変えず、止めたあとに理由を説明する。確かめられるときは見られていない変更と動いたコミット（最大 5 件）、確かめられないときは確認できないとだけ言う（ADR-0189 で、断定しない固定の文に変えた）。固定の案内として、エージェントが作っていないコミットがあれば取り込んだことを伝えて依頼し直す | 作者から自動で何かを判定しない。件名と作者は外から来た文字列として扱う |
| レビュー準備中・レビュー待ちの間の新しい依頼は、別のセッションで受けるよう案内する（機械的には止めない） | 同じ親のレビュー対応・相談・取り消し・次の計画は続けられる |
| Stop の促しの共通部分に、ユーザが止めたときはターンを終える 1 文を足す。状態ごとの次の一手は変えない | 促しが止める意思に勝たないようにする |

## 互換の版

互換の版を上げる。意味の変更（フィードバック計画の承認、`decide` の選択肢、未解決の数え方、ホストの分類）、公開している入口の削除（Chrome 拡張の取り下げ）、新旧の版が混ざったときの誤判定（古い実行ファイルは GHE.com を GitLab と読み、古い sh は GHE.com の API に届かない）があるため。sh・実行ファイル・VS Code 拡張・Chrome 拡張をそろえる。

## 得たもの・失ったもの

得たもの:

- GHE.com の origin が GitHub として分類され、API の URL が合う。分類が 3 か所に別々にあったのを、共通の表（`tests/fixtures/host-kinds.json`）で突き合わせられる
- GitLab で依頼コメントへ返した返信が、指摘として数えられる
- 変更要求・fix のスレッド・HEAD が動いたとき・レビュー待ちの間の新しい依頼の案内が、ホストと状況に合う。Stop の促しが、ユーザが止めた意思に勝たない

失ったもの:

- 互換の版を上げるので、sh・実行ファイル・VS Code 拡張・Chrome 拡張をそろえる必要がある。混ざると誤判定する（古い実行ファイルは GHE.com を GitLab と読み、古い sh は GHE.com の API に届かない）
- GHE.com のポート付きの origin は、API の URL を組めないので止める
- `decide` のダイジェストは、同じ discussion に付いた別の返信を検知しない。今回は変えない制約として残る
- レビュー待ちの間の新しい依頼は、機械的には止めず案内にとどめる
- GHE.com の URL の規則、GitLab の変更要求を再依頼で戻せるか、GHE.com と GitLab の実物での挙動は未検証


## 採らなかった案

- 版を上げずに文面だけ直す。GHE.com の分類と承認の意味は文面の調整ではなく、混ざると誤判定する
- 依頼の目印のキーに固定の 1 文を含める。既存の依頼を打ち直すと別のキーになり、二重に投稿される
