# ADR-0179: フローの文の中和は ASCII の素の混入だけにし、似た形の字への寄せはやめる

状態: 採用

## 状況

子チケットのフローの文は、案内に混ぜて渡す。ADR-0085 の L-a は、文の中の `[ccnavi` や案内の区切りの文が
ccnavi の知らせに見えないよう、互換分解（NFKD）と、似た形の字（キリル・ギリシャ・アルメニア・ローマ数字など）を
ラテン文字に寄せる表（`flow_text._CONFUSABLE`）を通した表記で見分けて、亀甲括弧に置き換えていた。

フローを書くのは、ccnavi を使う同じユーザ自身か、ユーザが取り込みのときに差分を読むエージェントの下書き
（ADR-0100）で、偽の知らせを混ぜられる経路は細い。`docs/21_design/limits.md` の「限界と保証しないこと」は、意図的な回避への防御を対象にしないと
している。似た字を寄せる表は、字を足すたびに増え、抜けは避けられない。

## 決定

ASCII の素の混入だけを中和する。

| 決めたこと | なぜ |
|---|---|
| `[` の直後が `ccnavi` で始まる括弧（大文字小文字・空白・結合文字・書式の制御を挟んだものも）は `〔…〕` に置き換える。案内の区切りの文は `〔区切りに似た文〕` に置き換える。組み立てた行でも見る | 経路が細くても、素の `[ccnavi dry-run]` が混ざる事故は安く防げる |
| 似た形の字の表（`_CONFUSABLE`）、互換分解（NFKD）、確かめ用の `impersonates` を外す | 見た目の寄せは、表を足し続けても完全にならない。保証しない方針とも合わない。正準等価（NFC と NFD）の違いは同じとみなす。似た形の字の寄せではない |
| キリル文字・ギリシャ文字・ローマ数字・全角の括弧などで書いた偽の知らせは中和しないことを、テストで固定しない | 保証しない挙動をテストで約束にしない |

## 得たもの・失ったもの

- 得たもの: 字の表と、それを保つ手間がなくなる。中和の処理が短くなる。
- 失ったもの: キリル文字や全角の括弧などで作った偽の `[ccnavi]` の知らせや区切りの文が、そのままモデルに
  読まれうる。ADR-0085 の L-a が防いでいた経路が開く。

## 採らなかった案

| 案 | 落とした理由 |
|---|---|
| 表を残して字を足し続ける | 同一ユーザが書くファイルで経路が細い。敵対的な回避は、`limits.md` の「限界と保証しないこと」で保証の対象から外している。表は完全にならない |
| ASCII の中和も全部やめる | 素の混入は安く防げ、取り込みのときに差分を読むユーザにも見えにくい |
