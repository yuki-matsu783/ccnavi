# ADR-0132: レビューの chat を廃止し、見る場所を none と mr の 2 つにする

状態: 採用（追記: 本文の「これまでどおり取り込み状態を持たず」は、取り込み状態そのものを廃止した ADR-0142 で前提ごと無くなった。さらに、MR で見るフェーズが無い親の扱いは ADR-0215 が置き換えた）

## 状況

ADR-0065 は、小さな作業にホストの認証とマージリクエストを求めないために、`review` に `chat`（このセッションでユーザが差分を見る）を足した。

その後、共通のフェーズ定義 `quick` は `mr` になり、`chat` を使う定義は共通側から消えた。残ったのは、`chat` 専用の分岐（実装・テスト・文書の広い範囲）と、`chat` の弱点だった。外形の証拠が薄い、レビューの中身が残らない、変更要求に該当する状態が無い、の 3 つである（ADR-0065 自身が挙げていた）。issue #379 で、設計書が `quick` を `chat` と書き、定義が `mr` と書く食い違いが見つかった。

## 決定

- `review` の値は `none` と `mr` の 2 つにする。`chat` は不正な値として読み、定義の読み込みが error にする（`review` は `none` か `mr`）
- `ccnavi-review.sh chat <N>` と `ccnavi --reviewed <N> --chat` を廃止する
- 計画のステップ・子の宣言・実績のリスクが「レビューが要る」とだけ言い、定義が `none` のときに上がる先は `mr` とする
- 既存の記録の `chat` の値を読む互換は持たない（`closed.json` の `reviews` と `reviewed.json` の `by` に残る値は、新しく書かれない）
- 全フェーズが `none` で、マージリクエストで見るフェーズが無い親子は、これまでどおり取り込み状態を持たず、`ccnavi-push-approved.sh` はコミットも push もしない

## 理由

ホスト認証なしで小さな作業を回すことを守る価値は、`chat` の弱点（証拠が薄い、中身が残らない）より小さいと判断した。`chat` の分岐は実装・テスト・文書の広い範囲に散っており、使う定義が無いまま保守の費用だけが残っていた。

## 得たもの・失ったもの

得たもの: 見る場所が 2 値になり、判定・文言・テストの分岐が減る。レビューの記録が常にホストに残る。

失ったもの: ホストの認証が無い環境で、ユーザが差分を見て進める道。`review: chat` の定義を持つ既存の環境は、定義を `mr` か `none` に直すまで正しく読めない。古い `closed.json` の `chat` は読み取りの互換が無い。

`review: chat` が残ったときの動きは、置き場で違う（実装を読んで確かめた分）。

- `phases.yml`（共通・プロジェクト）に残ると、定義の読み込みが error にし、同じファイルの他の定義も含めて、そのファイルの定義が全部読まれなくなる（定義の読み込みの既存の挙動で、どの error でも同じ）
- 承認済みの親の `phases:`（コピー）に残ると、その定義は読まれず、コピーの苦情でその親の子が止まる。止めるのは子の書き込みの範囲で、フェーズのレビューの判定は、定義が読めない番号として「子の宣言と実績のリスクが要ると言ったときだけ `mr`」になる。進行中の親がコピーに `chat` を持つ環境では、`mr` か `none` の定義で親を作り直す
- VS Code のボードは、読めない値を `mr` として出して苦情を表示する。保存すると `mr` になる

## 採らなかった案

- `quick` を `chat` に戻す: 弱点が残り、`chat` を支える実装も残る
- 読み取りだけ `chat` を許す互換: 互換の分岐を残すと、`chat` を支える読み取りの経路が残る。ユーザが互換なしを選んだ
