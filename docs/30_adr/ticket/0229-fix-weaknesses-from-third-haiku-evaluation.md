# ADR-0229: Haiku 3 回目の評価で見つかった弱点のうち、シンプルに直せるものを直す

状態: 採用

## 状況

Haiku に小・中・大・並行・範囲ずれの作業をさせて弱点を評価した（31 セッション、呼び出し約 1700 回）。頻度が高いか、影響が大きいか、1 か所の変更で直せるもので、まれな状態への作り込みを要さないものだけを取り込む。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| レビューの間も、通る形（ccnavi の sh 3 本と `--docs`）に付き添う `cd` と `\| head`・`\| tail`（リダイレクトなし）を通す。付き添いだけの連結は止める | 案内どおりの 1 本に `cd` や `\| tail` を付けて止まる拒否が、約 21 回出ていた。ADR-0228 は連結を通さないとしたが、通すのは読むだけの 3 種に絞り、判定は 1 つの関数に置く | `ls` など任意の読み取りを通す（止める意味が薄れる）。ADR-0228 のまま |
| launcher は、自分の `../bin/` に実体が無いとき、git の共通ディレクトリから本体のルートを決めて、そこの launcher に渡す。共通ディレクトリが `.git` で終わらなければ何もしない | ワークツリーに `bin/` は無く（追跡しない）、子・親のワークツリーから呼ぶと「ビルドして配布して」と案内されて全停止した | ワークツリーの作成時に `bin/` をコピーする（二重に置く）。bare などの特殊な配置を解く |
| 子の finish が未コミットの変更で止めるとき、追跡外で自分のコマンドが作った生成物（lock・キャッシュ・仮想環境など）は rm してよい、出所が分からないものは消さずユーザに確かめる、追跡済みの変更は rm せず `ccnavi-git.sh restore` で戻す、と言う | uv.lock で質問停止する再発が 5 回あった。名前を並べて許可の根拠にすると、ユーザの作業を消す方向に倒れる | 名前の一覧で許す。`.gitignore` に自動で足す（ADR-0228 は uv.lock を追跡する運用とした） |
| 共通の `rules.yml` に deny `no-direct-merge` を足す。`glab mr merge/approve`、`gh pr merge`、`gh pr review --approve`、`api` の末尾が merge / approve のパスだけを、コマンドの位置で止める。組み込みにはしない | 未レビューの MR を、トークンで直接マージできてしまった。`create` や読み取りの API は止めない（チケットの作業が使う）。python や curl 経由は止まらないので、確実な防止はエージェント用トークンを Developer 止まりにすることとし、`ticket-flow.md` に書く | 組み込みの deny にする。トークンのファイルの読み取りまで止める（テスト用の記録物で、`.git/config` の読み取りは普段の経路） |
| セッションの開始で、ルールのファイルがあるのに読めないレイヤーを 1 度だけ、モデルとユーザに言う | 読めないレイヤーは空として扱われ、そのレイヤーの deny が黙って効かなくなる（`--lint` を打つまで気づかない）。判定のたびに言うと毎回モデルに届くので、開始だけにする | 判定のたびに言う。読めないレイヤーだけ fail-closed にする |
| サブエージェントの launcher の許可に `--learnings` と `--suggest` を足し、拒否文に許している読み取りを書く | どちらも何も書かない。`--templates` は `--draft`、`--plan-order` は `--fill-phases`・`--write` が書き込むので、副命令の名前だけで許す表には足さない | 書き込み付きの形を見分ける作り込みをする |
| `risks.yml` の glob の例を `*billing/*` の形にして、`*/billing/*` はルート直下に当たらないことを書く | 例のとおりに書くと、最上位のディレクトリの変更が加点されない | lint に「一致するファイルが 0 件」を足す。リスクを試す口を足す |
| 取り込んでいない下書きを理由に ready やテンプレートの案内が言う `ccnavi-user-handoff.sh` に、`--root <ワークツリー>` を添える | ユーザが案内どおり打つと、取り込む下書きが 0 件になっていた（既定がルートの `wip/handoff`） | handoff の既定を cwd のツリーにする（取り込み先が黙って変わる） |

## 得たもの・失ったもの

- 得たもの: レビュー待ちの拒否の往復、ワークツリーでの全停止、生成物での質問停止が減る。未レビューの MR の直接マージを止め、黙って効かなくなる deny に気づける
- 失ったもの: ADR-0228 が採らなかった連結を、読むだけの 3 種に限って通すことにした
- 残る制限: python や curl 経由の直接マージは hook では止まらない。並行 2 親や同じ子を 2 セッションが進める問題、長い slug、`--slug` 忘れ、取り消した子のワークツリーは、頻度が低く、まれな状態への作り込みになるため取り込まない
