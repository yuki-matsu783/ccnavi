# ADR-0217: 開始前に分かる条件で止まる操作は、何も変えずに最初に断る

状態: 採用

## 状況

次の 3 つの操作は、処理が途中まで進んでから条件に気づき、案内を出して中断していた。

- `ccnavi worktree retire <親>`: 子のワークツリーを全部消してから、親が cwd の中・未コミット・無視ファイルありだと親だけ残して案内した
- `ccnavi-user-close-early.sh`: 受け入れの実行（ホストのスレッドへの返信と解決）・issue の作成・コメントのあとで、親の write-and-push が止まる状態だと止まった。このとき文面は「チケットの状態を書かずに止めた」と言うが、実際は書いたあとだった
- `ccnavi-stage.sh`: 引数ごとに確かめながら下書きを書き、不正な引数があれば最後に終了コード 2 で止めた。先の引数の下書きと `.orig` が残った

どれも、止める条件は操作の開始前に分かる。cwd・ファイルの有無・git の状態・引数の形・ローカルの記録だけで決まり、外部（ホストの API など）に聞く必要が無い。

## 決定

| 決めたこと | なぜ | 採らなかった側 |
|---|---|---|
| 開始前に分かる条件で止まる操作は、何も変えずに最初に断り、`次:` で直し方を示す | エージェントが案内どおり直して打ち直すだけで済む。半端に変わった状態を片付け直す手間と誤りが無くなる | 途中で気づいて案内を出して中断する（今まで） |
| `retire` は、子に触る前に親のワークツリーを消せるかを確かめる。判定は `drop` と同じ関数（`worktrees.blocked`）で行う | 同じ条件を 2 か所に書かず、`drop` を直接打つ経路と食い違わない | `retire` に同じ条件を書き写す |
| `close-early` は、ホストにも手元にも触る前に親の write-and-push の状態を確かめ、止まるなら止める | 返信・解決・issue・コメントはあとから戻せない。止めるなら、書く前でなければ文面が事実と合わない | 最後（承認の push の直前）で確かめる |
| `stage` は、下書きを書く前に全引数を確かめ、1 つでも不正なら何も書かずに止める | 先の引数の下書きが残ると、打ち直したときに「既にある」と扱われて紛れる | 引数ごとに確かめながら書く |
| 外部アクセスでしか分からない条件は、この決定の対象にしない | 開始前に確かめるには同じ外部アクセスが要り、操作の先取りになる | 全ての条件を前倒しする |

`drop` の cwd・未コミット・無視ファイルの判定は残す。`drop` や `retire` を直接打つ経路があるため。

## 得たもの・失ったもの

- 得たもの: 断られたときに何も変わっていないので、直して打ち直せば済む。止める条件を 1 か所の関数に置けた
- 失ったもの: `retire` は、親が消せないとき子のワークツリーも消さなくなった。子だけでも先に片付けたい場面では、親の側を直してから打ち直す必要がある
