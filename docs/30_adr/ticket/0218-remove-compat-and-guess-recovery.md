# ADR-0218: 旧形式への戻しと、手書きの記録の推測による修復を置かず、止めて直し方を言う

状態: 採用

## 状況

ccnavi と配布した sh は同じ版で動く。それでも、操作記録が作れないとき・受け入れの計画に操作 ID が無いときは「前の形」の直接投稿に戻り、frontmatter の無い気づきの記録には雛形を推して前置し、旧い区切りの文も置き換えていた。
どれも旧形式か、手で書いた記録のための処理で、二重投稿の防止を外したり、直し方を言わずに記録を書き換えたりしていた。

## 決定

| 決めたこと | なぜ | 採らなかった案 |
|---|---|---|
| 単発の投稿（`staged_send`）で操作記録を作れなければ、何も送らずに止めて、直し方を言う | 記録が無いと二重に送りうる | 記録なしで直接投稿する |
| `ccnavi-user-decide.sh` は、受け入れの計画に操作 ID が無ければ止める。操作 ID を持たない前の形の投稿（`post_decision` の直接投稿）は置かない | 現行の実行ファイルは計画に必ず操作 ID を書く。close-early は計画を使わないので、`op_id` が空のときに何もしない守りは残す | 前の形に戻す |
| 先頭に `learnings:` を持つ frontmatter が無い、空でない気づきの記録への追記は、止めて直し方を言う（空の記録は雛形から始める） | 手で書いた記録だけに効く推測の修復だった。読み取れない記録の扱いと揃える | 雛形を推して前置する |
| フローの文の中の旧い区切り（「ここからユーザが書いたフローの本文」）は置き換えない | 現行の出力に無い文で、旧形式への対応だった | 置き換え続ける |
| 後方互換を匂わせる文面の語（更新前に切った・古い実行ファイル・この変更より前）を現行に合わせる | 判定は変えない | — |

## 得たもの・失ったもの

- 得たもの: 二重投稿の防止を外す道と、旧形式を読む処理が減る
- 失ったもの: 古い版の混在や手書きの記録では、止まって直す手間がかかる

## 採らなかった案

- 作りかけの `ccnavi-start.sh` の再開と `ROUTE_UNKNOWN`（finish を通らず手で `done/` に動かした子への案内）は、普段の経路から届きうるので残した
