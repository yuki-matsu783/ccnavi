### 2.8 セッション開始時の提示 — REQ-SES

| ID | 型 | 要求 |
|---|---|---|
| REQ-SES-01 | 事象 | セッションが開始されたとき、ccnavi は、エージェントが編集できる場所を、作業の決まりの 1 行の要点として渡すこと。編集できない場所への書き込みを止めたときは、拒否の文面で編集できる場所を示すこと |
| REQ-SES-02 | 事象 | 上位の設定がチケットの要求を却下したとき、ccnavi は、却下された要求・理由・却下した設定の出どころをユーザに示すこと |
| REQ-SES-05 | 状態 | ccnavi 自身または設定が承認された内容と異なる間、ccnavi は、その差分を示し、承認されるまで許可を与えないこと |
| REQ-SES-06 | 事象 | セッションが開始されたとき、ccnavi は、自身の動作が前提にしている作業の決まり（ワークツリーを切ってから編集する、git はラッパーを通す、下書きの置き場、書き込みを止められた場所の直し方、プロジェクトへ移ってから作業する、サブエージェントに任せる、合意の要る変更）と、そのバックグラウンドにある考え方（コンテキストを清潔に保つ、判断するのはユーザ、並行する他セッションに影響しない）を、項目ごとに要点でエージェント側に渡し、詳しいことを聞く先（使い方の表示、拒否の案内、チケットの状態の表示、文書の索引）を示すこと。ワークツリーと git の項目は、それを支える拒否のルールがワークスペースにあるときだけ渡すこと。git の項目は、生の git を組み込みで拒んでいるとき（REQ-TKT-55）も渡すこと |
| REQ-SES-07 | 事象 | Claude Code が付き添いなしと示している（環境変数 `CLAUDE_CODE_SESSION_ATTENDED` が `0`）セッションが開始されたとき、ccnavi は、作業の決まりに、このセッションが非対話であることと、サブエージェントはバックグラウンドにせずフォアグラウンドで起動して完了を待つことを加えること。示されていないとき・読めない値のときは加えないこと |
| REQ-SES-08 | 事象 | REQ-SES-07 の非対話のセッションがチケット制御を使うワークスペースで開始されたとき、ccnavi は、作業の決まりに、終わると手元の子の作業が失われること、子が詰まったりユーザの確認が要ったりしたら、止まる前に、メインが子を取り消すか、合流して続きの子を提案として送るかを決め、リモートへ反映することを加えること。チケット制御を使っていないワークスペースでは加えないこと |

REQ-SES-01 を要点にするのは、書き込める領域・確認付きの領域・使えないツールを開始時に全部並べると、起きていない場面の分まで
常駐の文脈に入るため（REQ-CMN-12）。編集できる場所は、ワークスペースルートでは下書きの置き場とワークツリーの中だけで、
作業の決まりの 2 行がそのまま答えになる。

REQ-SES-06 は、これらの決まりがワークスペースの指示ファイル（`CLAUDE.md`）に書かれていると、ccnavi を入れた
ワークスペースごとに同じ文を書き写すことになり、ccnavi の動作が変わったときに食い違うため。渡すのは要点だけにする。文面はワークスペースの `.ccnavi/CCNAVI.md` にあり、導入スクリプトが配る（実行ファイルは条件と差し込みを解くだけ）。
この文は起動・再開・compact・clear のたびに常駐の文脈へ入るので、詳しいことは要る場面で ccnavi に聞く形にして短く保つ。
ワークツリーと git の項目を拒否のルールがあるときだけにするのは、ルールを外したワークスペースで渡すと、文と判定が食い違うため。

REQ-SES-07 は、非対話の `claude -p` で、メインが終わったあとのバックグラウンドのサブエージェントが、環境の設定によってはターン終了で消え、作業が途中で打ち切られるため。
REQ-SES-08 は、非対話のセッションが終わるとコンテナごと閉じ、手元だけにある子の作業が失われるため。聞ける相手がいないときの止まり方を、開始時に渡す。
付き添いの有無は Claude Code が環境変数で示す値を読む。値は Claude Code の文書に無いので、示されたときだけ非対話と見て、
疑わしいときは対話として扱う（対話を非対話と誤ると、聞くべきところで自走するため）。
