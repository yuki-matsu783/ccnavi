### 2.8 セッション開始時の提示 — REQ-SES

| ID | 型 | 要求 |
|---|---|---|
| REQ-SES-01 | 事象 | セッションが開始されたとき、ccnavi は、無確認で書き込める領域・確認付きで書き込める領域・使えないツールをユーザに示すこと |
| REQ-SES-02 | 事象 | チケットの要求が上位の設定によって却下されたとき、ccnavi は、却下された要求・理由・却下した設定の出所をユーザに示すこと |
| REQ-SES-03 | 事象 | チケットが想定作業範囲の外へ許可を与えたとき、ccnavi は、それを却下された要求と区別し、先に読む位置へ置いて示すこと |
| REQ-SES-04 | 事象 | セッションが開始されたとき、ccnavi は、同じ内容をエージェント側にも渡し、使えない権限とその代替手段を伝えること |
| REQ-SES-05 | 状態 | ccnavi 自身または設定が承認された内容と異なる間、ccnavi は、その差分を示し、承認されるまで許可を与えないこと |
| REQ-SES-06 | 事象 | セッションが開始されたとき、ccnavi は、自身の動作が前提にしている作業の決まり（ワークツリーを切ってから編集する、git はラッパーを通す、下書きの置き場、プロジェクトへ移ってから作業する、サブエージェントに任せる、合意の要る変更）を、項目ごとに 1 行の要点でエージェント側に渡し、詳しいことを聞く先（使い方の表示、拒否の案内、チケットの状態の表示、文書の索引）を示すこと。ワークツリーと git の項目は、それを支える拒否のルールをワークスペースが置いているときだけ渡すこと |

REQ-SES-03 は、却下された要求は実害が出ないが、想定外に許可された権限は実際に使われるため。

REQ-SES-06 は、これらの決まりがワークスペースの指示ファイル（`CLAUDE.md`）に書かれていると、ccnavi を入れた
ワークスペースごとに同じ文を書き写すことになり、ccnavi の動作が変わったときに食い違うため。渡すのは要点だけにする。
この文は起動・再開・compact・clear のたびに常駐の文脈へ入るので、詳しいことは要る場面で ccnavi に聞く形にして短く保つ。
ワークツリーと git の項目を拒否のルールがあるときだけにするのは、ルールを外したワークスペースで渡すと、文と判定が食い違うため。
