### 9.11 閉じる、早めに閉じる、Draft を外す

親を閉じられるのは、`plan` と `feedback` の全フェーズが閉じ、`feedback` が承認済み（空でも）で、
止まっていないとき。フィードバック対応フェーズの最後のレビューで指摘が残ったとき、`confirm` は
2 つの進め方を示す。同じフェーズに子を足してやり直す（ユーザが `decide` で「このフェーズで直す」を選ぶか、
エージェントが提案して承認を受ける）か、残りを切り出して受け入れて閉じるか。
切り出す先は進め方で違う。マージリクエストがある親ならユーザが `decide` で「issue に回す」を選び、どのフェーズも
マージリクエストに出していない親（全部 `false`）なら、新しい親チケットの提案を `wip/proposals/todo/`
に書いて、そちらでワークツリーごと切り直す。

閉じたことは `phases/<親>/closed.json` に残る。どのフェーズでレビューが要ったか（`{"reviews": {"1": true}}`）
を親のブランチに置く。

手順は「親を `finish` で閉じる → push → `ready`」。`ready` は親のワークツリーの
外から `--parent <親>` で打つ（`--parent` なしは何もせず、外から打つ案内だけ出す）。最後のレビューのあと、この順までは、ユーザがレビュー済みにした時点で
合意の範囲に入る。`confirm` の知らせと親の `finish` の出力が、push と Draft を外す前にユーザへ確認を取り直さないと言い切る。
`wip/` の追跡済みのファイルは `ready` が消して、退避と同じコミットに含める（未追跡のものがあれば、
履歴から戻せないので消さずに名指しして止まる）。Draft を外す手段は `ready` だけ。取り込みはユーザが squash で行い、途中のコミットと
チケットの置き場は、`ready` の退避で既定のブランチに残らないようにする。
`ready` は条件を確かめてから、親のワークツリーの承認済みの領域にある閉じた親（今回の親と、統合先に
たまっていた過去の親）の `done/` の親子のチケット・`phases/<親>/`・`flows/` のフローを、
ワークスペースの `logs/archive/<リポジトリ>/` へ移す（同じ構成で。`logs/` は git が追跡しないので削除になる）。
write-and-push がその削除をコミットして push してから Draft を外し、最後に片付ける（`ccnavi worktree retire`。実行ファイルが
条件を確かめて消す。親のワークツリーが消せない（cwd が中・未コミット・git が無視しているファイル）ときは、子に触る前に何も消さずに断る）。閉じた子のワークツリーは、完了でも取り消しでも、レビュー待ちだったものも全部消し
（`confirm`・`finish`・`cancel` のあとにも、その時点で閉じた子を消す）、子の手元のブランチは、合流した子なら先頭が
`merged_sha` と同じでその先頭が push 済みの親の祖先のときに消す。取り消した子のブランチは、一覧をユーザに見せて確認が取れてから
（`ccnavi-user-clean-branch.sh <子> --confirmed`）消す。続けて親のワークツリーを消す
（子に触る前に消せるかを確かめ、cwd がその中なら断る。外から打ち直す `ccnavi-launcher.sh worktree retire <親>` を出す）。
子のワークツリーも、未コミットの変更や git が無視しているファイルがあれば、理由を出して残す。閉じた子の一覧は、`ready` が子のチケットを退避へ移す前に状態の置き場の `retire/<親>.json` に書く。
`ready` の打ち直しは、MR がまだ Draft であることと親のブランチのツリーの様子で決める。

**退避の細部。** 退避の対象は、`done/` の親と子のチケット、`phases/<親>/` の下（マーカー・子の記録・`ready.json`・`closed.json`）、`flows/` の子のフロー。
子は名前の形ではなくチケットの `parent:` 欄で親に結ぶ。

- 移す順はマーカー・フロー・子のチケット・親のチケット。1 本ずつ一時ファイルから書いて読み戻してから元を消す。
- 退避の置き場の途中（`logs` から行き先まで）にリンクがあれば、書かずに止める。
- 親の承認済みチケットが親のワークツリーではなくワークスペースルートなどに在るときは、他の親子のチケットまで消さないよう、何も置かずに止める（親のワークツリーで打ち直す）。
- 条件を確かめた後、移す前に ready のマーカー `logs/archive/<リポジトリ>/ready/<親>.json`（どのツリーの、どの先頭（HEAD）から、どのファイルを移すか）を書く。
- 打ち直した `ready`（Draft を外し損ねた、移す途中で止まった）は、MR がまだ Draft で、ready のマーカーが今のツリーのものであるときだけ、ワークツリーの側の条件（未コミット・push 済み）だけを見て、残りを移してから通る。そろわなければ通常の条件の確かめに回る。
- 退避の行き先に違う中身のチケットが既に在れば、上書きせずに止める。
- `review ready` の標準出力は、1 行目がコメントの下書きのパス、2 行目が `tree <退避したツリーのルート>`。sh は write-and-push の外では 2 行目のツリーの置き場に未コミットの変更が無いことを確かめてから Draft を外す（実行ファイルとの約束。2 行目が無い古い実行ファイルでは cwd のツリーを見る）。
- 退避は手元の機械にだけ残るバックアップで、閉じたかの判定には使わない。閉じたかは MR がマージ済みかで決める。別の機械ではこの検査に使えない。

退避を読むのは次のところだけ。

- 子の連番（続きの子の識別子）。同じリポジトリの退避だけを見て、大文字小文字だけが違う識別子も同じものとして数える。閉じた識別子の使い回しは、開始時にホストへ「同名のブランチにマージ済みの MR が無いか」を聞いて確かめる（退避には頼らない）。
- 親のワークツリーの見分け（`ccnavi-sync.sh`・`ccnavi-fetch.sh`・`ccnavi-git.sh`・`--lint`）。ツリーから親のチケットが消えても、退避に親があれば親のワークツリーとして扱う（`ready` から親のワークツリーを片付けるまでの間）。

先行（`predecessors`）が閉じたかも退避では決めない（PC によって答えが割れるため）。置き場のどこにも無い先行は `PRED_MISSING`（9.2）になる。

退避の削除は、write-and-push の見分けと実行後チェックが ccnavi の書き込みとして外す。外すのは、ready のマーカーにそのツリーから移したと載っていて
（比べている版がマーカーを書いたときの先頭と同じ間だけ。ready の削除をコミットしてツリーが進めば、マーカーは以後の削除に効かない）、
`done/`・`phases/`・`flows/` の下にあり、消えた中身が退避したコピーと同じもの。`logs/archive/` は記録と state の置き場の守り（`builtin:guard-records` と、シェルの側の `builtin:guard-setting-files`）が書き込みを止める。

**片付けの細部。** 片付けた内容は 1 行ずつ出る。消さなかったものは、理由と手で消すコマンド（`git -C <リポジトリ> branch -D <ブランチ>`）が出る。
ワークツリーの消し方は、生成物（`node_modules`・`.venv` など）を消してから `git worktree remove`（`--force` なし）。git が無視しているファイル（`.env` など）があるワークツリーは名指しする
（`worktree remove` はそれごと消して戻せない）。数えないのは生成物だけで、下書きの置き場 `wip/handoff/` は追跡されるので、ここには現れない。
片付けの入口（`ccnavi worktree retire`・`ccnavi worktree branch`・`ccnavi sync tidy`・`ccnavi-user-clean-branch.sh`）は、メインのエージェントもサブエージェントも直には打てない。
`ccnavi-review.sh ready` と `ccnavi-sync.sh` が中で呼ぶか、ユーザが `!` を付けて打つ。消す前に、記録の子がチケットの `parent:` でもその親の子かを確かめ直す。
`ccnavi-user-clean-branch.sh` は、ccnavi が片付ける子として記録したブランチ以外は消さない。親の手元のブランチは MR がマージされるまで残す。
`ccnavi-clean.sh --worktree <名前>` の 1 本が Claude Code の自動モードの分類器に止められたら、ユーザに許可を頼むか、ユーザのホームの `~/.claude/settings.json` の
`permissions.allow` に操作ごとに絞った許可（例 `Bash(sh <ワークスペース>/.ccnavi/scripts/ccnavi-clean.sh --worktree *)`）を足す。分類器はプロジェクトの `.claude/settings.json` を読まない。
`ccnavi-git.sh *` のような広い許可は push まで通すので勧めない。

統合先には閉じたチケットが残らないので、親子のチケットが閉じたことは、MR がマージ済みかで決める。`ccnavi-sync.sh` が
`ccnavi-review.sh merged <MR の番号>`（答えは `merged <番号> <先頭の sha> <元ブランチ>` / `none` / `unknown`）でホストに聞き、
閉じたかを決めるのは聞いた答えだけで、答えが得られなければ止める。API か jq が失敗したときは `none`（マージされていない）にせず `unknown`（終了コード 3）を出す。道具やトークンが無ければ `none` を出さず、終了コード 2 で止まる。聞くのは親のブランチがリモートに残っている親も、ワークツリーを片付けた後に
`retire/<親>.json` だけが残る親も同じ。親のワークツリーが残っている間の MR の番号は親チケットの `mr:`、片付けた後は `retire/<親>.json` の
`mr` から引く（`ready` が `mr` も含めて記録を書き、書けなければ `ready` は error で止まる。列挙は `ccnavi sync retired`）。
`mr` が無ければ、閉じたか判断できないと 1 行出す。片付けるブランチの名前は親のワークツリーの HEAD か
MR の元ブランチ（記録の `branch` も使える）から取る。MR をマージせずに閉じた親（放棄した親）は、親のワークツリーを片付けても
列挙され続けて、`ccnavi-sync.sh` が毎回案内を出す（片付け待ちだけでは終了コード 0。write-and-push を無関係に止めないため。1 になるのは、親のワークツリーが在る間の、リモートに無くマージもされていない親など）。ユーザが `ccnavi worktree retire --abandon <親>` を打って記録を消すと止まる。
マージ済みと分かったら `ccnavi sync tidy` が、親のワークツリーと、
手元の先頭が MR の先頭に含まれるとき（未 push のコミットが無いとき）だけ親の手元のブランチ、残っていた子のブランチを消し、
ほかが全部片付いたときだけ `retire/<親>.json` を消す（`record yes|no`）。消さなかったものは理由と手で消すコマンドを出す。`logs/archive/` は消さず、バックアップとして
残す（子の連番を数えるときに読む）。ブランチを消す権限はエージェントに開けない
（`ccnavi-git.sh` は `branch -D` を通さない）。条件の確認と削除は実行ファイルが行い、ネットワーク（MR の状態の取得）は sh が行う。
マージリクエストを出さずに回した親（全部 `false`）は、「親を `finish` で閉じる →
`wip/` を消してコミット → 統合先に取り込む」で終わる。
マージされたかは `ccnavi-sync.sh` が聞く。

まだ残っているが早めに閉じたいときは、ユーザがターミナルで `ccnavi-user-close-early.sh --reason` を打つ。作業中の子がいる間は打てない。残っているものを全部見せてから y/N を取り、次を行う。

- 未着手の子の取り消し（理由は `close-early: <理由>`）
- レビュー未了のフェーズへのレビュー済みのマーカー
- 未着手の子を取り消すと終わるフェーズへの省略のマーカー
- 未解決の受け入れ（スレッドに返信を残して解決する）
- 残りの issue への書き出し

手を付けていないフェーズにはマーカーを置かず、issue に書き出す。Draft は親が片付けて push したあとの `ready` で外す。取り消しも省略も受け入れも、それぞれの層に普段と同じ形で残る。`close-early.json` があれば親は
フィードバック計画が無くても閉じられる。
