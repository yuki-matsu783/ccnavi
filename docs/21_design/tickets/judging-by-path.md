### 9.5 ファイルの行き先で選んだチケットによる判定

`Write` / `Edit` / `NotebookEdit` の対象を解いた先が `.claude/worktrees/<名前>/` の中なら、その名前と
同じ識別子の開いた承認済みチケットで判定する。呼び出し元の `cwd` も、サブエージェントかどうかも見ない
（REQ-TKT-01）。範囲の前置はそのワークツリーのルートから解く。

ワークツリーの特定は、パスの前置だけでなく `.git` ファイルの `gitdir:` と元リポジトリの
`.git/worktrees/<名前>/gitdir` の相互参照でも確かめる。候補が複数あるときは最長一致を採る。

ルールの判定とチケットの判定を両方出し、強い側を採る。強さは `deny` > `ask` > `allow` > 何も言わない。
チケットの範囲の外と、チケットが `deny` と書いた項は `deny`。同じ強さならルールを採る（ルールの文面のほうが具体的なため）。
ルールが `deny` ならそれで決まる。

| ルール | チケット | 結果 |
|---|---|---|
| `deny` にヒットする | どれでも | 止まる（ルールの文面） |
| `ask` / `allow` にヒットする | 範囲の外、または `deny` の項 | 止まる（`DENY_TICKET_SCOPE`） |
| `ask` にヒットする | 範囲の中（`ask` / `allow`）、またはチケットが無い | ユーザに確認が出る（`RULE_ASK`） |
| `allow` にヒットする | 範囲の中（`ask`） | ユーザに確認が出る（`TICKET_ASK`） |
| `allow` にヒットする | 範囲の中（`allow`）、またはチケットが無い | 通る |
| 何も言わない | 範囲の中（`allow`） | 通る |
| 何も言わない | 範囲の中（`ask`） | ユーザに確認が出る（`TICKET_ASK`） |
| 何も言わない | 範囲の外、または `deny` の項 | 止まる（`DENY_TICKET_SCOPE`） |
| 何も言わない | ワークツリーにチケットが無い | 権限モードに従う（`UNDECLARED`） |

「範囲の外」には、子の範囲の中だが親の範囲かフェーズ定義の上限の外を含む（下の切り詰め）。

**理由コードは増やさない。** 範囲の外も、チケットの `deny` の項も、ルールを狭めた回も `DENY_TICKET_SCOPE`。
区別は文面と記録で持つ。チケットがルールより強かった回は、文面の頭に `rule:` 行を足し、記録の `rules` を
`builtin:ticket-scope` とルールの id のリストにし、`source` を空にする。チケット（子か親）の `deny` の項にヒットしたときは
`ticket entry:` 行も足す。

```
rule: <id> (<allow|ask>) lets this through, but the ticket for this worktree narrows it
ticket entry: deny <書かれた表記>
```

ルールを狭めた回は、記録から次のように拾える。

```sh
jq -r 'select(.rules[0]? == "builtin:ticket-scope" and (.rules | length) > 1) | .subject' logs/decisions.jsonl
```

ルールの `additionalContext` は、どちらが判定を決めても載せる。承認済みチケットの走査は 1 回の判定で 1 度だけで、
プロジェクトの食い違いの点検と同じ一覧を使う。承認画面の親の見出し「このチケットで編集可能な範囲」の下と、
`--explain` のチケットの節の頭に、範囲がルールの `allow` / `ask` より強いことを 1 行で書く。

**子の範囲は親とフェーズ定義でも切り詰める。** 子 → 親 → フェーズ定義の `scope` の順に適用し、厳しい側を採る。
フェーズ定義の上限は `allow` か外かしか言わないので、子が `ask` と書いた場所がフェーズ定義の上限の中なら `ask` のまま。
regex で書いた子の範囲は、実際のパスで親とフェーズ定義に適用する。実行前チェック、実行後チェック（`POST_TICKET_SCOPE`）、
SubagentStop の差し戻しが同じ合成を使う。理由コードは増やさず、どの上限で外に出たかを文面の `limit:` 行で
名指しする（子自身の範囲の外なら `scope:` 行で足りる）。

```
limit: phase type 設計 (design): wip/design/*, docs/*
limit: parent i0001: src/*, tests/*
```

**フェーズ定義の上限は、親に固定したコピー（`phases:`）から読む。** 判定は `phases.yml` を開かない。承認のあとに
`phases.yml` を直しても、不正にしても、消しても、進行中の親の子はコピーの定義の上限で切り詰められる（9.7）。
フェーズ定義の `scope` が `inherit` なら、親までで切り詰めて何も言わない。計画を持つ親のコピーにその番号の定義が無い
（コピーが無い、ステップの定義がコピーに無い、コピーの定義が不正）ときは、親が判定の側の検査で止まり、子も同じ理由で
止まる（範囲を適用せずに deny）。計画を持たない親は `ticket start` が止まり（9.7）、その子も着手できない。
着手済みの古い親とその子だけが番号だけで残り、定義では切り詰めない。

チケットは閉じる向きにしか働かない。ルールの `deny` と `ask` を緩めることは無く、ルールの `allow` は狭める。
未承認のチケットは判定に何も反映せず、結び付いたワークツリーが無いチケットも適用されない（承認は残るので、同じ名前で
作り直せばまた適用される）。

チケットの置き場（提案の置き場 `wip/proposals/` と承認済みチケットの置き場 `.ccnavi/approved/` の下）は、
範囲の外として扱わない（次のチケットを提案する手段を残すため。提案は承認されるまで判定に何も反映されない）。状態の置き場と
承認済みチケットは組み込みの `deny`（9.2、8.2）が先に止めるが、組み込みが入るのは実行前のルール集合だけ。
外し方は、実行前チェック・サブエージェント終了時チェック・ターンの終わりのコミット済みのぶんは置き場ごと
（`ticket_places.is_ticket_place`）、呼び出しごとの実行後チェックは内容で選ぶ（`post_findings._script_writes`、7.2）。
ワークツリーのルートからの相対パスを `/` の境で見て大文字小文字を区別しない。

下書きの置き場（ワークツリーのルートからの相対で `wip/handoff/` の下）も、範囲の外として扱わない
（`ticket_places.is_handoff_place`）。ワークツリーで作業するエージェントが、範囲を宣言したワークツリーでも手元に下書きを
置けるようにするため。追跡して push する置き場で、`ccnavi-git.sh integrate` が取り込むときに外し、`ready` が `wip/` ごと
消すので、統合先の成果物には残らない。追跡されるので、実行前チェック（`ticket_places.is_unscoped`）に加えて、
実行後チェック（`post_findings.ScopeGuard.finding`）とサブエージェント終了時チェック（`phase.scope.scope_findings`）でも外す。
外さないと、実行前に通った書き込みがコミットのあとで範囲外として報告される。
外すのは `wip/handoff/` の下だけで、`wip/` のほかの場所・`wip/handoffX/`・`docs/wip/handoff/`・
同じ名前のファイルは外さない。大文字小文字は区別する。置き場の名前は固定。

ELI5 の HTML の置き場（ワークツリーのルートからの相対で `wip/eli5/` の下）も、範囲の外として扱わない（`ticket_places.is_eli5_place`）。レビューの依頼に必ず添える材料で（9.10）、親の範囲に毎回書かせると書き忘れた親が依頼の手前で止まるため。
下書きの置き場と同じく追跡される置き場なので、実行前チェック（`ticket_places.is_unscoped`）に加えて、実行後チェック
（`post_findings.ScopeGuard.finding`）とサブエージェント終了時チェック（`phase.scope.scope_findings`）でも外す。親のツリーでも子のツリーでも同じ。
外すのは `wip/eli5/` の下だけで、`wip/` のほかの場所・`wip/eli5x/`・`docs/wip/eli5/`・同じ名前のファイルは外さない。
大文字小文字は区別せず、`\` は `/` に直さずに見る（`wip\eli5\x.py` という名前の 1 ファイルは置き場ではない）。
`tree.relative` が `os.sep` を `/` に直すので、Windows の区切りはこれで足りる。チケットの置き場（`ticket_places._under`）と
下書きの置き場（`ticket_places.is_handoff_place`）も、同じく `\` を直さずに見る。名前は設定で動かさない。
`wip/` は `ready` の前に丸ごと消すので、ここに置いたものは squash した成果物に残らない。`ready` の前提は大文字小文字を区別せず、
名前が `wip\` で始まる 1 ファイルも `wip/` の残りとして止める（区別しない FS で `WIP/eli5/` を先に作った形を拾う）。
**この除外は、チケットの `deny` と、チケットが信頼できないときの全面停止（`LIMIT_BLOCKED`）より先に適用される**（`is_unscoped` が
範囲の判定より前にある。順を変えるとチケットの置き場と `wip/handoff/` の扱いにも及ぶので、この弱さは受け入れている）。

`Read` `Grep` `Glob` は範囲を見ない。Bash の実行前チェックにもチケットの範囲は適用しない。コマンド
文字列からパスを追えないため。シェルが書いたものは実行後チェックが `POST_TICKET_SCOPE` で言い
（7.2）、子のワークツリーについてはサブエージェントの終了時に基準点からの差分を見る（9.12）。

行き先のツリーが属するプロジェクトと、そのツリーに結び付く承認済みチケットの `project:` が違えば
`DENY_TICKET_PROJECT_MISMATCH` で止める（11 章）。

サブエージェント（`agent_id` 付き）からの `ccnavi-ticket.sh` / `ccnavi-review.sh` の操作と
`ccnavi-git.sh push` は、ルールより先に `DENY_SUBAGENT_TICKET_OP` で止める。シェルから実行ファイルを
`user` の入口（`ccnavi user …`）付き、または状態とレビューを動かすサブコマンド（`ticket start|finish|cancel|propose|consolidate|record-risk`、
`review prepare|requested|confirm|ready`）付きで直接打つ形は、素性によらず
`DENY_TICKET_APPROVAL_CLI` で止める。`ccnavi-user-*.sh` は引数に依らず、名前がコマンド行のどこにあっても同じ理由コードで止める。
大文字小文字によらない。止めは `tickets/model/user_only.py` の表から作る（9.18）。
`comment` / `fetch` / `origin` は sh だけの仕事なので適用していない。
**hook のほかに保護が無い形**は、実行ファイルの表記によらず、同じ理由コードで止める（`phase_forms.human_path_form`）。

- ボードの経路。`user agree` / `user reviewed` / `user handoff` / `user mirror` と `--yes` の組（実行ファイルを直接実行する `--agree` / `--reviewed` と `--yes` の組も）、
  sh の `--choices` と `--digest` の組。`--yes` の経路はターミナルを求めないので、ここが唯一の保護になる。
  `ccnavi-review.sh decide <N> --preview` と `--agree --preview` は通す（何も置かない）
- ターミナル要求を切る形。実行ファイルは `CCNAVI_GUARD_TICKET_APPROVAL` と `--guard-ticket-approval` でターミナル要求を
  外す（テストと CI のため）。変数は、読むだけの形（`$X`・`${X}`・`$env:X`）以外で名前が現れたら止める。フラグは、
  `enable` 以外の値を渡したら止める。切れなければ、ターミナルを持たないエージェントは実行ファイルの側で止まる

実行ファイルを呼ぶ書き方（`uv run -m ccnavi`、名前を変えたコピー、`awk` の `system()` など）は追い切れないので、
コマンドの位置は見ず、**コマンド行の生の文字列の全体**から引用符と `\` を外して表記を探す（`--y""es`・
`"--yes"` を同じに読む）。外すのは、並んだコマンドが全部、表示・検索・閲覧の道具（`echo`・`grep`・`cat` など。
名前の完全一致）のときだけ（`sed`・`awk`・`git`・`printf` は外さない）。この表記をシェルで探す・書くコマンドも
止まる（Grep ツールと Edit ツールで済む）。コミットの文面（`git commit` / `ccnavi-git.sh commit` の `-m` の値）は
外す。ただし値の中にコマンド置換があれば外さない。

**2 段目の無い入口は、止める操作を組み立てうる引数を読み切れなければ止める**（`phase_forms.hidden_user_entry`、同じ理由コード）。
上の 2 つは文字として並んだ表記を見るので、引数を変数・置換・glob で組み立てると外れる。ターミナル要求という 2 段目が
無い次の入口では、それが唯一の保護になるため。展開を含む語は、`$`・バッククォート・`*` `?` `[`・`{}` を含む語で、
単引用符の中と `\` を付けた文字（glob は二重引用符の中も）は文字どおりに読む。shellread が実行役（`sh`・`env` など）を外した層は引用を外して組み直してあるので、外側のコマンドの後ろ側と語が同じ層は、印の残った外側の語で読む（`sh …ccnavi-sync.sh '$X'` は通る）。`sh -c '…'` の文字列を読み直した層は外側と並びが合わないので、組み直した語のまま読む（止める側）。リダイレクトの演算子と行き先は引数に数えない。

| 入口 | 止める形 |
|---|---|
| 実行ファイル（`ccnavi`・`ccnavi.exe`・`python -m ccnavi`・`ccnavi-launcher.sh`・設定の実行ファイルの名前） | 展開を含む語があり、`user` の入口になりうる、または承認のオプション（`--agree` / `--reviewed`）と `--yes` が文字か展開でどちらもそろいうる。`worktree retire --abandon`（放棄した親の片付けの記録を消す操作）または `--guard-ticket-approval` になりうる。展開を含む語より前（`--` の前）に診断のオプション（`--docs`・`--test`・`--lint`・`--explain`・`--suggest`・`--version`・`--help`）か実行ファイルの知らないオプションがある形と、文字どおりの `--agree --preview` は止めない |

- 入口はコマンドの位置で探す。前に置けるのはシェル・`busybox`・`.`・シェルの選択肢・リダイレクト・代入だけで、
  `env`・`sh -c`・`find -exec`・`xargs` の中は shellread が外した層で見る。`git log --grep ccnavi-sync.sh` のように
  文字列として出るだけの形と、表示・検索の道具だけのコマンドにはヒットしない
- 入口の前置きには `uv run`・`uvx`・`pipx run` も入る
- 引数がコマンド行に無い形は、入口の名前が出た時点で止める。`xargs` が入口を実行する形、入口を `<` で読ませる形
- 標準入力から読むシェル（パイプの先の `sh`・`bash`、`sh -s`、`sh /dev/stdin`、ヒアドキュメント、ヒアストリング。シェルのオプションは、`--norc` のような長いオプションと、値を取るオプション（`--rcfile <値>`・`-o pipefail`・`-O extglob`）を読み飛ばす。前に置いた `env`・`command`・`exec` も外して見る。`-c` は文字列を実行するので数えない）があるときは、
  コマンド行の文字列の中で入口の名前が実行される語として現れれば止める（`echo "ccnavi worktree retire --abandon i1" | sh`）。流し込む文字列の中は語として読めないので、
  コマンドの切れ目と引用符で切り、前置き・代入・選択肢を飛ばした頭の語を見る。パスの一部（`cd /home/user/ccnavi`）・コメント・
  シェルの引数（`sh -s -- ccnavi`）として出るだけの名前は数えない。sh の入口はファイルとして渡すだけで中身が流れ込むので、語として出れば数える
- 走査が止まる形（バッククォート）は生の文字列の語で探す
- 実行ファイルが知っているオプションの一覧（`phase_forms.EXE_OPTIONS`）は、`ccnavi --version --json` の `flags` とテストで比べる
- 止めた文は、止めた語が何になりうるかと、通る形（識別子をそのまま書く・`ccnavi-review.sh decide <N> --preview`・診断のオプションを前に置く）を言う。値を変数で渡す形のうち、組み立てうるもの（`ccnavi-sync.sh "$P"`）は止まる

**これで止められないもの。** 表記を組み立てて隠す形（base64、文字の連結）、ファイルに書いたスクリプトを別の
呼び出しで走らせる形、擬似ターミナル（`script`・`pty`）でターミナル要求を満たす形、名前を変えたコピーやコマンド行全体を
変数に入れた形（`sh -c "$CMD"`）で上の入口を呼ぶ形。hook は最終防衛線ではない（12.4）。

どちらも実行役のコマンド越し（`env`・`sudo`・`sh -c`・`source`・`find -exec`）に打った形を、中で実行される
コマンドで止める（6.3.1）。実行ファイルのパスには `selfguard_shell.binary_clause`（8.2）が入るので、
`sh .ccnavi/bin/<os>-<arch>/ccnavi user agree …` も同じルールで止まる。
