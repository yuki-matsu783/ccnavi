## 6. 実行前チェック

### 6.1 流れ

`PreToolUse` の 1 回で、上から順に見る。

```
コアファイルのバックアップを取る（8 章）
  │
対象を取り出す（5.4）── 取り出せない → skip（no-subject）
  │
ルール集合を決める（5.5）── 読めない → 組み込みの既定（5.6）
  │  コアファイル保護の 3 本と、チケット制御の組み込みを先頭に足す（8.2、9.5）
  │
Bash なら実行される部分に絞る（6.3）── 何も残らない → skip（nothing-to-run）
  │  実行役のコマンドの中で実行されるコマンドを並べる（6.3.1）
  │
チケット制御の前置き（9 章）
  │  サブエージェントが打てない操作 → deny（DENY_SUBAGENT_TICKET_OP）。中で実行されるコマンドにも適用する
  │  フェーズがレビュー待ちで止まっている → deny（DENY_PHASE_REVIEW）
  │  ワークツリーの元リポジトリと承認済みチケットの project が違う → deny（DENY_TICKET_PROJECT_MISMATCH）
  │
deny → ask → allow の順にルールを適用する（5.2）── deny にヒットした → deny（6.4）
  │  deny と ask は中で実行されるコマンドにも適用する。allow は適用しない
  │
Bash の書き込み先がワークスペースルート直下 → deny（DENY_SHELL_WORKSPACE_ROOT）
  │  deny にヒットしなかった呼び出しだけ。書き込み先を `cd` をたどって絶対パスに解き、
  │  ルールファイルの `workspace-root` に Write として適用する（`hook/rootwrite.py`）
  │
チケットの範囲（9.5）── 範囲外・範囲の deny → deny、範囲の ask → ask、範囲内 → allow
  │  ルールの判定と比べて強い側を採る。同じ強さならルール
  │
どちらも判定を持たない → 権限モードに委ねる（6.5）
```

判定を返した後、ヒットしたルールがモデルへ渡す文を持てば `additionalContext` に載せる（6.6）。

### 6.2 パスは行き着く先で見る

`Read` `Write` `Edit` `NotebookEdit` `Grep` `Glob` のルールは、payload の `file_path`（`Grep` と `Glob`
は `path`、省略されていれば `cwd`）を `cwd` から絶対パスに直し、`~` を展開し、`..` を正規化し、
シンボリックリンクを解いた結果に適用する。まだ存在しないファイルは、絶対パスにして `..` を正規化するところまで。
Bash のコマンドに現れるパスはコマンド文字列として見る。

`Grep` と `Glob` で解くのは探し始める場所だけで、そこから降りて読まれたファイルは判定の対象にならない。
探すツールが読むファイルは `.gitignore` と `permissions.deny` の `Read(...)` で制限する。
`builtin:credentials` の `match` に `Grep` と `Glob` を含めないのも、起点にしかヒットしない判定を増やさないため。
`.gitignore` が働く範囲と働かない呼び方、`projects/` へ降りない場合は付録 C にある。

### 6.3 Bash は実行される部分だけを見る

`Bash` のルールは、コマンド文字列そのものではなく、シェルが実際に実行する部分に適用する。禁止された語を書いただけの操作は
止めず、二重引用の中の `$( )` のようにシェルが実行する部分は読み落とさない。

読みは 2 段で行う。先に原文を 1 回走査して、`shlex` が見ないもの（コマンド置換、プロセス置換、ヒアドキュメントの本文、
コメント、改行）と引用の状態を処理し、語の分割は `shlex` に任せる。食い違いは
`tests/core/test_shellread.py`（bash 3.2 と zsh で実測した 65 形）で確かめる。

1. 入力の `\x00` と `\x01`（後で目印に使う 2 文字）を空白に置き換える。行継続（`\` と改行）は 2 文字とも消す
2. 原文を走査する。単一引用と `$'…'` の中、`\` の後ろの 1 文字は文字。`$'…'` は、中に `\` が無ければ単一引用と同じ
   文字列なので `'…'` に書き換えて読む（`git $'push'` は `git push`）。`\` があればエスケープ（`\n`・`\x41` など）を
   展開しないと中身が決まらないので `ansi-c-escape` で縮退する（確定できない読み。`PARSE_UNCERTAIN`）。二重引用の中では `$( )`・
   バッククォート・`${ }`・`$(( ))` だけを見る。バッククォートは見つけたところで `backquote` で縮退する。
   `$( )` `<( )` `>( )` の中身は切り出し、外側には `$` を 1 文字残す（`> "$(pwd)/x"` は `> $/x`）。語の始まりの `#` から
   行末はコメントとして除き、語の途中の `#` は文字のまま。引用の外の改行はコマンドの区切りにする。
   ヒアドキュメント（`<<`、`<<-`）の本文と終端の行は除き、区切りを引用していなければ本文の置換を
   切り出す。終端の行は前後の空白を除いて比べる（シェルより早く閉じることはあっても遅くは閉じない）。
   閉じない引用とヒアドキュメントは `unterminated-quote`、閉じない置換は `unterminated-substitution`、`$( )` の中の `case`・
   算術かコマンド置換かが書かれた文字列から決まらない形（`$((cmd) | x)`）は `ambiguous-substitution` で縮退
3. `shlex`（posix、`punctuation_chars`、`commenters` は空）で語に分ける。走査がヒアドキュメントと
   読まなかった `<<` がトークンに出たら `unterminated-quote` で縮退（下の限界）
4. トークン列から `$(( … ))` を除く
5. `;` `;;` `&` `&&` `|` `||` `|&` `(` `)` でコマンドを切る。コマンドの位置にある予約語（`if` `then`
   `else` `elif` `fi` `do` `done` `while` `until` `for` `case` `esac` `select` `time` `coproc` `!` `{` `}`）は
   それだけで 1 本にし、後ろの語をコマンドの先頭にする（`! grep x f` を `grep x f` と読んで allow に適用しない）。
   コマンドの位置の `coproc` と `select` は、書き直しを求める形として並べる
6. `cd` が移った先から見たパスを別に組む（6.3.2）。書かれた表記は動かさない
7. 縮退するかを決める。先頭語が `eval` `source` `.` `xargs` のとき、または語のどこかに
   `bash` `sh` `zsh` `ksh` `dash` `su` と `-c`（`find` なら `-exec` / `-execdir` / `-ok` / `-okdir`）が
   並ぶとき（先頭語だけは見ない）。比べるときだけ、語からパスと `.exe` `.cmd` `.bat` を除く。
   `perl` と `python` は対象に入れない（`perl -pi -e 's/git push/.../' README.md` のような 1 行編集を通すため）。
   引用でコマンド名を区切った `"git" push` や `g"it" push` は縮退しない。語を組み直すので、本来の `git push` としてヒットする
   ただし `xargs` は、オプションと値を飛ばして最初に残った語が、`find -exec` は `-exec` などの次の語（すべて）が、読むだけの許可リスト
   （`grep` `egrep` `fgrep` `wc` `ls` `file` `stat` `sort` `uniq` `basename` `dirname` `echo`。`shellread_words._READONLY_RUNNEE`）に
   あれば縮退しない。許可リストとの比べ方は、パスと `.exe` を除いたうえで大文字小文字を区別しない。値を取るオプションは `xargs` の一覧（6.3.1）と同じで、
   一覧に無いオプションは値を取らないものとして読む。実行される語が決まらない形（語が無い、`{}` だけ）は、縮退のまま残す。
   許可リストにあるコマンドは、引数が標準入力から来る形も許す。`printf ~/.ssh/id_rsa | xargs grep -c x` のファイル名は、ルールからは見えない。
   ファイル名を見るルールは、この形の引数には外れる。後ろに別のコマンドが続く形（`xargs grep x | xargs rm`）はコマンドごとに見るので、`xargs rm` は縮退する
8. コマンド間を `\x00` でつなぐ。語の中の空白は `\x01` にし、語の中の `( ) ; < > | &` は両側に
   `\x01` を置く。ルールの `[^\x00]*` が同じコマンドの中だけを指せるようにするため。ルールに適用する表記は書かれたままで、
   パスは除かない（`*git push*` は `/usr/bin/git push` にヒットしない）。
   `.ccnavi/config/common/rules.yml` では、引用付きの `grep -n "git push" README.md` や `find . -name "a b"` は、後ろにコマンドが続かなければ
   `prefer-read-grep` / `prefer-glob`（allow）にヒットする。`cat README.md | head -20` は `\x00` をまたぐのでヒットしない
9. 切り出した中身を同じ手順で読み（入れ子は 16 段まで。越えたら `ambiguous-substitution`）、外側の読みの
   後ろに、出てきた順に `\x00` でつなぐ。中身は `\x00` の直後に来るので、`(^|\x00)` で書いたルールは引用の外と
   同じようにヒットし、`[^\x00]*$` の allow は中身が 1 本でもあれば外れる。中身が縮退すれば全体が縮退し、理由は中身のもの

引用の中の断り: 読みは、ルールを適用する `text` のほかに `bare`（`text` から、二重引用と区切りを引用しないヒアドキュメントの本文で
切り出したコマンドを除いたもの）を返す。判定は `text` で下し、ヒットした deny / ask のルールを `bare` にも適用し直す。
`bare` にヒットしなければ、文面に回避策（単一引用、`\$(` と `` \` ``、`commit -F`、`--description-file`（glab）・`--body-file`（gh）、値を出して
読んでから書く 2 手）の断りを 1 文足し、記録と `--test` に `quoted`（そのルールの id のリスト）を残す。

縮退（読み切れないとき）は生の文字列との一致になる。縮退した呼び出しに `allow` は適用せず、
`deny` と `ask` は適用したままにする。どこにもヒットしなければ `PARSE_UNCERTAIN` でユーザに確認を出し、権限モードに委ねない。
文面は「読めなかったので文字列に適用した」と伝える（REQ-HNT-04）。記録には `degraded`（`command-taken-as-code` /
`unterminated-quote` / `unterminated-substitution` / `ambiguous-substitution` / `backquote`）が付き、文面の断りも理由ごとに変わる。
後ろの 2 つは書き直しを求める形として並ぶので、ルールより先に止まり、縮退の断りは出ない。
複合コマンドは、1 つの区間が読めなければ全体が縮退する。

実行される部分が何も残らないコマンド（コメントだけの行）は判定に入らず、記録に `nothing-to-run` が残る。

ブレース展開は読まずに止める。走査は引用の外（`${ }` の中、置換の中身、`sh -c` と `eval` に渡った文字列を含む）の
`{a,b}`・`x{,.bak}`・`{1..3}` を `rewrites` に並べ、判定はルールより先に `DENY_BRACE_EXPANSION` で止める。文面は見つけた表記を
名指しし、語を並べて書くか、文字なら単一引用で包むよう案内する。並べるのはどちらかのシェルが広げる形（引用の外にカンマが
ある `{…}`、数か 1 文字の範囲）で、引用の中・`\{`・引用やエスケープで書いたカンマ（`{"a,b"}`）・ヒアドキュメントの本文・
コメント・`{}` と `{a}` は並べない。入れ子は外側だけを並べる。読み（`text`・`bare`・`degraded`）は変えない。

実行するときに決まるコマンド名・バッククォート・シェルによって読みが分かれる形も、同じく止める。`rewrites` に
（形, 表記）で並べ、ルールより先に形ごとの理由コードで止めて、書き直し方を 1 回で返す。記録の `rules` には `builtin:<形>`（例: `builtin:command-name-expansion`）が残る。

| 形 | 理由コード | 並べるもの |
|---|---|---|
| `brace-expansion` | `DENY_BRACE_EXPANSION` | 上のブレース展開 |
| `command-name-expansion` | `DENY_COMMAND_NAME_EXPANSION` | コマンドの位置の語に、変数か置換の `$`、`*` `?`、閉じた `[…]` がある。コマンドの位置の語は、前に置いた代入（`a[1]=x`・`x+=1` を含む）とリダイレクト（`>/dev/null`・`2>&1`、名前付き fd `{fd}>`）を飛ばした最初の語で、`case` `for` `select` の直後の 1 本は見ない。読んだコマンドと、実行役のコマンドを外した層（6.3.1）の両方で見るので、`env $c`・`sh $SCRIPT` も並ぶ。`eval` と `sh -c` の文字列を読み直した層は、外側が縮退していないときに見る。たとえば `FOO=1 eval "$c"` は見る |
| `backquote` | `DENY_BACKQUOTE` | 単一引用・`$'…'`・`` \` ``・引用付きヒアドキュメントの本文・コメントの外のバッククォート。見つけたところで読むのをやめ、`backquote` で縮退する |
| `ambiguous-form` | `DENY_AMBIGUOUS_FORM` | `ambiguous-substitution` で縮退した形（`$( )` の中の `case`、`$((cmd) \| x)`、16 段を超える入れ子）と、コマンドの位置の `coproc`・`select` |

`sh -c`・`eval`・後ろが読むだけの許可リストにない `xargs`・`find -exec` は、書き直すと中身がファイルになって見えなくなるので、ここでは止めず、縮退と層の読み
（6.3.1）のままにする。

残る限界: 引用符の中身が演算子の文字だけでできている 1 語（`grep -n "<<" f`）は、`shlex` のトークンでは演算子と区別が
付かない。そのためヒアドキュメントの始まりに見えて閉じない本文として縮退し、ヒアドキュメントのルールにヒットして止まる。
許容する誤検知（12.2）。

引用符の中身が `>` か `<` だけの 1 語（`grep -n ">" f`）は、走査が身代わりの文字に置き換えてから `shlex` に渡すので、文字として読む。
`<<` だけは身代わりを置かず、上のとおり縮退する。

#### 6.3.1 実行役のコマンドの中で実行されるコマンド

`env rm x` の `rm x` のように、別のコマンドを実行することが仕事のコマンドを実行役のコマンド、実行されるほうを
中で実行されるコマンドと呼ぶ。コマンドの先頭に固定して書いたルール（組み込みのシェルの書き込み `(^|\x00)(mv|rm|…)`、
サブエージェントの禁止、承認のルール）が `env`・`sudo`・`sh -c`・`xargs` などの前置きで外れないよう、読みの側で層を作る。

層の作り方（`shellread`）: `read()` は、コマンドごとに実行役のコマンドを 1 枚ずつ外した層を、外側から内側の順に
並べて返す。`Reading.unwrapped` が層を `\x00` でつないだもの、`Reading.runners` が層ごとの実行役のコマンドの名前で、
同じ順序。元の形は含めず、途中の層は残す（`env sh .ccnavi/scripts/ccnavi-user-agree.sh` からは
`sh .ccnavi/scripts/ccnavi-user-agree.sh` と `.ccnavi/scripts/ccnavi-user-agree.sh` の 2 層）。層は元の形と同じ規則で組み直す
（語の中の空白は `\x01`、語の中の演算子の文字は `\x01` で挟む）。

| 形 | 中で実行されるコマンド | その中をさらに外すか |
|---|---|---|
| `FOO=1 <cmd>` | `<cmd>` | 外す |
| `/bin/sh x`、`git.exe x` | `sh x`、`git x`（区切りの前の道筋と `.exe` `.cmd` `.bat` を除いた名前） | 外す |
| `env` `command` `exec` `nohup` `time` `nice` `sudo` `doas` `timeout` `stdbuf` `chrt` `ionice` `taskset` | オプション、値を取るオプションの値、位置引数、`--`、`env` と `sudo` の `名前=値` を飛ばした残り | 外す |
| `sh` `bash` `zsh` `dash` `ksh` `<ファイル> <引数>` | `<ファイル> <引数>` | 外さない |
| `sh -c '<文字列>'`（`-lc` のようにまとめた形も） | 文字列を読み直したコマンド | 外す |
| `eval <語…>` | 語を空白でつないで読み直したコマンド | 外す |
| `.` / `source` `<ファイル> <引数>` | `<ファイル> <引数>` | 外さない |
| `xargs [オプション] <cmd…>` | `<cmd…>` | 外す |
| `find … -exec` / `-execdir` / `-ok` / `-okdir` `<cmd…>` `;` か `+` | `<cmd…>`（複数あればそれぞれ） | 外す |

- シェルと `.` / `source` に渡したファイルの後ろの語はスクリプトの引数なので外さない
- `command -v` / `-V` と `sh -s a b` は層を作らない
- `shlex` は `\;` を区切りの `;` として返すので、`-exec` の類で始まるコマンドも find の続きとして読む
- `\(` `\)` や引用された `'('` `';'` も、演算子と同じ文字列で返るので、そこでも切れる。`-` で始まる断片は、書き込み・実行の述語
  （`-delete` `-exec` `-execdir` `-ok` `-okdir` `-fprint` `-fprint0` `-fprintf` `-fls`。`shellread_words._FIND_ACTIONS`）が断片の語のどこかにあるときだけ縮退する。それ以外は別のコマンドとして読む
- 深さは 4 まで（`UNWRAP_DEPTH`。元の形は数えない）、語数は 1 回の読みで 2000 まで（`UNWRAP_WORDS`）で、超えたらそこから先の
  層は作らない
- 縮退する形でも、トークンに分けられる限り作る（`degraded` と理由は残る）。閉じない引用と閉じないヒアドキュメントでは作らない

値を取るオプションは次のとおり（元の定義は `shellread_words._RUNNERS` と、シェル・`xargs` の一覧）。

| コマンド | 次の語を値に取るオプション | 前に置く位置引数 |
|---|---|---|
| `env` | `-u` `--unset` `-C` `--chdir` | 0 |
| `exec` | `-a` | 0 |
| `time` | `-f` `-o` `--format` `--output` | 0 |
| `nice` | `-n` `--adjustment` | 0 |
| `sudo` | `-u` `-g` `-C` `-h` `-p` `-U` `-r` `-t` `-T` `-D` `-R` `--user` `--group` `--close-from` `--host` `--prompt` `--other-user` `--role` `--type` `--command-timeout` `--chdir` `--chroot` | 0 |
| `doas` | `-u` `-C` | 0 |
| `timeout` | `-s` `--signal` `-k` `--kill-after` | 1（時間） |
| `stdbuf` | `-i` `-o` `-e` `--input` `--output` `--error` | 0 |
| `chrt` / `taskset` | — | 1 |
| `ionice` | `-c` `-n` `-p` `--class` `--classdata` `--pid` | 0 |
| `command` / `nohup` | — | 0 |
| `sh` `bash` `zsh` `dash` `ksh` | `-o` `+o` `-O` `+O` `--rcfile` `--init-file` | — |
| `xargs` | `-I` `-n` `-P` `-d` `-L` `-s` `-E` `-a` `--max-args` `--max-procs` `--delimiter` `--arg-file` `--max-chars` `--max-lines` `--process-slot-var` | 0 |

`--unset=HOME` や `-o0` のように値が同じ語に入っていれば 1 語。短いオプションをまとめた形（`-Eu me`）は、値を取る文字が
最後に来たときだけ次の語を値に取る。一覧に無いオプションは値を取らないものとして読む。

一覧は組み込みで持ち、ルールファイルからは足せない（コアファイルの組み込みの保護と同じく、ルールを書き換えて外せないようにする）。一覧に無い実行役のコマンド（`script -c`・`watch`・
`parallel`・`busybox sh`・`su -c`・`ssh host <cmd>`・`perl -e`・`python -c`）は外さず、先頭に固定したルールにはヒットしない。
変数の値・alias・関数の中身も読まない（12.1）。コマンド名の位置に変数を置いた形（`$SUDO rm …`）は書き直しを求める形として
止める（6.3）。

適用する先の線引き（`judge`）: 層は止める側のルールにだけ適用する。`judge` がルール 1 本ずつ、元の形に適用し、ヒットしなければ層を
並べた順に適用し、最初にヒットした層で止める。PowerShell は `shellread` で読まないので層は無い。

| 適用する先 | 元の形（読み切れなければ生の文字列） | 中で実行されるコマンド | `cd` で移った先（6.3.2） |
|---|---|---|---|
| `deny` / `ask`（組み込み・ユーザ） | 適用する | 適用する | 適用する |
| `allow` | 読み切れたときだけ適用する（6.3） | 適用しない | 適用しない |
| サブエージェントの禁止（`phase_forms.forbidden`） | 適用する | 適用する | 適用する |
| 止めている間でも通す形（`phase_forms.exempt`） | 読み切れたときだけ適用する | 適用しない | 適用しない |
| チケットの範囲（`ticket_verdict`） | Bash には適用しない（9.5） | 適用しない | 適用しない |

層は元の形の判定を消さないので、読み違えても緩くはならない。`allow` と `exempt` に適用すると、`sudo -u me cat /etc/hosts` の
中身が読み取りの `allow` にヒットして通るように、向きが逆になる。

コードと文面: 層でヒットしたルールの文（6.4）には、`subject:` の次に 1 行足す（`reasons.ran_by`）。層は目印を空白に戻して
1 行にまとめ、200 字で切る。

```
[ccnavi] DENY_COMMAND_PATTERN (rule: builtin:guard-setting-files)
subject: env rm -f .ccnavi/config/common/rules.yml
`env` が実行する `rm -f .ccnavi/config/common/rules.yml` にヒットしました。
ガード自身の設定と hook を、…
```

- 層でヒットした件には、読めなかった断り（6.3 の縮退）を付けない
- `deny` のコードは、ヒットしたルールが全部層でヒットしたなら、縮退していても `DENY_COMMAND_PATTERN`。1 本でも元の形でヒットし、
  縮退していれば `PARSE_UNCERTAIN`。ただし承認のルール（`builtin:guard-ticket-approval`）がヒットした件に入っていれば、
  どこでヒットしたか・縮退しているかに依らず `DENY_TICKET_APPROVAL_CLI` を優先する（元の形が縮退していれば読めなかった
  断りは付く）。`PARSE_UNCERTAIN` の件数で数える集計とはずれる。`ask` は `RULE_ASK` のまま。生の文字列の `>` が上限（50 個）を超えて組み込みの保護を適用せずに止めた回は `DENY_REDIRECT_LIMIT`。ルールの `deny` にヒットしていれば、そのルールのコードのまま
- 記録の欄 `unwrapped` には、ヒットした層だけを `\x00` でつないで残す（同じ層は 1 回）。元の形でヒットしたルールの分は空。
  サブエージェントの禁止は、元の形でヒットせず層でヒットしたときにその層を残す。`--test --json` にも同じ欄が出る

#### 6.3.2 `cd` で移った先

`cd` で入ってから書くと、行き先のパスからディレクトリの名前が消える（`cd .claude && echo x > settings.json`）。そのため、
`cd` の行き先を継ぎ足したパスも作って適用する。

組み方（`shellread`）: `read()` は、`cd` の行き先を継ぎ足したコマンドと、そこから 1 枚ずつ外した層（6.3.1）を
`Reading.moved` に `\x00` でつないで返す。`judge.screen` がそれを中で実行されるコマンドの層と同じリストに足し、実行役の
コマンドの名前には `shellread.MOVED`（`cd`）を置く。適用する先は 6.3.1 の表のとおり止める側のルールだけ。
書かれた表記（`Reading.text`）は動かさない。

- 読むのは `cd <リテラル 1 語>` だけ。行き先は `.` と `..` を正規化して継ぎ足し、絶対パスはそのまま使う。末尾の区切りは残す。
  `builtin cd` と `command cd` も `cd`。`env -C <パス>`・`sudo --chdir=<パス>` は、その 1 本だけ行き先を移す
- 継ぎ足すのは、リダイレクトの行き先と、コマンドの名前より後ろの語。リダイレクトはコマンドの位置より前に書いたもの
  （`> settings.json cat x`）とコマンドが無いもの（`> settings.json`）にも適用する。`dd of=<パス>` のように値にパスを取る語は、
  名前を残して値だけ継ぎ足す
- コマンドの位置の語、オプション、代入、絶対パス、`2>&1` のような fd の番号には継ぎ足さない。実行役のコマンド（`_RUNNERS`）を
  通した形は、中で実行されるコマンドの名前の位置を `_peel` と同じ読み方で出して、その後ろに継ぎ足す
- `cd` の行き先の語そのものは書かれたまま残す
- サブシェル `( )` は出入りで居場所を戻す。`|` `|&` `&` の左はサブシェルである。
  `case` から `esac` までは読まない
- 行き先が書かれた文字列から決まらない `cd`（引数なし・`cd -`・`~`・変数やグロブ・一覧に無いオプション・`pushd` `popd`）の
  あとは、継ぎ足さないだけで縮退させない（縮退すると書かれた表記で止まっている形が止まらなくなる）
- `$( )` の中身は外側の行き先を持たないが、中身の中の `cd` は中身に影響する
- 居場所のパスは 256 字（`_HERE_LIMIT`）、1 回の読みで継ぎ足す語数は 2000 語（`MOVED_WORDS`）まで。越えたら継ぎ足さない

文面: 層と同じ 1 行を足す（`reasons.ran_by`）。記録の `unwrapped` にはヒットした層が残るが、実行役のコマンドの層と同じ欄なので区別は付かない。

```
[ccnavi] DENY_COMMAND_PATTERN (rule: builtin:guard-setting-files)
subject: cd .claude && echo x > settings.json
`cd` で移った先から見ると `echo .claude/x > .claude/settings.json` で、そこにヒットしました。
ガード自身の設定と hook を、…
```

### 6.4 判定の文面

文面は、勝ったタイプのヒットしたルールを全部持つ。`deny` / `ask` は 1 件ずつ、`[ccnavi] <コード> (rule: <id>)`
/ `subject:` / （縮退の断り）/ `message` の閉じた文にし、空行で並べて 1 回で返す（REQ-HNT-01）。
同じイベントの hook は並行して走る。そのため、文はそれだけで成立させる。

縮退した回の文面は日本語で、読めなかった理由（`xargs`・`find -exec` の後ろ、`$'…'`、閉じない引用）ごとの書き換え例を添える。
非対話のセッション（`CLAUDE_CODE_SESSION_ATTENDED` が `0`）では、確認に答えられないので書き直すことを 1 行足す。

例外が 1 つある。同じ理由で同じ呼び出しを `CCNAVI_DENY_REPEAT` 回（既定 3）止めたら、その回から末尾に
「言い換えて打ち直さず、ユーザに相談する」一文を足す（`repeat`）。止められた側が文面から次の一手を読めず、
言い回しを変えて打ち直していても、1 回ごとの文面にはそのことが反映されないため。数えるキーは（判定を下したルールの id,
引用符を外して空白を均した対象のハッシュ）で、記録はセッションごとに `logs/state/denied-<セッション>.json`。
止めた回に 1 回読んで 1 回書くだけで、期限（3 秒）を圧迫しない。数えるのは `enable` の `deny` だけ（`dry-run` と `ask` は数えない）。
対象は均した文字列のハッシュだけを置き、表記は置かない。均すのは引用符（`'` `"` `` ` ``）を除き、連続する空白（改行・タブを含む）を 1 つにして前後の空白を除くことだけで、大文字と小文字は分けたまま数える。
payload にセッションが無ければ数えない。
記録を読めない・書けないときは何も足さず、判定は変えない。
ターンの終わり（7.4）には、N 回に達したキーをルールの id と回数でユーザへ 1 度だけ報告する。

もう 1 つ、`deny` は失敗の連続（`failstreak`）にも数える。ツール自体の失敗（`PostToolUseFailure`）と合わせて
`CCNAVI_FAIL_STREAK_COUNT` 回（既定 3。0 で無効）続いたら、その回の文面の末尾に資料の索引（`--docs`）を引く案内を足す。
こちらは `dry-run` の `deny` も数える（`dry-run` は判定を変えないので、案内を出してよい）。`ask` は数えない。ツール自体の失敗はユーザの中断を除く。案内は止められた操作の迂回を勧めず、
止まった理由と決まった手順を資料で確かめ、分からなければユーザに相談するよう書く。連続は成功（`PostToolUse`）で 0 に戻り、
案内は 1 つの連続で 1 回。記録はセッションとエージェント（サブエージェントの中は別に数える。案内はその文脈のモデルにしか届かないため）ごとに `state/failstreak-<セッション>-<main|エージェント>.json`。
payload にセッションが無ければ数えず、記録を読めない・書けないときは判定だけを続ける。

### 6.5 ルールが言及しない呼び出し

ccnavi は判定を返さず、Claude Code の権限モードに従う（REQ-PRE-10）。

| `permission_mode` | 結末 | 記録の `decision` |
|---|---|---|
| `auto` | classifier が判断する | `handover` |
| `default` / `acceptEdits` / `plan` | Claude Code 自身の権限の仕組みが決める | `handover` |
| 空 / 不明 | ユーザに確認が出る | `ask` |
| `dontAsk` / `bypassPermissions` | 通さない（REQ-PRE-08）。`CCNAVI_GUARD_UNWATCHED=disable` なら委ねる | `deny` |

渡した回も記録には `decision` が `handover` の行で残り、ユーザに聞いた回の `ask` とは混ざらない。集計は次のように取れる。

```sh
jq -r 'select(.decision == "handover") | .subject' logs/decisions.jsonl | sort | uniq -c | sort -rn
```

`CCNAVI_GUARD_UNWATCHED=disable` と書いたレイヤーがあると、`--lint` が切れていることを warn で知らせる。

確認と拒否の回の文面は、結末と読み切れたかの組で次の一手を変える（`reasons.undeclared`）。

| 読み切れたか | 結末 | 次の一手 |
|---|---|---|
| 読めた | `ask` | 普段の作業ならそう言い、ルールファイルの `allow` に足すようユーザに頼む |
| 読めた | `deny` | `allow` にあるもので代えるか、足すものをユーザに伝える |
| 読めない（`PARSE_UNCERTAIN`） | `ask` | 用途を言うか、読める形に書き直す |
| 読めない（`PARSE_UNCERTAIN`） | `deny` | 用途を言っても通らない。読める形に書き直し、書けなければ何に要るかをユーザに伝える |

組み込みの既定に退避した回（5.6）は、出所を `(ccnavi built-in defaults)` にし、読めなかったルールファイルへ
`allow` を足せとは言わない。直し方は同じ応答の退避の文が言うので、それを指すだけにする。読めない回の断りは
「どのルールも言及していない」と言い、ヒットしたルールを指す「this rule」は使わない。

理由コードは `UNDECLARED`。ルールの `ask` にヒットした呼び出し（`RULE_ASK`）は権限モードによらず確認に出す。判断できる相手が居る
4 つのモードでは確認を上乗せしない。確認できる者が居ないモードで通さないのは、ask が「誰も答えないまま通る」に
変わってしまうため。縮退した呼び出しは委ねない（6.3）。`CCNAVI_GUARD_UNWATCHED=disable` でも委ねない。
生の文字列の `>` が上限を超えて組み込みの保護を適用しなかった回は、この表に依らず、どのモードでも止める（`DENY_REDIRECT_LIMIT`）。上限を掛けるのは、外す保護（ガード自身の設定とチケットの置き場を守る組み込み）がそのツールにヒットするときだけ。既定の組み込みだけでチケット制御が無効なら、外す保護は Bash にしかヒットしないので、PowerShell には掛けない。
`CCNAVI_GUARD_UNWATCHED=disable` でも止める。保護の照合を終えていない呼び出しなので、確認には回さない。
上限が無ければ照合が期限を超えて `deadline-exceeded` の block になる入力で、上限はそれを止める側のまま、理由と書き直し方を返す形に変える。

ターミナルからの試験（10 章）には `permission_mode` が来ないので、言及の無い呼び出しは `ask` として出る。

`permissionDecision` を返すのは `deny` と `ask` だけで（`judge.refuse`）、
`allow` は記録に残して終わる。`allow` の働きは、この表の結末（確認と拒否）を起こさないことと、`additionalContext` を
適用する先になること。`allow` を足しても Claude Code の確認は省けない。

### 6.6 モデルへ渡す文

ヒットしたルールの `additionalContext`（渡す回のたび）と `additionalContextOnce`（文脈で渡す回の最初の 1 回）を、判定とは別の経路で届ける。
文脈は `session_id` と `agent_id` の組で、サブエージェントはその起動ごとに別に数える。記憶は
`state/once-<セッション>-<エージェント>.json` に「キー → ヒットした回数」で置き（キーはルールの `id`、無ければ `match` と表記の組）、`SessionStart`（起動・再開・compact の後）で破棄する。

| 何が起きたか | どうなるか |
|---|---|
| state の置き場が無い（`--state ""`） | 数えず、毎回届ける |
| 記録がまだ無い | 1 回目として数え、書く |
| 記録を読めなかった | 届ける側を採り、書き戻さない。一時的に開けないだけなら `fsio.read_json` が数回打ち直す |

記録は一時ファイルに書いてから差し替える。once の記憶は文とファイルで分けず、ルール 1 件で 1 度と数える。

`additionalContextOnce` の文を渡した呼び出しには、判定の記録に `hinted: true` を付ける（付録 B）。2 回目以降と、毎回渡す文だけの呼び出しには付けない。
`PreToolUse` のルールの文だけが対象で、チケットの提案の助言とプロジェクトのスキルの目録には付けない。

#### 渡す回

`every: N` を書くと、そのルールがヒットした回数が `N` の倍数になった回だけが渡す回になる。書かなければヒットするたびが渡す回。

| 欄 | いつ渡るか | `every: 5` のとき |
|---|---|---|
| `additionalContext` | 渡す回のたび | 5・10・15… 回目 |
| `additionalContextOnce` | 渡す回の最初の 1 回 | 5 回目だけ |

本文のファイルも同じで、`additionalContextFile` は `additionalContext` に、`additionalContextOnceFile` は `Once` に従う。
数えるのはそのルールがヒットした回数で、ファイルの本数でも時間でもない。
「1 回目に言いたいこと」と「たまったところで言いたいこと」を両方言うならルールを 2 件書く。
`Bash` を `match` に書かない限り、シェルやビルドが書いたファイルは数えない。
`--lint` は、何にでもヒットする `allow`（`glob: "*"` など）と選択肢が 3 つ以上ある `regex`（`(ls|cat|sed)`）に書いた `additionalContext` を warn にする。同じ文がヒットするたびに積まれるため。`every` を書いたルールには該当しない指摘なので出さない。渡すものが無い `every` は warn。

`every: 1` は `--lint` が何も言わない。刻みとして読めない値（`0`・負・整数でない）は error で名指しし、判定は 1 として扱って通す。

刻みは `SessionStart`（compact の後を含む）で 0 に戻るので、長い作業で正確に N 回ごとは守らない。compact がいつ起きるかは ccnavi から見えない。

| 書き方 | 0 に戻ると |
|---|---|
| `additionalContext` + `every: N` | 届くのが遅れる。戻りが続けば一度も届かないこともある |
| `additionalContextOnce` + `every: N` | セッション全体では 1 度より多く届く |

| タイプ | どう届くか |
|---|---|
| `allow` | 応答の `additionalContext` として届く |
| `ask` | ユーザが Yes を押したときだけ届く。No なら拒否の定型文だけがモデルに届いてターンが終わる |
| `deny` | `permissionDecisionReason` と一緒に届く |
| `dry-run` | 止める代わりに返す文に続けて届く |

ファイル（`additionalContextFile` / `additionalContextOnceFile`）は、行き先のワークツリー → 元リポジトリの
プロジェクト → ワークスペースルートの順に探し、最初に在ったものを読む。絶対パスと `..` で上に
出るパスは読まない。先頭 4000 文字で切り、切ったことと続きの在りかを末尾に添える。
無ければ何も足さず、`--lint` が warn で知らせる。`--test` と「判定を試す」には、モデルに届くものと同じ形（切った後）で出る（REQ-PRE-12）。同じタイプに複数ヒットすれば全部の文を空行で区切って並べる。

#### ターンの終わりに渡す文

`match` に `Stop` を書いた `allow` のルールは、メインエージェントのターンの終わり（`Stop`）にヒットする（REQ-PRE-17）。
適用する先の文字列は無いので固定の `(stop)` に適用し、ルールは `glob: "*"` と書く。渡す回にだけ `decision: block` で止め、`reason` を
`NUDGE_STOP_RULE: ` と決まった前置き（`events.STOP_PREFACE`）とルールの文にする。`every: 10` なら「ターンの終わり 10 回に 1 度」になる。
ルールの文を振り返りの手順にする前提の仕組みで、前置きもそう書いてある。

| 何を | どうするか |
|---|---|
| 読むレイヤー | 共通レイヤーとワークスペース自身のレイヤーだけ（`ruleload.stop_rules`）。プロジェクトのレイヤーは外のリポジトリにあり、そこに書いた 1 行が cwd に依らずメインのターンを止めることになり、ミラー（11.12）をワークスペースの中で読むと同じルールを二重に数える |
| 同じ id | レイヤーの前置きを除いた id が同じなら、最初の 1 本だけ |
| `every` | 2 より小さいものは実行時にも使わない（ターンの終わりのたびに止まる） |
| 本文のファイル | ワークスペースルートの版だけを読む。ワークツリーやプロジェクトにある版はエージェントが書き換えられる |
| 前置き | 「タスクの続きではない。振り返りだけをする。ユーザへの問い・確認で終わったターンなら、その問いを最後にもう一度書く。何も無ければ『振り返り: 無し』とだけ答える」。実行ファイルが持ち、ルールの文やファイルが何であっても付く |
| 数え | `state/stop-<セッション>.json`。compact・再開・clear では破棄せず、起動（`SessionStart` の `source=startup`）と古いセッションの後始末（prune）でだけ破棄する。`once-*` と同じ置き場だが、文脈ではなくセッションで数える |
| 記録 | `decision` は `nudge`、`code` は `NUDGE_STOP_RULE`、`rules` は実際に渡したルールの id だけ |

| 何が起きたか | どうなるか |
|---|---|
| `stop_hook_active` が真（Stop の hook が続けさせた連鎖の 2 回目以降） | 止めず、数えも進めない |
| 同じ Stop フック呼び出しで、`finish` の促し、レビュー依頼までの道の促し、サブエージェント結果の促し（`NUDGE_SUBAGENT_OUTCOME`。範囲外の変更を残したか、範囲を確かめられないまま終わったサブエージェントがある。同じ結果では 1 回。9.12）、直接作業の `integrate` の促し（下）のどれかがターンを引き止める | その促しだけを出し、ルールは数えもしない。1 回の Stop フック呼び出しで引き止める理由は 1 つだけ。順序は `finish` → 依頼までの道 → サブエージェント結果 → `integrate` → ルール |
| サブエージェント（`agent_id` がある。`SubagentStop` も） | 見ない。代わりに `SubagentStart` で「気づいたスキル候補は最後の報告に節を足して返す」の 1 行を渡す（9.12） |
| state の置き場が無い（`--state ""`）、記録を読めない・書けない | 止めない。覚えられないまま止めるとターンの終わりのたびに止まるので、何も言わない側を採る（上の表の「届ける側」と逆） |
| `dry-run` | `enable` と同じく止める（`finish` の促しと同じ）。Stop でモデルに文を届ける経路は止めることしか無いため、モードの約束より文が届くことを優先する |

- 保護領域の報告（7.4）と繰り返しの拒否の知らせは、止めたときも同じ応答の `systemMessage` に載る
- `--lint` は warn で言う: `deny` / `ask` に書いたもの（`Bash|Stop` なら `Stop` の部分だけ）、プロジェクトのレイヤーに書いたもの、`(stop)` にヒットしない表記、`every` の無いもの
- `--test Stop "(stop)"` と期待（`tool: Stop`）は、使われるルールを並べる。あれば `allow`、無ければ判定に入らない（10 章）
- 書いたルールが無ければ、今までどおり止めない

#### `finish` の打ち忘れを促す

メインエージェントの `Stop` で、cwd のワークツリーに結び付いたチケットが着手済みで、そのワークツリーに未コミットの変更が無く（追跡していないファイルも数える）、
基準点より先に自分で作ったコミットがあれば（子なら親のブランチ、親なら `origin/HEAD` を取り込んだだけのコミットとマージのコミットは数えない）、
`{"decision": "block", "reason": …}` で止める（理由コード `NUDGE_TICKET_FINISH`。条件と除く形は 9.6）。
文には `ccnavi-ticket.sh finish <識別子>` の書き方と「まだ続けるなら理由を書いてから終える」を書く。保護領域の報告があれば同じ JSON の `systemMessage` に載る。
記録の `decision` は `nudge`。同じセッションで同じチケットを同じ HEAD のまま促すのは 1 回だけで（記録は `logs/state/nudged-<セッション>.json`）、コミットを足せばまた促す。
`dry-run` でも止める（止めないと文がモデルに届かないため）。順序の先頭で、この促しが止める回は、以降の促しとルールを出さず、覚えもしない。

#### レビュー依頼までの道の途中で終えたとき

チケット作業の道（子の `finish`（親ブランチへの合流を含む） → ELI5 → `ccnavi-review.sh request`）の途中で、確認を取ってターンを終えるのを `Stop` で 1 回だけ止める（REQ-PRE-18。理由コード `NUDGE_TICKET_REQUEST`。チケット側の条件と除く形は 9.6）。ルールではなく状態で決める。文は `STOP_PREFACE` と同じ考え方で、決まった道の途中でユーザの許可は要らないこと、状態に応じた次のコマンド、ユーザの判断が本当に要る問いなら最後に書き直すことを言う。`finish` の促しと同じく `dry-run` でも止め、同じ状態では 1 回だけ（`nudged-<セッション>.json` の `request:` で始まるキー）。順序は `finish` の促し → この促し → 直接作業の `integrate` の促し → `match: Stop` のルール。

`finish` の促しと依頼までの道の促しは、このセッションに実行中のサブエージェントが居る間（`subagent.running`。記録を読めないときも）は見送り、「1 回だけ」の記録も進めない。委任して待つ回の誤った促しを防ぐだけで、メインが自分から早く `finish` を打つことは防がない。

#### フィードバック計画待ちを促す

親の局面（`phase.stage`）が「フィードバック計画待ち」のまま、メインエージェントがターンを終えようとしたとき、`Stop` で 1 回だけ止める（理由コード `NUDGE_TICKET_FEEDBACK`。`tickets/ops_stop_feedback.py`）。順序は `finish` → 依頼までの道 → フィードバック計画 → サブエージェントの結果。改版を書いて `ccnavi-ticket.sh propose` で送り、ユーザに承認を頼む。親のワークツリーの提案の置き場（`todo/`）に、親と同じ識別子で `feedback:` を持つ提案があれば「提案済み」の文面（送っていなければ送る・`status` で確かめる）、無ければ置き場の絶対パスと書き方（スクリプトだけが書く欄は空にする）を言う。同じ状態（親・HEAD・改版を提案済みか）では 1 回だけ。止め方とモードの扱いは依頼までの道の促しと同じ。

#### 直接作業の取り込みを促す

チケットに結び付かない直接作業のワークツリー（`.claude/worktrees/<名前>`。ブランチも同じ名前）で作業を終えようとしたとき、作業が残っていて、`integrate <名前>` の記録が無ければ、`Stop` で 1 回だけ止める（`NUDGE_INTEGRATE`）。直接作業はチケットに結び付かないので、チケット制御の有無は問わない。実行中のサブエージェントの印（`SubagentStart` が置く）も、チケット制御によらず置く。作業が残っているとは、未コミットの変更（追跡していないファイルも数える）があるか、統合先に入っていないコミットがあることをいう。記録は 2 種類ある。一つは統合先のツリーの git ディレクトリにある `ccnavi-integrate/<名前>/`（取り込みの途中）で、もう一つは片付けた記録のコピー `ccnavi-integrate-done/<名前>` である。コピーは、その `branch_sha` が今の HEAD と同じで、未コミットの変更も無いと確認できたときだけ「記録あり」とみなす。名前を使い直した作業を、前のコピーで黙らせないためである。コピーを読めないときは「記録なし」とみなし、促す側に倒す。チケットに結び付くかどうか（承認済みチケット・提案・HEAD のブランチが origin にある親のワークツリー `.claude/worktrees/<識別子>`）の判定は、`ccnavi-git.sh integrate` と同じである（実行ファイルの `bound_reason`。sh は `ccnavi tree bound` に聞く）。`integrate` が断る名前（`main`・`master`・`develop`・`release`・`release-*`、識別子の形でないもの）は促さない。統合先は、そのリポジトリの手元の `origin/HEAD`（無ければ `origin/main`・`origin/master`）で決める。

**調べる対象。** 1 本のツリーを調べた結果は、「ヒットする」「ヒットしない（確認済み）」「不明」のどれかになる。不明は、期限不足・git の失敗・ブランチを読めない・チケットとの結び付きを決められない・`_dirty` が読めない、などの場合である。不明のときは候補を外さず、促した記録も残さない。外してよいのは、ディレクトリが無い・HEAD のブランチが名前と違うと読めた・チケットに結び付くと分かった・`integrate` が受けない名前のときだけである。調べる順番は、まず cwd のツリー、次に候補の記録（`logs/state/direct-<セッション>.json`。`direct_candidates`）である。候補は `checked` の古い順に調べ、未調査のものを先にする。調べ始めた候補は、結果が不明でも `checked` を今にする。そのため、毎回同じ候補で時間を使い切っても、次の回にはその候補が後ろへ回る。cwd の候補を既に促していれば、記録の別の候補を促す。

**候補の登録。** 成功した `Write`・`Edit`・`NotebookEdit` の書き込み先が `.claude/worktrees/<名前>` の直接作業のツリーなら、そのツリーを候補の記録の末尾へ移す。`seen` は今にして、`checked` は 0 にする。メインにもサブエージェントにも効き、サブエージェントの候補は親のセッションの候補になる。git は呼ばず、ファイルシステムだけを使う。上限は 50 件で、超えたら `seen` の古いものから破棄する。登録は書き込みの先に限る。そのため、Bash だけで編集・コミットしたツリーは、Stop の時点で cwd がその中にあるときだけ拾える。記録は促しの候補であり、担当の証明ではない。保存できなかった候補、並行して書かれて 1 件落ちた候補、上限で破棄された候補は補わない。

**期限。** Stop の期限は `time.monotonic` の絶対時刻で、`decide_at_stop` から `direct_at_stop` まで渡す。期限つきの git（`gitcmd.run_until`）は、残りの時間から 0.5 秒を引いた値と既定の timeout のうち小さいほうで起こす。残りが 0.2 秒以下なら起こさない。保証するのは「期限を過ぎてから git を起こさない」ことだけである。処理全体が期限内に終わることは保証しない。

文には、`integrate` の打ち方（ユーザのチェックアウトで打つ。取り込み結果は一時ワークツリーに展開され、ユーザのチェックアウトには書かれない）、ユーザに差分と変わるファイルの一覧で確かめてもらうこと、`integrate-done` と `integrate --abort` の使い分けを書く。コマンドは 1 行で完結させる。別のツリーで打つものは `cd <引用したパス> && <ラッパー> …` で始める。Bashのcwdが次の呼び出しに残るとは限らないからである。メッセージは `-m '<メッセージ>'` と単引用符で書く。ラッパーを通らない `git` は文に残さない。hook自身は `integrate` を打たない。取り込み先は直接作業の記録の `base_branch` で決める。記録が無いときだけ、`ccnavi_integration` に従い、そのリポジトリの手元の `origin/HEAD`（無ければ `origin/main`・`origin/master`）で数える。

`integrate` の前提を満たせないときは、止めずに理由を `systemMessage` で 1 回だけ伝える。伝える理由は次のとおり。取り込み先が決まらない。ユーザのチェックアウトが取り込み先を開いていない（ブランチが切り替わった）。ユーザのチェックアウトに途中の操作がある。直接作業の記録が壊れている、または共通ディレクトリが合わない。未コミットの変更があるのに取り込み先のrefを引けない。コミットだけがあって統合先のrefを引けないときは、統合先に入っているかを数えられない。誤って促すより黙るほうを採り、不明として扱う。同じ状態（促すか理由か・未コミットの有無・統合先に入っていないコミットの数・HEAD）では、1 回だけ伝える。記録は `nudged-<セッション>.json` の `integrate:` で始まるキーに残す。残すのはヒットしたときだけである。`finish` の促し・依頼までの道の促しが止める回は、出さず覚えもしない。`dry-run` でも止める。実行中のサブエージェントが居る間は止めず、「1 回だけ」の記録も進めない。

セッション開始の知らせ。`SessionStart`（サブエージェントを除く）で、ワークスペースルートと各プロジェクトの元ツリーに残った `ccnavi-integrate/<名前>/marker` を知らせる（`pending_integrate`）。チケット制御は見ない。記録が無ければ何も足さず、gitも呼ばない。`.git` がディレクトリなら、ファイルの有無で記録を見る。版 4 のmarker（`version 4`）は、別の見方をする。Kを作ってあるか、取り込み先に載っているかを見て、続きの一手（`integrate-done` の打ち直し、`integrate --abort`、abortしてから打ち直し）を出す。Kの親が記録の `head`、Kの木が `c_tree` と合わないもの、必須の項目が欠けたものは、壊れた記録として「操作せずにユーザに確かめる」と出し、自動では再開しない。markerが無くても、残った一時ワークツリー・専用のref・片付けの途中の取り込み済みの記録を挙げる。版 4 でないmarker（版の無いものを含む）は、版を知らない壊れた記録として、同じく「操作せずにユーザに確かめる」と出す。別のセッションの取り込みの場合もあるので、ユーザに確かめるよう言う。期限はhookの期限と開始から 2 秒のうち小さいほうとする。期限が足りなければ「ほかのツリーは時間切れで確かめていません」と言う。モデルの文脈と `systemMessage` の両方に出す。索引（docsearch）より先に組む。
