# モジュール構成

実行ファイル（`go/`、module `ccnavi`）のパッケージと、その役割のまとまりを書く。
パッケージ 1 つごとの役割は、そのパッケージの `doc.go` に書いてある。ここにはコピーしない。パッケージを足す・名前を変える・役割が動くたびに、この表を直さなくて済ませるため。
`go/internal/` の直下のまとまりの層（読む向き）は、下の表の上から下の順で、`go/internal/layers_test.go` が import の向きを見る。
リポジトリのトップレベルの置き場は、開発の入口（40_development.md）の「ディレクトリ構成」にある。

## 入口と直下のまとまり

| 場所 | 役割 | 読むもの |
|---|---|---|
| `go/cmd/ccnavi/` | 実行ファイルの入口。標準入出力と引数を `entry/cli` の `Run` に渡すだけ | `entry` |
| `go/cmd/ccnavi-chrome/` | Chrome 拡張が読む WASM の入口。要求の JSON を `entry/chrome` に渡す | `entry` |
| `go/internal/infra/` | 土台。ファイル・git・パス照合・hook の入出力・設定・シェルの読み・ワークツリー | どれも読まない |
| `go/internal/records/` | 記録。伏せ字・判定の記録・診断ログ・後始末・拒否や失敗の数え・ターン中の印・学びの蓄積・放置セッションの引き継ぎ促し | `infra` |
| `go/internal/policy/` | ルール。読み込み・照合・組み込み・レイヤーの合成・自己防衛・文脈ファイル | `infra`、`records` |
| `go/internal/tickets/` | チケット。置き場、合意の手続き、承認・レビュー済みの判定、フェーズ、リスク、操作、ユーザの発言のときの共通レイヤー・工程スキルのミラー | `infra`、`records`、`policy` |
| `go/internal/catalog/` | 目録。文書の索引と `--docs` の引き方、プロジェクトのスキルの目録 | `infra`、`policy`、`tickets` |
| `go/internal/hook/` | hook の判定。実行前チェック・文面・実行後チェック・イベント・サブエージェント | `infra`、`records`、`policy`、`tickets`、`catalog` |
| `go/internal/entry/` | 入口。CLI・診断・lint・提案・版・Chrome 拡張の入口 | 下の全部。どこからも読まれない |

同じまとまりの中の読む順（段）は、`layers_test.go` の `subTiers` が持つ。パッケージを足したら、その表に段を足す。

## infra

土台。どのまとまりも読まない。

| まとまり | 役割 |
|---|---|
| hook の入出力・設定・モード | stdin の payload の解釈と応答の組み立て（`hookio`）、環境と設定ファイルからの設定解決・enable / dry-run / disable の 3 値と終了コード・ツール名の組・秒数のしきい値（`config`）、環境変数の名前（`env`） |
| パスと名前の比較 | 大文字小文字だけが違う名前を同じものとして扱うキー（`pathcase`）、glob から正規表現への翻訳（`pyre.TranslateGlob`）。パスと名前を比べるときは必ず `pathcase` を通し、自分で小文字にしない |
| 途中のリンクの判定 | 書き込み先・削除先までの道にシンボリックリンクか junction があるか（`pathmatch`）。調べる途中で失敗したときと root の外に出るときは、拒否する側（リンクあり）に倒す。書き込み先・削除先までの道をたどってリンクを探す判定は、必ず `pathmatch` を通す |
| シェルの読み（`shell`） | コマンド文字列のうち実際に実行される部分の切り出し。走査、語の見分け、`cd` で移った先の追跡をファイルに分けてある |
| ファイルと YAML | 読み書きの型（`fsio`。state の記録・マーカー・承認済みチケット・下書きは全部これを通る）、エージェントが書く YAML の読み手（`yaml`。YAML 1.1 の真偽・8 進・時刻を、ルールを書いた人の想定どおりに読む） |
| git とワークツリー | git を 1 回起動する（`git`。期限つきの起動は期限を過ぎてから起動しない）、ワークツリーの変更を git から読む、ワークツリーの特定、直接作業の記録を読む（`tree`。書かない） |
| 読み手に届くエラーの形 | 識別子・差し込む値・文面を引けないときの 1 行を持つ共通の形（`fault`）。エラー型が埋め込み、文にするのは出力の境界（`policy/texts` の `SayFault`）。`fault` 自体は文面ファイルを読まない |
| 答えを揃える土台 | 正規表現（`pyre`。ルールの `regex` を、書いた人の想定どおりの書き方で読む）、引数の読みと usage の文（`argparse`）、JSON の出力（`pyjson`）、値の文字列化（`pyfmt`）、差分（`difflib`）。どれも、ルールファイルと拡張・sh が読む出力の形を 1 字も変えないための写し |
| 機械の語 | `<os>-<arch>`（`platformtag`）。組み立ての置き場と、振り分けの sh が起動する実体の探し方 |

## records

| まとまり | 役割 |
|---|---|
| 記録 | 1 行 1 件の追記記録（`audit`）、診断ログ（`diaglog`。`logs/diag/<出どころ>.log`）、記録に残す文字列から秘密の形をした部分を伏せる処理（`redact`） |
| 後始末 | 記録と state のローテート、古い記録と終わったセッションの記録の削除（`prune`） |
| 数え | ターンの終わりに残っていた作業、ツール呼び出しの失敗や拒否の連続、同じルールの繰り返し（`turn`・`tally`）。判定は変えない |
| Stop の AI 判定（`stopreview`） | 判定計画・試行・結果の検証と最終分類、評価の集計、approval-request の操作実績 |
| 学びの蓄積の wiki（`wiki`） | パターン・採否の記録の読み取り。ワークツリーか git のオブジェクトから読む |
| 引き継ぎの促し（`handoff`） | 放置された大きな会話に、次のセッションへの引き継ぎを書かせる |

## policy

| まとまり | 役割 |
|---|---|
| ルールの読み込みと照合 | ルールファイルの読み込みと照合（`rules`）、文の差し込み（`texts`）、検査（`rulelint`。`--lint`・保護対象の下書きの取り込み・提案の候補の検査が呼ぶ）、この呼び出しに適用するルール集合を決める（`ruleload`。ワークスペース・プロジェクト・その和） |
| 組み込みの既定 | ルールファイルを読めないときの組み込み既定（`builtin`） |
| モデルへ渡す文 | ヒットしたルールがモデルへ渡す文（additionalContext）。ファイルの本文と once の記録（`ctxfile`） |
| 自己防衛（`selfguard`） | ccnavi 自身の設定ファイルと実行ファイルのバックアップと復元、守る対象の一覧、守る対象へのシェルからの書き込みを止める組み込みのルール |

## tickets

下の段から順に並べた。段の大きいものは、段の小さいものだけを読む。同じ段どうしは読まない（順は `layers_test.go` の `subTiers` の `tickets` が持ち、検査する）。テストだけが読む道具（`testkit`）は一番上の段に置き、本体からは読めない。

| 段 | パッケージ | 役割 |
|---|---|---|
| 0 | `model/` | 型と名前。書式の定数・状態の名前・範囲の項・計画のステップ、識別子とブランチ名の規則、状態の置き場を守る組み込みのルール、親子の立ち位置、誰がどの経路で動かしたか、ユーザだけが打つ操作の表（hook の止めとターミナル要求が引く正本）、ホストへの送信の段階の記録、閉じた親子の退避 |
| 1 | `config/` | フェーズ定義（`phases.yml`）の読み込み、ワークフロー、実績で測るリスク、設定の検査 |
| 1 | `flow/` | 子チケットのフロー（置き場・形の検査・文面の整え方・描き方） |
| 2 | `approval/` | 承認済みチケットの置き場と操作。読み込み・走査・提案の集め方、承認・欄の書き換え・閉じる・レビューへ送る、マーカー、構造の検査、write-and-push の見分け |
| 3 | `phase/` | フェーズの終わりと HITL ポイント、範囲の適用の仕方、手動で動かした決着 |
| 4 | `learning/` | 気づきの記録・受信箱・判定記録の要約、処理すべきものの判定 |
| 4 | `proposal/` | 合意（`agree`）。承認の対象を集めて `--preview` / `--verify` に答え、書き込みを並べて置き場へ動かす。計画の番号の振り直し・先行関係・親の提案の雛形と形式検査、テンプレートの使う側、提案の送り |
| 5 | `sync/` | 設定・スキル・ミラー・プロンプトの写しの同期、保護対象の下書きの取り込み |
| 6 | `lifecycle/` | 状態を動かす操作。`ticket start / finish / cancel / record-risk`、動かしてよいかの検査、Stop で打ち忘れや道の途中を見つけて促す判定、ワークツリーとブランチの片付け、ブランチの探索、統合の子を作る、合流の前に聞くこと |
| 7 | `notice/` | セッション開始で示す一覧と却下された要求、SessionStart の学びの通知、終わっていない integrate の記録、直接作業のワークツリーの一覧、`scratchpad/` の容量の知らせ |
| 7 | `review/` | 依頼と確認、sh との契約の JSON の形、残った指摘の対応方針の決定、親を閉じる |
| 8 | `core/` | 承認・レビュー済みの判定のコア。`entry/cli` と、`entry/chrome` を通した Chrome 拡張（WASM）はここを引く。手元の承認、レビュー済みの判定、拡張が引く判定と書くものの組み立てをファイルに分けてある |

## catalog

| まとまり | 役割 |
|---|---|
| 文書の索引 | 索引を組む（`docindex`）、問いに答える・SessionStart の案内と失敗が続いたときの案内・frontmatter が無い md の案内（`docs`） |
| スキルの目録（`skills`） | プロジェクトのスキルの目録を作って案内する |

## hook

| まとまり | 役割 |
|---|---|
| 判定の中核 | イベントごとの手順（`events`。1 回の起動で何が起きるかはここを上から読む）、実行前チェック（`judge`）、判定に添える文面と理由コード（`reasons`・`askcontext`）、判定に達せなかったときに通してよい呼び出しか（`failsafe`。設定もルールも読まずに答える） |
| 実行後チェック（`post`） | ワークツリーの読み取り、前からあった変更の記録、復元、変わったファイルを守る場所とチケットの範囲に適用する、差し戻しの文 |
| 書いたあとの案内（`hint`） | 直接作業のコミット後の案内（`PostToolUse` で、メインのエージェントの `ccnavi-git.sh commit` が直接作業のワークツリーで成功したとき、またはメインの Agent ツールが返って直前のコミットのある直接作業があるとき、レビュー手順の次の一手を足す。ワークツリーの名前ごとにセッションで 1 度だけ）と、親の提案を手書きしたときの書式の案内 |
| 実行前に止める形（`shellguard`） | サブエージェントが Bash から親のワークツリーへ書き込む形、Bash からワークスペースルート直下へ書く形（Write / Edit と同じ決まりに適用する）、保護済みの sh を呼ぶ形のうち止めるもの |
| ターン分離（`turngate`） | 「A を打ったら、ユーザの発言が 1 回はさまるまで B を打てない」を止める |
| サブエージェント | SubagentStart / SubagentStop（`subagent`）、終了結果の記録（`outcome`）、編集するものか読み取り専用かの見分け（`agentkind`）、起動ツールの PreToolUse での担当の決定（`launch`）、子 1 本の担当の案内（`childnote`） |
| セッション開始 | 作業の決まり（`.ccnavi/CCNAVI.md`）の条件と差し込み（`ccnavimd`）。目録（`catalog`）の案内を並べる |
| そのほか | Stop の AI 判定の判定役の呼び出しの見分け（`stopjudge`） |

## entry

| まとまり | 役割 |
|---|---|
| CLI（`cli`） | 1 回の起動の入口。標準入出力とコマンドラインを判定や各コマンドへ振り分け、ワークスペースルートを見つける。`--help` の本文、引数の読み分け、サブコマンドごとの入口 |
| lint（`lint`） | 設定とルールの検証。置き場・レイヤー・テンプレート・チケット・ブランチ・直接作業・wiki ごとにファイルを分けてある |
| 診断（`diagnose`） | 判定を実行せずに試す `--test` と `--explain`。名前を引き受ける入口と、試す・説明する・ボードの中身・共有する部品に分けてある |
| Chrome 拡張の入口（`chrome`） | 拡張が WASM で呼ぶ要求を受け、ブランチの中身から仮のツリーを組んで、手元と同じ判定を通す。拡張はここだけを呼ぶ |
| そのほか | sh がチケットについて聞くこと（`shask`。読むだけ）、チケットの状態の表示（`status`）、`--suggest`（`suggest`）、`--version`（`version`） |
