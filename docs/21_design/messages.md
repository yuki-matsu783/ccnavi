## 13. 文面ファイル

エージェントとユーザが読む文（拒否・確認・促し・出力の次の一手）は、条件（いつ出すか）と分けて、文面ファイルに置く。
条件はルールファイルとコードに残り、文面ファイルは識別子で引かれる。止める・止めないの判定に文面は関わらない。

### 13.1 構成

| 担当 | 持つもの | 持たないもの |
|---|---|---|
| ルールファイル・コード・sh | いつ出すか（条件）、どの識別子を引くか、差し込む値 | 文 |
| 文面ファイル | 識別子ごとの文（種類ごとの欄）、差し込みの名前の宣言 | 条件、判定 |
| `policy/texts.py` | 読み込み、レイヤーの和、検査、差し込み、組み立て、壊れたときの既定の文 | 判定 |
| `ccnavi text` | sh から `texts` を引く入口 | 文面ファイルの直接の読み書き |

組み込みの拒否・促し（Python）は `texts.say` を呼ぶ。sh は文面ファイルを読まず、`ccnavi text` を `ccnavi_text`（`ccnavi-common-state.sh`）で呼ぶ。

### 13.2 置き場とレイヤー

- 共通レイヤー: `.ccnavi/config/common/messages/*.yml`。ccnavi が配る
- 自身のレイヤー: 持たない。ワークスペースルートの `.ccnavi/config/project/messages/` に置いても読まない（13.5）
- プロジェクトのレイヤー（`projects/<名前>/`）は読まない。文面はワークスペースの文であり、呼び出しを受けるツリーのものではないから
- 共通レイヤーの中のファイルは名前順に読み、別のファイルに同じ識別子が現れたら、後ろを捨てて `--lint` が error を出す（1 つのファイルの中の重複は YAML の読みが後ろを採るので見分けられない）。ファイルの分け方（`deny.yml`・`nudge.yml`・`next-start.yml`）に意味は無い

保護: `.ccnavi/` の下は、名前で書くツールもシェルからの書き込みも組み込みの `guard-project-home` が止める。文面ファイルはその内側にあり、設定 3 本（コア）には加えない。コアに加えると、バックアップと復元の対象とミラーの種類（`settings.LAYER_KINDS`）が増える。直すときは下書きの置き場（`wip/handoff/`）から `ccnavi-user-handoff.sh` で取り込む。取り込めるのは共通レイヤーの文面ファイルだけで、13.7 の検査を通らない下書きは断る。

### 13.3 形式

YAML。1 ファイルに `version: 1` と `messages:`（識別子 → 1 件）を書く。1 件の形は種類（`kind`）で決まる。

```yaml
version: 1
messages:
  DENY_TICKET_PARENT:
    kind: deny
    values: [ticket, title, worktree, path, worktree_path]
    what: 親チケット {ticket}（{title}）のワークツリー {worktree} に {path} を書こうとしたため、止めました。
    why: 親のワークツリーは作業の場ではありません。…
    next: …
    no_bypass: …
    note: |
      承認の前に…
```

種類ごとの欄を次に示す。

| 種類 | 使う場面 | 必須の欄 | 任意の欄 | 組み立てる出力 |
|---|---|---|---|---|
| `deny` | 拒否・確認 | `what` `why` `next` `no_bypass` | `note` | `what` / `なぜ: why` / `次: next` / `迂回しない: no_bypass` / `案内: note` |
| `nudge` | Stop の促し | `what` `next` | `why` `no_bypass` `note` | `what` / `なぜ: why` / `次: next` / `迂回しない: no_bypass` / `案内: note` |
| `next` | 出力の次の一手 | `next` | `note` | `次: next` / `案内: note` |
| `choices` | 次の一手が 1 つに決まらないとき | `items`（2 件以上） | | `次の手:` と `  1. …` の番号つき |
| `note` | 条件つきで足す 1 件の補足 | `note` | | `案内: note` |

- どの種類も `values` を持つ（空でもよい）。文面に書いた差し込みの名前の全部と一致する
- `what` `why` `next` `no_bypass` は 1 行。`note` は複数行でよく、1 行ごとに `案内: ` を付けて出す。`items` の 1 件は 1 行
- `next` の値は `次:` で始めない。出力に `次: ` を付けるのは組み立てる側で、出力の `次:` の行はちょうど 1 行になる
- 欄の値は、文字列か、`{名前: 文字列}` の表（場合分け。13.4）

### 13.4 識別子・差し込み・場合分け

識別子は大文字と数字と `_` で書く。`<コード>` か `<コード>__<区別>`（`__` の後ろは場合の名前）。

| 種類 | コード | 例 |
|---|---|---|
| `deny` | 記録の `code` と同じ（`DENY_*`・`RULE_ASK` など） | `DENY_TICKET_PARENT`、`DENY_PHASE_REVIEW__WAITING` |
| `nudge` | 記録の `code` と同じ（`NUDGE_*`） | `NUDGE_INTEGRATE__CONFIRM` |
| `next`・`choices`・`note` | `NEXT_*`・`CHOICES_*`・`NOTE_*`。出力元の名前を 2 語目に置く | `NEXT_START_DRY_RUN` |

同じコードで文が分かれる場合（ホストの種類、段、操作）だけ `__` で分ける。コードを分けない（判定の根拠の種類は 1 つ）。

差し込みは `{名前}`。`{root}` と `{script:<名前>}` と同じ流儀で、sh からも Python からも同じ形で書く。

| 書き方 | 意味 |
|---|---|
| `{名前}` | 渡された値をそのまま入れる。文の中の語。名前は `[a-z][a-z0-9_]*` |
| `{名前:sh}` | 要るときだけ引用して入れる（`settings.shell_word`）。打てる形の一部になる語（題・名前）はこちら |
| `{名前:path}` | パスを引用して入れる（`settings.shell_path`。区切りは `/` に揃える）。`cd <パス> && …` のように打てる形の一部になるパス |
| `{名前_q}` | 呼ぶ側が引用を済ませた値（引数の並び）を、そのまま入れる。名前の末尾が `_q` のものだけで、`:sh` と `:path` は付けられない |
| `{script:<sh の名前>}` | `settings.script_command`（`sh <パス>`）。ルートはワークスペースルート |
| `{{` `}}` | `{` `}` の字 |

- 値に含まれる制御文字・行と段落の区切り・全角空白は、空白にする。外から来る語（題・本文）が行を足して案内を偽装することはできない
- 値が足りない、または文面にない値を指定する呼び出しは失敗とする（13.6）
- 相対の `.ccnavi/scripts/` の呼び出しは書かず、`{script:…}` を使う（cwd が違うと届かない）
- 引数に `--set` は無い。`ccnavi text <識別子> 名前=値 … @欄=場合 …`。`@欄=場合` は場合分けの選択

場合分けは、欄の値を表にして書く。呼ぶ側は `@what=agent` のように選ぶ。選ばない、または表に無い場合を選ぶ呼び出しは失敗とする。

### 13.5 上書き

上書きの口は持たない。自身のレイヤー（`.ccnavi/config/project/messages/`）に文面ファイルが置かれていても読まず、`--lint` も何も言わない。文を替えるときは、共通レイヤーの文面ファイルを直す。条件（止めるか通すか）は、もとからコードとルールが決める。

### 13.6 読み出し口

Python からの呼び方を次に示す。

```python
texts.say(root, "DENY_PHASE_REVIEW__WAITING", {"parent": …, "phase": …}, {"why": "child"})
```

戻りは組み立てた文。失敗しても例外を投げず、既定の文（13.8）を返す。呼ぶ側の判定は変わらない。

sh からの呼び方を次に示す。

```sh
ccnavi_text <ワークスペースルート> <識別子> [名前=値]... [@欄=場合]...
```

標準出力に組み立てた文を出す。実行ファイルが無い・版が合わない・文を引けないときは、識別子の種類（`NEXT_*` `CHOICES_*` `NOTE_*`）に合わせた短い既定の文を出す。どちらでも終了コードは 0（呼ぶ側の `set -e` を起こさない）。呼ぶ側の止める・止めないは変わらない。

実行ファイルの仕様を次に示す。

| 項目 | 内容 |
|---|---|
| 入口 | `ccnavi text <識別子> [名前=値]... [@欄=場合]...` |
| 標準出力 | 組み立てた文。末尾に改行 |
| 終了コード | 0 成功。1 引けない（識別子が無い・値の不足・文面ファイルが壊れている）。標準出力は空、理由は標準エラー。2 引数の誤り |
| 呼ぶ回数 | 1 回の起動で 1 件。1 回の実行で出る文は多くて 3 件なので、まとめて引く形は持たない |

### 13.7 点検

`--lint` の `(messages)` の節と、`user handoff` の取り込み前の検査が、同じ点検を使う。

| 点検 | 重さ |
|---|---|
| ファイルが読めない、形が違う、`version` が違う | error |
| 同じ識別子が 2 回ある | error |
| 識別子の形、種類と識別子の頭の対応 | error |
| 種類ごとの必須の欄が欠けている、知らない欄がある | error |
| `values` と文面の差し込みの名前が一致しない、`_q` と `:sh` の使い分けが合わない | error |
| `次:` の行が 1 行でない | error |
| 長さの上限（1 欄 600 字、1 件の出力 2000 字）を超える | error |
| ADR 番号（`ADR-0001` の形）がある | error |
| 相対の `.ccnavi/scripts/` の呼び出しがある | error |

ccnavi のリポジトリのテストは、次も見る（呼ぶ側が手元のソースにあるときだけ確かめられるため）。

- コードと sh が引く識別子で、文面ファイルに無いものが無い
- 文面ファイルの識別子で、コードと sh のどこからも引かれないものが無い
- 呼ぶ側が渡す値の名前が、`values` と一致する

### 13.8 壊れたときの扱い

壊れた文面ファイルで防御が消えることはない。文面を引けなくても、判定は変えない。

| 状況 | 振る舞い |
|---|---|
| 文面ファイルが無い、読めない、識別子が無い | 種類ごとの既定の短い文（コード内）。止める判定は同じ。文は、文面ファイルが読めないことと、ユーザに `--lint` を頼む次の一手を伝える |
| 値が足りない、場合を選べない | 既定の文 |
| 実行ファイルが無い、版が合わない（sh） | sh の既定の文（種類ごと。`CHOICES_*` は `次の手:` と番号つきの 1 行、`NOTE_*` は `案内:`、それ以外は `次:` を 1 行）。判定は変えない |
| 配布先に文面ファイルが無い | 文面ファイルが無いのと同じ。`ccnavi-setup.sh` が共通の文面ファイルを `.ccnavi/config/common/messages/` へ配る |

既定の文は 1 つの関数（`texts.fallback`）が組む。種類ごとに数行で、個々の文を持たない（文が 2 か所に残らない）。

### 13.9 移行の範囲

この設計に沿って、次を文面ファイルに移した。残りは `docs/42_claude/message-migration.md` の一覧表が持つ。

- 拒否: `DENY_TICKET_PARENT`・`DENY_PHASE_REVIEW`・`DENY_NEEDS_USER_TURN`
- 促し: `NUDGE_INTEGRATE`
- `ccnavi-start.sh` の `次:` と `次の手:` の全部と、`ccnavi_pf_next`（事前確認の `次:`。`ccnavi-ticket.sh` も使う）の文

`rules.yml` のインラインの `message` は、そのまま残す。識別子で引く形（`message_id:`）は持たない。ルールの書式の版（`rules.VERSION`）、レイヤーの合成、`--lint`、`--explain` に手を入れることになり、ルールの `message` は移す対象に含めていないため。移す日が来たら、`message_id` の識別子は 13.4 の `deny` の識別子（`RULE_*`）とする。
