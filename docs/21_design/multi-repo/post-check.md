### 11.7 実行後チェック

流れは設計の「7. 実行後チェック」（post-check.md）と同じ。ここには、複数リポジトリで違う点だけを書く。

- 見るツリー: ワークスペースルートと、そのターンで書き込みのあったプロジェクトとワークツリー。触ったツリーはセッションの記録（`session/<id>.trees`）が持っている
- 基準（ターンの始まり）と「もう伝えた」の記録は、ツリーごとに分ける。差し戻しはそのツリーの git で行い、報告にはツリーの名前を頭に付ける
- 元リポジトリで見た変更に適用するルールは、共通レイヤー（ワークスペースルートの 1 本）と、そのツリーのレイヤーの和。ワークツリーなら、そのツリーに結び付くチケットの範囲と、共通レイヤーと元リポジトリのレイヤーの和
- ミラー（11.12）はツール呼び出しの中では書かれない。ユーザの発言のときにコピーした分は、次の受け入れで基準に入るので報告しない。ツール呼び出しの中でミラーが書き換わったときは、共通レイヤーと同じ中身でも報告する
