### 11.11 見ないもの、入れないもの

- VS Code 拡張の画面のレイヤーへの追従は、拡張の要件（`extensions/vscode/ccnavi-board/docs/requirements/`）が決める。
  ルール管理とリスク管理は、編集する 1 本（共通・ワークスペース・プロジェクト）を切り替え、統合結果の表示は実行ファイルの出力を使う。
  フェーズ管理は、共通レイヤー・ワークスペースの config・プロジェクトの config を開く（共通レイヤーの `phases.yml` は `--phases` で差し替える）。
  フェーズ定義は `--project-phases-file` で、共通レイヤーと足した形で検証してから保存する。
  テンプレート管理は、共通の設定・ワークスペースの設定・プロジェクトの設定の 3 種を「設定」の欄で切り替え、一覧（開いている対象の層）と統合結果の枠は実行ファイルの答えを使う。読むだけで、書かない。
  下書きの取り込みは「取り込み待ち」の画面が `user handoff --yes --expect --via board` を実行ファイルに打たせる（拡張はファイルを書かない。9.19）
- `CCNAVI_TICKET_CONTROL` のプロジェクト単位化。この変数はワークスペース単位のつまみで、手引きの語をその意味に直すだけ
- 統合先ブランチの git オブジェクトから設定を読む形。読むのは checkout されている版だけ
- `.ccnavi/scripts/` をコアファイルにする形（11.6）。中身のハッシュを突き合わせる形も入れない
- レイヤーが無いことを `--lint` が言う形。このため、レイヤーを消す・レイヤーが入る前のコミットへ `checkout` する、のどちらでも
  そのプロジェクトの deny が痕跡なく消える（「壊す」と error、「消す」と何も言わない、の非対称）
- プロジェクト A に居るときだけ適用される Bash のルール、`cwd` と `cd` の追跡、引数の語の走査
- ワークツリーの中に checkout された設定ファイルとスクリプト

受け入れる代償。

- プロジェクトは共通レイヤーの `ask` を `allow` に緩められない（`ask` は `allow` より先にヒットする）
- 共通レイヤーの `allow` が全プロジェクトに適用される
- パスを持つツールに他プロジェクトのルールは足さないので「A のルールを B にも」は書けない。要るなら共通レイヤーへ上げる
- ワークツリーで足した `.ccnavi/` の変更は、元リポジトリに入るまで使われない
- `glob` も `regex` もどの機械でも大文字小文字を区別せずに適用するので、`allow` も表記違いに広がる
- レイヤーの数だけ読み込みが増える。`ms` の欄で見る（11.10）
