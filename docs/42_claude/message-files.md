# 文面ファイルに文を足す・直す

エージェントとユーザが読む文は、コードや sh に書かず、文面ファイル（`.ccnavi/messages/*.yml`）に置く。
条件（いつ出すか）はコード・ルール・sh に残る。設計は[文面ファイルの設計](../21_design/messages.md)、一覧と移行の進み具合は[文面の移行の一覧](message-migration.md)にある。
止め方の選び方と拒否の文の型は[止め方の型と選び方](stop-patterns.md)、出力の `次:` の決まりは[スクリプトの出力に次の一手を書く](script-output.md)。

## 文を足す手順

1. 文面ファイルに 1 件足す。種類は識別子の頭で決まる（`DENY_*`・`RULE_*` は `deny`、`NUDGE_*` は `nudge`、`NEXT_*` は `next`、`CHOICES_*` は `choices`、`NOTE_*` は `note`）。拒否と促しの識別子は、記録の `code` と同じ。同じコードで文が分かれるときだけ `__<区別>` を足す
2. 種類ごとの欄を書く。文は `|-` のブロックで書くと、`{` や backtick を含んでも引用符で囲まずに済む

   | 種類 | 必須 | 任意 |
   |---|---|---|
   | `deny` | `what` `why` `next` `no_bypass` | `note` |
   | `nudge` | `what` `next` | `why` `no_bypass` `note` |
   | `next` | `next` | `note` |
   | `choices` | `items`（2 件以上） | |
   | `note` | `note` | |

3. 差し込む値の名前を `values` に全部書く。文面に書いた `{名前}` と過不足なく一致させる
4. 呼ぶ側に識別子と値を渡す。Python は `texts.say(root, "ID", {"名前": 値})`（値の辞書は直接書く。テストが名前を数えるため）。sh は `ccnavi_text "$root" ID "名前=値"`。出力の `次:` と `案内:` の見出しは文面ファイルの側が付けるので、コードや sh に書かない
5. `tests/core/test_texts_catalog.py` が、引く識別子が文面ファイルにあること、値の名前が一致すること、どこからも引かれない識別子が無いことを見る。通るまで直す
6. 移した出力は、文面ファイルを引いた結果に対して、`次:` の行が 1 行で値が埋まっていることを確かめる
7. [文面の移行の一覧](message-migration.md)の行を「移した」にする

## 書き方の決まり

- `what` `why` `next` `no_bypass` は 1 行。`next` は `次:` で始めない。`note` は複数行でよく、1 行ごとに `案内: ` を付けて出す
- 差し込みは `{名前}`（そのまま）、`{名前:sh}`（語の引用）、`{名前:path}`（パスの引用。`cd <パス> && …` の形に使う）、`{名前_q}`（呼ぶ側が引用を済ませた値。引数の並びだけ）、`{script:<sh の名前>}`（`sh <絶対パス>`）。字の `{` `}` は `{{` `}}`
- コマンドの一部になる値は、`:sh` か `:path` で引用する。sh から渡すときは引用せずにそのまま渡す。sh が引用を済ませた引数の並びは、名前を `_q` で終える
- 値の制御文字・行の区切り・全角空白は空白になる。外から来る語（タイトル・本文）が行を足して案内を偽装することはできない
- 相対の `.ccnavi/scripts/` の呼び出しは書かない（`{script:…}` を使う）。ADR 番号を書かない（[実行環境とADRの扱い](environment.md)）
- 1 欄 600 字、1 件の合計 2000 字まで
- 共有する部品の文（複数の出力が同じ定数を使い、テストもその定数を見ているもの）は、値として渡さず、いまは呼ぶ側のコードに残している。一覧の「残り」の行にある

## 引けないとき

`texts.say` は例外を投げない。文面ファイルが無い・壊れている・識別子や値が合わないときは、種類ごとの短い既定の文（`texts.fallback`）を返す。止める判定は呼ぶ側が決めたままで変わらない。`ccnavi_text` は同じ場面で sh の既定の文を出し、終了コードは 0（呼ぶ側の `set -e` を起こさない）。個々の文を既定として組み込みに残さない（直した文と食い違うため）。

## 上書きと保護

文だけを替える上書きの口は持たない。`.ccnavi/messages/` の外（`.ccnavi/config/project/messages/` や旧い置き場）に文面ファイルが置かれていても読まず、`--lint` も何も言わない。読まれるのは `.ccnavi/messages/` だけで、共通レイヤーのミラーにも入らない。

`.ccnavi/` の下は組み込みの保護が止めるので、エージェントは書けない。直す下書きは `wip/handoff/` に置き、ユーザが `ccnavi-user-handoff.sh` で取り込む（`.ccnavi/messages/<名前>.yml` の下書きだけが取り込める。取り込み前に検査（欄・差し込みの名前・`次:` の数・長さ・ADR 番号・相対の script）が走る）。文面ファイルは設定 3 本（コア）に加えていない。

## 配る

`scripts/ccnavi-setup.sh` が、配布元の `.ccnavi/messages/*.yml` を配布先の同じ場所へ配る。配布先に無いと、文は短い既定の文に落ちる。配布先に旧い置き場 `.ccnavi/config/common/messages/` が残っていても自動では消さず、不要と案内するだけ（古い実行ファイルが走っている間に消すと、文が既定の文に落ちる）。

## 使う側のテスト

使い捨てのワークスペースで文を見るテストは、同じプロセスで動く Python なら、文面ファイルが無い木でもこのリポジトリの文面ファイルの文を引く（`tests/__init__.py`）。別プロセスで起こす sh と実行ファイルを使うテストは、`tests.put_messages(root)` でコピーする。
