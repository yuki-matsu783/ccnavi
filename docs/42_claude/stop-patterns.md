# 止め方の型と選び方

エージェントを止める、またはユーザの返事を求める仕組みを足すときの決まり。どの型で止めるかを先に選び、拒否なら文面の型で書く。
成功側の出力に次の一手を書く決まりは[スクリプトの出力に次の一手を書く](script-output.md)にある。

## 型の表

| 型 | 何で止める | 向く場面 | 非対話（`claude -p`）での挙動 | 現在の例 |
|---|---|---|---|---|
| 拒否（deny） | ルールファイルの `deny` と、`hook/judge.py` の組み込みの関門 | 戻せない・代わりの経路がある | 止まる。文面がエージェントに返る | ルール `workspace-root`、組み込みの `DENY_TICKET_PARENT`・`DENY_PHASE_REVIEW`・`DENY_CHILD_PUSH` |
| 確認（ask） | ユーザの確認ダイアログ（ルールの `ask`） | ユーザが毎回見たい | 確認に答える人が居ないので、実質の拒否。理由文（`reasons.ask_hint`）がエージェントに返る | ルール `direct-worktree-confirm`、`RULE_ASK` |
| 確認コード | スクリプトが今の状態から出す `--accept <コード>` を付けて打ち直す | ユーザが状態の報告を見て了承し、その了承を、その状態に結び付けたい（状態が動くとコードが変わり、古い了承は通らない） | コードはルールの確認に出る行に付くので、確認と同じく実質の拒否 | `ccnavi-worktree.sh` の `--accept` |
| ユーザ専用の入口 | `ccnavi-user-*.sh`（ユーザの端末で打つ）。エージェントが打つ形は組み込みの関門が止める | 承認・取り下げなど、人の判断 | 止まる。対話・非対話で同じ | `ccnavi-user-agree.sh`（止める関門は `DENY_TICKET_APPROVAL_CLI`） |
| 発言をまたぐ関門（ターン分離） | 前の段のあとにユーザの発言が 1 回あること（`hook/turngate.py`） | 「見せて返事を待つ」を機械で確かめたい | 1 回の発言では通らない。対話・非対話で同じ | `integrate` → `integrate-done`（`DENY_NEEDS_USER_TURN`） |
| 促し（nudge） | `Stop` で 1 回だけ止めて文を渡す | 次の一手を忘れさせたくない | 同じ | `NUDGE_INTEGRATE`、`NUDGE_TICKET_FINISH` |
| 案内（context） | `additionalContext` / `additionalContextOnce` | 止めずに言う | 同じ | ルール `prefer-read-grep`、`prefer-webfetch` |

- 拒否は、`dry-run` では一般の `deny` が報告だけになり、関門と補助の保護は止める（`infra/modes.py` の分類）。発言をまたぐ関門は関門に入れる
- 促しは判断ではなく文を渡すだけ。促しで続けた同じターンは、ユーザの発言に数えない

## 選び方

1. AI の判断に任せてはならない、ユーザの返事が要る段は、対話・非対話の両方で意味を持つ型を先に検討する。**発言をまたぐ関門**と**ユーザ専用の入口**がそれにあたる。確認（ask）と確認コードは、非対話では実質の拒否になり、ユーザの返事を待つ形にならない
2. 戻せなくて代わりの経路があるなら、拒否にする。文面で代わりの経路を言う
3. ユーザが毎回見たい操作で、対話が前提の場面だけ、確認にする。非対話の理由文も書く（`ask_hint`）
4. 止めずに言えば足りるなら案内にする。止めないので、守られることは保証しない
5. ユーザの返事を待たせたいが、その場でユーザの端末に打たせるほどではないなら、発言をまたぐ関門にする。保証するのは「ターンが 1 回終わり、ユーザが 1 回発言した」ことだけ。ユーザが差分を読んだことは保証しない

## 確認（ask）は、あとのスクリプト側の拒否を隠さない

確認のあとに、スクリプトが状態を見て拒否することがある。確認の理由が「了承されたら打ち直してください」としか言わないと、エージェントは了承を頼み、打ち直し、同じ内容の拒否に着く。

- 確認の理由に、通らない条件を入れる。`ask_hint` のルールごとの 1 行（`_ASK_ALTERNATIVE`）に足す。条件は対象の語で絞れる（`--adopt` のときだけ、など）
- hook は git もネットワークも起こさない（[実行ファイルの境界](exe-boundary.md)）ので、スクリプトの拒否を hook で先に出さない。ルールの `except` と `when` は、ワークスペースルートと名前しか見えず、結び付きのような状態を知らない
- 例: `direct-worktree-confirm` の `--adopt` は、チケットに結び付く名前のワークツリーには、了承されても通らない。理由がそれを先に言う

## 拒否の文面の型

拒否の文は、それだけで読んで成立する。順に 4 つを書く。文は[文面ファイル](message-files.md)に置き、4 つの段は `deny` の欄（`what` `why` `next` `no_bypass`）になる。欄の欠け、`次:` の数、値の埋まり方は、文面ファイルの検査（`--lint` と `tests/core/test_texts_catalog.py`）が見る。

| 段 | 書くこと |
|---|---|
| 何が起きたか | エージェントが打ったことと、止めたこと。値（名前・キー・コマンド名）を埋める |
| なぜ | 止めた理由。守っているもの |
| 次の一手 | `次:` で始めて 1 行。そのまま打てる形に値を埋める（`script-output.md` の「決まり」と同じ）。ユーザに頼む操作は「ユーザに〜を頼んで返事を待つ」と書く |
| 迂回しない | 言い換えや別の経路でも同じ関門に当たることと、待つこと |

- 拒否コード（`DENY_*`）は、判定の根拠の種類を指す。1 つの種類に複数の宣言があるときは、コードを分けず、記録の `rules`（`builtin:` で始まる名前）と文面に、宣言の id を出す。コードを足したら、設計書の付録の理由コードの表と組み込みの名前の表に行を足す
- 組み込みの拒否は `reasons.builtin_refusal(code, rule_id, subject, text)` で組む。先頭の行に、コードと記録の `rules` と同じ名前が並ぶ。`text` は `texts.say` が文面ファイルから組む（移した拒否。まだ移していないものは[文面の移行の一覧](message-migration.md)にある）
- 文言に ADR 番号を書かない（[実行環境とADRの扱い](environment.md)）
- 経緯は書かない。いまの理由だけ書く
- 点検項目:
  - 4 つの段が順に揃い、`次:` が 1 行で、値が埋まっている
  - **拒否同士が行き止まりを作らない。** 次の一手が指す先が、別の拒否に着かない。着く先の拒否が、元の拒否と同じ判定（結び付くか、など）を使っているなら、元の側が先に同じ判定で案内を変える。判定は共用し、二重に実装しない
  - 確認（ask）が、あとの拒否を隠さない（上の節）
  - 記録が読めない・書けないときは、閉じる側に倒しても、文面が次の一手を言う
  - `dry-run` で止めるかを、分類（`GENERAL`・`GATE`・`AUX`）で決めた

行き止まりの例（直した）: `ccnavi-git.sh integrate` が「直接作業の記録がありません」と言って `--adopt` を案内し、その `--adopt` が「チケットに結び付くワークツリーです」と断った。チケットに結び付く名前のとき、`integrate` は `--adopt` を言わず、マージリクエストで出すと言う。結び付くかの判定は `--adopt` と共通（`ccnavi_tree_bound`）。

## ターン分離の関門

「A を打ったら、ユーザの発言が 1 回はさまるまで B を打てない」を止める汎用の部品（`hook/turngate.py`）。宣言（`Gate`）の表を渡して判定するので、別の組を止めるには宣言を足す。止めるのは B の側だけで、A と B が同じターンに起きたことを、あとから点検する処理は作らない。

### 宣言の書き方

| 欄 | 意味 |
|---|---|
| `id` | 宣言の識別子。記録の `rules`（`builtin:turn-gate:<id>`）と文面に出る |
| `first` / `second` | A と B の条件（`Cond`）。`regex` か `glob` のどちらか 1 つ。読み方はルールと同じ（大文字小文字を区別しない、先読みと後方参照は使えない）。コマンドを `;` や `&&` で分けた 1 つずつに適用し、実行役が中で実行するコマンドも含む |
| `but` | 同じコマンドにこの regex があれば、その条件にヒットしない |
| キー | `regex` の名前つきグループ `key`。A と B の両方に書くと、同じキーの組だけを対象にする。書かなければ宣言ごとに 1 組 |
| `first_name` / `second_name` | 文面で A と B を呼ぶ名前 |
| `message` | 文面ファイルの識別子（`DENY_NEEDS_USER_TURN__<宣言>`）。「なぜ」と「次の一手」と、`what` の場合分け（`same_command`・`no_user_turn`）をそこに書く。`{key}` と `{script:<sh の名前>}` を埋める |
| `key_name` | キーが解けなかったときに `{key}` に入れる仮の値 |

記録を読み書きできない場合の文は、宣言によらず `DENY_NEEDS_USER_TURN__STATE`。

別の組を足す手順:

1. `turngate.py` の `BUILTIN` に宣言を 1 件足す。キーの regex は、引数の並びの揺れ（`-m <メッセージ>` を名前の前後どちらにも置ける、など）を実際のスクリプトの引数の読み方に合わせて書く
2. `tests/core/test_turngate.py` に、宣言の表を直接渡す単体のテストを足す。`integrate` と関係の無い架空の組が先例にある
3. hook の入口のテスト（`tests/guard/test_turngate_hook.py`）に、実際の呼び出しの順で止まることと、発言を 1 回はさむと通ることを足す
4. 文面ファイルに `DENY_NEEDS_USER_TURN__<宣言>` を足し、宣言の `message` に指す。上の文面の型に沿わせる。設計書の付録の組み込みの名前の表に宣言の id を足す
5. 手順書・出力・促しが、A のあとの一手を「ユーザの発言のあと」と言うように揃える

宣言は組み込みの表に置く。ユーザの了承の関門を、配布先のルールファイルで外されないようにするため。`rules.yml` に `turn-gates:` の節を足して、ルールファイルから宣言を足せるようにする道は、いまは持たない。最初の利用が 1 件で、2 件目の具体的な需要がなく、書式の版（`rules.VERSION`）と、レイヤーの合成・lint・`--explain` に手が入るため。足す日が来たら、宣言の欄がそのままノードの欄になる。足すだけで、組み込みの宣言を外す・弱めることはできない形にする。

### ユーザの発言の数え方

ユーザの発言の時刻は、`state/userprompt-<セッション>.json` に、`hookio.is_user_prompt` が真の `UserPromptSubmit` だけが書く。ターンの印（`records/turn.py`）は `Stop` で消えるので使えない。迷うものは数えない。

| 形 | 数えるか | 根拠 |
|---|---|---|
| ユーザが打った文 | 数える | |
| バックグラウンド作業の完了通知（`prompt` のどこかに `<task-notification>`） | 数えない | 実機で確かめた。ユーザが何も打たなくても `UserPromptSubmit` を起こす |
| ccnavi が放置したセッションを起こす指示（先頭が `[idle-handoff]`） | 数えない | ccnavi 自身が起こす |
| 外の出来事がセッションを起こす封筒（先頭が `<wake`・`<webhook-payload`・`<child-session-event`・`<event `） | 数えない | 実行環境の案内が示す形。`hook` の payload では確かめていない |
| システムの通知（先頭が `[SYSTEM NOTIFICATION`・`<system-reminder`） | 数えない | 同上 |
| 空の発言、サブエージェントの中、`UserPromptSubmit` 以外のイベント | 数えない | |
| 予約した実行（`session_crons`・`ScheduleWakeup`・`send_later`）の `prompt` | 数える側に残る。見分けられない | 保存した文そのままで来る。payload にユーザの発言と言い切れる欄（来歴）が無い |

- `from_background_task`（ターンの印と、ユーザの手による変更の受け入れに使う）は変えない。`is_user_prompt` は関門だけが使う
- `Stop` の促しで続けたターンは、新しい `UserPromptSubmit` を起こさないので、数えない
- 動かしている作業が残っていること（`busy`）は、発言を数えない理由にしない。ユーザの手による変更かを決める材料であって、発言かどうかではない。数えないと、予約が残る限り、ユーザの返事でも関門が開かなくなる
- `<task-notification>` を含む判定は、先頭に限らない。ユーザがその文字列を自分で打っても関門は開かない。開かないのは安全側で、普通に打ち直せば通る

### 状態と、壊れた記録

- A を許したとき（`PreToolUse`）、宣言 id・キー・時刻・呼び出しの識別子を 1 件 1 ファイルで残す（`turngate-<セッション>-….json`）。実行後（`PostToolUse`）でなく実行前に残すのは、同じメッセージで A と B を並べた呼び出しが、A の記録の前に B を通らないようにするため。拒否された A と、失敗した A（`PostToolUseFailure`）は、その呼び出しの記録を消す。失敗した A は数えない
- B は、同じ宣言・同じキーの記録があり、その時刻より後のユーザの発言が無ければ止める。同じコマンドの中に A と B が両方ある形も止める。B が通ったとき、起動と再開（`SessionStart`）で記録を消す。compact と clear では消さない
- 閉じる側（B を止める）に倒す。ユーザの発言の記録が無い・読めない、関門の記録のファイルが読めない、置き場を読めない、A の記録を書けない。壊れた記録が防御を消さないため。文面が次の一手を言う。ユーザの発言の記録は次の発言が書き直すので、詰まらない
- 名前を引数に取る A と B のキーが、変数や置換で解けない形（`$name`）は、どのキーとも一致する扱い
