# ccnavi の作業の決まり

セッションの開始（起動・再開・compact・clear）のたびに ccnavi が渡す。サブエージェントには渡さない。
決まりは危険な作業や失敗を検知した時に案内する。案内が出たらそれに従い、迂回しない。

## 考え方

- メインのコンテキストを清潔に保つ。実装・調査・テストはサブエージェントにバックグラウンドで任せ、メインはユーザとの相談・判断・報告を受け持つ。
- 判断するのはユーザで、エージェントは材料を出す。判定が緩む・やり取りの形が変わる・元に戻せない・影響範囲を読み切れない変更は、実装する前にユーザと合意する。
- 合意した手順の中では、判断に要る問題がなければ次のユーザ確認地点まで進める（「次へ進めてよいか」では止まらない）。実装前の合意・承認待ち・レビュー待ち・取り込み待ちは越えない。停止・相談の指示や拒否があれば止まり、理由を報告する。流れは `direct-flow.md`・`ticket-flow.md`。
- 並行して動く他セッションと影響し合わない。自分のワークツリーの外にある未コミットの変更は他セッションのもの。コミット・ブランチの移動・reset をしない。
<!-- ccnavi:if non_interactive -->
- このセッションは非対話。ユーザとやり取りできず、メインが終わったあと、バックグラウンドのサブエージェントは環境の設定によっては作業の途中で消える。上の「バックグラウンドで任せ」より優先し、サブエージェントはバックグラウンドにせずフォアグラウンドで起動して、完了を待つ。
<!-- ccnavi:endif -->

## 作業の決まり

<!-- ccnavi:if workspace_root -->
  - 編集する前に {{worktree_sh}} <名前> でワークツリー（{{worktrees}}/<名前>）を切り、その中で編集する。直接作業の名前は <先頭の語>-<番号>-<slug>（.ccnavi/docs/worktree.md）。
  - ワークツリーを切るスクリプトが「確認が要る」と言ったら、報告をユーザに伝え、了承を得るまで `--base`・`--accept`・`--side-by-side` を付けない。
  - 取り込み先のブランチを切り替えない。integrate-doneの前に、変わるファイルをユーザに伝え、未保存の編集は保存してもらう。
<!-- ccnavi:endif -->
<!-- ccnavi:if git_wrapper -->
  - git は直接呼ばず {{git_sh}} を通す。止められたら迂回せず、出力の案内に従う。
<!-- ccnavi:else -->
  - git は直接呼ばない。止められたら迂回せず、出力の案内に従う。git の操作が要るときはユーザに頼む。
<!-- ccnavi:endif -->
- ホスト（issue・MR など）の操作は glab を基本にし、gh は origin が GitHub のときだけ使う。ccnavi のスクリプトがある操作はそちらを優先する。認証で止まったら、ユーザに glab auth login（GitHub なら gh auth login）を頼む。
- 下書きの置き場は 2 つ。ユーザに渡す物は {{handoff}}/（追跡される。integrate が外し、ready が消す）、一時的な物・コミットしたくない物はワークスペースルート直下の {{scratch}}/（追跡されない。終わったら自分で消す）。セッションのスクラッチパッドには置かない。
- 書き込みを止められている場所（保護対象など）は、{{stage_sh}} <元のパス> で {{handoff}}/ にコピーして編集する。複数あるときはすべてコピーしてからターンを終える。対話セッションでは、ユーザに `ccnavi-user-handoff.sh` での取り込みを案内してターンを終える。非対話セッションでは、編集済みの下書きを push し、確認と取り込みをユーザに頼んでターンを終える。
<!-- ccnavi:if projects -->
  - {{projects}}/<名前>/ を直すときは、そこへ cd してから作業する（git は cwd のリポジトリに向く）。
<!-- ccnavi:endif -->
<!-- ccnavi:if tickets -->
  - 承認済みチケットの状態は、ファイルを読んで推測せず {{ticket_sh}} status [<親>] で確かめる。
<!-- ccnavi:endif -->
- サブエージェントに子の作業を任せるときは、プロンプトに担当の子の識別子を 1 つだけ書く（他の子やパスは書かず、isolation は使わない）。範囲とフローの案内は ccnavi が書き足す。
<!-- ccnavi:if docs -->
  - 詳しい決まりは案内の --docs で、--keyword <語> を付けて引く。
<!-- ccnavi:endif -->

## 詳細

詳しい決まりは `.ccnavi/docs/` にある。作業が表の「読むとき」に該当したら開く。

| 読むとき | 開くファイル（`.ccnavi/docs/` の中） |
|---|---|
| ワークツリーを切る、他セッションの影響を受けた、親の正本・ワークツリーが無い、`mr:` を確かめる、issue・MR を指定して頼まれた | `worktree.md`、`worktree-start.md` |
| `<統合先>` に取り込む、子の finish で親へ合流する・衝突を解く、MR に出す、ワークツリーや子のブランチを片付ける | `worktree-merge.md`、`worktree-cleanup.md` |
| 下書き・使い捨てのファイルを置く | `scratchpad.md` |
| `projects/` 配下を直す、チケット・マーカー・記録の置き場を確かめる、`rules.yml` の `message` を書く | `projects.md` |
| 提案を書く、承認・レビュー済みをユーザに頼む、相談が要るか迷う、ccnavi に止められた、サブエージェントに任せる | `decisions.md` |
| 親の提案を始める、完了した親の計画とフローを使い回す、閉じるときにテンプレートの案内が出た | `templates.md` |
| 用語（ワークスペースルート・統合先ブランチなど）を引く、`.ccnavi/CCNAVI.md` の条件・差し込みを書く、md に frontmatter を付ける・直す、索引で引く | `terms.md`、`ccnavi-md.md`、`frontmatter.md` |
| フィードバックが届いた、`.claude/skills/` を直す、スキルを新しく作る、スキルの振り返りで知識を溜める・読む、工程スキル（process-*）の reference を引く・足す | `skill-review.md`、`skill-wiki.md`、`skill-processes.md` |
| ルール・フェーズ・リスク・計画テンプレート・工程スキルが育つ流れを確かめる | `grow.md` |

<!-- ccnavi:if tickets -->
  ## 作業の進め方

  このワークスペースはチケット制御を使っている。調査・小さな修正は直接作業。設計に触れる・複数のフェーズに分かれる・ユーザのレビューが要るものはチケット作業で、{{tickets_dir}}/todo/ に提案を書き {{ticket_sh}} propose で送る。迷ったらユーザに聞く。チケット作業は issue と MR のセットで（issue が無ければ ccnavi-start.sh --new-issue <題> で作る）、入口で ccnavi-start.sh --check を打つ。issue・MR 指定の実装は必ずこれ。詰まったら直接実装せず、報告して止まる。
  親のワークツリーには書かず、子のワークツリーで作業する。自分が準備・依頼したレビューの待ち中に別の依頼が来たら、別のセッションで受けるようユーザに伝える。他の会話の親は対象外。詳細は `.ccnavi/docs/ticket-work.md`。
  <!-- ccnavi:if non_interactive -->
  （このセッションは非対話。終わるとコンテナごと手元の子の作業が消える。子が詰まったり、ユーザの確認が要ったりしたら、報告して止まる前に、メインが子を `cancel` するか、`finish` して続きの子を `propose` で送るかを決め、リモートへ反映する。ユーザの停止・待機の指示や、ガードの拒否、範囲・計画の改版が要るときは、これらで迂回せず、報告して止まる）
  <!-- ccnavi:endif -->
