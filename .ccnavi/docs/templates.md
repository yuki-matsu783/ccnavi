# 作業・レビュー計画のテンプレート

テンプレートは、1 つの親の作業・レビュー計画（`plan:` と `feedback:` のステップ、ステップどうしの先行 `after`）と、子のフローの本文を 1 ファイルにまとめたもの。完了した作業の形を、次の作業で使い回すために溜める。

## 置き場

| 置き場 | 中身 | 書けるのは |
|---|---|---|
| `.ccnavi/config/common/templates/<名前>.yml` | 共通。配布先にも届く | ユーザ（取り込み） |
| `.ccnavi/config/project/templates/<名前>.yml` | そのプロジェクトだけ | ユーザ（取り込み） |
| `wip/handoff/` の下の同じ相対パス | 下書き。効力は無い | エージェント |

エージェントは `.ccnavi/` の下に書けない。溜めるときは `wip/handoff/` に下書きを書き、ユーザが `ccnavi-user-handoff.sh` で取り込む。フローの文は子への案内文になるので、ユーザが差分を読んでから効かせる。

共通とプロジェクトに同名があり、中身が違うときは error になり、プロジェクト側は使われない。

共通のテンプレートは、導入 sh（`ccnavi-setup.sh`）が配布先へ配り、着手済みの親があるときのユーザの発言が、プロジェクトの `.ccnavi/config/common/` へコピーする（error のあるテンプレートはコピーせずに飛ばし、置き場が読めないときはテンプレートだけコピーしない）。導入 sh は配布元の `.ccnavi/config/common/templates/*.yml` を配布先の同じ場所へコピーする。名前に使えない文字（空白など）を含むテンプレートは配られない。

## 見つける

- `ccnavi --templates` で一覧を見る。`--keyword <語>` で名前・説明・使う場面を検索し、`--show <名前>` で中身を見る
- `ccnavi --templates --json` が機械向けの答え。`ccnavi --lint` もテンプレートを検査する
- `ccnavi --templates --check-file <パス> [--layer <名前>] --json` は、任意のパスのテンプレートを置き場に入れずに検査する（読むだけ。画面の保存前の確かめに使う）
- `--layer <名前>` で、統合結果の相手のレイヤー（プロジェクト名）を選ぶ。省けば自身のレイヤー
- `ccnavi --docs` の索引には載らない。yml なので `--templates` で探す

## 溜める

エージェントが溜める手順は、ほかの保護対象と同じ handoff に一本化している（[scratchpad.md](scratchpad.md)）。ユーザが取り込み済みのテンプレートを直すときは、下の「画面で直す」でもできる。

1. 計画を持つ親が閉じるときに、ccnavi が案内を 1 行出す。`ready` の前に `ccnavi --templates --draft <親>` で下書きを作る。`ready` を打つと下書きの材料が退避されて拾えなくなる
2. 下書きは `wip/handoff/` の下の、取り込み先と同じ相対パス（既定は `wip/handoff/.ccnavi/config/project/templates/<名前>.yml`）に書かれる。`description` と `when` に `TODO` の印が付くので、固有名を一般化し、効かなかった手順を削り、印を消す。直すのはエージェントでよい（Write で直接編集する）
3. ユーザが `ccnavi-user-handoff.sh [<相対パス>…]` で見る。何も書かず、検査と差分（既存があれば文の前後まで）と `--expect` のハッシュを見せる。読んだうえで、`--yes --expect <ハッシュ>` を付けて取り込む
4. 取り込んだ下書きは消える

`--draft` の主なオプションは次のとおりです。

- `--name <名前>`: 下書きの名前。既定は親の識別子。日本語など名前に使えない識別子の親では、`--name` で英数字の名前を付ける（英数字で始め、英数字と `.` `_` `-` だけ）
- `--to common|project`: 取り込み先。`common` は共通（他のプロジェクトへ配られる。ワークスペースルートのツリーでだけ書ける）、`project` はプロジェクトの層。既定は `project`
- `--layer <名前>`: `--to project` のときに、取り込み先のプロジェクトのレイヤーを選ぶ（省けば自身のレイヤー）。`--templates` の一覧・`--show` でも、統合結果の相手のレイヤーを選ぶ

取り込み先に同名のテンプレートが既にあるときは、`--draft` は断る。同名の下書きがあるときも上書きしない。既存のテンプレートを直すときは、`ccnavi-stage.sh <パス>` で既存のファイルを `wip/handoff/` にコピーして編集する。

下書きの検査は、`description` と `when` の `TODO` の印の残りを warn で言う。制御文字・書式文字（右から左への上書き、幅ゼロの文字、復帰など）を含む下書きは error で、取り込めない。取り込みの下見は、そうした文字を `\uXXXX` に直して見せる。

**未取り込みの下書きは `ready` を止める。** 取り込み先と中身が違う下書きが `wip/handoff/` に残っていると、親の `ready` が止まる。`--draft` を打ったら、取り込むか、`ready` の前に下書きを消す。

`ccnavi-user-handoff.sh` はユーザ専用で、見るだけの形もエージェントは打てない。`--yes` で書くのは、ターミナルの前のユーザ。エージェントの下書きの手直しは、`wip/handoff/` への Write でよい。

**改名・移動・削除。** 取り込み済みのテンプレートの改名・移動・削除は、実行ファイルでできない。ユーザがファイルを直接操作する。

## 画面で直す

ユーザは VS Code 拡張（ccnavi ボード）の「テンプレート管理」で、置き場のテンプレートを直せる。行は最初から開いて、計画とフローの図が出る。行の「図を編集」を押すと、説明と使う場面、全体計画とフィードバック計画のステップと先行の線、ステップごとの子のフローを直して保存できる。ステップと線は図で、子のフローはフロー編集と同じ図で直す。「作る」で新しいテンプレートも作れる。保存するのはユーザの操作で、エージェントは使えない（エージェントは `wip/handoff/` の下書きだけ）。保存は次の3つをすべて満たしたときだけ書く。実行ファイルの検査（`--templates --check-file`）に error が無いこと、開いたあとにファイルが外で変わっていないこと、作業中のチケットが無いこと。改名・移動・削除は画面に無く、ファイルを直接操作する。

下書きの取り込みは「取り込み待ち」の画面でもできる。`wip/handoff/` の下書きのうち、テンプレート・設定（`rules.yml` など）・文書の種類を一覧にし、差分を読んでから取り込む。防御のファイル（`.ccnavi/scripts/`・hook・`settings.json`）は一覧に出るが、ボードからは取り込めず、ターミナルで打つコマンドを案内する。作業中のチケットがあると、テンプレートと設定の取り込みは止まる（共通とワークスペースの設定は、どのツリーの作業中でも止まる）。`CCNAVI_TICKET_CONTROL` が `disable` なら入口ごと出ない。

## 使う

`ccnavi ticket new <識別子> --title <題> --template <名前> [--layer <名前>] [--with-feedback] --issue <値> --mr <番号>` で、親の提案（`wip/proposals/todo/`）と、子のフローの下書き（`wip/proposals/flows/`）を作る。親のブランチへ送るのは `ccnavi-ticket.sh propose <識別子>`（承認を頼む前に打つ）。

- 提案に書くのは全体計画 `plan:` だけ。テンプレートにフィードバック計画があっても、`--with-feedback` を付けないかぎり `feedback:` は書かない。フィードバック計画は全体計画の最後のレビューを見てから、改版で 1 回だけ足す決まりで、最初の提案に入れると、承認後に全体計画を改版できなくなる。書かなかったときは、出力がフィードバック計画のステップ数を言う。全体計画のレビューを見てから足すなら、`--with-feedback` を付けて作り直すか、提案を改版で足す。`--with-feedback` は `ticket new --template` でだけ使える
- 提案の `plan:` / `feedback:` の `after` は、提案の番号に付け直される（フィードバック計画は全体計画の続きの番号）
- 提案は通常どおり承認を通る。循環・終端が 1 つ・種類の `kind` の検査は変わらない
- フローの下書きに効力は無い。ユーザがフロー編集画面で読んで取り込むまで、サブエージェントには渡らない
- 子の識別子は、各フェーズの最初の子 `<親>-<フェーズ番号>-01` と仮定している。別の連番で子を起こすときは、下書きの名前を合わせる
- `phases.yml` に無い種類を使うテンプレートは、提案を書かずに断る
- 使えるテンプレート（`usable`）が 1 本以上あるプロジェクトでは、`ccnavi-start.sh` は提案を作る `次:` の案内の末尾に、「`--plan` の代わりに `--template <名前>` を使う」と書いた `案内:` を 1 行出す。0 本のときや、一覧を読めないときは出さない

## 古くなったテンプレート

種類の定義が変わると、テンプレートが定義と食い違う。`--lint` は warn にとどめ、使うときの承認で error になる。直すときは、`ccnavi-stage.sh` で既存のファイルを `wip/handoff/` にコピーして編集し、ユーザが `ccnavi-user-handoff.sh` で取り込む。
