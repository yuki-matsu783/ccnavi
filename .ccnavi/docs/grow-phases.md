# フェーズが育つ流れ

フェーズ定義は「作業の型」（種類、レビューが要るか、範囲の上限、成果物）で、親が `plan:` に並べて使う。
計画に使いたい型が無い、または範囲やレビューの置き方が合わないときに足す・直す。

共通の 6 段は[grow.md](grow.md)。この対象に固有の中身は次のとおり。

| 段階 | フェーズ定義での中身 | 使うもの |
|---|---|---|
| きっかけ | 計画を書こうとして使える定義が無い、`scope` が実際の置き場に合わない、レビューの要否を変えたい | 計画の提案、`ccnavi --lint` |
| 下書き | 定義を 1 つ足す・直す。`kind` `title` `review` `scope` `deliverables` を決める。順序は定義でなく親の計画のステップの `after` で書く | `/ccnavi-config` |
| 検証 | `id` と `title` の重複、`scope` が親の外に出ないか、件数の上限（重複は error）。`--phases` で下書きを差し替える | `ccnavi --lint --phases <下書き>` |
| 効く | 親の提案を承認するとき、計画が使う定義だけを親の `phases:` にコピーして固定する。承認のあとの判定はコピーを読む | `ccnavi --plan-order <親> --fill-phases` |

## 規則

- 定義を直しても、進行中の親には届かない。承認したときの定義を親に固定するため（途中で緩むのを防ぐ）。直したいときは親の計画を改版する
- 足すのは共通レイヤーと、親の `project:` が指す 1 レイヤーの 2 本だけ。どのプロジェクトでも同じ構成を前提にできる定義は共通、`scope` がレイアウトに依存する定義はレイヤーに置く
- `scope` を超えても承認は止まらず、承認画面に警告として出る。判定は子の範囲を上限でも切り詰める
- 計画の無い親は着手できない。定義が 1 つも無ければ計画は承認できない
