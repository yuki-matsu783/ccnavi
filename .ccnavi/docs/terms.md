# ccnaviの呼び名

- ワークスペースルート: Claude Codeを起動したディレクトリ（`CLAUDE_PROJECT_DIR`）。プロジェクトの作業もワークスペースルートで起動して`cd`で入る。プロジェクトの中で起動すると、ワークスペースの`.claude/settings.json`が読まれず、ワークスペースのccnaviのhookは動かない（プロジェクトが自前の`.claude/`を持っていれば、その`.claude/`のhookとスキルが使われる）
- gitプロジェクトルート: `.git`があるディレクトリ。ワークスペース自身、`projects/`の下の各プロジェクト、
  各ワークツリーがそれぞれ持つ
- 統合先ブランチ: 作業を合流させるブランチ。各リポジトリの`origin/HEAD`が指すブランチで、pushの拒否・MRの宛先・チケットの起点を決める
- ユーザのチェックアウト: そのリポジトリの`git worktree list`の先頭（gitのmain working tree）。ワークスペースルートか`projects/<名前>`。ユーザが開いているブランチのチェックアウトである。エージェントはこれを直接書き換えず、`.claude/worktrees/<名前>`のワークツリーで作業する。ブランチ名の`main`とは関係ない
- 取り込み先: 直接作業のワークツリーを切った時点で、ユーザのチェックアウトが開いていたブランチ。直接作業はここから切り、ここへ1コミットで戻す。統合先と同じとは限らない
- 起点（S）: 直接作業のワークツリーの切り元のコミット。取り込み先のHEAD、または`--copy-wip`でコピーした書きかけのスナップショット
- 書きかけ: ユーザのチェックアウトの未コミットの変更（追跡済みの変更と新規ファイル。ccnavi が作るワークツリーの置き場 `.claude/worktrees/` は数えない）。`--copy-wip`は確認した時点のものを起点にコピーし、`--no-wip`はコピーしない
- 確認コード: `ccnavi-worktree.sh`が、リモートとのずれや書きかけの状態から作る8桁。`--accept`に渡すと、その状態をユーザが了承したことになる。状態が動くと合わなくなり、報告からやり直す
- 横で作業する: `--side-by-side`の指定。ワークツリーが残っている間は、ユーザのチェックアウトの変更を自動復元で戻さず、「出所不明の変更」として報告する。ccnaviの設定ファイルは戻す
- 一時ワークツリー: `integrate`が取り込み結果を展開する使い捨てのワークツリー（`logs/direct-tmp/<repo>/<名前>`）。取り込み結果の検証と、取り込みコミット（K）の作成に使う。ここは編集しない
- 作業・レビュー計画: 親の提案の `plan:`（全体計画）と `feedback:`（フィードバック計画）をまとめた呼び名。ステップは種類・先行（`after`）・ユーザがレビューする位置（`review`）を持つ。
  - 短くは「計画」と書く。ただし文脈で `plan:` だけを指すことがある
  - ステップどうしの先行を引き直す画面は「計画編集」
- フロー: 子チケットを担当するエージェントに渡す作業手順の本文。計画（`plan:`）の各ステップごとに置く（使わない言い方: ワークフロー）
- 先行関係: 計画のステップどうしの順序で、ステップの `after` で決まる。チケット間の先行（`predecessors`）とは別
- ユーザ待ち: 次に動くのがユーザである状態（使わない言い方: あなたの番）
- 有効／無効: テンプレートや定義の状態の札（使わない言い方: 使える／使えない）
- ヒットする: ルールや glob が対象に一致すること（使わない言い方: ヒットする）
- 出力の行頭の語: ccnaviのスクリプトの出力で、行頭に付く語の意味。
  - `次:` は次の一手。そのまま打てるコマンドか、次にやる行為（ユーザに頼む、サブエージェントに任せる）。書いてあるとおりに進める。自分で手順を補わない
  - `必須:` は書き漏らすと承認や検査が止まる項目
  - `案内:` は補足と注意
  - `次の手:` は、次の一手が1つに決まらないときの番号つきの選択肢。決めるのはユーザのことがある
  - 詰まって進められないときは、直接実装などの別の道に切り替えず、ユーザに報告して止まる
