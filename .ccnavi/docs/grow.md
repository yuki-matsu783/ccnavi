# 設定と工程スキルが育つ流れ

作業中に見つけた直しは、対象によらず次の 6 段で進める。1 回で完成させず、止まった・通ってしまった・重さが合わなかった事実を材料に足していく。

```
きっかけ → 下書き → 検証 → 承認（ユーザが置く） → 効く → 配る
```

| 段階 | 共通の中身 | 誰が |
|---|---|---|
| きっかけ | 実際の振る舞いと意図のずれに気づく | ユーザ。記録からは ccnavi が候補を出す |
| 下書き | 本物の全文をコピーして直す。置き場は `wip/handoff/`（`ccnavi-stage.sh` でコピーする）。ルール・フェーズ・配点は `/ccnavi-config` | エージェント |
| 検証 | 読めるか・ヒットするかを機械に聞く。目で判定を真似しない | エージェント |
| 承認 | 何をなぜ変えるかと一緒に渡し、ユーザが差分を読んで `ccnavi-user-handoff.sh` で置く。設定ファイルは保護対象で、エージェントは直接書けない | ユーザ |
| 効く | 置いたあとの判定・作業から効く。進行中の親や子には届かないものがある（対象ごとの文書） | ccnavi |
| 配る | ccnavi の導入のときに共通の設定を配布先へ配る。配布先では、共通レイヤーは、着手済みの親があるとき、ユーザの発言のたびに、そのワークツリーのプロジェクトの `.ccnavi/config/common/` へミラーされる。ミラーは誰も編集しないコピーで、プロジェクト固有のものは `.ccnavi/config/project/` に置く。ずれたときの同期は、ユーザが `ccnavi-user-mirror.sh` で行う（工程スキルの `skills/` も同じ入口） | ccnavi |

テンプレートと工程スキルの reference は、承認と効く段の主体が上の表と違う（それぞれの文書に書く）。

## 対象ごとの文書

各文書は、その対象だけの「きっかけ・検証・効き方」と規則を書く。6 段の共通部分はここが正で、各文書には書かない。
