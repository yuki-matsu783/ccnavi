# 作業の進め方（直接作業とチケット作業）

チケット制御を使っているワークスペースでは、進め方は 2 つある。

- 直接作業（調査・小さな修正）: チケットを起こさずそのまま進める。判定は全体ルールだけ。
- チケット作業（設計に触れる・複数のフェーズに分かれる・ユーザのレビューが要る）: `wip/proposals/todo/` に提案を書き、`ccnavi-ticket.sh propose <識別子>` で親のブランチへ送って承認を受ける。承認されると提案は `.ccnavi/approved/doing/` へ動く。以後の操作は `ccnavi-ticket.sh` を通す（使い方は `--help`）。

どちらで進めるか迷ったら、ユーザに聞く。ただし issue・MR を指定された実装は、直接作業にせずチケット作業で進める（ホストで作られたものを途中から頼まれた場合も同じ）。詰まったら直接実装に切り替えず、ユーザに報告して止まる。

## 正本と親のワークツリー

作業中の正本は親のブランチを checkout した親のワークツリー（名前はブランチ名の `/` を `-` にしたもの）。親のワークツリーには書かず、子のワークツリーで作業する。ワークツリーが無い・HEAD が違う PC では操作が止まるので、案内の `ccnavi-start.sh` で準備する。親の提案には `mr:` を必ず書く。詳細は [worktree.md](worktree.md)。

## レビュー準備中・レビュー待ちの間

別の親・別の目的の新しい依頼をこのセッションで受けず、ワークスペースルートで起動した別のセッションで受けるようユーザに伝える。同じ親のレビュー対応・相談・止める指示・取り消し・次のフェーズの計画・動いている子の完了処理は続けてよい（案内だけで、機械的には止めない）。
