# リスクの配点が育つ流れ

リスクは宣言ではなく実績で測る。子を `ticket finish` で閉じるとき、差分を数えて点を付け、`phases/<親>/<子>.risk.json` に残す。
配点（`risks.yml`）は、その測り方が実際の重さに合っているかを見て直す。

```
きっかけ → 下書き → 検証 → 承認（ユーザが置く） → 効く → 配る
```

| 段階 | 何が起きるか | 誰が | 使うもの |
|---|---|---|---|
| きっかけ | 軽いと思った変更が HIGH になった、重い変更が LOW で通った。点と加点の理由は、閉じたときの出力・`--explain`・レビュー依頼の先頭に出る | ユーザが気づく | `risk.json`、`ccnavi --explain` |
| 下書き | 項目を足す・点を変える・境目（既定 20 / 40 / 70）を動かす。本物の全文を写して直す | エージェント | `/ccnavi-config`、置き場は `wip/handoff/`（`ccnavi-stage.sh` で写す） |
| 検証 | 読めるか、境目の順、`id` の重複、`script:` の置き場を機械に聞く。`--risk` で下書きを差し替えて本物の残り 2 本と組み合わせて見る | エージェント | `ccnavi --lint --risk <下書き>` |
| 承認 | 何をなぜ変えるかと一緒に渡し、ユーザが置く | ユーザ | `ccnavi user handoff` |
| 効く | 次に子を閉じるときから。進行中の子の記録は変わらない | ccnavi | `ticket finish` |
| 配る | 共通レイヤーの配点は、親の着手でプロジェクトの `.ccnavi/config/common/` へミラーされる（スクリプトも同じパス） | ccnavi | 親の `ticket start` |

## 項目の 3 系統

| 系統 | 向く場面 | 注意 |
|---|---|---|
| 定量（`lines_over` `files_over` `deleted_over` `glob`） | 差分の大きさ・触った場所で決まるもの | `include` / `exclude` で数えるパスを絞れる |
| スクリプト（`script:`） | 組み込みで数えられない定量 | 守られた場所にだけ置ける。測れなければ重いほうとして加点する（壊れたスクリプトで点を消さないため） |
| 定性（`judge:`） | 問いにしか答えられないもの | 判定が揃うまで子は閉じられない。判定は子の HEAD に結び、記録できるのは親だけ |

## 規則

- 配点は足すだけで、上書きも取り消しもしない。共通レイヤーの保護が下限として残る
- 同じ `id` で中身が違う項目は、レイヤーを空にせず両方を数える。空にすると点が下がるため
- HIGH 以上は宣言に関わらず人間レビューが要る。実績が小さくても、宣言のレビュー要は下げない
- 配点が壊れていれば組み込みの 4 項目を使い、`--lint` と閉じたときの出力が言う。両方無いときだけ組み込み、共通が無く config だけあるときは config の項目だけを数える
