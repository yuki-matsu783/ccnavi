# Chrome 拡張の置き場を既定に固定し、置き場の env と env 名の定数を読まない実装を入れる

親 i0065 のフェーズ 2（implement）。文書（`docs/`）と `ccnavi/` には触らない。

## 直すもの

| 置き場 | 直すこと |
|---|---|
| `py/ccnavi_chrome.py` | `PLACEMENT_ENV`・`_env_from_settings`・`_ABSOLUTE` を消す。`_placement` は env を読まず `settings.DEFAULT_TICKETS`・`DEFAULT_APPROVED`・`DEFAULT_PROJECT_HOME` を直に使い、絶対パスの検査と返り値の `"env"` を消す。`_environ(place["env"])`・`_preview(root, place["env"], ...)` は置き場の env を入れない形にし、「他の ccnavi の変数を外す」役目は残す。`SETTINGS_FILE` は互換のマーカーと一緒に統合先から読む一覧（`integration_files`・`workspace_files`）に残す |
| `src/core/guard.ts` | `TICKETS_ENV`・`APPROVED_ENV` を消す。`placesFromSettings` は env を読まず既定（`DEFAULT_TICKETS`・`DEFAULT_APPROVED`）を返す。名前を変えるかは実装で決め、報告に書く |
| `src/core/protocol.ts` | 上に合わせる。統合先の `settings.json` を置き場のために読む処理が要らなくなれば外す |
| `test/board.test.ts`・`test/protocol.test.ts`・`test/review.test.ts` | `settings.json` の `env` で置き場が動く前提の試験を、env を入れても既定の置き場を使う試験に書き換える。絶対パスを入れても止めない試験を足す |
| `test/fixtures/core-scenarios.json` | 答えの形が変わったときだけ、`CCNAVI_CHROME_FIXTURE=1` を付けて `tests.ticket.test_core` を回して書き直す |
| `tests/` の `_placement(None)` の呼び出し（`tests/ticket/test_core.py`・`test_chrome_project.py`・`test_chrome_write.py`・`tests/sh/test_c1_sh.py`） | `_placement` の引数の形を変えたときだけ合わせる。フェーズ 1 の B1〜B5 は直さない。直したくなったら、その試験が親チケットの受入テストと食い違う理由を報告に書く |

`_placement` が `settings_text` を受けなくするか、受けても使わないかは実装で決める。受けなくするなら
`tests/` の呼び出しを合わせる（範囲に `tests/*` を入れているのはこのため）。

## 終わりの条件

- フェーズ 1 の B1〜B5 が通る
- `uv run python -m unittest discover -s tests -t .` の全件が通る
- `uv run --with ruff ruff format --check .` と `uv run --with ruff ruff check .` が通る
- 拡張: `chrome-extension/ccnavi-approval` で `pnpm test`（`node scripts/test.js`）が通り、env を入れても既定の
  置き場を使う試験と、絶対パスでも止めない試験がその中にある
- `grep -rn "TICKETS_ENV\|APPROVED_ENV\|PROJECT_HOME_ENV\|CCNAVI_TICKETS_\|CCNAVI_PROJECT_HOME" chrome-extension/ccnavi-approval/py chrome-extension/ccnavi-approval/src`
  が何も返さない
- `ccnavi/`・`docs/`・`.ccnavi/scripts/` に差分が無い

## 得るもの

- i0064 を main に入れても Chrome 拡張が import で落ちない
- Chrome 拡張が統合先の `settings.json` の `env` を読む処理と、絶対パスを断る分岐が Python 側と TS 側の両方から
  消え、読む側の食い違いが 1 つ減る
- フェーズ 1 の落ちていた試験が通る

## 失うもの

- **i0064 が main に入るまで、置き場の env を手で書き換えたワークスペースでは、Chrome 拡張だけが既定の置き場を見る。**
  実行ファイルと sh はその間 env に従うので、拡張と手元で見る置き場が食い違う。導入スクリプトが書き出すのは
  既定と同じ値だけなので、食い違うのは手で env を書き換えたワークスペースに限られる
- 置き場を動かしたワークスペースを Chrome 拡張で扱えなくなる（ADR-0098 で決めたことの一部）
- 絶対パスを入れたワークスペースに対し、今は「Chrome では読めない」と断っていたのが、黙って既定の置き場を読む形になる

## やらない場合

フェーズ 1 の試験が落ちたまま残り、親のフェーズ 3（docs）はこのフェーズを待つので親全体が止まる。
i0064 を main に入れると Chrome 拡張が import で落ちる。
