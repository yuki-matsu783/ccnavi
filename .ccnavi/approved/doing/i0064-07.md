## なぜフェーズ 3 に足すか

フェーズ 5 の提案 i0064-06 は、文書の直しとコードのコメントの直しを 1 本に持っていた。`--approve --preview --verify`
は `ccnavi/*`・`scripts/*`・`tests/*`・`vscode-extension/*`・`wip/design/*` を「承認しても書けない（種類 docs の範囲を超える）」と言う。
子の種類は親の `plan` の番号で決まり（`phase: 5` なら `docs`）、子の側では変えられない。
利用者の決定で、種類の範囲に合わせて子を分けた。

| 子 | phase（種類） | 範囲 | 中身 |
|---|---|---|---|
| **i0064-07（これ）** | 3（implement） | `ccnavi/*`・`scripts/*`・`vscode-extension/*`・`tests/*` | コード・テストの番号、env を例にしたコメント、拡張の README、拡張のテスト ID |
| i0064-08 | 4（staging） | `wip/design/*` | `.ccnavi/scripts/` の写す版の作り直し、設計書の番号 |
| i0064-06 | 5（docs） | `README.md`・`ccnavi.md`・`docs/*` | ADR の改名・一覧・追記、README・ccnavi.md の置き場の説明 |

順序は **07 → 08 → 06**。08 は `predecessors: [i0064-07]`、06 は `predecessors: [i0064-08]` を持つ。
終わったフェーズ 3 に子を足すと、承認でフェーズ 3 のマーカー（pending・requested・reviewed）が消え、
この子が閉じたらフェーズ 3 のレビューをもう一度受ける（`ccnavi.md` の「終わったフェーズに子を足して承認すると、
その番号のマーカーを全部消す」）。フェーズ 4 はフェーズ 3 を待つので、08 はフェーズ 3 のレビューが済むまで承認されない。

振る舞いは変えない。直すのはコメント・docstring・文面の中の番号、下の表の「直す（コメントだけ）」の行、
拡張の README、テストの ID 2 つだけ。
