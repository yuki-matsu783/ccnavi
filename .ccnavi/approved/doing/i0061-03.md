# `{!root}` を実装する

親 i0061 のフェーズ 3（implement）。`acceptance`（i0061-02）と `overlap` するので
並行してよいが、閉じるのは受入テストが揃ってから。

## 最初に決めること — §4.4

設計が「実装フェーズの最初に決める」と名指しした唯一の分岐。**ここを決めずに
コードを書き始めない。**

いまの `_build` は `tuple[Rule, None] | tuple[None, Problem]` を返し、
`parse` は Problem が付いた回を `continue` で飛ばす。「報告しつつ採用する」道が無い。

| 案 | 中身 | 得るもの | 失うもの |
|---|---|---|---|
| 1 | 戻り値を `tuple[Rule \| None, Problem \| None]` に広げ、`parse` に「両方ある」経路を足す | 一般的な仕組みになり、将来ほかの「壊れているが捨てたくない」ルールにも使える | **すべてのルールが通る経路の型が変わる**。呼び出し側の網羅を確かめる必要がある |
| 2 | 生成に失敗したときだけ、`match` の全部に当たる `compiled` を持った Rule を作って返す | 変更が `{!root}` の周りに閉じる。既存の型も `parse` も触らない | 「当たる式」を捏造して Rule に詰めるので、`--explain` に出る式が嘘になる（§8 の「書いた綴りを出す」で覆えるか要確認） |

**着手時にこの表を埋め直し、選んだ理由を書いてから実装に入る。**

## 実装するもの（設計 §8 の表）

| 置き場 | 足すもの |
|---|---|
| `rules.py` | `NOT_ROOT_PLACEHOLDER`、正規化（`realpath` + `rstrip`）、展開関数、位置の検査、`regex` 専用の検査、256 字の検査、繰り返しを含まないことの検査 |
| `rules.py` | 書いた綴りを残す（`--explain` と報告は `^{!root}` を出す） |
| `rules.py` / `ruleload.py` | `RecursionError` の捕捉（`shellread.py:936-940` に倣う） |
| `rules.py` `_build` / `parse` | 上で選んだ案 |
| `lint.py` | 256 字の error、位置違反の error、`glob` の error、続く式の warn |
| `events.py` | SessionStart の報告（どこまでやるかは §6.1 の 2 択から選ぶ） |
| 記録 | `root-too-long` |

## 実装フェーズで確かめること（設計が「確かめていない」と書いたもの）

1. **Claude Code の hook が終了コード 2 以外の異常終了をどう扱うか**（止めるか通すか）。
   `RecursionError` を捕まえる意味がここに掛かる。ccnavi の外側の契約なので実測が要る
2. `os.path.realpath` がシンボリックリンク・UNC パス（`\\server\share\…`）・
   ドライブ相対（`C:foo`）に何を返すか。必要なら別チケットに切る
3. SessionStart で全層を読むときの実行時間（hook の期限は 10 秒）
4. 実装した形が設計 §2.1 と違うなら、**256 という閾値を測り直す**

## 一緒に片付けること

設計 §5 の申し送り。実測スクリプト（`verify.py` ほか）は追跡されない `scratchpad/` に
あるので、ツリーの中へ移す。置き場はテストの側（`tests/` の下）が自然。

## 得るもの

- ルールファイルから「ワークスペースの外」が書けるようになる
- レビューで見つかった 4 つの欠陥が、設計とテストの両方で塞がれた状態で実装に入れる

## 失うもの

- **`_build` / `parse` は全ルールが通る経路**。案 1 を採れば、`{!root}` と無関係な
  ルールの読み込みにも影響する。回帰は受入テストと既存のテスト全件で見る
- SessionStart に新しい読み込みが入ると、hook の起動が重くなる
- 組み立てが毎プロセス +2 ms（`{!root}` を使うルール 1 本あたり）

## やらない場合

設計だけが残り、道具は無いまま。`outside-temp` のような名指しの列挙を続ける。

## 範囲について

`implement` フェーズの `scope` は `ccnavi/*` `tests/*` `build.py` `pyproject.toml`
`scripts/*` `.ccnavi/*` `vscode-extension/*` と広いが、**この子は `ccnavi/*` と
`tests/*` だけを宣言する**。設定ファイルや配布物には触らない。
