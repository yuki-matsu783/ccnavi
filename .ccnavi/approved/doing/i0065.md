# Chrome 拡張の置き場を既定に固定し、置き場を動かす環境変数を読まない

## なぜ

- 置き場を既定に固定する決定（ADR-0098）の実装は i0064 が持つ。i0064 は `ccnavi/infra/settings.py` から
  env 名の定数（`TICKETS_ENV`・`APPROVED_ENV`・`PROJECT_HOME_ENV` など）を消す
- main の Chrome 拡張（`chrome-extension/ccnavi-approval/`）は、この定数をモジュールの読み込み時に参照している
  （`py/ccnavi_chrome.py` の `PLACEMENT_ENV`）。i0064 を main に入れた時点で、拡張の Python 側は import で落ちる
- i0064 の範囲に `chrome-extension/` は無い。改版でも範囲は広げられないので、i0064 の中では直せない
- そこで、Chrome 拡張だけを既定に固定する親チケットを別に立て、i0064 より先に main に入れる

## 受入テスト

- 統合先の `.claude/settings.json` の `env` に `CCNAVI_TICKETS_PROPOSAL`・`CCNAVI_TICKETS_APPROVED`・`CCNAVI_PROJECT_HOME`
  を入れても、Chrome 拡張（Python 側と TS 側の両方）は既定の置き場（`wip/proposals`・`.ccnavi/approved`・`.ccnavi`）を使う
- 同じ env に絶対パスを入れても止めない（読まないので、対象外にする理由が無くなる）
- `chrome-extension/ccnavi-approval/py/ccnavi_chrome.py` が `settings` の env 名の定数を参照しない
  （i0064 で定数が消えても import で落ちない）
- `tests/ticket/test_core.py` の `CoreChromeTest` が通る
- 拡張のテスト（`npm test`、`node scripts/test.js`）が通る

**前提（ユーザの作業）**: 今の `.ccnavi/config/phases.yml` では、どの work の種類の `scope` にも
`chrome-extension/*` が無い（implement は `ccnavi/*`・`tests/*`・`vscode-extension/*` など）。このままだと 2 の子は
承認できても「チケットで編集対象としているが、書き込めない場所」になり、判定が止める。2 の子を承認する前に、
ユーザが implement の `scope` に `chrome-extension/*` を足す（`phases.yml` はユーザが持つ設定で、エージェントは書かない）。

フィードバック計画は改版で 1 回しか足せないので、レビューの指摘に備えて `implement-feedback`（範囲は親を継ぐ）を最初から入れておく。

## i0064 との順序

1. このチケットを先に main に入れる
2. i0064 が main を取り込めば、Chrome 拡張は env 名の定数を引かなくなっているので、定数を消しても落ちない
3. i0064 の側で Chrome 拡張に触る必要は無い

逆の順（i0064 を先に入れる）だと、入れた時点から main の Chrome 拡張が import で落ちる。

## 得るもの

- i0064 を main に入れても Chrome 拡張が落ちない
- Chrome 拡張が統合先の `settings.json` の `env` を読む処理と、絶対パスを断る分岐が消え、読む側の食い違いが 1 つ減る

## 失うもの

- このチケットが入ってから i0064 が入るまで、main では Chrome 拡張だけが置き場の env を無視し、実行ファイルと sh は env に従う期間がある。
  置き場を既定から動かしているワークスペースでは、その間 Chrome 拡張と手元で見る置き場が食い違う。
  導入スクリプトが書き出すのは既定と同じ値だけなので、実際に食い違うのは手で env を書き換えたワークスペースに限られる
- 置き場を動かしたワークスペースを Chrome 拡張で扱えなくなる（ADR-0098 で決めたことの一部）

## やらない場合

- i0064 を main に入れると Chrome 拡張が落ちる。i0064 は範囲の外なので直せず、入れられないまま止まる

## 代案

| 代案 | 採らない理由 |
|---|---|
| i0064 で `settings` の env 名の定数だけ残す | 消すと決めた口の名残が残り、Chrome 拡張は env を読み続ける。ADR-0098 と食い違う |
| i0064 を閉じて、`chrome-extension/*` を範囲に含めた親チケットで出し直す | i0064 の進んだフェーズとレビューを捨てることになる |
| i0064 を入れたあとに Chrome 拡張を直す | その間 main の Chrome 拡張が落ちる |
