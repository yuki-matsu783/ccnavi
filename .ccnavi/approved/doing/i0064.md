# 置き場を既定に固定し、置き場を動かす環境変数を消す

## 方針

**置き場は既定だけにする。変えたい要望が出たら、そのとき口を足す。**

いまある口は、使われていないのに読む側すべてに分岐を強いている。口を先に用意して
おく利点より、仕様と実装が複雑になる代償のほうが大きい。

## 消すもの

| 変数 | 既定（これに固定） | 空文字でできたこと（これも消える） |
|---|---|---|
| `CCNAVI_PROJECTS` | `projects`（ワークスペースルート直下） | プロジェクトを数えない |
| `CCNAVI_PROJECT_HOME` | `.ccnavi`（各 git プロジェクトルート直下） | — |
| `CCNAVI_TICKETS_PROPOSAL` | `wip/proposals`（各ツリー） | — |
| `CCNAVI_TICKETS_APPROVED` | `.ccnavi/approved`（各ツリー） | — |
| `CCNAVI_LOG` | `logs/log.jsonl` | 記録しない |
| `CCNAVI_STATE` | `logs/state` | 控えを持たない |

- `settings.py` の overrides 表から 6 行を消す。**ccnavi 自身の上書き設定ファイル**
  （`ccnavi.settings.local.json`）の同じ名前のキーも読まなくなる。同じ表を読んでいるため
- `Settings` の欄（`conf.projects` など）は既定の値を持って残す。渡している先は触らない
- 環境に値が残っていても**無視する**。止めない

### 残すもの

| 残すもの | 理由 |
|---|---|
| `CCNAVI_BIN_PATH` | 置き場のレイアウトではなく、hook がどの実行ファイルを起動するかの指定。既定を持たない設計（置き場がプロジェクトごとに違い、誤った既定は無関係のファイルを守ることになる）で、守る対象を決める鍵でもある |
| `CCNAVI_WORKSPACE` | sh が cwd から上へ辿ってもワークスペースを見つけられないときの逃げ道。置き場を動かすものではない |
| 診断のフラグ（`--log` `--state` `--approved` `--tickets` `--projects` `--project-home`） | テスト 20 本以上がこれで一時的な置き場を指している（例: `--approved .ccnavi/tickets`）。消すとテストの作りを大きく変えることになるので、別のチケットにする。人が書く設定ではなく、hook からは渡らない |

## 読む側で変わること

| 読む側 | 変えること |
|---|---|
| 実行ファイル | `settings.py` の env 名の定数 6 つと overrides 表の 6 行。`--lint` の「`CCNAVI_TICKETS_APPROVED` が空」の指摘は、指摘の元ごと消す |
| sh（保護済み） | `ccnavi-common.sh`・`ccnavi-git.sh`・`ccnavi-fetch.sh`・`ccnavi-push-approved.sh` などの `${CCNAVI_…:-既定}` を既定の綴りにする。`ccnavi-push-approved.sh` の綴りの正規化（`/` や `.` を既定に戻す分岐）を消す |
| 導入スクリプト | `CCNAVI_LOG` と、`--all` で書いていた 4 つを書かない。**既に入っている `settings.json` の `env` からこの 6 つを外す**（導入スクリプトが持つ欄なので）。値が既定と違っていたら、外したことを名指しで 1 行出す |
| VS Code 拡張 | `envFromSettingsJson` などで読んでいる置き場の env をやめる。プロジェクト画面の「置き場が無効」の分岐・文面・ボタンの抑止を消す |

## 名前がぶつかったら知らせる

**見つける条件:** ワークスペースの git が `projects/` の下のファイルを 1 本でも追跡している
（`git ls-files -- projects/`）。

これは「ワークスペース自身のソースに `projects/` がある」ということ。固定にしたあとは
名前を逃がす手段が無いので、ぶつかると次のことが起きる。

- `.gitignore` に `/projects/` を足せない（足すとソースが追跡から外れる）ので、
  VS Code 拡張の「無視されていない」警告が消えない
- `projects/` の下で `.git` を持つもの（サブモジュールなど）がプロジェクトとして数えられ、
  その中の `.ccnavi/config/` が層として読まれる

**知らせる場所:**

| 場所 | 形 |
|---|---|
| `ccnavi --lint` | `(projects)` の warn。これが出るときは、既存の「無視されていない」を出さない（原因が同じで、`.gitignore` に足せという案内が誤りになるため） |
| VS Code 拡張のプロジェクト画面 | 上の warn をバナーで出す。「`.gitignore` に足す」ボタンを出さない |
| 導入スクリプト | 入れ終わったところで同じ条件を見て、同じ案内を出す。入れる瞬間がいちばん気付きやすいため。止めない |

**文面の案（`--lint`）:**

> `projects/` はワークスペースの git が追跡している（例: `projects/foo/main.py`）。
> ccnavi はワークスペース直下の `projects/` をプロジェクトの置き場として使い、名前は変えられない。
> このままだと `projects/` の下で `.git` を持つディレクトリ（サブモジュールを含む）が
> プロジェクトとして数えられ、その中の設定が判定に使われる。
> 直すには、ワークスペースの `projects/` を別の名前に移す（例: `git mv projects apps`）。
> ccnavi でプロジェクトを置かないなら、このままでも動く。そのときは `projects/` の下に
> `.git` を持つものを置かない

error にはしない。プロジェクトを置かない運用なら判定は正しく動く。

他の置き場（`.ccnavi/`・`wip/proposals/`・`logs/`）の名前のぶつかりは、このチケットでは
扱わない。`.ccnavi/` と `wip/proposals/` は ccnavi のためにワークスペースの git が追跡する
場所で、ぶつかっても既存の中身と並ぶだけ。`logs/` は今も既定のまま動いていて、固定にしても
振る舞いが変わらない。

## 得るもの

- 置き場の決まり方が 1 通りになる。読む側すべてから「env を見て、無ければ既定」の分岐が消える
- 読む側ごとの食い違いが分岐ごと消える（絶対パスを `ccnavi_project` だけが受けない、
  拡張が `CCNAVI_TICKETS_PROPOSAL` を読まず、変えるとボードが自動で更新されない）
- sh の綴りの正規化と、そのテストが要らなくなる
- ADR-0077 がコマンド行で止める `CCNAVI_*` が 6 つ減り、hook が見る範囲が狭くなる
- README の環境変数の表が 6 行減る。置き場の説明が「ここに固定」で済む
- ぶつかったとき、サブモジュールを黙って層として読むのではなく、原因と直し方が出る

## 失うもの

- **「記録しない」「控えを持たない」「プロジェクトを数えない」を env で言えなくなる。**
  記録を止めたい人は止められない。控えを持たないと実行後の監視が働かないので、
  控えを止める意味はもともと薄い
- **名前がぶつかったワークスペースは、自分のソースの `projects/` を改名するしかない。**
  改名はそのリポジトリの参照（ビルド設定、CI、import）を直す仕事になる
- **配布先で値を変えている人がいれば、既定に戻る。** こちらから確かめる手段が無い。
  導入スクリプトを打ち直した人には名指しの 1 行が出るが、打ち直さない人は気付かない
- **導入スクリプトが既存の `settings.json` から 6 つのキーを消す。** 人が手で書いた値も
  消える（既定と違えば名指しする）
- **テストの書き方が変わる。** env で置き場を指していたテスト（`CCNAVI_PROJECT_HOME` 7 本、
  `CCNAVI_TICKETS_APPROVED` 3 本など）と、「数えない」を `CCNAVI_PROJECTS=""` で言っていた
  テストを直す。ADR-0067 が「人が settings.json に書く経路に近い」として選んだ形を捨てる
- 保護済みの sh を直すので、写す版（`wip/design/scripts/`）を作って人が写す手間が要る
- 導入スクリプトの案内は `--lint` と同じ条件を sh でもう 1 度書く。文面が 2 か所に分かれる
- 診断のフラグは残るので、「置き場は動かない」は hook と sh の話で、診断では動く。
  これが片付くのは次のチケット

## やらない場合

使われていない口のために、置き場を読むコードを書くたびに「env を見て、無ければ既定」を
足し続ける。読む側ごとの食い違いも残る。

## 代案

1. **`CCNAVI_PROJECTS` だけ消す（元の i0064）。** 変更は小さいが、同じ理由で要らない口が
   5 つ残り、同じ議論をあと 5 回する
2. **置き場は固定し、`CCNAVI_LOG` / `CCNAVI_STATE` の空文字（止める口）だけ残す。**
   記録を止めたい人の逃げ道が残るが、「場所は変えられないが止めることはできる」という
   半端な口が残る。要望が出ていないので入れない
3. **診断のフラグも同じチケットで消す。** 1 回で片付くが、テストの一時的な置き場の作りを
   20 本以上直すことになり、このチケットのレビューが重くなる
4. **消したうえで、環境に値が残っていたら `--lint` で知らせる。** 黙って既定に戻る人に
   気付かせられるが、消した変数を読むコードが残る。導入スクリプトの 1 行で足りるとみて入れない
